## What it is

The sandbox execution primitive — `run(command | wasm, spec) -> output` behind a swappable
backend seam. This is the layer that lets an agent *do* things — run commands, evaluate
code, explore a workspace — with real isolation:

- **In-process wasmtime / WASI** ephemeral sandbox is the default.
- **Command backends** (docker, microsandbox, opensandbox) and the **remote Daytona REST**
  backend are detect-gated swaps selected by name via `select_backend`.
- Owns the **long-lived-workspace session** path and the **per-run metering heartbeat**
  (kill-isolation + Gateway `sandbox/tick` debit).

## Swap seam

Host couplings the crate cannot own — the Gateway URL/bearer for metering, the data dir for
the persisted default-backend selection, the registered org id, and the preferences-backed
default run budget — inject through the narrow global `SandboxHost` seam. In-process by
default, consumed as a non-optional path dependency (Core's sidecar, session, and eval-code
data paths reach it unconditionally).

## Where it lives

`crates/core/sandbox`

## API surface

- `/api/sandboxes/*` — list, exec, and destroy sandboxes; choose the backend (see the
  [Sandboxes API reference](/docs/develop/api-reference/core/sandboxes)).
