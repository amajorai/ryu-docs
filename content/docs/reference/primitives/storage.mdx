## What it is

The plugin-owned key/value storage primitive. It backs the plugin-host `storage:kv`
capability with an isolated, `(plugin_id, namespace, key)`-namespaced SQLite KV store — one
plugin can never read or overwrite another plugin's keys, and a plugin's storage survives
the plugin being disabled and re-enabled.

## Swap seam

`PluginStorage::open` takes an explicit database path, so the crate has no kernel coupling.
The default path choice and the process-global handle stay Core-side as wiring. In-process
by default — the plugin turn-hook runtime reaches it unconditionally.

## Where it lives

`crates/core/storage`

## API surface

The store is the backing state for the plugin-host `storage:kv` capability; plugin
authors reach it through the SDK's `storage` primitive rather than the crate directly. See
[Plugin runtime](/docs/develop/extensions/plugin-runtime) and
[SDK Primitives](/docs/develop/sdk/primitives).
