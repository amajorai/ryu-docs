## What it is

The Identity Vault primitive: a crypto-sealed, per-domain credential store. It lets an
agent act as a logged-in user on a specific web domain without the underlying credential
ever reaching the model.

- **`IdentityStore`** — SQLite store sealed with the `enc:v1:` envelope via
  [crypto](/docs/primitives/crypto), using `SealedState`/`SecretState` newtypes that are
  never `Serialize` and whose `Debug` is redacted, so a log line can't leak a secret.
- **`CredentialSource` seam** — the swappable capture/rotation backend. `ManualImport`
  (paste a cookie or token) is the default; the per-domain `CredentialSourceRegistry`
  makes additional sources drop-in.
- **Staleness sweep** — a health loop flips stale connections back to `NEEDS_AUTH` so a
  rotated credential can't silently go dead.

Governance — the Gateway grant + audit read chokepoint, tool-call consult, and
elicitation — stays kernel-side in Core, not in this crate.

## Swap seam

The one kernel coupling, the `~/.ryu` data dir, is inverted as an `IdentityStore::open(dir)`
constructor parameter. Sealing routes through `ryu_crypto::global_cipher`. In-process by
default: it is a function-call hot path, no IPC.

## Where it lives

`crates/core/vault`

## API surface

- `/api/identities` — list profiles and per-domain connections.
- `/api/identities/connections/*` — create, login, poll, import (seal), and remove
  connections.

For the full design — the 3-layer never-to-LLM invariant, the tool-dispatch consult
chokepoint, and the credential consumer — see [Identity Vault](/docs/core/identity-vault).
