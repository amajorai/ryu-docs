Ryu ships a store full of built-in apps. On a fresh install the picture is simple: the
**default-on** apps below are the only ones with a record, and each of those is seeded **enabled**.
Every other built-in app has **no record at all** - the Store lists it as available, and Install →
Enable from the Store creates it. See [App lifecycle](/docs/core/app-manifest-lifecycle) for the
mechanism.

Everything built-in is Core-tier (ships in the binary, may spawn a sidecar or register an MCP
server). The tables below list the per-app defaults that matter.

## Enabled on first run

These are seeded **enabled** on a fresh install. They are the batteries.

| App | Sidecar port | Default model | Notes |
|---|---|---|---|
| Calendar | - (in-crate) | - | Companion page was always-on before extraction |
| Dictation | - (Core STT) | whisper `ggml-base.en.bin` | Previously hardcoded into Island; the plugin is now the single switch |
| Learning | - (in-crate) | - | Owns the `learning.skills-enabled` / `learning.enabled` consent switches |
| MarkItDown | 8094 | - | The default `document.parse` provider |

### Core subsystems (fixtures)

These ship as manifests so Core can describe its own subsystems to the plugin lifecycle. They are
all default-on; several are mandatory or load-bearing:

| App | Status | Notes |
|---|---|---|
| Engines | **Load-bearing** + default-on | Local llama.cpp chat (`:8080`) + embeddings (`:8081`); the model `gemma-4-E2B-it-Q4_K_M` |
| Durable | **Load-bearing** + default-on | In-process durable workflow engine |
| Agents | **Load-bearing** + default-on | Agent catalog the composer reads |
| Spaces | **Mandatory** + default-on | Document/workspace root every retrieval path resolves through |
| RAG | **Mandatory** + default-on | Retrieval; requires Engines |
| Layers | **Mandatory** + default-on | Toolkit defaults (search limit, crawl depth, crawl page limit) |
| Skills | **Mandatory** + default-on | Skill injector |
| Media | **Mandatory** + default-on | Image/render path |
| Hardware | **Mandatory** + default-on | Device probing the engine picker reads |
| Output Styles | Default-on | The composer's nine built-in styles |

## Available in the Store (not pre-installed)

Every other built-in app ships **without a record** - a fresh machine does not list it as installed,
and uninstalling one stays uninstalled. Most are opt-in for a deliberate reason (a key, a binary
that is not on a normal install, or a capability you should switch on). Install them from the Store.

### Document parsers (opt-in weight)

The four `document.parse` providers. Only MarkItDown (above) is default-on; these three are
deliberately heavy (pip installs, Torch stacks, model downloads):

| App | Port | Notes |
|---|---|---|
| Docling | 8095 | IBM Docling; ~1 GB+; models cached in `~/.ryu/models/hf` |
| Mineru | 8096 | 16-32 GB RAM advised; GPU |
| Unstructured | 8093 | 1-2 GB pip install + native helpers (poppler/tesseract/libreoffice/pandoc); ~60 formats |

## Everything else

Apps in the Store catalog that are not compiled in (third-party, Community-tier) are covered by the
[Apps](/docs/apps) section and the [Marketplace](/docs/desktop/user-guide/marketplace). The tables
above are only what ships in the binary.
