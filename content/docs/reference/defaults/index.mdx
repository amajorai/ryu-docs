Ryu ships ready to use: a local chat model, embeddings, voice, a default agent, and a set of
installed-and-enabled apps and plugins. None of it is hardcoded - every default below resolves
through a registry, a config store, or a manifest, and each one has a documented override. This
section is the map of what ships and how to change it.

## The default model

Every surface starts with a model. The full table - the managed desktop agent, the Gateway, every
local engine (llama.cpp, whisper, Audio, image, MLX), and each app's side model - is on the
[Default models](/docs/reference/defaults/models) page. The short version:

- **Desktop / managed agent**: `gemma-4-E2B-it-Q4_K_M` (local, zero keys) or `openrouter/auto`
  (managed subscription).
- **Utility and sub-agent completions**: `gpt-4o-mini`.
- **Local embeddings**: `nomic-embed-text-v1.5` (768-dim) on `:8081`.
- **Gateway smart-routing classifier**: `gemma-3-270m-it-qat-Q4_0` on `:8083`.
- **Every channel bot**: `gpt-4o`.

## What installs and turns on

Ryu's apps and plugins are not all present from the first boot. Three independent properties
decide what a fresh install actually has, and they are easy to conflate - see the
[app lifecycle](/docs/core/app-manifest-lifecycle) page for the full mechanism:

| Property | Question it answers | Enforced by |
|---|---|---|
| **Tier** | Core-tier (reviewed capability policy; may run sidecars / MCP servers / Pi extensions) vs Community (needs the Gateway's grants) | `CORE_PLUGINS` membership |
| **Default-on** | The record is seeded **enabled** on first run | `CORE_DEFAULT_ON` membership |
| **Not pre-installed** | No record exists on a fresh store (so the Store lists it as *available*, and an uninstall sticks) | `NOT_PRE_INSTALLED` membership |

Every default-on app or plugin is Core-tier, but most Core-tier packages are **not** pre-installed at
all - only the default-on set carries a record on a fresh store, and everything else is one Install
→ Enable away from the Store. On a stock install the only records that exist are the default-on
ones; every other app (sidecar apps, document parsers, policies, system apps) arrives absent.

The complete per-app and per-plugin posture is in [Apps](/docs/reference/defaults/apps) and
[Plugins](/docs/reference/defaults/plugins).

### Tiers within the default set

Even among the default-on plugins, three are load-bearing (disable requires an explicit
`force`): `@ryu/engines` (the local Chat runtime every default agent routes through), `@ryu/durable`
(the in-process workflow engine), and `@ryu/agents` (the agent catalog the composer reads). Six are
**mandatory** - never disableable, never uninstallable, no override: `@ryu/spaces`, `@ryu/rag`,
`@ryu/layers` (data plane), `@ryu/skills`, `@ryu/media`, `@ryu/hardware` (capability plane). See
[Plugins](/docs/reference/defaults/plugins) for the full list.

## How a default is resolved

Defaults are a fallback chain, not a single source. From the
[configuration](/docs/start-here/configuration) reference:

```
explicit request argument → preference → node-wide default → environment variable → built-in default
```

- The **built-in default** is the last stop - the value in the code or manifest, listed on this
  section's pages.
- An **environment variable** overrides it for headless and container deploys. The
  [Environment Variables](/docs/start-here/environment-variables) page lists every variable.
- A **preference** (set from Settings, stored per node) beats the environment.
- An **explicit request argument** beats everything.

Most settings have a picker in Settings, and the picker wins - the matching environment variable
only applies when nothing has been set through the UI.

## Ports

Every built-in sidecar, engine, and app binds a documented loopback port, and all of them are
profile-aware. On the release profile the numbers below are literal; on `dev` every port shifts
`+1000` (Core on `:8980`, llama.cpp chat on `:9080`), on `canary` `+2000`. The complete map is on
the [Ports](/docs/reference/defaults/ports) page.

## Swappable by design

These defaults exist so a fresh install works with zero API keys, not to lock you in. Every one is
replaced through the same seams:

- **Chat / utility model** - pick another in Settings, or set `RYU_DEFAULT_LLM_MODEL`.
- **Local engine** - install any GGUF / safetensors / MLX model from the
  [model catalog](/docs/surfaces/desktop/models).
- **Embeddings** - set `RYU_EMBED_MODEL`.
- **Capability providers** - e.g. swap the default `web.search` provider (Exa) for Tavily, Brave,
  Serper, or Parallel; bind `document.parse` to Docling or Mineru instead of MarkItDown.
- **Apps and plugins** - disable any default-on record, or install and enable anything else,
  from the Store.
