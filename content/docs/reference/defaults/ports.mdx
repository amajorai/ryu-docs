Every Ryu process that listens binds a loopback port. The full map is below, in release-profile
values. None of them are authoritative URLs you should hardcode: the desktop reaches an app through
`/api/ext/<plugin_id>/*` and a sidecar is told its own port via an injected `RYU_<APP>_PORT`, so a
port moving is invisible to UI and bookmarks.

## Profiles shift every port

Ports are **profile-aware**. The numbers in this section are the release profile; other profiles add
an offset to every base:

| Profile | Offset | Core | llama.cpp chat |
|---|---|---|---|
| release | +0 | 7980 | 8080 |
| dev | +1000 | 8980 | 9080 |
| canary | +2000 | 9980 | 10080 |
| nightly | +3000 | 10980 | 11080 |
| beta | +4000 | 11980 | 12080 |

Set `RYU_PROFILE` (or a `--profile` flag) to choose one. `RYU_BIND` overrides the Core bind address.
The same offsets are used by standalone app sidecars (including Browser, Desktop, Simulator, and
Dashboards); an unknown profile is rejected rather than silently sharing a release port. A relocated
`RYU_DIR` still wins over the profile default, so sidecars continue to open the node's chosen data
directory.

## Core substrate

Ports Core itself binds, or that are reserved against apps squatting them. The table at
`apps/core/src/plugin_manifest/mod.rs` (`CORE_RESERVED_PORTS`) is the enforced copy of this list.

| Port | Owner | Purpose |
|---|---|---|
| 3200 | SDK adapter | Default SDK app port |
| 7980 | Core | Main Core HTTP API (the surface every client talks to) |
| 8000 | vLLM / OMLX | Heavy serving engines |
| 8080 | llama.cpp | Local Chat (`llamacpp`) - also restate http + ingress |
| 8081 | llama.cpp | Embeddings (`llamacpp-embed`) |
| 8082 | llama.cpp | Reranker |
| 8083 | llama.cpp + sd.cpp | Classifier / inspector **and** image generation |
| 8084 | MLX-VLM | Apple Silicon vision |
| 8085 | ryutts | Audio |
| 8086 | MLX | Apple Silicon chat |
| 8087 | research | Research's Python autoresearch engine |
| 8090 | whisper.cpp | Voice Recognition |
| 9070 | restate | Restate admin |
| 30000 | sglang | Heavy serving engine |
| 11434 | Ollama | Managed `ollama serve` (not in the reserved table - the reserved list is apps, not engine proxies) |
| 3030 | Shadow | Ambient context monitor (`RYU_SHADOW_URL`) |

## Gateway

| Port | Owner |
|---|---|
| 7981 | Gateway (release; profile-aware like Core) |

The Gateway is reached by Core at `127.0.0.1:7981`, which is also the default in every app's
`DEFAULT_GATEWAY_URL`.

<Callout type="info">
  **Finetune binds two ports.** The Rust proxy serves `:7990`; the Unsloth Python trainer is on
  `:8086`, which overlaps MLX's base - a known, frozen overlap (both are opt-in and rarely resident
  at the same time). `:8087` is shared by research's Python engine and meetings' diarization.
</Callout>

## Plugin services

Plugins that bind a port rather than running as a stdio MCP server or a Core-sidecar:

| Address | Plugin | Purpose |
|---|---|---|
| `127.0.0.1:8787` | Headroom | Compression transform service |
| `127.0.0.1:47821` | Pxpipe | Loopback token-saving proxy |
| `127.0.0.1:9990` | Bytebot | Remote `computer.control` (fixed loopback port) |

## Non-port endpoints

A few built-ins expose remote HTTP endpoints rather than a local port:

| Endpoint | Owner |
|---|---|

| `https://bot.ryuhq.com` | Gateway managed bot |
| `https://api.anthropic.com` | Anthropic upstream |
| `https://chatgpt.com/backend-api/codex` | Codex upstream |
