title: Tasks
description: The current RyuBench task categories, what each asks the agent to do, and how it is verified against persisted state.
---

Task set `0.2.0` has **50 tasks** across thirteen deterministic Tier-A categories plus
computer-use Tier B. Forty-seven tasks form the scored API-state core. The 3
computer-use tasks are reported separately.

Every task is a small object with a natural-language `prompt` (the only thing the agent sees),
an optional `setup`, and an `assert` that reads real state through the public API. The prompt is
**under-specified**: it tests whether the model understands Ryu, not whether it can follow a
checklist. It always pins an exact resource name so the assertion can find what the agent built.

<Callout type="info">
  The `assert` never inspects the transcript. It calls `GET`/`POST` against the node and grades
  the result. If the resource was never created, the task fails safe. The agent is graded on what
  it *did*, not what it *said*.
</Callout>

## Tier A: the scored core

| Category | The agent must… | Verified by (public API) |
|---|---|---|
| **workflow** | build a DAG via `POST /workflows` (nodes, edges, templates), run it, or park it at a human-in-the-loop node | `GET /workflows` structure match; `GET /workflows/runs/:id` reaches `completed` / `awaiting_input` |
| **harness** | create durable parent/child sessions and bind an external runtime id | `GET /api/harness/sessions/:id` matches runnable and lineage fields |
| **agent** | create/update an agent with the right configuration (name, system prompt, `chat_model`, tools allowlist, tts voice) | `GET /api/agents/:id` echoes the configuration; `GET /api/agents/:id/tools` matches |
| **tool** | register an MCP server, find a tool via the catalog, or compute a digest in the PTC exec sandbox and persist it | recompute the reference digest in-harness and compare the persisted memory; confirm tool ids are real catalog entries |
| **gateway** | configure a budget, firewall, or organization firewall overlay via `PUT /v1/config` | `GET /v1/config` shows the rule with the expected fields |
| **spaces** | create a Space, store a document, or ingest a fact so it becomes RAG-retrievable | `GET /api/spaces/:id/documents`; independent `POST /api/spaces/:id/search` returns the fact |
| **plugin** | build a valid manifest and pass grant validation / signing, or toggle a plugin | `POST /v1/grants/validate` `all_approved`; `POST /v1/manifests/verify` `valid`; `GET /api/plugins` enabled flag |
| **monitor** | create a monitor + condition and run it, or file a quest | `GET /api/monitors` shape; `GET /api/monitors/:id/snapshots`; `GET /api/quests` |
| **chat** | drive a session to a stateful outcome (record a memory, capture a quest, fork a conversation) | the downstream artifact exists; the reply text is not graded |
| **output-style** | author and update a reusable response profile | `GET /api/output-styles/:id` matches the persisted style, then teardown deletes it |
| **catalog** | add, select, and restore a custom skill catalog source | `GET /api/catalog/sources?kind=skill` proves the persisted active source |
| **notifications** | unregister a mobile push token | a single deletion probe returns `404`; `200` fails and consumes the fixture, with the result cached for repeat grading |
| **approvals** | set the global approval mode and restore the prior mode | `GET /api/approvals/mode` returns the requested mode |

## Tier B: computer-use (separate track)

| Category | The agent must… | Verified by |
|---|---|---|
| **computer-use** | reach the Ghost/Shadow desktop tools via `POST /api/mcp/tools/call` | tool **reachability** and graceful degradation; never deterministic screen content |

Computer-use is non-deterministic and needs a sandbox VM to score, so its result is
reported beside the Tier-A headline and never folded into it.

## App prerequisites

Before a run, install and enable the apps required by the selected categories. Workflow
version tasks require Workflows; approval-mode tasks require Approvals. An unavailable
app is an environment failure, not a model-capability result.

To add a task or calibrate the assertions, see [Author a task](/docs/reference/benchmark/authoring-tasks).
