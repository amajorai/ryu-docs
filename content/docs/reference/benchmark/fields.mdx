title: Field Track
description: Score models on design, writing, data analysis, coding, automation, and research work, with every attempt routed through a Ryu node and graded by deterministic checks.
---

The [Tier-A suite](/docs/reference/benchmark/tasks) asks whether a model can operate Ryu. The field track asks a different
question: which model is best for a kind of work, such as design, writing, or data analysis,
when it runs through Ryu? Each field has its own score and its own page on the public
[RyuBench leaderboard](https://ryuhq.com/benchmark).

Every field task attempt is one chat completion sent to the node's OpenAI-compatible
`/v1/chat/completions` endpoint, the same route your own apps use. The request has no tools and
no system prompt, so the score reflects the model rather than the scaffold.

<Callout type="info">
  Field scores are reported per field. They are never folded into the Tier-A headline.
</Callout>

## Fields and their sources

A field can draw on three sources. Each source writes its own scorecard.

| Field | Source | Command |
|---|---|---|
| Design | Field tasks | `ryubench fields run --field design` |
| Writing | Field tasks | `ryubench fields run --field writing` |
| Data analysis | Field tasks | `ryubench fields run --field data-analysis` |
| Coding | [Harbor](/docs/reference/benchmark/harbor): SWE-bench Verified, Terminal-Bench 2.0, Aider Polyglot | `ryubench harbor run --dataset <alias>` |
| Automation & agents | Tier A: workflow, harness, agent, tool, monitor, notifications, approvals | `ryubench run --category …` |
| Research & knowledge | Tier A: spaces, chat | `ryubench run --category spaces --category chat` |

`ryubench fields list` prints every field task and the matching commands for the other sources.

## How field tasks are graded

A field task's verifier reads only the model's final answer. It extracts the last fenced block
of the requested type (for example ` ```svg ` or ` ```json `) and checks hard constraints. No
model grades another model's answer, so the same answer always gets the same result.

- **Design**: SVG canvas size and `viewBox`, required brand colors, WCAG contrast ratios for
  text and color tokens, brand hue distance, and modular type-scale steps.
- **Writing**: word and character limits, required terms and figures, banned words, bullet
  structure, and no invented amounts.
- **Data analysis**: JSON answers compared with precomputed results within 0.01.

A task passes only when every check passes. With `--k` above 1, the scorecard also reports
pass^k, the share of tasks that passed every repetition, and a Wilson 95% interval on the pass
rate. [Scoring and governance](/docs/reference/benchmark/scoring) explains both measures.

## Run the field track

Start a Ryu node, then run:

```sh
bun run --cwd apps/benchmark run:fields --model <model-id> --k 3
bun run --cwd apps/benchmark run:fields --model <model-id> --field design --field writing
```

| Flag | Default | Meaning |
|---|---|---|
| `--model <id>` | `RYUBENCH_MODEL` | Model the node routes the request to |
| `--field <id>` | all fields | Repeatable filter: `design`, `writing`, `data-analysis`, `coding`, `automation`, `research` |
| `--k <n>` | `1` | Repetitions per task |
| `--node-url <url>` | `RYU_NODE_URL` or `http://127.0.0.1:7980` | Core base URL |
| `--node-token <tok>` | `RYU_NODE_TOKEN` | Core node token |
| `--timeout <ms>` | `120000` | Per-attempt budget |
| `--out <dir>` | `./.ryubench` | Output directory |

The run writes `fields-<timestamp>.json` and `fields-<timestamp>.md`. The scorecard records the
model, the Core version, the field-set version, `k`, the start time, and the endpoint, so each
number can be reproduced.

Selecting a field whose score comes from Tier A or Harbor prints the commands for those sources
at the end of the run.
