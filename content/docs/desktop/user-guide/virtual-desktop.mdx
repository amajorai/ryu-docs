---
title: "Virtual Desktop"
description: "Stream any node's full desktop live and drive it with your mouse and keyboard — the same screen Ghost automates."
---

The **Virtual Desktop** panel streams a node's *entire* desktop — a real graphical session, not a
browser tab — to the desktop app live, with full mouse and keyboard input. It works for **every**
node type: a managed Ryu Cloud node, a self-hosted Hetzner box, or your own local Linux machine.

It is also the **watch-the-agent-work** surface: Ghost drives the **same** display, so when an agent
uses `computer.control` tools (`computer__click`, `computer__type`, `computer__capture`), you see
exactly what it is doing, and you can take over with your mouse at any moment.

## What you get

- **A whole computer, live.** The node runs a headless X session (Xvfb + a window manager + starter
  apps) with a VNC server on loopback. The panel connects a real VNC client (noVNC) to it over
  Core's WebSocket tunnel.
- **Interactive, not a view.** Pixels stream down the same socket your mouse and keyboard events go
  up. It feels like a remote desktop, because it is one.
- **Works on any node, with no new firewall rule.** The stream rides Core's existing port through a
  generic WebSocket tunnel. Nothing extra is exposed on the network; the VNC server binds loopback
  only.

<Callout type="info">
The virtual desktop is **Linux-first**: it needs the `xvfb`, `tigervnc`, and `openbox` packages
(plus `xdotool`, `scrot`, and `at-spi2-core` for Ghost) on the node. On macOS or Windows the
sidecar reports itself unavailable and the panel explains why. Managed cloud nodes can opt in at
provision time; self-hosted nodes install the toolchain with one flag.
</Callout>

## Enable it

1. **Install the Virtual Desktop app** for the node. In the desktop, open the node selector →
   **Toolkits / layers**, or the Store, and enable **Virtual Desktop** (`@ryu/desktop`). The app is
   opt-in, like Simulators and the Browser sidecar.
2. **Make sure the toolchain is on the node.**
   - **Managed (Ryu Cloud) nodes:** provision with the virtual-desktop option enabled (this sets
     `RYU_DESKTOP=1` on the node and installs the packages).
   - **Self-hosted nodes:** install with `RYU_DESKTOP=1` when running `infra/install.sh`.
   - **Local Linux:** the panel's "Enable" prompt installs the packages for you.
3. Open the **Virtual Desktop** dock panel from the right side of the workspace. It connects
   automatically and shows the node's desktop.

## Use it

- **Mouse** clicks and drags map to the virtual screen. **Keyboard** input types into the focused
  app on the desktop.
- The connection status dot in the panel header shows whether the stream is live; **Reconnect**
  re-establishes it (useful after switching nodes).
- The panel follows the **active node** — switch nodes and it reconnects to that node's desktop.

## The same screen Ghost uses

The node's `core.env` sets `DISPLAY=:99` and Core passes it to the Ghost MCP sidecar through its
environment allowlist. So Ghost's accessibility tree, screen capture, and synthetic input all point
at the same virtual display the panel shows. Concretely:

- Enable **Ghost** for the node (it is default-on and provides the `computer.control` capability).
- Ask an agent to "open the browser and search for X" — it will call `computer__*` tools, and you
  will *see* the browser open on the virtual desktop in the panel.
- Interrupt or take over by clicking and typing in the panel yourself.

There is no copy or indirection: the node genuinely has a desktop, Ghost drives it, and you watch
and share it.

## How it works under the hood

1. Core spawns the `ryu-desktop` sidecar on loopback (port `8015`), which brings up
   `Xvnc :99` (TigerVNC's `Xvnc` is both the X server and the VNC server) plus a window manager and
   starter apps, bound to `127.0.0.1:5900`.
2. The desktop panel opens `wss://<node>/api/ext/ws/@ryu/desktop/ws` — Core's generic WebSocket
   ext-proxy authenticates the node token and bridges to the sidecar.
3. The sidecar's `/ws` route is a websockify-style pump: RFB-over-WebSocket in, VNC-over-TCP out.
4. Ghost, spawned with `DISPLAY=:99`, captures and drives the same desktop through its own MCP
   tools.

Because the stream rides Core's authenticated port, no sidecar port is ever exposed on the
firewall, and nothing on the node is reachable without the node token.

<Callout type="warn">
The interactive path is live-verified at the transport level (a WebSocket bridge test round-trips
bytes through a fake VNC server), but the full stack has not been exercised against a real Hetzner
node with a real desktop session. If the panel shows "no display", check the node's virtual-desktop
toolchain and that the app is enabled.
</Callout>
