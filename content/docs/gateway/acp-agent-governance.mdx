An ACP agent is a **whole harness**, not a model behind an API. Claude Code, Codex, and Pi each own
their tool loop, native tools, permission prompts, and credentials. Routing an ACP agent through
the Gateway therefore covers separate paths: model traffic, file writes, injected tools, and hooks
can each have different enforcement.

Ryu governs an ACP agent in **four independent layers**.

```mermaid
flowchart TD
  subgraph Agent["ACP agent process (Claude Code / Codex / Pi)"]
    L[Model call] --> A1
    T[Native tool call<br/>Bash, Write, Edit] --> A2
    R[Ryu-injected tool call] --> A3
  end
  A1[["Layer 1 — egress<br/>base-URL swap"]] --> GW[Gateway: firewall, budget, audit]
  A2[["Layer 2 — native tools<br/>request_permission seam"]] --> SC[Command-approval scanner]
  A3[["Layer 3 — injected tools<br/>MCP bridge"]] --> CAT[Unified catalog + allowlist]
  A2 --> HK[["Layer 4 — plugin hooks<br/>pre_tool_use / tool_result"]]
  A3 --> HK
```

## Layer 1 — Model egress

The agent's HTTP client is pointed at the Gateway instead of the provider, so completions pass
through the firewall, spend budgets, and the audit log.

The mechanism differs per agent family because the wire formats and credentials differ, and the
constraint throughout is that **the user's subscription must survive**. Full detail in
[Gateway for any agent](/docs/gateway/gateway-for-any-agent):

| Agent | Mechanism | Credential |
|---|---|---|
| Claude Code | `ANTHROPIC_BASE_URL` → `/passthrough/anthropic` | The user's own OAuth bearer, forwarded unchanged. An API key is **never** injected, because either `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN` would take precedence over Pro/Max OAuth and flip the account onto API-key billing |
| Codex | Isolated `CODEX_HOME` → `/passthrough/openai-responses` | OAuth bearer plus `ChatGPT-Account-ID`, forwarded unchanged |
| Pi (managed) | Agent-scoped `OPENAI_BASE_URL` + gateway token, plus a `models.json` pin | Gateway token. The pin is required because Pi does not honour `OPENAI_BASE_URL` on its own |
| BYO OpenAI-compatible | Agent-scoped `OPENAI_BASE_URL` + gateway token | Gateway token |

Subscription-preserving routing for Claude Code and Codex is **on by default** for new and
auto-installed routable agents. An explicit `false` in `claude-gateway-routing` or
`codex-gateway-routing` keeps that agent's subscription egress direct. Generic BYO ACP egress is
also **on by default**: an absent `agent-gateway-routing` entry means Gateway-governed traffic, and
an explicit `false` is the direct-egress opt-out. The managed Pi remains Gateway-routed according
to its provider setting.

When the routed provider is OpenRouter, the agent-scoped URL lets the Gateway attach the ACP
agent to the request before it records OpenRouter's response-reported `usage.cost`. That keeps
ACP model spend in the same per-agent USD cap as ordinary Ryu chat. The Gateway's OpenAI tool loop
and the in-process ACP MCP bridge also emit one separate charge for each successful Composio
action; the agent's **Paid tools** budget toggle controls whether those charges count.

Native subscription passthroughs are not OpenRouter calls, so OpenRouter's generation endpoint
cannot recover their provider cost. Direct-egress ACP traffic is likewise outside Ryu's Gateway
budget. Local/self-hosted inference has no upstream billing feed and uses the configured estimate
when a local budget is enabled.

## Layer 2 — The agent's own native tools

Every ACP tool call passes through the **permission-request seam** before the agent is granted
permission to proceed, and Ryu scans it there. So Claude Code's own `Bash`, `Write`, and `Edit`
calls are governed, not merely the tools Ryu injected. A `deny` verdict rejects the permission
outright, including in a headless session that would otherwise auto-approve.

This also covers file mutation. Native coding agents edit through tools shaped
`{ file_path, content }` with no command string, so Ryu synthesizes a `write <path>` representation
and scans it. See
[Command approval and HITL](/docs/security/command-approval).

## Layer 3 — Ryu-injected tools

When the bridge is active the agent also receives Ryu's meta-tools (`tool_search`, `describe`,
`execute`, `resume`, and the `skills.*` tools) over MCP. These resolve against the
[unified tool catalog](/docs/core/unified-tool-catalog) and are gated by the agent's allowlist on
the call path. Search is open; execution is allowlisted. See
[Tool governance](/docs/gateway/tools).

## Layer 4 — Plugin hooks

Installed plugins can intercept any tool call on either plane: `pre_tool_use` can `deny` it, and
`tool_result` can `transform` the result before the model sees it. This is where per-organization
policy that is too specific for a general scanner belongs. See
[Hooks and lifecycle](/docs/extend/develop/extensions/hooks-lifecycle).

## Each layer has its own switch

The layers are independent:

- **Layer 1 is per agent family**, each with its own preference: `claude-gateway-routing`,
  `codex-gateway-routing`, the managed-Pi routing mode, and a generic per-agent toggle for BYO
  agents. Claude, Codex, and generic BYO routing default to Gateway governance; they are separate
  because turning any one off changes how a subscription credential flows, and that is a decision
  per agent, not per node.
- **Layer 2 is node-wide**, armed unless explicitly turned off.
- **Layer 3** follows whether the bridge is injected for that agent.
- **Layer 4** follows which plugins are installed and enabled.

<Callout type="warn">
  An agent with Layer 1 off sends model calls **straight to the provider**. Those calls are
  unmetered, unfiltered, and absent from the audit log. This keeps a subscription agent outside
  Ryu's egress path, but the setting applies per agent.
When you need a node where nothing is ungoverned, confirm Layer 1 for each installed agent rather
than assuming a node-level setting covers them.
</Callout>

## ACP session lifecycle and resource bounds

ACP sessions are pooled per conversation so a follow-up message can reuse the same
agent process. On a node with many old threads, that resident state can otherwise
consume memory indefinitely. The Gateway's **Agent runtime** settings put a bound
around the pool:

- **Stop idle ACP sessions after** — defaults to 10 minutes. When a session has no
  new turn for that long, Ryu tears down its ACP subprocess. The next message
  starts it again, so the first reply can take longer.
- **Maximum parallel ACP agents** — defaults to **Auto**. Core derives a
  conservative limit from the node's physical CPU cores and RAM, then queues new
  ACP sessions until a slot is available. A manual limit from 1 to 32 is available
  when the node's workload is known.
- **Keep this device awake while agents run** — on by default for local nodes.
  Ryu asks the operating system to prevent idle system sleep only while an ACP
  process is active; the display can still turn off. It does not keep a remote
  device awake.

The same settings can be written in `gateway.toml` when managing a node without
the desktop UI:

```toml
[acp]
idle_timeout_minutes = 10
# Omit max_parallel_agents for Auto; set it to 1..32 for a manual limit.
max_parallel_agents = 4
keep_computer_awake = true
```

This is built-in node enforcement, not a plugin-owned control. Plugins may observe
or report the resulting runtime state, but disabling a plugin must not remove the
resource guard that protects the node hosting every ACP agent.

## What this does not do

Ryu governs at seams the agent must pass through: its HTTP egress, its permission requests, its
injected tools. It does not contain a process that decides to ignore those seams. The
command scanner is accident prevention, not a sandbox. For untrusted code the isolation boundary is
[the sandbox](/docs/core/sandbox) and
[programmatic tool calling](/docs/core/programmatic-tool-calling), which run code in a separate
process with deny-by-default permissions.

The scanner is also **stateless per call**: it judges the command in front of it, not the session's
history. A policy like "require approval to push once this session has installed a new dependency"
is a stateful policy and is not expressible today.
