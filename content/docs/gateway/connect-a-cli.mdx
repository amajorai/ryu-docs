---
title: "Connect a Coding CLI"
description: "Point Claude Code, Codex CLI, OpenCode, Gemini CLI, and other coding CLIs at the Gateway from Desktop with a client key, and reset them to their previous settings."
---

In Desktop, open **Gateway → API & traffic → Gateway client API keys**. Create a named key, enter a
model ID, and choose **Apply** next to the CLI you use. Ryu records the previous file for **Reset**.
Reset restores the prior file only while it still matches Ryu's applied version; it refuses to
overwrite changes made afterward. A remote Ryu node cannot edit this computer's CLI files, so run
this from the local Desktop app.

Apply stores the Gateway client key in the local CLI config, and the CLI then sends its model
requests through the Ryu Gateway with that key and the selected model. This selects Gateway provider
routing and billing for that CLI, including when it previously used its own subscription or account
sign-in. The original CLI authentication file is left in place, and Reset restores the earlier
configuration. For Claude Code and Codex CLI, use the
[subscription-preserving passthrough](/docs/gateway/gateway-for-any-agent#subscription-preserving-passthrough-claude-code-codex) to
keep subscription billing instead.

After you create a client key, **Connect a local CLI** can configure Claude Code, Codex CLI,
OpenCode, Gemini CLI, Pi, Factory Droid, OpenClaw, Hermes Agent, Continue, Kilo Code, Cline CLI,
iFlow CLI, or Qwen Code with a chosen Gateway model and this key. Apply edits that CLI's user-level
config on this computer. Reset restores that CLI's previous settings when no later edits would be
lost. The key is written into the local CLI config, so keep that file private and revoke the client
key if it may have been exposed.

Each CLI's setup is described below.

For OpenCode, Apply adds a `ryu-gateway` OpenAI-compatible provider and selects the chosen model in
the global `~/.config/opencode/opencode.json` config, or the existing `opencode.jsonc`. Comments and
unrelated settings are retained. Apply includes OpenCode's schema declaration when missing so normal
CLI startup preserves the written file. Reset restores the original file exactly. Project configs
and OpenCode's custom config environment variables can override global settings; see the
[OpenCode configuration guide](https://opencode.ai/docs/config/) if requests still use another endpoint.

Gemini CLI setup updates `~/.gemini/settings.json` and `~/.gemini/.env` together. It selects
`gemini-api-key` authentication, sets the Gateway root URL, client key, model, and `v1beta` API
version, and preserves unrelated settings and environment entries. Reset checks both files for
later edits before restoring them. This uses Gateway routing instead of the CLI's native OAuth
subscription. Existing shell variables, project settings/environment files, system policy, and
workspace trust can override or prevent the global setup from loading. See the
[Gemini CLI configuration reference](https://geminicli.com/docs/reference/configuration/).

Pi setup updates `~/.pi/agent/settings.json` and `~/.pi/agent/models.json` together. It adds
the `ryu-gateway` provider with the Gateway's OpenAI Responses endpoint, the selected model,
and the client key, then selects that provider and model for new Pi sessions. Other provider
entries and settings are retained. Reset checks both files for later edits before restoring
their original contents. Project settings or a Pi agent-directory override can take precedence;
see Pi's [model configuration](https://pi.dev/docs/latest/models) and
[settings reference](https://pi.dev/docs/latest/settings).

Factory Droid setup adds a `Ryu Gateway` custom model to `~/.factory/settings.json`, selects it
as the default for new sessions, and keeps other custom models and settings. It uses Droid's
`generic-chat-completion-api` provider with the Gateway `/v1` endpoint and client key. If another
custom model already uses the selected model ID, Apply stops without changing the file. Reset
restores the original settings only if no later edits would be lost. Custom model IDs differ in
some older Droid headless releases; if a pinned release does not recognize the selected default,
choose the Ryu Gateway model from `/model` or update Droid. See Factory's
[custom model guide](https://docs.factory.ai/model-independence/byok).

OpenClaw setup adds a `ryu-gateway` OpenAI-compatible provider to
`~/.openclaw/openclaw.json`, registers the selected model in the default agent's allowlist,
and selects it as the default model. Its default-agent fallback list is cleared so the Gateway
owns fallback routing. Explicit per-agent model selections remain separate. JSON5 input is
accepted, including comments and unquoted keys; Apply writes formatted JSON. Reset restores
the exact original JSON5 bytes when no later edits would be lost. A conflicting `ryu-gateway`
provider stops Apply. Config and agent-directory overrides can take precedence; see
[OpenClaw's custom-provider guide](https://docs.openclaw.ai/gateway/config-tools/custom-providers).

Hermes setup adds a named `ryu-gateway` provider to `~/.hermes/config.yaml` and selects
`custom:ryu-gateway` as the main provider. Its client key belongs to that provider, so another
provider's key is not reused for Ryu. Main-model fallbacks are cleared so Gateway routing owns
failover; explicit auxiliary-model settings are retained. Apply rewrites YAML formatting;
Reset restores the exact original file when it has not been edited since Apply. A conflicting
provider name stops Apply. Shell variables and `HERMES_HOME`, `HERMES_CONFIG`, or profile
overrides can change which config Hermes loads.

Hermes versions supporting `session_affinity_header` send the conversation ID in
`x-ryu-session-id` for stable Gateway account selection. Older versions ignore that option;
upgrade Hermes to enable automatic conversation affinity. See the
[Hermes model configuration guide](https://hermes-agent.nousresearch.com/docs/user-guide/configuring-models).

Continue setup adds a `Ryu Gateway` OpenAI-compatible model at the start of
`~/.continue/config.yaml`. It sets the `/v1` URL, client key, and selected model for chat, edit,
and apply roles. Choose a tool-capable Gateway model for Agent mode. Existing models, rules,
MCP servers, and embedding settings remain in the config. Apply rewrites YAML formatting;
Reset restores the original bytes when no later edits would be lost. A conflicting model
name or unsupported config schema stops Apply.

The Continue CLI and IDE extensions share this format. For the CLI, use
`cn --config ~/.continue/config.yaml` to override a previously saved config selection.
In the IDE, select the local config and `Ryu Gateway` model. See
[Continue's config reference](https://docs.continue.dev/reference) and
[CLI config precedence](https://docs.continue.dev/cli/configuration).

Kilo Code setup writes a named `ryu-gateway` OpenAI-compatible provider into
`~/.config/kilo/kilo.json`, or the existing `kilo.jsonc`, and selects the Gateway model.
Enter the model's actual context and maximum output token limits in the setup row. These values
enable Kilo's context management; Ryu does not guess limits for a routing alias or custom model.
Choose a tool-capable model for coding-agent use.

Kilo's JSONC comments and unrelated settings are retained. Reset restores the selected file
exactly and refuses later edits. A conflicting `ryu-gateway` provider stops Apply. The current
Kilo CLI and its CLI-backed editor extension share this config contract; older extension releases
may use another settings store. Project configs and Kilo config overrides can take precedence.
See [Kilo's custom-model reference](https://kilo.ai/docs/code-with-ai/agents/custom-models).

Cline CLI setup targets its current version-1 provider settings in
`~/.cline/data/settings/providers.json`. It selects the OpenAI-compatible provider with the
Gateway `/v1` URL, client key, and chosen model. Other provider entries remain intact; the
previous OpenAI-compatible settings and active selection are included in Ryu's exact-file backup.
Reset restores those original bytes when there have been no later setting edits. Cline's normal
UTC `updatedAt` refresh for that provider is metadata; credential, model, URL, and other changes
still prevent Reset from overwriting the file.

This is the Cline CLI configuration contract, not the older globalState/secrets migration
shortcut or the editor extension's settings store. Unsupported provider-settings versions stop
Apply. `CLINE_DATA_DIR` or `CLINE_PROVIDER_SETTINGS_PATH` can select another store at launch;
see [Cline's CLI reference](https://github.com/cline/cline/blob/main/docs/cli/cli-reference.mdx).

Qwen Code setup uses the documented OpenAI-compatible model-provider configuration in
`~/.qwen/settings.json` with settings schema version 4. It adds a model using the local Gateway
and a dedicated `RYU_GATEWAY_API_KEY` entry, selects OpenAI authentication, and preserves other
providers and preferences. Existing conflicting model IDs or key entries require review before
Apply. Reset restores the original bytes and refuses later edits. Shell and workspace overrides
can still affect the effective connection. This setup uses Qwen Code's API-key route.
See [Qwen authentication](https://qwenlm.github.io/qwen-code-docs/en/users/configuration/auth/).

iFlow CLI setup writes `selectedAuthType: "openai-compatible"`, the Gateway client key,
base URL, and model into `~/.iflow/settings.json`. Existing preferences are retained; Reset
restores the original file when later edits would not be lost. Environment, project, and system
settings can override this file, as described in the
[iFlow configuration reference](https://github.com/iflow-ai/iflow-cli/blob/main/docs_en/configuration/settings.md).

In custom OpenAI-compatible mode, iFlow's provider-owned WebSearch, WebFetch, built-in multimodal
features, and tool-call optimization are unavailable. See the
[custom-model migration guide](https://vibex.iflow.cn/t/topic/4868).
