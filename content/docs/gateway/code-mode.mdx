"Code mode" names two different features that both pass through the Gateway. Both keep
intermediate tool results out of the model context.

- **Anthropic programmatic tool calling.** The model writes code in Anthropic's code-execution
  sandbox and calls your tools from inside it. It runs upstream.
- **Ryu code mode.** The model writes a program that Ryu runs locally. The program drives many tools
  through an injected proxy. It runs on your machine.

```mermaid
flowchart LR
  C[Your client or agent] --> GW[Ryu Gateway]
  GW -->|passthrough or OpenAI-compat chat| AN[Anthropic code execution<br/>runs upstream, calls back<br/>into your declared tools]
  GW -.->|execute / resume meta-tools| RY[Ryu code mode<br/>runs on your machine,<br/>calls the unified tool catalog]
```

## Anthropic programmatic tool calling

This is Anthropic's feature, not Ryu's. The caller declares Anthropic's code-execution tool in the
request, and marks each custom tool that generated code is allowed to invoke with `allowed_callers`.
The model then writes code that calls those tools inside Anthropic's sandbox, and only what the
program returns comes back as text.

- **No beta is inferred from your tools.** Anthropic gates these features behind opt-in beta
  identifiers sent on the `anthropic-beta` request header. Ryu forwards that header and does not
  inspect your tool types to guess a beta.
- **One beta is added for you.** The Gateway adds the extended cache lifetime beta on its own, and
  only when your request asks for a longer prompt cache than the default.
- **The hosted Gateway does not offer it.** Ryu's hosted Gateway accepts only function tools and
  the prompt caching betas (`prompt-caching-2024-07-31` and `extended-cache-ttl-2025-04-11`). A
  server tool such as code execution, or any other beta, is refused with `403`
  `feature_not_permitted`.
- **Use a self-hosted Gateway instead.** Run programmatic tool calling through a self-hosted Gateway
  with your own Anthropic key. See
  [Hosted Gateway restrictions](/docs/gateway/managed-data-plane#hosted-gateway-restrictions).
- **Code execution can only call tools declared in the request.** Anthropic documents that its
  sandbox invokes the custom tools carried in that request's `tools` array, and that tools reached
  through an MCP server are not available to generated code. Anything the program must call has to be
  offered as a plain custom tool definition.

## Ryu code mode

Ryu's version is the `execute` and `resume` meta-tools. The program runs on your machine against
your tool catalog, so it reaches every tool Ryu governs, not only the tools one request declared.

The program model, the sandbox and its bounds, the pause and resume flow, and the Gateway
exec-budget bracket around it all live in
[Programmatic tool calling](/docs/core/programmatic-tool-calling). The tools a program can reach are
governed as described in [Tool governance](/docs/gateway/tools).

## Which route to use

For Anthropic's feature, pick the route by what your client speaks.

| Your client | Route | Why |
|---|---|---|
| A native Anthropic client, for example Claude Code | The Anthropic passthrough lane | The wire format is never translated and the `anthropic-beta` header is forwarded, so a feature Ryu has never heard of still reaches Anthropic |
| An OpenAI-compatible client pointed at an Anthropic model | The standard chat route | Ryu translates the tool surface in both directions (below) |

The passthrough lane is opt-in and loopback-only. Use it for a local agent, not for a remote
integration.

- [Gateway for any agent](/docs/gateway/gateway-for-any-agent#subscription-preserving-passthrough-claude-code-codex)
  covers how to enable it, what it rewrites when the firewall is on, and its maturity caveat.
- [Loopback and internal routes](/docs/gateway/loopback-routes) lists it among the non-standard
  endpoints.

## What the chat route translates

The OpenAI-compatible chat route ([Routing](/docs/gateway/routing)) speaks OpenAI JSON to you and
Anthropic Messages to the provider, so it translates the tool loop between the two formats. A
request that names no tools is not changed by this translation.

On the way out:

| OpenAI field | Becomes |
|---|---|
| `tools[]` with a `function` body | Anthropic's `{name, description, input_schema}`. A tool that is already Anthropic-shaped, including Anthropic's own server-side tools, passes through verbatim |
| `allowed_callers`, `defer_loading`, `cache_control` on a tool | Carried to the tool's top level, where Anthropic reads them |
| `tool_choice` | `auto`, `none`, and `required` map to Anthropic's `auto`, `none`, and `any`; naming one function becomes `{"type": "tool", "name": …}` |
| `parallel_tool_calls: false` | `disable_parallel_tool_use` inside the resulting choice object |
| An assistant message carrying `tool_calls` | An assistant turn whose content is a block array, its text followed by one `tool_use` block per call |
| `role: "tool"` messages | `tool_result` blocks merged into a single user turn, which is the only shape Anthropic accepts |

And on the way back:

| Anthropic field | Becomes |
|---|---|
| `tool_use` blocks | `message.tool_calls`, with arguments re-encoded as the JSON string OpenAI callers parse |
| Blocks the OpenAI shape cannot hold, such as code-execution results | `message.ryu_content_blocks`, the original block array verbatim, attached only when one is present. Echo that assistant turn back as you received it and the blocks replay upstream, which is what lets a paused turn resume |
| `usage.server_tool_use` | Copied across unchanged, because it is how Anthropic bills server-side tools and OpenAI has no equivalent |
| `stop_reason: pause_turn` | A `finish_reason` of `pause_turn`, which is not an OpenAI value |

### Handle `pause_turn`

Code against the last row. Anthropic pauses a long-running server-tool turn with `pause_turn` and
expects the caller to resume by sending the response back. Reporting it as `stop` would present a
truncated answer as a complete one, so the Gateway passes it through and leaves the decision to you.

```mermaid
sequenceDiagram
  participant C as OpenAI-compatible client
  participant G as Gateway chat route
  participant A as Anthropic
  C->>G: chat request with tools
  G->>A: Messages request with translated tools
  A-->>G: stop_reason pause_turn
  G-->>C: finish_reason pause_turn plus ryu_content_blocks
  C->>G: same assistant turn echoed back
  G->>A: blocks replayed verbatim
  A-->>G: turn continues
```

<Callout type="warn">
  The mapping above is exercised against a stand-in upstream rather than live Anthropic credentials,
  so treat it as the intended contract and verify it on your first real run.

  Ryu's own code mode depends on a JavaScript runtime that is provisioned on demand. If that
  provisioning fails, code mode stays unavailable and the `execute` and `resume` tools are not
  offered.
</Callout>
