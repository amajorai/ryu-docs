Ryu Challenges are time-boxed build briefs for people who want to make something useful and show the work. A challenge has one clear problem, an opening and closing date, a prize pool, and a public list of past winners.

Browse the live [Challenges hub](https://ryuhq.com/challenges) to see what is open, what is coming up, and where previous credit awards went.

<Callout type="warn">
The current Web slice is a browser-backed product preview. It demonstrates the challenge, review, and award workflow with seeded data, but it does not yet write server-side challenge records or mint Polar-backed credit grants.
</Callout>

## Enter a challenge

1. Choose a live brief and read its judging lens.
2. Build a working Ryu app, plugin, workflow, or companion surface.
3. Submit the project name, a live demo or repository link, and a short explanation of the problem it solves.
4. Keep the project link available through the judging window.

The strongest entries are easy to try. Start with the friction, ship the smallest useful loop, and leave enough context for another person to understand what changed.

## Credits and judging

The preview shows the total credit pool and the amount assigned to each seeded winning place. Its local review controls demonstrate the intended judging flow, but they do not send submissions to judges or add credits to a Ryu balance.

The preview archive can show seeded challenge briefs, projects, builder handles, and placeholder awards. A real challenge service will need authenticated server-side records, review audit history, and an idempotent credit-grant integration before those values represent a live program.

## For challenge operators

Ryu administrators can create a brief with:

- a title, summary, and concrete build prompt;
- a category and opening and closing dates;
- a credit pool and number of winning places; and
- a judging lens that tells builders what the reviewers value.

The browser preview lets operators save a draft, publish a live or upcoming brief, review local project links, shortlist or decline entries, and assign a place and placeholder credit amount to a winner. The public hub and review queue read the same browser-local record; changes are not shared with other users.
