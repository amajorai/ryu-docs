---
title: "Primary Bot"
description: "Choose the bot you normally talk to on a node, with a per-user selection that never retargets existing chats"
---

Your **primary bot** is the bot you normally talk to on a connected node. Each signed-in person
has their own choice, and the node operator (a client that connects with only the node token)
has a separate one. Choosing a primary bot never moves or retargets an existing conversation,
running worker, or session; it only changes which bot your entrypoints treat as yours.

The primary bot is separate from model defaults. The model and effort a chat uses still come from
the session, project, bot, global, and lane defaults described in
[Coordinator threads](/docs/core/coordinator-threads) and the [Projects app](/docs/apps/projects).
A project's coordinator also stays owned by the Projects app, so the same project runs the same
coordinator for everyone.

## Choosing a primary bot

- **Desktop:** when a bot's own main thread (a bot main thread outside any project) is open, its
  thread bar shows a star button. **Make primary** selects that bot; on the current primary bot
  the button reads **Primary bot** and clears the choice. When you have not chosen one, the
  default bot shows **Primary bot (default)**. The button has a readable label and a pressed
  state, so the selection is not shown by color alone. Ordinary chats opened from the sidebar are
  not bot main threads and do not show the star yet.
- **API:** any client can read and change the selection with the endpoints below.
- **Browser extension:** the signed-in New Tab bar shows **Primary bot** with a bot picker, a
  star, and **Clear primary**. Its model picker follows the effective primary bot.

Clearing the choice returns you to the node's current chat default. If the bot you chose is
deleted, uninstalled, disabled, in draft, or no longer runnable for you, the choice is kept and
marked unavailable, and the node falls back to the default bot when one is available. Choose
another bot, or restore the original one, to use it again.

## Your own bot conversations

A bot's own main thread, the conversation you open from the bot itself rather than from a
project, belongs to one person. When two signed-in people open the same bot, each gets their own
main thread, and neither can read the other's. Conversations the node operator opened earlier keep
their history and workers. Project and Group main threads stay shared under the project's access
rules.

## Signed-in identity

The node decides whose selection to read or change from your verified sign-in, never from an ID
in the request. If your client sends a sign-in that the node cannot verify (for example, an
expired session), the request is refused with `401` instead of falling back to the node operator's
selection or conversations. Sign in again and retry. Desktop also refuses to read or change the
selection while signed in without a usable identity token, and asks you to reconnect your account.

## API

| Method | Path | Body | Result |
| --- | --- | --- | --- |
| `GET` | `/api/primary-bot` | none | The current selection |
| `PUT` | `/api/primary-bot` | `{ "agentId": string \| null, "expectedRevision": number }` | The saved selection |

The selection has this shape:

```json
{
  "agentId": "scout",
  "effectiveAgentId": "scout",
  "revision": 3,
  "source": "selected",
  "unavailableReason": null
}
```

- `agentId` is the bot you chose, or `null` when you have not chosen one.
- `effectiveAgentId` is the bot your entrypoints use now: your choice when it is usable,
  otherwise the default bot.
- `source` is `selected` when your choice is in effect and `default` otherwise.
- `unavailableReason` explains why your choice (or the default) cannot be used, with a recovery
  step.
- `revision` starts at `0` and increases with every change, including a clear.

`PUT` is a compare-and-set: send the `revision` from your latest read as `expectedRevision`. If
the selection changed elsewhere, the node answers `409` with `primary_bot_revision_conflict`;
read again before retrying. Sending `agentId: null` clears your choice. The body accepts no user
or project fields. Choosing a bot requires permission to run it, and a bot that is not installed
or not runnable is refused with `409` and `primary_bot_unavailable`.
