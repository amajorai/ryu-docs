---
title: "Shared Node Collaboration"
description: "Share a node with teammates, control who sees each chat and document, co-edit safely, and see your own usage"
---

A Ryu node can serve one person or a whole organization. When several people
use the same node, visibility rules decide who sees each item, saves detect
conflicting edits, and a signed user token names the person behind a request.

## Invite teammates and share a node

1. Invite people to your organization from **Members → Invite a member** (see
   [Organization access and invitations](/docs/billing/organization-access)).
   An invitation can name a team.
2. Bind the node to the organization. A bound node can be shared with the whole
   organization, with one team, or kept as one person's personal node. A
   teammate outside that scope is refused before any resource check runs.
3. Teammates connect from the node selector. Managed nodes appear
   automatically; self-hosted nodes are reachable over the private mesh (see
   [Tunnels and Private Networks](/docs/core/private-networking)).
   Ryu does not relay traffic between machines that cannot reach each other,
   so use the mesh when teammates are on different networks.

## Who can see a chat or document

Every chat, Space and document has an owner and a visibility:

| Visibility | Who can open it |
| --- | --- |
| Private | The owner, plus anyone the owner shares it with directly |
| Team | Members of the chosen team inside the node's organization |
| Organization | Everyone in the node's organization |

Organization members and admins can edit shared items; viewers can only read
them. A direct share grants read or write access to one person, and only
inside the resource's own organization. Only the owner or an organization
admin can change who has access.

The same rule applies to lists, search, the HTTP API and live rooms, so a
chat that does not appear in your sidebar cannot be opened by id or joined as
a live room either.

## Identity from every client

A node token or pairing admits a device to a node; it does not say which
person is using it. Each request on a shared node also carries a short-lived,
signed user token that names the person:

- Desktop and the web app attach it from your signed-in session.
- The CLI, Island and Raycast ask the Ryu Core on the same machine for a token
  for the account signed in to Ryu there. They never send one device's node
  token to another node to get it.
- The browser extension uses the account signed in to the extension.

When no one is signed in, a request carries no identity. On a shared node that
means it sees nothing that belongs to anyone.

### Personal nodes

On a personal node that is not bound to an organization, the person at the
machine keeps full access to their own chats and documents while signed out.
A request from another device without a user token, such as a paired phone or
a node token used remotely, sees only chats and documents that were never
attached to a signed-in account.

## Editing at the same time

- **Live documents and pages** use collaborative editing: two people typing in
  the same page merge their changes, and everyone in the room sees presence
  and cursors.
- **Agents and workflows** are saved as a whole. Each save names the revision
  it was based on. If a teammate saved in between, the save is refused with a
  conflict (HTTP `409`, code `agent_revision_conflict` or
  `workflow_revision_conflict`) that includes the current version, so you can
  reload and reapply your change instead of silently overwriting theirs.
- **Documents synced between your own devices** keep both versions when the
  same page was edited offline on two devices. The newer edit wins, and the
  other one is saved in the page's version history labelled as a sync
  conflict, so nothing is lost.

## Seeing your own usage

Node owners see the full Gateway usage log. Every other member can see the
model calls made under their own account from `GET /api/usage/me`, which
accepts optional `from`, `until` and `limit` parameters. The filter is always
your own verified account; it cannot be pointed at someone else.
