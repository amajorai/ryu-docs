This page covers how Core cuts documents into chunks and imports them from connected sources. For
retrieval modes, embeddings, and search, see [Spaces and RAG](/docs/core/spaces-rag).

## Chunking strategies

Each Space chooses how its documents are cut into chunks. A Space that has never been configured
uses the `default` strategy, which packs paragraphs word by word into chunks of at most 1,000
characters with no overlap, so existing Spaces keep their chunks unchanged.

| Strategy | What it does | Options (defaults) |
|---|---|---|
| `default` | Paragraph and word packing at 1,000 characters. | None |
| `recursive` | Splits on the coarsest separator that occurs (`\n\n`, `\n`, sentence ends, `, `, spaces, then characters), recurses into pieces that are still too long, and packs the rest into overlapping windows. | `chunk_size` (1000), `chunk_overlap` (200), `separators` |
| `markdown` | Cuts at ATX headers (`#` to `######`; `#` lines inside fenced code are ignored), then splits each section recursively. Every chunk records its header path. | `chunk_size` (1000), `chunk_overlap` (200), `include_header_path` (true) |
| `token` | The recursive splitter measured in approximate tokens instead of characters. | `chunk_size` (256), `chunk_overlap` (32) |
| `semantic` | Embeds each sentence with the Space's embedder and starts a new chunk where the distance between neighbouring sentences is above a percentile of all such distances. | `breakpoint_percentile` (95), `buffer_size` (1), `max_chunk_size` (2000) |

Set a strategy with `PUT /api/spaces/:id/chunking`. For example:

```json
{ "chunking": { "strategy": "markdown", "chunk_size": 800, "chunk_overlap": 100 } }
```

Send `{ "chunking": null }` to return to `default`. A new strategy applies to documents that are
ingested or edited after the change; existing chunks are not cut again until their document is
saved. `chunk_overlap` must be smaller than `chunk_size`, and sizes are limited to 32,000.

With `include_header_path`, a markdown chunk starts with its breadcrumb (for example
`Guide > Install`), so the chunk still says where it came from when it is retrieved on its own.
The `token` strategy uses a deterministic approximation of a GPT-style tokenizer (about four
characters per word piece, one token per punctuation mark), not a specific model's tokenizer.
The `semantic` strategy embeds every sentence, so it costs one embedding per sentence at ingest;
documents with more than 2,048 sentences fall back to recursive splitting.

Every chunk stores the splitter's metadata: its `index`, an approximate `token_count`, and, for
markdown, its `header_path`. It is encrypted on disk like the chunk text. Search results return it,
and filters can match it.

Knowledge bundles accept the same strategy object: pass `chunking` to
`POST /api/knowledge/catalog/install` to cut concept bodies with it. Without it, bundles keep the
historical splitter. A bundle cut with a strategy still exports its concept bodies exactly as they
were ingested, and each of its chunks can be filtered by `okf_type`, `concept_path`, `tags`, and
(for markdown) `header_path`.

## Connector imports

`POST /api/spaces/:id/imports/connector` reads a source directly through its API and imports it
into the Space. It needs `space.write`, answers `202` with the import record, and runs in the
background; follow it in `GET /api/spaces/:id/imports`.

| `provider` | Fields | Creates |
|---|---|---|
| `web` | `urls` (https, up to 200) | A page per HTML page (converted to Markdown); PDF, Office, CSV, and text responses go through the file import path |
| `notion` | `page_ids`, `database_ids` (ids or URLs) | A page per Notion page; a database per Notion database |
| `google_drive` | `file_ids`, `folder_ids` (ids or URLs; a folder imports its direct children) | Docs as pages, Sheets as databases, Slides as text pages, and supported files by format |
| `confluence` | `base_url`, `email`, `page_ids`, `space_key` | A page per Confluence page |
| `github` | `repo` (`owner/name`), `ref`, `path` | A page or database per Markdown, text, HTML, PDF, Office, or CSV file |

Every request also takes `title` (the history label) and `max_items` (default 50, at most 200),
which bounds the pages, files, and databases one import creates and the rows read per Notion
database.

```bash
curl -X POST "$NODE/api/spaces/$SPACE/imports/connector" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"provider":"notion","credential":"secret:NOTION_TOKEN","database_ids":["https://www.notion.so/acme/0123456789abcdef0123456789abcdef"]}'
```

**Credentials.** `credential` is a vault reference such as `secret:NOTION_TOKEN` or
`secret:/connectors/GITHUB_TOKEN`, never the token itself. It is resolved for the calling user
with the same precedence agent tools use (your user scope, then node, team, and organization), and
a missing or unreadable secret fails the request with `400`. Notion, Google Drive, and Confluence
require one; GitHub uses one when given (for private repositories); web imports take none. Store
the integration token, a Google OAuth access token, or a GitHub token as the secret value. For
Confluence Cloud, store the API token and pass `base_url` (`https://<site>.atlassian.net/wiki`)
and `email`. For Confluence Data Center, store a JSON value so the site is bound to the token:

```json
{ "token": "<personal access token>", "base_url": "https://wiki.example.com" }
```

A request cannot send a stored Confluence token to a host other than an Atlassian Cloud site or
the `base_url` stored with it.

**Network.** Requests use https only, refuse private, loopback, link-local, and cloud metadata
addresses, and pin the addresses they checked. Redirects are followed one hop at a time with
each hop checked again, and the `Authorization` header is dropped when a redirect leaves the
original host. Items that fail (an unsupported file type, a page that returns an error) are
listed in the import's `message`; the import fails only when nothing could be imported.

Imported documents are ordinary Space pages and databases: they are chunked, embedded, and
searched like any other document. The [TypeScript document loaders](/docs/extend/develop/sdk/document-loaders)
read the same sources into your own code instead of a Space.
