---

Ryu Cloud uses **prepaid USD credits**. Polar keeps the authoritative credit
meter and billing state; Ryu sends server-side usage events, reads the current
customer state, and applies the product access decision. Your balance is spent
down as work runs. When it reaches zero, managed inference pauses or falls back
to a free local model; Ryu does not bill you after the fact.

Before a managed completion starts, its output is capped at what the remaining
balance can pay for after the prompt's estimated cost. That cap is priced before
the call from an estimate of the prompt and from the Gateway's per-model price
or flat rate. The remaining balance accounts for your most recent charge and for
requests still running, so parallel requests cannot each spend the same balance.
The charge afterwards uses the real token counts, or the provider-reported cost
on OpenRouter routes, so a request can finish past zero by the difference. The
next managed request then stops or falls back until the balance is restored.

## Who owns the balance

For one-time or monthly funding restricted to standalone services, see
[Standalone service credits](/docs/billing/standalone-credits). These purchased
credits have a separate spending scope from workspace allowances and general
top-ups, while sharing the organization's usage meter.

Polar owns subscriptions, credit grants, top-up products, usage meters, and the
provider-side balance. Ryu keeps a small synchronized projection so the desktop,
web, and gateway can render and enforce the same organization state. A signed
provider event or a fresh provider-state read is authoritative; a stale browser
value is never permission to spend. Ryu pins Polar API requests to the `2026-04` contract
with the `Polar-Version` header.

Polar does not block an action when a meter reaches zero. Ryu checks the
balance before managed work and stops or falls back by the active product policy. This is enforcement, not a second
financial ledger.

## Free credit

Promotional, referral, and challenge credit is **free credit**. You never pick
it: Ryu spends it automatically, before any other credit, whenever it can.

- The model picker has one managed provider, **Ryu Router**. You choose models
  by their usual names, such as `anthropic/claude-sonnet-4.5` or `openai/o3`.
  Ryu never shows which provider served a request.
- While you have free credit, models it can pay for carry a small **Free** tag
  in the Ryu Router list. Picking a Free model spends your free credit first,
  then your plan credit, then purchased credit. Any free credit you hold can pay
  for any Free model, whichever offer or referral it came from.
- Models without the tag use your plan and purchased credit as usual. Free
  credit never pays for them, or for anything you run on your own provider key.
- The set of Free models changes over time. Ryu adds models, and a model loses
  its tag when Ryu can no longer serve it for free. The desktop app picks up
  changes within about ten minutes, with no app update.
- When the default **Auto** model is selected and you have free credit, Ryu
  picks a Free model for the request.
- Responses, the `x-routed-model` header, usage, and the credit ledger always
  show the model id you picked. The `x-provider` header reads `ryu`.
- If a Free model is briefly unavailable, Ryu serves the request through Ryu
  Router as usual instead of failing it. That request is paid with plan or
  purchased credit.

Free credit can expire. The Credits view shows one **Free credit** balance with
the nearest expiry date. In Polar-billed organizations, free credit is also
held on separate Polar meters, and the balance itself remains Polar-owned.

## Managed tool providers

Agent tool calls that run through a managed provider spend the organization's
shared credits. Treg is the default provider and Composio the fallback:

- **Treg** answers every call its catalog can serve. Each call is billed at the
  cost Treg reports for that endpoint, passed through. Endpoint prices differ, so
  the Integrations Store shows each endpoint's listed price where Treg publishes one.
  A call to an endpoint with no known price is refused rather than run free.
- **Composio** answers what Treg cannot: connected user accounts (OAuth), toolkit
  actions Treg does not list, and trigger events. It is billed at the
  [Composio rates](#composio-usage-and-zero-data-retention) below.

A tool or integration you pin to a specific provider always uses that provider.

## Composio usage and zero data retention

Managed Composio usage spends the organization's shared credits. Tool calls and
delivered trigger events have separate rates. One delivered event is billed once,
even when it starts several agents or workflows. Polling is not a delivered event.

| Usage | Managed OAuth apps | Own OAuth app or API credentials |
|---|---:|---:|
| Tool calls | $0.0005 per call | $0.0003 per call |
| Delivered trigger events | $0.005 per event | $0.003 per event |
| Direct execution outside a Session | +$0.0001 per call | +$0.0001 per call |
| Enabled zero data retention add-on | +$0.0001 per tool call | +$0.0001 per tool call |

Premium or Instant tools using Composio's provider accounts carry a separate
provider charge. Ryu uses the exact reported USD amount, which already includes
Composio's provider fee. It does not estimate premium charges from toolkit names
or add that fee a second time. Tool discovery and meta operations are free.
Other enabled Composio add-ons can add to the call price.

These are usage rates, not a free allowance for each Ryu organization. Composio's
allowances and monthly plan credit belong to the upstream Composio account.
Its Hobby plan stops at its caps; Composio Pro is required for paid overages.

OpenRouter ZDR is required for every Ryu plan. Requests exclude data-collecting
providers and restrict inference to ZDR endpoints. Credits use the actual reported
provider cost, with no separate Ryu ZDR surcharge.

<Callout type="warn">
  Composio ZDR is behind a global rollout flag that is off by default. While it is
  off, no ZDR surcharge is billed. Once it is on, the $0.0001 tool-call surcharge
  applies equally to every organization, with no user opt-out or plan gate.
  **Gateway > Integrations** shows the current rollout status. Direct managed calls
  cost $0.0006 before rollout and $0.0007 after rollout, before premium charges.
</Callout>

ZDR has limited coverage. Composio excludes triggers, sandbox, staged files, and
managed OAuth apps on Pro from full ZDR coverage. Instant tools do not store their
payloads at Composio, but their underlying providers may retain data. Audit and
billing metadata remain available. OpenRouter's ZDR option restricts inference to
eligible provider endpoints; it does not govern tools, plugins, or Ryu's own logs.

See [Composio pricing](https://composio.dev/pricing),
[Composio ZDR coverage](https://docs.composio.dev/docs/security/zero-data-retention),
and [Composio Instant tools](https://docs.composio.dev/docs/instant-tools).

## How credits work

1. **Included pool:** Teams and Business receive one shared grant each billing
   period. It is use-it-or-lose-it and does not roll over; Teams adds $50 for each
   started five-seat bundle, while Business grants one $100 pool for five
   through nine seats and adds another at each completed five-seat bundle.
2. **Top-up balance:** an organization owner or billing manager can buy additional
   credits without a managed plan. No-plan purchases use the 27% base deposit
   fee with a $5 minimum; active managed plans use their discounted rate.
   Top-ups roll over and never expire. A positive prepaid balance enables
   Ryu-managed Gateway inference without a monthly pool or a separate Ryu node;
   requests stop when eligible balance is exhausted. This balance does not grant
   unrelated product entitlements.
3. **Spend order:** free credit is spent first on models marked Free, then the
   expiring included plan pool, then redeemed gift balance, then your paid
   rollover top-up balance.

The Credits view keeps these sources separate. **Available now** is the total;
it includes your free credit, remaining plan credits, gift balance, and
on-demand credits. Free credit is shown as one balance with its nearest expiry
date.

| Balance | What it means | Where it can be used |
|---|---|---|
| **Free credit** | Promotional, referral, and challenge credit | Used automatically, first, on Ryu Router models marked Free; never on other models or your own provider keys |
| **Plan credits** | The remaining included credit from the current plan | Managed providers and eligible first-party metered work; resets at the next billing period and does not roll over |
| **Gift balance** | A credit gift or gift card redeemed to your personal workspace | Credit gifts expire 12 months after redemption; gift cards do not. Gift balance is spent before paid top-ups |
| **On-demand credits** | Credit purchased by an organization owner or billing manager | Managed Gateway inference; other first-party products only where their own access and metering are enabled; paid top-ups roll over between billing periods |

Info icons beside each balance explain the rule in the product. Free credit is
spent first on models marked Free, followed by plan credit and then on-demand
credit. Free credit is part of the total, not an extra balance to add on top.

Before payment, the Credits page shows a **Current → After top-up** preview with
your wallet balance and the amount that will be added. Continue to checkout only
after the balance change looks right; the deposit fee is shown as an extra
payment-side charge and does not reduce the face value credited to the wallet.

Every card-funded action requires an enrolled authenticator. Entering the current authenticator-app
code is required in a blocking confirmation dialog before a manual top-up, automatic-recharge
change, plan change, or purchase can be submitted. Email codes are not accepted for billing, and an
account without 2FA must enroll before it can spend or move money.

Checkout APIs also require an `Idempotency-Key` header. Keep the same key when
retrying a request so a timeout cannot create a second checkout; the web and
desktop clients generate this header for you.

After checkout, Ryu returns to a receipt printer that feeds the payment confirmation
through its output slot, then shows **Receipt ready**. Reduced-motion preferences show the paper
immediately. The animation confirms the receipt presentation; wallet settlement can still be syncing. The
signed Polar webhook is the normal fast path. The return page also sends the opaque checkout id to
Ryu, which re-reads the provider checkout and paid order before applying the same idempotent ledger
write, so credit still lands if the webhook is delayed. Until the provider order is visible, the receipt says the wallet is syncing instead of
claiming credit that has not been verified. The Credits page refreshes the provider state when the
payment settles.

A top-up adds wallet credit without changing your plan, so returning from it shows only the
receipt, not the plan confirmation and welcome card that follow a plan purchase.

Closing the receipt page stops its local verification retries. Reopening the receipt
or refreshing Billing can check again; leaving the page does not cancel a payment.

Top-ups require a valid provider settlement amount. Missing or malformed payment amounts do not grant wallet credit, and the credited amount cannot exceed the verified settlement. Checkout metadata alone is insufficient to increase a balance.

Ryu's automated fraud checks pause manual top-ups (new checkouts) for up to 24
hours when an organization or the paying account shows a pattern typical of
card testing, such as several small top-ups within an hour or repeated failed
automatic top-ups. While paused, a top-up request returns `429` with
`code: "topup_temporarily_unavailable"` and a `Retry-After` header; credit you
already hold is unaffected. A Ryu reviewer looks at every pause. Contact support
if you think one is a mistake: when a reviewer agrees, the pause ends at once and
the same check does not pause your organization again for the period they set.

## Included pool

| Plan | Monthly pool |
|---|---:|
| Free | $0 |
| Pro | **$14/mo for one personal workspace** |
| Max | **$30/mo for one personal workspace** |
| Teams | **$50/mo for each started five-seat bundle ($50 at 5 billed seats, $100 at 6–10), pooled across the organization** |
| Business | **$100/mo for 5–9 billed seats; +$100 at each completed five-seat bundle, pooled across the organization** |
| Enterprise | Contracted |

Pro and Max are public individual managed plans with fixed personal pools. A
separately issued private individual offer uses its own fixed pool and recorded
pricing version; changing the public parent-plan price does not rewrite that
private contract.

A Major Pass and the local desktop license do not include a monthly managed
credit pool. Owners and billing managers can still buy manual prepaid credits for managed
Gateway use. Automatic top-up remains limited to organizations with an active
managed plan.

The deposit fee is **26.5% on Pro** and **26% on Max, Teams, and Business**, with
a **$5 minimum**. Without a managed plan, the base fee is **27% with the same
$5 minimum**. The fee is added to the amount credited: a $5 top-up credits $5
and charges $10 at the minimum fee. This fee covers provider funding and
payment costs; model usage itself is metered at cost with no per-token markup.
OpenRouter routes bill the provider-reported cost. Other routes bill from the
Gateway's per-model price table, or from a flat estimate recorded as estimated
on the charge's credit ledger entry; see
[Metering rates](/docs/billing/metering#models).

The included pool is attached to the organization's pricing version and shared
across its seats, workflows, and agents. It is calculated from **billed** seats,
not from private negotiated capacity. Teams receives $50 at five seats and $100
at six through ten; Business receives $100 at five through nine and $200 at ten
through fourteen. If Ryu changes the public price and pool in the future, existing
organizations keep the snapshot attached to their agreement.

## What the included pool can pay for

Teams and Business included pools are the organization's unrestricted subscription balance. They
can fund eligible managed provider inference and first-party metered work such
as tool calls, media, sandbox runtime, and Ryu-hosted services when those
surfaces are enabled for the deployment. The pool is shared across the
organization; it is not locked to one agent.

### What a monthly pool roughly buys

The [pricing page](https://ryuhq.com/pricing) shows how far each public plan's pool goes if you
spend all of it on one kind of usage. These are estimates: credits are shared
across all your usage, so spending on one thing leaves less for the others.

| Plan pool | Agent steps | Small Box running hours | Composio tool calls |
|---|---:|---:|---:|
| Pro, $14 | ~9,000 | ~560 | ~28,000 |
| Max, $30 | ~19,000 | ~1,200 | ~60,000 |
| Teams, $50 per 5 seats | ~32,000 | ~2,000 | ~100,000 |
| Business, $100 per full 5 seats | ~64,000 | ~4,000 | ~200,000 |

An agent step here is 20k input tokens, 70% of them cached, plus 1k output tokens
on DeepSeek V4.1 Flash, about $0.0015 a step. Box hours use the current small
Box rate (2 vCPU and 4 GiB at $0.0250 an hour while running), and tool calls use
the managed-app Composio rate of $0.0005 a call.

## What credits cover

Credits cover managed model inference, agent tool calls, image/video generation,
audio, voice recognition, sandbox compute, and Ryu-hosted Box, Notify, Passport,
Connect, and Messaging usage, plus Mail sends beyond a paid plan's allowance. Model usage is
metered at cost by default (provider-reported cost where the provider reports
one, otherwise the Gateway's configured per-model price or a flat estimate); a
provider-level billing policy can explicitly select raw-cost pass-through or
inherit the Gateway's configured markup. See
[Metering rates](/docs/billing/metering) for the current unit details.

### Ryu-hosted service usage

Hosted service usage is settled hourly from each service's usage report and
charged with no pool, so the included plan pool is spent first, then gift
balance, then top-up credit. Free allowances are per organization per calendar
month (UTC). Self-hosted services are never billed by Ryu.

| Service | Rate | Free each month |
|---|---|---|
| Box | Small, default, or large: **$0.025, $0.04 or $0.07 per hour** while running, per minute with a 5-minute minimum per start (a resume within the hour already paid owes no new minimum); **$0.05** per GiB-month of saved workspaces and snapshots | 25 GiB of Box storage per organization on a paid plan, 10 GiB without one |
| Notify | **$0.10** per 1,000 accepted events | 10,000 events |
| Passport | **$0.10** per connection-month (30 days) and **$0.10** per 1,000 upstream fetches | 5 connection-months and 10,000 fetches |
| Connect | Each direct Composio execution at the [Composio rates](#composio-usage-and-zero-data-retention); each direct call of a toolkit Connect serves natively at **$0.40** per 1,000 calls (a native call Ryu Core makes through Connect is charged as a Composio tool call) | None |
| Mail | **$1.00** per 1,000 recipients beyond a paid plan's monthly allowance | The plan's allowance |
| Messaging | Each message and 30-day phone number lease at the [AWS End User Messaging price](https://aws.amazon.com/end-user-messaging/pricing/), with no markup | None |

Box create and resume from the Ryu dashboard need a plan pool or a positive
balance, and running Boxes are stopped within minutes when credits run out, even
ones started through the Box service's own API. Notify, Passport, and Connect keep working and can
take the balance below zero; low-balance alerts and automatic top-up apply.
Mail overage is charged only from a positive balance; otherwise a send beyond
the allowance is refused. Messaging is charged per message rather than hourly:
each send or lease holds its maximum price first and is refused when the
available balance cannot cover the hold, so it never goes below zero. See
[Metering rates](/docs/billing/metering#ryu-hosted-services).


A Claude Code or Codex task that runs on your own Claude or ChatGPT plan uses that plan's usage,
not Ryu credits. When such a task runs in a Ryu Box, the Box time is still billed in Ryu credits.
See [Cloud sessions on your own plan](/docs/surfaces/desktop/user-guide/cloud-sessions-on-your-plan).

## When credits run out in chat

Chat stops the failed turn instead of leaving it spinning or presenting an
empty assistant reply. The error card stays in conversation history and includes
a **Retry** action for after you restore capacity or change models.

- **Ryu managed OpenRouter** shows **Ryu credits exhausted**. Open **Settings →
  Credits** to top up, or select a BYOK or local model before retrying.
- **OpenRouter BYOK** shows **OpenRouter credits exhausted**. Refill the
  OpenRouter account connected to that API key, or select another provider
  before retrying. BYOK spend remains on the provider account and never consumes
  the organization's Ryu wallet.

Sending a different follow-up also clears the stopped error state, so the
conversation does not remain locked after a provider rejects one turn.
