Every fresh install gets a **7-day local desktop trial**: a trial of local power
features, not of a Teams subscription. After it ends, without an active
subscription or desktop license key, those features sit behind a **soft,
dismissible paywall**; closing it drops you into free local chat.

## The trial

- **Length**: 7 days from first launch
- **What you get**: the full desktop app's local power features
- **What it does NOT include**: managed inference, credits, and cloud servers. Those
  are billed monthly through an individual Pro/Max plan or a shared Teams,
  Business, or Enterprise agreement, never through this desktop trial.
- **No card needed**: the trial starts automatically on first launch
- **After expiry**: the paywall appears. You can dismiss it to continue with free local chat.

## Desktop onboarding offer

When onboarding identifies a useful first workflow and the workspace is not
already subscribed, the desktop shows the offer that matches the workspace
ownership boundary. A personal workspace can start Pro checkout:

- **Personal Pro**: $49/month for one person; Max remains available from Pricing.

An organization owner or admin can start the Teams offer from the desktop:

- **First month**: $50
- **From month two onward**: $250/month at the five-seat Teams floor

Polar applies the first-month discount. Ryu confirms the subscription status
before creating the suggested first task, so canceling checkout never starts a
task by accident. Existing subscribers skip this offer.

<Callout type="warn">
  A trial is not a Teams subscription. Everything in the trial runs **on your own machine** at no cost to us, which is exactly why we can give it away. Anything we pay a recurring bill for (Ryu-managed models, pooled credits, a hosted server) requires a subscription.
</Callout>

## Access decision logic

The desktop app resolves access in this order:

1. **Active subscription** → Pro, Max, Teams, or Business unlocked, managed inference enabled
2. **Valid desktop license key** → desktop features unlocked, no managed inference
3. **Beta free flag** → desktop features unlocked (beta), no managed pool — break-glass only, off by default
4. **Inside the 7-day local desktop trial** → desktop features unlocked, no managed pool
5. **Offline + fresh cache** → Ride the cached entitlement (offline grace window)
6. **Otherwise** → Paywalled (free local chat stays usable)

## The paywall

The paywall is **soft**: it's a dismissible modal, not a hard block. Dismissing it drops you into free local chat with Band 1 features (local/BYOK chat, starter agents, tool calling, MCP, skills). The managed free path applies the numeric starter caps documented in [Free-tier limits](/docs/billing/limits); a self-hosted deployment remains operator-controlled.

The paywall shows:

- Trial countdown (if still in trial)
- Current access state (subscription, license, trial, locked)
- Upgrade / manage actions

## Offline grace

When the control plane is unreachable (network down, server error), the app uses a **cached last-good entitlement** for up to **7 days**. This prevents a paying user from being falsely locked out by a flaky network.

The cache stores:

- `proUnlocked` — the resolved Pro state at cache time
- `managedInference` — whether managed inference was enabled
- `plan` — the plan id (if any)
- `cachedAtMs` — when the cache was written

After 7 days offline, the cache expires and the app falls back to free local chat.

## Self-hosted Ryu Server

The commercial access model applies to Ryu's managed path. A self-hosted Ryu server
is the customer-operated Core + Gateway runtime and does not require a Ryu
account or Ryu-operated backend:

- **No Ryu commercial caps** — the operator controls local limits and policy.
- **Local/BYOK inference** — use local models or provider keys owned by the operator.
- **No managed inference** — Ryu's hosted provider fleet is not part of this path.
- **CLI/SDK access** — connect directly to the server without the account-backed product shell.

The ordinary Desktop build is an optional Console client and currently starts
behind an account session. It therefore needs a compatible Better Auth/control
plane for a fresh Desktop login, even when the active server is self-hosted. A
Private/Full Ryu Deployment can provide that control plane; a backend-free
deployment should use the CLI/SDK until a local-only Desktop identity mode is
introduced.

## License key validation

Desktop license keys are validated via `POST /api/billing/license/validate`. The
key is stored locally and checked on app launch. A valid license:

- Unlocks all Band 2 features (Pro feature set)
- Does **not** enable managed inference (Band 3)
- Does **not** provide Agent Inboxes (Band 3)
- Includes one year of app updates
