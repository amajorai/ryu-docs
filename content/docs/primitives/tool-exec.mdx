## What it is

The programmatic-tool-calling (PTC) code-execution sandbox — where a model-generated tool
call becomes a *real, isolated* program run. It executes model-authored code (and
shell-style tool calls) through a **Deno subprocess backend** with:

- **deny-by-default permissions** — nothing is granted unless the run spec says so,
- **real process isolation** — kill-isolation so a runaway run can't take the node down,
- **tool-call bridging** back to the host, and
- **exec budgets** enforced against the Gateway.

This is the difference between "the model typed some code" and "the model actually ran it,
safely."

## Swap seam

In-process by default, consumed as a non-optional path dependency (Core's sidecar, session,
and eval-code data paths reach it unconditionally). See the
[sandbox](/docs/primitives/sandbox) primitive for the general-purpose `run(command|wasm)`
seam this execution model builds on.
