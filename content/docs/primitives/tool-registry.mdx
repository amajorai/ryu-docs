## What it is

The unified tool-catalog primitive (#474). One contract for describing every tool an agent
can call — built-in, MCP, plugin, or Composio — so search, describe, and permission checks
share one vocabulary:

- **Contract-1 descriptor types** — `ToolKind`, `ToolDescriptor`, `DescribedTool`,
  `DescribedArg`.
- **`ToolRanker`** — the swappable ranking seam: BM25 by default, with an
  embedder-backed Semantic seam.
- **Argument-schema parsing** and the pure search/describe bodies over `ToolDescriptor`.

Without it, every surface would invent its own tool shape and agents couldn't share a
catalog.

## Swap seam

The semantic embedder injects via the narrow `ToolEmbedder` trait. The
`RegistryTool`→`ToolDescriptor` ingest adapter, built-in server inventory classification,
Composio live fetch, and registry-driven embedder choice stay Core-side
(`apps/core/src/sidecar/mcp/catalog.rs` + `apps/core/src/tool_registry_host.rs`). In-process
by default, consumed as a non-optional path dependency (the `/api/tools/{search,describe}`
endpoints and the MCP-bridge tool-search meta-tool reach it in every build).

## Where it lives

`crates/core/tool-registry`

## API surface

- `/api/tools/search` and `/api/tools/describe` (see the
  [Tools API reference](/docs/develop/api-reference/core/tools)).
