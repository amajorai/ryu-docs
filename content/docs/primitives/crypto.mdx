## What it is

The encryption-at-rest primitive. Every encrypted row in Ryu — memory, vault credentials,
sessions, plugin state — goes through the `FieldCipher`: a ChaCha20-Poly1305 AEAD with a
self-describing `enc:v1:` field envelope (and a legacy-plaintext passthrough so old rows
read back cleanly).

It also owns the master-key custody ladder, the swappable chain that decides *where the
encryption key lives*:

| Tier | Custodian |
|---|---|
| 1 | Environment variable (`RYU_MASTER_KEY`) |
| 2 | OS keychain (per-profile suffix) |
| 3 | File fallback in the `~/.ryu` data dir |

The local-key → KMS swap story lives on the internal `Keychain` port, so a managed-key
deployment can replace the whole ladder without touching cipher callers.

## Swap seam

Kernel couplings — the profile-scoped keychain suffix and the data dir — invert through the
narrow `CryptoHost` trait that Core installs at boot. The crate itself has zero dependency
on `apps/core`. In-process only: it is a function-call hot path on every encrypted
read/write, never IPC.

## Where it lives

`crates/core/crypto` — re-exported from Core as `crate::crypto`.

## Uses it

- [Memory](/docs/primitives/memory) encrypts every row with the shared master key.
- [Vault](/docs/primitives/vault) seals per-domain credentials with the `enc:v1:` envelope.
- Gateway [governance](/docs/primitives/gw-governance) builds on the same cipher types for
  manifest signing and verification.
