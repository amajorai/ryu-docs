---
title: "On-Device Models"
description: "Download, run, cancel, and remove the curated GGUF models that Ryu Mobile runs on the phone through llama.rn."
---

Ryu Mobile can run a language model on the phone itself, with no node involved in the answer. This
page explains which models you can download, how downloads behave, and how local chat works.

## Available models

The **Models** screen starts with two curated models:

| Model | Quantization |
| --- | --- |
| SmolLM3 3B | Q4_K_M |
| Qwen3 4B | Q3_K_M |

Model weights are never bundled with the app. Nothing downloads until you choose a model, and the
app does not download weights in the background on its own.

## Requirements

`llama.rn` is a native module, so it is compiled into a native development client or an EAS build.
Installed iOS and Android apps use the native downloader, local chat, inference engine, and device
tools. Expo Go and the browser build do not load the native module. Browser-local AI is a separate
path; see [Browser local models](/docs/browser-extension/local-models).

## Download a model

1. Open **Models** and choose a curated model.
2. Choose **Download**. The weights go into the app's own storage on the phone.
3. Wait for the download to finish, then open local chat.

How downloads behave:

- A download that stopped after saving part of the file resumes from that part.
- Split GGUF files are supported.
- Each download writes to a temporary file first and moves into place only when it is complete.
- **Cancel** stops the transfer and removes its temporary file. Models that already finished stay
  in storage.
- If a transfer fails, Models shows an error. The model stays available for another **Download**,
  and your other models are not touched.
- **Delete** removes a downloaded model from the phone.

When a run needs a copy of the model on the node, Core stages it there. The Models screen shows
Core's downloads and the phone's own download in one list, with the same states and progress.

## If the download list cannot load

If Mobile cannot read the selected node's downloads, it shows **Could not load downloads** and
**Retry**. Retry stays unavailable while a request is still pending.

If Core refuses to cancel a download, **Could not cancel download** appears and the task stays in
the list. Choose **Retry** to send Cancel again. A cancelled Core task leaves the list; downloads
to the phone keep their own state.

When you switch nodes or disconnect, Mobile shows only the newly selected node's downloads. A late
answer from the earlier node cannot replace them. Downloads to the phone stay visible.

## Keep downloaded models

Downloaded models stay available after app updates that keep app data, even if the system moves the
app's storage folder. Ryu checks for the model files before it opens local chat. Removing the app or
clearing its data can remove the weights; download the model again if its files are gone.

## Local chat

- Answers stream into the conversation as text. Model reasoning and tool requests stay separate
  from the answer, so a tool-only reply does not add tool markup to the chat.
- **Stop** also works while a turn is still preparing its prompt. While stopping, Ryu shows
  **Stopping…** and keeps the composer unavailable until the work finishes.
- The composer moves with the keyboard so the prompt and Send stay visible.

Which tools a local model can use is described in
[Tools and privacy](/docs/mobile/tools-and-privacy).
