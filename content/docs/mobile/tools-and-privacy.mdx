The local model can use Ryu and MCP tools only through Core's typed MCP and approval APIs when a
node is reachable. Offline runs hide remote tools and keep native Mobile tools available.

The native registry covers device status, navigation, notifications, haptics, camera and media,
sharing, clipboard, user-selected files, contacts, calendar, BLE discovery, and Ryu-owned
background tasks.

## Permissions and confirmations

Every descriptor declares its risk, OS permission, foreground requirement, offline availability, and
confirmation policy. Sensitive reads and all writes show an in-app confirmation card by default.
The card puts a first-person question such as “Can I read the current battery and power state?”
above the plain-language summary, then offers the decision.

Results and tool arguments are redacted before local transcript persistence. Local `local:`
conversations are separate from Core conversations and only cross that boundary when the user
explicitly copies content.

## Offline behavior

When the device is offline, remote tools are unavailable and the native registry remains available
only for operations that the current build and permission state support. An unavailable capability
is shown as unavailable; it is not treated as a successful tool call.

## Host detection

Feature-detect native actions through `host.capabilities`. A plugin must not infer iOS or Android
behavior from the user agent. See [Native bridges](/docs/extend/develop/extensions/native-bridges)
for the shared host contract.
