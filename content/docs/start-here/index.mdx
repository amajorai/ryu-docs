## Which Ryu product should I use?

Use [Bot](https://ryuhq.com/bot) for a managed agent experience, [OS](https://ryuhq.com/products/os)
for the desktop workspace, and [Agent](https://ryuhq.com/agent) to configure models, tools,
permissions, and nodes. Manage your organizations in [Console](https://ryuhq.com/console).
Developers build on [Platform](https://ryuhq.com/platform) through SDKs, Core, and Gateway. The
[product map](/docs/start-here/architecture/three-products) explains how these surfaces fit
together.

## What is the difference between Core and Gateway?

Core decides what runs: agents, sessions, workflows, and tools. Gateway decides what is allowed,
routed, measured, and paid for on calls it handles. Read
[Core and Gateway coverage](/docs/start-here/architecture/core-vs-gateway) before you assume that
a provider-native engine sends every model call through Gateway.

## Where can Ryu run?

Choose a managed Ryu Cloud node, a self-hosted node with Core and Gateway, or a private deployment
when you also operate the control plane. See
[self-host a Ryu server](/docs/start-here/getting-started/self-host) and
[current pricing](https://ryuhq.com/pricing).
