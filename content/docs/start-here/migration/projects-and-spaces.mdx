In Ryu, project can mean a code folder or a Projects app board. A Space is a portable source
collection. Choose the matching path so a transcript, repository, and knowledge base keep their
relationships.

## Project folders and repositories

Open an existing folder, add source folders in **Edit project**, or choose **Clone from GitHub**.
The folder remains the source of truth for code, Git history, branches, and project-local
instruction files.

`AGENTS.md` and `CLAUDE.md` are read from the project hierarchy. When importing a native agent
thread, use its recorded working directory as the destination project. If that path no longer
exists, import the transcript first and attach it after the repository is available.

See [Git Workspace & Worktrees](/docs/surfaces/desktop/user-guide/git-workspace) for source folders,
branches, worktrees, and GitHub cloning.

## Projects app boards

The Projects app is a local board for project names, owners, due dates, delivery status, and tasks.
Its public contract currently documents create and update behavior, not a cross-product
import/export format.

For an external board migration:

1. Export the source board to CSV or JSON when the source supports it.
2. Keep every source ID in your mapping.
3. Map projects, owners, due dates, statuses, and tasks before creating records.
4. Import a small board first and check ownership and deadlines.
5. Build an app-specific importer for repeatable migrations. Do not write directly to another app's
   storage.

## Space source and retrieval

Use a portable Space package when the destination should receive the source, not the source node's
embedding implementation. A package contains Markdown pages, YAML frontmatter, database schemas,
and Markdown row files.

It does not contain embeddings, vector tables, provider credentials, chat history, or session data.
Import creates the source on the destination without vectors. Re-index it with the destination
node's current embedding and retrieval configuration.

The [Spaces and RAG](/docs/core/spaces-rag) page documents file imports, connected-app imports,
portable source, and re-indexing behavior. The [portable package guide](/docs/extend/develop/extensions/portable-packages)
documents local folders, `.ryupack` archives, and pinned GitHub packages.

## Move a complete node

Use [Data Folder & Storage](/docs/surfaces/desktop/user-guide/data-and-storage) when the destination
should look like the source node. Its zip export/import moves the node's conversations, Spaces,
memory, media, models, and engine files together.

Restore is offline because it replaces live database files. A complete data backup is different from
a portable package, which moves a versioned definition and artifact tree without personal history,
session runs, memory indexes, or node credentials.

## Continue one conversation on another node

Use [RNP conversation continuity](/docs/extend/integrate/rnp) for a reviewed handoff between
configured Ryu nodes. RNP moves a bounded transcript snapshot and leaves behind files, credentials,
filesystem paths, structured tool calls, provider provenance, run state, and native ACP session IDs.
The destination does not send a turn automatically; the next message starts or resumes execution
there.
