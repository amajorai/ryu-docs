This page is generated from the typed schemas and every tracked per-app .env.example file. Each row is classified so structured-config candidates do not look like secrets, bootstrap inputs, or internal sidecar wiring.

<Callout type="info">
  **Legend.** *Required* means the app fails to start or a feature is unusable without the var in that deployment mode. *Optional* means a built-in default exists or the feature is opt-in. *Required* on .env.example rows means the example shows it uncommented for local dev - check the schema for production rules.
</Callout>

## How configuration is organized

| Layer | Mechanism | Apps |
|---|---|---|
| Typed schemas | @ryu/env (T3 env + Zod) | apps/server, apps/web, apps/native, packages/auth, db, api, email, mail |
| Env-only compatibility readers | process.env / import.meta.env / std::env | Core, Gateway, desktop/webapp/extension build inputs, cloud-bot, sidecars |
| TOML + env overrides | gateway.toml + GATEWAY_* env | apps/gateway |
| Structured node config | ryu/node-config.json + env compatibility overrides | apps/core |
| User preferences | Raycast extension prefs (not env) | apps/raycast |

Copy the matching .env.example to .env (or .env.local) in each app directory. Core reads non-secret RYU_* overrides from ryu/node-config.json; Gateway reads gateway.toml.

## Migration notes

- **Bootstrap / env:** profile, bind, data directory, config-file location, and process ports.
- **Secret / env or vault:** provider keys, tokens, passwords, private keys, and webhook secrets.
- **Build-time / env:** public bundle values and build metadata such as `VITE_*`, `NEXT_PUBLIC_*`, and `EXPO_PUBLIC_*`.
- **Internal wiring:** manifest-generated sidecar ports and child-process bridges.
- **Structured config candidate:** non-secret Core/Gateway behavior, model defaults, routing, sandbox, voice, catalog, and policy values.
- **Legacy / remove:** compatibility names that no longer have a runtime owner.

## Gap analysis

The inventory is source-driven and intentionally does not print example values. Add a
new environment variable to its owning schema or .env.example, then assign its
ownership role in `config/env-policy.json`. Do not add credentials to public docs.
