title: Environment Variables
description: Reference for the public environment variables a self-hosted Core node, the Gateway, or a CLI/SDK client reads, with defaults and examples
---

Most people do not need environment variables. Use **Settings** for a desktop node. Use
`gateway.toml` for Gateway rules. Use environment variables for startup values, secrets, or a
headless client.

This page lists public setup variables only. It does not list private cloud settings, internal
service variables, or every variable used by the Ryu monorepo. Keep secret values out of source
control.

## Core node

Set these variables when you run Core yourself.

| Variable | What it does | Example |
|---|---|---|
| `RYU_BIND` | Address and port where Core listens. Keep the default on a local-only node. | `127.0.0.1:7980` |
| `RYU_TOKEN` | Bearer token for Core API access. If unset, Core uses `secrets/node-auth.token` in the data folder, or mints one. Set a strong value before exposing Core to a network. | `change-me-to-a-long-random-value` |
| `RYU_DIR` | Data folder for the node. | `/var/lib/ryu` |
| `RYU_NODE_PUBLIC_URL` | Public base URL where a remote node is reachable. Core never derives it from `RYU_BIND`. When unset, the node does not advertise a URL. A remote node with an HTTPS value uses it for the hosted OAuth callback of [authenticated MCP servers](/docs/extend/develop/extensions/authenticated-mcp). | `https://node.example.com:7980` |
| `RYU_PROFILE` | Selects the profile: `release` (default), `dev`, `canary`, `nightly`, or `beta`. Each profile has its own data folder and port offset (see [Release channels](/docs/start-here/release-channels)). | `release` |
| `RYU_SKIP_LOCAL_STACK_INSTALL` | Set to `1` for a node that uses only provider keys. Core then downloads no local engines, models, or companion tools on its own, at startup or later. Chat uses your provider until you install a local model yourself. Installs you start from the Store still download. Requires a Core release later than v0.4.0. | `1` |

Example, running Core from a source checkout:

```bash
RYU_BIND=127.0.0.1:7980 \
RYU_TOKEN='use-a-long-random-token' \
RYU_DIR=/var/lib/ryu \
cargo run --manifest-path apps/core/Cargo.toml
```

If Core starts the Gateway for you, Core fills in the local Gateway settings. You normally do not
need to set `RYU_GATEWAY_URL` or `GATEWAY_CONFIG` yourself.

## Gateway

The Gateway reads `gateway.toml` first. These variables are for startup overrides or a simple
self-hosted setup.

| Variable | What it does | Example |
|---|---|---|
| `GATEWAY_CONFIG` | Path to the Gateway config file. Without it, a standalone Gateway reads `gateway.toml` from the platform config directory (`~/.config/ryu/` on Linux). | `/etc/ryu/gateway.toml` |
| `GATEWAY_BIND` | Address and port where the Gateway listens. | `127.0.0.1:7981` |
| `GATEWAY_MASTER_KEY` | Enables Gateway auth and protects its admin settings. Treat it as a secret. Every Gateway key must be at least 24 printable characters with no whitespace, or the Gateway refuses to start. | `$(openssl rand -hex 24)` |
| `GATEWAY_RELAY_KEY` | Inference-only bearer for agent model requests. | `gwrelay_…` |
| `GATEWAY_CORE_RELAY_KEY` | Trusted Core forwarding credential. Keep it separate from the agent relay and master key. | `gwcore_…` |
| `GATEWAY_CORE_PROOF_KEY` | Proof-only signing secret for agent identity and Core-forwarded requests; it is not a bearer. | `gwproof_…` |
| `RYU_IDENTITY_ROOT` | Secret that salts end-user hashes per organization. Optional on a self-hosted Gateway, where setting it keeps hashes stable across restarts. Only Ryu's own hosted Gateway fleet requires it. Base64 of 32 or more random bytes. | `$(openssl rand -base64 32)` |
| `RYU_GATEWAY_FLEET` | Exposure hardening for a Gateway behind a load balancer, reverse proxy or another container. When set to `1`, Gateway refuses to start with authentication off, never trusts a `127.0.0.1` caller as the local operator, and refuses `/passthrough/*` with `403`. It does not make the Gateway a hosted Ryu Gateway. | `1` |
| `OPENAI_API_KEY` | Key for the OpenAI provider. | `sk-...` |
| `OPENAI_BASE_URL` | Optional OpenAI-compatible provider URL. | `https://api.openai.com/v1` |
| `ANTHROPIC_API_KEY` | Key for the Anthropic provider. | `...` |
| `ANTHROPIC_BASE_URL` | Optional Anthropic-compatible provider URL. | `https://api.anthropic.com` |
| `OPENROUTER_API_KEY` | Key for the OpenRouter provider. | `...` |
| `OPENROUTER_BASE_URL` | Optional OpenRouter URL override. | `https://openrouter.ai/api/v1` |
| `LITELLM_API_KEY` | Key for your LiteLLM proxy. Setting it enables the `litellm` provider. | `...` |
| `LITELLM_BASE_URL` | LiteLLM proxy URL. Defaults to `http://127.0.0.1:4000/v1`. | `https://litellm.example.com/v1` |
| `LOCAL_LLM_URL` | URL for a local model server. | `http://127.0.0.1:8080/v1` |
| `RYU_AUDIT_DB_PATH` | Runtime audit-store path for a Core-managed Gateway child. Core sets this automatically to keep profile data isolated; it is not written back to `gateway.toml`. | `/var/lib/ryu/audit.db` |
| `RYU_PRODUCT_DASHBOARD_URL` | Where the Gateway's `GET /` redirects a browser. Unset, `GET /` returns a short JSON description instead. | `https://dashboard.example.com` |
| `RYU_CORS_ORIGINS` | Extra browser origins the Gateway allows, comma-separated. | `https://app.example.com` |
| `RYU_CORS_ALLOW_HOSTED_WEB` | `1` or `0` to allow or block the hosted Ryu web app origin. By default it is allowed only for a Core-managed Gateway or a hosted Ryu Gateway. | `0` |
| `RYU_AUDIT_RETENTION_DAYS` | Maximum age of local Gateway audit rows. `0` disables the age bound; default `90`. | `30` |
| `RYU_AUDIT_MAX_ROWS` | Maximum local Gateway audit rows. `0` disables the row bound; default `1000000`. | `250000` |

You can store provider settings in `gateway.toml` instead. See [Gateway configuration](/docs/gateway/configuration).

## Model and recall defaults

Set node defaults in [`node-config.json`](/docs/start-here/configuration#core-node-config) when
you run Core without the Settings UI. Each grouped path still has an environment name, and an
explicitly set environment value wins over the file.

| `node-config.json` path | Environment name | What it does |
|---|---|---|
| `models.defaultAgent` | `RYU_DEFAULT_AGENT` | Default agent ID. Defaults to `ryu`. |
| `models.defaultLlm.model` | `RYU_DEFAULT_LLM_MODEL` | Default chat model for requests that do not name a model. Fallback for the `default-agent-selection` preference. |
| `models.embedding.model` | `RYU_EMBED_MODEL` | Embedding model used for search and Space recall. Defaults to `nomic-embed-text-v1.5`. |
| `models.embedding.dims` | `RYU_EMBED_DIMS` | Embedding dimensions. Defaults to `768`. |
| `models.embedding.provider` | `RYU_EMBED_PROVIDER` | `gateway` sends embeddings through the Gateway. Unset uses the local or configured endpoint. |
| `rag.autoRecall.enabled` | `RYU_AUTO_RECALL_ENABLED` | Turns automatic conversation recall on or off. Fallback for `auto-recall-enabled`. |
| `rag.autoRecall.topK` | `RYU_AUTO_RECALL_TOP_K` | Sets how many recalled results Core can add to a turn. Fallback for `auto-recall-top-k`. |
| `rag.contextMaxTokens` | `RYU_CONTEXT_MAX_TOKENS` | Caps the context size used by a turn. Fallback for the `context.max-tokens` preference. |
| `btw.model`, `btw.effort` | `RYU_BTW_MODEL`, `RYU_BTW_EFFORT` | Fallbacks for the `btw-model` and `btw-effort` preferences (the `/btw` side-question model). |
| `models.fallbackLlm.model`, `models.fallbackLlm.baseUrl` | `RYU_FALLBACK_LLM_MODEL`, `RYU_FALLBACK_LLM_BASE_URL` | Local fallback model when the primary provider fails. Defaults `gemma2` at `http://127.0.0.1:8080`. |
| `fts.recallEnabled` | `RYU_FTS_RECALL_ENABLED` | Turns keyword-based recall on or off. Off by default. Fallback for `fts-recall-enabled`. |
| `rag.provider`, `rag.vectorStore.*` | `RYU_RAG_PROVIDER`, `RYU_RAG_VECTOR_STORE_*` | Attaches an external vector collection. See [Vector store](/docs/start-here/configuration#vector-store). |
| `graph.extractionModel` | `RYU_GRAPH_EXTRACTION_MODEL` | GraphRAG entity-extraction model. |
| `reranker.model`, `reranker.provider` | `RYU_RERANKER_MODEL`, `RYU_RERANKER_PROVIDER` | Reranker model (default `BAAI/bge-reranker`) and provider (default local). |
| `predict.model` | `RYU_PREDICT_MODEL` | Predictive-typing model. Falls back to the default model. |
| `learning.interval`, `learning.synthModel` | `RYU_LEARNING_INTERVAL`, `RYU_LEARNING_SYNTH_MODEL` | Continual-learning loop interval and skill-synthesis model. |

These remain environment variables:

| Variable | What it does |
|---|---|
| `RYU_DEFAULT_LLM_BASE_URL` | OpenAI-compatible base URL for the default chat route. Defaults to OpenAI. |
| `RYU_DEFAULT_LLM_API_KEY` | API key for the default chat route. When unset, Core uses `OPENAI_API_KEY`. |
| `RYU_ADVISOR_MODEL` | Fallback for the `advisor-model` preference (the `/advisor` reviewer model). |

An explicit request or a value in Settings wins over these defaults. See
[Node preferences](/docs/start-here/configuration#node-preferences).

overrides.

| `node-config.json` path | Environment name | Default |
|---|---|---|
| `agent.egressSsrfGuard` | `RYU_AGENT_EGRESS_SSRF_GUARD` | On. `false` disables the agent egress screen. |
| `agent.egressAllowHosts` | `RYU_AGENT_EGRESS_ALLOW_HOSTS` | Empty. Hosts that bypass the egress screen. See [Agent hardening](/docs/gateway/agent-hardening). |
| `acp.gatewayInject` | `RYU_ACP_GATEWAY_INJECT` | On. `false` lets ACP agents call their provider directly. |
| `chat.checkpointMaxAgeDays` | `RYU_CHAT_CHECKPOINT_MAX_AGE_DAYS` | `30`. `0` keeps folder snapshots indefinitely. |
| `codex.transcriptMaxAgeDays` | `RYU_CODEX_TRANSCRIPT_MAX_AGE_DAYS` | `30`. `0` keeps Codex session logs indefinitely. |
| `downloads.autoresume` | `RYU_DOWNLOADS_AUTORESUME` | Off. Set to `1` to resume interrupted downloads at startup. |
| `media.dir` | `RYU_MEDIA_DIR` | `files/media` in the data folder. Where generated images and audio are saved. |
| `features.acpDirectSpawn` | `RYU_ACP_DIRECT_SPAWN` | On. ACP agents launched with `npx` run from their installed package with `node`. `0` launches them through `npx` (`false` is not read). |
| `features.tregAgentTools` | `RYU_TREG_AGENT_TOOLS` | Off. `true` lists the `treg.describe` and `treg.call` agent tools. See [Built-in tools](/docs/core/built-in-tools). |
| `diagnostics.exportEnabled`, `diagnostics.contentMode`, `diagnostics.maxContentBytes` | `RYU_DIAGNOSTICS_EXPORT_ENABLED`, `RYU_DIAGNOSTICS_CONTENT_MODE`, `RYU_DIAGNOSTICS_MAX_CONTENT_BYTES` | Fallbacks for the diagnostics privacy preferences, which win when set. |
| `audiocpp.backend`, `audiocpp.device`, `audiocpp.threads`, `audiocpp.maxLoadedModels` | `RYU_AUDIOCPP_BACKEND`, `RYU_AUDIOCPP_DEVICE`, `RYU_AUDIOCPP_THREADS`, `RYU_AUDIOCPP_MAX_LOADED_MODELS` | Platform backend, device `0`, `4` threads, `2` loaded models. A set value overrides the engine's Settings values. |
| `audiocpp.sttModel`, `audiocpp.sttModelId`, `audiocpp.ttsModel`, `audiocpp.ttsModelId`, `audiocpp.ttsVoice`, `audiocpp.ttsVoiceFile` | `RYU_AUDIOCPP_STT_MODEL`, `RYU_AUDIOCPP_STT_MODEL_ID`, `RYU_AUDIOCPP_TTS_MODEL`, `RYU_AUDIOCPP_TTS_MODEL_ID`, `RYU_AUDIOCPP_TTS_VOICE`, `RYU_AUDIOCPP_TTS_VOICE_FILE` | The bundled audio.cpp speech models and the `alba` voice. Model and voice-file values are paths. |

## Clients

Use these variables when a CLI, MCP client, or another app needs to reach a running node.

| Variable | What it does | Default |
|---|---|---|
| `RYU_CORE_URL` | Core node URL used by the CLI or a client. | `http://127.0.0.1:7980` |
| `RYU_CORE_TOKEN` | Optional bearer token sent to Core. Clients fall back to `RYU_TOKEN`, then (for a loopback URL) the token Core minted in its data folder. | Unset |
| `RYU_GATEWAY_URL` | Gateway base URL used by a client or SDK. | Set by Core when it manages the Gateway |
| `RYU_GATEWAY_TOKEN` | Bearer token sent to the Gateway. | Unset |
| `RYU_GATEWAY_CORE_TOKEN` | Core-only trusted relay for an externally managed Gateway. | Unset |
| `RYU_GATEWAY_CORE_PROOF_KEY` | Core-only proof signer paired with `GATEWAY_CORE_PROOF_KEY`. | Unset |

For `ryu-cli`, `--node <name|url>` overrides `RYU_CORE_URL`. For an MCP client, see [MCP quickstart](/docs/extend/mcp/quickstart).

## Keep secrets safe

API keys, tokens, and master keys are secrets. Do not put real values in a committed `.env` file,
a public issue, or a client bundle. Use your host's secret store when you deploy Ryu.

If a setup guide names a variable that is not on this page, check the guide for the product or
provider that owns it. Do not copy a private cloud variable into a self-hosted deployment just
because it appears in an example.
