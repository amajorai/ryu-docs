---
title: Public environment variables
description: The environment variables you may need for a self-hosted Ryu node, the Gateway, or a client.
---

Most people do not need environment variables. Use **Settings** for a desktop node. Use
`gateway.toml` for Gateway rules. Use environment variables for startup values, secrets, or a
headless client.

This page lists public setup variables only. It does not list private cloud settings, internal
service variables, or every variable used by the Ryu monorepo. Keep secret values out of source
control.

## Core node

Set these variables when you run Core yourself.

| Variable | What it does | Example |
|---|---|---|
| `RYU_BIND` | Address and port where Core listens. Keep the default on a local-only node. | `127.0.0.1:7980` |
| `RYU_TOKEN` | Bearer token for Core API access. Set a strong value before exposing Core to a network. | `change-me-to-a-long-random-value` |
| `RYU_DIR` | Data folder for the node. | `/var/lib/ryu` |
| `RYU_PROFILE` | Selects a local profile such as `dev`, `release`, or `canary`. | `release` |

Example:

```bash
RYU_BIND=127.0.0.1:7980 \
RYU_TOKEN='use-a-long-random-token' \
RYU_DIR=/var/lib/ryu \
cargo run --manifest-path apps/core/Cargo.toml
```

If Core starts the Gateway for you, Core fills in the local Gateway settings. You normally do not
need to set `RYU_GATEWAY_URL` or `GATEWAY_CONFIG` yourself.

## Gateway

The Gateway reads `gateway.toml` first. These variables are for startup overrides or a simple
self-hosted setup.

| Variable | What it does | Example |
|---|---|---|
| `GATEWAY_CONFIG` | Path to the Gateway config file. | `/etc/ryu/gateway.toml` |
| `GATEWAY_BIND` | Address and port where the Gateway listens. | `127.0.0.1:7981` |
| `GATEWAY_MASTER_KEY` | Enables Gateway auth and protects its admin settings. Treat it as a secret. | `use-a-long-random-key` |
| `OPENAI_API_KEY` | Key for the OpenAI provider. | `sk-...` |
| `OPENAI_BASE_URL` | Optional OpenAI-compatible provider URL. | `https://api.openai.com/v1` |
| `ANTHROPIC_API_KEY` | Key for the Anthropic provider. | `...` |
| `ANTHROPIC_BASE_URL` | Optional Anthropic-compatible provider URL. | `https://api.anthropic.com` |
| `OPENROUTER_API_KEY` | Key for the OpenRouter provider. | `...` |
| `OPENROUTER_BASE_URL` | Optional OpenRouter URL override. | `https://openrouter.ai/api/v1` |
| `LOCAL_LLM_URL` | URL for a local model server. | `http://127.0.0.1:8080/v1` |

You can store provider settings in `gateway.toml` instead. See [Gateway configuration](/docs/gateway/configuration).

## Model and recall defaults

These variables set node defaults when you run Core without the Settings UI.

| Variable | What it does |
|---|---|
| `RYU_DEFAULT_LLM_MODEL` | Default chat model for requests that do not name a model. |
| `RYU_EMBED_MODEL` | Embedding model used for search and Space recall. |
| `RYU_AUTO_RECALL_ENABLED` | Turns automatic conversation recall on or off. |
| `RYU_AUTO_RECALL_TOP_K` | Sets how many recalled results Core can add to a turn. |
| `RYU_FTS_RECALL_ENABLED` | Turns keyword-based recall on or off. |
| `RYU_CONTEXT_MAX_TOKENS` | Caps the context size used by a turn. |

An explicit request or a value in Settings wins over these defaults. See [Configuration](/docs/start-here/configuration).

## Clients

Use these variables when a CLI, MCP client, or another app needs to reach a running node.

| Variable | What it does | Default |
|---|---|---|
| `RYU_CORE_URL` | Core node URL used by the CLI or a client. | `http://127.0.0.1:7980` |
| `RYU_CORE_TOKEN` | Optional bearer token sent to Core. | Unset |
| `RYU_GATEWAY_URL` | Gateway base URL used by a client or SDK. | Set by Core when it manages the Gateway |
| `RYU_GATEWAY_TOKEN` | Bearer token sent to the Gateway. | Unset |

For the Ryu CLI, `--node <url>` can replace `RYU_CORE_URL`. For an MCP client, see [MCP quickstart](/docs/extend/mcp/quickstart).

## Keep secrets safe

API keys, tokens, and master keys are secrets. Do not put real values in a committed `.env` file,
a public issue, or a client bundle. Use your host's secret store when you deploy Ryu.

If a setup guide names a variable that is not on this page, check the guide for the product or
provider that owns it. Do not copy a private cloud variable into a self-hosted deployment just
because it appears in an example.
