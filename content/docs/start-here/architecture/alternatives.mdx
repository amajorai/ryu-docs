Ryu sits at the control-plane and runtime layer around an agent. It can run a self-hosted
Core/Gateway node or use a managed node, while connecting agent engines, models, tools, memory,
workflows, and delivery surfaces.

The [Ryu README comparison matrix](https://github.com/amajorai/ryu#how-ryu-compares) is the
current point-in-time capability map. It is a scope comparison, not a benchmark of model quality,
latency, price, or security certification. `✅` means a first-class documented capability; `🟡`
means composition, configuration, or limited/preview scope; `❌` means the product's primary
documentation does not present that surface.

The hosted `eve`/Vercel path is usage-metered: Vercel charges for Function active CPU,
provisioned memory time, and invocations. Ryu's self-hosted path runs on infrastructure you
control. See [Vercel Functions pricing](https://vercel.com/docs/functions/usage-and-pricing).

## The alternatives solve different layers

| Category | Examples | Primary boundary |
| --- | --- | --- |
| Agent frameworks | [Mastra](https://mastra.ai/ai-agents), [LangChain / LangGraph](https://www.langchain.com/langgraph), [eve](https://eve.dev/) | Build agent logic and workflows in application code; hosting and governance are selected separately. |
| Local agent runtimes | [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness), [OpenClaw](https://github.com/openclaw/openclaw), [Hermes Agent](https://hermes-agent.nousresearch.com/docs/) | Run an integrated agent and gateway locally, with their own sessions, tools, channels, and credentials. DeepSeek Harness is a developer preview focused on composable agent runtime internals. |
| Meta-harnesses | [Omnigent](https://omnigent.ai/), [Cordis](https://github.com/cordiverse/cordis) | Wrap existing agent harnesses, or provide the runtime kernel for shared services, events, lifecycle, and composition. Cordis is the framework underneath DeepSeek Harness rather than a standalone hosted agent product. |
| Managed agent products | [Claude Managed Agents](https://platform.claude.com/docs/en/managed-agents/overview), [Notion Custom Agents](https://www.notion.com/help/custom-agents), [Grok Bot](https://x.ai/bot), [Hyperagent](https://www.hyperagent.com/docs/get-started), [ChatGPT Workspace Agents](https://help.openai.com/en/articles/20001143-chatgpt-workspace-agents-for-enterprise-and-business) | Host configured agents inside a vendor-controlled service, workspace, or cloud computer. |
| Cloud agent platforms | [Microsoft Foundry](https://learn.microsoft.com/en-us/azure/foundry/agents/overview), [Vertex AI Agent Engine](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/agent-engine/overview), [Vercel AI Cloud](https://vercel.com/agents) | Deploy and operate agents with a cloud provider's identity, model catalog, scaling, and observability. |

Choose the layer that matches the constraint you need to own. Ryu is for teams that want one
portable control plane above existing agents and models, with local/self-hosted and managed
deployment choices. A framework is usually the better starting point when the agent itself is the
application. A managed product is usually the shorter path when vendor-hosted execution and
vendor-specific integrations are acceptable.

## DeepSeek Harness and Cordis

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) is a useful runtime-internals
comparison for Ryu. Its [Cordis primer](https://deepseek-harness.github.io/deepseek-harness/en/reference/cordis-primer)
describes plugins as services mounted into a shared context, with typed events, dependency
injection, and reversible effects. Its session log is the source for model history, replay, fork,
resume, and telemetry.

Ryu overlaps on tools, skills, sandboxes, approvals, durable runs, and provider swapping, then
adds a cross-surface Core/Gateway boundary, tenant-aware governance, apps, channels, Marketplace
distribution, and self-hosted or managed deployment. The architectural lesson is complementary:
Ryu should adopt the same runtime invariants without treating a local in-process plugin tree as a
replacement for its distributed control plane.
