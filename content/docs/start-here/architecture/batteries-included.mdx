description: "The local models, engines, agents, skills, and tools that a fresh Ryu install prepares without an API key, and what happens when a download fails."

Ryu can prepare a local model stack during onboarding without a provider API key. Local
inference needs the downloads, the runtime installation, enough device capacity, and a successful
startup. Local inference does not turn off analytics, sync, backups, or connected network tools.

One Core routine, `install_local_stack` in `apps/core/src/sidecar/onboarding.rs`, owns every
default model download. The engines only serve these files. They never download them.

Each default below can be replaced. Each layer routes through one registry or config, so you can
replace the chat model, the embedder, the Voice Recognition or Speech Processing engine, or the
agent without changing anything else. See [Why Ryu](/docs/start-here/architecture/why-ryu) for
the "nothing hardcoded" principle.

<Callout type="warn">
  Each download step is independent, and a failed step does not stop the others. A failure
  (offline, or no prebuilt binary for the OS) is recorded as a warning. Chat still needs a ready
  local model or a configured remote model. If `llama.cpp` fails to install, the GGUF downloads
  that it serves (chat, embedding, reranker, classifier, Speech Processing) are skipped, RAG falls
  back to a local hashing embedder, and chat falls back to a configured remote route.
</Callout>

## What downloads on first run

`install_local_stack` installs `llama.cpp` first. It then registers the other steps with the
download center together. The download center decides how many files stream at once and queues the
rest. The chat model claims the first download slot. The image step runs last so it can size its
download against the remaining free disk. Each file is checksum-verified and marked installed, so
the matching sidecar becomes eligible to start.

| What | Sidecar or engine | Purpose |
|---|---|---|
| `llama.cpp` (`llama-server` binary) | `llamacpp`, and `llamacpp-embed` on port 8081 (auto-started) | Local chat and embedding runtime |
| Default chat GGUF (`gemma-4-E2B-it-Q4_K_M`) and its matching vision adapter (`mmproj`) | `llamacpp` | The default chat model, with image input |
| `nomic-embed-text-v1.5.Q4_K_M` GGUF | `llamacpp-embed` | Semantic embeddings for RAG, memory, and search |
| `bge-reranker-v2-m3.Q4_K_M` GGUF | `llamacpp-rerank` (port 8082, started on first use) | Spaces RAG reranking. A failure keeps the vector order |
| `gemma-3-270m-it-qat-Q4_0` GGUF | `llamacpp-classify` (port 8083, started when a Gateway config selects the classify tier) | The Gateway classifier tier |
| `s1-mini-q4_k_m` GGUF | `llamacpp-speech` (port 8088, started on first use) | Optional Speech Processing cleanup after Voice Recognition |
| `whisper.cpp` server and `ggml-base.en` model | `whispercpp` | Voice Recognition. A prebuilt server downloads on Windows only; on macOS and Linux, build `whisper-server` from source (`apps/core/src/sidecar/providers/whispercpp/downloader.rs`) |
| parakeet v3 ONNX speech model | `parakeet` | Alternative Voice Recognition engine |
| Silero VAD ONNX model | Voice mode | Voice activity detection. A failure falls back to the built-in energy detector |
| OuteTTS and WavTokenizer GGUFs (`llama-tts` binary) | `outetts` | Text-to-speech fallback engine |
| Kokoro 82M runtime, then its model files | TTS sidecar | The default text-to-speech engine. The model files download only after the runtime is ready |
| `stable-diffusion.cpp` server and a default image model sized to the device | `sdcpp` (started on first image request) | Text-to-image. The standard tier is about 11 GB and the lite tier about 2.8 GB. A device without enough RAM or free disk downloads nothing and needs a cloud image provider. Prebuilt servers exist for Windows x64, macOS arm64, and Linux x86_64 only |

<Callout type="warn">
  parakeet and Silero VAD *inference* are behind the off-by-default `voice-parakeet` and
  `voice-vad` build features. The model downloads run anyway, so the files are present. Without
  the `voice-parakeet` feature, parakeet transcription returns a "feature not built" error and
  whisper.cpp remains the local engine. Builds with the feature use parakeet by default. See
  [Voice engines](/docs/surfaces/desktop/engines/voice-engines).
</Callout>

The vision adapter is bound to the chat model's stem by the `<stem>.mmproj.gguf` convention, so a
multimodal default like Gemma can accept image input after its model, adapter, and runtime are
ready. A text-only default, or a failure to fetch the adapter, leaves the model chatting as text.
Engines that are not in the startup order (whisper.cpp, parakeet, OuteTTS, the reranker,
classifier, and Speech Processing servers, and `sdcpp`) are only eligible to start after install.
They run when you turn them on or when a request needs them.

## Defaults that work without a download

These ship as config or registry defaults, not downloaded files. They are active on install with
no setup.

| Default | What it is | Where to swap |
|---|---|---|
| Default agent "Ryu" | Pi with the Gateway on top; `DEFAULT_AGENT_ID` is `"ryu"` | [Agents](/docs/surfaces/desktop/user-guide/agents) |
| Founder bot "Jay Jr." | An AI twin of Ryu's founder on Ryu's engine, with a seeded Space built from his personal website; installed by default and removable | [Agents](/docs/surfaces/desktop/user-guide/agents#jay-jr-the-founder-bot) |
| Patrol | A health and security bot on Ryu's managed Pi with an hourly check and a daily report; installed by default and removable | [Agents](/docs/surfaces/desktop/user-guide/agents#patrol-watches-your-setup) |
| Ryu and pstack skills | Embedded first-party skill instructions and resources available offline | [Skills](/docs/surfaces/desktop/skills) |
| RAG strategy | Vector retrieval over sqlite-vec by default, with shipped offline GraphRAG as a per-Space choice | [Spaces and RAG](/docs/core/spaces-rag) |
| `agentbrowser` | Web browsing tool app | [Tools and connections](/docs/surfaces/desktop/user-guide/tools-and-connections) |
| `spider` | Web scraping tool app | [Tools and connections](/docs/surfaces/desktop/user-guide/tools-and-connections) |

The default agent "Ryu" manages its own Pi binary. Jay Jr. and Patrol run on that same managed
Pi. Every other built-in agent (Claude Code, Codex, Gemini CLI, bare Pi, OpenClaw) is opt-in
through the agents catalog. Onboarding detects which agent CLIs are already on PATH and offers to
add the matching agents. The catalog routes are `GET /api/agents/catalog`,
`POST /api/agents/catalog/install`, and `POST /api/agents/catalog/uninstall`. The picker at
`GET /api/agents` lists only the installed set.

## Modalities and standards

Ryu has a replaceable default for each of five modalities: chat, image generation, audio, Voice
Recognition, and Speech Processing.

Ryu supports the Agent **Skills** standard, **MCP** (Model Context Protocol), and **ACP** (Agent
Client Protocol). A fresh install can read the embedded Ryu and pstack skills. MCP tools need a
configured server and explicit agent grants before an agent can call them through the unified
registry. The larger external recommended skill-pack catalog is optional. Onboarding shows its
descriptions with all rows selected by default, and downloads only the selected collections.

<Callout type="info">
  The default agent fails to start until the managed Pi engine is installed, which onboarding
  warms but does not always install end to end on every machine. If "Ryu" reports that `pi` was
  not found, install it from the agents catalog or pick another installed agent.
</Callout>
