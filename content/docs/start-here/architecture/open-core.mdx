---
title: "Open Core"
description: "Which parts of Ryu are open source, which are proprietary, and why the split is drawn where it is"
---

Ryu uses an **open-core** model: the orchestration and control plane are open-source, while the
UX and identity layers are proprietary. The Desktop and Island source is published
source-available, so it can be read and audited, but it is not open source. The open part is the
part you need to audit and self-host. The product surface stays proprietary.

The public self-hosting contract is the **Self-hosted Ryu Node**: customer-operated
Core and Gateway, used through `ryu-cli`, the [SDK](/docs/extend/develop/sdk), or another compatible client. It does
not require a Ryu-operated account or control-plane backend. A **Private/Full Ryu
Deployment** is a separate customer-operated offering that adds the proprietary
identity and product control plane around one or more nodes.

## The licensing boundary

| Component | License | Why |
|---|---|---|
| **Ryu Core** (`apps/core`) | Apache-2.0 | The orchestration engine. Users must be able to audit, fork, and self-host the "what runs" layer. |
| **Ryu Gateway** (`apps/gateway`) | AGPL-3.0 | The control plane. AGPL prevents proprietary forks from reselling the control layer (firewall, routing, budgets, evals). |
| **Desktop** (`apps/desktop`) | Proprietary, source-available | The flagship UX surface. The product is the app, not the engine. Its source is published for reading, auditing, and local builds, not for redistribution; it is not open source. |
| **Web** (`apps/web`) | Proprietary | Marketing, auth flows, dashboard, and the `/ai` playground. |
| **Server** (`apps/server`) | Proprietary | Identity (Better Auth) and billing (Polar). |
| **CLI** (`apps/cli`, `ryu-cli`) | Apache-2.0 | Bun/OpenTUI terminal client for a Core node. |
| **Native** (`apps/native`) | Proprietary | Expo/React Native mobile app. |
| **Island** (`apps/island`) | Proprietary, source-available | Dynamic-island companion overlay, published on the same terms as Desktop. |
| **Ghost + Shadow** (`apps/ghost`, `apps/shadow`) | Apache-2.0 | Desktop automation and screen capture. Open because they touch the user's screen. |
| **SDK** (`packages/sdk`) | Apache-2.0 | Developer SDK. Must be open for adoption. |
| **Client** (`packages/client`) | Apache-2.0 | Embedding library. Must be open for adoption. |
| **Kernel contracts** (`crates/core/kernel-contracts`) | Apache-2.0 | Pure-data manifest types shared between Core and apps. |
| **Fumadocs** (`apps/fumadocs`) | Apache-2.0 | Documentation site. |
| **Raycast** (`amajorai/ryu-raycast`) | MIT | Raycast extension. |
| UI, Auth, Settings, Env, Command, and the other shared Desktop/Island packages | Proprietary, source-available | Published with Desktop and Island on the same terms. |
| **Core client, Protocol, Config** (`packages/{core-client,protocol,config}`) | Apache-2.0 | Typed Core client and shared wire/config helpers used by the CLI and the apps. |
| DB, API, Email | Proprietary | Closed packages for the identity layer; not published. |

Source-available components are licensed under the
[Ryu Commercial Source License](https://github.com/amajorai/ryu/blob/main/LICENSE-COMMERCIAL.md),
which permits reading, auditing, local builds, and contributions but not production use outside an
official binary, redistribution, hosted resale, or building a competing product. The repository's
[`LICENSING.md`](https://github.com/amajorai/ryu/blob/main/LICENSING.md) lists every unit and its
licence.

Enterprise identity follows the same boundary. The open-source Core and
Gateway can run agents and enforce control-plane policy, but organization SSO,
SCIM provisioning, provider secrets, audit export, and commercial capability
entitlements are implemented in the proprietary server/web/API layer. A
self-hosted Enterprise deployment receives a vendor-signed license whose public
key is used locally to enable the contracted capabilities; it does not expose
the signing key or turn the license into a user credential.

## The principle

The split follows one rule: **if it orchestrates, it is open. If it is the product surface, it is
closed.**

- **Core** (what runs) is Apache-2.0. Anyone can self-host, audit, and extend it.
- **Gateway** (what is allowed) is AGPL. A fork that is distributed or offered as a network service must release its source changes.
- **Desktop, Web, and Mobile** (what the user sees) are proprietary.

## Deployment units

### Self-hosted Ryu Node

The Self-hosted Ryu Node contains:

1. **Core** (Apache-2.0), the orchestration engine on port 7980.
2. **Gateway** (AGPL-3.0), the local model and tool governance layer on port 7981.
3. **`ryu-cli` and SDK clients**, the headless and programmatic entry points.

The operator owns the machine, storage, provider credentials, network, and
operational policies. Local models and BYOK providers work without a Ryu
account, Ryu billing, or Ryu-operated backend. Desktop, Web, Native, and other
surfaces may connect as clients, but they are not required to operate the node.

The Gateway is AGPL, so if you modify and distribute it, you must release your
modifications under AGPL. If you run it internally without distribution, no
copyleft obligation applies.

### Private/Full Ryu Deployment

A Private/Full Ryu Deployment adds the proprietary control plane and product
surfaces for account sessions, organizations, RBAC, entitlements, billing,
Marketplace commerce, managed inference, and hosted operations. It remains
customer-operated, but it depends on that backend.
It is separate from the public OSS node and available under the applicable
commercial terms.

## What this means for plugin authors

Plugins live in OSS Core. The plugin runtime, the manifest format, the capability broker, and
the SDK are all Apache-2.0. As a result:

- Third-party plugins can be open or proprietary. Core places no copyleft obligation on them.
- The closed desktop app stays extensible through the plugin system.

<Callout type="warn">
  The Apache-2.0 and AGPL-3.0 assignments above cover first-party code only. A full license audit
  of third-party transitive dependencies has not yet been completed.
</Callout>
