## Core concepts

### Runnable

The one contract for anything Ryu executes: it takes an input, runs, and returns an output. The
eight kinds (`agent`, `workflow`, `tool`, `skill`, `companion`, `channel`, `engine`, `policy`) are
peers, not a hierarchy. See [The Runnable Model](/docs/start-here/architecture/runnable-model).

### Session

The backend record of a conversation's run history and state. A session lives in Core, maps to one
agent, and persists across turns. See [Conversations & sessions](/docs/core/conversations-sessions).

### Conversation

A user-visible thread of messages. One conversation can span several sessions, for example when
you swap the agent. See [Conversations & sessions](/docs/core/conversations-sessions).

### Plugin / App

Both are `manifest.json` bundles that you install and enable the same way. A **plugin** adds logic
that runs inside the platform. An **app** ships its own process or surface and uses a scoped id
such as `@ryu/<app>`. See [Plugins vs Apps](/docs/extend/develop/extensions/plugins-vs-apps).

## Architecture terms

### Core

The local Rust backend (`apps/core`) that decides **what runs**: engines, conversations, memory,
tools, workflows, and scheduling. See [Core](/docs/core).

### Gateway

The model and tool control layer (`apps/gateway`) that decides **what is allowed, shared,
measured, or paid for** on the calls it handles. It exposes an OpenAI-compatible API. See
[Gateway](/docs/gateway).

### Core vs Gateway rule

Code that decides what runs belongs in Core. Code that decides what is allowed, shared, measured,
or paid for belongs in Gateway. See [Core vs Gateway](/docs/start-here/architecture/core-vs-gateway).

### Sidecar

A child process that Core downloads, verifies, starts, and health-checks, such as an inference
engine, an agent runtime, or Gateway itself. See
[Install agent runtimes](/docs/start-here/getting-started/install-sidecar).

### Capability layer

One of the runtime responsibility layers: the Core kernel, Gateway governance, shared services,
and applications. See [Capability Layers](/docs/start-here/architecture/capability-layers).

### Platform decomposition

The split of Ryu into a small Core kernel plus swappable capability packages and self-contained
apps. See [Platform Decomposition](/docs/start-here/architecture/platform-decomposition).

## Routing terms

### Plane A: model routing

Gateway picks *which model* serves one OpenAI-compatible completion. See
[Routing planes](/docs/gateway/routing-planes).

### Plane B: agent routing

Core picks *which agent* serves the turn. See [Routing planes](/docs/gateway/routing-planes).

### Smart routing

An opt-in, fail-open Gateway feature that uses a low-cost classifier to pick a model before
routing. See [Smart model routing](/docs/gateway/smart-routing).

### Auto routing

A Core feature where the auto agent resolves to a concrete agent at runtime. See
[Agent-auto](/docs/gateway/agent-auto).

### Fallback chain

An ordered list of providers Gateway tries when the primary provider fails, set as
`fallback_chain` under `[routing]`. See
[Circuit breaker and fallback](/docs/gateway/reliability#circuit-breaker-and-fallback).

## Protocol terms

### ACP (Agent Client Protocol)

The protocol Ryu uses to run agents such as Claude Code, Codex, and Pi as subprocesses. See
[ACP agents](/docs/start-here/architecture/acp-agents).

### OpenAI-compatible

Any endpoint that speaks the OpenAI `/v1/chat/completions` wire format. See
[OpenAI-compatible API](/docs/extend/integrate/openai-compat).

### MCP (Model Context Protocol)

A protocol that lets an AI host find and call tools from an MCP server. An MCP server provides the
tools and an MCP host uses them. A connection is different: it usually means a signed-in account.
See [MCP](/docs/extend/mcp).

### SKILL.md

The agent skills format: a Markdown file with YAML frontmatter that teaches an agent one task. See
[Agent Skills](/docs/extend/skills).

## Gateway subsystems

### Firewall

The request and response policy that detects PII, prompt injection, jailbreak attempts, and custom
patterns, then blocks, warns, or sanitizes. See [Security](/docs/gateway/security).

### DLP (Data Loss Prevention)

The part of the firewall that finds sensitive data in outbound content and redacts or blocks it.
See [Outbound DLP](/docs/security/outbound-dlp).

### Budgets

Per-user, per-agent, and per-session caps on charged model spend. See
[Budgets](/docs/gateway/reliability#budgets).

### Evals

Automated quality scores for single requests or datasets, which can also inform routing. See
[Evals](/docs/gateway/evals).

### Audit

The per-request trail of what Gateway decided: model, budget checks, firewall results, cache hits,
and token usage. See [Audit](/docs/gateway/audit).

### Circuit breaker

Per-provider failure tracking that opens the circuit and moves traffic to the next provider in the
fallback chain. See [Circuit breaker and fallback](/docs/gateway/reliability#circuit-breaker-and-fallback).

### Semantic cache

A cache that matches requests by embedding similarity instead of exact text. Off by default. See
[Caching](/docs/gateway/reliability#caching).

### Passthrough proxy

A Gateway proxy for Claude Code and Codex that keeps the caller's subscription and adds
request-side firewall, DLP, and audit. See
[Gateway for any agent](/docs/gateway/gateway-for-any-agent).

## Core subsystems

### Memory

Long-term facts and preferences that persist across sessions, scoped to an agent, the user, the
node, a project, or an organization. See [Memory](/docs/core/memory).

### Spaces (RAG)

Knowledge spaces of documents that agents search through semantic retrieval. See
[Spaces & RAG](/docs/core/spaces-rag).

### Workflow engine

A DAG execution engine with typed nodes and durable, checkpointed execution. See
[Workflows](/docs/core/workflows).

### Capability broker

The registry that resolves an abstract capability requirement, such as `rag`, to a concrete
provider app. See [Platform Decomposition](/docs/start-here/architecture/platform-decomposition).

### MCP registry

Core's catalog of registered MCP servers and their tools. See
[MCP registry](/docs/core/mcp-registry).

### Passport

Standalone, tenant-separated identity storage for per-domain cookies, tokens, and session state.
See [Passport](/docs/standalone/passport).

### Delegation

One agent fans out subtasks to other agents and collects the results. See
[Delegation](/docs/core/delegation).

### Goals

A persistent objective set with `/goal` that an agent pursues across turns. See
[Goals](/docs/core/goals).

### Side questions

A `/btw` question answered inline without interrupting the main conversation. See
[Side questions](/docs/core/side-questions).

## Plugin terms

### manifest.json

The manifest format for Ryu plugins and apps. See
[Plugin manifests](/docs/extend/develop/extensions/plugin-json-manifest).

### Permission grants

Host capabilities a plugin declares in `manifest.json`, such as `storage:kv`. Core validates each
grant with Gateway on enable and fails closed. See [Governance](/docs/gateway/governance).

### Activation events

Events that control when a plugin activates, such as `onStartup` or `onChat`. See
[Plugin manifests](/docs/extend/develop/extensions/plugin-json-manifest).

### Contribution points

Declarative UI and command extensions a plugin lists under `contributes`. See
[Contribution surfaces](/docs/extend/develop/extensions/contribution-surfaces).

### Companion

An in-desktop overlay or panel that a plugin or app contributes, labeled **Companion** in the UI.
See [Desktop Companion](/docs/extend/develop/extensions/desktop-companion).

## Configuration terms

### gateway.toml

The Gateway's main configuration file. See [Gateway configuration](/docs/gateway/configuration).

### Environment variables

Process settings such as `RYU_TOKEN`, `GATEWAY_MASTER_KEY`, and `RYU_DIR`. See
[Environment variables](/docs/start-here/environment-variables).

### Preference keys

Runtime settings stored by Core, such as `agent-gateway-routing` and `approval-mode`. See
[Node preferences](/docs/start-here/configuration#node-preferences).

## Protocol and data terms

### OKF (Open Knowledge Format)

A bundle format that moves spaces, documents, and embeddings from one Ryu node to another. See
[CLI reference](/docs/surfaces/cli/reference).

### Worktree

A per-run isolated git copy of the working folder, so an agent's file changes do not collide with
other runs. See [Git workspace](/docs/surfaces/desktop/user-guide/git-workspace).

### Prompt injection

An attack that hides instructions in content a model reads so the model ignores its system prompt.
See [Security](/docs/gateway/security).

### HITL (Human-in-the-Loop)

An approval gate where an agent pauses until a person confirms. See
[Approvals](/docs/core/approvals).

### PTC (Programmatic Tool Calling)

Agents call tools from code through `POST /api/tools/exec` in a sandbox inside Core. See
[Programmatic tool calling](/docs/core/programmatic-tool-calling).
