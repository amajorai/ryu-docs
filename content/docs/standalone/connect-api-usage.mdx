title: "Connect Usage Report"
description: "Read the tenant's Composio, native, vendor, and composed-tool billing receipts"

`GET /v1/usage` lists the authenticated tenant's billing receipts: one line
for each execution whose receipt Connect has read, on any execution path. For
setup and bearers, see the [Connect API](/docs/standalone/connect-api).

- It uses the runtime bearer.
- It contacts Composio only to read receipts it could not read when the call
  ran.
- Ryu's hosted billing reads this report. A self-hosted Connect serves it too
  and is never billed by Ryu.

## Request

```sh
curl -fsS 'https://connect.example/v1/usage?from=2026-10-01T00:00:00Z&to=2026-10-02T00:00:00Z' \
  -H 'Authorization: Bearer <connect-api-token>'
```

| Parameter | Rule |
|---|---|
| `from`, `to` | ISO 8601 timestamps with a time zone, both on a whole UTC hour. The window is `[from, to)`, must end after it starts, and may span at most 31 days. |
| `limit` | 1 to 1000 lines per page; default 1000 |
| `cursor` | The previous page's `nextCursor` |

Anything else, including unknown or repeated parameters, returns `400` with
`code: "invalid_request"`. Receipts are kept for 400 days, so the response's
`from` and `to` are clipped to retained data and end no later than the end of
the current hour.

## Response

```json
{
  "type": "usage.report",
  "ok": true,
  "from": "2026-10-01T00:00:00.000Z",
  "to": "2026-10-02T00:00:00.000Z",
  "lines": [
    {
      "transactionId": "log_abc123",
      "at": "2026-10-01T09:14:03.120Z",
      "usage": {
        "kind": "toolCall",
        "authSource": "managedApp",
        "directExecution": true,
        "premiumChargeMicroUsd": null
      }
    }
  ],
  "nextCursor": null,
  "unresolved": []
}
```

### Ordering and paging

Lines are ordered by `at`, the time Connect recorded the receipt, then by
`transactionId`, the Composio execution log ID that the call's `billingReceipt`
carried.

When `nextCursor` is not `null`, repeat the request with the same window and
`cursor` set to it. The cursor is a position in that order, so receipts
recorded while you page never repeat or skip a line, and a window that has
ended no longer changes.

### Which calls get a line

- Each transaction ID appears once.
- Calls refused before reaching Composio and failed provider requests have no
  line.
- A call whose receipt is not read yet gets its line once it is read, stamped
  with that time.
- A call whose receipt can never be read is listed in `unresolved` on the first
  page instead, as `{ transactionId, at, reason }` where `reason` is
  `unverifiable` or `expired` (see
  [billing receipts and metering](/docs/standalone/connect-api-billing#billing-receipts-and-metering)).
  Later pages return an empty `unresolved`.

### Line sources

Composio lines never carry `source` or `toolkit`. Other lines add one of these
`source` values.

| `source` | Added for | Extra fields | Transaction ID |
|---|---|---|---|
| `native` | Executions of a [natively served toolkit](/docs/standalone/connect-api-composio#natively-served-toolkits), as their own meter | `toolkit` | `rnx_…`, the same ID the call's `billingReceipt` carried |
| `vendor` | A vendor call that Connect paid with Ryu's key (see [the credential ladder](/docs/standalone/connect-api-relay#the-credential-ladder)); calls on your own keys have no line | `endpoint` (catalog) | `rvx_…` |
| `composed` | A [composed tool](/docs/standalone/connect-api-composed) run whose maker's fee you paid | `tool`; `usage` names the tool, its version, the maker's organization and the fee | `rcx_…` |

A native line's `usage` has the shape of a Composio own-app direct execution,
but Ryu prices these lines at the Connect native rate, not the Composio rates.

A line for a call you labelled with [builder tags](/docs/standalone/connect-api-tags)
adds `tags`, the call's tags sorted and lowercased. Untagged lines have no
`tags`.
