This reference covers `GET /v1/usage`, the Connect usage report. For setup, bearers, and request shapes, see the
[Connect API](/docs/standalone/connect-api).

`GET /v1/usage` lists the authenticated tenant's billing receipts: one line
for each execution whose receipt Connect has read, on any execution path.
Composio lines are described first; native, vendor, and composed-tool lines
follow. It uses the runtime bearer, and contacts Composio only to read receipts it
could not read when the call ran. Ryu's hosted billing reads this report; a
self-hosted Connect serves it too and is never billed by Ryu.

```sh
curl -fsS 'https://connect.example/v1/usage?from=2026-10-01T00:00:00Z&to=2026-10-02T00:00:00Z' \
  -H 'Authorization: Bearer <connect-api-token>'
```

`from` and `to` are ISO 8601 timestamps with a time zone, and both must fall on
a whole UTC hour. The window is `[from, to)`. It must end after it starts and
may span at most 31 days. `limit` is 1 to 1000 lines per page, default 1000.
Anything else, including unknown or repeated parameters, returns `400` with
`code: "invalid_request"`. Receipts are kept for 400 days, so the response's
`from` and `to` are clipped to retained data and end no later than the end of
the current hour.

```json
{
  "type": "usage.report",
  "ok": true,
  "from": "2026-10-01T00:00:00.000Z",
  "to": "2026-10-02T00:00:00.000Z",
  "lines": [
    {
      "transactionId": "log_abc123",
      "at": "2026-10-01T09:14:03.120Z",
      "usage": {
        "kind": "toolCall",
        "authSource": "managedApp",
        "directExecution": true,
        "premiumChargeMicroUsd": null
      }
    }
  ],
  "nextCursor": null,
  "unresolved": []
}
```

Lines are ordered by `at`, the time Connect recorded the receipt, then by
`transactionId`, the Composio execution log ID that the call's `billingReceipt`
carried. When `nextCursor` is not `null`, repeat the request with the same
window and `cursor` set to it. The cursor is a position in that order, so
receipts recorded while you page never repeat or skip a line, and a window
that has ended no longer changes.

Each transaction ID appears once. Calls
refused before reaching Composio and failed provider requests have no line. A
call whose receipt is not read yet gets its line once it is read, stamped with
that time. One whose receipt can never be read is listed in `unresolved` on the
first page instead, as `{ transactionId, at, reason }` where `reason` is
`unverifiable` or `expired` (see
[billing receipts and metering](/docs/standalone/connect-api-billing#billing-receipts-and-metering)).
Later pages return an empty `unresolved`.

Executions of a [natively served toolkit](/docs/standalone/connect-api-composio#natively-served-toolkits)
are listed too, as their own meter. Their lines add `"source": "native"` and
the `toolkit`, and their `transactionId` is a Connect-issued ID starting with
`rnx_`, the same ID the call's `billingReceipt` carried. Their `usage` has the
shape of a Composio own-app direct execution, but Ryu prices these lines at the
Connect native rate, not the Composio rates. Composio lines never carry
`source` or `toolkit`.

A vendor call that Connect paid with Ryu's key adds a line with
`"source": "vendor"`, its catalog `endpoint` and an `rvx_` transaction ID (see
[relay and the credential ladder](/docs/standalone/connect-api-relay#the-credential-ladder)).
Calls on your own keys have no line.

A [composed tool](/docs/standalone/connect-api-composed) run whose maker's fee
you paid adds a line with `"source": "composed"`, the `tool` id and an `rcx_`
transaction ID; its `usage` names the tool, its version, the maker's
organization and the fee.

A line for a call you labelled with [builder tags](/docs/standalone/connect-api-tags)
adds `tags`, the call's tags sorted and lowercased. Untagged lines have no
`tags`.
