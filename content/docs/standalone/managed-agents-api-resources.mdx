This reference covers how the Managed Agents write routes treat their bodies
and the limits they enforce. Every path on this page is relative to
`/api/v1/managed-agents`. For the route table and error codes, see the
[Ryu Managed Agents API](/docs/standalone/managed-agents-api).

## Resource behavior

| Route | Behavior |
|---|---|
| `POST /agents` | Only `name` is required. Creates version 1. Backend compatibility is checked later, when a session is created. A builtin tool or MCP server can set `requireApproval: true` to ask before each call ([tool approvals](/docs/standalone/managed-agents-events#tool-approvals)); only the `anthropic` backend accepts it. |
| `PATCH /agents/{agentId}` | Omitted fields keep their value. `tools` and `mcpServers` replace the stored value. `metadata` merges per key, and a `null` value deletes the key. A change that matches the latest version creates no new version. A stale `expectedVersion` gets `409 version_conflict`. |
| `POST /environments` | `config` is optional, and each backend has defaults. The credential source must match the backend. A `byok` credential must be active and belong to the same provider. The name is unique among active environments. |
| `PATCH /environments/{environmentId}` | `config` replaces the stored value. `backend` cannot change. A stale `expectedRevision` gets `409 revision_conflict`. An accepted change increments `revision` and affects only new sessions. |
| `POST /credentials` | The body is `provider`, `label`, and `apiKey`. The key is 8 to 512 characters with no whitespace. The label is unique among the organization's active credentials for that provider. |
| `PUT /credentials/{credentialId}/key` | Replaces the stored key. Sending the same key again changes nothing. |
| `DELETE /credentials/{credentialId}` | Revokes the credential. It always succeeds. |
| `POST /sessions` | `agentVersion` defaults to the latest version. `initialEvents` holds 0 to 8 `user.message` events. `budget.maxCostMicroUsd` is optional. |
| `PATCH /sessions/{sessionId}` | Changes `title` and `metadata` in Ryu only. |
| `POST /sessions/{sessionId}/cancel` | Accepts an optional `reason` of up to 256 characters. Allowed from `pending`, `running`, and `idle`. Repeating it while the cancel is in progress returns `202`; after the session is canceled it returns `200`. |
| `POST /sessions/{sessionId}/complete` | Allowed only from `idle`. Interrupt or cancel a running session first. |
| `DELETE /sessions/{sessionId}` | Allowed only for a session in a terminal status. The session disappears from reads at once, and Ryu deletes it and its events later. Repeating the call returns `204` until Ryu removes the session, usually within a minute; after that it returns `404 not_found`, which means the session is already deleted. |

Environment `config` defaults:

| Backend | Default `config` |
|---|---|
| `anthropic` | Limited networking with no extra hosts, package managers off, MCP servers allowed, and no packages |
| `openai` | `mode` `"responses"`, `codeExecutionTool` `"code_interpreter"`, a `4g` container with network disabled, no `maxToolCalls`, and no vector stores |
| `gemini` | `agent` `"antigravity-preview-09-2026"`, network disabled, and no `maxTotalTokens` |
| `ryu_node` | `timeoutSeconds` 60; `nodeId` is required |

## Limits

| Limit | Value |
|---|---|
| Agent name, session title | 256 characters |
| Description | 2,048 characters |
| Credential label | 64 characters |
| Model id | 128 characters |
| Instructions | 100,000 characters |
| Tools per agent | 64, with a 1,024-character description and a 64 KiB input schema |
| MCP servers per agent | 20, with a 2,048-character URL and 128 allowed tools each |
| Allowed domains per tool, network allowlist entries | 64 each |
| Packages per package manager | 64, with names up to 128 characters |
| Metadata | 16 pairs, with 64-character keys and 512-character values |
| Provider API key | 8 to 512 characters |
| Agents, environments, and credentials per organization | 500, 100, and 50 |
| Versions per agent, agent versions per organization | 1,000 and 10,000 |
| Active sessions per organization | 100 |
| Sessions created per organization per hour | 1,000 |
| Idle session lifetime | 7 days without activity, then the session is completed |
| Events per request, initial events per session | 8 each |
| Queued inputs per session | 32 |
| User event bytes per organization per day | 512 MiB |
| Text blocks per message, text per message | 16 blocks and 100,000 characters |
| Event size, events per session | 512 KiB and 100,000 |
| Session budget | 10,000 to 1,000,000,000,000 micro-USD |
| OpenAI `maxToolCalls` | 1 to 200 |
| Gemini `maxTotalTokens` | 1,000 to 10,000,000 |
| Node `timeoutSeconds` | 30 to 120 |

When a limit is hit:

- The agent, version, environment, and credential counts return
  `409 limit_reached`, and `details.limit` names the limit.
- Too many active sessions returns `429 session_limit_reached`.
- Sessions created per hour, queued inputs, and user event bytes return
  `429 rate_limited` with `details.limit`.

Stream and event page limits are on
[Managed Agents events and streams](/docs/standalone/managed-agents-events).
