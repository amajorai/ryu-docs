Ryu Connect is the standalone integration edge for products that need MCP
hosting, `SKILL.md` content, governed tool calls, and Composio actions. It gives
those lanes one tenant-scoped bearer boundary while preserving the existing
Ryu-native ownership seams:

| Lane | Connect owns | Execution owner |
|---|---|---|
| MCP | Native Skill resource server at `/mcp`, with optional forwarding below `/mcp/` | Connect for Skill resources; configured upstream for forwarded requests |
| Skills | Local catalog and `SKILL.md` hosting | The configured Skill source directory |
| Tools | Native tenant-bound registry and exact tool grants | Connect calls registered MCP servers directly |
| Composio | Tenant-bound account, version, credential, and tool grants | Connect calls the Composio execution API directly |

Connect serves Skill resources directly over MCP without Core or Gateway.
Initialize the server, list resources, and read a `ryu-skill:///` resource
using your Connect bearer. It uses stateless Streamable HTTP with JSON responses.
Native MCP tools and Composio actions use one discovery and execution surface.
Alternatively, a separate single-tenant compatibility mode forwards to existing
Core and Gateway upstreams. It cannot be combined with native registrations.
When a lane is not configured, its route returns an explicit unavailable
response and `/health` reports that state.

## Start Connect

```sh
RYU_CONNECT_API_TOKEN=replace-me \
RYU_CONNECT_TENANT_ID=demo \
RYU_CONNECT_SKILLS_DIR=$PWD/apps/skills \
bun run apps/connect/src/index.ts
```

The default bind is `127.0.0.1:8094`.

The default Skill directory is resolved relative to the service, so repository
startup from the Connect package works independently of the shell directory.
Set `RYU_CONNECT_SKILLS_DIR` explicitly for packaged deployments.

For compatibility mode, configure the upstreams explicitly:

```sh
RYU_CONNECT_CORE_URL=http://127.0.0.1:7980 \
RYU_CONNECT_CORE_TOKEN=core-token \
RYU_CONNECT_GATEWAY_URL=http://127.0.0.1:7981 \
RYU_CONNECT_GATEWAY_TOKEN=gateway-token \
RYU_CONNECT_MCP_UPSTREAM=http://127.0.0.1:3000 \
RYU_CONNECT_MCP_TOKEN=mcp-upstream-token \
bun run apps/connect/src/index.ts
```

The Connect bearer is never forwarded upstream. Operator-configured upstream
credentials are kept in process memory and are never returned by Connect.

## Use Connect beside Passport

### Core Composio execution

Core can hand Composio action execution to a native Connect service. Configure
Core's `RYU_CONNECT_URL` and `RYU_CONNECT_USER_TOKENS`, mapping verified Core user
IDs to their Connect runtime tokens. Local calls require an explicit `local`
mapping. Provider project keys and Connect management keys are not runtime tokens.

Core retains its policy checks and sends a selected account only as a constraint;
Connect cannot use that constraint to switch the tenant's assigned account. Remote
errors never fall back to Core's provider credential. Native execution and catalog
endpoints do not forward through compatibility mode. Core's unified tool search
uses Connect's tenant-filtered Composio catalog with the verified caller identity;
local discovery requires the same explicit `local` mapping as local execution.
Core's connection, callback, and workflow-trigger surfaces use the same Connect
management and target-binding contracts; Connect remains the owner of provider
accounts, signed ingress, and leased event delivery. Legacy Core provider
webhook routes fail closed in remote mode instead of executing outside Connect.

### Identity service

Passport owns durable identity state; Connect owns the integration edge. A
governed runtime can use Passport for a connection lifecycle and Connect for
the MCP/tool/Composio call path without copying credential material between
services.
