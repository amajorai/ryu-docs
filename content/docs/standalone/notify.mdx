Ryu Notify is a standalone notification and event API for products and agents.
It stores bounded JSON events in SQLite, exposes tenant-scoped history and
aggregates, streams events and live activities over Server-Sent Events, and
delivers through durable, retrying HTTP destinations.

Notify is not a replacement for Core's user-scoped
`/api/notifications/*` feed. Core owns Ryu users, workflow gates, desktop and
native notifications, and Expo push. Notify owns this external product API.
See [Notify parity and adapters](/docs/standalone/notify-parity) for the
supported channel boundaries and the comparison with adjacent notification
services.

## Start the service

```sh
RYU_NOTIFY_API_TOKEN=replace-me \
RYU_NOTIFY_TENANT_ID=demo \
RYU_NOTIFY_DATA_DIR=/var/lib/ryu-notify \
bun run apps/notify/src/index.ts
```

For more than one tenant, map each tenant to a distinct bearer key:

```sh
RYU_NOTIFY_API_TOKENS='{"acme":"acme-secret","beta":"beta-secret"}' \
RYU_NOTIFY_DATA_DIR=/var/lib/ryu-notify \
bun run apps/notify/src/index.ts
```

The default bind is `127.0.0.1:8092`. Set `RYU_NOTIFY_HOSTNAME` and
`RYU_NOTIFY_PORT` when the service has an authenticated network boundary. If
it is exposed beyond the host, put TLS and an edge rate limit in front of it.

API keys stay in process memory and are never written to the Notify database or
returned in responses. The service stores events in `events.db` below
`RYU_NOTIFY_DATA_DIR`.

## Health and capabilities

`GET /health` is unauthenticated and returns the service name, API version, and
the features available in this process:

| Feature | Meaning |
|---|---|
| `events` | Create and read durable events |
| `activities` | Start, update, end, and stream progress activities |
| `analytics` | Read bounded level, source, topic, and acknowledgement aggregates |
| `destinations` | Deliver to signed webhooks, ntfy, or a BuzzKit HTTP bridge |
| `filters` | Filter history by level, source, recipient, topic, priority, tags, time, and state |
| `idempotency` | Safely retry event creation with an idempotency key |
| `interactive-responses` | Collect approval, yes/no, and text replies with optional callbacks |
| `preferences` | Mute recipients or defer delivery during quiet hours |
| `silences` | Temporarily suppress matching source, project, topic, or fingerprint events |
| `sse` | Receive newly-created matching events live |
| `acknowledgements` | Mark a tenant-owned event as acknowledged |
| `topics` | Publish plain text or JSON events to ntfy-style topic paths |
