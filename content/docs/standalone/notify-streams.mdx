Notify streams are live-only. The durable event list is the recovery path for
events created while a consumer was disconnected.

## Open a stream

```sh
curl -N "$NOTIFY_URL/v1/events/stream?source=github-actions" \
  -H "Authorization: Bearer ${RYU_NOTIFY_API_TOKEN}"
```

The stream sends an initial `: ryu-notify` comment, then one frame for each
matching event:

```text
event: notification
id: evt_...
data: {"id":"evt_...","title":"Deploy complete",...}
```

The optional `source` and `recipient` query parameters filter the stream. The
service sends comment keep-alives and removes a subscriber when the client
disconnects.

## Reconnect without gaps

1. Read the durable list endpoint with the last `nextCursor` or other recovery
   marker.
2. Process the bounded history returned by that request.
3. Open `/v1/events/stream` again with the same tenant bearer and filters.

The service does not replay history from the SSE connection. This explicit
split keeps the live hub small and makes the durable recovery boundary visible.

## Box and Agent Mail examples

The repository examples call the source service first and Notify second:

```sh
# Agent Mail -> Notify
MAIL_BASE_URL=http://mail.example \
MAIL_API_TOKEN=mail-secret \
MAIL_INBOX_ID=inbox-id \
MAIL_TO=operator@example.com \
NOTIFY_BASE_URL=http://notify.example \
NOTIFY_API_TOKEN=notify-secret \
bun run examples/notifications/agent-mail.ts

# Box -> Notify
BOX_BASE_URL=http://box.example \
BOX_API_TOKEN=box-secret \
NOTIFY_BASE_URL=http://notify.example \
NOTIFY_API_TOKEN=notify-secret \
bun run examples/notifications/box.ts
```

The Mail example publishes an accepted transport hand-off. The Box example
publishes lifecycle status. Neither example sends message bodies, raw MIME,
attachments, command output, provider credentials, or inbound HMAC secrets.

## What Notify does not do

Notify v1 does not provide Apple or Expo push, email or SMS delivery,
third-party webhook fan-out, workflow orchestration, action execution, user
preferences, hosted billing, or multi-process pub/sub. Add those as separately
owned adapters around the event contract after their credentials, retries,
consent, and operational proof are defined.
