Agents and people can rate how useful a call was. A review is always tied to a
call the reviewer actually made through Connect, so a review cannot be written
for an endpoint nobody called.

## Review a call

Every call answer carries its call id (`ryuCallId`, or the `x-ryu-call-id`
header on a vendor call). Review it within 30 days.

```sh
curl -X POST https://connect.example/v1/reviews \
  -H "Authorization: Bearer $RYU_CONNECT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "callId": "call_0123456789abcdef0123456789abcdef",
    "rating": 4,
    "outcome": "useful",
    "issues": ["slow"],
    "comment": "Right answer, took a while."
  }'
```

| Field | Values |
|---|---|
| `callId` | The call's id; it must be one of your own calls |
| `rating` | 1 to 5 |
| `outcome` | `useful`, `partial` or `not_useful` |
| `issues` | Up to four of `wrong_results`, `incomplete`, `stale`, `slow`, `bad_format`, `error`, `overpriced` |
| `comment` | Optional, up to 500 characters; shown only to you |

Calls that can be reviewed: vendor calls to catalog endpoints (including
routed calls, arena runs and composed-tool steps) and Composio-shaped tool
calls. A second review of the same call replaces the first (`revision` goes
up). `GET /v1/reviews` lists your reviews with their comments, and
`DELETE /v1/reviews/<callId>` withdraws one. Reviews are free.

## Summaries

`GET /v1/reviews/summary/<endpoint>` returns an endpoint's summary, and the
same `reviews` object appears on [search and describe](/docs/standalone/connect-api-discovery)
rows, on [routing candidates](/docs/standalone/connect-api-routing) and on the
[catalog browse](/docs/standalone/connect-api-catalog) rows.

```json
{
  "reviewers": 7,
  "reviews": 12,
  "shown": true,
  "minReviewers": 5,
  "rating": 4.2,
  "outcomes": { "useful": 0.71, "partial": 0.29, "not_useful": 0 },
  "issues": [ { "issue": "slow", "share": 0.29 } ],
  "lastReviewAt": "2026-10-20T14:03:00.000Z"
}
```

- Each organization counts once, however many calls it reviewed: its reviews
  are averaged first, then organizations are averaged. A team key counts as
  its organization.
- The rating, outcome shares and issues are shown only once five
  organizations reviewed the endpoint (`shown: true`); until then only the
  counts are.
- Summaries cover the last 90 days. Comments, call ids and who reviewed are
  never part of a summary.

## Refusals

| Status, code | Meaning |
|---|---|
| `400 invalid_review` | The body does not fit the fields above |
| `404 call_not_found` | No call of yours with this id is on record |
| `409 call_too_old` | The call ran more than 30 days ago |
| `429 review_rate_limited` | More than 1,000 reviews from one key's tenant in a UTC day |
| `404 review_not_found` | You have no review of this call to withdraw |
| `404 reviews_unavailable` | This deployment does not take reviews |

Reviewing needs a key or `tools:exec`; reading summaries needs `tools:read`.
