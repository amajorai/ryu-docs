The Ryu Box API is a tenant-scoped HTTP contract under `/v1`. The standalone
service listens on `http://127.0.0.1:8090` by default. Core and other clients
use the same bearer boundary.

## Authentication and request limits

Every protected request sends:

```text
Authorization: Bearer <RYU_BOX_API_TOKEN>
```

Use `RYU_BOX_API_TOKENS` when one service hosts more than one tenant. Its JSON
object maps tenant ids to distinct bearer keys. Do not reuse a Core, Gateway,
Mail, or provider credential.

The service accepts JSON bodies up to 512 KiB. Command output is bounded to
1 MiB. Responses include `X-Request-ID`; errors expose a stable `code`, safe
message, status, and request id.

## Endpoint surface

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/health` | Read driver, mode, version, and feature state without a bearer |
| `GET` | `/` | Redirect a person to the Ryu organization dashboard |
| `GET` | `/v1/boxes` | List active Boxes in the caller's tenant |
| `POST` | `/v1/boxes` | Create a Box; requires `Idempotency-Key` |
| `GET` | `/v1/boxes/:id` | Read one tenant-owned Box |
| `DELETE` | `/v1/boxes/:id` | Destroy one Box and retain its audit event |
| `GET` | `/v1/boxes/:id/events` | Read bounded lifecycle events |
| `POST` | `/v1/boxes/:id/commands` | Run one bounded command in a ready Box |
| `POST` | `/v1/boxes/:id/prompt` | Queue work for a supported agent provider |
| `GET` | `/v1/boxes/:id/prompts` | List prompt runs without prompt text |
| `POST` | `/v1/boxes/:id/prompts/:run/claim` | Claim one queued prompt |
| `POST` | `/v1/boxes/:id/prompts/:run/complete` | Complete a claimed prompt |
| `POST` | `/v1/boxes/:id/stop` | Stop the workspace while retaining its disk |
| `POST` | `/v1/boxes/:id/resume` | Resume a stopped workspace |
| `POST` | `/v1/boxes/:id/fork` | Fork a ready or stopped Box; requires `Idempotency-Key` |

Connected provider mode forwards the provider's supported `/v1` routes through
the same tenant-authenticated bridge. The `/health` response reports the
active mode and feature list so a client can distinguish local coverage from
connected coverage.

## Create a Box

```sh
export BOX_API_BASE=http://127.0.0.1:8090/v1
export BOX_API_TOKEN=replace-me

curl -fsS -X POST "$BOX_API_BASE/boxes" \
  -H "Authorization: Bearer $BOX_API_TOKEN" \
  -H "Idempotency-Key: create-demo-001" \
  -H "Content-Type: application/json" \
  -d '{"name":"demo","size":"small","network":"none"}'
```

The create body supports:

| Field | Values or limit | Default |
|---|---|---|
| `name` | Letters, numbers, `.`, `_`, `-`; up to 64 characters | `box` |
| `image` | An allowlisted image name; up to 128 characters | `ubuntu:24.04` |
| `size` or `type` | `small`, `default`, `large` | `default` |
| `network` | `none` or `egress` | `none` |
| `ttlSeconds` | Positive integer up to seven days | No expiry |

The response contains a public Box projection. It does not expose the tenant
id or driver reference.

## Idempotency and errors

Create and fork operations store the request body hash with the idempotency
key. Repeating the same request returns the existing Box with `200`. Reusing a
key with a different body returns `409 idempotency_conflict`.

Common error codes include `unauthorized`, `invalid_request`, `box_not_ready`,
`box_busy`, `driver_unavailable`, `idempotency_conflict`, and `not_found`.
Clients should branch on `code`, not on the message text.
