A Box's `secrets` reach its processes as plain environment variables, so any
program in the Box, an agent included, can read and print them. A **network
secret** keeps the value out of the Box. The Box only sees a placeholder, and
the Box's egress proxy puts the real value in its place on the way out, only on
HTTPS requests to the hosts you bound it to.

## Create a Box with a network secret

Store the value as a tenant secret first, then bind it by name when you create
the Box:

```bash
curl -X PUT "$BOX_URL/v1/secrets/OPENAI_API_KEY" \
  -H "Authorization: Bearer $BOX_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"value":"sk-..."}'

curl -X POST "$BOX_URL/v1/boxes" \
  -H "Authorization: Bearer $BOX_API_TOKEN" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "network": "allowlist",
    "allowedHosts": ["api.openai.com"],
    "networkSecrets": [{
      "secret": "OPENAI_API_KEY",
      "placeholder": "__RYU_SECRET_3f9c2a7b1d0e4c6a__",
      "hosts": ["api.openai.com"]
    }]
  }'
```

Then pass the placeholder to your program, for example as the per-command
environment variable `OPENAI_API_KEY=__RYU_SECRET_3f9c2a7b1d0e4c6a__`. A
request with `Authorization: Bearer __RYU_SECRET_3f9c2a7b1d0e4c6a__` to
`api.openai.com` reaches OpenAI with the real key.

| Field | Values or limit |
|---|---|
| `networkSecrets` | Up to 16 bindings |
| `secret` | The name of a stored tenant secret; it may not also be in `secrets` or be `repo.tokenSecret` |
| `placeholder` | `__RYU_SECRET_` followed by 16 to 64 letters or digits, then `__`; unique within the Box |
| `hosts` | 1 to 16 host names, `*.example.com` wildcards allowed; with `allowlist`, every host must be in `allowedHosts` |
| `substituteIn` | Optional. `["header"]` (the default) or `["header", "body"]` to also replace the placeholder in small request bodies |

## How it works

- The Box gets a certificate authority of its own, created for it alone. That
  authority can vouch only for the bound hosts: its signing key is discarded
  as soon as the proxy's certificate is issued.
- The Box trusts that authority. Before any setup step runs, the Box service
  installs it in the system store when the image supports it, and in a bundle
  of the system roots plus the authority. `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`,
  `CURL_CA_BUNDLE`, `GIT_SSL_CAINFO`, `DENO_CERT` and `NODE_EXTRA_CA_CERTS`
  point runtimes at them.
- For a tunnel to a bound host, the proxy terminates TLS, replaces bound
  placeholders in credential headers, and forwards the request over a new TLS
  connection that verifies the real host. Every substituted request uses its
  own connection.
- Only these headers are substituted: `Authorization`, `X-Api-Key`,
  `Api-Key`, `X-Auth-Token`, `X-Access-Token`, `Private-Token` and
  `X-Goog-Api-Key`. A bound placeholder in the URL path or query, or in any
  other header, gets `400 Bad Request` instead, because a server that quotes
  the URL or echoes headers back would otherwise hand the value to the Box.
- In those headers a placeholder inside an HTTP Basic credential is replaced
  too: `Authorization: Basic base64(user:__RYU_SECRET_…__)` reaches the host
  as `base64(user:value)`, which is how Git sends a token.
- A placeholder in a request body is replaced only for a binding with
  `substituteIn: ["header", "body"]`. Without it, the body reaches the host
  with the placeholder unchanged. For a binding that opts in, the body is
  replaced when it is at most 256 KiB, has an exact `Content-Length`, is not compressed, and is
  `application/json` (or a `+json` type), `application/x-www-form-urlencoded`
  or `text/plain`. The value is escaped for its type: as a JSON string, or
  percent-encoded in a form field. The proxy answers `Expect: 100-continue`
  itself and sends the body with its new length. Chunked, compressed,
  multipart, binary or larger bodies are relayed unchanged. A request with
  both `Content-Length` and `Transfer-Encoding`, or more than one
  `Content-Length`, gets `400 Bad Request`.
- A placeholder sent to any other host, or in a body the proxy relays
  unchanged, travels as the placeholder and is useless there.
- The value is decrypted while the Box is created and handed to that Box's
  proxy. It is never written to the Box, to logs, or to the proxy
  container's configuration on the Docker host. The Box service keeps a copy
  sealed with its secrets key, so the proxy gets the value again when a
  stopped Box resumes, even after the service restarts. The copy is removed
  when the Box is deleted. A Box whose value the service no longer holds
  answers a resume with `409 conflict` instead of starting without it, on
  Docker and on hosted VMs alike; create a new Box with the network secret.

## Browser credential fills

An agent in a session Box can sign in to a site with a saved account through
`browser.fill_credential` (see
[Box browser credential fills](/docs/standalone/box-browser-fills) for the
service routes). A password fill uses the same egress proxy as network
secrets, with a binding that lives for one fill only.

- **Per-fill bindings.** The Box browser receives a single-use placeholder,
  never the password. The proxy swaps it for the value only in one `POST` to
  a login URL on the account's site, as one whole form or JSON field, within
  45 seconds (60 at most). A fill placeholder is never substituted in a URL or
  header: a request that carries one there gets `400 Bad Request`. Fill
  bindings are kept apart from the network secrets above.
- **Login URLs.** A login URL is an `https` address on the account's host,
  its `www.` variant or a subdomain, without a user name, port, query or
  fragment; an account or item takes up to four. They decide where the
  password can go. An agent's own account gets them when it is created or
  later from its login URL setting, and an item you attach gets one in the
  attach dialog, prefilled from the item's URL when that names a page. An
  account or item without a login URL is not filled in a Box.
- **Without a login URL.** For an item you attach, you can allow a Box fill
  without a login URL. With this option the agent can capture the password,
  by sending it to another page on the same site, so allow it only for a site
  and a password you accept that risk for. The site's traffic stays
  intercepted for the rest of the Box: one request per connection, and no
  WebSockets or HTTP/2 to that site.
- **Echoes.** The proxy checks the response to a filled request (and, without
  a login URL, all of the site's traffic) for the value in common encodings.
  A match cuts the response, and fills for that site are refused in that Box
  from then on. This is best effort: a value transformed in another way (a
  hash, part of it, an image) is not recognized.
- **The guessing oracle.** Because a match cuts the response, a correct guess
  of the password is visible once. A weak or reused password can be guessed
  within the rate limits: 10 fills per Box and 3 password fills per account in
  10 minutes. Use strong, unique passwords for anything you attach.
- **Shared addresses.** While a Box holds a fill without a login URL, the
  proxy refuses connections to IP addresses and to other names that resolve
  to that site's addresses. Unrelated sites behind the same CDN address are
  refused in that Box too.
- **Own accounts.** An agent chooses its own account's site and login URLs, so
  a fill protects that password only from hosts the agent does not control.
  No password of yours is involved.

## Vault broker services in a cloud task Box

A Ryu node's credential broker can also serve a cloud task's Box, so the Box
uses a broker service (an injected auth header, a placeholder, or a connected
OAuth account) while the value stays on your node.

- Mark the service for Boxes: `boxRelay: true` on
  `PUT /api/vault/broker/services/{name}`. Unmarked services never reach a
  Box. The Desktop service editor does not show the setting yet, and saving
  the service there turns it off.
- When a cloud task creates its Box, Core mints a broker session for that Box
  alone. It covers the marked services that are enabled in the active vault
  environment, that you may `use`, and whose host is a DNS name the Box's
  network admits. It lives as long as the task and is revoked when the Box is
  deleted or stopped.
- The session token goes to the Box's egress proxy only, never into the Box.
  For a covered host the proxy forwards the Box's request over a WebSocket to
  your node's public URL (`RYU_NODE_PUBLIC_URL`, `https` on port 443), where
  the broker answers it. The Box trusts the broker's certificate authority
  for those hosts.
- A Box's session is narrower than a local one: hosts no service in it covers
  are refused whatever the environment's unmatched-host policy, placeholders
  are replaced in headers only (never in the path, query, body or WebSocket
  messages), payment cards are never used, and the session works only through
  the Box's relay.
- If a marked service would apply but the broker is off, the node has no
  public `https` URL, or the Box service cannot relay the broker yet, the task
  is refused instead of starting without it. If the node goes offline or the
  session is revoked, the Box's requests to covered hosts get `502` or `403`.

Any process in the Box can make requests with a covered service, so mark only
services you would let the task's code use. Secrets the services reference
must be node secrets: personal (user-scoped) references do not resolve for a
Box. A host that echoes an injected header back can still reveal the value, as
with network secrets.

## Limits

- Network secrets need `network: "egress"` or an allowlist. A Box with
  `network: "none"` refuses them.
- Docker Boxes and hosted virtual-machine Boxes substitute network secrets.
  On a hosted VM the value reaches the Box's VM over the service's
  authenticated agent connection, and that VM's proxy substitutes it. A Box
  service whose Boxes cannot substitute them answers `422 not_supported`;
  pass the value with `secrets` there.
- A value may not be empty or contain a line break.
- Bind a secret only to hosts you trust with it: a bound host that echoes
  its credential headers back in a response can still reveal the value.
- Opt in to bodies only for hosts that never store or return what you send.
  Many APIs keep a request body and return it later: an issue or gist
  created on GitHub, or a prompt a chat API repeats. With body substitution,
  a Box could write the placeholder into such a body and read the real value
  back.
- A fork, and a Box booted from a snapshot of a Box with network secrets,
  keep the source Box's network secrets: its files already trust the same
  certificate authority and hold the same placeholders. A snapshot keeps its
  sealed copy until the snapshot is deleted. A snapshot boot that binds its
  own `networkSecrets` uses only those, and one with `network: "none"` gets
  none.
