<Callout type="warn">
Connect is not distributed for self-hosting yet. There is no published source
tree, package, container image, or release binary for the service, and the
hosted product is in early access. This page documents the service contract
for early-access deployments; it is not a download or install path. Members of
an organization with Ryu-hosted Connect create keys in the Ryu console instead
(see [Connect keys](/docs/standalone/connect#connect-keys)).
</Callout>

This reference lists the settings a Connect deployment reads. For what each
lane does, see [Ryu Connect](/docs/standalone/connect).

## Settings

| Setting | Purpose |
|---|---|
| `RYU_CONNECT_API_TOKEN` and `RYU_CONNECT_TENANT_ID` | One runtime bearer and the tenant it authenticates |
| `RYU_CONNECT_API_TOKENS` | A JSON object mapping tenant IDs to distinct runtime bearers, used instead of the pair above for several tenants |
| `RYU_CONNECT_SKILLS_DIR` | Directory of `<skill>/SKILL.md` folders served to every tenant |
| `RYU_CONNECT_HOSTNAME` and `RYU_CONNECT_PORT` | Bind address; the default is `127.0.0.1:8094` |
| `RYU_CONNECT_DATA_DIR` | Location of Connect's account, trigger, event, usage, idempotency, tool-demand, async task, vendor resource, and native connection SQLite stores, of the spool for spooled answers, and of hosted reference media |
| `RYU_PRODUCT_DASHBOARD_URL` | Optional URL that `GET /` redirects browsers to; unset or blank, `GET /` returns a short JSON description of the service |
| `RYU_CONNECT_MCP_SERVERS` | JSON array of registered MCP servers, each bound to one tenant and an exact tool allowlist |
| `RYU_CONNECT_COMPOSIO_BINDINGS` | JSON array binding each tenant to one Composio account, toolkit version, project-key variable, allowed actions, optional call limits, and optional agent accounts (`agentSubjects`) |
| `RYU_CONNECT_COMPOSIO_MANAGEMENT_TOKENS` | JSON object mapping tenant IDs to management bearers for account linking and trigger administration |
| `RYU_CONNECT_TRIGGER_GRANTS` and `RYU_CONNECT_TRIGGER_BINDINGS` | Trigger types each tenant may create, and statically configured trigger deliveries |
| `RYU_CONNECT_TOOLKIT_PROVIDERS` | JSON object choosing `"composio"` or `"native"` per toolkit, for example `{"github":"native"}`; unset, every toolkit uses Composio |
| `RYU_CONNECT_OAUTH_APPS` | JSON array of your own OAuth apps, one per natively served toolkit: client ID, the name of the environment variable holding the client secret, scopes, callback URL, and return URL |
| `RYU_CONNECT_NATIVE_GRANTS` | JSON array granting each tenant the natively served actions it may call, with an optional per-minute call limit and `"oauthClient": "tenant"` for a tenant that links through its own OAuth app |
| `RYU_CONNECT_OAUTH_CALLBACK_BASE` | Connect's public base URL; a tenant's own OAuth app registers `<base>/v1/oauth/callback/<toolkit>`. Required when a grant uses `"oauthClient": "tenant"` |
| `RYU_CONNECT_TOKEN_KEY` | 32-byte key (64 hex characters or base64) that encrypts stored native OAuth tokens and signs [task webhooks](/docs/standalone/connect-api-tasks#webhooks); required with native grants or any toolkit set to `"native"` |
| `RYU_CONNECT_DISCOVERY_GATEWAY_URL` and `RYU_CONNECT_DISCOVERY_EMBEDDING_MODEL` | Optional: the Ryu Gateway (HTTPS, or loopback HTTP) and embedding model for [hybrid search](/docs/standalone/connect-api-discovery#hybrid-search); unset, a hybrid search answers with word search and says so |
| `RYU_CONNECT_DISCOVERY_JUDGE_MODEL` | Optional: the judge model hybrid search may call; each tenant may make up to 60 judge calls per hour |
| `RYU_CONNECT_DISCOVERY_INDEX_KEY` | Optional: your own Gateway key that pays for embedding tool descriptions (cached in `discovery-embeddings.db` under `RYU_CONNECT_DATA_DIR`); unset, the caller's key pays for the descriptions it is first to need |
| `RYU_CONNECT_SPOOL_TOTAL_MIB` | Optional: the disk budget in MiB for the whole [spool](/docs/standalone/connect-api-tasks#spooled-answers) of spooled answers (default 1024) |
| `RYU_CONNECT_MEDIA_TOTAL_MIB` | Optional: the disk budget in MiB for all hosted [reference media](/docs/standalone/connect-api-media#reference-media) (default 2048) |
| `RYU_CONNECT_FREE_ROUTES` | `on` serves catalog [free routes](/docs/standalone/connect-api-catalog#free-routes) without a key (needs the catalog feed); default `off` |
| `RYU_CONNECT_FREE_ROUTES_CLIENT_IP_HEADER` | Optional header your own proxy sets to the client address on every request (for example `cf-connecting-ip`), used to count free-route calls per client; unset, the socket address is used. When the header has several comma-separated values (`x-forwarded-for` behind a proxy that appends), the rightmost, which your proxy added, is used. Set it only when every request passes through that proxy, or callers can choose their own address |
| `RYU_CONNECT_ROUTING_TREG_CANDIDATES`, `RYU_CONNECT_ROUTING_GATEWAY_URL` and `RYU_CONNECT_ROUTING_GATEWAY_KEY` | Optional, all three together: Treg endpoints that [routed capability calls](/docs/standalone/connect-api-routing) may choose (a JSON array of `{endpoint, adapter, perCallMicroUsd}`, where `adapter` names the request shape the endpoint relays, such as `tavily.search.basic`, and `perCallMicroUsd` is the most one call may be charged), and the Ryu Gateway (HTTPS, or loopback HTTP) and trusted-forwarder key they run through; unset, routed calls choose among Ryu-served endpoints only |
| `RYU_CONNECT_REVIEWS_URL` | Optional: the control plane's public review feed (`https://<control-plane>/api/tool-catalog/reviews`, HTTPS or loopback HTTP). Connect then shows the feed's [review](/docs/standalone/connect-api-reviews) summaries and, with the key feed's bearer, reports the reviews it takes (without comments); unset, rows show this Connect's own reviews. Reviews and [composed tools](/docs/standalone/connect-api-composed) are kept in `reviews.db` and `composed.db` under `RYU_CONNECT_DATA_DIR` |
| `RYU_CONNECT_ADMIN_TOKEN` | Optional operator bearer for `GET /v1/admin/demand`, the report of tool requests and searches that found nothing across tenants, for `POST /v1/admin/health/sweep`, which runs a credential check now, and for `GET /v1/admin/operator-accounts`; it must be at least 32 printable ASCII characters with no spaces and differ from every tenant and management bearer and from the billing status and key feed secrets, or Connect refuses to start; unset, the route does not exist |
| `RYU_CONNECT_TENANT_PARENTS` | Optional JSON object mapping a team tenant to its organization tenant, for the team and organization rungs of the [credential ladder](/docs/standalone/connect-api-relay#the-credential-ladder). Both tenants must be configured, and the map is one level deep |
| `RYU_CONNECT_NOTIFY_URL` and `RYU_CONNECT_NOTIFY_TOKEN` | Optional Ryu Notify base URL and bearer for credential alerts. Set both or neither; the URL must be HTTPS or loopback HTTP |
| `RYU_CONNECT_DATA_KEY` | Base64 of 32 random bytes. Required for trigger delivery: it encrypts webhook payloads waiting in the event inbox |
| `RYU_CONNECT_ALLOW_PLAINTEXT` | Development only. Set to `1` to run the event inbox without a data key outside production |

Trigger delivery needs `RYU_CONNECT_DATA_KEY`. Without it, Connect starts with
the event inbox and trigger delivery off and logs why. The trigger lane then
reports as not configured on `/health`, and the rest of Connect keeps running.
When you upgrade a deployment that has trigger grants or bindings, set the key
before you upgrade. Otherwise trigger delivery stops, and events that were
already pending wait in the inbox until you set the key and restart. Keep the
key in your secret store, apart from the data directory. Pending events
encrypted under a key you lose cannot be delivered.

After Connect has started once with `RYU_CONNECT_DATA_KEY`, an older Connect
release still starts, but it cannot read the encrypted events in the event
inbox file (`events.db` in the data directory): delivering triggers to a
workspace fails while one of those events is waiting. To roll back, stop
Connect and move `events.db` out of the data directory first. Events still
waiting in it are not delivered by the older release.

Bind to a public interface only behind TLS and an edge rate limit. By default
`GET /` returns a short JSON description of the service: its name, version, API
version, and the `/health` path. Set `RYU_PRODUCT_DASHBOARD_URL` to send
visitors to your own portal instead. Ryu's hosted deployment sets it to the Ryu
dashboard, so a self-hosted Connect never sends visitors to Ryu by default.

## Fixed limits

These limits are built into Connect and are not read from the environment:

- [Async tasks](/docs/standalone/connect-api-tasks): 8 running at once, 2 per
  tenant, 100 queued and running per tenant, and 300 seconds for one task's call.
- [Spool](/docs/standalone/connect-api-tasks#spooled-answers): 64 MiB per answer,
  and 128 MiB per organization or tenant (or the whole spool, if smaller). A
  download URL works for 3600 seconds, and one answer must be written within
  120 seconds.
- [Reference media](/docs/standalone/connect-api-media#reference-media): 25 MiB
  per file, 128 MiB and 100 live files per organization or tenant (or all hosted
  media, if smaller). A file's URL works for 3600 seconds by default and for at
  most 21600 seconds, and one upload must arrive within 120 seconds.
- [Free routes](/docs/standalone/connect-api-catalog#free-routes): 30 calls per
  client per minute and 300 per hour, and 600 per minute for the whole route.
- [Hybrid search](/docs/standalone/connect-api-discovery#hybrid-search): a tool
  ranks by meaning only at a similarity of 0.3 or more.
- [Credential checks](/docs/standalone/connect-api-relay#credential-checks) run
  every six hours.

## Compatibility mode upstreams

For compatibility mode, configure each upstream:

| Setting | Purpose |
|---|---|
| `RYU_CONNECT_CORE_URL` and `RYU_CONNECT_CORE_TOKEN` | Core tool search and describe |
| `RYU_CONNECT_GATEWAY_URL` and `RYU_CONNECT_GATEWAY_TOKEN` | Gateway tool execution and Composio |
| `RYU_CONNECT_MCP_UPSTREAM` and `RYU_CONNECT_MCP_TOKEN` | MCP forwarding below `/mcp/` |

Upstream URLs must use HTTPS, or plain HTTP only to `localhost`, `127.0.0.1`, or
`[::1]`, without credentials, query, or fragment. Other values refuse startup,
because these upstreams receive operator bearers and tenant payloads. The
Connect bearer is never forwarded upstream. Operator-configured upstream
credentials are kept in process memory and are never returned by Connect.
