A [Ryu Box](/docs/standalone/box) service that lists `browser-fill-v2` in its
`/health` `features` can fill a login field in a desktop Box's browser without the Box's processes holding the
password. The caller names the element and the hosts, the service checks the
page, and a password is typed as a single-use placeholder. The Box's egress
replaces the placeholder with the real value only in one `POST` to a login URL
on a bound host, within the fill's time limit (at most 60 seconds).

| Request | Body | Answer |
|---|---|---|
| `POST /v1/boxes/:id/browser-fills` | `ref`, optional `tabId`, `field` (`username`, `email`, `password`, `totp`), `pageHosts` (1 or 2), `bindHosts` (1 to 6), optional `submitUrls` | `201` with `fillId`, `pageUrl`, and `tab` |
| `POST /v1/boxes/:id/browser-fills/:fillId` | `{"mode":"placeholder","value","submitUrls","unbound","ttlSeconds","submit"}`, or `{"mode":"text","value","submit"}` | `200` with `filled`, `protected`, and `tab` |
| `GET /v1/boxes/:id/browser-fills/:fillId` | none | `200` with `state` and, once used, `consumed` (`method`, `path`) |
| `DELETE /v1/boxes/:id/browser-fills/:fillId` | none | `204` |

- Fills need a desktop Box created with `egress` or `allowlist` networking on a
  service that supports them. Any other Box answers
  `409 browser_fill_unsupported` before a value is sent.
- Hosts must be exact DNS names, and in an `allowlist` Box they must be
  allowed. Login URLs must be `https` URLs on a bound host, without userinfo,
  another port, a fragment, or `.` and `..` segments.
- A prepared fill must be committed within 30 seconds. A Box holds at most
  four pending or live fills, and a new fill for the same host revokes the
  older one.
- A password is committed only in `placeholder` mode. `unbound: true` fills
  without a login URL: the value can then reach any path of the bound hosts,
  so those hosts stay guarded for the Box's life.
- If a site echoes a filled value back, the response is cut and fills for
  that host answer `409 browser_fill_echoed` in that Box from then on.
- Box events record `browser.fill.prepared`, `.bound`, `.consumed`,
  `.echoed`, `.expired`, and `.revoked`, without values.

## In a Ryu conversation

An agent signs in to a site in its [session Box](/docs/core/boxes#session-boxes) with
`browser.fill_credential`, using one of its own website accounts or an item you attached to it,
and finds account ids with `browser.list_credentials`, which returns names and addresses only.
Core makes the calls above for it. It takes the hosts and login URLs from the account or the item,
never from the call's arguments, and no value is read before the Box passes every check.

- An account or item needs a login URL, or, for an item you attach, your opt-in to fill without
  one. With that opt-in the agent can capture the password.
- A fill is refused in a conversation with more than one agent, for a sub-agent or worker thread,
  and for read-only or trial agents.
- Each Box allows 10 fills, and 3 password fills per account, in 10 minutes. A site that echoes a
  filled value back is blocked for fills in that Box.
- A Box that cannot fill safely (an older Box service or image) refuses with "This Box cannot fill
  credentials safely; start a new session Box".

How the egress binding works, and what it does not protect, is in
[Box network secrets](/docs/standalone/box-network-secrets#browser-credential-fills).

The rest of the Box API is described in the [Ryu Box API](/docs/standalone/box-api)
reference, and static network secrets in
[Box network secrets](/docs/standalone/box-network-secrets).
