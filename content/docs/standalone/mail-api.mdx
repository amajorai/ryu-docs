The standalone Mail service preserves the `/api/mail/*` route spelling used by
the Core companion. Protected routes use the standalone Mail bearer. Inbound
mail uses a per-inbox HMAC secret instead.

## Route surface

| Method | Path | Credential | Purpose |
|---|---|---|---|
| `GET` | `/health` | None | Read service liveness and safe feature state |
| `GET` | `/api/mail/status` | Mail bearer | Read Mail configuration status |
| `GET/POST` | `/api/mail/inboxes` | Mail bearer | List or create an inbox |
| `GET/PATCH/DELETE` | `/api/mail/inboxes/:id` | Mail bearer | Read, rename, or delete an inbox |
| `POST` | `/api/mail/inboxes/:id/rotate-secret` | Mail bearer | Replace an inbound HMAC secret |
| `GET` | `/api/mail/inboxes/:id/messages` | Mail bearer | List messages in an inbox |
| `GET` | `/api/mail/messages/:id` | Mail bearer | Read one message and its metadata |
| `POST` | `/api/mail/inboxes/:id/send` | Mail bearer | Hand a message to the configured transport |
| `POST` | `/api/mail/inbound/:id` | Per-inbox HMAC | Receive signed raw mail |

## Bearer authentication

Protected calls send:

```text
Authorization: Bearer <RYU_MAIL_API_TOKEN>
```

The token is required before a standalone process may bind beyond loopback. It
is separate from Core sidecar credentials, Gateway keys, and the inbound HMAC
secret.

## Signed inbound mail

The inbound route does not use the bearer. It requires:

```text
X-Ryu-Signature: sha256=<hex>
```

Compute the hexadecimal SHA-256 HMAC over the raw request body with the
inbox's inbound secret. Create an inbox or rotate its secret through the
protected API, then place that secret in the mail provider's webhook
configuration.

The raw body must be signed exactly as received. Do not parse and reserialize
the MIME body before calculating the signature.

## Inbox and secret responses

The create and rotate-secret responses return `inbound_secret` once. List and
get inbox responses omit it. Treat the secret as sensitive and store it only in
the provider webhook configuration or another protected secret store.

The compatibility fields `created_at`, `inbox_id`, and
`provider_message_id` remain available to the Ryu companion. The Mail service
owns the database and attachment blobs for its process.
