Ryu's TypeScript and Python packages, command lines, and MCP servers each
do a different job, and most projects need only one or two of them. Start
from the job in the table below.

## Pick by job

| If you want to... | Use | Language |
|---|---|---|
| Build agents, tools, workflows, or multi-agent systems that call models through the Gateway | [`@ryuhq/sdk`](/docs/extend/develop/sdk) | TypeScript |
| Package agents, tools, workflows, or skills as a Ryu plugin, then validate, pack, and install it | [`@ryuhq/sdk`](/docs/extend/develop/sdk) and its `ryu` command (see [What you can install today](/docs/standalone/sdk/choose-an-sdk#what-you-can-install-today)) | TypeScript |
| Serve SDK agents over HTTP or AG-UI, or bundle them for a host | [`createRyuServer`](/docs/extend/develop/sdk/server) and `ryu build` in `@ryuhq/sdk` | TypeScript |
| Build agents, tools, structured output, or Core workflows in Python | [`ryu-sdk`](/docs/extend/develop/sdk/python) (`ryu_sdk`) | Python |
| Embed agent chat from a running Ryu Core node in your app | [`@ryuhq/client`](/docs/extend/develop/sdk/client) | TypeScript |
| Manage a Core node's agents, plugins, models, skills, MCP servers, or workflows | [`@ryuhq/core-client`](/docs/extend/develop/sdk/core-client) | TypeScript |
| Call a hosted or standalone service such as Managed Agents, Mail, Notify, Box, or Messaging | [`@ryuhq/services`](/docs/standalone/sdk) | TypeScript |
| Call the same standalone services from Python | `ryu_sdk.services` in [`ryu-sdk`](/docs/standalone/sdk#python) | Python |
| Call the standalone services from a shell or a CI job | [`ryu-services`](/docs/standalone/sdk/cli), or `ryu-cli services` | Shell |
| Give an AI host tools for the standalone services | [`ryu-services mcp`](/docs/standalone/sdk/mcp) | MCP (stdio) |
| Give an AI host the agents and tools of a Ryu Core node | [Ryu MCP](/docs/extend/mcp) | MCP (HTTP or stdio) |
| Run Ryu from a terminal | [`ryu-cli`](/docs/surfaces/cli) | Shell |
| Call a Core node from a JVM app | [Java library](/docs/extend/develop/sdk/java) (`com.ryu:ryu-client`) | Java |
| Use the shared Rust kernel from Go, Swift, Kotlin, or C# | [Libraries and bindings](/docs/extend/develop/sdk/language-bindings) | Several |

## The libraries

### Build on Ryu with `@ryuhq/sdk`

`@ryuhq/sdk` is the framework for writing agents and the code around them:
typed tools with zod or any Standard Schema validator, structured output,
the `Agent` loop, the workflow DSL, supervisors and handoffs, prompts, RAG,
evals, AG-UI, and `createRyuServer`. Every model call goes through the Ryu
Gateway. The same package authors plugins: it validates and packs
`manifest.json`, and its `ryu` command installs the bundle into a Core node.

It does not call the standalone services. To publish a Notify event or send
mail from an SDK tool that runs in your own process, call `@ryuhq/services`
inside that tool, as in [Use them together](/docs/standalone/sdk/choose-an-sdk#use-them-together).

### Talk to Core with `@ryuhq/client` and `@ryuhq/core-client`

`@ryuhq/client` is a small fetch client whose only dependency is zod. It
embeds agent chat from a Core node, drives durable harness runs, and holds
the low-level clients for Managed Agents, Messaging, Mail, Notify, and Box,
which take explicit options and read no environment variables. Some of these
clients are newer than the published 0.3.0 release; see
[What you can install today](/docs/standalone/sdk/choose-an-sdk#what-you-can-install-today).
`@ryuhq/core-client` is the full Core and Gateway client that the desktop app, the terminal client, and the mobile app
share.

### Call the standalone services with `@ryuhq/services`

`@ryuhq/services` puts every standalone service behind one `new Ryu()`. It
wraps the low-level clients in `@ryuhq/client` and adds what an application
needs: settings from the environment, idempotency keys, safe retries, typed
`RyuError` codes, `{ data, error, meta }` results, pagination, and webhook
verification. Use it when your code calls a service. If you are writing an
agent that runs in your own process, use `@ryuhq/sdk` and call
`@ryuhq/services` from its tools.

### `ryu-sdk` for Python

The Python package `ryu-sdk` (module `ryu_sdk`) has two parts that match the
TypeScript packages:

- the authoring surface, which matches `@ryuhq/sdk` - `Agent`, `@tool`,
  structured output, middleware, the workflow DSL, and clients for Core
  harness runs and workflows;
- `ryu_sdk.services`, which matches `@ryuhq/services` - `Ryu` and `AsyncRyu`,
  with the same environment variables, headers, idempotency keys, and retry
  rules. The [SDK overview](/docs/standalone/sdk#python) lists where the
  Python client differs. `from ryu_sdk import Ryu` is an alias for the same
  class.

`ryu_sdk.ManagedAgentsClient` is the low-level Managed Agents client, like
the one in `@ryuhq/client`. It takes its key and base URL as arguments and
reads no environment variables; `Ryu().managed_agents` reads them for you.

| Capability | TypeScript | Python |
|---|---|---|
| Agent loop with tools | `Agent` and `defineTool` from `@ryuhq/sdk` | `Agent` and `@tool` from `ryu_sdk` |
| Workflow DSL that compiles to Core workflows | `createWorkflow` and `createCoreWorkflowClient` from `@ryuhq/sdk/workflow` | `Workflow` and `WorkflowClient` from `ryu_sdk` |
| Durable harness runs | `HarnessAPI` in `@ryuhq/client` | `HarnessClient` in `ryu_sdk` |
| Managed Agents, low level | `createManagedAgentsClient` from `@ryuhq/client` | `ManagedAgentsClient` from `ryu_sdk` |
| Standalone services | `Ryu` from `@ryuhq/services` | `Ryu` and `AsyncRyu` from `ryu_sdk.services` |

## Use them together

An `@ryuhq/sdk` agent can call a standalone service from a tool. The agent
reads its Gateway settings, and the `Ryu` client reads `RYU_NOTIFY_API_KEY`.

```ts tab="Node"
import { Agent, defineTool } from "@ryuhq/sdk";
import { Ryu } from "@ryuhq/services";
import { z } from "zod";

const ryu = new Ryu();

const notifyTeam = defineTool({
  id: "notify-team",
  name: "Notify team",
  description: "Publish a Notify event for the team",
  schema: z.object({ title: z.string() }),
  async run({ title }) {
    const event = await ryu.notify.publish({ title, level: "info" });
    return { id: event.id };
  },
});

const agent = new Agent({
  name: "release-bot",
  model: "your-model-id",
  tools: { notify_team: notifyTeam },
});

const result = await agent.generate("Tell the team the deploy finished.");
console.log(result.text);
```

```python tab="Python"
from ryu_sdk import Agent, tool
from ryu_sdk.services import Ryu

ryu = Ryu()


@tool
def notify_team(title: str) -> dict[str, str]:
    """Publish a Notify event for the team."""
    event = ryu.notify.publish({"title": title, "level": "info"})
    return {"id": event["id"]}


agent = Agent("release-bot", model="your-model-id", tools=[notify_team])

result = agent.generate("Tell the team the deploy finished.")
print(result.text)
```

This works when the agent runs in your own process: `agent.generate()`,
`createRyuServer`, or a bundle from `ryu build`. It does not work in a tool
you pack into a plugin with `ryu pack`, because Core runs that tool's body
by itself in a sandbox, without your imports, your module-level `ryu`
client, or your service keys. In a plugin, reach the service through a
Core tool instead: a remote tool reference (`ryuTool`), or a Core MCP or
connector tool.

## Environment variables

Each package reads only the variables for what it calls. The Gateway
variables have the same names and default everywhere. The standalone
services' variables are listed with their defaults in
[Configure](/docs/standalone/sdk#configure).

| Package or command | Reads | Notes |
|---|---|---|
| `@ryuhq/sdk` agents and model client | `RYU_GATEWAY_URL`, `RYU_GATEWAY_TOKEN` | The Gateway URL defaults to `http://127.0.0.1:7981`. |
| `createRyuServer` in `@ryuhq/sdk` | `RYU_MODEL`, `RYU_SERVER_PUBLIC`, `RYU_SERVER_TOKEN` | `RYU_MODEL` is the model used when an agent names none; it defaults to `default`. The server refuses to start without authentication unless `RYU_SERVER_PUBLIC=1` says the API is meant to be public; `RYU_SERVER_TOKEN` is the bearer token the refusal message suggests passing to `bearerAuth`. |
| `@ryuhq/sdk` remote tools, harness sessions, prompts, and `createCoreWorkflowClient` | `RYU_CORE_URL`, `RYU_CORE_TOKEN`, `RYU_TOKEN` | The Core URL defaults to `http://127.0.0.1:7980`. `RYU_CORE_TOKEN` wins over `RYU_TOKEN`. |
| `ryu install` and eval uploads in `@ryuhq/sdk` | `RYU_CORE_URL`, `RYU_CORE_TOKEN`, `RYU_TOKEN` | `RYU_CORE_TOKEN` wins over `RYU_TOKEN`. For a loopback URL only, the node's own token is the last fallback. |
| `ryu github-publish` in `@ryuhq/sdk` | `RYU_AUTH_TOKEN`, `RYU_MARKETPLACE_API_URL`, `RYU_API_URL` | A signed-in session; API keys are refused on publishing routes. The origin is `RYU_MARKETPLACE_API_URL`, else `RYU_API_URL`, else `https://api.ryuhq.com`. |
| `@ryuhq/client` and `@ryuhq/core-client` library clients | none | Each client takes its URL and token as options. |
| `resolveLocalNodeToken` in `@ryuhq/core-client` | `RYU_CORE_TOKEN`, `RYU_TOKEN`, `RYU_DIR`, `RYU_PROFILE` | `RYU_CORE_TOKEN` wins over `RYU_TOKEN`. Only a loopback URL falls back to the local node's token file, found through `RYU_DIR` and `RYU_PROFILE`. |
| The `box-tunnel` command in `@ryuhq/client` | `RYU_BOX_URL`, `RYU_BOX_API_KEY` | Both are required. |
| `@ryuhq/services`, `ryu-services`, and `ryu_sdk.services` | `RYU_API_URL`, `RYU_API_KEY`, `RYU_ORGANIZATION_ID`, and each service's own `RYU_<SERVICE>_URL` and key | The same names in TypeScript, Python, and the CLI. A `ryu_` key in `RYU_API_KEY` is sent only to the control-plane services. |
| `ryu_sdk` agents, harness, and workflows | `RYU_GATEWAY_URL`, `RYU_GATEWAY_TOKEN`, `RYU_CORE_URL`, `RYU_CORE_TOKEN`, `RYU_TOKEN` | Defaults match `@ryuhq/sdk`, so `RYU_CORE_TOKEN` wins over `RYU_TOKEN`. Python `HarnessClient` also defaults to them, where `HarnessAPI` in `@ryuhq/client` needs explicit options. |
| `ryu-cli` | `RYU_CORE_URL`, `RYU_CORE_TOKEN`, `RYU_PROFILE` | `RYU_PROFILE` picks the default Core port (`dev` uses 8980). `ryu-cli services` reads the `ryu-services` variables instead. |
| `ryu-mcp` | `RYU_CORE_URL`, `RYU_CORE_TOKEN`, `RYU_TOKEN`, `RYU_PROFILE`, `RYU_DIR`, `RYU_AUTH_URL`, `RYU_MCP_AUTH_FILE` | `RYU_CORE_TOKEN` wins over `RYU_TOKEN`; only a loopback URL falls back to the local node's token. `RYU_PROFILE` picks the default Core port. `RYU_AUTH_URL` and `RYU_MCP_AUTH_FILE` set the sign-in backend and where its session is stored. |

The Core token has two names. `RYU_CORE_TOKEN` is the current one. Both
SDKs, `ryu-mcp`, `ryu install`, and eval uploads read it first and then the
older `RYU_TOKEN`, for any URL, so an inherited `RYU_TOKEN` is sent to a
remote `RYU_CORE_URL` too. `ryu-cli` alone reads only
`RYU_CORE_TOKEN`. Prefer `RYU_CORE_TOKEN`, and unset a `RYU_TOKEN` that an
older setup exports for another node.

## Command lines

| Command | Package | What it does |
|---|---|---|
| `ryu` | `@ryuhq/sdk` | Validates, packs, and installs plugins; runs `ryu dev`, `ryu build`, and `ryu deploy` for SDK projects. A project runs it with `bunx ryu`. The published 0.3.0 release has only `pack`, `publish`, `github-publish`, `agent-plugin`, and `dev`. See [Tooling](/docs/extend/develop/sdk/tooling). |
| `ryu-cli` | The Ryu terminal client | Opens the terminal workspace and runs Core commands. See the [command reference](/docs/surfaces/cli/reference). |
| `ryu-services` | `@ryuhq/services-cli` | Calls the standalone services, prints curl with `--dry-run`, checks configuration with `doctor`, and verifies webhooks. See [ryu-services CLI](/docs/standalone/sdk/cli). |
| `create-ryu-app` | `create-ryu-app` | Scaffolds a plugin, an app, an agent, a workflow, or a multi-agent project, or with `--template services` a standalone server on `@ryuhq/services`. See the [quickstart](/docs/extend/develop/quickstart) and [Tooling](/docs/extend/develop/sdk/tooling). |

`ryu-cli services` runs `ryu-services` inside the terminal client. Every
argument after `services` is passed on unchanged, so these two lines do the
same thing:

```sh
ryu-services notify publish --title "Deploy finished" --dry-run
ryu-cli services notify publish --title "Deploy finished" --dry-run
```

The command reference writes `ryu` as shorthand for `ryu-cli`, so it shows
the second line as `ryu services`. That is not the `ryu` command from
`@ryuhq/sdk`, which has no `services` command.

## MCP servers

| Server | Gives an AI host | Credential |
|---|---|---|
| `ryu-services mcp` | Tools for the standalone services you configured, over stdio | The `@ryuhq/services` environment variables |
| Connect's `/mcp` | Connect Skill resources and the tools granted to the key | The Connect runtime key; `ryu.connect.mcp()` returns the URL and headers |
| A Core node's `/mcp/<agent-id>` | One agent's tools on a local, self-hosted, or managed node | A node bearer or paired token |
| The hosted `/mcp/<node-id>/<agent-id>` | One agent on a managed or organization-bound node, for remote hosts | OAuth with PKCE |
| `ryu-mcp` | The fixed `ryu_*` Core tools, over stdio, for hosts that need a local process | `RYU_CORE_URL` with `RYU_CORE_TOKEN` or `RYU_TOKEN`, or the local node's token for a loopback URL |
| `https://docs.ryuhq.com/mcp` | Read-only documentation search and page content | None |
| The website's `/mcp` | Public website pages, Marketplace and Cloud catalog discovery | None |

To write your own MCP server in TypeScript, use the MCP bridge in
`@ryuhq/sdk` (`@ryuhq/sdk/mcp`). [Ryu MCP](/docs/extend/mcp) explains the
Core endpoints and their credentials.

## What you can install today

<Callout type="info">
@ryuhq/services is not yet published to npm; it requires @ryuhq/client 0.4 or later, which is also not yet on npm (latest is 0.3.0).
</Callout>

<Callout type="info">
The `ryu-sdk` Python package is not yet published to PyPI, so the Python client cannot be installed outside Ryu either.
</Callout>

`@ryuhq/services-cli` is not on npm yet either.

| Package | Registry | Status |
|---|---|---|
| `@ryuhq/sdk` | npm | 0.3.0 is published. The `workflow`, `server`, `agui`, `rag`, `evals`, `prompts`, `schema`, `loaders`, `voice`, `a2a`, and `chatgpt` entry points are newer and are not in 0.3.0, and so are the `ryu validate`, `install`, `build`, `deploy`, `dev --studio`, and `chatgpt-plugin` commands. |
| `@ryuhq/client` | npm | 0.3.0 is published. The Managed Agents, Messaging, Notify, and Box clients are newer and are not in 0.3.0. `@ryuhq/services` needs 0.4, which is not published. |
| `@ryuhq/core-client` | npm | 0.3.0 is published. |
| `create-ryu-app` | npm | 0.3.0 is published. The `workflow`, `multi-agent`, and `services` templates are newer and are not in 0.3.0. |
| `@ryuhq/services` | npm | Not published. |
| `@ryuhq/services-cli` (`ryu-services`) | npm | Not published. |
| `ryu-sdk` (`ryu_sdk`, including `ryu_sdk.services`) | PyPI | Not published. |
| `ryu-cli` and `ryu-mcp` | none | Ship with Ryu. They are not npm packages. |

Until a package is published, the curl examples on each
[service page](/docs/standalone/sdk) are the way to call a standalone
service from outside Ryu.
