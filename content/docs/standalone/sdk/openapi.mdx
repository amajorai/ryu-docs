Each standalone service with an HTTP API has its own OpenAPI document. Use
them to generate a client in another language, to import the routes into an
API tool, or to check a request by hand.

The documents describe the same routes,
idempotency keys, and error bodies that `@ryuhq/services` uses, and Ryu's
tests compare each document with the SDK and the service's own routes.

| Service | Document | Servers | Authentication |
|---|---|---|---|
| Managed Agents | [managed-agents.json](https://ryuhq.com/openapi/managed-agents.json) | `https://api.ryuhq.com/api/v1/managed-agents` (preview) | A `ryu_` key in `x-api-key` or as a bearer token, plus `X-Ryu-Organization` for a personal key |
| Mail | [mail.json](https://ryuhq.com/openapi/mail.json) | `https://api.ryuhq.com` (hosted), or your server (self-hosted, default `http://127.0.0.1:7996`) | A `ryu_` key with Mail scopes in `x-api-key` or a node gateway key in `x-gateway-key` (hosted), or a bearer token (self-hosted) |
| Notify | [notify.json](https://ryuhq.com/openapi/notify.json) | `https://notify.ryuhq.com` (hosted, early access), or `{baseUrl}` (default `http://127.0.0.1:8092`) | Tenant bearer token |
| Box | [box.json](https://ryuhq.com/openapi/box.json) | `https://box.ryuhq.com` (hosted, early access), or `{baseUrl}` (default `http://127.0.0.1:8090`) | Bearer token |
| Connect | [connect.json](https://ryuhq.com/openapi/connect.json) | `{baseUrl}` (default `http://127.0.0.1:8094`) | Runtime or management bearer token |
| Passport | [passport.json](https://ryuhq.com/openapi/passport.json) | `{baseUrl}` (default `http://127.0.0.1:8093`) | Admin or runtime bearer token |
| Sites | [sites.json](https://ryuhq.com/openapi/sites.json) | `{baseUrl}` (default `http://127.0.0.1:8021`), the management listener | Bearer token |
| Messaging | [messaging.json](https://ryuhq.com/openapi/messaging.json) | `https://api.ryuhq.com/api/messaging` (early access, enabled per organization) | A `ryu_` key with a `messaging:read` or `messaging:manage` scope in `x-api-key`, plus `X-Ryu-Organization` for a personal key |

A `{baseUrl}` server is a variable: set it to the URL of your deployment, or
to the URL Ryu issued for an early-access service. The local defaults are
the services' own development ports, not hosted endpoints.

## What the documents include

- Every route the SDK calls, with request and response schemas. Every
  operation, parameter, request-body field, and JSON success-response field
  (nested fields and list wrappers included) has a description.
- An example for every JSON request body and JSON success response. Ryu's tests
  check each example against its schema and decode each success example
  with the SDK. Where a service publishes a schema in code, the document is
  generated from it.
- The `Idempotency-Key` header on exactly the routes in the
  [idempotency table](/docs/standalone/sdk/retries-and-idempotency#idempotency-keys),
  marked required where the service rejects a write without one.
- Each service's error body for every `4xx` and `5xx`, with `Retry-After` on
  `429`, and the rate-limit and deprecation headers.
  The Mail document lists the machine `code` values hosted Mail sends with
  each status and what to do about each.
- The signed requests a service sends to your endpoints, listed under OpenAPI
  `webhooks`. These are Mail event deliveries, Messaging event deliveries, and Notify
  destination deliveries and response callbacks. Each one lists its signature
  headers (`webhook-id`, `webhook-timestamp`, and `webhook-signature`, or
  Notify's `X-Ryu-Notify-Signature`) and an example body.

Mail documents both deployments in one file. An operation that only one
deployment serves is marked `x-ryu-deployment: hosted` (hosted Mail only) or
`x-ryu-deployment: standalone` (self-hosted Mail only), and its page in the
interactive reference says which.

## Gateway

Ryu Gateway is OpenAI-compatible and already has an interactive reference:
the [Gateway API reference](/docs/extend/develop/api-reference/gateway). The
SDK's Gateway client calls `GET /health`, `GET /v1/auth/status`,
`GET /v1/models`, `POST /v1/chat/completions`, and `POST /v1/embeddings`.

## The control-plane API

Ryu's hosted control plane, which issues `ryu_` keys and serves the
organization Admin API, has its own document at
[v1.json](https://ryuhq.com/openapi/v1.json); see the
[API reference](/docs/reference/api).
