This page runs the Box calls from the
[Box SDK quickstart](/docs/standalone/sdk/box) with the `ryu-services`
command line and its MCP tools.

## CLI

The `ryu-services` command line reads the variables from
[Configure](/docs/standalone/sdk/box#configure). Add `--json` for
`{ data, meta }` output, or `--dry-run` to print the equivalent curl command
with `$RYU_BOX_API_KEY` in place of the key. Replace `<box-id>` with the `id`
that `box create` prints, such as `bx_0123...`.

```sh
ryu-services box list
ryu-services box create --name cli-runner --size small
ryu-services box get <box-id>
ryu-services box exec <box-id> -- uname -a
ryu-services box stop <box-id>
ryu-services box resume <box-id>
ryu-services box delete <box-id>
```

### What each command prints

| Command | Output |
|---|---|
| `box list` | One JSON line per Box (see [list output](/docs/standalone/sdk/cli#list-output)) |
| `box stop` | The Box afterwards, read again after stopping, so a script can check `status` |
| `box resume` | The Box afterwards |
| `box delete` | `OK` |

With `--json`, `box stop` prints the Box with the stop request's `meta` (its
`requestId`), not the read's. If the read after a stop fails or takes longer
than a few seconds, the stop still succeeded, and `box stop` prints `OK`, or
`data: null` with the stop's `meta` under `--json`.

### Run a command with box exec

`box exec` streams the command's output to stdout and stderr as it arrives.

- With `--json` it prints one JSON line per event.
- `--buffered` waits and prints the result instead, with a request timeout
  that covers `--command-timeout` unless you pass `--timeout`.

When the command exits non-zero, is killed, or times out, `box exec` prints
its output, then fails with the error code `command_failed`
(`details.exitCode`) and exits `1`. So
`ryu-services box exec <box-id> -- ./run-tests.sh && deploy` stops when the
script fails.

### Create a Box

`box create --wait` waits until the Box leaves `provisioning`. Without
`--name`, `box create --idempotency-key <key>` derives the name from the
key, so running the same command again returns the first Box.

### Before the CLI is published

Until `@ryuhq/services-cli` is on npm, run these as `ryu-cli services box ...`
with the same flags. `ryu-cli services` arrives in a Ryu release after 0.4.0,
and until then neither the CLI nor the MCP server can be installed outside the
Ryu repository (see
[Run it from ryu-cli](/docs/standalone/sdk/cli#run-it-from-ryu-cli)).

## MCP

`ryu-services mcp` serves MCP tools over stdio for the services you have
configured. Limit it to Box with `--services box`.

By default it exposes only the read tools `box_list`, `box_get` and
`box_read_file`. Add `--allow-writes` to the args to also expose the tools
that create a Box, run commands or write files in it, or stop, resume or
delete it.

Until `@ryuhq/services-cli` is on npm, start it through `ryu-cli`, as below.
`ryu-cli services` arrives in a Ryu release after 0.4.0. Once it is published,
use `"command": "ryu-services"` and drop `"services"` from `args`.

```json
{
  "mcpServers": {
    "ryu-services": {
      "command": "ryu-cli",
      "args": ["services", "mcp", "--services", "box"],
      "env": {
        "RYU_BOX_API_KEY": "<tenant-key>"
      }
    }
  }
}
```

Without `RYU_BOX_URL`, the MCP server calls `https://box.ryuhq.com`. For a Box
at another URL, such as a self-hosted one, add
`"RYU_BOX_URL": "<your Box URL>"` to `env`, or every tool answers `401`.

| Tool | What it does | Read-only |
|---|---|---|
| `box_list` | Lists the tenant's Boxes and their status. | Yes |
| `box_get` | Returns one Box and its status; poll it after `box_create` until the Box leaves `provisioning`. | Yes |
| `box_create` | Creates a Box. Open world. | No |
| `box_exec` | Runs one command, waits up to its `timeoutSecs` (default 120), and returns its exit code and output. Never replayed. Destructive. | No |
| `box_read_file` | Reads a file as text. | Yes |
| `box_write_file` | Creates or replaces a file. Destructive. | No |
| `box_stop` | Stops a Box; its disk is kept, but every running process ends. Destructive. | No |
| `box_resume` | Starts a stopped Box again with its disk and returns the Box. A Box that is already ready or running is returned unchanged. | No |
| `box_delete` | Deletes a Box and its disk. Destructive. | No |

Results carry `{ data, meta }`. Failures are tool errors that carry the
`RyuError` fields, including `code` and `requestId`, and never the key.
