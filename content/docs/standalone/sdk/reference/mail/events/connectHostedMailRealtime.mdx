      - content: >-
          Hosted Mail. Upgrade to a WebSocket offering `ryu-mail.v1` and
          `ryu-ticket.<ticket>` in `Sec-WebSocket-Protocol`, with a ticket from
          `POST /api/mail/realtime/tickets`; the server selects `ryu-mail.v1`,
          so the ticket is never echoed back. The first attempt consumes the
          ticket, whatever its outcome. Frames match self-hosted Mail:
          `connected` on open, a JSON `{ eventTypes?, inboxIds? }` filter
          acknowledged with `subscribed` (a malformed or oversized filter gets a
          `{ type: "error", code, error }` frame with code
          `invalid_subscription` instead), `ping` answered with `pong`, and `{
          type: "event", event }` carrying a `MailEvent`. A node gateway key's
          socket sees no other node's agent inboxes. The upgrade re-checks the
          organization's IP allowlist against the connecting client (403
          `org_ip_not_allowed`; 503 when the policy cannot be read). A
          credential holds at most 16 open sockets and an organization at most
          64 (429). A request that is not a WebSocket upgrade gets 426
          `upgrade_required`, and 503 means Mail is not configured on this
          deployment. Every minute an open socket re-checks the credential that
          minted its ticket (key or gateway credential still live with
          `mail:read`, member or service account still holding `mail.read`, Mail
          still enabled) and closes with code 4001 when it no longer may read;
          every socket is also closed with 4001 after 15 minutes. On 4001, mint
          a new ticket, reconnect, and replay any gap from `GET
          /api/mail/events`.
