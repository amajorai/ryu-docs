Ryu Mail stores inboxes, messages, threads, drafts and attachments, sends mail through the configured transport, and delivers signed event webhooks. One `/api/mail/*` contract has two deployments.

**Hosted Mail** (`https://api.ryuhq.com`) authenticates with an organization's node gateway key in `x-gateway-key` (minted only through Ryu node enrollment), or with a Ryu API key in `x-api-key` that carries Mail scopes: `mail:read` for reads, `mail:send` to send, reply, forward and work drafts, and `mail:manage` for inbox, domain, list, pod and webhook changes. Changing the organization mailbox, its aliases or the send policy, and deciding an approval, are console-member actions that no key can call (`x-ryu-api-key-scope: session_only`).

Each hosted operation names its scope in `x-ryu-api-key-scope`. An organization key acts in its own organization; a personal key names the organization in `X-Ryu-Organization`. Either key is also limited by the current `mail.read` / `mail.manage` permissions of the member it acts for. A key without the scope gets 403 `insufficient_scope`. A signed-in console session also works from the dashboard. There is no self-serve hosted Mail signup.

**Self-hosted Mail** (`{baseUrl}`, port 7996 by default) authenticates with its own bearer token (`RYU_MAIL_API_TOKEN` on the server). One process serves one tenant.

Operations only one deployment serves are marked `x-ryu-deployment: hosted` or `x-ryu-deployment: standalone`. Schemas show the camelCase form hosted Mail returns; self-hosted Mail may use snake_case names and wrap single objects (`{ "message": … }`). The `@ryuhq/services` SDK reads both.
