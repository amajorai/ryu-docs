Ryu Connect is a tenant-scoped integration edge: a shared SKILL.md catalog, governed tool search and execution over registered MCP servers and Composio, native Composio execution, a Composio usage report, its own MCP servers at /mcp and /mcp/meta, the tenant's balance, async tasks, call reviews, vendor resources and reference media.

Every `/v1` and `/mcp` request carries one tenant's runtime bearer. Hosted Connect is in early access: Ryu provisions the base URL and key; there is no self-serve signup, and the service is not distributed for self-hosting yet.

Errors are `{ code, error, ok: false }`, with the request id in `x-request-id`. Call-limit refusals add `retryAfterSeconds`. A request whose Accept names `application/problem+json` gets RFC 9457 problem details instead (the first `ConnectError` form): `type`, `title`, `status`, `detail`, `instance`, `code` and `docs`, plus every legacy member. A 401 carries `WWW-Authenticate: Bearer realm="ryu-connect"`.

Responses forwarded from an upstream in compatibility mode (`/v1/exec/tool`, `/v1/composio` and `/v1/tools/*` without native bindings, and `/mcp`) keep the upstream's body, are not normalized and are not negotiated; JSON-RPC errors from the MCP endpoints keep the JSON-RPC format. No route deduplicates writes by Idempotency-Key, so tool and action execution must not be retried blindly.

When the tenant's Composio binding sets `maxCallsPerMinute`, native Composio executions (`/v1/composio/execute`, and `/v1/exec/tool` for `composio.*` tools) carry `RateLimit` and `RateLimit-Policy` (draft-ietf-httpapi-ratelimit-headers-11, policy `composio-calls`, a rolling 60-second window), as does their `429 rate_limited`.
