Ryu Notify is a tenant-scoped event inbox for products and agents: durable event history, interactive approvals, live activities, Server-Sent Events, and signed, retrying delivery to webhook, ntfy and BuzzKit destinations.

Every `/v1` request carries one tenant's bearer key. Hosted Notify (`https://notify.ryuhq.com`) is in early access: Ryu provisions the key; there is no self-serve signup. The self-hosted service is not yet published.

Errors share one envelope: `{ ok: false, type: "notify.error", code, message, status, requestId, error: { code, message, status, requestId, details? } }`, with the request id also in `X-Request-ID`. A request whose Accept names `application/problem+json` gets RFC 9457 problem details instead (`NotifyProblem`): `type`, `title`, `status`, `detail`, `instance`, `code` and `docs`, plus every legacy member except `type`. A replayed publish answers 200 with `idempotent: true`; Notify sends no `Idempotent-Replayed` header.

A known path called with a method it does not serve answers `405 method_not_allowed` with an `Allow` header (the `NotifyError405` response); `HEAD` is served wherever `GET` is, `OPTIONS` on a known path answers `204` with `Allow`, and an unknown path answers `404 not_found`. With a publish limit configured, publishes carry `RateLimit` and `RateLimit-Policy` (draft-ietf-httpapi-ratelimit-headers-11, policy `publish`). Destinations with a secret receive Standard Webhooks headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`) beside `X-Ryu-Notify-Signature`.
