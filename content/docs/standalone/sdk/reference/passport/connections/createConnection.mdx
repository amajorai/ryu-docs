      - content: >-
          Creates a `NEEDS_AUTH` connection with `IDLE` flow status. A Passport
          whose capabilities list `features.idempotency_keys: true` honours an
          optional `Idempotency-Key` header (1 to 255 printable ASCII
          characters, scoped to the tenant): a retry with the same key and body
          answers with the first result and `Idempotent-Replayed: true` instead
          of creating a second connection, the same key with a different body
          gets `409 idempotency_conflict`, and a retry while the first still
          runs gets `409 idempotency_in_progress` with `Retry-After`. Without
          the header every request creates a connection. The `@ryuhq/services`
          SDK sends a key it generates, and retries the create with it after a
          network error, timeout or 5xx, only when `GET /v1/capabilities` lists
          `features.idempotency_keys: true`; otherwise it never retries this
          create. A key you supply is always sent.
