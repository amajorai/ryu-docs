Ryu Sites is early access and self-hosted only, and standalone mode needs a ryu-sites release after 0.4.0, which is not published yet. The published 0.4.0 runs only as the Core-managed sidecar; with a later release you run the standalone process yourself, and there is no Ryu-hosted offer. This document covers the management listener (`RYU_SITES_PORT`; the Sites docs start it on `http://127.0.0.1:8021`), whose `/api/sites/*` routes take the standalone management bearer.

Deployed pages, their `/_ryu/*` data routes and each Site's MCP endpoint are on the separate visitor listener and are not in this document. Every change sends the `revision` it read as `expectedRevision`; a stale one answers `409 conflict`. A new Site is private, and deploying it does not change that: to serve it to everyone, the operator sets `RYU_SITES_PUBLIC=1` and you set `settings.audience` to `public` with `PUT /api/sites/projects/{id}/settings`.

Errors are `{ error: { code, message, fields? } }`, or RFC 9457 problem details when Accept names `application/problem+json`; every response carries `X-Request-ID`, except the listener's empty 413 for a body over 2,200,000 bytes.
