<Callout type="warn">
Early access: hosted on the Ryu control plane; Ryu enables it per organization, and the organization must also turn on its Ryu Messaging feature (off by default); there is no self-hosted service.
</Callout>

This page runs the Messaging calls from the
[Messaging SDK quickstart](/docs/standalone/sdk/messaging) with the `ryu-services`
command line and its MCP tools.

<Callout type="info">
Until `@ryuhq/services-cli` is on npm, run the commands below as
`ryu-cli services messaging ...`, with the same flags. `ryu-cli services` arrives
in a Ryu release after 0.4.0, and until then neither the CLI nor the MCP
server can be installed outside the Ryu repository (see
[ryu-services CLI](/docs/standalone/sdk/cli#run-it-from-ryu-cli)).
</Callout>

## CLI

The `ryu-services` command line reads the variables from
[Configure](/docs/standalone/sdk/messaging#configure). Add `--json` for
`{ data, meta }` output, or `--dry-run` to print the equivalent curl command
with `$RYU_API_KEY` in place of the key.

```sh
ryu-services messaging status
ryu-services messaging quote --to +6591234567 --body "Your order has shipped."
ryu-services messaging sms send --from <number-id> --to +6591234567 --body "Your order has shipped." --idempotency-key order-1842-shipped
ryu-services messaging numbers list
ryu-services messaging messages list --direction inbound --limit 20
ryu-services messaging messages get <message-id>
```

- `numbers list` and `messages list` print one JSON line per item, and
  `messages list` names the next page's `--cursor` on stderr (see [list output](/docs/standalone/sdk/cli#list-output)).
- `messages list --all` follows `nextCursor` to the end of the log and prints
  one message per JSON line.
- `numbers list --include-released` adds released
  and failed numbers.
- Retry a failed `sms send` with the same
  `--idempotency-key`.

## MCP

`ryu-services mcp` serves MCP tools over stdio for the services you have
configured. Limit it to Messaging with `--services messaging`. By default it
leaves out `messaging_send_sms`; add `--allow-writes` to the args to expose
it.

Until `@ryuhq/services-cli` is on npm, start the server through `ryu-cli`, as
below. Once it is published, use `"command": "ryu-services"` and drop
`"services"` from `args`.

```json
{
  "mcpServers": {
    "ryu-services": {
      "command": "ryu-cli",
      "args": ["services", "mcp", "--services", "messaging"],
      "env": {
        "RYU_API_KEY": "ryu_...",
        "RYU_ORGANIZATION_ID": "<organization-id>"
      }
    }
  }
}
```

| Tool | What it does | Read-only |
|---|---|---|
| `messaging_status` | Reports whether the control plane has Messaging configured and which channels can send, not whether Messaging is on for your organization. It needs no key, so `ryu-services mcp` registers it even when `RYU_API_KEY` and `RYU_ORGANIZATION_ID` are unset, and then sends neither. | Yes |
| `messaging_quote` | Quotes the hold an SMS would place, and the available credit. | Yes |
| `messaging_send_sms` | Sends a real SMS and holds its cost; requires an `idempotencyKey`. Optional `messageType` (`TRANSACTIONAL` or `PROMOTIONAL`) and `ttlSeconds` (5 to 259200) match the CLI's `--message-type` and `--ttl`. | No |
| `messaging_list_messages` | Lists one page of the message log. | Yes |
| `messaging_get_message` | Reads one message, with its status and charge. | Yes |
| `messaging_list_numbers` | Lists the organization's numbers, whose ids a send uses as `from`. `includeReleased: true` also lists released and failed numbers, like the CLI's `--include-released`; `all` is its deprecated alias. | Yes |

Results carry `{ data, meta }`. Failures are tool errors that carry the
`RyuError` fields, including `code`, `requestId`, and `hint`, and never the
key.
