<Callout type="info">
Available: hosted with a Ryu API key that has Mail scopes or a Ryu node gateway key, or self-hosted.
</Callout>

With a `ryu_` key in `RYU_API_KEY` whose Mail access is **Read & send**
(`mail:read` and `mail:send`), sending from hosted Mail takes three lines. A
personal key also needs `RYU_ORGANIZATION_ID` set to the organization it acts
in; an organization key does not:

```ts tab="Node"
import { Ryu } from "@ryuhq/services";

const ryu = new Ryu();
await ryu.mail.send({ from: "agent@acme.example", to: ["person@example.com"], subject: "Welcome", text: "Hello from Ryu Mail." });
```

```python tab="Python"
from ryu_sdk.services import Ryu

ryu = Ryu()
ryu.mail.send({"from": "agent@acme.example", "to": ["person@example.com"], "subject": "Welcome", "text": "Hello from Ryu Mail."})
```

`from` as an address makes the SDK look the inbox up first, which is a read
(`mail:read`). A key with only `mail:send` can send when `from` is the inbox
ID, such as `from: "<inbox-id>"`, because that is a single send request.

This page makes a first call to [Ryu Mail](/docs/standalone/mail) with curl,
with the `@ryuhq/services` TypeScript SDK, with the `ryu_sdk.services` Python client, with the `ryu-services` command
line, and with its MCP tools. Hosted and self-hosted Mail share one
`/api/mail/*` contract; the full route, signature, and attachment rules are on
[Ryu Mail API](/docs/standalone/mail-api).

<Callout type="info">
@ryuhq/services is not yet published to npm; it requires @ryuhq/client 0.4 or later, which is also not yet on npm (latest is 0.3.0).
</Callout>

<Callout type="info">
The `ryu-sdk` Python package is not yet published to PyPI, so the Python client cannot be installed outside Ryu either.
</Callout>

## What you need

Pick one deployment.

- **Hosted Mail with a Ryu API key** (`https://api.ryuhq.com`): a `ryu_` key
  that carries Mail scopes, sent as `x-api-key`. `mail:read` covers reads,
  `mail:send` covers sending, replies, drafts and labels, and `mail:manage`
  covers inboxes, domains, lists, pods, webhooks and deletes; a classic token
  includes at most read and send. A personal key also needs the organization
  ID, sent as `X-Ryu-Organization`; an organization key acts in its own
  organization. The key is also limited by the current organization
  permissions of what it acts for. The full rules are under
  [Hosted Mail API keys](/docs/standalone/mail-api#hosted-mail-api-keys).
  Create the key in the Ryu console as a fine-grained token, under
  **Personal access tokens** or your organization's **Access > API keys** (the
  Team API keys page), and set its **Mail** access to **Read & send** for the
  quickstart above.
- **Hosted Mail with a node gateway key**: an organization's node gateway key,
  sent as `x-gateway-key`. It is minted only through Ryu node enrollment. Team
  and personal node credentials cannot reach organization Mail. How the
  organization gateway key authenticates Mail is described under
  [Agent Inboxes API](/docs/extend/develop/agent-inboxes-api#authentication).
- Plan limits for hosted Mail are on
  [Agent Inboxes billing](/docs/billing/agent-inboxes).
- **Self-hosted Mail**: a Mail process you run, as described in
  [Start the standalone service](/docs/standalone/mail#start-the-standalone-service).
  It listens on port 7996 by default and accepts the bearer token you set as
  `RYU_MAIL_API_TOKEN` on the server. To send, the server also needs an
  outbound transport: set `RYU_SMTP_HOST` and `RYU_SMTP_PASSWORD` (with
  `RYU_SMTP_PORT`, `RYU_SMTP_USERNAME` and `RYU_SMTP_FROM` as your provider
  needs) where it runs. Until then `mail.status()` reports
  `sendConfigured: false` and a send fails with
  `400 bad_request: email transport is not configured`.

`ryu.mail.status()` (Python `ryu.mail.status()`, CLI `ryu-services mail
status`, MCP `mail_status`) is the one Mail call that runs without a key on
hosted Mail: the control plane answers `GET /api/mail/status` unauthenticated,
so with no Mail key and `RYU_MAIL_URL` unset (or on the control-plane origin)
it goes to the control-plane origin and sends no key or organization. It
reports the deployment's Mail configuration, not whether your key or
organization may use Mail. A self-hosted server answers its status route only
with its token, so there `status()` still needs `RYU_MAIL_API_KEY`. The result
also carries `domain`, the domain hosted inboxes use (`null` when it is unset,
and on self-hosted Mail).

Every other Mail call needs a key. When `RYU_MAIL_URL` is the control-plane
origin, that is hosted Mail, and a missing-key error names `RYU_API_KEY` or
`RYU_MAIL_GATEWAY_KEY`, not `RYU_MAIL_API_KEY`.

If a count or size in a Mail reply is not a number, the TypeScript SDK throws
`RyuResponseValidationError` (`invalid_response`) instead of returning `NaN`,
and the `mail_*` tools in both SDKs return that error.

You also need an inbox to send from. On hosted Mail, create one in the Ryu
dashboard. On self-hosted Mail, create it with a name and the inbox's full
`address`, as below.

```ts tab="Node"
import { Ryu } from "@ryuhq/services";

// Reads RYU_MAIL_URL and RYU_MAIL_API_KEY.
const ryu = new Ryu({ result: "object" });

const { data: inbox, error } = await ryu.mail.inboxes.create({
  name: "Agent",
  address: "agent@acme.example",
});
console.log(error ? error.message : inbox.id);
```

```python tab="Python"
from ryu_sdk.services import Ryu

# Reads RYU_MAIL_URL and RYU_MAIL_API_KEY.
ryu = Ryu(result="object")

inbox, error, _ = ryu.mail.inboxes.create({"name": "Agent", "address": "agent@acme.example"})
if error:
    print(error.message)
elif inbox:
    print(inbox["id"])
```

From the command line, `ryu-services mail inboxes create --name Agent --address
agent@acme.example` does the same. A hosted `ryu_` key needs `mail:manage` to
create an inbox. Self-hosted Mail requires `address`. Hosted Mail ignores
`address`. Send `localPart` to choose the part before `@` (a taken or invalid
local part is refused, so check it first with `inboxes.checkAddress`, Python `check_address`), or leave
it out and the inbox gets a local part made from the name (with a suffix added
when that address is taken, or a random one when the name gives none). Either
way the address is on the default domain, or on `domainId` when you send one.
On the command line, hosted Mail takes `--local-part` instead of `--address`;
the CLI does not send `--address` to hosted Mail and says so on stderr.

Hosted Mail records which credential created each inbox. The HTTP API returns
it as `createdWith` to callers who may manage Mail, never to node gateway keys (see [Hosted Mail API
keys](/docs/standalone/mail-api#hosted-mail-api-keys)). The SDK's inbox object
carries it as an optional `createdWith` object with `via` (`session`, `api_key`, `oauth` or
`gateway_key`) plus `apiKeyId`, `serviceAccountId`, `oauthClientId` and
`gatewayCredentialId` (IDs only, `null` when they do not apply). It is `null` for an
inbox created before Ryu recorded it, and absent when your credential may not see it
or the server is self-hosted, so check for it before you read it. Python returns the
same key in the inbox `dict` (typed as `MailInboxCreatedWith` in
`ryu_sdk.services.shapes`). Creates made with a `ryu_` key or a hosted MCP
app also appear as `mail.inbox.create` in the organization's audit log.

## Configure

The SDK and the CLI read these environment variables. Options passed to
`new Ryu()` win over them, and `new Ryu({ env: false })` turns env reads off.

| Variable | Default | Description |
|---|---|---|
| `RYU_MAIL_URL` | none | Mail origin. Required for self-hosted Mail; hosted Mail defaults to the control-plane origin when a gateway key or a ryu_ key selects it. |
| `RYU_MAIL_GATEWAY_KEY` | none | Hosted Mail node gateway key, sent as x-gateway-key. Minted only through Ryu node enrollment; wins over a ryu_ key. |
| `RYU_MAIL_API_KEY` | none | Self-hosted Mail bearer token. |

Hosted Mail also reads the control-plane `RYU_API_KEY`, `RYU_ORGANIZATION_ID`
and `RYU_API_URL` described on the [SDK overview](/docs/standalone/sdk#configure),
or the `apiKey`, `organizationId` and `baseUrl` options.

Hosted Mail with a Ryu API key:

```sh
export RYU_API_KEY="<ryu_ key with Mail: Read & send>"
# A personal key also needs the organization:
export RYU_ORGANIZATION_ID="<organization-id>"
```

Hosted Mail with a node gateway key:

```sh
export RYU_MAIL_GATEWAY_KEY="<node-gateway-key>"
```

Self-hosted Mail:

```sh
export RYU_MAIL_URL="http://127.0.0.1:7996"
export RYU_MAIL_API_KEY="<the server's RYU_MAIL_API_TOKEN>"
```

When more than one credential is set, a key passed to `new Ryu()`
(`mail.gatewayKey`, `mail.apiKey`, or `apiKey`) wins over every environment
variable. Among the options, and then among the environment variables, the
SDK picks the first of these that applies:

1. A node gateway key (`mail.gatewayKey`, or `RYU_MAIL_GATEWAY_KEY`). With a
   self-hosted bearer and a `RYU_MAIL_URL` that is not
   `https://api.ryuhq.com`, the bearer is used instead.
2. A self-hosted bearer (`mail.apiKey`, or `RYU_MAIL_API_KEY`). It needs
   `RYU_MAIL_URL`; without one the call fails with a
   `RyuConfigurationError` that names it.
3. The control-plane `ryu_` key (`apiKey`, or `RYU_API_KEY`), with
   `X-Ryu-Organization` when an organization is set. It is skipped when
   `RYU_MAIL_URL` points anywhere but the control-plane origin.

`managedAgents.apiKey` is only for Managed Agents and never selects hosted
Mail.

The SDK sends `RYU_API_KEY` only to hosted Mail on the control-plane origin.
With a self-hosted `RYU_MAIL_URL` and no `RYU_MAIL_API_KEY`, a call fails with
a `RyuConfigurationError` instead of sending the `ryu_` key there.

## First call with curl

List your inboxes on hosted Mail with a Ryu API key. Leave out
`X-Ryu-Organization` for an organization key:

```sh
curl -sS "https://api.ryuhq.com/api/mail/inboxes" \
  -H "x-api-key: $RYU_API_KEY" \
  -H "X-Ryu-Organization: $RYU_ORGANIZATION_ID" \
  -H "Accept: application/json"
```

With a node gateway key, send it as `x-gateway-key` instead:

```sh
curl -sS "https://api.ryuhq.com/api/mail/inboxes" \
  -H "x-gateway-key: $RYU_MAIL_GATEWAY_KEY" \
  -H "Accept: application/json"
```

On self-hosted Mail, use your URL and the bearer token:

```sh
curl -sS "$RYU_MAIL_URL/api/mail/inboxes" \
  -H "Authorization: Bearer $RYU_MAIL_API_KEY"
```

Send from an inbox. The `Idempotency-Key` makes a retry of the same request
safe. As with the list call, leave out `X-Ryu-Organization` for an
organization key:

```sh
curl -sS -X POST "https://api.ryuhq.com/api/mail/inboxes/<inbox-id>/send" \
  -H "x-api-key: $RYU_API_KEY" \
  -H "X-Ryu-Organization: $RYU_ORGANIZATION_ID" \
  -H "Idempotency-Key: welcome-42" \
  -H "Content-Type: application/json" \
  -d '{"to":["person@example.com"],"subject":"Welcome","text":"Hello from Ryu Mail."}'
```

## First call with the SDK

With `result: "object"`, every call resolves to `{ data, error, meta }` and
never throws for API or configuration errors. `mail.send()` takes the sending
inbox as `from`, either its address or its id:

```ts tab="Node"
import { Ryu } from "@ryuhq/services";

// Reads RYU_MAIL_GATEWAY_KEY, RYU_MAIL_URL and RYU_MAIL_API_KEY, or RYU_API_KEY.
const ryu = new Ryu({ result: "object" });

const { data, error, meta } = await ryu.mail.send(
  {
    from: "agent@acme.example",
    to: ["person@example.com"],
    subject: "Welcome",
    text: "Hello from Ryu Mail.",
  },
  { idempotencyKey: "welcome-42" }
);

if (error) {
  console.error(error.code, error.message, error.requestId);
} else {
  console.log(data.id, data.status, meta.idempotencyKey);
}
```

```python tab="Python"
from ryu_sdk.services import Ryu

# Reads RYU_MAIL_GATEWAY_KEY, RYU_MAIL_URL and RYU_MAIL_API_KEY, or RYU_API_KEY.
ryu = Ryu(result="object")

data, error, meta = ryu.mail.send(
    {
        "from": "agent@acme.example",
        "to": ["person@example.com"],
        "subject": "Welcome",
        "text": "Hello from Ryu Mail.",
    },
    idempotency_key="welcome-42",
)

if error:
    print(error.code, error.message, error.request_id)
elif data and meta:
    print(data["id"], data["status"], meta.idempotency_key)
```

An address in `from` costs one extra `inboxes.list` call the first time it is
used. The answer is cached for the life of that `Ryu` instance, so later sends
from the same address make one request. Pass the inbox id to skip the lookup.
The second argument takes `idempotencyKey`, `signal`, and `headers`; set a
per-call timeout with `ryu.mail.with({ timeoutMs })`.

A `react` field sends a React Email element instead of `html`. It is rendered with the optional peer package `@react-email/render`,
which you install yourself. Without it the call fails with
`react_renderer_missing`, and nothing is sent. The SDK loads the renderer at
runtime and bundlers leave that import out, so a bundled build or an edge
runtime does not include it: render the element yourself with
`@react-email/render` and pass the result as `html`.

For every other `ryu.mail` method (inboxes, messages, threads, drafts,
webhooks, events, pods, domains, lists), list limits, realtime sockets, and
inbox iteration, see [Mail SDK resources](/docs/standalone/sdk/mail-resources).

## Expected response

A send returns the stored message. Example from the
[OpenAPI document](https://ryuhq.com/openapi/mail.json):

```json
{
  "attachments": [],
  "bcc": [],
  "cc": [],
  "createdAt": "2026-10-01T12:05:00.000Z",
  "direction": "outbound",
  "from": "agent@acme.example",
  "id": "msg_01",
  "inboxId": "inbox_01",
  "labels": ["sent"],
  "status": "sent",
  "subject": "Welcome",
  "text": "Hello from Ryu Mail.",
  "threadId": "thr_01",
  "to": ["person@example.com"],
  "updatedAt": "2026-10-01T12:05:00.000Z"
}
```

Hosted Mail returns this camelCase form. Self-hosted Mail can use snake_case
field names and wrap the object as `{ "message": … }`; the SDK reads both.

## Webhooks

Mail signs event webhooks with Standard Webhooks headers. Verify a delivery
against the raw request body with `verifyMailWebhook`, and answer a
`RyuWebhookVerificationError` with `401`, or `422` when its code is
`webhook_payload_invalid` (a signed delivery whose body is not the expected
JSON). The Python sample is a FastAPI handler; `ryu-sdk` does not depend on
FastAPI, so install it first, for example
`pip install fastapi uvicorn`.

```ts tab="Node"
import { RyuWebhookVerificationError, verifyMailWebhook } from "@ryuhq/services/webhooks";

export async function POST(request: Request): Promise<Response> {
  try {
    const event = await verifyMailWebhook({
      payload: await request.text(),
      headers: request.headers,
      secret: process.env.MAIL_WEBHOOK_SECRET ?? "",
    });
    console.log(event.event_type, event.event_id);
    return Response.json({ ok: true });
  } catch (error) {
    // A signed delivery whose body is not the service's JSON gets 422. A forged, altered, or stale one gets 401 so it is not acknowledged; each retry fails verification again.
    if (error instanceof RyuWebhookVerificationError) {
      const status = error.code === "webhook_payload_invalid" ? 422 : 401;
      return Response.json({ code: error.code }, { status });
    }
    throw error;
  }
}
```

```python tab="Python"
import os

from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse
from ryu_sdk.services import RyuWebhookVerificationError, verify_mail_webhook

app = FastAPI()


@app.post("/webhooks/mail")
async def mail_webhook(request: Request) -> JSONResponse:
    try:
        event = verify_mail_webhook(
            payload=await request.body(),
            headers=request.headers,
            secret=os.environ.get("MAIL_WEBHOOK_SECRET", ""),
        )
    except RyuWebhookVerificationError as error:
        status = 422 if error.code == "webhook_payload_invalid" else 401
        return JSONResponse({"ok": False, "error": {"code": error.code, "message": error.message}}, status_code=status)
    print(event["event_type"], event["event_id"])
    return JSONResponse({"ok": True})
```

Deliveries are retried, so deduplicate on `event_id`. The signature scheme and
the event list are on [Ryu Mail API](/docs/standalone/mail-api).
