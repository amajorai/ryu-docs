This page runs the Mail calls from the
[Mail SDK quickstart](/docs/standalone/sdk/mail) with the `ryu-services`
command line and its MCP tools. For Ryu's hosted `/mcp` endpoint, which needs
no node and no install, see
[Hosted Mail MCP tools](/docs/standalone/sdk/mcp-hosted-mail).

## CLI

The `ryu-services` command line reads the variables from
[Configure](/docs/standalone/sdk/mail#configure). Add `--json` for
`{ data, meta }` output, or `--dry-run` to print the equivalent curl command
with `$RYU_MAIL_GATEWAY_KEY` (or `$RYU_MAIL_API_KEY` for self-hosted Mail) in
place of the key.

```sh
ryu-services mail status
ryu-services mail inboxes list
ryu-services mail inboxes create --name Agent --address agent@acme.example   # self-hosted
ryu-services mail inboxes create --name Agent --local-part agent              # hosted
ryu-services mail messages list <inbox-id> --limit 20
ryu-services mail messages get <message-id>
ryu-services mail send --from agent@acme.example --to person@example.com --subject "Welcome" --text "Hello from Ryu Mail." --idempotency-key welcome-42
```

Until `@ryuhq/services-cli` is on npm, run these as
`ryu-cli services mail ...`, with the same flags; `ryu-cli services` arrives
in a Ryu release after 0.4.0, and until then neither the CLI nor the MCP
server can be installed outside the Ryu repository (see
[ryu-services CLI](/docs/standalone/sdk/cli#run-it-from-ryu-cli)).

`inboxes list` and `messages list` print one JSON line per item (see
[list output](/docs/standalone/sdk/cli#list-output)). A full `messages list` page may have more below it, so stderr names
the `--before` value for the next page; `messages list --all` pages through
every message and prints one JSON line each. `send` takes `--html-file <path>` instead of `--text`, and repeated
`--to`, `--cc`, and `--bcc` flags. With an address in `--from`, a dry run
prints only the inbox lookup, which is the first request. When a self-hosted
server has no outbound transport, `send` prints a hint naming the
`RYU_SMTP_*` settings and the
[setup steps](/docs/standalone/mail#start-the-standalone-service).

## MCP

`ryu-services mcp` serves MCP tools over stdio for the services you have
configured. Limit it to Mail with `--services mail`. By default it leaves out
`mail_create_inbox` and `mail_send`; add `--allow-writes` to the args to
expose them.

Until `@ryuhq/services-cli` is on npm, start the server through `ryu-cli`,
as below (`ryu-cli services` arrives in a Ryu release after 0.4.0; until then
neither the CLI nor the MCP server can be installed outside the Ryu
repository); once it is published, use
`"command": "ryu-services"` and drop `"services"` from `args`.

```json
{
  "mcpServers": {
    "ryu-services": {
      "command": "ryu-cli",
      "args": ["services", "mcp", "--services", "mail"],
      "env": {
        "RYU_MAIL_GATEWAY_KEY": "<node-gateway-key>"
      }
    }
  }
}
```

| Tool | What it does | Read-only |
|---|---|---|
| `mail_status` | Reports whether the Mail server has Mail configured and can send. On hosted Mail it needs no key, so `ryu-services mcp` registers it even when Mail is not configured; a self-hosted server needs its token. | Yes |
| `mail_list_inboxes` | Lists the inboxes this key can see. | Yes |
| `mail_list_messages` | Lists one inbox's messages, newest first; page with `before`. | Yes |
| `mail_get_message` | Reads one message in full. | Yes |
| `mail_create_inbox` | Creates an inbox from `name` and a required `clientId`, with `address` (self-hosted, required) or `localPart` and `domainId` (hosted), plus optional `podId` and (hosted only) `description`. | No |
| `mail_send` | Sends an email from an inbox address or id, with exactly one of `text` or `html`. Requires `idempotencyKey`. | No |

Results carry `{ data, meta }`. Failures are tool errors that carry the
`RyuError` fields, including `code` and `requestId`, and never the key.
`mail_send` reaches real recipients, so hosts should ask before running it.
Its `idempotencyKey` is required (printable ASCII, 1-255 characters): a tool
call that is run again with the same key does not send a second email. Inbox
and message ids are letters, digits, `_`, and `-`; anything else is refused
before a request is made.

`mail_create_inbox` gives an agent with a new key its first inbox. Its
`clientId` (printable ASCII, with no leading or trailing space) is your own id
for the inbox: both hosted and self-hosted Mail answer a create that repeats a
`clientId` with the inbox already made, so a retried tool call does not create
a second inbox. On hosted Mail, a retry that overlaps a first call still in
progress also gets that inbox back, with or without an explicit `localPart`.
A hosted key needs the `mail:manage` scope.
