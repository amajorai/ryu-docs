This reference covers the signed inbound route and outbound event webhooks of
the Ryu Mail HTTP API. For the route table, bearers, and error codes, see the
[Ryu Mail API](/docs/standalone/mail-api).

## Signed inbound mail

The inbound route does not use the bearer. Sign each delivery with the inbox's
inbound secret and send the current Unix time with it:

```text
X-Ryu-Timestamp: <unix seconds>
X-Ryu-Signature: sha256=<hex>
```

The signature is the hexadecimal HMAC-SHA256, keyed with the inbound secret, of
the `X-Ryu-Timestamp` value exactly as sent, a period, and the raw request body:

```sh
ts="$(date +%s)"
sig="$( { printf '%s.' "$ts"; cat message.eml; } \
  | openssl dgst -sha256 -hmac "$INBOUND_SECRET" | awk '{print $NF}')"
curl -sS "https://mail.example.com/api/mail/inbound/$INBOX_ID" \
  -H "X-Ryu-Timestamp: $ts" \
  -H "X-Ryu-Signature: sha256=$sig" \
  --data-binary @message.eml
```

Mail refuses a timestamp more than five minutes from its own clock, so keep the
relay's clock synchronized. It keeps the SHA-256 of every accepted timestamped
delivery for 24 hours, so a captured request cannot be replayed, even after the
message it stored is deleted. A replay is answered `200` with
`"duplicate": true` and stores nothing. Mail records a delivery in the same
step that stores its message, so resending the same signed request after an
error or a dropped connection is safe while its timestamp is in the window: it
is stored if the first attempt was not, and answered as a duplicate if it was.
Signing the same message again with a new timestamp is a new delivery.

The route accepts raw MIME up to 25 MiB. Create an inbox or rotate its secret
through the protected API, then place that secret in the mail provider's
webhook configuration. Sign the raw body exactly as it is sent. Do not parse and
reserialize the MIME body before calculating the signature.

### Body-only signatures

Without `X-Ryu-Timestamp`, Mail still accepts the older form: `X-Ryu-Signature`
over the raw body alone. That signature never expires, so keep such requests
out of logs. Mail answers a re-delivery of a stored message with the same
`Message-ID` or identical raw bytes with `"duplicate": true` and raises no
second event, but once that message is deleted a captured body-only request
can store it again.

When your relay sends timestamps, set `require_timestamp: true` on the inbox
(on `POST /api/mail/inboxes` or `PATCH /api/mail/inboxes/:id`;
`requireTimestamp` is also accepted). Mail then refuses body-only deliveries
with `401`. Inbox responses include `require_timestamp`. A request that carries
`X-Ryu-Timestamp` must use the timestamped signature; Mail never falls back to
the body-only check for it.

## Outbound event webhooks

Create a webhook with `event_types` such as `message.received`, `message.sent`,
`message.delivered`, `message.bounced`, `message.complained`,
`message.rejected`, or `message.opened`. Omitting `event_types` subscribes to
the sidecar's standard event set; an explicit empty list returns `400`.
`inbox_ids` and `pod_ids` narrow delivery; `addInboxIds`, `removeInboxIds`,
`addPodIds`, and `removePodIds` update those scopes without replacing the whole
list. The camelCase spellings `eventTypes`, `inboxIds`, and `podIds` are also
accepted.

Custom header values are accepted on create and update, but only their names
are returned later. Use `removeHeaders` with
the headers endpoint to remove values atomically. A custom header cannot use a
name Mail sets itself (`webhook-id`, `webhook-timestamp`, `webhook-signature`,
the `svix-*` equivalents, `host`, `cookie`, or `content-length`). Destinations
must be public HTTPS endpoints; loopback, private, link-local, metadata, and
internal DNS targets are rejected.

List directions follow the AgentMail vocabulary: `send`, `receive`, and
`reply`, each with an `allow` or `block` list. The hosted API also accepts the
legacy `outbound` and `inbound` path names as aliases and stores them under the
canonical directions.

Each delivery is a JSON envelope:

```json
{
  "type": "event",
  "event_type": "message.received",
  "event_id": "evt_…",
  "data": { "message": { "id": "…", "message_id": "<…>", "subject": "…" } }
}
```

`data.message.id` is the id `GET /api/mail/messages/:id` reads, and
`message_id` is the RFC `Message-ID`. A `message.received` delivery includes the
full text and HTML body, so point webhooks only at endpoints you trust.
`message.sent` carries a `send` object with the recipients and ids, and a
scheduled draft that could not be sent arrives as `message.rejected` with
`draft` and `reason`.

### Verifying deliveries

Deliveries are signed with [Standard Webhooks](https://www.standardwebhooks.com/),
so the Standard Webhooks and Svix libraries verify them with the webhook's
`secret`. The create response returns the secret once. Each delivery carries:

```text
webhook-id: <event_id>
webhook-timestamp: <unix seconds>
webhook-signature: v1,<base64>
```

It repeats the same values as `svix-id`, `svix-timestamp`, and
`svix-signature`. The signature is a base64 HMAC-SHA256 over
`<webhook-id>.<webhook-timestamp>.<raw body>`. Its key is the base64-decoded
part of the secret after `whsec_`. Reject deliveries whose timestamp is far
from your clock; the libraries allow five minutes by default. Webhook responses
include `signature_scheme`.

Mail makes up to three delivery attempts with sub-second backoff and records
each attempt. Treat `event_id` as the idempotency key at the consumer.

### Webhooks created by earlier versions

A webhook created before Standard Webhooks signing reports
`signature_scheme: "legacy"` and keeps working without changes. Its
`svix-signature` is still keyed with the UTF-8 bytes of the whole `whsec_…`
secret, prefix included, as earlier versions signed it. Its `webhook-signature`
already uses the Standard Webhooks key, so a Standard Webhooks library can
verify the `webhook-*` headers with the existing secret.

A Svix SDK checks the `svix-*` headers first. Rotate the secret before you
switch to one: `PATCH /api/mail/webhooks/:id` with `{"rotateSecret": true}`
(`rotate_secret` is also accepted) returns a new secret once, as `secret`, and
moves the webhook to `standard`. The old secret stops verifying immediately.
