`ryu connect` brings Ryu Connect to the terminal: browse Ryu's tool catalog
with USD prices, then search, describe, request and call the tools your
Connect key can use, and check what new calls can spend.

The installed binary is `ryu-cli`. As in the
[CLI reference](/docs/surfaces/cli/reference), the command table uses `ryu` as
shorthand; type `ryu-cli connect` in your shell. The copy-paste examples use
`ryu-cli`.

## Set up

The key is read only from the environment, so it never appears in your shell
history or process list:

| Variable | Purpose |
|---|---|
| `RYU_CONNECT_URL` | Your Connect deployment's base URL (or pass `--url <url>`) |
| `RYU_CONNECT_KEY` | Your Connect key (see [Connect keys](/docs/standalone/connect#connect-keys)) |
| `RYU_TOOL_CATALOG_URL` | Optional catalog URL for `browse` (or `--catalog-url <url>`); `off` turns browsing off |

Without `RYU_TOOL_CATALOG_URL`, `browse` reads `/api/tool-catalog` on your
control plane, taking the first of these:

1. `RYU_CONTROL_PLANE_URL`, if set;
2. `RYU_SERVER_URL`, if set;
3. otherwise Ryu's public catalog at `https://api.ryuhq.com/api/tool-catalog`.

If you set `RYU_SERVER_URL` for other Ryu tools (for example a local
development server), `browse` reads that server's catalog too. Set
`RYU_TOOL_CATALOG_URL` to choose another.

The CLI sends your key only to `RYU_CONNECT_URL`, which must use HTTPS (plain
HTTP only to `localhost`, `127.0.0.1` or `[::1]`), and it never follows a
redirect.

## Commands

| Command | What it does |
|---|---|
| `ryu connect` | Live status: the Connect URL and version, whether a key is set, and your balance |
| `ryu connect browse [platform]` | Ryu's catalog: every platform with its endpoint count, verified count and lowest price, or one platform's endpoints with the price of one call and their verification state. Needs no key |
| `ryu connect search <words…>` | Search the tools your key can call (`--limit 1-25`, `--kind any\|composio\|mcp`). A search that finds nothing lists the words nothing matched and close tool IDs |
| `ryu connect describe <id>` | One tool's price, catalog verification, reliability over the last seven days, and argument schema |
| `ryu connect request <text…>` | Ask for a tool that does not exist yet (`--toolkit`, `--query`) |
| `ryu connect call <id>` | Call a tool |
| `ryu connect balance` | What new calls can spend now, what is held by calls in flight, and where to add credit |

Add `--json` to any command for machine-readable output. Run
`ryu-cli connect help` for the full list.

`ryu connect <agent>` with a coding agent's name, such as `claude-code`, still
adds Ryu's MCP tools to that agent (see the
[CLI reference](/docs/surfaces/cli/reference#coding-agents)); the first word
decides which one runs.

## Calling a tool

```bash
ryu-cli connect call composio.GITHUB_GET_AN_ISSUE \
  --args '{"owner":"octo","repo":"hello","issue_number":1}' \
  --max-cost 1000
```

- `--args '<json>'` or `--args-file <path>` (`-` reads standard input) gives the
  arguments, a JSON object. Without either, the tool gets `{}`.
- `--max-cost <micro-USD>` refuses the call before it runs when its estimate
  is higher (`402 max_cost_exceeded`).
- `--idempotency-key <label>` makes a retry safe. Without it, the CLI sends a
  fresh label and prints it, so you can retry the same call with
  `--idempotency-key <that label>`.

The tool's result goes to standard output. Then one JSON line on standard
error says what the call cost:

```json
{"call_id":"call_…","tool":"composio.GITHUB_GET_AN_ISSUE","ok":true,"charged_micro_usd":400,"cost_micro_usd":400,"estimated":false,"price_source":"connect_native","exceeded_max_cost":false,"idempotency_key":"ryu-cli-…"}
```

`charged_micro_usd` is `null` where Ryu does not bill. Keep `call_id` when you
report a problem. A tool that ran and reported an error exits with status 1.

A refused call prints Connect's error and what to do next:

- the account to connect for `precondition_required`;
- where to add credit for `insufficient_credits`;
- close tool IDs for an unknown tool;
- how long to wait for `rate_limited`.

With `--json`, the refusal is printed to standard error as Connect's JSON with
`status` added. The full list of refusals is in the
[Connect API errors](/docs/standalone/connect-api#errors).
