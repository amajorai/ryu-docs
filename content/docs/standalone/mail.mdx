Ryu Mail is the service behind Agent Inboxes. It stores inboxes, messages,
threads, drafts, and attachments, accepts signed inbound mail, delivers signed
event webhooks, and hands outbound mail to the configured transport.

Mail can run inside a Ryu node or as its own process. Both shapes use the same
`/api/mail/*` contract, but they have different process and credential owners.

## Choose a deployment shape

| Shape | Credential | API ownership |
|---|---|---|
| Ryu node app | Core-issued sidecar bearer | Core proxies the node-local `/api/mail/*` contract |
| Standalone process | `RYU_MAIL_API_TOKEN` | Mail serves `/api/mail/*` directly for one process and data directory |

The standalone process is intentionally one tenant per service instance. Run a
separate process and data directory when tenants must be isolated. Do not use a
Core-issued `RYU_EXT_TOKEN` as a public API credential.

## Start the standalone service

```sh
git clone --depth 1 https://github.com/amajorai/ryu-mail.git
cd ryu-mail
RYU_MAIL_MODE=standalone \
RYU_MAIL_API_TOKEN=replace-me \
RYU_MAIL_HOSTNAME=127.0.0.1 \
RYU_MAIL_PORT=7996 \
RYU_DIR=/var/lib/ryu-mail \
cargo run --manifest-path backend/Cargo.toml
```

For direct standalone sending, also configure the node-owned SMTP relay:

```sh
RYU_SMTP_HOST=smtp.example.com
RYU_SMTP_PORT=587
RYU_SMTP_USERNAME=agent@example.com
RYU_SMTP_PASSWORD=use-a-secret-store
RYU_SMTP_FROM=agent@example.com
RYU_SMTP_STARTTLS=true
```

The process refuses protected API access without its bearer, and refuses an
outbound webhook destination that is not public HTTPS. The full route,
signature, WebSocket, attachment, and retry contract is in [Ryu Mail API](/docs/standalone/mail-api).

To expose the process beyond the host, set an explicit standalone token and
put TLS and rate limiting in front of it. A non-loopback bind without
`RYU_MAIL_API_TOKEN` is refused. The Mail database and attachment blobs remain
owned by this process.

## Organization entry point

Hosted organization members manage Agent Inboxes from the Ryu dashboard's
**Products** view. The browser uses the authenticated control-plane session; it
does not receive a Mail service bearer or an inbound HMAC secret.

The standalone Mail home redirects people to the organization dashboard at
`GET /`. The `/api/mail/*` routes remain the service contract for authenticated
callers and the inbound webhook.
