Skills and tools are two separate ways to extend what an agent can do. This lesson covers skills first, then tools.

## Skills

<TryInRyu page="skills" />

Skills are reusable Agent Skills in the standard `SKILL.md` format. The **Skills** page browses the public skills.sh directory and installs skills into the universal `~/.claude/skills` location.

Because the location is shared, a skill you install through Ryu also works in Claude Code, and a skill that Claude Code installed shows up in Ryu.

### Installed is not the same as active

Skills you install through Ryu are active right away. Skills that Ryu discovers in the shared folder are visible and counted as installed, but they stay inactive until you toggle them on.

Ryu injects only active skills because every skill body at once would overflow a local model's context window.

<Callout type="info">
  If a skill is installed but does not seem to take effect, check that it is toggled active on the Skills page.
</Callout>

New agents receive every **enabled** skill by default. A custom skill selection narrows that
scope, while an explicitly empty selection turns skills off; installed-but-inactive skills are
never made available by the agent default.

## Tools

Tools come from MCP (Model Context Protocol) servers and a unified tool catalog. The **Tools** page manages your MCP tools and connections.

New agents start with no MCP, built-in, or enabled plugin/app tools. Grant only the tools the agent
needs in the agent editor; selecting every tool is an explicit opt-in.

Two rules govern how an agent uses them:

- An agent can only call tools that are on its allowlist.
- Ryu-bridged tool calls use governed execution; runtime-native tools and external services need separate checks.

This means tool access is still per-agent. A new agent starts with no tool grants, while selecting a
row or using **Enable all** stores an explicit per-agent allowlist. Adding a tool to the catalog does
not change an agent that has already been customized.

### Composio and built-ins

Composio provides a large set of third-party tool integrations, gated per agent so each agent only
reaches what you allow. Ryu also ships built-in tools, including desktop notifications and channel
sends.

<Callout type="warn">
  Tool access requires explicit grants: disabled apps/plugins, inactive skills,
  Gateway policy, and human approval can still block a call. Gateway governance is also a separate
  per-agent model-egress setting for ACP runtimes; turn it off only when you want direct provider
  traffic. Narrow an agent's access whenever its task does not need the full catalog.
</Callout>
