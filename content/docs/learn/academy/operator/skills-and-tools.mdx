Skills and tools are the two ways you extend what an agent can actually do. They are different things, so this lesson covers each in turn.

## Skills

<TryInRyu page="skills" />

Skills are reusable Agent Skills in the standard `SKILL.md` format. The **Skills** page browses the public skills.sh directory and installs skills into the universal `~/.claude/skills` location.

That shared location is the point - a skill you install through Ryu also works in Claude Code, and a skill Claude Code installed shows up in Ryu. One install, usable across tools.

### Installed is not the same as active

Skills you install through Ryu are active right away. Skills that Ryu discovers in the shared folder are visible and counted as installed, but they stay inactive until you toggle them on.

The reason is context - injecting every skill body into a local model at once would overflow its context window, so Ryu only injects the ones you have chosen to activate.

<Callout type="info">
  If a skill is installed but does not seem to take effect, check that it is toggled active on the Skills page.
</Callout>

New agents receive every **enabled** skill by default. A custom skill selection narrows that
scope, while an explicitly empty selection turns skills off; installed-but-inactive skills are
never made available by the agent default.

## Tools

Tools come from MCP servers and a unified tool catalog. The **Tools** page manages your MCP tools and connections.

New agents start with every currently registered MCP, built-in, and enabled plugin/app tool. The setting is live for future tools too, so you can get started without building an allowlist first.

Two rules govern how an agent uses them:

- An agent can only call tools that are on its allowlist.
- Every tool call is governed and measured by the Gateway.

This means tool access is still per-agent. A new agent starts broad for simplicity, while switching off a row or using **Disable all** stores a narrower per-agent allowlist. Adding a tool to the catalog does not change an agent that has already been customized.

### Composio and built-ins

Composio provides a large set of third-party tool integrations, gated per agent so each agent only
reaches what you allow. Ryu also ships built-in tools, including desktop notifications and channel
sends.

<Callout type="warn">
  The default is convenient, not unrestricted governance: disabled apps/plugins, inactive skills,
  Gateway policy, and human approval can still block a call. Gateway governance is also a separate
  per-agent model-egress setting for ACP runtimes; turn it off only when direct provider traffic
  is intentional. Narrow an agent's access whenever its task does not need the full catalog.
</Callout>
