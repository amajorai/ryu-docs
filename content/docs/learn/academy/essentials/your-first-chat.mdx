In this lesson you send your first message, watch the agent use a tool, and learn the basic chat
controls.

## Start a conversation

<TryInRyu page="chat" />

1. Click **New chat** in the sidebar.
2. Type a message and send it.

Your message goes to Ryu Core, which routes it to the default **Ryu** agent. The agent generates a
reply using the configured model and streams it back. Local inference requires downloaded model
files and a ready runtime; a provider-backed route sends requests to that provider.

## Watch a tool get used

A plain reply is text generation. An agent can also **use a tool**. Ask it to do something that
needs one, for example to fetch a page or look something up.

The agent follows a loop. It decides that it needs a tool, calls the tool, reads the result, and
continues. You see the tool call and its result in the conversation.

<Callout type="info">
  Ryu-bridged tools require explicit allowlist grants. Runtime-native tools and external services
  have separate controls. Later courses show how to manage them.
</Callout>

## Useful controls

- **Stop** halts a running response.
- **Voice input** - the microphone button captures speech, uses the configured transcription engine, and drops the
  text into the composer.
- **Branch** - from a message you can fork the conversation into a new chat that copies the history
  up to that point. Your conversations stay linear, and the branch opens in a new tab.
- **Sessions** - a read-only view of the runs that make up a conversation.

## What just happened

The desktop app sent your request to Core. Core routed it to an agent. The agent generated a reply
and optionally called a tool. The result streamed back and was saved.

First, the reflection prompts. Say the answers out loud or jot them down, in your own words.

- Describe the chat-to-agent-to-tool-to-result loop in your own words.
- What limits which tools an agent can call?
- How do you fork a conversation from a specific message?
- What does the Sessions view show?
