Many engines can run agents, including OpenAI, Claude Code, Gemma, and other OpenAI-compatible
runtimes (services that use the OpenAI API format). Ryu is not another engine. Ryu adds controls
around the engine. It decides what an agent can reach, which tools it can use, what data is safe to
send, what it costs, and how good its output is.

## Why a control layer?

An engine on its own generates text. It does not decide what an agent may reach, use, send, or
spend. Ryu makes those decisions with three parts.

- **Core** decides **what runs**, including which agent, session, workflow, and tool.
- **Gateway** decides **what is allowed, shared, measured, and paid for**, including routing,
  firewall, budgets, evals, and audit.
- The **selected runtime and model** do the actual generation; supported replacements need their own setup.

On the default compatible route, Core selects the agent and the Gateway checks the model request
before forwarding it. Provider-native runtimes and direct integrations can have separate paths;
check [runtime routing](/docs/surfaces/desktop/engines/agent-runtimes).

Later courses cover Core and the Gateway in detail. For now, remember that Ryu sits around supported
runtimes. Switching runtimes can require different credentials, tools, and configuration.

## Surfaces and layers, one Ryu system

Ryu shows up differently depending on the job you need to do.

- **Bot** - the fully managed consumer surface for everyday work. You sign in, give it a task, and get the result back.
- **Agent** - the desktop surface for power users and admins who configure and run a Ryu node.
- **Ryu Platform** - the developer layer: SDKs, Core, Gateway, orchestration, routing, and governance.
- **Ryu Apps** - extensions that add packaged features and interactive surfaces.
- **Ryu Infra** - where Ryu runs: managed Ryu Cloud, or self-hosted in your own environment.

This course follows the **Agent** path, because it is the surface that exposes the runtime and
its configuration. Bot hides those controls for people who only need to give AI work.

## Nothing hardcoded

Supported models, providers, runtimes, retrieval strategies, and tools are configurable. Local
inference still needs downloaded model files and a ready runtime.

<Callout type="info">
  Changing a default requires a supported replacement and its own setup. Installing a replacement
  does not migrate existing workflows, so check runtime, credential, tool, and state compatibility
  first.
</Callout>
