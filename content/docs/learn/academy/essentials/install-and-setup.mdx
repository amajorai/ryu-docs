Ryu is designed to work the moment it is installed, with no service key and no setup. This lesson walks
through what happens the first time you launch the app.

## Install the desktop app

Download the Ryu desktop app for your platform and install it like any other application. The
desktop app bundles **Ryu Core**, the local backend that does the real work, so you do not install
anything separately.

When the app starts for the first time, it runs **onboarding**. This is where Ryu sets up your local
stack.

## Choose your defaults

After you choose a local, managed, or remote node, onboarding offers the agents found on that node.
The next screen sets a separate **local default** for plugins, side-model calls, and utility work.
Fresh installs use the Ryu agent with the installed Gemma 4 model. Normal chats have a separate
**cloud default**: paid plans start with Ryu through the managed `openrouter/auto` route, while free
plans leave the cloud lane empty so chats use the local lane unless you configure a BYOK provider.

Both screens use the same universal agent/model command picker as the rest of the desktop. Ryu can
carry its agent, provider, model, and effort together. External ACP agents keep their own advertised
model, effort, and permission controls. When you open a nested provider or model page, its back
action is the first command option below the search field, so keyboard and pointer navigation keep
the same row treatment throughout the picker.

If the account has more than one organization, onboarding asks which one to make active. A personal
organization is selected automatically when it is the only organization.

## What onboarding downloads

Onboarding installs a complete local stack so Ryu is private and fully functional offline. Each step
is best-effort, so if one fails it warns you and never blocks chat.

- **A local Chat runtime and model** - llama.cpp plus a default Gemma GGUF model that runs on most
  machines. This is what answers your messages out of the box.
- **An embedding model** - a local GGUF used for retrieval and memory, served by a dedicated
  embeddings instance.
- **A Voice Recognition engine** - whisper.cpp plus a base model for recognition.
- **A recognition model** - the parakeet ONNX model for an alternative Voice Recognition path.

Everything above runs locally. No data leaves your machine unless you later choose a cloud model or
connect an external service.

<Callout type="info">
  Onboarding detects which agent command-line tools you already have installed and offers to add
  the matching agents. Only the default **Ryu** agent is installed automatically. Everything else is
  opt-in.
</Callout>

## Connect sources and import threads

Free users can optionally add BYOK provider keys before choosing a cloud default. Paid users can
connect Composio sources from onboarding, including Gmail, Notion, Slack, GitHub, and searchable
additional tools. Connections are read-only inputs for the setup flow; Ryu never sends or edits
external content without a later interactive action.

Onboarding also scans the last 90 days for threads from the agents you selected. It shows counts per
agent, lets you confirm or skip the import, and turns **Auto-import future threads** on by default.

Eligible paid owners and admins on an onboarding-eligible node can ask Ryu to build an initial
profile from the connected sources and imported conversations. The build writes a user profile and,
when you choose to share everything, an organization profile. Local models may produce a weaker
draft, so a stronger ACP agent or the Ryu cloud model is recommended. You can skip before
materialization; if the build runs longer than 20 seconds, **Run in background** creates a profile
chat you can revisit. If the
profile already exists on the node, onboarding says **You already did this before** and offers
**Rebuild Profile** instead of silently creating a second setup.

## Start with Telegram

On an unbound local node, or a personal self-hosted node for its owner, onboarding checks Gateway
for existing channels.
If none are configured, it can create a Telegram bot for you and route it to the default Ryu agent,
so you can start talking to Ryu immediately without visiting BotFather or copying a token. If a
channel already exists, onboarding says **You already have channels** and leaves the existing setup
unchanged. If Ryu cannot verify the existing channel list, it fails closed and creates nothing; if
managed pairing is unavailable, it lets you continue and add the channel later from Gateway →
Channels.

The same duplicate check applies to connected sources and profile builds: when an existing setup
cannot be verified, onboarding offers **Continue** instead of starting another connection or
profile build.

Managed nodes and self-hosted nodes with organization or team ACLs do not show these gateway-level
onboarding controls. Their node administrator can configure channels and profile settings from the
regular Gateway surfaces.

When setup is complete, onboarding closes with a short welcome screen. The Ryu wordmark is drawn in
the same signature style used across the product, then an Apple-inspired hello animation cycles
through greetings in supported languages. Select **Continue to Ryu** when you are ready to open your
workspace. Your first Ryu chat then starts with an assistant-only hello. If the local model is still
being prepared, the chat waits and resumes automatically; a ready cloud model can start immediately.

## Sign in (optional)

You can sign in to sync conversations, manage billing, and use cloud features. Signing in is not
required to chat. The local stack works whether or not you have an account.

On the web sign-in page, open **More options** for available passkey, SSO, and email-link methods.
The choices shown depend on which methods are enabled for the account.

## Where things live

Two pieces matter for the rest of this course.

- **Sidebar** on the left holds New chat, search, and quick links to Agents, Models, and Skills.
- **Command palette** opens with **Ctrl+K** or **Cmd+K** and jumps you to any page in the app.

If onboarding finished without errors, you already have a working agent. Open it from the sidebar.
