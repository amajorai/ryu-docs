Ryu works right after install, with no service key. This lesson shows how to install the desktop app
and what happens the first time you open it.

## Install the desktop app

Download the Ryu desktop app for your platform and install it like any other application. The
desktop app bundles **Ryu Core**, the local backend, so you do not install anything separately.

The first time the app starts, it runs **onboarding**, which sets up your local stack.

## Choose your defaults

First, choose a local, managed, or remote node. Onboarding then offers the agents it found on that
node. Next, you set two defaults:

- The **local default** handles plugins, side-model calls, and utility work. Fresh installs use the
  Ryu agent with the installed Gemma 4 model.
- The **cloud default** handles normal chats. Paid plans start with Ryu through the managed
  `openrouter/auto` route. Free plans leave it empty, so chats use the local default unless you add
  your own provider key (BYOK).

Both screens use the same agent and model picker as the rest of the desktop app. For the Ryu agent,
the picker sets agent, provider, model, and effort together. External ACP (Agent Client Protocol)
agents keep their own model, effort, and permission controls. On a nested provider or model page,
the back action is the first option below the search field.

If the account has more than one organization, onboarding asks which one to make active. A personal
organization is selected automatically when it is the only organization.

## What onboarding downloads

Onboarding installs a complete local stack in the background so chat, retrieval, and voice work
fully offline. Each step is best-effort, so if one fails it warns you and never blocks chat.

- **Chat** - llama.cpp plus a default Gemma GGUF model that runs on most machines. This is what
  answers your messages out of the box.
- **Retrieval and memory** - a local embedding GGUF, served by a dedicated embeddings instance, plus
  a bge reranker GGUF that reranks Spaces search results. If the reranker is missing, results fall
  back to vector order.
- **Guardrails** - a small (270M) classifier GGUF that serves the Gateway's classify tier, the
  default inspector model.
- **Voice input** - whisper.cpp plus a base model, the parakeet ONNX model as an alternative
  recognition path, the Silero VAD model for end-of-speech detection, and the S1-mini model that
  cleans up transcripts after recognition.
- **Voice output** - Kokoro 82M, the default text-to-speech engine, with OuteTTS installed as the
  fallback.
- **Images** - the stable-diffusion.cpp server plus the default Qwen Image model (about 11 GB). It
  is skipped with a warning on platforms that have no prebuilt server (Intel Mac, ARM Linux). The
  video model is not part of onboarding; it downloads on first use.

The optional pieces (reranker, classifier, S1-mini, text-to-speech, and the image engine) only start
when first used. To swap any of the defaults, see [Default models](/docs/reference/defaults/models).

Everything above runs locally. Your prompts, conversations, and files stay on your machine unless
you choose a cloud model or connect an external service. Separately, product analytics, crash
reports, and anonymous community stats are on by default and never include your content. You can
turn each off in **Settings → Privacy**. See [Privacy and telemetry](/docs/surfaces/desktop/transparency).

<Callout type="info">
  Onboarding detects which agent command-line tools you already have installed and offers to add
  the matching agents. Only the default **Ryu** agent is installed automatically, with its own
  managed Pi engine kept separate from any `pi` already on your PATH. Everything else is opt-in.
</Callout>

## Connect sources and import threads

Free users can add BYOK (bring your own key) provider keys before choosing a cloud default. Paid users can
connect Composio sources from onboarding, including Gmail, Notion, Slack, GitHub, and searchable
additional tools. Connections are read-only inputs for the setup flow; Ryu never sends or edits
external content without a later interactive action.

Onboarding also scans the last 90 days for threads from the agents you selected. It shows counts per
agent, lets you confirm or skip the import, and turns **Auto-import future threads** on by default.

Eligible paid owners and admins on an onboarding-eligible node can ask Ryu to build an initial
profile from the connected sources and imported conversations. The build writes a user profile and,
when you choose to share everything, an organization profile.

Local models may produce a weaker draft, so use a stronger ACP agent or the Ryu Cloud model for this
step. If Ryu suggests agents, the desktop app shows each generated reason, tool list, and full prompt.
You must acknowledge that prompt and tool review before **Add** creates the Trial/read-only agent.

The build starts as soon as you choose **Build my profile**, and you can wait on the progress screen
until it finishes. **Skip and cancel** stops a build that has not started saving, and removes its
profile chat, so nothing is kept. If the build runs longer than 20 seconds, **Run in background** lets
you continue setup while it keeps running. Either way, the profile is saved to memory only when the
draft is ready. If the profile already exists on the node, onboarding says **You already did this
before** and offers **Rebuild Profile** instead of creating a second setup.

## Start with Telegram

On an unbound local node, or a personal self-hosted node for its owner, onboarding checks the
Gateway for existing channels. If none are configured, it can create a Telegram bot for you and
route it to the default Ryu agent. You do not need to visit BotFather or copy a token. If a channel
already exists, onboarding says **You already have channels** and leaves the existing setup
unchanged. If Ryu cannot verify the existing channel list, it fails closed and creates nothing; if
managed pairing is unavailable, it lets you continue and add the channel later from the **Channels**
page.

The same duplicate check applies to connected sources and profile builds: when an existing setup
cannot be verified, onboarding offers **Continue** instead of starting another connection or
profile build.

Managed nodes and self-hosted nodes with organization or team ACLs do not show these gateway-level
onboarding controls. Their node administrator can configure channels and profile settings from the
regular Gateway surfaces.

Onboarding opens with a short welcome screen that greets you in several languages. Select
**Skip**, or press Enter or Escape, to go straight to setup. Near the end of setup, the privacy
screen has a **Get started** button that finishes onboarding. Your first Ryu chat starts with a
hello from the assistant. If the local model is still being prepared, the chat waits and resumes
automatically. A ready cloud model can start right away.

## Sign in (optional)

You can sign in to sync conversations, manage billing, and use cloud features. Signing in is not
required to chat. The local stack works whether or not you have an account.

On the web sign-in page, open **More options** for available passkey, SSO, and email-link methods.
The choices shown depend on which methods are enabled for the account.

During desktop sign-in, a **Cancel** button appears below the verification actions after three
seconds. Select it to return to the welcome screen.

## Where things live

Two pieces matter for the rest of this course.

- **Sidebar** on the left holds New chat, search, and quick links to Agents, Models, and Skills.
- **Command palette** opens with **Ctrl+K** or **Cmd+K** and jumps you to any page in the app.

If onboarding finished without errors, you already have a working agent. Open it from the sidebar.
