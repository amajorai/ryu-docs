Model routing decides which provider and model serves each request. The base router resolves a model id to a provider. Smart routing is an optional layer on top of it.

## Smart routing

Smart routing is a classifier-driven router. You write plain-language rules, and a low-cost classifier model picks the model for each request. For example:

- "Coding questions go to Claude."
- "Casual chat goes to a local model."

You configure it under **Gateway → Model routing → Smart routing**. It is off by default. To use it, set:

- A low-cost **classifier model** that reads the request and chooses a rule.
- An ordered list of **rules**, each a description plus a target model.
- An optional **default** model for when no rule matches.

## It fails open

Smart routing fails open. If the classifier errors, times out, or returns an unusable answer, the originally requested model is used. Routing should improve outcomes, not become a single point of failure. Classifier calls are still governed, so a governance denial on that call is returned to the caller.

```mermaid
flowchart TD
  Req[Request with a model id] --> On{Smart routing on?}
  On -->|No| Use[Use the requested model]
  On -->|Yes| Cls[Cheap classifier reads the request<br/>and picks a matching rule]
  Cls -->|rule matches| Route[Route to the rule's model]
  Cls -->|no rule matches| Def[Use the default model]
  Cls -. error or timeout .-> Use
```

<Callout type="info">
  The routed model is returned in the `x-routed-model` response header, so you can see which model served a request.
</Callout>

## Nothing is hardcoded

A target can be any routable model id, including local models and OpenRouter slugs. The routing layer is not tied to one provider.

<Callout type="warn">
  Bare `gemini-*` model ids route through the native `genai` provider. Google Vertex is a separate opt-in provider that an operator targets through `routing.model_map` or `default_provider`; it is not claimed by a built-in prefix. A `google/...` model id can still be mapped to OpenRouter.
</Callout>

## When changes take effect

The smart-routing switch and its rules (`routing.smart_routing`) apply to new requests as soon as you save, with no restart. The base router's `model_map`, `fallback_chain`, and `provider_tiers` load at startup, so changes to them take effect on the next gateway restart.

## Reference

[Gateway routing](/docs/gateway/routing) is the canonical reference for the resolution order, `routing.smart_routing`, and every other routing setting.
