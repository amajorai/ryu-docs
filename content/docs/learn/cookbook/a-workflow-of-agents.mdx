---
title: "Orchestrate Agents with a Workflow"
description: "Use the Ryu SDK to define a workflow that calls agents as steps, composing them into one run."
---

A workflow coordinates several agents around one job. The example defines a workflow with the Ryu
SDK, calls a researcher and a writer as ordered steps, and returns one result.

## What you'll use

- [The SDK](/docs/extend/develop/sdk): the `defineWorkflow` and `defineAgent` factories.
- [Workflows](/docs/core/workflows): the Core DAG engine, for when you want a workflow as data rather than code.

## Prerequisites

- **Bun** on your PATH (`bun` and `bunx`).
- A scaffolded plugin project. If you do not have one, start from
  [Build your first agent in code](/docs/learn/cookbook/first-sdk-agent).
- **A running Ryu Core** (it runs the Gateway sidecar) with a routable model, since both agent
  steps call the model through `ctx.gateway`.

## Steps

<Steps>

<Step>

### Define the agents

Each step is a [Runnable](/docs/start-here/architecture/runnable-model). Start with two agents in
`src/agents.ts`. Each one calls the model through `ctx.gateway`.

```ts
import { defineAgent } from "@ryuhq/sdk";

export const researcher = defineAgent({
  id: "agent-researcher",
  name: "Researcher",
  async run({ topic }: { topic: string }, ctx) {
    const { content } = await ctx.gateway.chat([
      { role: "user", content: `List the key facts about: ${topic}` },
    ]);
    return { facts: content };
  },
});

export const writer = defineAgent({
  id: "agent-writer",
  name: "Writer",
  async run({ facts }: { facts: string }, ctx) {
    const { content } = await ctx.gateway.chat([
      { role: "user", content: `Write a short paragraph from these facts:\n\n${facts}` },
    ]);
    return { paragraph: content };
  },
});
```

</Step>

<Step>

### Define the workflow

A workflow is a Runnable with `kind = "workflow"`. List the agents in `steps` and call each one's
`run()` in order inside the workflow body. Each step's output is the next step's input. Save it as
`src/workflow.ts`.

```ts
import { defineWorkflow } from "@ryuhq/sdk";
import { researcher, writer } from "./agents";

export const report = defineWorkflow({
  id: "workflow-report",
  name: "Report",
  steps: [researcher, writer],
  async run({ topic }: { topic: string }, ctx) {
    const { facts } = await researcher.run({ topic }, ctx);
    const { paragraph } = await writer.run({ facts }, ctx);
    return { report: paragraph };
  },
});
```

The workflow and its agents are peers, not a hierarchy. A workflow calls an agent's `run()`, and an
agent can list a workflow as a tool. The shared `ctx` carries the Gateway client to every step, so
every model call stays governed.

</Step>

<Step>

### Run and bundle

`run()` needs a context with a `gateway`. `defineModel` returns a client that targets
`RYU_GATEWAY_URL` (default `http://127.0.0.1:7981`). Create `src/run.ts`.

```ts
import { defineModel } from "@ryuhq/sdk";
import { report } from "./workflow";

const gateway = defineModel(process.env.RYU_MODEL ?? "gpt-4o-mini");
const topic = process.argv.slice(2).join(" ") || "the Rust borrow checker";
const result = await report.run({ topic }, { gateway });
process.stdout.write(`${result.report}\n`);
```

Run it, then bundle the plugin:

```bash
bun run src/run.ts "solar panels"
bun run pack
```

</Step>

</Steps>

<Callout type="info">
This is the *code* way to compose Runnables. Use it when the orchestration is simple sequencing. When
you want triggers, retries, human-in-the-loop gates, durable resume, or a visual canvas, model the
workflow as data with the [Core workflow engine](/docs/core/workflows) instead, and let your agents
be its `prompt`/`agent_delegate` nodes.
</Callout>

## Check your work

- `bun run src/run.ts "<topic>"` prints one `report` paragraph, not the intermediate facts.
- Change the topic and the paragraph changes with it, because `facts` passes from the first step
  into the second.
- Both calls use the shared `ctx.gateway`. If the Gateway cannot route the model, the run fails at
  the first step instead of producing a partial report.
