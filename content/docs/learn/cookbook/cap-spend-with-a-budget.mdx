---
title: "Cap what an agent can spend with a budget"
description: "Put a lifetime charged-spend cap on an individual agent, choose which spend categories count, then downgrade or reject once it is hit."
---

An agent that loops or fans out can spend money quickly. The example adds a charged-spend budget to
the Gateway. When the cap is reached, the Gateway swaps to a cheaper model or rejects the request,
according to the configured action. Use it when an agent needs a hard USD ceiling.

## What you'll use

- [Configuration](/docs/gateway/configuration): where keys and budgets are defined and how config is written.
- [Security and governance](/docs/gateway/governance): the broader policy surface the gateway enforces.

## Steps

<Steps>

<Step>

### Pick the budget scope

The gateway tracks charged spend at three scopes. Budget `limit` values are integer micro-USD:
`1_000_000` is `$1.00`, and `0` disables that rule. This is a cost cap, not a token cap. Pick the
scope that matches what you want to bound:

- **Per key**: a legacy lifetime token-count cap on a single gateway API key. Keep this separate from
  the charged-spend budgets below; it is controlled by `token_budget_total`.
- **Per user / per agent**: rules under `[budgets]`, keyed by the `x-ryu-user-id` / `x-ryu-agent-id`
  a *trusted forwarder* passes (Ryu Core relaying a real end-user identity).
- **Per session**: a running charged-spend cap per `x-ryu-session-id`, so a single conversation
  cannot overrun.

</Step>

<Step>

### Set a lifetime cap on a key

If you also need the legacy token-count guard on an API key, give it a `token_budget_total` and
decide what happens when it is hit:

```toml
[[auth.api_keys]]
key = "YOUR_GATEWAY_KEY"
name = "my-app"
token_budget_total = 5000000     # legacy lifetime token cap, input + output (0 = unlimited)
downgrade_to = "gpt-4o-mini"     # swap to this model once the cap is hit
```

With `downgrade_to` set, requests keep working on the cheaper model after the cap. Leave it unset and
the gateway instead rejects the request with `BudgetExceeded` once the cap is reached, a hard stop
rather than a quiet downgrade.

</Step>

<Step>

### Set an agent spend cap

Put the agent rule under `[budgets.agents]`. This example stops the agent after `$1.00` of charged
spend and excludes paid tool calls:

```toml
[budgets.agents.my-agent]
limit = 1_000_000       # $1.00; charged micro-USD on the wire
action = "stop"         # notify | downgrade | restrict | stop
alert = "warn"          # silent | warn | fanout | email

[budgets.agents.my-agent.include]
model = true            # provider/model inference
media = true            # image, video, speech
tools = false           # paid Composio actions
```

The Gateway uses OpenRouter's response-reported `usage.cost` when a request is routed through
OpenRouter, otherwise it uses the configured model or modality estimate. The charged amount
includes the configured platform markup, so the cap matches what the wallet would debit.
`downgrade` uses `downgrade_to`; `restrict` still uses `restrict_max_tokens` to limit the response
after the spend cap is reached. Existing rules default all three categories to `true`.

The three controls are independent: model inference, media generation (image/video/speech), and
paid tools (Composio actions). Turn off a category when it should not consume that agent's cap.

</Step>

<Step>

### Drive per-user and per-agent budgets safely

Per-user and per-agent budgets only apply when a *trusted forwarder* supplies the identity. By
default the gateway ignores client-supplied `x-ryu-user-id` / `x-ryu-agent-id` headers, so an
untrusted caller cannot rotate identities to evade its quota. Set `trusted_forwarder = true` only on
a key for an intermediary you control:

```toml
[[auth.api_keys]]
key = "ryu-sk-core-relay"
name = "core-relay"
trusted_forwarder = true   # this intermediary may pass x-ryu-user-id / x-ryu-agent-id
```

The per-user and per-agent rules themselves live under `[budgets]`. See [Configuration](/docs/gateway/configuration#trusted-forwarders).

</Step>

<Step>

### Apply it

Budgets are hot-swapped live: a `PUT /api/gateway/config` (which relays `PUT /v1/config`) with a
`budgets` patch takes effect without a restart, unlike routing. `GET /v1/config` returns the live
budget view.

<Callout type="info">
On desktop, open an existing agent's edit page and use **Model & provider → Budget** to set that
agent's cap, action, notification tier, and live spend. The Gateway dialog's **Budgets** card remains
the overview for adding, editing, and removing every per-user and per-agent rule, plus the global
per-session cap. You need the `gateway.configure` permission to change rules. You can also author
budget rules through the gateway config (`PUT /api/gateway/config`) or the web dashboard.
</Callout>

</Step>

</Steps>

## How provider cost is attributed

For OpenRouter-routed ACP and regular model calls, Ryu sends a stable agent identity with the
request and records OpenRouter's inline `usage.cost` as soon as the response completes. OpenRouter's
generation metadata can then be reconciled by matching its `external_user` to that identity; it is a
reconciliation/reporting source, not a second hot-path debit.

This does not make every ACP provider billable through OpenRouter. Claude/Codex subscription
passthroughs remain subscription traffic, and direct-egress agents are outside the Gateway cap.
Self-hosted/local inference has no provider invoice feed, so its cap uses the configured estimate.
Composio actions are separate tool charges and are counted only when **Paid tools** is enabled.

## Check your work

- Set a low `limit` on a test agent, such as `1_000_000` for `$1.00`, and drive governed model calls
  past the cap. With `downgrade_to` set, requests keep succeeding but on the cheaper model; leave it
  unset and the gateway returns `BudgetExceeded` once the cap is hit.
- If you use the legacy API-key guard, set a low `token_budget_total` separately and verify its
  token-count behavior; it is not the charged-spend budget.
- `GET /v1/config` returns the live budget rules, so you can confirm each cap without a
  restart; `GET /v1/budget/spend` returns the current in-memory per-agent usage as charged micro-USD
  with `currency = "USD"` and `unit = "micro_usd"`.
- Budgets hot-swap: a `PUT /api/gateway/config` with a `budgets` patch takes effect immediately,
  unlike routing, which needs a refresh.
- In the desktop, open the agent's edit page, set a cap in **Model & provider → Budget**, and check
  its live spend as the agent makes governed model calls. The Gateway dialog's **Budgets** card
  shows the same rule in the all-agents overview.
