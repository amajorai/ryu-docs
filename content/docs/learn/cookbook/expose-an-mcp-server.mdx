---
title: "Expose Your Tools to Any Agent over MCP"
description: "Wrap your Runnables in an MCP stdio server with the Ryu SDK, register it with Core, and call it from chat."
---

MCP (Model Context Protocol) is a protocol that lets an AI host call tools from an MCP server. In
this recipe, you wrap a tool in an MCP stdio server, register it with Core, and call it from chat.
Any agent you allowlist can then use the tool, with no manifest and no restart.

## What you'll use

- [The SDK](/docs/extend/develop/sdk): `defineTool` and the SDK's `McpServer`.
- [Register an MCP server](/docs/extend/develop/extensions/mcp-server): the canonical guide for the registration handshake and allowlisting.
- [MCP registry](/docs/core/mcp-registry): how Core discovers and dispatches the tools.

## Prerequisites

- **Bun** on your PATH, to run the stdio server (`bun run src/server.ts`).
- **A running Ryu Core** on `http://localhost:7980`, so `POST /api/mcp/servers` can register the
  server and hot-reload the registry.
- Your server `command` (here `bun`) must be on Core's PATH, or registered with an absolute path.

## Steps

<Steps>

<Step>

### Write the server

The SDK's `McpServer` handles the MCP `initialize` handshake, `tools/list`, `tools/call`, and the
content-block envelope. Register objects with a `name`, an optional `inputSchema`, and a `run`
function. Then call `serve()` to read JSON-RPC from stdin and write responses to stdout.

```ts
// src/server.ts
import { McpServer } from "@ryuhq/sdk/mcp/server";

const server = new McpServer();

server.register({
  name: "word_count",
  description: "Count the words in a piece of text.",
  inputSchema: {
    type: "object",
    properties: { text: { type: "string", description: "Text to count" } },
    required: ["text"],
  },
  run({ text }: { text: string }) {
    return { words: text.trim().split(/\s+/).filter(Boolean).length };
  },
});

await server.serve(); // reads process.stdin, writes process.stdout
```

<Callout type="info">
`McpServer` is exported from the published package as `@ryuhq/sdk/mcp/server`
(also reachable via `@ryuhq/sdk/mcp`). See the
[TypeScript SDK guide](/docs/extend/develop/extensions/typescript-sdk#mcp-bridge).
</Callout>

</Step>

<Step>

### Register it with Core

Core exposes `POST /api/mcp/servers`. It appends the server to `~/.ryu/state/mcp.json` and hot-reloads the
registry, so the tools become callable with no restart. The caller needs the `gateway.configure`
permission. Set `command` and `args` to the command that starts your server. `$RYU_TOKEN` is the node
token (Core reads `RYU_TOKEN`, then `~/.ryu/secrets/node-auth.token`).

```bash
curl -X POST http://localhost:7980/api/mcp/servers \
  -H "Authorization: Bearer $RYU_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "name": "mytools",
    "command": "bun",
    "args": ["run", "src/server.ts"],
    "description": "My SDK tools over MCP."
  }'
```

<Callout type="info">
`name` must be non-empty and must not contain `__` (a reserved legacy separator). Core namespaces
the tool in the dotted form `mytools.word_count`. The `command` must be on Core's PATH, or use an
absolute path.
</Callout>

</Step>

<Step>

### Allowlist the tool for an agent

Registration alone does not grant access. The MCP bridge filters every registered tool through each
agent's allowlist before it injects the tool into a session. Add your tool to each agent's allowlist
on the **Tools** tab of its edit page. The built-in `ryu` agent is seeded with the explicit `*`
grant, so it reaches your tool with no extra config. A new agent has no executable MCP tools until
you grant this server or `*`.

</Step>

<Step>

### Call it from chat

With the server registered and allowlisted, its tools are injected into ACP agent sessions through
Core's MCP bridge. When an agent emits a tool call for `mytools.word_count`, Core dispatches it and
feeds the result back into the chat loop, the same tool loop the built-in tools use. You can also
list servers and call tools directly:

```http
GET  /api/mcp/servers
POST /api/mcp/tools/call
```

</Step>

</Steps>

## Check your work

- After registering, `GET /api/mcp/servers` lists `mytools`, which shows Core reloaded the registry
  with no restart.
- Your tool appears as `mytools.word_count`. A server `name` that contains `__` is rejected at
  registration.
- `POST /api/mcp/tools/call` for `mytools.word_count` with `{ "text": "one two three" }` returns
  `{ "words": 3 }`, the same result an agent gets when it emits the tool call in chat.
