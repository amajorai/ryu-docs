---

Run a chat model on your own machine. This recipe installs a model, makes it the active local model,
and tests one chat turn with the network off. Cloud models, network tools, sync, and telemetry have
separate data destinations. Check [Transparency](/docs/surfaces/desktop/transparency) before you
work with sensitive content.

## What you'll use

- [Models](/docs/surfaces/desktop/models): browse the Hugging Face catalog and install a GGUF.
- [Chat](/docs/surfaces/desktop/engines/chat-engines): the active runtime that serves your model.
- [Transparency](/docs/surfaces/desktop/transparency): diagnostics export is off by default; product analytics and crash reports are on by default and have separate controls.

## Steps

<Steps>

<Step>

### Install a model from the catalog

Onboarding may already have installed a model and runtime. To add one, open the **Models** tab. It
browses the Hugging Face Hub for GGUF models. Each file shows its real size, a SHA-256, and a
**device-fit verdict** computed from your machine's RAM, VRAM, and free disk:

| Verdict | Meaning |
|---|---|
| `great`, `ok` | Fits fully on the GPU |
| `partial`, `cpu` | Runs, but slower (partial GPU offload or CPU only) |
| `too_big` | Does not fit in memory. The install route refuses it |
| `no_space` | Not enough free disk to download. The install route refuses it |
| `unknown` | Ryu could not measure the fit |

Pick a quant that fits, then install it. Core verifies the checksum of the download. Wait for the
download to finish before you disconnect.

<TryInRyu page="models" />

The API equivalent is:

```http
GET  /api/models/catalog
POST /api/models/catalog/install
```

</Step>

<Step>

### Make it the active model

Chat serves one model at a time. In the installed model's detail, click **Use this
model** to make it the served model and restart the local engine onto it. Over the API:

```http
POST /api/models/active
{ "id": "unsloth/gemma-3-12b-it-GGUF" }
```

The `id` is a repo id or an installed stem. Core writes the preference, restarts the resident local
engine onto the new model, and refreshes the Gateway so routing picks it up.

</Step>

<Step>

### Chat

Open **Chat** and send a message. The default `ryu` agent routes to your active local engine through
the Gateway when it is configured to use that local endpoint. Confirm the selected model and disable
network-dependent tools for this test.

<TryInRyu page="chat" />

</Step>

</Steps>

<Callout type="info">
A `ryu://models/<source>/<id...>` deep link on a web page opens the desktop app to a confirm dialog.
The model installs only after you confirm. See [Models](/docs/surfaces/desktop/models).
</Callout>

## Check your work

- The installed model's detail shows it as the **active** model after you click **Use this model**,
  and Chat routes to it.
- Disconnect the network, then send a message with no network tools enabled. A successful reply
  verifies that this configured inference turn can run offline. It does not prove that other
  tasks, later turns, or separate telemetry and sync processes never send data.
- If the reply is slow, check the model's device-fit verdict. Prefer a quant marked `great` or `ok`.
