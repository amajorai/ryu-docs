Bind an agent or team to Telegram, Slack, WhatsApp Personal, WhatsApp Business, or Discord. The bot
uses the same memory, tools, and Gateway governance as the agent in Desktop.

<Callout type="warn">
Hosted channel bots need an active managed Pro, Max, Teams, or Business plan. See
[Channel bots](/docs/gateway/channels) for plan and organization rules.
</Callout>

## What you'll use

- [Channel bots](/docs/gateway/channels): how the Gateway runs the platform listeners and routes turns to Core.
- [Agent groups](/docs/core/agent-teams): the coordination strategies a group uses when a channel routes to one.

## Prerequisites

- For a manual setup, admin access on the platform to create a bot and copy its credential (a Telegram
  BotFather token, a Slack bot token, a WhatsApp Business Cloud API credential, a WhatsApp Personal
  OpenWA session credential, or a Discord bot token). For Telegram, the **Create a bot for me**
  pairing flow in Desktop does not require copying a token.
- An agent (or a group) you want the channel to reach.

## Steps

<Steps>

<Step>

### Choose how to supply credentials

For Telegram in Desktop, choose **Create a bot for me** to open the QR code or deep link in
Telegram. Wait for the bot to be created, verify the returned `@username`, and choose **Connect**.
If the pairing is not available or you want to reuse an existing bot, choose **Paste a token** and
copy a Telegram BotFather token. For Slack or Discord, create the bot on that platform and copy its
token. For WhatsApp, choose **WhatsApp Personal** for an OpenWA session or **WhatsApp Business
(Cloud API)** for Meta credentials. Those two setups are separate channel types.

To abandon an unaccepted Telegram pairing, choose the `Not mine, discard` button or **Cancel**. The
credential is revoked, and the pairing link expires after a short window.

</Step>

<Step>

### Open Channels

Channels belong to your account, not to one Core node. When an organization is active, the saved
channel belongs to that organization and its Gateway serves it.

<TryInRyu page="channels" />

In Desktop, open **Settings → Channels**, or search for **Channels** in the command palette.

</Step>

<Step>

### Add the channel and choose what it routes to

Add a channel. Pick the platform, supply the credential, and set the **Routes to** target. The picker
lists your agents and your teams.

- Route to an **agent** and every inbound message runs that single agent (`run_reply_text`).
- Route to a **group** and the group's lead orchestrates its members per the group's coordination
  strategy and returns one combined, attributed reply (`run_team_reply_text`).

A group is selected with a `team:` sentinel and persisted as `teamId` (otherwise `agentId`) on the
channel config.

<Callout type="info">
A channel with neither an agent nor a group falls back to a legacy single-call Gateway path with the
channel's configured model and prompt. Bind an agent or team instead. That setup persists each
sender's conversation and reaches Core memory and tools.
</Callout>

</Step>

<Step>

### Save and talk to it

Save. The platform adapter normalizes each inbound message and sends it to Core's
`POST /api/channels/run` with the channel's `agent_id` or `team_id`. Each chat keeps a persistent
Core conversation that you can also open in Desktop. Model calls still go from Core to the Gateway,
so routing, firewall, budgets, and audit still apply.

</Step>

</Steps>

## Check your work

- Send a message in the channel and the bound agent (or team) replies with the same memory and tools
  it has in Desktop.
- Each chat keeps a **persistent** conversation. A follow-up message continues where the last one
  left off.
- Route to a **team** and the reply is one combined, attributed answer from the team's members, not a
  single agent's.
