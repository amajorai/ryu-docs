Build an agent in TypeScript with the Ryu SDK. The example scaffolds a project, defines an agent whose
model calls go through the Gateway without a provider key in your code, runs it locally, streams
its reply, and bundles it as a plugin.

This is the *write-your-own-agent* path (`defineAgent` + `ctx.gateway`). For the standalone
`defineModel` script path, where the model is a swappable string, start from the
[Quickstart](/docs/extend/develop/quickstart). The same Gateway governs both paths.

## What you'll use

- [Quickstart](/docs/extend/develop/quickstart): scaffold a plugin with `create-ryu-app`.
- [The SDK](/docs/extend/develop/sdk): the `defineAgent` factory and the Gateway-mandatory model client.
- [Gateway](/docs/gateway): what governs every model call your agent makes.

## Prerequisites

- **Bun** on your PATH (`bun` and `bunx`). Ryu uses [Bun](https://bun.sh) across the monorepo.
- **A running Ryu Core**, which runs the Gateway as a managed sidecar on `http://127.0.0.1:7981`.
- A model the Gateway can route. Local onboarding tries to install a default local model; check that
  it finished before you rely on it.
- If your Gateway requires auth, the `RYU_GATEWAY_TOKEN` for it. This is the Gateway token, never a
  provider API key.

## Steps

<Steps>

<Step>

### Scaffold a project

Scaffold a new plugin, passing a lowercase project name:

```bash
bunx create-ryu-app my-first-agent
cd my-first-agent
bun install
```

`create-ryu-app` writes a valid `manifest.json`, a starter `src/agent.ts`, and a `package.json` that
depends on `@ryuhq/sdk`. See [Quickstart](/docs/extend/develop/quickstart) for what each file is.

</Step>

<Step>

### Write the agent

An agent is a [Runnable](/docs/start-here/architecture/runnable-model): an object with an `id`, a
`name`, and a `run()` method. The one rule is that every model call goes through `ctx.gateway`,
never a provider SDK. Replace `src/agent.ts` with:

```ts
import { defineAgent } from "@ryuhq/sdk";

export const researcher = defineAgent({
  id: "agent-researcher",
  name: "Researcher",
  async run({ query }: { query: string }, ctx) {
    const result = await ctx.gateway.chat([
      { role: "system", content: "You answer concisely." },
      { role: "user", content: query },
    ]);
    return { answer: result.content };
  },
});
```

There is no API key and no base URL here. `ctx.gateway` is injected for you, and it is the only
allowed path to a model. The Gateway resolves the provider, applies routing and budgets, and
returns the reply. Your agent code never names a provider or a model id. That decision lives in the
Gateway config, so you can change the model without editing this file. See
[the Gateway overview](/docs/gateway).

</Step>

<Step>

### Run it locally

`run()` takes the input and a context whose only required field is `gateway`. `defineModel` returns
a model client that targets `RYU_GATEWAY_URL` (default `http://127.0.0.1:7981`) and sends
`RYU_GATEWAY_TOKEN` when it is set. Create `src/run.ts`.

```ts
import { defineModel } from "@ryuhq/sdk";
import { researcher } from "./agent";

const gateway = defineModel(process.env.RYU_MODEL ?? "gpt-4o-mini");
const query = process.argv.slice(2).join(" ") || "What does a gateway do?";
const { answer } = await researcher.run({ query }, { gateway });
process.stdout.write(`${answer}\n`);
```

Then run it:

```bash
bun run src/run.ts "What is a Runnable?"
```

<Callout type="warn">
`bunx ryu dev <entry>` is not a runner for `defineAgent`. It loads the module's `default` (or
`runnable`) export and calls `run(messages, model)` as a generator that yields `text`, `tool_call`,
and `tool_result` events. A `defineAgent` runnable does not match that contract.
</Callout>

<Callout type="warn">
The agent needs a model the Gateway can route. If the Gateway cannot resolve the model id, the turn
fails. Use a model your Gateway can route, for example a local model id or an `openrouter/...` slug.
</Callout>

</Step>

<Step>

### Stream the reply token by token

`ctx.gateway.chat()` waits for the whole reply. To show tokens as they arrive, swap it for
`ctx.gateway.stream()`, which yields `{ content, finishReason }` deltas. Accumulate them into the
return value and write each fragment to stdout as it lands:

```ts
import { defineAgent } from "@ryuhq/sdk";

export const researcher = defineAgent({
  id: "agent-researcher",
  name: "Researcher",
  async run({ query }: { query: string }, ctx) {
    let answer = "";
    for await (const delta of ctx.gateway.stream([
      { role: "system", content: "You answer concisely." },
      { role: "user", content: query },
    ])) {
      if (delta.content) {
        process.stdout.write(delta.content);
        answer += delta.content;
      }
    }
    return { answer };
  },
});
```

Nothing else changes. The same Gateway governs the streaming call, so routing, budgets, and audit
still apply. Run `bun run src/run.ts` again. The reply now prints as it generates, and `src/run.ts`
prints the full answer at the end.

</Step>

<Step>

### Bundle it for the store

When the agent works, bundle the plugin so the Store in Desktop can install it.

```bash
bun run pack
```

This runs `bunx ryu pack .`, validates `manifest.json` against the same schema the store reads, and
writes `dist/plugin.bundle.json`. An invalid manifest exits non-zero and names the failing field.

</Step>

</Steps>

## Check your work

- `bun run src/run.ts "<question>"` prints a concise answer, which shows the call reached a model
  through the Gateway.
- After the streaming step, the reply prints fragment by fragment before the full answer.
- If the Gateway cannot resolve the model, the turn fails with a routing error instead of hanging.
  Point it at a model your Gateway can route (see the callout above).
- `bun run pack` exits `0` and writes `dist/plugin.bundle.json`. A broken `manifest.json` exits
  non-zero and names the failing field, so a bad manifest never reaches the store.
