---
title: "Give a Model a Tool It Can Call"
description: "Define a typed tool with the Ryu SDK, validate its input, and let an agent call it during its turn."
---

A tool lets a model run your code during a turn. The example defines a tool with the Ryu SDK,
validates its typed input before your code runs, and gives it to an agent.

## What you'll use

- [The SDK](/docs/extend/develop/sdk): the `defineTool` factory and the `Agent` class.
- [MCP registry](/docs/core/mcp-registry): how tools are discovered and dispatched once installed.

## Prerequisites

- **Bun** on your PATH (`bun` and `bunx`).
- A scaffolded plugin project. If you do not have one, start from
  [Build your first agent in code](/docs/learn/cookbook/first-sdk-agent) and come back.
- **A running Ryu Core** (it runs the Gateway sidecar) with a model the Gateway can route.

## Steps

<Steps>

<Step>

### Define the tool

A tool is a [Runnable](/docs/start-here/architecture/runnable-model) with `kind = "tool"` and a JSON
Schema describing its input. The schema is the same shape Core's tool layer expects, so it forwards
without transformation. The SDK validates input against it before your `run()` body executes. A
missing required field or a type mismatch throws an error instead of reaching your code. Save it as
`src/word-count.ts`.

```ts
import { defineTool } from "@ryuhq/sdk";

export const wordCount = defineTool({
  id: "tool-word-count",
  name: "Word Count",
  schema: {
    type: "object",
    properties: {
      text: { type: "string", description: "The text to count words in" },
    },
    required: ["text"],
  },
  async run({ text }: { text: string }) {
    return { words: text.trim().split(/\s+/).filter(Boolean).length };
  },
});
```

A tool body that runs in-process receives the normal `(input, ctx)` arguments. When the tool ships
inside a plugin, Core runs the serialized body in its JS sandbox with only `input` and `host` in
scope. `ctx.gateway` is not available there. A shipped tool reaches a model through
`host.sideModel`, gated by the plugin's grants.

</Step>

<Step>

### Give it to an agent

The SDK `Agent` class (`@ryuhq/sdk/agent`) owns a tool-calling loop. Pass the tool in `tools`, and
the model can call it during the turn. This is the same pattern as the scaffold's starter
`src/agent.ts`.

```ts
import { Agent } from "@ryuhq/sdk/agent";
import { wordCount } from "./word-count";

const agent = new Agent({
  name: "Editor",
  model: process.env.RYU_MODEL ?? "gpt-4o-mini",
  instructions: "You are an editor. Call the wordCount tool when the user asks about length.",
  tools: { wordCount },
});

const result = await agent.generate("How many words are in this sentence?");
process.stdout.write(`${result.text}\n(${result.steps} step(s))\n`);
```

Every model call goes through the Gateway at `RYU_GATEWAY_URL` (default `http://127.0.0.1:7981`).
Set `RYU_MODEL` to a model id your Gateway can route. The loop stops after 10 model-to-tool rounds
by default.

`defineAgent` also accepts a `tools` list. That list declares the tools the agent exposes in its
agent card. See [the Runnable model](/docs/start-here/architecture/runnable-model).

</Step>

<Step>

### Run and bundle

Run the agent, then bundle the plugin:

```bash
bun run src/agent.ts
bun run pack
```

`pack` validates the manifest and writes `dist/plugin.bundle.json` for the store.

</Step>

</Steps>

<Callout type="info">
Input validation is enforced at `run()` time. Calling the tool with a missing `text`, or with a
number where a string is expected, throws before the body runs.
</Callout>

## Check your work

- `bun run src/agent.ts` prints the answer and the step count. Ask about the length of a text, and the answer uses the real word count.
- Call `wordCount.run()` with a missing `text` (or a number in its place) and it throws a
  validation error **before** the body executes.
- `bun run pack` exits `0` and writes `dist/plugin.bundle.json` for the store.
