---
title: "Record a Desktop Task Once, Replay It as a Workflow"
description: "Capture your clicks and typing one time, then run them on demand as a workflow."
---

Record a repeated desktop task, such as filling a form or clicking through the same panels, and turn
it into a workflow. You then replay the captured steps without authoring each node by hand.

## What you'll use

- [Recorded Automations](/docs/surfaces/desktop/productivity/recipes): record a desktop task into workflow steps.
- [Workflows](/docs/core/workflows): the DAG engine that runs the recorded steps.

<Callout type="warn">
  Recording and replay need the Ghost desktop-automation sidecar installed. Input capture is
  Windows-native. On other platforms, recording and replay report an error until the sidecar is
  available. Replay needs a display.
</Callout>

## Steps

<Steps>

<Step>

### Open the Workflows surface

In the desktop app, open the **Workflows** page. You author and record workflows there.

</Step>

<Step>

### Start recording

Click **Record a task**, describe what you are about to do, then start recording. Ryu begins
capturing your input on screen.

</Step>

<Step>

### Perform the task

Do the task once, as you normally would (clicks, typing, scrolls). Ryu records each action.

</Step>

<Step>

### Stop recording

Click stop. Ryu turns the captured actions into a workflow with an `Input` node, one node per action,
and an `Output` node. Each captured action becomes a `ghost_action` step node that you can read and
edit.

</Step>

<Step>

### Review the workflow

The canvas shows the actions in order, for example a click step labelled from its
target ("click to Compose") followed by a type step. Each `ghost_action` node carries an action verb,
a target, and any params. You can edit, reorder, or delete steps before running. Because the steps are
ordinary workflow nodes, you can also feed them upstream data with `{{...}}` template tokens, the same
way other workflow nodes resolve values (see [Template variables](/docs/core/workflows#template-variables)).

</Step>

<Step>

### Run it

Choose **Run** above the canvas, then **Run** in the panel that opens. You can also trigger it
through the Core API:

```http
POST /api/workflows/:id/run
```

Each `ghost_action` step maps to the matching Ghost action (click, type, scroll, ...) and replays it
through the Ghost engine, the same way a recorded recipe replays step by step.

</Step>

</Steps>

<Callout type="info">
  New in-canvas recordings produce per-action step nodes that you edit on the canvas. To keep a whole
  automation as one unit instead, Ghost's recipe engine can also save and replay a
  complete recipe as a single `recipe` node. See [Recorded Automations](/docs/surfaces/desktop/productivity/recipes).
</Callout>

## Check your work

- After you stop recording, the canvas shows an `Input` node, one `ghost_action` node per captured
  action (labelled from its target, for example "click to Compose"), and an `Output` node.
- Each `ghost_action` node carries an action verb, a target, and params you can edit or reorder
  before running.
- **Run** (or `POST /api/workflows/:id/run`) replays the steps through the Ghost engine, so the
  same clicks and typing happen again.
