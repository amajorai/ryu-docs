---
title: "Broker Console"
description: "Manage credential broker services, sessions, request logs, discovered hosts, and per-environment settings from the Vault page in the Ryu desktop app."
---

The **Broker** tab on the desktop app's Vault page manages the
[credential broker](/docs/security/secret-vault-broker). It never shows a credential value: services
name `secret:` and password-manager references, and the request log records only the method, host,
path, and status of each request.

People without broker access see their own card spend approvals and a notice that the rest of the
tab is for broker admins.

## Requests

**Requests** opens first. It lists:

- Card spend approvals, with **Reject**, **Allow 15 min**, and **Approve once**.
- Pending agent [proposals](/docs/security/secret-vault-broker#proposals), with **Approve** and
  **Reject**. A password-manager request also has a menu for how long the approval lasts.
- Services, with **Add service** and, on each row, **Edit** and **Delete**.

**Add service** starts from a built-in template (Anthropic, OpenAI, GitHub, GitLab, Gemini, Linear,
npm, Slack, Stripe) or from **Custom service**:

- From a template, you choose the service name and the credential reference. The template fills in
  the host, path, and auth scheme.
- From a custom service, you set the host, port, path prefix, description, and the credential:
  - a bearer token reference;
  - an API key header and its reference, with an optional value prefix;
  - basic auth;
  - custom headers written as `Name: {{secret:REF}}`, one per line;
  - no credential, for services that only use placeholders.

Editing keeps the parts the form does not show: placeholders, notes, plain-HTTP opt-in, and an
OAuth connection. Saving needs `admin` on `sys/broker/<service>` and `use` on every credential the
service names. Otherwise the vault refuses the save and the dialog shows why.

## Environment

**Sessions**, **Activity**, and **Settings** apply to one environment. You pick it at the top of the
tab, and it starts as the environment selected on the Vault page.

## Sessions

**Sessions** lists live broker sessions, including the `runtime:` sessions Ryu mints for the agents
it starts. Each row shows its services, who started it, and when it expires. **Revoke** ends a
session at its next request. Listing sessions needs `admin` on `sys/broker`. You can always revoke a
session you started.

**New session** starts a session for the enabled services you tick, with a label and a lifetime of
15 minutes to 24 hours. You need `use` on each service. The token and a block of `export` lines for
the proxy environment appear once. Copy them before you close the dialog, because they are not kept
anywhere and cannot be shown again. The proxy environment contains the token, so treat it like the
token.

## Activity

**Discovered hosts** lists hosts that agents asked for when no service matched, with the request
count and when each was last seen. **Create service** opens the service form for that host. If a
built-in template matches the host, the form starts from that template.

**Request log** shows brokered requests, newest first: status, method, host, path, service, outcome,
and latency. You can filter by status class (2xx to 5xx) and load older rows. While **Live** is on,
the log refreshes every few seconds. Both lists need `list` on `sys/broker`.

## Settings

**Settings** sets the environment's
[unmatched-host policy](/docs/security/secret-vault-broker#requests-to-unknown-hosts). Choose
whether to refuse such requests and tell the agent how to propose a service, or to forward them
without a credential.

The same view edits the agent skills: up to 64 KiB of text that agents read through discovery.
Keep credentials out of the skills, because every agent with a session can read them.

The view also shows whether the broker proxy is listening on this node. Saving needs `admin` on
`sys/broker`.
