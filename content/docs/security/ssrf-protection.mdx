---
title: "SSRF protection"
description: "How Ryu guards outbound fetches against server-side request forgery, including cloud-metadata and homograph host attacks."
---

When a Core-owned feature fetches a user-or-model-supplied URL through the guarded egress path, it gets destination screening, connection pinning, redirect denial, and bounded responses. These guarantees belong to that transport boundary; a URL validation result or a separate provider/child-process client is not equivalent.

The same sink-time rule applies to model/runtime downloads, skill archives, workflow webhooks, Core notifications, hosted-node delegation, and mail delivery. Artifact downloads require an integrity digest before executable bytes are installed; child-process crawlers and unpinned remote Git clones fail closed.

## Existing protections

- Blocks loopback, private, link-local, CGNAT, and ULA address ranges on guarded requests
- Pins guarded client connections to the validated IP, so DNS cannot be re-resolved to a different address after the check
- Forbids redirects on guarded requests, so a redirect cannot bounce them to an internal target
- Caps guarded response bodies
- Requires SHA-256 metadata before downloaded runtimes, tools, plugins, or MCP servers can be
  installed and executed

## Added protections

Features that use the shared guarded transport inherit these protections automatically. Other
outbound surfaces must use an equivalent broker or remain explicitly constrained; they must not
claim SSRF protection merely because a URL was screened earlier.

### Cloud-metadata hostname denylist

The `169.254.169.254` metadata IP was already blocked. The guard now also rejects the metadata *hostnames*, case-insensitive - a host equal to or ending in `metadata.google.internal` or `metadata.goog`, plus the bare host `metadata`. This closes the gap where a name resolves to the metadata endpoint through DNS rather than a literal IP.

### Homograph and hostile-host guard

The guard rejects a host that:

- contains non-ASCII characters
- contains zero-width or bidi control characters
- fails to round-trip through IDNA / punycode encoding (a decode mismatch)
- contains embedded control characters or whitespace

This blocks lookalike-domain (homograph) attacks and hosts crafted with invisible or directional Unicode to disguise their real target.

<Callout type="info">
Use the guarded transport for server-side fetches. Provider-owned HTTP clients, browser/crawler
navigation, command-line network tools, downloads, and sidecar callbacks need their own pinned
egress boundary; a preflight check alone does not close DNS rebinding or redirect risks.
</Callout>
