---
title: "Hardening Checklist"
description: "A checklist for operators who deploy Ryu beyond a single local machine."
---

The defaults assume single-user local use on loopback. Before you expose Ryu on a shared machine, a server, or a tunnel, work through this list. Each item links to the page that explains it.

## Network and access

- [ ] Set `RYU_TOKEN` before any non-loopback bind. Never expose `0.0.0.0` or a LAN address without it. See [Network binding and auth](/docs/security/network-binding-auth).
- [ ] Keep Gateway authentication on. Do not set `[auth] require_auth = false`. See [Network binding and auth](/docs/security/network-binding-auth).
  - In that mode, when no Gateway administrator key is set, a loopback peer can reach Gateway administration.
  - A co-located reverse proxy makes external callers look like loopback.
- [ ] Keep the Gateway administrator key away from apps, agents, and proxies.
- [ ] Verify that any proxy or tunnel forwards the `Authorization` header intact.

## Execution governance

- [ ] Keep `RYU_EXEC_APPROVAL_MODE=manual` in any shared or server deployment. See [Command approval](/docs/security/command-approval).
- [ ] Do not set `RYU_ALLOW_GATEWAY_FALLBACK=1` in production. It disables the fail-closed default when the scanner is unreachable. See [Command approval](/docs/security/command-approval).
- [ ] Do not plan workflows around permanent deletion. Core always denies it; approvals, managed rules, and Gateway fallback cannot authorize it. See [Command approval](/docs/security/command-approval).
- [ ] Confirm the hardline blocklist behavior with a dry run before you give agents a shell.

## Data protection

- [ ] Configure and test outbound redaction for response bodies, errors, and logs. Check the rules and traffic boundary for your deployment; redaction does not detect every secret. See [Outbound DLP](/docs/security/outbound-dlp).
- [ ] Restrict each MCP server's config `env` block to the exact keys it needs. Core scrubs everything else, but a wide `env` block re-introduces secrets. See [Credential and environment scrubbing](/docs/security/credential-scrubbing).
- [ ] Keep data-folder permissions tight (`~/.ryu/` on the release profile) so the SQLite store and its encrypted fields are not world-readable. See [Encryption at rest](/docs/core/encryption-at-rest).

## Host boundary

- [ ] Run the supplied Docker images as their rootless runtime users. The supplied `docker-compose.yml` applies these defaults:
  - keep the root filesystem read-only;
  - drop all Linux capabilities;
  - enable `no-new-privileges`;
  - never mount `/var/run/docker.sock` or use `privileged: true` for Ryu.
- [ ] On a VPS, keep Core and Gateway under the dedicated non-login `ryu` system user. Do not remove the systemd directives the installer (`infra/install.sh`) sets in an override:
  - `ProtectSystem=strict` with one writable state directory;
  - `PrivateDevices` and `PrivateTmp`;
  - an empty capability set.
- [ ] Use the current VPS installer when you reinstall an existing node.
  - It creates configuration and toolchain files inside service-owned state with the service user's permissions, so a redirected state path cannot make the installer change protected host files as root.
  - It preserves existing node configuration and stops if it finds a configuration symlink.
- [ ] Treat an agent workspace as disposable when it holds irreplaceable data. Managed Codex has an OS deletion backstop, but no process sandbox makes arbitrary host writes safe without a VM or copy-on-write workspace. See [Sandboxing and isolation](/docs/security/sandboxing-isolation).

## Routing and surface

- [ ] Scope channel and agent routing allowlists to the minimum each channel needs. See [Channel allowlists](/docs/security/channel-allowlists).
- [ ] Check which sandbox backend actually runs tool code. Each backend has a different boundary, and the opt-in `local` backend has none. See [Sandboxing and isolation](/docs/security/sandboxing-isolation).

## Operations

- [ ] Keep Ryu current. Security fixes ship in updates. See [Updates](/docs/core/updates).
- [ ] Read the [Trust model](/docs/security/trust-model) so you know what the boundary covers. In particular, Ryu is single-tenant.

## Build and publish

- [ ] Scan new commits for credentials before you merge. If a credential was committed, revoke it; deleting it in a later commit does not remove it from Git history.
- [ ] Inspect the files in each package, browser bundle, or container before you publish. Exclude private keys, dotenv files, and browser source maps unless you intend to disclose the source.
- [ ] Treat browser build-time environment variables as public. Keep provider and signing credentials on the server or in a secret store.
