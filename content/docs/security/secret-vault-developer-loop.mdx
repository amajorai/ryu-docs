The `ryu-cli secrets` commands on this page cover the day-to-day loop of building against the
Secret Vault: point a project at an environment once, start your app with the values it needs, get
fresh credentials per run, and keep the app on current values while you work.

## Pin a project to an environment

```sh
ryu-cli secrets init --env dev --path /api --tags backend
```

`init` checks that the environment exists on the node, then writes `.ryu-vault.json` in the current
directory:

```json
{
  "version": 1,
  "environment": "dev",
  "path": "/api",
  "tags": ["backend"]
}
```

The file names an environment, a folder, and a tag filter. It never holds a value, so you can
commit it. `init` will not replace an existing file unless you add `--force`.

`list`, `get`, `set`, `delete`, `versions`, `rollback`, `restore`, `destroy`, `import`, `export`,
`snapshot`, and `run` look for the nearest `.ryu-vault.json` in the current directory or any parent
directory, and use its environment and folder when you do not pass `--env` or `--path`. Its tags
narrow `run` and `export` unless you pass `--tags`. When the file sets the environment or folder,
the CLI names the file and the environment and folder it used on stderr. `delete` and `destroy`
never take their target from the file: when it would set one, they stop and ask you to pass
`--env` (and `--path`) yourself. Add `--no-project` to ignore the file for one
command. A file that is not valid JSON, or that has a field other than `version`, `environment`,
`path`, `tags`, and `orgProject`, stops the command with an error naming the file.

## Include an organization project's values

```sh
ryu-cli secrets run --org-project <projectId> -- npm run dev
ryu-cli secrets init --env dev --org-project <projectId>
```

On a node enrolled in an organization, `--org-project` adds that project's shared values to `run`
and `export`, ahead of Team and Organization values. `init --org-project` records it as
`orgProject` in `.ryu-vault.json`, and `run` and `export` then use it (and say so on stderr) unless
you pass `--org-project`. Other commands ignore it. The control plane checks that you can reach the
project, and a command that names one fails if the project's values cannot be fetched; see
[Project values at run time](/docs/security/secret-vault-shared-values#project-values-at-run-time).
It is not available with a machine token (`RYU_VAULT_TOKEN`).

## Run with only the tagged values

```sh
ryu-cli secrets run --tags backend,db -- npm run dev
ryu-cli secrets export --tags backend --format dotenv
```

`--tags` keeps the values that carry at least one of the listed tags (set them with
`ryu-cli secrets set NAME --tag T`). When the same name exists at several levels, such as your own
value and a node value, it is included only if every one of them carries a listed tag, so the
filter never lets in a value you did not tag. When nothing matches, the command gets no values and
the CLI says so on stderr.

The tag filter needs to list values, so it is not available with a machine token
(`RYU_VAULT_TOKEN`).

## Lease a credential for one run

```sh
ryu-cli secrets run --lease db -- npm test
ryu-cli secrets run --lease aws=AWS --lease-ttl 30m -- terraform plan
```

Each `--lease ROLE` issues a new credential from a [dynamic role](/docs/security/secret-vault-engines)
before the command starts and adds its fields to the command's environment as `PREFIX_FIELD`. The
prefix defaults to the role name in capitals, so a Postgres role named `db` gives `DB_USERNAME` and
`DB_PASSWORD`; `ROLE=PREFIX` picks another prefix. `--lease-ttl` sets the lease length.

When the command exits, the CLI revokes every lease it issued, also when the CLI is stopped with
`SIGTERM` or `SIGHUP`. If a lease field would replace a value that is already set, or a later lease
cannot be issued, the leases issued so far are revoked and the command does not start. A revoke
that fails is reported with the lease id and its expiry time; the lease then ends at that time.

`--lease` puts a credential in the command's environment, so it cannot be combined with
`--broker`.

## Restart when values change

```sh
ryu-cli secrets run --watch -- npm run dev
```

With `--watch`, the CLI subscribes to the node's change notifications before it reads any values.
When a value in the run's environment is written, deleted, destroyed, or imported, when a change
request for it is applied, or when one of the run's leases is revoked or expires, it stops the
command, reads the values and issues the leases again, and starts it anew. Changes that arrive
together cause one restart. With `--tags`, the tagged values are selected again at every restart,
so a value that lost its tag is no longer passed to the command. If the command exits by itself, the watch ends with its exit code.

The notifications carry names and versions, never values, and you receive only those for values
you may list. If the node refuses the subscription, the command never starts. If the connection
drops, the CLI reconnects and restarts the command once to pick up anything it missed; a long watch
can reconnect any number of times. If it cannot reconnect after a few attempts, or the node refuses it, the CLI stops the command rather than leave it running on values
it can no longer follow.

Changes to Team and Organization values made on the control plane do not send notifications to the
node, so they take effect at the next restart. `--watch` is not needed with `--broker`, because the
broker reads the current values on every request.

## Dynamic roles and leases

| Need | Command |
|---|---|
| List dynamic roles | `ryu-cli secrets dynamic roles` |
| Create or replace a role from a JSON file | `ryu-cli secrets dynamic put ROLE role.json` |
| Issue one credential and print it | `ryu-cli secrets dynamic issue ROLE --ttl 1h` |
| Revoke every lease of a role | `ryu-cli secrets dynamic revoke-all ROLE` |
| Delete a role | `ryu-cli secrets dynamic delete ROLE` |
| List active leases (add `--all` for revoked ones) | `ryu-cli secrets lease list --name ROLE` |
| Extend or end a lease | `ryu-cli secrets lease renew ID --increment 1h`, `ryu-cli secrets lease revoke ID` |

The role file holds the provider settings, so the provider's own credentials never appear on the
command line:

```json
{
  "provider": { "kind": "random", "charset": "hex", "length": 32 },
  "defaultTtl": "1h",
  "maxTtl": "24h"
}
```

`kind` is `postgres`, `aws-sts`, `webhook`, or `random`, with that provider's fields. Listings show
roles with their credentials redacted. With `RYU_VAULT_TOKEN` set, `dynamic issue` and
`lease renew|revoke` use the machine token.

## Destroy versions

`delete` hides a value and `restore` brings it back. `destroy` erases stored versions for good:

```sh
ryu-cli secrets destroy API_KEY 3 4
ryu-cli secrets destroy API_KEY --all
```

Destroying every version needs `--all`, so a missing version number never erases the whole history.

## Encrypted snapshots

```sh
export RYU_VAULT_PASSPHRASE='a long passphrase you keep elsewhere'
ryu-cli secrets snapshot --env prod --out prod.snapshot.json
ryu-cli secrets import prod.snapshot.json --format snapshot
```

`snapshot` exports the values you may read in the environment and folder as a file encrypted with
your passphrase (at least 12 characters). The file is created readable only by you, and `--out`
will not replace an existing file unless you add `--force`. Without `--out` the encrypted file goes
to standard output. The passphrase is read from `RYU_VAULT_PASSPHRASE`; `--passphrase` also works
but is visible to other processes and in shell history.

## In an AI coding agent

When the CLI detects a coding agent (see
[Secret Vault](/docs/security/secret-vault#when-an-ai-coding-agent-runs-the-cli)), `dynamic issue`
and `snapshot` refuse to print, like `get` and `export`. `run` prefers the credential broker when
the environment has broker services, and a broker run refuses `--lease`, so the agent's command
does not receive a leased credential. A person at a terminal can add `--human` to lift the checks
for one command.
