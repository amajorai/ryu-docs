By default Core binds `127.0.0.1:7980` and the Gateway binds `127.0.0.1:7981` - loopback only. Nothing is reachable from another machine until you deliberately change the bind address. Core still mints and requires a local node credential: loopback limits network reach, but it is not a substitute for authentication between local processes. See [Ryu port scheme](/docs/core) for the full port layout.

## Token auth for non-loopback exposure

Loopback is the safe binding default. Core's protected routes also require a valid owner, paired,
or delegated credential. If Core cannot load or persist its node credential, startup stops before any listener or child
process starts. Repair the credential storage before restarting; Ryu never substitutes an
unauthenticated owner session.

| Setting | Default | Effect |
|---|---|---|
| Bind address | `127.0.0.1` | Reachable only from the same machine |
| `RYU_TOKEN` | locally generated when unset | Operator-supplied owner credential; otherwise Core persists a random local owner credential |

Clients pass the token as a standard bearer header:

```
Authorization: Bearer <RYU_TOKEN>
```

## Gateway authentication

Gateway inference requires a credential by default, including on loopback. Ryu provisions
separate credentials for administration, trusted Core forwarding, and app or agent inference.
Apps and agents receive an inference credential; they do not receive the Gateway administrator
credential. Core applies the credentials when it starts the Gateway and forwards model requests,
so normal local use does not require copying a key into settings.

Native ACP and Pi agents receive signed inference credentials bound to their assigned agent
and, when available, user and conversation. Changing a request's identity cannot move its spend
to another agent or bypass that agent's budget. These credentials grant neither administration
nor trusted forwarding authority.

A standalone Gateway stores private `gateway-admin.key` and `gateway-relay.key` files beside
its configuration. External clients use the inference key from `gateway-relay.key` as their bearer;
the administrator key is reserved for administration. Explicitly configured credentials must have
at least 24 printable characters without whitespace. Credentials are validated,
and invalid configuration or unavailable credential storage stops Gateway startup.

Core verifies a fresh signed readiness proof, bound to the listening address, protocol version,
and credential roles, before sending credentials to an already-running Gateway.
An older unauthenticated listener must be restarted with the managed configuration before Core
will use it. A reverse proxy or mesh connection does not grant administrative authority.

An explicit local development configuration can disable inference authentication. This is an
unsafe opt-out, is not used by Core-managed Gateways, and cannot be combined with a non-loopback bind.

## When to set a token

- Binding to `0.0.0.0` or a LAN address - always set `RYU_TOKEN` first.
- Exposing through Tailscale, Headscale, Tailcat, or another tunnel/proxy - set the token and verify the
  transport forwards the `Authorization` header. A Tailcat address is separate from the Core token and grants
  access to the Tailcat listener; treat both values as secrets.
- Pure local single-user use on loopback - let Core generate its local credential; clients pair for narrower access.

Use the owner token only for recovery and owner-only administration. Ordinary apps and MCP hosts
should use a paired capability bearer, which can be scoped, bound, expired, and revoked independently.

For a locally generated owner token, `POST /api/node/token/rotate` atomically persists a new token and
switches every live Core verifier before responding. The previous bearer stops working immediately
across REST, realtime sockets, extension proxies, and local self-calls; no Core restart is required.
An operator-supplied `RYU_TOKEN` cannot be rotated through this route because the environment remains
authoritative—change the deployment secret and restart the process instead.
