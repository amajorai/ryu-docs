---
title: "Reconnect Retry"
description: "Retry chats that were interrupted by a Wi-Fi, LAN, or node outage"
---

**Reconnect Retry** is an opt-in chat reliability plugin. It watches the selected
node and the app's network reachability, remembers conversations that were actively
running when connectivity disappeared, and asks Core to retry eligible turns when
the connection returns.

## What happens

- A live turn is resumed first when Core kept running it underneath the dropped UI
  connection.
- If the turn became `failed` or `interrupted`, the plugin queues it for one retry
  after both the network and selected node are reachable again.
- The already-persisted user message is reused, so reconnecting does not append a
  duplicate prompt.
- The desktop shows a short connection/retry status banner, including how many chats
  were queued and restarted.

The queue is node-local and expires after a short window. Only conversations seen as
running during the outage are candidates; an unrelated old failure is never swept up
by the feature. Core re-checks conversation access, the caller's run permission, and
the terminal run state before accepting the retry. A second window cannot claim the
same terminal run concurrently.

## Enable it

Install and enable **Reconnect Retry** from the Ryu Store. It is deliberately off
until you choose the plugin because an automatic retry can repeat a provider call.
The plugin makes one bounded attempt per conversation per outage; if that attempt
cannot start, the chat stays available for a normal manual retry.

Reconnect Retry covers chats routed through the selected Ryu node. It does not claim
that a provider-side failure, an expired credential, or a user-pressed **Stop** was a
network outage. Those remain ordinary terminal chat states.
