## What it does

Spider Cloud (https://spider.cloud) provides hosted multi-page crawling through one declarative HTTP tool. It is the second provider for the swappable `web.crawl` layer alongside the local `spider` CLI. Selecting it routes the stable `web.crawl` tool to a hosted crawler that needs no local binary.

The crawl is synchronous. `run_in_background` defaults to false, and one request returns every fetched page's content, so there is no job id to poll. The plugin omits the canonical `depth` argument because Spider Cloud's `depth: 0` means no limit, while Ryu's contract uses 0 for the start page only. Requires a BYOK Spider Cloud API key.

## What it exposes

### Tools

### `spidercloud.crawl` - Spider Cloud Crawl

Crawl a site from a start URL with the hosted Spider Cloud crawler and return every fetched page as markdown in a single request. Requires `RYU_SPIDERCLOUD_API_KEY`. Crawl depth is pinned to three hops. Spider Cloud's `depth` is a maximum where 0 means no limit, the inverse of the canonical `web.crawl.depth`, where 0 means the start page only. Without the pin, an unqualified crawl would use Spider Cloud's default of 25.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `url` | string | yes | The start URL to crawl from. |
| `limit` | integer | no | Maximum number of pages to fetch (default 10). Capped well below the canonical ceiling because the crawl is synchronous and the host HTTP tool aborts at 30s; the upstream API treats 0 as "crawl every page on the site", which is why this is never sent empty. |
