## What it does

Hosted multi-page web crawling via the Spider Cloud API (https://spider.cloud), exposed as one declarative HTTP tool. Provides the swappable `web.crawl` layer as a SECOND provider alongside the local `spider` CLI, so selecting it re-points the stable `web.crawl` tool at a hosted crawler that needs no local binary. The crawl is synchronous - `run_in_background` defaults to false and one request returns every fetched page's content, so there is no job id to poll. The canonical `depth` argument is deliberately DROPPED: Spider Cloud documents `depth: 0` as "no limit will be applied", the exact inverse of the canonical contract's "0 = the start page only". Requires a BYOK Spider Cloud API key.

## What it exposes

### Tools

### `spidercloud.crawl` - Spider Cloud Crawl

Crawl a site from a start URL with the hosted Spider Cloud crawler and return every fetched page as markdown, in a single request. Requires RYU_SPIDERCLOUD_API_KEY. Crawl depth is pinned to 3 hops: Spider Cloud's `depth` is a maximum where 0 means NO limit - the inverse of the canonical `web.crawl.depth`, where 0 means the start page only - so the canonical argument cannot be translated by a rename and is dropped. Without a pin an unqualified crawl would run at Spider Cloud's own default of 25.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `url` | string | yes | The start URL to crawl from. |
| `limit` | integer | no | Maximum number of pages to fetch (default 10). Capped well below the canonical ceiling because the crawl is synchronous and the host HTTP tool aborts at 30s; the upstream API treats 0 as "crawl every page on the site", which is why this is never sent empty. |
