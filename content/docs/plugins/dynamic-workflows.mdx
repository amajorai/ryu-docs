### `workflow.script` - workflow.script

Run a durable workflow script: JavaScript that orchestrates sub-agents. Helpers: agent(prompt, &#123;label, preset, max_tokens, timeout_secs, schema, json&#125;) resolves to the agent's text (or parsed JSON with schema/json); parallel([() => agent(...), ...]) runs thunks concurrently (a failed one yields null); pipeline(items, ...stages) streams each item through async stages; phase(title) labels progress; log(...) records notes; args holds the 'args' input. The body is an async function body: use await and return the result. Sub-agents run as the calling agent. Every finished agent() call is checkpointed: if Ryu restarts, a background task crashes, or a provider rate/usage/session limit is hit, the run resumes on its own and finished agents are not run again. The call waits up to wait_secs for the result; if the run is still going, call again with run_id to keep waiting.

Calling again with the same script and args re-attaches to the same run instead of starting over.

Backend: Sandboxed JS

| Parameter | Type | Required | Description |
|---|---|---|---|
| `script` | string | no | Async JavaScript body using agent(), parallel(), pipeline(), phase(), log(), and args. |
| `args` | string | no | Any JSON value passed to the script as args. |
| `preset` | string (one of: research, code_read, code_write, summarise) | no | Default sub-agent preset (research when omitted). code_write runs the calling agent with its tools. |
| `run_key` | string | no | Set to run the same script and args again as a separate run. |
| `run_id` | string | no | Follow an existing run instead of starting one. |
| `wait_secs` | integer | no | How long to wait for the result (default 300). |
