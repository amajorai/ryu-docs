## What it does

Usage Pacer selects a lower model for a turn before it starts when an agent is consuming its subscription quota too quickly. It reads the same 5-hour and weekly windows shown beside the composer; it never refreshes provider credentials and never changes an agent's saved model.

For an even seven-day window, the target burn is about 14% per day. A window consumed faster than its elapsed share is shown as **in deficit**; a slower window is **in reserve**. The plugin can use that pace signal or use only explicit usage thresholds.

## Configure a ladder

Open **Settings → Plugins → Usage pacing**, enable automatic selection, then edit **Agent and global ladders**. The setting is JSON so one policy can define any number of agents and providers. An agent entry takes precedence over `global`.

```json
{
  "global": {
    "windows": "weekly",
    "pace_deficit": 15,
    "ladder": [
      { "from": "opus", "at": 50, "model": "sonnet" },
      { "from": "sonnet", "at": 75, "model": "haiku" }
    ]
  },
  "agents": {
    "acp:claude": {
      "windows": "both",
      "pace_deficit": 15,
      "ladder": [{ "from": "opus", "at": 50, "model": "sonnet" }]
    }
  }
}
```

`windows` is `weekly`, `session` (the rolling 5-hour window), or `both`. `at` is the percentage already consumed. In **Even burn** mode, deficit beyond `pace_deficit` adds pressure toward the next step; it cannot skip a rung by itself. In **Usage thresholds only** mode, only `at` activates a step.

## Permissions

The plugin may read its own settings and a sanitized subscription-usage snapshot. It cannot read provider credentials, refresh tokens, or alter saved agent configuration.
