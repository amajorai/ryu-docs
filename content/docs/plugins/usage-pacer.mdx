## What it does

Usage Pacer selects a model for a turn before it starts based on the agent's readable subscription windows. It can select a lower model while you are burning quota too quickly, then select a stronger model or enable an ACP option when the window is nearly spent or close to reset. It reads the same 5-hour and weekly windows shown beside the composer; it never refreshes provider credentials and never changes an agent's saved model.

For an even seven-day window, the target burn is about 14% per day. A window consumed faster than its elapsed share is shown as **in deficit**; a slower window is **in reserve**. The plugin can use that pace signal or use only explicit usage thresholds.

## Configure pacing and escalation

Open **Settings → Plugins → Usage pacing**, enable automatic selection, then edit **Agent and global ladders**. The setting is JSON so one policy can define any number of agents and providers. An agent entry takes precedence over `global`.

```json
{
  "global": {
    "windows": "weekly",
    "pace_deficit": 15,
    "ladder": [
      { "from": "opus", "at": 50, "model": "sonnet" },
      { "from": "sonnet", "at": 75, "model": "haiku" }
    ],
    "upgrade_ladder": [
      { "from": "sonnet", "remaining": 20, "model": "opus" },
      { "from": "opus", "within_minutes": 1440, "acp_config": { "fast_mode": "true" } },
      { "from": "opus", "within_minutes": 60, "effort": "high" }
    ]
  },
  "agents": {
    "acp:claude": {
      "windows": "both",
      "pace_deficit": 15,
      "ladder": [{ "from": "opus", "at": 50, "model": "sonnet" }],
      "upgrade_ladder": [
        { "from": "sonnet", "remaining": 20, "model": "opus" },
        { "from": "opus", "within_minutes": 1440, "acp_config": { "fast_mode": "true" } }
      ]
    }
  }
}
```

`windows` is `weekly`, `session` (the rolling 5-hour window), or `both`. `at` is the percentage already consumed. In **Even burn** mode, deficit beyond `pace_deficit` adds pressure toward the next step; it cannot skip a rung by itself. In **Usage thresholds only** mode, only `at` activates a step.

`upgrade_ladder` is the reverse policy. A step is eligible when any selected window has `remaining` percent or less, or when any selected window resets within `within_minutes`. Use one or both conditions. The step can set `model`, `effort`, and `acp_config`; an active end-of-window rule takes precedence over `ladder`, so ordinary pacing cannot undo the emergency upgrade.

`acp_config` is sent only through the ACP turn path. Usage Pacer's readable `fast_mode` key maps to the current official adapter ids: Codex ACP's `fast-mode` and Claude ACP's `fast`. Its value is kept as a string in the rule and crosses ACP as a boolean. If an older adapter or model does not advertise the option, Core logs a best-effort warning and continues the turn with the adapter's normal mode. Other ACP options pass through using their advertised ids.

## Permissions

The plugin may read its own settings and a sanitized subscription-usage snapshot. It cannot read provider credentials, refresh tokens, or alter saved agent configuration.
