## What it does

Emoji reactions on chat messages. People react from the message toolbar or right-click menu, and agents react with the agents.react tool, for example a 👍 on a quick instruction instead of a "Got it" reply. On a channel bot, the agent's reaction is mirrored onto the message it answered on platforms that support bot reactions.

## What it exposes

### Tools

### `agents.react` - React to a Message

Put an emoji reaction on a message in the current conversation, the way a person reacts in a messaging app. Omit message_id to react to the user's latest message: use it to acknowledge a quick instruction (👍), thank (🙏), laugh (😂), celebrate (🎉) or empathise (😢) without padding your reply with "Got it". React only when a person would; most messages need none, and a reaction never replaces an answer the user is waiting for. Pass an exact persisted message_id (for example from search_conversations.search) to react to an earlier message or to another agent's message. Repeating the same reaction is idempotent. Core resolves the conversation and the reacting agent; neither can be supplied here.

Backend: Sandboxed JS

| Parameter | Type | Required | Description |
|---|---|---|---|
| `message_id` | string | no | Optional. The exact persisted Core message id to react to. Omit it to react to the user's latest message. Streaming/client-generated ids and ids from another conversation are rejected; messages authored by other agents are allowed. |
| `emoji` | string | yes | One emoji, such as 👍, 🙏, 😂, 🎉, ❤️ or 👀. Prefer common emoji: chat platforms such as Telegram only accept a fixed set. |

## How reactions appear

Reactions on your own messages show as a small badge on the corner of the message bubble, so an
agent's 👍 is visible at a glance. Reactions on agent replies are listed in the reaction button of
the reply's toolbar. Add or remove your own reactions from the message toolbar or the right-click
menu.

## Agent reactions

Agents can react too. The `agents.react` tool lets an agent answer the way a person would in a
messaging app: a 👍 on a quick instruction, a 🙏 on thanks, a 😂 on a joke. Agents are told to
react only when a person would and never to use a reaction in place of an answer you are waiting
for.

Without a message id, the reaction goes on your latest message. With an id, an agent can react to
an earlier message or to another agent's message in the same conversation. Core decides which
conversation the reaction belongs to and which agent placed it, so an agent cannot react in
another chat or as a different agent. An agent's reaction is shown like anyone else's and does not
count as one of yours.

Turning off Message Reactions removes both the reaction controls and the agent tool.

## On channel bots

When a channel bot runs through Core, the agent's reaction is copied to the message it replied to
on platforms that support bot reactions, such as Telegram, Slack, Discord and WhatsApp. See
[Channel controls](/docs/gateway/channel-controls#reactions) for how this fits with the 👀
working reaction.
