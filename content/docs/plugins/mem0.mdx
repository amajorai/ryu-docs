## What it does

Mem0 reads and writes a hosted memory project (https://mem0.ai) through the Mem0 Platform REST API. The plugin exposes three declarative HTTP tools and is the second provider for the swappable `memory` layer. The built-in store remains the default and runs alongside Mem0. Selecting Mem0 routes `memory.search`, `memory.store`, `memory.sync`, and `memory.forget` to the project and enables the kernel bridges that include Mem0 in recall and mirror this node's writes to it.

Mem0 does not provide the canonical `memory.context` verb. Its API has no standing-summary endpoint, so mapping `memory.context` to a get-all operation would return raw facts where agents expect a synthesis. Both write verbs call `POST /v3/memories/add/`, which processes requests asynchronously and returns `&#123;message, status: "PENDING", event_id&#125;`, not a fact id. `memory.store` therefore returns an accepted-for-processing envelope. The kernel `mirror` and `sync` bridges send writes without waiting for that response.

The verbs differ in one field. `store` sends `infer: false` because the caller has already decided the fact and Mem0 should keep the text as-is. `sync` sends a raw turn with Mem0's default inference enabled. Mem0 expects the entity id inside `filters` for search and at the top level for add; both values come from the `mem0.user-id` preference. Requires a BYOK Mem0 API key.

## What it exposes

### Tools

### `mem0.search` - Mem0 Search

Search a hosted Mem0 project with hybrid retrieval (semantic, BM25, and entity matching) and return ranked memories. Mem0 requires the entity id inside `filters`; a top-level `user_id` is rejected with 400. Ryu reads from the bucket named by the `mem0.user-id` preference, so pass that value unless the project uses other ids. Requires `RYU_MEM0_API_KEY`.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `query` | string | yes | Natural-language search query. |
| `filters` | object | yes | Entity and metadata filters. Must include at least one entity id (`user_id`, `agent_id`, `app_id`, or `run_id`); Ryu's bucket comes from the `mem0.user-id` preference. Also supports AND / OR / NOT and the comparison operators in / gte / lte / gt / lt / ne / icontains. |
| `top_k` | integer | no | Number of memories to return (Mem0 default 10). |
| `threshold` | number | no | Minimum combined relevance score to keep (Mem0 default 0.1; pass 0.0 to disable). |
| `rerank` | boolean | no | Apply Mem0's managed reranker for better ordering (Mem0 default false; adds latency). |
| `show_expired` | boolean | no | Include memories whose expiration_date has passed (Mem0 default false). |

### `mem0.add` - Mem0 Add

Hand conversation turns to a hosted Mem0 project so it can extract and store memories. Mem0 queues the work and returns `&#123;message, status, event_id&#125;` with status `PENDING`, so this tool reports that the write was accepted and does not return the id of a stored fact. Do not pass `event_id` to `mem0.delete`; it identifies the job, not the memory. Unlike `mem0.search`, this endpoint takes the entity id at the top level (`user_id`), not inside `filters`. Requires `RYU_MEM0_API_KEY`.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `messages` | array | yes | Conversation turns for Mem0 to extract memories from. Each object must carry `role` and `content`; a message missing `role` is not a documented shape. |
| `user_id` | string | no | Entity the memory is associated with. Mem0 requires at least one entity id (`user_id`, `agent_id`, `app_id`, or `run_id`) and takes it at the top level on this endpoint. Nesting it under `filters`, as `mem0.search` requires, would be ignored and the write would be rejected for having no entity. |
| `infer` | boolean | no | Defaults to true. Mem0 extracts memories from `messages` and stores what it derives. Set false to skip inference and store the provided text as-is. |

### `mem0.delete` - Mem0 Delete

Delete one memory from the Mem0 project by its id, as returned by mem0.search. Answers `&#123;status, body&#125;` rather than the raw upstream body: Mem0 documents this as a 204, and an unwrapped 204 with an empty payload reaches the caller as a bare empty string, which reads like a failure. Requires RYU_MEM0_API_KEY.

Backend: HTTP · Method: DELETE

| Parameter | Type | Required | Description |
|---|---|---|---|
| `memory_id` | string | yes | The Mem0 memory id (a uuid) to delete. |

    - `memory.forget` -> `mem0.delete`
