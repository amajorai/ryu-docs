## What it does

Drives a Bytebot desktop (https://github.com/bytebot-ai/bytebot) through `bytebotd`, its local HTTP daemon, as the SECOND provider of the swappable `computer.control` layer - the first thing that makes that layer actually swappable rather than merely marked selectable. READ THIS BEFORE SELECTING IT: bytebotd drives the desktop IT runs on, which in the shipped Bytebot product is a containerized Linux desktop, NOT the machine running Ryu. Selecting it re-points `computer.capture` / `computer.click` / `computer.type` / `computer.key` / `computer.scroll` away from your own screen (`ghost`, the declared default) and onto that desktop - the same remote-target relationship `browser.control` already has between the local Chromium sidecar and a hosted browser. It serves FIVE of the six canonical verbs: `computer.focus_app` is deliberately NOT bound, because bytebotd's `application` action takes a closed seven-value enum (firefox, 1password, thunderbird, vscode, terminal, desktop, directory) while the canonical verb takes a free-form app name, so any other name would be a schema-legal call that 400s. The app switch is still reachable natively as `bytebot.application`, whose own schema carries that enum so an illegal call cannot be composed. Requires no API key - bytebotd ships with no authentication at all, which is also why this plugin only ever addresses it over loopback. SECURITY, read before enabling: bytebotd ships with NO authentication - no auth middleware, permissive CORS - and this plugin reaches it at the fixed loopback port 9990. Its egress grant is `tool:http-egress:127.0.0.1`, which is HOST-scoped, not port-scoped: approving it grants reach to any service on loopback, not just bytebotd. Only enable this on a machine where you accept that an unauthenticated desktop-control daemon is running and reachable. TARGET: bytebotd drives the desktop IT runs on - in the shipped Bytebot product that is a containerized Linux desktop, NOT the machine running Ryu - so selecting this instead of `ghost` does not give you another way to drive your own computer.

## What it exposes

### Tools

### `bytebot.screenshot` - Bytebot Screenshot

Capture the Bytebot desktop as a PNG. Returns `&#123;image&#125;`, base64-encoded, with no accessibility metadata - Bytebot's daemon is pixels-only, so target coordinates by looking at the image. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

_No parameters_ (empty schema).
### `bytebot.click` - Bytebot Click

Move the pointer to a coordinate on the Bytebot desktop and click. `button` and `clickCount` are required by the daemon and defaulted here to a single left click. Answers `&#123;status, body&#125;` rather than the raw upstream payload: this action returns an EMPTY body on success, and an unwrapped empty string reads like a failure. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `coordinates` | object | yes | Where to click, in screen pixels. |
| `button` | string (one of: left, right, middle) | no | Which mouse button (daemon default when omitted: left). |
| `clickCount` | integer | no | How many clicks; 2 is a double-click. Bytebot spaces repeats 150ms apart. |

### `bytebot.type_text` - Bytebot Type Text

Type literal text into whatever has keyboard focus on the Bytebot desktop. Answers `&#123;status, body&#125;` because the action returns an empty body on success. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `text` | string | yes | The text to type. |
| `delay` | integer | no | Milliseconds between keystrokes; slower typing is more reliable in apps that debounce input. |

### `bytebot.type_keys` - Bytebot Press Keys

Press keys together as one chord on the Bytebot desktop - the daemon presses every key, then releases every key. This is `type_keys`, NOT the daemon's `press_keys`: that one holds keys down or releases them as a half-action, so a chord sent through it would leave modifiers physically held. Answers `&#123;status, body&#125;` because the action returns an empty body on success. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `keys` | array | yes | Key tokens pressed together, e.g. ["ctrl", "s"] or ["escape"]. |
| `delay` | integer | no | Milliseconds to hold the chord before release. |

### `bytebot.scroll` - Bytebot Scroll

Scroll the Bytebot desktop at the pointer's current position. `scrollCount` counts MOUSE-WHEEL TICKS, not pixels, and the daemon sleeps 150ms between ticks - so it is capped low on purpose: a value meant as pixels would wedge the desktop for minutes. Answers `&#123;status, body&#125;` because the action returns an empty body on success. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `direction` | string (one of: up, down, left, right) | yes | Which way to scroll. |
| `scrollCount` | integer | no | Number of wheel ticks (daemon requires it; defaulted to 3 here). |

### `bytebot.application` - Bytebot Open Application

Focus (or launch) one of the applications preinstalled on the Bytebot desktop. The name is a CLOSED enum the daemon validates - it is not an arbitrary app name - which is exactly why the canonical `computer.focus_app` verb is not bound to this tool. `desktop` minimises everything to show the desktop. Answers `&#123;status, body&#125;` because the action returns an empty body on success. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `application` | string (one of: firefox, 1password, thunderbird, vscode, terminal, desktop, directory) | yes | Which preinstalled application to bring to the front. |

### Capabilities

- **Computer** - capability `computer.control`
  - Target: remote-desktop
  - Verbs:
    - `computer.capture` -> `bytebot.screenshot`
    - `computer.click` -> `bytebot.click`
    - `computer.type` -> `bytebot.type_text`
    - `computer.key` -> `bytebot.type_keys`
    - `computer.scroll` -> `bytebot.scroll`
