## What it does

Bytebot Desktop connects to the Bytebot desktop (https://github.com/bytebot-ai/bytebot) through `bytebotd`, its local HTTP daemon. It is the second provider for the swappable `computer.control` layer. The built-in `ghost` provider remains the default.

`bytebotd` controls the desktop where the daemon runs. In the shipped Bytebot product, that is a containerized Linux desktop, not the machine running Ryu. Selecting Bytebot routes `computer.capture`, `computer.click`, `computer.type`, `computer.key`, and `computer.scroll` to that desktop. `computer.focus_app` stays unbound because the daemon accepts only seven application names, while the canonical verb accepts a free-form app name. Use the native `bytebot.application` tool when you need one of the supported names.

Bytebot needs no API key because `bytebotd` has no authentication. The plugin reaches it at loopback port 9990. Its `tool:http-egress:127.0.0.1` grant is host-scoped, so approval permits access to every service on loopback, including services other than `bytebotd`. Enable this provider only when you accept that an unauthenticated desktop-control daemon is reachable on the machine. It controls the daemon's desktop and does not provide another way to control the computer running Ryu.

## What it exposes

### Tools

### `bytebot.screenshot` - Bytebot Screenshot

Capture the Bytebot desktop as a PNG. Returns `&#123;image&#125;`, base64-encoded, with no accessibility metadata - Bytebot's daemon is pixels-only, so target coordinates by looking at the image. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

_No parameters_ (empty schema).
### `bytebot.click` - Bytebot Click

Move the pointer to a coordinate on the Bytebot desktop and click. `button` and `clickCount` are required by the daemon and defaulted here to a single left click. Answers `&#123;status, body&#125;` rather than the raw upstream payload: this action returns an EMPTY body on success, and an unwrapped empty string reads like a failure. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `coordinates` | object | yes | Where to click, in screen pixels. |
| `button` | string (one of: left, right, middle) | no | Which mouse button (daemon default when omitted: left). |
| `clickCount` | integer | no | How many clicks; 2 is a double-click. Bytebot spaces repeats 150ms apart. |

### `bytebot.type_text` - Bytebot Type Text

Type literal text into whatever has keyboard focus on the Bytebot desktop. Answers `&#123;status, body&#125;` because the action returns an empty body on success. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `text` | string | yes | The text to type. |
| `delay` | integer | no | Milliseconds between keystrokes; slower typing is more reliable in apps that debounce input. |

### `bytebot.type_keys` - Bytebot Press Keys

Press keys together as one chord on the Bytebot desktop. The plugin uses `type_keys`, whose action presses and releases the complete chord; the daemon's `press_keys` action can leave modifiers held because it supports separate press and release operations. Answers `&#123;status, body&#125;` because the action returns an empty body on success. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `keys` | array | yes | Key tokens pressed together, e.g. ["ctrl", "s"] or ["escape"]. |
| `delay` | integer | no | Milliseconds to hold the chord before release. |

### `bytebot.scroll` - Bytebot Scroll

Scroll the Bytebot desktop at the pointer's current position. `scrollCount` counts mouse-wheel ticks, not pixels. The daemon sleeps 150 ms between ticks, so the plugin keeps the default and maximum low. Answers `&#123;status, body&#125;` because the action returns an empty body on success. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `direction` | string (one of: up, down, left, right) | yes | Which way to scroll. |
| `scrollCount` | integer | no | Number of wheel ticks (daemon requires it; defaulted to 3 here). |

### `bytebot.application` - Bytebot Open Application

Focus or launch one of the applications preinstalled on the Bytebot desktop. The daemon validates the name against a closed enum, which is why the canonical `computer.focus_app` verb is not bound to this tool. `desktop` minimizes every window to show the desktop. Answers `&#123;status, body&#125;` because the action returns an empty body on success. Requires a reachable bytebotd at 127.0.0.1:9990.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `application` | string (one of: firefox, 1password, thunderbird, vscode, terminal, desktop, directory) | yes | Which preinstalled application to bring to the front. |

### Capabilities

- **Computer** - capability `computer.control`
  - Target: remote-desktop
  - Verbs:
    - `computer.capture` -> `bytebot.screenshot`
    - `computer.click` -> `bytebot.click`
    - `computer.type` -> `bytebot.type_text`
    - `computer.key` -> `bytebot.type_keys`
    - `computer.scroll` -> `bytebot.scroll`
