## What it does

pxpipe (https://github.com/teamchong/pxpipe) is a token-saving loopback proxy. It renders bulky, static request sections, including the system prompt, tool schemas, large tool results, and older history, into PNG pages and sends them as image blocks. Vision models price those blocks by pixel area rather than character count. Dense text uses about 3.1 characters per image token instead of one per text token, so the same budget carries roughly 4.7 times more context. Recent turns and sparse content stay as text.

The plugin owns the pxpipe process lifecycle, including startup, health checks, and restarts, and mounts its dashboard behind Core authentication. It is a transparent proxy with no credential of its own. It forwards the key supplied by the caller, so point a custom provider at `http://127.0.0.1:47821` with your own API key. See the pxpipe README for provider configuration.

The plugin runs `npx -y pxpipe-proxy@0.11.1`. Node must be on `PATH`; the package is fetched on first start.
