## What it does

Token-saving loopback proxy (https://github.com/teamchong/pxpipe): it renders the bulky, static parts of a request - the system prompt, the tool-schema block, large tool results and older history - into PNG pages and sends them as image blocks, which vision models price by pixel area rather than by character. Dense text lands at roughly 3.1 characters per image-token against 1 per text-token, so the same budget carries ~4.7x more context; recent turns and sparse content stay as text. This plugin owns the process lifecycle (spawn, health, restart) and mounts pxpipe's dashboard behind Core auth. It is a TRANSPARENT proxy and holds no credential of its own: it forwards whatever key its caller sends, so point a custom provider at http://127.0.0.1:47821 with your own API key (see README). Runs `npx -y pxpipe-proxy@0.11.1`; needs Node on PATH and fetches the package on first start.
