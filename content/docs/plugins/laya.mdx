## What it does

Laya classifies a bounded text, email, ticket, or JSON state into structured choices, scores, or calibrated yes/no answers. It does not generate prose, so it suits routing, moderation, guardrails, and triage rather than autocomplete or writing help.

After you enable the plugin, Core provisions its local Python runtime and downloads three pinned checkpoints (English, multilingual, and typed decisions). The model bundle is about 2.37 GB before the runtime dependencies. Inference runs on your Ryu node.

## Use a model profile

Agents call `laya.predict` with a state and typed questions. Set `model` to choose a profile:

| Profile | Behavior |
| --- | --- |
| `router` | Chooses `english` or `multilingual` from the input. |
| `english` | Uses the English checkpoint. |
| `multilingual` | Uses the multilingual checkpoint. |
| `typed-decisions` | Uses the fine-tuned workflow checkpoint. Never selected automatically. |

`laya.status` reports whether the runtime and checkpoints are available, so an agent can check before it sends a prediction.

Requests are limited to 512 KiB, with the state capped at 256 KiB and at most 64 questions. The sidecar runs one prediction at a time. If another prediction is still running after a short wait, it returns a retryable `429 inference_busy` response instead of queueing the request.

## Decision Models layer

Laya is also a provider for Ryu's shared [Decision Models](/docs/core/decision-models) layer. In the node selector, enable Laya or [Ollaya](/docs/plugins/ollaya) and choose the provider under **Decision Models**. Agents then call the stable `decision.predict` tool, and Ryu routes it to the selected provider. `laya.predict` stays available for workflows that need Laya's provider-specific profiles.

Ollaya is a separately installed local service with a TypeSafe-compatible API at `/v1/systemone`.

## What it exposes

### Tools

### `laya.predict` - Laya Predict

Run a local Laya typed-decision pass over text, email, tickets, or JSON. Returns choice, score, or calibrated boolean answers with routing metadata. This model never writes prose. Set model to router, english, multilingual, or typed-decisions when you need a specific checkpoint.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `state` | string | yes | The text, JSON object, or list to classify. |
| `questions` | object | yes | Question id to typed-question definitions using choice, score, or noul. |
| `model` | string (one of: router, english, multilingual, typed-decisions) | no | Checkpoint selection. router chooses English or multilingual from the input; typed-decisions is explicit only. |
| `task` | string | no | Optional Laya task alias. Use typed-decisions for the fine-tuned workflow checkpoint. |
| `lang` | string | no | Optional language hint such as en or hi. |

### `laya.status` - Laya Status

Report which pinned Laya checkpoints are installed on this node and whether the local classifier is available.

Backend: HTTP · Method: GET

_No parameters_ (empty schema).

### Capabilities

- **Typed Decisions** - capability `decision.typed`
  - Verbs:

## Model and license

The packaged checkpoints come from [Convai Innovations' Laya model](https://huggingface.co/convaiinnovations/laya), licensed Apache-2.0. The plugin pins a model revision and allowlists the checkpoint files it downloads.

## Shadow computer use

Shadow offers the four Laya profiles under **Settings → Plugins → Shadow → Computer use → Local
model plugin**, as **Laya · Router**, **Laya · English**, **Laya · Multilingual**, and
**Laya · Typed decisions**. Shadow maps its current action set into Laya questions and receives
one normalized operation and target decision. Text entry still uses Shadow's configured text model.

The plugin pins the published `laya` 0.3.20 Python package. See
[Shadow Computer Use](/docs/plugins/shadow) and
[Bundle Hugging Face models in a plugin](/docs/extend/develop/extensions/local-model-plugins).

<Callout type="warn">
  Laya is a general typed-decision model, not a computer-use fine-tune. Treat its planner profiles
  as experimental. Confidence is a signal, not a guarantee of correctness. Shadow limits choices to
  its current action catalog, revalidates the target, and never submits forms automatically.
</Callout>
