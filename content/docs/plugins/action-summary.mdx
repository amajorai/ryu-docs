## What it does

Action Summary adds a first-person question and one plain-language summary for
each tool call while the agent works. It is designed for people who do not need to know whether
the agent ran Bash, read a file, searched the web, or used another tool. The
summaries appear out of band, so they do not become part of the conversation
transcript.

For a tool action, the question sits above the summary — for example, “Can I run
Bash now?” followed by “I’m running the test suite to verify the change.” This
intent shape is also carried by Core approval requests and native confirmations,
so the approval card can explain the proposed action without making the summary
itself an approval.

The plugin observes the common streamed action boundary used by ACP, local, and
gateway-backed chats. It does not change the main agent model or send tool
output to the summarizer. Likely secrets are redacted and action input is
bounded before the side model sees it.

## Permissions

**Grants:** `hook:side-model`, `preferences:read`

## Settings

- **Explain thinking and tool actions** - master toggle; enabled by default
  after the plugin is enabled.
- **Detail** - `brief`, `standard`, or `full`. Each result remains one line;
  the setting controls how much useful context it includes.
- **Summary model** - optional model override. When empty, Ryu uses its normal
  side-model/node default, like the other summary plugins.

The plugin is opt-in because each surfaced action may use one side-model call.

On mobile, installed-plugin notes from remote Core chats appear as an accented
out-of-band callout beside the assistant message, with the first-person question
above the summary. Offline on-device chats cannot call the Core side model, so
Ryu instead instructs the handset model to write one short explanation before
each native tool call and uses the same question/summary shape in its native
confirmation card. The question is explanatory; Core approval and native
confirmation remain the actual decision boundaries.
