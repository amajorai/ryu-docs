## What it does

Recap adds a short summary after long agent turns without changing the main answer. You can also ask for one at any time.

| Command | What it does |
| --- | --- |
| `/recap` | Summarizes the conversation so far. Add words after it to focus the recap. |
| `/recap off` | Mutes automatic recaps in this chat. |
| `/recap on` | Turns automatic recaps back on in this chat. |
| `/recap clear` | Clears the stored recaps for this chat and turns automatic recaps back on. |

## When a command cannot save

`/recap on`, `/recap off`, and `/recap clear` confirm the change only after storage accepts it. If saving or clearing fails, the command reports the failure and you can retry. It never confirms a change that was not saved.

If the existing recap history cannot be read or parsed, changing automatic recap settings refuses to replace it with empty history. Retry after storage recovers. Use `/recap clear` when you want to clear the history on purpose.

## Model failure and retry

If the configured recap model is unavailable or rejects the request, `/recap` reports that it could not generate a recap. It does not forward the command to the main agent or change the stored recap history. Check the model in **Settings → Recap**, then run `/recap` again to retry.

An empty model response also gives a retry message. Automatic per-turn recaps keep their existing behavior.
