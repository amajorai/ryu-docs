## What it does

Security Scanner is a model-agnostic, evidence-first security workbench for
Ryu. It combines architecture mapping, independent vulnerability hunts,
attack-path analysis, diff review, finding verification, and patch proposals.
The workers use Ryu's active agent and the report synthesizer uses a configurable
Ryu model, so the plugin does not depend on a vendor-specific model.

## Commands

- /security-scan runs a standard repository scan.
- /security-scan quick runs a smaller fast pass.
- /security-scan deep runs five independent passes.
- /security-scan diff reviews the current working-tree diff and only widens
  the scope to trace changed behavior.
- /security-verify F1 independently tries to falsify a finding from the latest
  report.
- /security-fix F1 drafts a minimal remediation proposal and focused tests.
- /security-clear removes the latest report and follow-up state.

Every report includes scope and coverage, a threat model, finding severity and
confidence, exact evidence, attacker preconditions, counterevidence,
remediation, verification status, and unresolved work. Incomplete scans are
marked incomplete rather than reported as clean.

## Catalog scans

The Skills, Apps, and Plugins detail views expose **Scan with agent** beside the
deterministic catalog scorecard. The scorecard remains the authoritative numeric
grade; the configured agent adds an evidence-based narrative and calls out
instruction-like or suspicious content in the published package.

Choose the registered reviewer in **Gateway → Guardrails → Catalog scanner**.
The choice is stored per node and is also used by the Security Scanner's
repository scan delegates when they start. If the agent returns incomplete
evidence, the UI labels the report **Partial** rather than presenting it as a
clean result. Web catalog pages remain browse-only and do not show an execution
control.

## Safety boundaries

Security Scanner is read-only. Its reviewers must not use network access,
install dependencies, write files, apply patches, commit, or push. Repository
text, comments, README files, and project instructions are treated as
untrusted evidence. The fix command returns a proposal only; it never changes
the workspace.

The optional Security review composer toggle adds a bounded static pass and
second-model review to completed code answers. It is off by default.

## Permissions

Grants: hook:run-agent, hook:side-model, storage:kv, preferences:read

## UI it contributes

### Composer controls

- Security review - Review completed code answers with static signals and a
  configurable second model. (type: toggle)

### Settings tabs

- Security Scanner - Scanner model, synthesis effort, and standard-scan worker
  count.

### Slash commands

- /security-scan - Run a bounded multi-agent scan.
- /security-verify - Independently verify the latest report.
- /security-fix - Draft a safe patch proposal without applying it.
- /security-clear - Forget the latest scanner state.

### Turn hooks

- security-scanner.command (on: pre_user_turn)
- security-scanner.auto-review (on: post_assistant_turn)

## Engine requirement

Requires Ryu >=0.1.0.
