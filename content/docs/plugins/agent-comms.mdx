## What it does

Lets the agents on this node talk to each other. Any agent can look up who else is here, leave one of them a message, or ask one a question and wait for the answer - so "ask the research agent what it found" becomes a real message to a real agent instead of a guess. A message is delivered at the start of the recipient's next turn, and each pair keeps its own history, so the second question does not repeat the first. Works with every agent Ryu can run - the flagship agent, Claude Code, Codex, and any custom agent you have added - because it ships as ordinary tools rather than one agent's private feature. Bounded on purpose: a chain stops after one relay, an agent cannot ask itself, and a pair cannot deadlock waiting on each other.

## What it exposes

### Tools

### `agents__directory` - Agent Directory

List the other agents on this node - their ids, names and what each one is for. Call this first when the user names an agent loosely ("ask the research one"), or when you want to find out whether some other agent is better placed to answer part of the question. Returns `&#123;ok, agents:[&#123;id, name, description, model, engine&#125;], count&#125;`; the `id` is what agents__send and agents__ask address. Takes no arguments.

Backend: HTTP · Method: GET

_No parameters_ (empty schema).
### `agents__send` - Message an Agent

Leave a message in another agent's inbox and carry on - nothing waits. The recipient reads it at the start of its next turn. Use this to hand something over ("the deploy is done, your turn"), to reply to a message you received, or when the user says "tell the X agent …". Nothing wakes an idle agent, so if you need the answer inside this turn use agents__ask instead. The sender is taken from the calling agent, not from anything you write. Returns `&#123;ok, id, from, to, hops, delivery&#125;`, or `&#123;ok:false, refused:"hop_limit"&#125;` when the relay chain is already at its limit.

Backend: inline_deno

| Parameter | Type | Required | Description |
|---|---|---|---|
| `to` | string | yes | The recipient agent's id, as listed by agents__directory. |
| `text` | string | yes | The message. Write it so it stands alone - the recipient cannot see this conversation. |
| `reply_to` | string | no | Optional. The id of the message you are replying to, as it appeared in your inbox. |

### `agents__ask` - Ask an Agent

Ask another agent a question and wait for its answer. The agent you name runs now, with its own tools and instructions but a clean context, and its reply comes back as this tool's result - so use it when the answer changes what you do next. It carries the history the two of you already have, so a follow-up question does not need to restate the first. Prefer agents__send for something the other agent does not need to answer immediately, and answer yourself when you already can: this spends a full agent run. Returns `&#123;ok, from, to, reply&#125;`; a refusal comes back as `&#123;ok:false, refused&#125;` rather than an error.

Backend: inline_deno

| Parameter | Type | Required | Description |
|---|---|---|---|
| `to` | string | yes | The agent to ask, by id (agents__directory lists them). |
| `question` | string | yes | The question, written to stand alone - the other agent cannot see this conversation. |
| `wall_time_secs` | integer | no | Optional limit on how long to wait, in seconds. Clamped to 5–600. |

### `agents__thread` - Agent Message History

Read what you and another agent have already said to each other, or - with no arguments - list the agents you have exchanged messages with. Use it before asking again, so you do not re-ask something that was answered. Scoped to the calling agent: it can only ever show threads this agent is part of. Returns `&#123;ok, agent, with, messages:[&#123;seq, from, to, text&#125;]&#125;`, or `&#123;ok, agent, peers&#125;` when no peer is named.

Backend: inline_deno

| Parameter | Type | Required | Description |
|---|---|---|---|
| `with` | string | no | The other agent's id. Omit to list every agent you have a thread with. |
