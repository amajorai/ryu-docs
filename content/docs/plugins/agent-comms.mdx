## What it does

Lets the agents on this node talk to each other. Any agent can look up who else is here or leave one of them a message. A message is delivered at the start of the recipient's next turn, and each pair keeps its own history. Works with every agent Ryu can run - the flagship agent, Claude Code, Codex, and any custom agent you have added - because it ships as ordinary tools rather than one agent's private feature. Bounded on purpose: a chain stops after one relay, and an agent cannot message itself. This plugin only queues mail; it cannot start another agent run or wait on another model.

## What it exposes

### Tools

### `agents.directory` - Agent Directory

List the other agents on this node - their ids, names and what each one is for. Call this first when the user names an agent loosely ("the research one"), or when you want to find out whether some other agent is better placed to answer part of the question. Returns `&#123;ok, agents:[&#123;id, name, description, model, engine&#125;], count&#125;`; the `id` is what agents.send addresses. Takes no arguments.

Backend: HTTP · Method: GET

_No parameters_ (empty schema).
### `agents.send` - Message an Agent

Leave a message in another agent's inbox and carry on - nothing waits. The recipient reads it at the start of its next turn. Use this to hand something over ("the deploy is done, your turn"), to reply to a message you received, or when the user says "tell the X agent …". Nothing wakes an idle agent, and this tool cannot start another agent run. The sender is taken from the calling agent, not from anything you write. Returns `&#123;ok, id, from, to, hops, delivery&#125;`, or `&#123;ok:false, refused:"hop_limit"&#125;` when the relay chain is already at its limit.

Backend: inline_deno

| Parameter | Type | Required | Description |
|---|---|---|---|
| `to` | string | yes | The recipient agent's id, as listed by agents.directory. |
| `text` | string | yes | The message. Write it so it stands alone - the recipient cannot see this conversation. |
| `reply_to` | string | no | Optional. The id of the message you are replying to, as it appeared in your inbox. |

### `agents.thread` - Agent Message History

Read what you and another agent have already said to each other, or - with no arguments - list the agents you have exchanged messages with. Use it before asking again, so you do not re-ask something that was answered. Scoped to the calling agent: it can only ever show threads this agent is part of. Returns `&#123;ok, agent, with, messages:[&#123;seq, from, to, text&#125;]&#125;`, or `&#123;ok, agent, peers&#125;` when no peer is named.

Backend: inline_deno

| Parameter | Type | Required | Description |
|---|---|---|---|
| `with` | string | no | The other agent's id. Omit to list every agent you have a thread with. |

## UI it contributes

### Turn hooks

- **agent-comms.deliver** (on: `pre_user_turn`)
- **agent-comms.directory** (on: `tool_result`)

### Desktop transcript activity

On desktop, `agents.send` is shown as a transcript activity instead of a
generic tool row. The marker names the sending agent, uses ghost-style agent
chips for the sender and recipient, and says who the message was sent to. The
message itself appears below it in a left-aligned bubble with the sender's
avatar, name, recipient, and full message text.

`agents.send` uses the same activity surface. The queued message remains visible
as the sender's message, so an agent-to-agent handover remains visible when the
conversation is reopened in a workspace tab.

### Bot-mode threads and group chats

Desktop Bot mode treats each direct conversation with a bot as a thread. Bot mode is built
into the desktop/Core experience; this plugin adds the agent-to-agent messaging that appears
inside it, rather than owning the sidebar mode itself. Use
the disclosure on a bot row to show its threads; the list uses the sidebar's
normal page-size setting, “Show more/less”, and searchable overflow view. A
message's **Fork** action creates a new conversation from that point. The new
conversation is marked as a branch and appears under the same bot as soon as it
is created.

Conversations with more than one participant converge into a **Group chat** in
the Sessions/Chats sidebar. The group header shows the participants as a small
orbit of avatars, and expanding it reveals the group's conversation threads.
Team-routed turns already carry this participant metadata, so an explicit team
mention naturally opens as a group chat rather than being presented as one bot.
