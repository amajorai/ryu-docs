## What it does

ChatGPT Web exposes a signed-in ChatGPT Web session in Ryu's Browser app as an OpenAI-compatible model provider. Each completion uses a Temporary Chat, selects the requested reasoning profile through the page's accessibility tree, and returns the visible text answer through Ryu's normal model routing.

This is a Ryu plugin. It does not modify the Codex desktop app, read browser cookies, extract a ChatGPT API token, or call ChatGPT's private backend API.

## Enable it

1. Install and enable the **Browser** app.
2. Sign in to [ChatGPT Web](https://chatgpt.com) in the Ryu Browser.
3. Enable Ryu's experimental plugin runtime (`ryu:experimental-plugin-runtime=true`).
4. Have an operator explicitly allow the `sidecar:process` grant in the Gateway policy. Ryu denies this grant for community plugins by default because managed Node sidecars are unsandboxed in this build; preserve existing allowlist entries when adding the plugin's declared grants.
5. Install and enable **ChatGPT Web**.
6. Select the provider in Ryu's model/provider settings.

## Models

The provider advertises:

- `chatgpt-web/instant`
- `chatgpt-web/medium`
- `chatgpt-web/high`
- `chatgpt-web/extra-high`
- `chatgpt-web/pro`

The plugin settings tab can narrow the list with a comma-separated list of profile ids.
Unsupported and duplicate entries are ignored, and changes apply on the next request.

## Capability and permissions

- Requires the Browser app's `browser.session` capability, so it keeps working even
  when another provider is selected for the general `browser.control` layer.
- Uses the `browser:control` grant to open, snapshot, click, and type in the signed-in browser.
- Uses `preferences:read` for the configurable model list.
- Uses the explicitly approved `sidecar:process` grant to run its managed Node bridge.
- Uses Temporary Chat for each completion.

## Current limits

The first version is text-only and supports normal conversations plus one-shot SSE responses. It does not support image inputs, tool calls, file uploads, or the upstream project's full MCP/browser harness. Because it drives a web UI, ChatGPT Web accessibility-label changes can require an adapter update; model and readiness failures are surfaced explicitly.

The implementation was inspired by [codex-chatgpt-web](https://github.com/miuuyy/codex-chatgpt-web), but runs within Ryu's plugin, managed-sidecar, capability-broker, and Browser-app boundaries.

## Engine requirement

Requires Ryu `>=0.1.0`.
