## What it does

Rules gives every agent its own Ryu-managed directives and discovers the rule files already present in the active project. The plugin applies the resulting context before the model answers without copying hidden rule blocks into visible chat history.

Rules is enabled by default. Disable the plugin to remove its automatic context injection without deleting your saved agent rules or project files.

## Supported project rules

Ryu detects and labels these formats:

- `AGENTS.md` files at the project root and in nested folders
- `CLAUDE.md`, `CLAUDE.local.md`, and `.claude/CLAUDE.md`
- `.cursor/rules/**/*.mdc`, including Cursor's `alwaysApply`, `globs`, and `description` frontmatter
- `.claude/rules/**/*.md`, including Claude's `paths` frontmatter

Cursor and Claude rule files stay in their original folders. Ryu reads them live and lists their source, path, and apply mode in the agent editor. See the [Cursor rules reference](https://cursor.com/docs/rules) and [Claude Code rules reference](https://code.claude.com/docs/en/memory#organize-rules-with-claude/rules/) for the native formats.

## Configure an agent

Open an agent and find the plugin-contributed **Rules** section. You can:

- add, edit, disable, or remove rules stored for that agent in Ryu;
- enable or disable rule processing for the agent;
- turn automatic context injection on or off;
- choose **Auto**, **Always**, or **Manual** application;
- limit injection to the first number of turns in each plan, or use `0` for every turn;
- review the project rules Ryu detected and the mode inferred from their metadata.

**Auto** preserves each source's native behavior: always-on files are injected, path-scoped files wait for matching file context, described Cursor rules are selected when relevant, and manual rules are only listed. **Always** injects every enabled rule. **Manual** stops automatic project-rule injection while keeping the saved configuration available.

Agent rules are stored on the Ryu node, not folded into the agent's system prompt. Existing rules created by older versions are migrated from the legacy prompt block when the agent is next saved.

## Context and turn limits

**Auto-injected context** is on by default. A positive **turns per plan** value sends the rule block only for the first N turns of each conversation; `0` keeps it available on every turn. Turn counts are isolated by conversation, so starting a new plan starts a fresh budget.

Project rules are instructions, not an enforcement boundary. Use approvals, tool policy, or Gateway controls when an action must be blocked regardless of model behavior.
