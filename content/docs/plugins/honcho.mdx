## What it does

Honcho (https://honcho.dev) gives the swappable `memory` layer a provider that maintains a representation of the user. It watches the messages you send and derives a representation for each peer. Its Dialectic endpoint, `POST /v3/workspaces/&#123;workspace_id&#125;/peers/&#123;peer_id&#125;/chat`, answers natural-language questions about a peer with Honcho's synthesis. This implements the canonical `memory.context` contract and lets the kernel's `context` bridge (`memory.provider-context`) use a provider for that verb.

The plugin serves two verbs: `memory.context` and `memory.search`. Search calls `POST .../peers/&#123;peer_id&#125;/search` and returns conversation text, not the conclusions Honcho derives from it. The `prefetch` bridge is enabled by default, so those message excerpts can be injected into each turn. The plugin also binds `memory.sync` and `memory.store` through an adapter.

Honcho's documented write endpoint is `POST /v3/workspaces/&#123;workspace_id&#125;/sessions/&#123;session_id&#125;/messages`. Each `messages[]` item requires a nested `peer_id`, which a declarative `arg_template` cannot reach because it substitutes only caller arguments and cannot read a resolved `pref:` value. The adapter receives resolved preferences and places the per-install peer inside `messages[]`. The session and both peers use caller-provided ids and are created on the first write. Ryu writes its own replies as a separate peer so they do not affect the representation derived about the user.

`memory.forget` stays unbound because Honcho documents no message-delete endpoint. The built-in `memorystore.save` tool and this node's per-turn memory write remain kernel features. Every call uses one workspace and one peer from the settings tab; using a hardcoded pair would put every installation in one shared bucket. Requires a BYOK Honcho API key.

## What it exposes

### Tools

### `honcho.chat` - Honcho Dialectic

Ask Honcho's Dialectic endpoint a natural-language question about one peer and return the synthesis it derives from that peer's messages and conclusions. The result is `&#123;"content": "…"&#125;`, not a list of stored rows. `reasoning_level` defaults to `minimal` because the kernel context bridge abandons a provider after four seconds; raise it in the Honcho settings tab when calling this tool directly. Streaming is not exposed because the endpoint returns `text/event-stream` when `stream` is true, which is not a JSON tool result. Requires `RYU_HONCHO_API_KEY`.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `workspace_id` | string | yes | The Honcho workspace to query. Filled automatically from the Honcho settings tab when this runs as the `memory` layer; pass your workspace id from https://app.honcho.dev if you call this tool directly. |
| `peer_id` | string | yes | The peer whose representation to query. Filled automatically from the Honcho settings tab when this runs as the `memory` layer. |
| `query` | string | yes | The natural-language question to put to the peer's representation. |
| `session_id` | string | no | Optional session id to scope the representation to one conversation. |
| `target` | string | no | Optional other peer to get the representation FOR, from this peer's perspective. |
| `reasoning_level` | string (one of: minimal, low, medium, high, max) | no | How much reasoning Honcho applies before answering. More reasoning is slower; Honcho's own default is `low`. |

### `honcho.search` - Honcho Search

Search one peer's messages in a Honcho workspace and return the matches. This searches conversation text handed to Honcho, not the conclusions it derives from that text; use `honcho.chat` for the derived view. Answers a bare JSON array of messages. Requires `RYU_HONCHO_API_KEY`.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `workspace_id` | string | yes | The Honcho workspace to search. Filled automatically from the Honcho settings tab when this runs as the `memory` layer. |
| `peer_id` | string | yes | The peer whose messages to search. Filled automatically from the Honcho settings tab when this runs as the `memory` layer. |
| `query` | string | yes | Search query. |
| `limit` | integer | no | Number of messages to return (Honcho default 10). |

### `honcho.messages` - Honcho Add Messages

Add messages to a Honcho session. Honcho derives each peer's representation from the messages you send, so this is the write path for the memory layer. Answers a 201 array of the created messages. The session and every named peer must exist first; see `honcho.session_upsert` and `honcho.peer_upsert`. Requires `RYU_HONCHO_API_KEY`.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `workspace_id` | string | yes | The Honcho workspace to write to. Filled automatically from the Honcho settings tab when this runs as the `memory` layer. |
| `session_id` | string | yes | The session to append to. Filled automatically when this runs as the `memory` layer. |
| `messages` | array | yes | The messages to add. Each item needs a `content` and the `peer_id` that produced it. |

### `honcho.session_upsert` - Honcho Get or Create Session

Get a Honcho session by id, or create it if it does not exist. The caller chooses the id, which lets the node use a stable session without requiring the user to create one first. Requires `RYU_HONCHO_API_KEY`.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `workspace_id` | string | yes | The Honcho workspace the session belongs to. |
| `id` | string | yes | The session id to get or create. |

### `honcho.peer_upsert` - Honcho Get or Create Peer

Get a Honcho peer by id, or create it if it does not exist. Ryu writes the user's turns as one peer and its own replies as another, so a turn never depends on a peer being set up by hand. Requires `RYU_HONCHO_API_KEY`.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `workspace_id` | string | yes | The Honcho workspace the peer belongs to. |
| `id` | string | yes | The peer id to get or create. Honcho allows letters, digits, underscore and hyphen. |

### Capabilities

- **Memory** - capability `memory`
  - Verbs:
    - `memory.context` -> `honcho.chat`
    - `memory.search` -> `honcho.search`
    - `memory.sync` -> `honcho.messages`
    - `memory.store` -> `honcho.messages`
