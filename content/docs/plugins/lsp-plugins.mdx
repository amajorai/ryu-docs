The official Ryu Marketplace publishes **twelve language plugins**, one per language, mirroring Anthropic's official
Claude Code code-intelligence plugins field-for-field — the same config body loads in either host.
They are **config-only** and **opt-in**: enabling a plugin writes its server into the managed agent's
config on the next spawn. You install the language-server binary; the plugin ships config.

In the public marketplace mirror, these entries are grouped under `plugins/lsp/<name>/` so they are
separate from ordinary declarative plugins under `plugins/plugins/<name>/` and hosted providers under
`plugins/external_plugins/<name>/`.

| Plugin | Language | Server binary | Install (example) |
|---|---|---|---|
| `@ryu/clangd-lsp` | C/C++ | `clangd` | `brew install llvm` |
| `@ryu/csharp-lsp` | C# | `csharp-ls` | `dotnet tool install --global csharp-ls` |
| `@ryu/gopls-lsp` | Go | `gopls` | `brew install gopls` |
| `@ryu/jdtls-lsp` | Java | `jdtls` | Eclipse JDT LS distribution |
| `@ryu/kotlin-lsp` | Kotlin | `kotlin-lsp` | `brew install kotlin-language-server` |
| `@ryu/lua-lsp` | Lua | `lua-language-server` | `brew install lua-language-server` |
| `@ryu/php-lsp` | PHP | `intelephense` | `npm install -g intelephense` |
| `@ryu/pyright-lsp` | Python | `pyright-langserver` | `npm install -g pyright` |
| `@ryu/ruby-lsp` | Ruby | `ruby-lsp` | `gem install ruby-lsp` |
| `@ryu/rust-analyzer-lsp` | Rust | `rust-analyzer` | `rustup component add rust-analyzer` |
| `@ryu/swift-lsp` | Swift | `sourcekit-lsp` | Ships with the Swift toolchain |
| `@ryu/typescript-lsp` | TypeScript/JavaScript | `typescript-language-server` | `npm install -g typescript-language-server typescript` |

## How they work

Install the binary, then enable the plugin for a language you actually use. On the next agent spawn
the server is registered for that language's file extensions. The agent then gets:

- **Diagnostics after every edit** — errors first, capped at 20 with a trailing count.
- **Eight navigation tools** — `lsp_definition`, `lsp_references`, `lsp_hover`, `lsp_symbols`,
  `lsp_symbol_search`, `lsp_implementations`, `lsp_call_hierarchy`, `lsp_diagnostics`.

A server binary that is missing from `PATH` is a **graceful skip with a visible reason**, never a hard
failure. Two plugins pin a longer 120s `startupTimeout` because their servers are slow to handshake:
`@ryu/jdtls-lsp` and `@ryu/kotlin-lsp`.

## Caveats

- The plugins share one extension namespace, so **first registration wins** across them too — if two
  enabled plugins claim the same extension, the first one sorted owns it.
- Language servers are wired for the flagship **`ryu`** agent only. Other ACP agents are not wired yet
  (an agent with its own LSP support, like Claude Code, keeps using it and ignores this contribution).
- `@ryu/clangd-lsp` deliberately omits the uppercase `.C`/`.H` entries: Ryu lowercases file
  extensions, so `.C` would collide with `.c`.
