## What it does

Parallel adds web search and page extraction from [Parallel](https://parallel.ai). It ships three HTTP tools and one capability adapter, and it provides the swappable `web.search` and `web.extract` layers. Select Parallel in the layer picker and the stable `web.search` and `web.extract` tools route to it, so agents keep calling the same tools.

Search works without a key through [Parallel's public Search MCP endpoint](https://docs.parallel.ai/integrations/mcp/search-mcp), which is rate-limited. Add your own Parallel API key in the **Parallel Search** settings tab to use the higher-limit REST search and to enable extraction. `parallel.extract` requires the key.

## What it exposes

### Tools

### `parallel.search` - Parallel Search

Web search that takes a natural-language objective plus 2-3 keyword queries and returns ranked URLs with long, LLM-ready markdown excerpts. There is no result-count parameter: size the response with max_chars_total instead. Requires RYU_PARALLEL_API_KEY.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `objective` | string | no | Natural-language description of the question driving the search. Should be self-contained and atomic - one specific piece of information. |
| `search_queries` | array | yes | Concise keyword search queries, 3-6 words each. At least one is required; 2-3 give the best results. |
| `mode` | string (one of: turbo, fast, basic, advanced) | no | Search preset. turbo is the fastest, fast is the recommended sub-second mode, basic returns longer excerpts, and advanced does more retrieval and compression (Parallel's own default when omitted). |
| `max_chars_total` | integer | no | Upper bound on total characters across the excerpts of all results. |

### `parallel.free_search` - Parallel Search (no key)

Web search through Parallel's PUBLIC Search MCP endpoint, which needs no API key. Rate-limited free tier, intended as the zero-setup path when RYU_PARALLEL_API_KEY is unset; add a key to use the higher-limit parallel.search instead. Speaks JSON-RPC: the caller supplies the whole `tools/call` envelope, and the reply is a plain JSON-RPC response whose result payload is a JSON string, so the capability adapter parses it rather than a response map.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `jsonrpc` | string | yes | JSON-RPC version, always "2.0". |
| `id` | integer | yes | JSON-RPC request id. |
| `method` | string | yes | JSON-RPC method, always "tools/call". |
| `params` | object | yes | `{name, arguments}` naming the Parallel MCP tool to call (web_search or web_fetch) and its arguments. |

### `parallel.extract` - Parallel Extract

Fetch up to 20 URLs and return their readable content as markdown. Parallel returns objective-focused excerpts by default; this tool asks for full page content instead, so a caller that wanted the whole page gets it. Requires RYU_PARALLEL_API_KEY.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `urls` | array | yes | URLs to extract content from. Up to 20 per request. |
| `objective` | string | no | Natural-language description of what to look for in these URLs, used to focus the excerpts. |
| `search_queries` | array | no | Keyword queries (3-6 words each) used with the objective to focus excerpts. Pass the queries from the search that surfaced these URLs. |
| `max_chars_total` | integer | no | Upper bound on total characters across all extracted results. |
