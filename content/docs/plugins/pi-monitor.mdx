## What it does

Adds the monitor tool to the managed Pi agent, so it can watch a command or WebSocket in the background and react when events arrive.

## The tool

The `monitor` tool holds the turn open until the watch ends, so it is always bounded: pass a command
that exits on its own (a build, a bounded `timeout N tail -f …`), or a `timeout_ms` cap.

| Parameter | Type | Meaning |
|---|---|---|
| `command` | string | Shell command to run (in `cwd`, defaulting to the session directory). |
| `ws.url` | string | `ws://`/`wss://` endpoint instead; each incoming message becomes one line. A `ws.url` must be ASCII, must not embed credentials, and a literal `169.254.0.0/16` (link-local / cloud-metadata) target is refused. |
| `ws.protocols` | string[] | WebSocket subprotocols to offer during the handshake. |
| `until` | string | A regular expression. The watch ends the moment a line matches and reports which one — stop on an error, a successful build, etc. |
| `timeout_ms` | integer | Lifetime cap. Default 5 minutes, clamped to `[1000, 1800000]`. |
| `description` | string | Short human-readable label for the watch. |

Pass exactly one source — `command` **or** `ws.url`, never both. A command watch is torn down with
SIGTERM then SIGKILL after a 5 s grace period. A WebSocket message larger than 1 MiB ends the watch.
