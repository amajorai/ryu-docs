This page lists real examples of products and workflows built on Ryu. To pick an integration path
for your own product, see [Integrate with Ryu](/docs/extend/integrate). For what each Ryu product
name means, see [Ryu Products, Services, and Infra](/docs/start-here/architecture/three-products).

## Examples

One example is an outside product. The others are Ryu-built surfaces that use the same contracts.

### Update Night

[Update Night](https://github.com/amajorai/updatenight) is an external product. Its AI generation
path uses [`@ryuhq/client`](/docs/extend/develop/sdk/client) to send text-generation work to Ryu
Core. The product keeps its own UI and flow, and Ryu supplies the runtime.

### Ryu Apps

The [Ryu Apps catalog](/docs/apps) holds focused applications, such as browser work, meetings,
documents, sites, and CRM. Each App owns its workflow and surface. Core and the Gateway keep the
shared runtime, permissions, and budgets. To build one, see
[Ryu Apps](/docs/extend/develop/extensions/ryu-apps).

### Local AI in the tab

The [browser extension](/docs/browser-extension) can run a small model inside the browser or
connect to a Ryu server that the user chooses. See
[Local models](/docs/browser-extension/local-models) for the boundaries.

### Ryu in GitHub

The [GitHub Action](/docs/ci/github-actions) runs saved agents and allowlisted tools as steps in a
CI workflow, against a managed or self-hosted Core server.
