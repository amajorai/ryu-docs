Ryu is one interface across the AI stack. You can use a ready-made App, build a new one, embed
agent chat in an existing product, route model traffic through the Gateway, or run the whole server
yourself. The integration point changes; the primitives and governance do not.

## Choose the seam

| You want to… | Start with… | The short version |
|---|---|---|
| Add AI to an existing product | [`@ryuhq/client`](/docs/extend/develop/sdk/client) or the [Core HTTP API](/docs/extend/develop/api-reference) | Embed a Ryu conversation or call a server from your own backend. |
| Author a typed extension | [Ryu SDK](/docs/extend/develop/sdk) | Define agents, workflows, tools, and skills as Runnables. |
| Route any model client | [Gateway endpoints](/docs/extend/integrate/openai-compat) | Use OpenAI, Anthropic, or Gemini-compatible APIs with one control layer. |
| Connect tools | [MCP integration](/docs/extend/integrate/mcp-integration) | Expose Ryu to an MCP host or bring external MCP servers into Ryu. |
| Drive another agent runtime | [ACP integration](/docs/extend/integrate/acp-integration) | Run agent subprocesses with a Core-owned event and tool loop. |
| Connect remote agents | [A2A integration](/docs/extend/integrate/a2a) | Exchange tasks with trusted remote A2A peers. |
| Ship a complete application | [Ryu Apps](/docs/extend/develop/extensions/ryu-apps) | Package a sidecar, surface, permissions, and shared platform seams. |
| Add a widget or companion | [Inline widgets](/docs/extend/develop/extensions/inline-widget) or [standalone apps](/docs/extend/develop/extensions/standalone-apps) | Put a sandboxed iframe widget in chat or ship a separate surface from a starter project. |
| Run AI in CI | [GitHub Actions](/docs/ci/github-actions) | Run saved agents and allowlisted tools from a workflow. |
| Let users run AI locally | [Browser extension](/docs/browser-extension) or [Mobile](/docs/mobile) | Run a model in the browser or on-device, or connect to a server the user controls. |
| Use managed or provider-backed access | [Gateway for any agent](/docs/gateway/gateway-for-any-agent) | Use Ryu's managed path, a provider subscription, BYOK, or self-hosting. |

## Product hierarchy

Ryu is the platform. Each entry point has one job:

- **SDK — Integrate.** Developers use the Ryu SDK to add AI capabilities to existing products.
- **Core — Run.** Engineering teams use Ryu Core to run AI applications on infrastructure they control.
- **Build — Create.** Product teams use Ryu Build to create AI applications visually.
- **Gateway — Control.** Engineering teams use Ryu Gateway to control model access, spending and providers.
- **Bot — Automate.** Operations teams use Ryu Bot to run defined business workflows automatically.
- **Apps — Use.** Business teams use Ryu Apps to deploy ready-made software for specific workflows.

The shorthand is **SDK: Integrate · Core: Run · Build: Create · Gateway: Control · Bot: Automate ·
Apps: Use**.

## What makes Ryu Ryu

The same platform composes these primitives instead of scattering them across separate SDKs and
services:

`Models` · `Agents` · `Tools` · `Memory` · `RAG` · `Workflows` · `Policies` · `Servers` · `Surfaces` · `Apps`

Core owns execution and context. The Gateway owns the governed path around model and tool calls:
permissions, firewall and DLP, budgets, approvals, routing, and audit. A client can enter through
an HTTP endpoint, SDK, MCP, ACP, A2A, browser, mobile app, or GitHub workflow and still reach the
same platform boundaries.

## Built with Ryu

The gallery is deliberately split between Ryu-built surfaces and outside products using the same
contracts. That makes the boundary clear: Ryu is useful as the product, underneath a product, or as
the bridge between products.

### Update Night

[Update Night](https://github.com/amajorai/updatenight) is an external product integration. Its AI
generation path uses [`@ryuhq/client`](/docs/extend/develop/sdk/client) to send text-generation work
to Ryu Core, so the application can keep its own UI and product flow while Ryu supplies the governed
runtime.

### Ryu Apps

The [Ryu Apps catalog](/docs/apps) includes focused applications for browser work, meetings,
documents, fine-tuning, workflows, sites, dashboards, CRM, media, and more. Each App owns its
workflow and surface while Core and Gateway keep the shared runtime, permissions, budgets,
approvals, and audit boundaries in place.

### Local AI in the tab

The [browser extension](/docs/browser-extension) demonstrates the surface range: a small model can
run inside the browser, a website can expose an explicit **My local server** path, and normal turns can
connect to Core or Cloud. The user chooses the boundary; the browser does not silently move a token
or a conversation between them.

### Ryu in GitHub

The [GitHub Action](/docs/ci/github-actions) brings agents and allowlisted tools into CI. A workflow
can target a managed or self-hosted Core server, run a saved agent, persist a result when intentional,
or invoke one direct tool while keeping the server token masked.
