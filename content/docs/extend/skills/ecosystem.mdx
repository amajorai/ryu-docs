A skill interacts with the tool system, the Gateway, and the agent's context. The `SKILL.md`
format is on [Skills](/docs/extend/skills).

## How skills interact with tools

A skill declares the tools it needs in the `allowed-tools` front-matter.

```yaml
---
name: "Web Researcher"
allowed-tools:
  - "agentbrowser"
  - "spider"
---
```

When the skill is active, Core surfaces those tools to the MCP bridge for the turn. The Gateway
enforces the grant. A declared tool that the caller is not granted stays uncallable.

```mermaid
flowchart LR
  S[Skill activated] -->|"allowed-tools"| BRIDGE[MCP Bridge]
  BRIDGE -->|"tool definitions"| AGENT[Agent]
  AGENT -->|"tool_search + execute"| REG[Tool Registry]
  REG -->|"allowlist check"| GW[Gateway]
  GW -->|"approved"| TOOL[Tool execution]
```

## Progressive disclosure mechanics

Progressive disclosure injects only skill metadata up front and loads full bodies on demand.

### The flow

1. **Selection phase:** Only each skill's `name` and `description` are injected into the system
   prompt. The model sees a list of available skills.

2. **Decision phase:** The model decides which skill is relevant to the current turn.

3. **Loading phase:** The model calls `skills.load` with the skill id. Core loads the full
   `SKILL.md` body and injects it into the context.

4. **Execution phase:** The model follows the skill's instructions, using the tools it declared.

### Always-on skills

Set `always-on: true` in the front-matter to inject the full body up front.

```yaml
---
name: "Security Checker"
always-on: true
---
You MUST check every outbound request for PII before sending.
```

Use this for critical skills or models that cannot reliably self-load skills.

## Skill injection into requests

When a skill is active, Core injects it into the outgoing request body.

```mermaid
flowchart TD
  REQ[Outgoing request] --> INJ["Skill injection<br/>(inside route_openai_stream)"]
  INJ -->|"system message prepended"| BODY[Final request body]
```

The injection happens **after** context trimming. The context window manager reserves 512 tokens
(`SKILLS_RESERVE`) for it. The Gateway counts skill-tagged calls toward budget and audit
through the `x-ryu-skill-ids` header.

## Skill-tool interaction patterns

### Pattern 1: Skill declares tools, agent uses them

```yaml
---
name: "Code Reviewer"
allowed-tools:
  - "file_read"
  - "git_diff"
---
Review the code changes in the current branch. Use git_diff to see
the changes, then file_read to inspect specific files.
```

The agent loads the skill, sees the declared tools, and uses them in sequence.

### Pattern 2: Skill provides decision logic, agent picks tools

```yaml
---
name: "Data Analyst"
description: "Decides which analysis tools to use based on data type"
---
Analyze the user's data. Choose the right tool:
- CSV data → use csv_parser
- JSON data → use json_analyzer
- Database → use sql_runner
```

The skill does not declare `allowed-tools`. The agent discovers tools through `tool_search` and
picks one based on the skill's instructions.

### Pattern 3: Skill + turn hook

A skill provides the instructions, and a turn hook provides the automation.

```json
{
  "contributes": {
    "turn_hooks": [{
      "id": "auto-review",
      "on": "post_assistant_turn",
      "code_file": "hooks/auto-review.js"
    }]
  }
}
```

The hook body in `hooks/auto-review.js` runs after the assistant turn. In this example it checks
whether code was modified and injects a review follow-up when the "Code Reviewer" skill is active.

## Reviewing hooks in Gateway

The Desktop **Gateway → Hooks** tab is where you review and trust hooks such as the one above. See
[Review hooks in Gateway](/docs/extend/develop/extensions/hooks-authoring#review-hooks-in-gateway)
for the scope order and the trust rules.

## Skill discovery by agents

Agents discover skills through the `skills` MCP server.

1. `skills.search` returns matching installed skills (name and description only).
2. The model decides which skill fits the current conversation.
3. `skills.load` loads that skill's full body.

## Skill lifecycle

| Phase | What happens |
|---|---|
| **Install** | SKILL.md scanned from the shared skills roots (`~/.claude/skills/`, then `~/.agents/skills/`; or `RYU_SKILLS_DIR`) plus the built-in defaults |
| **List** | `GET /api/skills` lists installed skills; `GET /api/skills/catalog` lists catalog skills |
| **Activate** | `POST /api/skills/activate` with `{ "id": "<id>", "active": true }` turns injection on |
| **Inject** | On each turn, active skills' metadata is injected |
| **Load** | The model calls `skills.load`, and Core injects the full body |
| **Deactivate** | `POST /api/skills/activate` with `"active": false` turns injection off |
