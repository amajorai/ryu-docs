title: "LLM-friendly docs (llms.txt)"

The docs site serves every page as plain Markdown, so a coding agent, a RAG pipeline, or a custom crawler can read it without scraping HTML. Reading these endpoints requires no API key. Responses advertise a one-day public cache lifetime; hosting-level traffic controls can still apply.

Two consumption models cover almost every host:

- **Plain text over HTTP** - the `llms.txt` family below. Works everywhere `curl` works, including hosts with no MCP support.
- **MCP server** - the same content behind three tools (`docs_search`, `docs_get_page`, `docs_index`) at [`/mcp`](/docs/extend/mcp/docs-server). Better when the agent should discover pages by search rather than follow a list.

## Endpoints

| Endpoint | Format | Use case |
|---|---|---|
| `GET /llms.txt` | Plain text index | Discover every page (title + URL). |
| `GET /llms-sections/<section>` | Full text per section | Pull one section's pages (e.g. `gateway`, `extend`). |
| `GET /llms-full.txt` | Full text, all pages | Bulk ingestion of the whole docs. |
| `GET /llms.mdx/docs/<path>` | Markdown, one page | Fetch a single page by slug. |
| `GET /docs/<path>.md` | Markdown, one page | Fumadocs' standard Markdown suffix. |
| `GET /docs/<path>.mdx` | Markdown, one page | Processed Markdown used by the page actions. |

The base URL is `https://docs.ryuhq.com`. Every endpoint returns `Content-Type: text/markdown; charset=utf-8` and `Cache-Control: public, max-age=86400`.

The site also advertises the index the standard way: the document `<head>` ships `<link rel="alternate" type="text/plain" title="LLM-friendly docs index" href="/llms.txt">`, which clients can use to discover the Markdown index.

### Search and link previews

The [XML sitemap](https://docs.ryuhq.com/sitemap.xml) lists canonical documentation URLs. HTML pages provide page-specific titles, descriptions, canonical links, and social preview images. Preview images remain crawlable so shared documentation links can display their cards.

The Markdown index complements the HTML documentation; it does not guarantee indexing or citation by a search engine. Use each page's canonical HTML URL when linking to documentation, and its Markdown representation when reading from an agent.

### Website discovery and authentication

The main website publishes a [curated LLM index](https://ryuhq.com/llms.txt).
Its `/llms-full.txt` redirects to the generated documentation corpus above.
Both sites publish `/robots.txt`, `/sitemap.xml`, `/manifest.webmanifest`, favicons,
Apple touch icons, and social preview metadata using Next.js metadata conventions.
Robots rules guide crawlers; they do not authorize access to private resources.

For account-based API access, read [auth.md](https://ryuhq.com/auth.md) and the
[OAuth protected resource metadata](https://ryuhq.com/.well-known/oauth-protected-resource).
Ryu documents dynamic client registration followed by authorization code with PKCE
and interactive user consent. Public documentation does not require this flow.
The docs site's `/auth.md` redirects to the same authentication guide.

The [AI capability catalog](https://ryuhq.com/.well-known/ai-catalog.json) indexes
the public MCP server card, Core OpenAPI schema, and documentation index. It uses
the AI Catalog 1.0 data model with stable `urn:air` identifiers and representative
queries. Its public JSON response allows cross-origin reads. Each entry references
its native artifact; the catalog does not grant access to protected APIs.

OAuth discovery names `https://api.ryuhq.com/api/auth` as the issuer. Fetch its
[RFC 8414 metadata](https://api.ryuhq.com/.well-known/oauth-authorization-server/api/auth)
and check the issuer before registering. The `agent_auth` extension describes
anonymous OAuth client registration followed by authorization code with PKCE;
`claim_uri` is the authorization endpoint and requires the full OAuth request.
Registration alone grants no access. WorkOS identity assertions and claim-token
grants are not supported. Token revocation uses the issuer's advertised revocation
endpoint; no revocation event receiver is advertised.

DNS-AID service bindings can also locate the website's discovery and MCP services
under `_agents.ryuhq.com`. Clients should require DNSSEC-authenticated responses
before trusting DNS discovery; finding a signature alone does not prove a complete
trust chain.


Security researchers can report vulnerabilities privately to [security@amajor.ai](mailto:security@amajor.ai) and discover the reporting policy at
[`/.well-known/security.txt`](https://ryuhq.com/.well-known/security.txt).
The main site's `/security.txt` and both security-file paths on the docs site
redirect to that canonical policy. The file includes a review expiry; clients
should treat it as stale after that date.

### Content negotiation

The normal HTML page URL also serves processed Markdown when the request prefers a Markdown media type. This keeps one canonical URL useful to both browsers and agents:

```sh
curl -H 'Accept: text/markdown' https://docs.ryuhq.com/docs/extend/mcp/quickstart
```

Use the explicit `.md` or `.mdx` suffix when a client cannot set request headers. If a deployment puts the HTML and negotiated Markdown behind a shared cache, configure that cache to vary on `Accept`; Next.js may otherwise remove the header while finalizing an App Router page response.

### The index: `/llms.txt`

The root of the format. It lists every documentation page as `Title: URL`, grouped by section, and is the recommended entry point: fetch it first, decide which pages matter, then fetch those pages individually.

```
$ curl https://docs.ryuhq.com/llms.txt
```

### Per-page Markdown: `/llms.mdx/docs/<path>`

Fetch one page as processed Markdown. Use the same slug as the docs URL without the `/docs` prefix:

```
$ curl https://docs.ryuhq.com/llms.mdx/docs/extend/mcp/quickstart
```

Each page starts with a structured header agents can parse:

```text
Source: https://docs.ryuhq.com/docs/extend/mcp/quickstart
Title: Quickstart
Description: ...
Tags: ...

<body markdown>
```

This is the lowest-overhead way to load exactly the pages a task needs into context.

### Per-section: `/llms-sections/<section>`

All pages under one top-level section, concatenated and delimited by `--- END OF PAGE ---`. Valid current section names are `start-here`, `showcase`, `surfaces`, `mobile`, `browser-extension`, `hardware`, `core`, `gateway`, `standalone`, `providers`, `ci`, `extend`, `ui`, `apps`, `programs`, `plugins`, `security`, `legal`, `billing`, `reference`, `learn`, and `roadmap`. Legacy names such as `desktop`, `develop`, `mcp`, `cookbook`, and `academy` remain aliases.

```
$ curl https://docs.ryuhq.com/llms-sections/gateway
```

Use this when you want a coherent slice of the docs (e.g. everything about the Gateway) without pulling the whole site.

### Full text: `/llms-full.txt`

Every page in one response, headed by a summary of the other endpoints. It is large - prefer `/llms-sections/` or per-page fetches unless you are building an offline index.

```
$ curl https://docs.ryuhq.com/llms-full.txt -o ryu-docs.txt
```

## Using it from an agent

### Direct fetch (any agent)

Point your agent's instructions at the index and let it fetch pages as needed. Add to `AGENTS.md`:

> Ryu docs are served as Markdown. Fetch `https://docs.ryuhq.com/llms.txt` to list pages, then `https://docs.ryuhq.com/llms.mdx/docs/<path>` to read one. Prefer this over guessing.

With `curl`:

```sh
# list pages, pick a slug
curl -s https://docs.ryuhq.com/llms.txt

# read one page
curl -s https://docs.ryuhq.com/llms.mdx/docs/extend/develop/quickstart
```

### MCP server

The [Docs MCP](/docs/extend/mcp/docs-server) server exposes the same content as tools - `docs_search` finds pages by query, `docs_get_page` reads one, `docs_index` lists a section. Point Claude Code, Cursor, VS Code, or Claude Desktop at it:

```bash
claude mcp add --transport http --scope user ryuDocs https://docs.ryuhq.com/mcp
```

The plain-text endpoints are the fallback for hosts that cannot run an MCP client.

### RAG / offline ingestion

For an embedding pipeline, fetch `/llms-full.txt` (or a section) and chunk on the `--- END OF PAGE ---` and `Source:` markers - they map one-to-one onto pages and URLs, so every chunk can cite its source page:

```sh
curl -s https://docs.ryuhq.com/llms-full.txt
```
