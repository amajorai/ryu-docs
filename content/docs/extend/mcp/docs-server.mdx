The docs site hosts a public Model Context Protocol server at `https://docs.ryuhq.com/mcp`. It is documentation-only: read access to Ryu's docs (search + page content), the same content `/llms.txt` serves, exposed as MCP tools so an agent can pull the right page into context while it works. It never calls a Ryu API and never runs a model.

**Server URL:** `https://docs.ryuhq.com/mcp`

## Tools

| Tool | Description |
| --- | --- |
| `docs_search` | Search the docs. `{ query, limit?, tag? }` — returns ranked hits with URLs and snippets. |
| `docs_get_page` | Fetch one docs page as Markdown. `{ path }` accepts a `/docs/...` path, bare slugs (`mcp/quickstart`), or a full URL. |
| `docs_index` | List documentation pages. `{ section? }` filters to one top-level section (e.g. `start-here`, `mcp`, `develop`). |

## Using it in Ryu

The **`@ryu/docs`** plugin is an official marketplace package and is installed and enabled by
default on fresh installs. It declares the docs server as a remote MCP server, so as soon as the
package is enabled the tools register in Core's MCP registry as `docs__docs_search`,
`docs__docs_get_page` and `docs__docs_index`, and every agent can reach them.

You can disable it from the App store like any other plugin. To point it at a local or staging docs build instead of the public site, add a `docs` entry to your `~/.ryu/mcp.json` — a user `mcp.json` entry with the same name wins over the package declaration:

```json
{
  "mcpServers": {
    "docs": {
      "type": "http",
      "url": "http://127.0.0.1:4000/mcp"
    }
  }
}
```

## Using it from other agents

Because the endpoint is a plain remote MCP server, any MCP host can add it directly.

**Claude Code** — add it from any project (or with `--scope user` to make it available everywhere):

```bash
claude mcp add --transport http --scope user ryuDocs https://docs.ryuhq.com/mcp
```

Run `/mcp` to confirm the server is connected, then ask something like "Look up the plugin manifest schema in the Ryu docs and summarize the required fields."

**Cursor** — add to `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "ryuDocs": {
      "url": "https://docs.ryuhq.com/mcp"
    }
  }
}
```

Restart Cursor, enable the server in the tools picker, and ask an agent a Ryu question.

**VS Code (Copilot Agent mode)** — add a `.vscode/mcp.json` in the project root:

```json
{
  "servers": {
    "ryuDocs": {
      "type": "http",
      "url": "https://docs.ryuhq.com/mcp"
    }
  }
}
```

**Claude Desktop** — add to `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "ryuDocs": {
      "type": "http",
      "url": "https://docs.ryuhq.com/mcp"
    }
  }
}
```

## Getting the agent to reach for it

Agents only consult an MCP server when they know to. Add a line to your project's `AGENTS.md` so Ryu questions route to the docs automatically:

> Always use the Ryu Docs MCP server (`ryuDocs`) to look up Ryu APIs, plugins, the manifest schema, and configuration before answering a Ryu question — don't wait to be asked.

## Tips

- Search results include the target page URL; follow up with `docs_get_page` on the best hit to read the full page.
- Keep the server name short and descriptive (`ryuDocs`) if you run several MCP servers, so the agent can pick it out.
- The plain-Markdown endpoints — [`/llms.txt`](/llms.txt), [`/llms-full.txt`](/llms-full.txt) and `/llms-sections/<section>` — expose the same content for hosts without MCP support. See [LLM-friendly docs](/docs/extend/mcp/llms).
