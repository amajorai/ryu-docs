---
title: "Ryu Docs MCP"
description: "Connect any MCP host to the hosted, read-only Ryu documentation MCP server, which Ryu also ships as the official @ryu/docs plugin."
---

The docs site hosts a public, anonymous MCP (Model Context Protocol) server at `https://docs.ryuhq.com/mcp`. Its tools search the docs and return page content as Markdown, the same content `/llms.txt` serves. The server never calls a Ryu API and never runs a model.

## Tools

| Tool | Description |
| --- | --- |
| `docs_search` | Search the docs. Takes `{ query, limit?, tag?, locale? }` (`limit` 1-20, default 8) and returns ranked hits with breadcrumbs, snippets, and page URLs. Pass a `locale` such as `es` to search that language's pages. Pages that are not yet translated are served in English, so search them with English terms. |
| `docs_get_page` | Fetch one docs page as Markdown. `{ path }` accepts a `/docs/...` path, a bare slug (`mcp/quickstart`), or a full URL. |
| `docs_index` | List documentation pages. `{ section?, locale? }`; `section` filters to one top-level section, such as `start-here`, `extend`, or `gateway`, or to a nested prefix such as `extend/mcp`. Legacy section names such as `mcp` and `develop` still work. |

## Using it in Ryu

The **`@ryu/docs`** plugin is an official package that is pre-installed and enabled on
fresh installs. It declares the docs server as a remote MCP server. When the plugin is
enabled, the tools register in Core's MCP registry as `docs.docs_search`,
`docs.docs_get_page`, and `docs.docs_index`, and every agent can reach them.

Disable it from the Store like any other plugin. To point it at a local or staging docs build, add a `docs` entry to `<data dir>/state/mcp.json` (for example `~/.ryu/state/mcp.json`). A user `mcp.json` entry with the same name wins over the plugin declaration.

```json
{
  "mcpServers": {
    "docs": {
      "type": "http",
      "url": "http://127.0.0.1:<port>/mcp"
    }
  }
}
```

## Using it from other agents

Any MCP host that supports remote HTTP servers can add the endpoint directly.

**Claude Code.** Add it from any project. `--scope user` makes it available in every project.

```bash
claude mcp add --transport http --scope user ryuDocs https://docs.ryuhq.com/mcp
```

Run `/mcp` to confirm the server is connected, then ask a question such as "Look up the plugin manifest schema in the Ryu docs and summarize the required fields."

**Cursor.** Add the server to `~/.cursor/mcp.json`.

```json
{
  "mcpServers": {
    "ryuDocs": {
      "url": "https://docs.ryuhq.com/mcp"
    }
  }
}
```

Restart Cursor, enable the server in the tools picker, and ask an agent a Ryu question.

**VS Code (Copilot Agent mode).** Add `.vscode/mcp.json` in the project root.

```json
{
  "servers": {
    "ryuDocs": {
      "type": "http",
      "url": "https://docs.ryuhq.com/mcp"
    }
  }
}
```

**Claude Desktop.** Add the server to `claude_desktop_config.json`.

```json
{
  "mcpServers": {
    "ryuDocs": {
      "type": "http",
      "url": "https://docs.ryuhq.com/mcp"
    }
  }
}
```

## Tell the agent to use it

An agent consults an MCP server only when it knows to. Add a line like this to your project's `AGENTS.md` so Ryu questions go to the docs.

> Always use the Ryu Docs MCP server (`ryuDocs`) to look up Ryu APIs, plugins, the manifest schema, and configuration before answering a Ryu question.

## Tips

- Search results include the target page URL; follow up with `docs_get_page` on the best hit to read the full page.
- If you run several MCP servers, give this one a short, distinct name (`ryuDocs`) so the agent can pick it out.
- For hosts without MCP support, the plain-Markdown endpoints [`/llms.txt`](/llms.txt), [`/llms-full.txt`](/llms-full.txt), and `/llms-sections/<section>` expose the same content. See [LLM-friendly docs](/docs/extend/mcp/llms).
