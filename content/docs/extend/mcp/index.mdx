MCP (Model Context Protocol) is the wire format an AI host uses to discover and call tools. It does not decide who the user is or which Ryu node the host may access.

Ryu has several MCP-shaped surfaces because Ryu can be a public website, a node, a hosted service, or an MCP client. Choose the row that matches what you are trying to do.

Core's direct and hosted node endpoints support MCP protocol `2026-07-28`, including stateless per-request metadata and HTTP routing headers. They also accept the `2025-06-18` initialize flow for older hosts. The public website and docs endpoints remain anonymous and read-only.

| Surface | Use it for | Credential |
|---|---|---|
| `https://ryuhq.com/mcp` | Public website pages, Marketplace discovery with an MCP Apps results view, and Cloud catalog discovery. See [Website MCP and NLWeb](/docs/extend/mcp/website). | None; read-only |
| `https://ryuhq.com/ask` | NLWeb natural-language search over the website, documentation, and Marketplace | None; read-only |
| WebMCP on `https://ryuhq.com` | Read the current page and start a hosted product or Cloud checkout from the visitor's browser | Same-origin browser session; checkout tools are server-authorized |
| `https://docs.ryuhq.com/mcp` | Ryu documentation search and page retrieval | None; read-only |
| WebMCP on `https://docs.ryuhq.com` | Search, read, and index the documentation from the browser or the Ask Ryu widget | Same-origin docs page; read-only |
| `POST https://<node>/mcp/<agent-id>` | A host calling one local, self-hosted, or directly selected managed Core node | Node or paired bearer, a managed user JWT on an org-bound node, or a hosted delegation |
| `https://<ryu-service>/mcp/<node-id>/<agent-id>` | A remote host calling a managed or organization-bound node | Better Auth OAuth with PKCE; the service exchanges it for a short-lived node delegation |
| `https://api.ryuhq.com/mcp` (no node; the control plane's `/mcp` on Ryu's hosted service) | Hosted Mail tools for the signed-in user. See [hosted Mail tools](/docs/standalone/sdk/mcp-hosted-mail). | Better Auth OAuth with PKCE and `mail:read`, `mail:send`, or `mail:manage` (inbox creation, only when requested by name); each Mail call names the organization, which must allow the app (`mail_list_organizations` lists the ones that do) |
| Core MCP registry | Ryu calling another MCP server | The configured server header or Passport connection |

## The request paths

```mermaid
flowchart TD
  Host["MCP host"] --> Public["Website /mcp\npublic read-only tools"]
  Host --> Direct["Direct Core /mcp/:agent-id\nnode or paired bearer"]
  Host --> Hosted["Hosted /mcp/:node-id/:agent-id\nBetter Auth OAuth + PKCE"]
  Hosted --> Delegate["45-second exact-node delegation"]
  Direct --> Core["Ryu Core node"]
  Delegate --> Core
  Core --> Registry["McpRegistry\nallowlist + approval + dispatch"]
  Registry --> External["Configured stdio or HTTP MCP server"]
  Core --> Gateway["Gateway\nmodel routing + policy + budget + audit"]
```

The direct Core endpoint is the canonical node MCP endpoint. The `apps/mcp` package is a compatibility bridge for hosts that require a stdio process. It exposes a fixed set of `ryu_*` REST wrappers and points them at one Core URL.

## Authentication is separate from MCP

Ryu uses different credentials for different boundaries:

- A Better Auth session or device-grant token identifies a person to the Ryu control plane. It is used for website sign-in, account operations, and managed-node discovery.
- A node bearer admits a caller to one Core node. Local Core mints `node-auth.token`; operators can provide `RYU_TOKEN`; Core can also issue a scoped paired token.
- Desktop's managed-node discovery also returns a short-lived managed user JWT for organization-bound nodes. See [MCP Credentials and Security](/docs/extend/mcp/security#direct-local-or-self-hosted-mcp).
- A hosted MCP request starts with a Better Auth OAuth grant. The hosted service checks organization membership and scopes, then sends Core a short-lived Ed25519 delegation bound to one node and agent.
- A third-party MCP server's OAuth or API key is a credential Core uses when it acts as an MCP client. It does not authenticate a caller to Ryu.

Signing in through the website does not silently grant direct access to every node. The managed-node list is scope-filtered, and Core repeats that check. For local or self-hosted nodes, pairing or a node bearer is still the node-access step; for external managed MCP hosts, use hosted OAuth and delegation.

## What Core does after admission

Core validates the MCP JSON-RPC method, resolves the exact agent named in the URL, applies the agent's tool allowlist and approval policy, and dispatches through the shared registry. Tool discovery is progressive: `tools/list` stays short, while large app and Composio catalogs are reached through `tool_search` and `describe`.

For model calls, Core routes through the Gateway. The Gateway applies model routing, firewall rules, budgets, billing, and audit. MCP changes who starts the call, not those controls.

## MCP Events

Authenticated Core endpoints can expose the `thread.run_status_changed` webhook event for a thread the caller may read. Ryu verifies the callback challenge, signs each delivery, encrypts subscription state at rest, and stops delivery when the thread is no longer visible. The public website and documentation MCP endpoints do not accept subscriptions.

See [MCP Events](/docs/extend/mcp/events) for the event schema, subscription lifecycle, and delivery limits.
