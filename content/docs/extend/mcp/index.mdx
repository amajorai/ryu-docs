MCP (Model Context Protocol) is a protocol for passing tools between an AI host and a server. An
MCP server provides tools. An MCP host, such as Claude Desktop, an IDE, or another agent, finds
and calls those tools.

The Ryu Core MCP server lets an MCP host use your Ryu node. It exposes Core actions as MCP tools,
so the host can use your models, search your memory, run your agents, and start your workflows
without calling Core's HTTP API directly.

MCP is not a generic word for a connection. A connection usually signs you in to an account or
links you to a service. MCP describes the protocol used to find and call tools.

The server lives in `apps/mcp`. Core can use external MCP servers as tools. The `apps/mcp` process
does the reverse: it lets external MCP hosts use Core as a server.

| Term | Meaning |
|---|---|
| **MCP host** | An app that uses MCP tools, such as Claude Desktop or an IDE. |
| **MCP server** | A program that provides tools to an MCP host. |
| **Ryu Core MCP server** | The Ryu process that exposes Core actions as MCP tools. |

## The picture

An external host speaks MCP over stdio to the `apps/mcp` process. That process speaks HTTP to a Ryu Core, local or remote. Core does the real work and the Gateway governs every model call.

<Mermaid chart={`flowchart LR
  Host["MCP host Claude Desktop"] -->|"MCP stdio"| Bridge["apps/mcp Ryu MCP server"]
  Bridge -->|"HTTP RYU_CORE_URL"| Core["Ryu Core node"]
  Core --> Gateway["Gateway routing budget audit"]
`} />

The bridge holds no model and runs no inference. It translates MCP tool calls into Core HTTP requests and streams the results back. Point it at a different `RYU_CORE_URL` and the same host now drives a different node, including a remote node over Tailscale.

<Callout type="info">
  Core decides what runs; the Gateway decides what is allowed, measured, and paid. Driving Core through MCP changes nothing about that split. A tool call from Claude Desktop is governed exactly like a call from the desktop app.
</Callout>

## Choose the right MCP boundary

Ryu has three intentional MCP surfaces:

- The website MCP endpoint is anonymous and read-only. Its server card says so explicitly, and it
  does not grant access to an account or a node.
- The Core bridge is node-level access. Its node credential is the boundary for the particular Core
  instance, while Core capability checks and Gateway governance remain in force.
- The official Ryu authorization service is the OAuth provider for protected remote MCP resources.
  It uses PKCE and consented Ryu scopes; it does not replace the node credential for a local bridge,
  and it does not silently turn a plugin's provider connection into an organization-wide grant.
