An MCP request crosses more than one boundary. Each boundary has its own credential and its own check.

## Credential map

| Credential | Where it is checked | What it grants |
|---|---|---|
| Better Auth session or device token | Ryu control plane | A signed-in user and their organization memberships |
| Node bearer or paired token | Core | Access to one Core node, with paired capabilities and bindings |
| Managed user JWT | An organization-bound Core node | The user's role plus organization, team, or personal-node scope for direct managed-node requests |
| Hosted MCP OAuth grant | Hosted MCP service | Consent, resource audience, and requested MCP scopes |
| Ed25519 node delegation | Core | One hosted request, one node, one agent, and a short expiry |
| Third-party provider credential | Core MCP registry / Identity Vault | Core's request to one configured external MCP server |

These values are not interchangeable. Website sign-in does not pair a node. A node token does not sign a user into the website. A plugin's provider credential does not grant access to Ryu.

## Direct local or self-hosted MCP

The direct endpoint is:

```text
POST https://<node>/mcp/<agent-id>
Authorization: Bearer <node-or-paired-token>
```

Core checks the bearer before it reads the JSON-RPC message. For `tools/list`, the caller needs `tools:read`. For `tools/call`, it needs `tools:exec`. Core then requires an exact known agent id and checks that agent's allowlist.

For a managed node selected by Desktop, the bearer can instead be the short-lived
`userJwt` returned by `GET /api/control-plane/nodes`. Desktop also sends it as
`x-ryu-user-jwt`; Core verifies the signature, matches the organization, and
checks team or personal ownership before applying the route capability. This
managed shortcut is not available on an unbound local or self-hosted node.

Local Core creates `node-auth.token` on first boot. A local stdio bridge can read it when the target URL is loopback. A browser or another machine cannot read that file, so it uses the node pairing flow instead. Pairing approval happens on the node and can work without a control-plane account.

## Managed or organization-bound MCP

The hosted endpoint is:

```text
POST https://<ryu-service>/mcp/<node-id>/<agent-id>
Authorization: Bearer <Better-Auth-OAuth-token>
```

The hosted service:

1. Validates the OAuth token, client, session, resource audience, and expiry.
2. Checks organization membership, personal or team ownership, and requested scopes.
3. Intersects the OAuth grant with the user's organization role.
4. Signs a short-lived Ed25519 delegation bound to the exact node and agent.
5. Forwards the JSON-RPC request to the node's `/mcp/<agent-id>` endpoint.

The hosted service never forwards the original OAuth token to Core. Core verifies the delegation locally using the public key pinned during node enrollment. It also checks the node id, organization, team, agent, issuer, scope, and expiry.

The Desktop node selector uses a related direct path. It asks the control plane for reachable nodes with the user's Better Auth session, receives a short-lived managed user JWT, and sends that credential to the selected organization-bound Core node. It refreshes the JWT before it expires; the JWT is kept in memory and is not written into `nodes.json` as a node secret.

## Tool execution after authentication

Authentication only admits the request. Core still applies the MCP method capability, agent allowlist, approval policy, app lifecycle checks, tenancy rules, and Identity Vault bindings before dispatch.

The Gateway is not the node-discovery service. For model calls, Core sends traffic through the Gateway, where routing, firewall rules, budgets, billing, and audit apply. Core's MCP registry then connects to the configured external MCP server over stdio, Streamable HTTP, or legacy SSE.

## Revocation and storage

- Revoke a paired client from the node's Connections settings. This does not rotate the node owner's credential.
- Revoke a managed node or organization membership in the control plane. Future hosted delegations stop, and existing delegations expire quickly.
- Keep direct node tokens out of source control and MCP host prompts.
- `ryu-mcp login` stores its user session in `~/.ryu/mcp-auth.json`. It is separate from Desktop's encrypted credential store and does not replace the node bearer used for Core calls.

The public website MCP endpoint is a separate anonymous, read-only service. It has no account session and no node access.
