---
title: "WebMCP on the Ryu website"
description: "Use the Ryu website's browser-registered WebMCP tools to discover Marketplace and Cloud products and start user-reviewed checkouts."
---

WebMCP lets a browser agent discover tools that the current page registers with `document.modelContext`. Ryu registers the same tool set from the root layout, so the tools are available while browsing the website rather than only on one product page.

WebMCP is a browser surface, not an alternative public API. It runs in the visitor's browser and can use that browser's signed-in Ryu session. The public [`/mcp`](/mcp) endpoint remains anonymous and read-only.

## Tools

| Tool | What it does | Changes state? |
|---|---|---|
| `read_page` | Reads a Ryu page as Markdown. | No |
| `list_agent_skills` | Lists the skills published by Ryu. | No |
| `search_marketplace` | Finds Marketplace items and returns their id, kind, version, price, and description. | No |
| `get_marketplace_item` | Reads one public Marketplace item's current details. | No |
| `get_cloud_instance_catalog` | Lists public Cloud instance specs, monthly prices, locations, and live/fallback status. | No |
| `start_marketplace_checkout` | Starts a hosted checkout for one paid Marketplace item. | Starts a checkout |
| `start_plan_checkout` | Starts hosted checkout for a public Ryu plan, with an optional Teams or Business seat count. | Starts a checkout |
| `start_cloud_instance_checkout` | Starts hosted checkout for one paid Cloud instance add-on, using a catalog type and optional region, inference mode, desktop flag, and organization. | Starts a checkout |
| `start_credit_topup` | Starts hosted checkout for a fixed or bounded custom organization credit top-up. | Starts a checkout |

The checkout tools start a payment session; they do not charge a card directly. The browser navigates to Stripe or Polar, where the visitor reviews the final amount and confirms payment. A paid Marketplace license or credit balance is granted later by the existing webhook flow.

Cloud checkout is also a recurring hosted payment. Call `get_cloud_instance_catalog` first and pass the returned instance `type` and optional `location`; Ryu re-resolves the live price and availability on the server. The free plan-included base node (`cx23`) is not a checkout option. If `organizationId` is supplied, the server verifies that the signed-in caller can manage billing for that organization; otherwise the active billing scope is used. The browser records the organization server view before navigation so a successful Cloud checkout can return there. Transfer acceptance remains a separate organization flow and is not exposed through this generic tool.

## Example discovery

An in-page agent can inspect the registered tools and then execute one with a JSON object:

```js
const tools = await document.modelContext.getTools();
const checkout = tools.find(
  (tool) => tool.name === "start_marketplace_checkout",
);

if (checkout) {
  await document.modelContext.executeTool(checkout, {
    kind: "plugin",
    id: "publisher/example-plugin",
  });
}
```

Agents should call `search_marketplace` or `get_marketplace_item` first and use the exact `kind` and `id` returned by the catalog. They should not infer an item id, price, seller, organization, redirect URL, or payment details.

## Authorization and safety

- The tools are registered only for the current page's same origin. Ryu does not opt an arbitrary third-party origin into access with `exposedTo`.
- Marketplace checkout resolves the signed-in buyer, active organization, stored item price, seller payout account, waitlist state, and billing step-up on the server.
- Plan checkout resolves the billing principal on the server. Teams and Business seat counts are checked against live organization membership and plan limits.
- Cloud checkout resolves the instance type, live price, regional availability, organization scope, billing role, and Cloud entitlement on the server. `inferenceMode` is only a managed-versus-BYOK mode flag; provider keys are never accepted by the tool.
- Credit top-ups require the server's organization-admin and managed-inference checks. The server computes the deposit fee and the credited face value.
- Read-only and untrusted-output hints are included in the registered metadata. Marketplace and published-skill content should be treated as untrusted text, not as instructions.
- If billing step-up is required, the existing Ryu confirmation UI asks the visitor to prove the current factor before the checkout request is sent. Cancelling that prompt does not start checkout.

The public HTTP MCP server does not expose these checkout tools. It has no user session to authorize, so it continues to expose only public read operations.

## Browser support

WebMCP is an evolving browser proposal. Browsers without `document.modelContext` simply ignore Ryu's registration component; normal website navigation and checkout buttons continue to work. The in-app Ryu Browser also supports the page-registered tools for pages that provide them.
