---
title: "Configuration"
description: "Point the Ryu stdio bridge at one local or remote Core node, or use hosted MCP OAuth."
---

The `apps/mcp` compatibility bridge has one target. It does not maintain a node registry or choose between local and managed nodes.

## Environment variables

| Variable | Default | Meaning |
|---|---|---|
| `RYU_CORE_URL` | `http://127.0.0.1:7980` | The Core node used by the stdio bridge. |
| `RYU_CORE_TOKEN` | unset | Explicit bearer for the target Core. For a loopback URL, the bridge falls back to that machine's `node-auth.token`. It never sends the local file token to a remote URL. |
| `RYU_DIR` | unset | Core's relocated data directory; used to find a loopback `node-auth.token`. |
| `RYU_AUTH_URL` | `http://localhost:3000` | Better Auth control-plane URL used by `ryu-mcp login`, `logout`, and `whoami`. |
| `RYU_MCP_AUTH_FILE` | `~/.ryu/mcp-auth.json` | Local file for this bridge's Better Auth session. |
| `RYU_HOME` | `~/.ryu` | Directory used for the bridge's local session when `RYU_MCP_AUTH_FILE` is not set. |

`RYU_CORE_TOKEN` and the session created by `ryu-mcp login` are different values. The first admits the bridge to Core. The second identifies a person to the control plane.

## Local target

```json
{
  "mcpServers": {
    "ryu-local": {
      "command": "bun",
      "args": ["run", "apps/mcp/src/index.ts"],
      "env": {
        "RYU_CORE_URL": "http://127.0.0.1:7980"
      }
    }
  }
}
```

For a current local Core, the bridge reads `node-auth.token` automatically. An explicit `RYU_CORE_TOKEN` wins over the file.

## Self-hosted remote target

Use the remote node's reachable URL and its node or paired token:

```json
{
  "mcpServers": {
    "ryu-self-hosted": {
      "command": "bun",
      "args": ["run", "apps/mcp/src/index.ts"],
      "env": {
        "RYU_CORE_URL": "https://node.example.com",
        "RYU_CORE_TOKEN": "<token-for-that-node>"
      }
    }
  }
}
```

The URL can be a private Tailscale or Headscale address. The mesh handles reachability, while Core still checks the bearer on every request.

## Managed target

Do not point the stdio bridge at the control-plane URL. The control plane lists managed nodes, but it is not the Core API for those nodes.

For an external MCP host, use the hosted resource:

```text
https://<ryu-service>/mcp/<node-id>/<agent-id>
```

The MCP host authenticates with Better Auth OAuth and PKCE. The service resolves the node's registered HTTPS URL and forwards the request with a short-lived, node-and-agent delegation.

The Ryu Desktop node selector performs this discovery itself through `GET /api/control-plane/nodes`. It receives and refreshes a short-lived managed `userJwt`, which Core accepts only for the matching organization, team, or personal node scope. A local, LAN, or self-hosted node is not replaced by this cloud list.

## Multiple nodes

Register one stdio entry per direct node and give each a distinct name. For example, `ryu-local` and `ryu-office`. Each entry has its own URL and bearer. A host cannot switch the bridge's target by changing a tool argument.

If you need a single hosted endpoint that names the destination in its URL, use hosted MCP instead.

<Callout type="info">
  Core's canonical direct MCP route is `/mcp/<agent-id>`. The stdio bridge exposes a fixed compatibility list of `ryu_*` wrappers, so newly registered Core tools may only appear through the canonical Core route.
</Callout>
