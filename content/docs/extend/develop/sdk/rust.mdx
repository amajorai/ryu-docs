The `ryu-sdk` crate (`crates/sdk/core/`) is the shared Rust kernel that every Ryu language binding
builds on. It holds the one implementation of the parts that must not drift across languages:

- **Shared local logic**, bound out through FFI: the `manifest.json` and Runnable model with its
  validation (`manifest.rs`, `runnable.rs`), and the Gateway egress rules (`gateway.rs`). The
  manifest and Runnable types are re-exported from the `ryu-kernel-contracts` crate
  (`crates/core/kernel-contracts/`), which Core also uses.
- **Transport**: the Gateway-mandatory model and embedding clients (`model.rs`, `embedding.rs`),
  which call the Gateway's OpenAI-compatible API.

For the manifest format and the full Runnable kind table, see
[Plugin manifests](/docs/extend/develop/extensions/plugin-json-manifest) and
[Plugin API](/docs/extend/develop/sdk/plugin-api). For the Runnable concept, see
[the Runnable model](/docs/start-here/architecture/runnable-model). This page documents the Rust
surface only.

<Callout type="warn">
  This is the lower-level kernel crate (version `0.4.0`). Most application developers should use a
  client library instead: [`@ryuhq/client`](/docs/extend/develop/sdk/client),
  [`@ryuhq/core-client`](/docs/extend/develop/sdk/core-client), or the
  [Java library](/docs/extend/develop/sdk/java).
</Callout>

## The Runnable model

`RunnableKind` is the union of every executable thing in Ryu. `ryu-sdk` re-exports it from
`ryu_kernel_contracts::runnable`, and `apps/core/src/runnable/mod.rs` re-exports the same type, so
a manifest authored against this enum deserializes identically in Core. The eight kinds are
documented once on [the Runnable model](/docs/start-here/architecture/runnable-model).
`RunnableKind::as_str()` returns the stable lowercase identifier. `RunnableMeta { id, name, kind }`
is the kind-agnostic identity snapshot.

### Per-kind config and validation

A `RunnableEntry` is one entry inside a manifest. It holds identity fields plus an optional
`config` value whose required shape depends on `kind`. Each kind has a dedicated config struct
(`AgentConfig`, `WorkflowConfig`, `ToolConfig`, `SkillConfig`, `CompanionConfig`, `ChannelConfig`,
`EngineConfig`, `PolicyConfig`).

```rust
pub struct RunnableEntry {
    pub id: String,
    pub name: String,
    pub kind: RunnableKind,
    pub config: Option<serde_json::Value>,
}
```

`validate_runnable(entry)` enforces each kind's contract and returns a descriptive `String` error
when it fails. It is the same function Core uses: `apps/core/src/plugin_manifest/schema.rs`
re-exports `ryu_kernel_contracts::schema`. The per-kind required-field table lives on
[Plugin API](/docs/extend/develop/sdk/plugin-api).

```rust
use ryu_sdk::{validate_runnable, RunnableEntry, RunnableKind};

let entry = RunnableEntry {
    id: "tool-web-search".into(),
    name: "Web Search".into(),
    kind: RunnableKind::Tool,
    config: Some(serde_json::json!({ "slug": "web_search" })),
};
validate_runnable(&entry)?; // Ok(()) - tool has a non-empty slug
```

## Manifest validation

`PluginManifest` is the in-memory model of a `manifest.json`. It is defined in
`crates/core/kernel-contracts/src/manifest.rs` and is the same type Core loads. The excerpt below
shows the identity fields. The full struct also carries `contributes`, `requires`, `targets`, and
other optional sections.

```rust
pub struct PluginManifest {
    pub id: String,
    pub name: String,
    pub version: String,
    pub runnables: Vec<RunnableEntry>,
    pub permission_grants: Vec<String>,
    pub companion: Option<CompanionSurface>,
    // ... contributes, requires, targets, and more
}
```

To load an untrusted manifest, call `parse_and_validate`. It parses the JSON, then runs full
validation:

```rust
use ryu_sdk::PluginManifest;

let manifest = PluginManifest::parse_and_validate(raw_json)?;
for meta in manifest.runnable_metas() {
    println!("{} ({})", meta.name, meta.kind.as_str());
}
```

`validate()` runs `validate_plugin_id` (reverse-domain, with no path separators, `..`, or leading
or trailing dots, so the id is safe as an identity key and a directory name), parses the version
with the `semver` crate, and runs `validate_runnable` on every entry. It then checks declared
capabilities, event subscriptions, surface commands, MCP OAuth settings, code sources, the
declarative HTTP policy, and each `contributes` section.

### Loading installed plugins

`plugins_dir()` resolves the scan directory the same way Core does: `RYU_PLUGINS_DIR`, then the
legacy `RYU_APPS_DIR`, then `<data dir>/plugins` (for example `~/.ryu/plugins` on the release
profile). The data dir is `RYU_DIR`, then the folder chosen in the desktop Storage setting, then
`~/.ryu` with the profile suffix (`~/.ryu-dev` when `RYU_PROFILE=dev`). An unrecognized
`RYU_PROFILE` resolves to the release layout instead of failing. The SDK no longer falls back to
the old `~/.ryu/apps` folder when `~/.ryu/plugins` is missing; set `RYU_APPS_DIR` to keep scanning
it. `load_user_plugins()` scans it for `manifest.json`, `plugin.json`, or legacy `ryu.json`
files (first match wins) and returns only manifests that pass id, semver, and duplicate checks.
Built-in manifests are not on disk. To list every manifest Core loaded, including built-ins, call
`GET /api/plugins`.

```rust
use ryu_sdk::load_user_plugins;

for manifest in load_user_plugins() {
    println!("{} v{}", manifest.id, manifest.version);
}
```

### JSON Schema export

`ryu_sdk::json_schema::plugin_manifest_schema()` emits the JSON Schema for `PluginManifest`,
derived from the Rust types with `schemars`. Any language can validate a `manifest.json` against
this schema without a Rust FFI binding. The schema stays in lockstep with the Rust types.

## The Gateway-mandatory model client

Every model call routes through the Ryu Gateway. The crate enforces this at construction.

`DEFAULT_GATEWAY_URL` is `http://127.0.0.1:7981`. `resolve_gateway_url()` reads `RYU_GATEWAY_URL`
and falls back to the default. `resolve_gateway_token()` reads `RYU_GATEWAY_TOKEN`.

`assert_allowed_egress(base_url)` (`crates/sdk/core/src/gateway.rs`) rejects a URL that matches the
blocklist of known direct-provider hosts (`api.openai.com`, `api.anthropic.com`, `openrouter.ai`,
and the Google, Cohere, Mistral, Groq, Together, Replicate, and Perplexity APIs) with an
`EgressNotAllowed` error. Any other URL passes, including loopback, the configured Gateway, and
private addresses. Provider credentials belong in the Gateway, never in SDK config.

`ModelClient` (`crates/sdk/core/src/model.rs`) sends `POST {base}/v1/chat/completions`. Build it
with `ModelClient::new(model, options)` or the `define_model(model, options)` factory, which
mirrors the TypeScript `defineModel`. The egress check runs at construction time, so a
direct-provider base URL fails before any request.

```rust
use ryu_sdk::{define_model, ChatMessage, ModelClientOptions};

let model = define_model("gemma4", ModelClientOptions::default())?;

// Non-streaming:
let result = model.chat(&[ChatMessage::user("hello")]).await?;
println!("{}", result.content);
if let Some(usage) = result.usage {
    println!("tokens: {}", usage.total_tokens);
}

// Streaming (OpenAI-compatible SSE):
use futures_util::StreamExt;
let messages = [ChatMessage::user("write a haiku")];
let mut stream = model.stream(&messages);
while let Some(delta) = stream.next().await {
    let delta = delta?;
    print!("{}", delta.content);
}
```

`ChatMessage` has `system`, `user`, and `assistant` constructors. `ChatResult` carries `content`,
an optional `finish_reason`, and an optional `Usage`. `ChatDelta` carries an incremental `content`
fragment and an optional `finish_reason` on the final chunk. `ModelError` has three variants:
`Egress` (blocked URL), `Transport` (network failure), and `Http { status, url, body }` (non-2xx
from the Gateway).

## The Gateway-mandatory embedding client

`EmbeddingClient` (`crates/sdk/core/src/embedding.rs`) sends `POST {base}/v1/embeddings` to the
Gateway. Build it with `EmbeddingClient::new(model, options)` or the
`define_embedding(model, options)` factory. The same `assert_allowed_egress` check runs at
construction, so a direct-provider base URL fails before any request.

```rust
use ryu_sdk::{define_embedding, EmbeddingClientOptions};

let embedder = define_embedding("nomic-embed-text-v1.5", EmbeddingClientOptions::default())?;
let result = embedder.embed(&["first text".into(), "second text".into()]).await?;
for vector in result.vectors() {
    println!("dims: {}", vector.len());
}
```

The input is always sent as an array, so one call embeds a single text or a batch. `embed_one(text)`
returns one vector. `EmbeddingResult` holds `embeddings` (one `Embedding { index, vector }` per
input, in input order) and an optional `EmbeddingUsage`, with `vectors()` and `first_vector()`
accessors. `EmbeddingError` has the same `Egress`, `Transport`, and `Http { status, url, body }`
variants as `ModelError`.

## OpenAPI codegen (optional)

The canonical OpenAPI specs are vendored under `crates/sdk/core/specs/`
(`core-openapi.json`, `gateway-openapi.yaml`) as the contract. The crate's transport is a
hand-written `reqwest` client. An optional `codegen` Cargo feature generates a client from the
vendored spec.

<Callout type="warn">
  `codegen` is off by default. The vendored specs are OpenAPI 3.1, which the `progenitor` generator
  does not fully support, so the default build does not depend on the generator. The
  `spec_conformance` test still exercises the spec.
</Callout>

## Crate API at a glance

```rust
// Re-exported from crates/sdk/core/src/lib.rs:
pub use embedding::{ define_embedding, Embedding, EmbeddingClient, EmbeddingClientOptions,
                     EmbeddingError, EmbeddingResult, EmbeddingUsage };
pub use gateway::{ assert_allowed_egress, resolve_gateway_token, resolve_gateway_url,
                   EgressNotAllowed, DEFAULT_GATEWAY_URL };
pub use manifest::{ load_user_plugins, plugins_dir, validate_plugin_id,
                    CompanionSurface, PluginManifest };
pub use model::{ define_model, ChatDelta, ChatMessage, ChatResult, ModelClient,
                 ModelClientOptions, ModelError, Usage };
pub use runnable::{ validate_runnable, AgentConfig, ChannelConfig, CompanionConfig, EngineConfig,
                    PolicyConfig, RunnableEntry, RunnableKind, RunnableMeta, SkillConfig,
                    ToolConfig, WorkflowConfig };
```

## Language bindings

Three binding crates wrap the same `ryu_sdk::*` functions, so manifest rules, the egress blocklist,
and the model and embedding transport stay identical across languages:

| Crate | Target | Mechanism |
|---|---|---|
| `crates/sdk/napi` | TypeScript / JS | napi-rs native addon (keeps the streaming closure boundary via `ThreadsafeFunction`) |
| `crates/sdk/ffi` | C and Go | raw C ABI |
| `crates/sdk/uniffi` | Python / Swift / Kotlin | generated by `uniffi-bindgen` |
| `crates/sdk/uniffi` + `uniffi-bindgen-cs` | C# | version-matched third-party generator |

The UniFFI surface (`crates/sdk/uniffi/src/lib.rs`) exports `validate_plugin_id`,
`parse_and_validate_manifest`, `plugin_manifest_json_schema`, the Gateway resolvers,
`assert_allowed_egress`, and blocking `ModelClient` and `EmbeddingClient` objects, plus streaming
through the `ChatSink` callback interface. `uniffi::setup_scaffolding!("ryu_sdk")` makes the emitted
Python package import as `ryu_sdk`. The `uniffi-bindgen` driver
(`crates/sdk/uniffi/src/bin/uniffi-bindgen.rs`) emits bindings on demand. See
[Libraries and bindings](/docs/extend/develop/sdk/language-bindings) for per-language commands.

For TypeScript, use the published packages instead of the napi addon:
[`@ryuhq/sdk`](/docs/extend/develop/sdk) for authoring and [`@ryuhq/client`](/docs/extend/develop/sdk/client) for
calling a Core node. For a language without a binding, validate manifests against the exported JSON
Schema and call Core's [HTTP API](/docs/extend/develop/api-reference) and the Gateway's
`POST /v1/chat/completions` directly.
