title: Client SDK
description: Reference for @ryuhq/client, the TypeScript client for agent chat, sessions, harness runs, Spaces, and mail on a Ryu Core node, plus the Notify, Managed Agents, Messaging, and Box clients.
---

`@ryuhq/client` is the TypeScript client for a running Ryu Core node's HTTP
API. Use it to pick an agent, stream a reply, read conversations, search Spaces, or operate a
[durable harness run](/docs/extend/develop/sdk/harness). For the full Core management surface
(plugins, models, skills, MCP servers, workflows, Gateway config), use
[`@ryuhq/core-client`](/docs/extend/develop/sdk/core-client).

The client is a typed wrapper over the platform `fetch`, with `zod` as its one runtime dependency.
It runs anywhere a global `fetch` exists: Node 18+, Bun, Deno, modern browsers, and React Native.

<Callout type="warn">
  A client token is a Ryu Core node token. It is not a provider API key. Keep it in the app's
  secure storage, and keep provider credentials in the Gateway.
</Callout>

<Callout type="warn">
  `@ryuhq/client` 0.3.0 is the current npm release. The Managed Agents, Messaging, Notify, and Box
  clients are newer and are not in 0.3.0.
  [What you can install today](/docs/standalone/sdk/choose-an-sdk#what-you-can-install-today) lists
  each package's status.
</Callout>

## Install

```bash
bun add @ryuhq/client   # or: npm install @ryuhq/client
```

## React Native / Expo

The same client is the React Native library. Expo apps inject `expo/fetch` for response
streaming.

```tsx
import { fetch as expoFetch } from "expo/fetch";
import { createRyuClient, type RyuFetch } from "@ryuhq/client";

const client = createRyuClient({
  baseUrl: "http://192.168.1.10:7980",
  token: nodeToken,
  fetch: expoFetch as RyuFetch,
});

const reply = await client.agents.run("pi", [
  { role: "user", content: "Hello from Expo." },
]);
```

## Create a client

`createRyuClient(options)` returns a `RyuClient` with typed `agents`, `sessions`, `harness`,
`spaces`, and `mail` namespaces. Pass the optional `notify` connection to add a tenant-scoped
`notify` namespace. Its API key is separate from the Core node token.

```typescript
import { createRyuClient } from "@ryuhq/client";

const client = createRyuClient({ baseUrl: "http://localhost:7980" });

// Remote node with a token:
const remote = createRyuClient({
  baseUrl: "https://my-node.example.com",
  token: process.env.RYU_TOKEN,
});
```

```typescript
interface RyuClientOptions {
  baseUrl: string; // Base URL of the Core server, e.g. "http://localhost:7980"
  fetch?: RyuFetch; // Optional Expo/RN fetch implementation
  token?: string;  // Optional bearer token for authenticated nodes
  mailRealtime?: "core" | "standalone"; // Core WS by default; direct sidecar WS for standalone Mail
  notify?: { baseUrl: string; apiKey: string; fetch?: RyuFetch }; // Optional standalone Notify
  userJwt?: string | (() => string | null); // Verified end-user JWT for an organization-bound Core
}
```

`userJwt` is separate from the node `token`. Core uses it for per-user and per-team tenancy on an
organization-bound node. A function value is called for every request, so the caller can rotate
sessions.

## `client.notify`

```typescript
const client = createRyuClient({
  baseUrl: "http://127.0.0.1:7980",
  token: coreToken,
  notify: { baseUrl: "https://notify.example", apiKey: notifyTenantKey },
});

const event = await client.notify?.publish(
  { title: "Deploy complete", topic: "deployments", source: "ci" },
  "deploy-184",
);
for await (const item of client.notify?.stream({ topic: "deployments" }) ?? []) {
  if (item.type === "notification") console.log(item.event.title);
}
```

The namespace also covers topics, acknowledgement and archive, interactive responses, live
activities, destinations, preferences (`updatePreferences` sends `PATCH`), silences, groups,
analytics, and usage reports. Display `response.callbackUrlPreview` (origin only), not the
deprecated `response.callbackUrl`. [Ryu Notify](/docs/standalone/notify) is the service contract.

## Separate service clients

The package also exports clients for hosted and standalone services. They are not namespaces
of `createRyuClient`, and none of them takes a Core node token.

| Factory | Service | Credential | Reference |
|---|---|---|---|
| `createManagedAgentsClient({ baseUrl, apiKey })` | [Managed Agents API](/docs/standalone/managed-agents-api) | Ryu API key | [TypeScript client](/docs/standalone/managed-agents-api#typescript-client) |
| `createMessagingClient({ baseUrl, apiKey, organizationId })` | [Messaging API](/docs/standalone/messaging-api) (SMS, MMS, WhatsApp, voice, numbers) | Ryu API key (`messaging:read` to read, `messaging:manage` to send, buy numbers, or change settings) | [TypeScript client](/docs/standalone/messaging-api#typescript-client) |
| `createBoxClient({ baseUrl, apiKey })` | Ryu Box | Box tenant key | [Boxes](/docs/core/boxes-local-mode#routes-and-features) |
| `createNotifyClient({ baseUrl, apiKey })` | [Ryu Notify](/docs/standalone/notify) | Notify API key | Same API as `client.notify` |

```typescript
import { createManagedAgentsClient, createMessagingClient } from "@ryuhq/client";

const managed = createManagedAgentsClient({ baseUrl: "https://<control-plane-host>", apiKey });
const messaging = createMessagingClient({
  baseUrl: "https://<control-plane-host>",
  apiKey,
  organizationId,
});

const message = await messaging.sms.send(
  { from: numberId, to: "+6591234567", body: "Hi" },
  { idempotencyKey: "welcome-6591234567" },
);
```

Failed requests throw `ManagedAgentsError` or `MessagingError` (with the API's stable `code`).
`verifyMessagingWebhook` checks a signed Messaging webhook delivery.

## `client.agents`

Agent CRUD and chat streaming over Core's `/api/agents` and `/api/chat/stream` endpoints.

| Method | Returns | Calls |
|---|---|---|
| `list()` | `AgentSummary[]` | `GET /api/agents` |
| `get(id)` | `Agent` | `GET /api/agents/:id` |
| `create(input)` | `Agent` | `POST /api/agents` |
| `update(id, input)` | `Agent` | `PUT /api/agents/:id` |
| `run(id, messages)` | `string` | `POST /api/chat/stream` (buffered) |
| `stream(id, messages)` | `AsyncGenerator<StreamChunk>` | `POST /api/chat/stream` |

### List and fetch agents

```typescript
const agents = await client.agents.list();
for (const agent of agents) {
  console.log(agent.id, agent.name);
}

// Full record (tools, engine binding, version) for one agent:
const pi = await client.agents.get("pi");
```

### Create and update agents

`create()` saves a custom agent and returns the record Core stored. `update()` is a patch: fields
you leave out keep their saved values. Pass `expectedUpdatedAt` (the `updatedAt` you last loaded) to
have Core reject the update if someone else changed the agent first.

```typescript
const researcher = await client.agents.create({
  name: "Researcher",
  systemPrompt: "Find and summarize sources.",
  identityMode: "individual",
});

await client.agents.update(researcher.id, {
  identityMode: "mixed",
  accountAccess: ["provider:openai", "platform:desktop"],
});
```

### Identity mode and account access

Every `Agent` carries `identityMode`, which decides whose accounts it works with:

| `identityMode` | In the app | Behavior |
|---|---|---|
| `"managed"` | Acts as you | Works on your behalf with the accounts you've connected. |
| `"individual"` | Its own identity | Gets its own accounts and logins, and never touches yours. |
| `"mixed"` | Both | Has its own accounts, and can also use the ones of yours you allow. |

`create()` defaults to `"managed"` when you omit it. An agent saved before identity modes existed
also reads as `"managed"`. If the client sees a mode it does not recognize, it reports
`"individual"`, the most restrictive mode, so writing the value back can never let the agent act
as you.

`accountAccess` is an optional allowlist of account keys. It narrows what the identity mode
permits; it never widens it, and a key that does not parse grants nothing.

| Key | Account |
|---|---|
| `provider:<id>` | One of your model providers, such as `provider:openai` |
| `composio:<connected_account_id>` | One of your Composio accounts |
| `mcp:<profile_id>:<plugin_id>:<server>` | One MCP OAuth sign-in |
| `mcp-secret:<server-or-plugin>` | An MCP server or app tool that calls out with one of your saved keys |
| `platform:treg` | Treg |
| `platform:desktop` | Control of your desktop. An `"individual"` agent never gets it |
| `agent:<vault_account_id>` | One of the agent's own vault accounts |
| `agent-composio:<connected_account_id>` | A Composio account connected to the agent's own identity |

`null` and `[]` mean different things:

| Value | On read | In `update()` |
|---|---|---|
| omitted | Not applicable | Leaves the saved allowlist unchanged |
| `null` | No allowlist: every account the identity mode permits | Clears the allowlist back to unrestricted |
| `[]` | No accounts, and no Treg | Allows no accounts and no Treg |
| `["…"]` | Only the listed accounts | Replaces the allowlist |

The allowlist belongs to the node it was set on. It is not part of a shared agent template, so an
imported agent always starts without one.

### Stream a chat turn

`stream()` yields a `StreamChunk` for every text fragment as it arrives from Core's SSE stream, then
a final `{ type: "done" }` chunk.

```typescript
const messages = [{ role: "user" as const, content: "Write a haiku about Rust." }];
const controller = new AbortController(); // call controller.abort() to cancel

for await (const chunk of client.agents.stream("pi", messages, { signal: controller.signal })) {
  if (chunk.type === "text") process.stdout.write(chunk.content ?? "");
  if (chunk.type === "done") break;
}
```

A single stream event larger than 256 KiB (including one that never ends) stops the stream with
an `SseFrameTooLargeError`, which the package exports.

### Buffer the whole reply

`run()` consumes the stream and returns the full text. If the turn fails after the stream opens (for
example a provider or rate-limit error), `run()` rejects instead of returning partial text; use
`stream()` to keep the partial reply. It also stops and throws once the reply passes
`maxOutputChars` (1,000,000 characters by default, exported as `MAX_AGENT_RUN_OUTPUT_CHARS`):

```typescript
const reply = await client.agents.run("pi", messages, { maxOutputChars: 50_000 });
console.log(reply);
```

## `client.spaces`

Spaces and RAG search over Core's `/api/spaces` endpoints. A Space is a named document collection
with a `retrievalMode` of `"vector"` or `"graph"`.

| Method | Returns | Calls |
|---|---|---|
| `list()` | `Space[]` | `GET /api/spaces` |
| `create(name, description?, retrievalMode?)` | `string` (Space id) | `POST /api/spaces` |
| `search(id, query, limit?)` | `SpaceMatch[]` | `POST /api/spaces/:id/search` |
| `startRetrievalModeChange(id, mode)` | `RetrievalModeJob` | `POST /api/spaces/:id/retrieval-mode` |
| `getRetrievalModeStatus(id, jobId)` | `RetrievalModeStatus` | `GET /api/spaces/:id/retrieval-mode/status` |
| `cancelRetrievalModeChange(id, jobId)` | `RetrievalModeCancellation` | `POST /api/spaces/:id/retrieval-mode/cancel` |
| `queryDatabase(spaceId, databaseId, input)` | `SpaceDatabaseQueryResult` | `POST /api/spaces/:id/databases/:doc_id/query` |

```typescript
const spaces = await client.spaces.list();
const matches = await client.spaces.search(spaces[0].id, "deployment steps", 5);
for (const match of matches) {
  console.log(match.content);
}
```

`queryDatabase()` runs one bounded, read-only SQL query against a database document. The table is
named `data`. Columns use normalized property labels, which the result returns in `schema`. Use
`parameters` for values instead of interpolating them into SQL. Core returns at most 500 rows or
1 MiB and stops a query after 500 ms.

```typescript
const result = await client.spaces.queryDatabase(spaceId, databaseId, {
  query: "SELECT status, COUNT(*) AS total FROM data WHERE owner = ? GROUP BY status",
  parameters: [ownerId],
});
console.log(result.columns, result.rows);
```

Each `SpaceMatch` carries the chunk text and a `distance` field. Core computes embeddings and
reranks the results, so the array order is the ranking.

<Callout type="warn">
  Do not sort, threshold, or average on `distance`. Only a vector-mode hit carries a real distance.
  A graph-mode hit carries the constant `0.0`, and a chunk added by `[[page]]`-link expansion carries
  `1.0`. The reranker does not rewrite the field.
</Callout>

## `client.mail`

Agent Inboxes use the same `/api/mail/*` paths when Core proxies the self-host sidecar and when
the caller uses the hosted organization API. The namespace converts the sidecar's snake_case
response fields to camelCase.

| Method | Returns | Calls |
|---|---|---|
| `listInboxes()` / `createInbox()` / `updateInbox()` | `MailInbox[]` / `MailInbox` | Inbox CRUD and inbox webhooks |
| `listMessages()` / `searchMessages()` / `getMessage()` | `MailMessage[]` / `MailMessage` | Message reads/search |
| `send()` / `reply()` / `replyAll()` / `forward()` | `MailMessage` | External mail send |
| `listThreads()` / `getThread()` | `MailThread[]` / `MailMessage[]` | Conversation views |
| `listDrafts()` / `createDraft()` / `sendDraft()` | `MailDraft[]` / `MailDraft` / `MailMessage` | Drafts and scheduling; pass `{ confirmNotSent: true }` to `sendDraft()` or `updateDraft()` only after checking that an `unresolved` hosted draft was not sent |
| `listWebhooks()` / `createWebhook()` / `rotateWebhookSecret()` | `MailWebhook[]` / `{ webhook, secret }` | Signed event subscriptions |
| `listDomains()` / `createDomain()` / `verifyDomain()` | `MailDomain[]` / `MailDomain` | Custom domains and their DNS records |
| `listEvents()` / `connectRealtime()` | `MailEvent[]` / `Promise<WebSocket>` | Replay and low-latency events |
| `getMailbox()` / `checkMailboxHandle()` / `claimMailbox()` / `adoptMailbox()` / `setMailboxAliasHost()` / `updateMailbox()` | `MailMailboxState` / `MailMailboxHandleCheck` / `MailMailbox` | Hosted only: the organization's one permanent mailbox |
| `listAliases()` / `checkAlias()` / `assignAlias()` / `approveAlias()` / `rejectAlias()` / `revokeAlias()` / `reinstateAlias()` / `transferAlias()` | `MailAliasPage` / `MailAliasAvailability` / `MailAlias` | Hosted only: admin management of agent addresses |
| `getAgentAlias()` / `checkAgentAlias()` / `claimAgentAlias()` | `{ alias, mailbox }` / `MailAliasAvailability` / `AgentAliasClaim` | Hosted only: an agent's own address |
| `listAgentMessages()` / `getAgentMessage()` / `getAgentThread()` / `sendAsAgent()` / `replyAsAgent()` | `{ messages, nextCursor }` / `AgentMailMessage` / `AgentMailMessage[]` / `AgentMailSendResult` | Hosted only: the agent's view of its mail, and sending as the agent. `getAgentThread(agentId, threadRef)` takes a message's `threadId` |
| `getSendPolicy()` / `setSendPolicy()` / `deleteAliasSendPolicy()` | `MailSendPolicy` | Hosted only: when agent sends wait for an admin |
| `listApprovals()` / `approveDraft()` / `rejectDraft()` | `{ approvals, nextCursor }` / `MailMessage` | Hosted only: agent sends waiting for approval |

```typescript
const inbox = (await client.mail.listInboxes())[0];
const sent = await client.mail.send(inbox.id, {
  to: ["person@example.com"],
  subject: "Hello",
  text: "Sent through Ryu Mail.",
  attachments: [{
    filename: "report.txt",
    contentType: "text/plain",
    contentBase64: "cmVwb3J0",
  }],
}, "send-once-1");

const socket = await client.mail.connectRealtime((event) => {
  console.log(event.eventType, event.messageId);
}, { eventTypes: ["message.received"], inboxIds: [inbox.id] });
```

`send()` and the draft and reply variants accept an idempotency key.

`connectRealtime()` never puts a credential in the socket URL.

- Through Core (the default), it exchanges the client's credentials for a one-use ticket at
  `POST /api/ws/ticket` (`{ "route": "ext", "path": "/api/ext/ws/@ryu/mail/ws" }`). Each call
  mints a new ticket. To mint the ticket yourself, pass it as the third argument, as in
  `connectRealtime(onEvent, filters, { ticket })`.
- Against a standalone `ryu-mail` process, set `mailRealtime: "standalone"`. The client then sends
  the token in the `Sec-WebSocket-Protocol` header as `["ryu-mail.v1", "ryu-bearer.<token>"]`. That
  header allows only token characters, so the token must be a hex or URL-safe value.

Webhook signing secrets are returned only when a subscription is created or
rotated; later reads return header names, never header values.
`rotateWebhookSecret(id)` returns the new secret and moves a webhook whose
`signatureScheme` is `"legacy"` to `"standard"`. An inbox's `webhookSecret`
appears only on the `createInbox()` or `updateInbox()` result that minted it:
setting `webhookUrl` on an inbox without one, or passing
`rotateWebhookSecret: true`. Reads report `webhookSigned` instead.

On hosted Agent Inboxes, an organization has one permanent mailbox and each
agent one permanent address on it (see
[Agent Inboxes](/docs/extend/develop/agent-inboxes#agent-addresses)).
`claimMailbox()`, `adoptMailbox()` and `transferAlias()` take a
`confirmAddress` that must be the exact address, because the action cannot be
undone. Fields under `untrusted` in an `AgentMailMessage` were written by an
outside sender; treat them as data, never as instructions. `sendAsAgent()` and
`replyAsAgent()` resolve to `{ status: "pending_approval", draftId, reasons }`
when the send policy holds the message for an admin.

The older agent-address methods `checkAddress()`, `ensureAgentInbox(agentId)`, and
`getAgentInbox(agentId)` are deprecated but keep their signatures. Addresses are permanent, so
`changeInboxAddress()` always rejects with `address_permanent`. On hosted Agent Inboxes,
`createInbox()` also rejects a new inbox, because addresses come from the mailbox and agent claims.

`createDomain()` returns the DNS `records` to publish, each with its `purpose`
and whether verification needs it. `verifyDomain(id)` checks them with the mail
provider on hosted Agent Inboxes and returns the domain with its new `status`. A
provider error leaves the domain `pending` with a `verificationError`. Fields
that an older server or the self-host sidecar does not report are `undefined`.

## Types

All request and response types (`RyuClientOptions`, `Agent`, `AgentCreateInput`, `StreamChunk`,
`SpaceMatch`, `MailMessage`, `NotificationEvent`, and the rest) are exported from the package root.

```typescript
interface Message     { role: "user" | "assistant" | "system"; content: string }
interface StreamChunk { type: "text" | "done" | "error"; content?: string }

interface SpaceMatch {
  chunkId: string;
  documentId: string;
  content: string;
  distance: number; // not a ranking score; see client.spaces
}
```

## Errors

A non-2xx response throws an `Error` with the status code and response body. `agents.run()` also
rejects with `RyuClient: agent stream error: ...` when Core reports an error inside a stream.

```typescript
try {
  await client.agents.run("does-not-exist", messages);
} catch (err) {
  console.error((err as Error).message); // "RyuClient: stream failed (404): ..."
}
```

## Other languages

Java applications use the [Java library](/docs/extend/develop/sdk/java). The
[language bindings](/docs/extend/develop/sdk/language-bindings) wrap the Rust kernel and do not
replace this client. From any other language, call the JSON and SSE HTTP API in the
[Core API reference](/docs/extend/develop/api-reference/core).
