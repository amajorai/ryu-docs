`@ryuhq/core-client` (`packages/core-client/`) is the typed HTTP client that every first-party Ryu
surface uses to talk to a running Core node. It lists and installs plugins, manages agents,
models, skills, MCP (Model Context Protocol) servers, Spaces, and workflows, and reads Gateway
status.

[`@ryuhq/sdk`](/docs/extend/develop/sdk) authors Runnables and packs them into a plugin.
`@ryuhq/core-client` operates a Core node. Its functions call the same endpoints as the Desktop
Store and Settings panels.

## Which client does each surface use?

Every Ryu client app talks to the same Core HTTP API on the active node. They differ in which
package carries that traffic:

| Surface | Core HTTP layer | Why |
|---|---|---|
| **Desktop** | `@ryuhq/core-client` (plus an app-local HTTP helper for identity and session headers) | Runs on or beside a local node whose token is readable from disk. Shares one typed client keyed to `{ url, token }` |
| **`ryu-cli`** | `@ryuhq/core-client` | Commands such as `list`, `add`, `enable`, and `disable` wrap `@ryuhq/core-client` domain modules |
| **Mobile app** | `@ryuhq/core-client` | React Native has `fetch` and `WebSocket` and no browser CORS, so it calls the selected node (LAN IP or cloud URL) directly |
| **Web app** | `@ryuhq/core-client` | Shares the desktop React tree, so it inherits the same client |
| **Browser extension** | Browser-safe `@ryuhq/core-client` modules and extension HTTP adapters | The shared dashboard uses browser-safe modules; content scripts reach Core through the MV3 background worker |

## React Native / Expo

React Native is a supported target. For normal JSON calls, pass `{ url, token }`. For Expo response
streaming, add `expo/fetch` to the target:

```tsx
import { fetch as expoFetch } from "expo/fetch";
import { fetchAgents } from "@ryuhq/core-client/agents";
import type { ApiTarget, RyuFetch } from "@ryuhq/core-client/client";

const target: ApiTarget = {
  url: "http://192.168.1.10:7980",
  token: nodeToken,
  fetch: expoFetch as RyuFetch,
};

const agents = await fetchAgents(target);
```

Store `nodeToken` with `expo-secure-store`. The token belongs to the selected Core node. Never
replace it with an OpenAI, Anthropic, or other provider key.

The mobile app imports the shared domain modules directly (`@ryuhq/core-client/agents`,
`/plugins`, `/models`, `/skills`, `/mcp`, `/spaces`, `/workflows`, `/meetings`, and others), tags
each request `X-Ryu-Surface: mobile`, and reaches the node the user selects. `localhost` works only
as an emulator loopback, never on a real device.

The mobile app's web build is a browser page, so its requests to the Ryu control plane are
cross-origin and carry the same `X-Ryu-Surface` header. The control plane allows that header in
CORS preflights from the origins it accepts. Other origins are refused.

## Browser extension connections

The extension reuses browser-safe Core client modules and response schemas, including in its
shared dashboard. It does not use Node-only local token helpers such as `resolveLocalNodeToken`,
which read from disk. Pair with a node explicitly and supply its saved `{ url, token }` instead.

Content scripts use the MV3 background worker for Core HTTP calls. The worker's declared host
permissions allow those requests without depending on the page's origin or CORS policy. Extension
HTTP adapters and shared modules use the same Core API and node credentials. The browser bridge
also carries the current signed-in member identity when required.

## Install and target

```bash
bun add @ryuhq/core-client
```

Every domain function takes an `ApiTarget`.

```typescript
import { fetchApps, installApp } from "@ryuhq/core-client/plugins";
import { fetchAgents } from "@ryuhq/core-client/agents";
import { fetchGatewayStatus } from "@ryuhq/core-client/gateway";

const target = { url: "http://localhost:7980", token: process.env.RYU_TOKEN };

const apps = await fetchApps(target);
const status = await fetchGatewayStatus(target);
```

## Agent identifiers

Pass raw agent IDs to the functions in `@ryuhq/core-client/agents`. The client
encodes IDs as a single URL path segment, so IDs containing `:`, `/`, `%`, `?`,
or `#` cannot change the destination endpoint. Do not pre-encode an ID. The
standalone IDs `.` and `..` are rejected before sending a request because URL
parsers treat them as directory navigation.

## Root exports

The package root exports the HTTP primitives and the backups module (`packages/core-client/src/index.ts`).
Import every other domain module by subpath.

| Export | Purpose |
|---|---|
| `ApiTarget` | `{ url, token, fetch?, userJwt? }`, the target every domain call is keyed to |
| `RyuFetch` | the `fetch` signature a target can override |
| `request(target, path, options, responseCodec)` | JSON `fetch` wrapper that parses the response with the supplied Zod codec |
| `RequestOptions` | `method`, `headers`, `body`, and `signal` for `request` |
| `apiUrl(target, path)` | resolves a path against a target |
| `fetchForTarget(target)` | returns the target's `fetch`, or the global `fetch` |
| `makeHeaders(token, userJwt?)` | builds headers with the bearer, user JWT, and surface |
| `SURFACE_HEADER` | the `X-Ryu-Surface` request header name |
| `setSurfaceProvider(fn)` | wires the calling surface name once at app entry |
| `BUYER_TOKEN_HEADER`, `buyerTokenHeader` | the `X-Ryu-Buyer-Token` header for paid marketplace installs |
| `setBuyerTokenProvider(fn)` | wires the marketplace buyer token, if any |

Every direct `request` call must supply a response codec as its fourth argument.
Use the domain modules below when they already cover your endpoint. For a new
endpoint, provide a Zod codec for its complete response contract. An endpoint
that returns an empty body needs a codec that accepts `undefined`. Pass
`undefined` for `options` when no request options are needed. An invalid response
fails parsing instead of being returned under an unchecked TypeScript type.

Validate the endpoint's actual fields and nested values. A permissive codec or a
TypeScript assertion does not establish that a response follows its contract.

Core filters its plugin list, catalog, and contributions by the `X-Ryu-Surface` header to what runs
on the calling surface. Each app wires it once at entry, for example
`setSurfaceProvider(() => "cli")`. Values include `"desktop"`, `"cli"`, `"mobile"`, and
`"extension"`. A request without the header gets an unfiltered list.

### Space search results

`SpaceMatch.distance` is `number | null`, matching Core's response. Preserve `null`
when no numeric distance is available. Display results in the returned order:
reranking can change that order without changing distances, and graph or linked
document matches can carry placeholder distances. Do not sort, average, or apply
a relevance threshold using this field.

## Embedded agent chat: @ryuhq/client

To embed agent chat in an app (list agents, stream a turn, read sessions, search Spaces), use the
smaller [`@ryuhq/client`](/docs/extend/develop/sdk/client). It has `agents`, `sessions`, `harness`,
`spaces`, and `mail` namespaces plus an optional `notify` namespace.

## Which SDK when?

| Job | Package |
|---|---|
| Author Runnables, pack and publish a plugin | [`@ryuhq/sdk`](/docs/extend/develop/sdk) |
| Operate a Core node (plugins, agents, models, ...) | `@ryuhq/core-client` |
| Embed agent chat in an app | [`@ryuhq/client`](/docs/extend/develop/sdk/client) |
| Validate against the exact Rust rules | `@ryuhq/sdk-native` (used by `@ryuhq/sdk` internally) |

For why Core operates nodes and the Gateway governs model traffic, see
[Core vs Gateway](/docs/start-here/architecture/core-vs-gateway).
