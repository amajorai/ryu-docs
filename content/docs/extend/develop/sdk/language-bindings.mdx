Ryu's SDK has one shared Rust kernel. It owns the `manifest.json` model,
validation, Gateway egress rules, and Gateway-required model and embedding
clients. Language bindings wrap that kernel instead of reimplementing those
rules in each language.

This page covers the native binding projects under `bindings/` and their shared
source at `crates/sdk/uniffi/` or `crates/sdk/ffi/`. For TypeScript authoring,
see [TypeScript SDK](/docs/extend/develop/sdk); for calling a running Core node,
see [Client SDK](/docs/extend/develop/sdk/client) and
[Core client](/docs/extend/develop/sdk/core-client).

<Callout type="info">
  Every language project contains a no-network example and contract tests. The
  examples validate a plugin id, enforce Gateway-only egress, and construct a
  Gateway-pointed client. They do not require provider credentials. The Rust
  SDK transport tests use a local one-shot HTTP server for chat and embeddings.
</Callout>

## Architecture

There are three binding mechanisms around the same `ryu-sdk` kernel:

| Binding | Languages | Surface | Status |
|---|---|---|---|
| `crates/sdk/napi` | TypeScript / JavaScript | Manifest rules, egress, chat, streaming, embeddings | Shipped; smoke-tested through the package loader |
| `crates/sdk/ffi` | C and Go through cgo | Blocking manifest, egress, chat, and embeddings | Shipped; Go has unit tests and an example |
| `crates/sdk/uniffi` | Python, Swift, Kotlin | Manifest rules, egress, blocking chat/embeddings, streaming through `ChatSink` | Generated and tested in the language projects |
| `crates/sdk/uniffi` + `uniffi-bindgen-cs` | C# | The same UniFFI surface, including `ChatSink` | Generated and smoke-tested in the example project |

The Rust implementation is the source of truth. `uniffi::setup_scaffolding!`
and `#[uniffi::export]` define the foreign surface; the generated files are
build outputs and are not hand-edited.

## Shared API

The generated bindings expose these operations:

- `validatePluginId` / `validate_plugin_id`
- `parseAndValidateManifest` / `parse_and_validate_manifest`
- `pluginManifestJsonSchema` / `plugin_manifest_json_schema`
- `resolveGatewayUrl` and `resolveGatewayToken`
- `assertAllowedEgress` / `assert_allowed_egress`
- `ModelClient` with `chat` and `stream`
- `EmbeddingClient` with `embed`

The exact naming follows each language's generator. `ModelClient` and
`EmbeddingClient` reject direct provider URLs during construction. Provider
credentials belong in the Gateway; a binding token is a Gateway token.

Streaming uses the UniFFI `ChatSink` callback interface. A sink receives zero or
more deltas and then exactly one `onDone` or `onError` callback. A callback must
return before it calls another blocking SDK method; this avoids re-entering the
binding's Tokio runtime.

## Python

The Python project is under `bindings/python/`. Its generated `ryu_sdk/`
package is loaded by `__init__.py`; the generated module and native library are
created by the test command.

```sh
bash bindings/python/test.sh
```

This runs `test_sdk.py`, `smoke_test.py`, and `example.py`. The import name is
`ryu_sdk` and the distribution shell is named `ryu-sdk`.

## Go

The Go project is under `bindings/go/`. It uses the hand-written C ABI in
`crates/sdk/ffi`, which keeps Go independent of third-party UniFFI generator
version lag. The binding includes lifecycle methods and JSON-returning
`ModelClient` / `EmbeddingClient` methods.

```sh
bash bindings/go/test.sh
```

The command builds the Rust FFI, runs `ryusdk_test.go`, and runs
`example/main.go`.

## C#

The C# project is under `bindings/csharp/`. The generated source is produced by
the version-matched `uniffi-bindgen-cs` generator. The pinned generator version
is `v0.9.2+v0.28.3` for the UniFFI `0.28.3` dependency.

```sh
cargo install uniffi-bindgen-cs \
  --git https://github.com/NordSecurity/uniffi-bindgen-cs \
  --tag v0.9.2+v0.28.3
bash bindings/csharp/test.sh
```

`Program.cs` is the no-network example and smoke test. The generated source and
native library remain ignored build outputs.

## Swift

The Swift Package example is under `bindings/swift/`. It includes an executable
target and XCTest target. The generated `RyuSdk.swift` file is produced from the
same UniFFI library.

```sh
bash bindings/swift/test.sh
```

The current script targets macOS because it links the macOS Rust dynamic
library. The package exposes `ChatSink` for streaming and the same manifest,
egress, model, and embedding operations as Python and Kotlin.

## Kotlin

The Gradle/JVM example is under `bindings/kotlin/`. UniFFI generates the Kotlin
source and JNA provides the JVM bridge.

```sh
bash bindings/kotlin/test.sh
```

The command runs the JUnit tests and the no-network example with JDK 17 or
newer. The example targets the JVM; Android packaging and native ABI delivery
remain host integration work, not a second Ryu contract.

## TypeScript and NAPI

The authoring package (`@ryuhq/sdk`) and the Core client (`@ryuhq/client`) have
their own Bun test suites. The NAPI addon smoke uses the same `index.js` loader
that consumers use, so platform-specific `.node` filenames are tested through
the normal resolution path:

```sh
(cd crates/sdk/napi && bun test)
(cd packages/sdk && bun test)
(cd packages/client && bun test)
```

The NAPI binding retains callback streaming because Node-API can bridge a
per-invocation callback directly. The UniFFI bindings use `ChatSink` so Swift,
Kotlin, Python, and C# have an explicit cross-thread lifetime contract.

## CI coverage

`.github/workflows/sdk-bindings.yml` runs the structural matrix check and
language jobs for Python, Swift, Kotlin, Go, C#, and NAPI. The main CI workflow
also runs the Core, Gateway, Web, Fumadocs, Native, Desktop, CLI, server, and
package test tasks. The matrix is a test gate; it does not claim a provider
round-trip or a store publication.
