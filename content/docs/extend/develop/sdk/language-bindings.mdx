---
title: "Libraries and bindings"
description: Use a Ryu client library from your app, or embed the shared Rust kernel through a generated binding.
---

There are two different integration jobs:

1. **Call Ryu from an application.** Use a client library. It sends normal HTTP and JSON requests
   to a running Core node.
2. **Embed the shared Rust kernel.** Use a generated binding. It exposes manifest validation,
   Gateway egress checks, model calls, and embeddings, but it does not run Core for you.

If you are unsure, use the client library first. You do not need a Rust toolchain or a generated
binding just to call an agent.

## Choose your library

| Application | Start with | Package/install |
|---|---|---|
| TypeScript or JavaScript | Embedded chat | [`@ryuhq/client`](/docs/extend/develop/sdk/client) |
| React Native or Expo | Embedded chat | [`@ryuhq/client`](/docs/extend/develop/sdk/client) with `expo/fetch` for streaming |
| React Native or Expo | Full Core control | [`@ryuhq/core-client`](/docs/extend/develop/sdk/core-client) |
| Java 17+ | Core client | [`com.ryu:ryu-client`](/docs/extend/develop/sdk/java) |
| Rust | Kernel or Gateway model client | [`ryu-sdk`](/docs/extend/develop/sdk/rust) |
| Python, Swift, Kotlin, or C# | Rust-kernel surface | `ryu-sdk-uniffi` generated binding |
| C or Go | Rust-kernel surface | `ryu-sdk-ffi` C ABI |

## React Native / Expo

Ryu's React Native integration is a TypeScript library, not a Node-API addon. The first-party
mobile app uses `@ryuhq/core-client` directly. The package has no React or platform dependency, so
you provide the selected node target from your app.

For list, create, and management calls:

```tsx
import { fetchAgents } from "@ryuhq/core-client/agents";
import type { ApiTarget } from "@ryuhq/core-client/client";

const target: ApiTarget = {
  url: "http://192.168.1.10:7980",
  token: nodeToken,
};

const agents = await fetchAgents(target);
```

For embedded chat with Expo's streaming implementation:

```tsx
import { fetch as expoFetch } from "expo/fetch";
import { createRyuClient, type RyuFetch } from "@ryuhq/client";

const client = createRyuClient({
  baseUrl: "http://192.168.1.10:7980",
  token: nodeToken,
  fetch: expoFetch as RyuFetch,
});

const reply = await client.agents.run("pi", [
  { role: "user", content: "Hello from Expo." },
]);
```

Store `nodeToken` with `expo-secure-store`. A node token grants access to that Core node; it is not
a provider key. Never put an OpenAI, Anthropic, or other provider key in the mobile bundle.

## Java

Java application developers should use the high-level Maven library:

```xml
<dependency>
  <groupId>com.ryu</groupId>
  <artifactId>ryu-client</artifactId>
  <version>0.2.5</version>
</dependency>
```

```java
import com.ryu.sdk.RyuClient;
import java.util.List;

try (var ryu = new RyuClient("http://127.0.0.1:7980", nodeToken)) {
  var reply = ryu.run(
      "pi",
      List.of(RyuClient.Message.user("Hello from Java.")));
}
```

The source library is in `bindings/java`; run `mvn install` there when using a checkout. Its
verification command is:

```bash
bash bindings/java/test.sh
```

See the
[Java library guide](/docs/extend/develop/sdk/java) for streaming and Spaces.

## Kernel bindings

These targets are generated from the same Rust export. They are the right choice when your app
needs the kernel's local validation or Gateway model/embedding client, rather than Core's broader
HTTP API.

The generated surface is:

| Operation | Purpose |
|---|---|
| `validate_plugin_id` | Check a plugin identifier |
| `parse_and_validate_manifest` | Parse and validate a `manifest.json` string |
| `plugin_manifest_json_schema` | Get the Rust-derived JSON Schema |
| `resolve_gateway_url` / `resolve_gateway_token` | Read Gateway connection defaults |
| `assert_allowed_egress` | Reject direct-provider URLs |
| `ModelClient` | Gateway-routed chat and streaming |
| `EmbeddingClient` | Gateway-routed embeddings |

The generated files are build outputs. The source of truth is `crates/sdk/uniffi`; do not hand-edit
generated language code.

## Python

```bash
bash bindings/python/test.sh
```

```python
import ryu_sdk

ryu_sdk.validate_plugin_id("io.example.plugin")
client = ryu_sdk.ModelClient("gemma4", None, None)
reply = client.chat([ryu_sdk.ChatMessage("user", "Hello from Python.")])
print(reply.content)
```

## Kotlin

The generated Kotlin package is callable from Kotlin or Java, but the application-facing Java
library above is easier for Core HTTP access. Use this binding only when you need the Rust-kernel
surface:

```bash
bash bindings/kotlin/test.sh
```

## Swift

```bash
bash bindings/swift/test.sh
```

The Swift package uses the same `ModelClient`, `EmbeddingClient`, manifest,
and egress operations. Streaming is callback-based through `ChatSink` because
UniFFI cannot export a language-neutral closure.

## C#

```bash
bash bindings/csharp/test.sh
```

The C# package uses the same `ModelClient`, `EmbeddingClient`, manifest, and
egress operations. It uses the version-matched third-party UniFFI generator.

## C

`ryu-sdk-ffi` is the maintained C ABI. The generated header is in
`crates/sdk/ffi/include/ryu_sdk.h` in the hub. Returned strings are owned by
the library and must be released with the matching `*_free` functions.

## Node-API

`@ryuhq/sdk-native` is the Node-API implementation detail used by
`@ryuhq/sdk`. Application code should install `@ryuhq/sdk` rather than loading
the addon directly.

```bash
(cd crates/sdk/napi && bun test)
```

## Go

`ryu-sdk-ffi` is the maintained C ABI. Go uses it through cgo:

```bash
bash bindings/go/test.sh
```

The C ABI owns returned strings and exposes explicit `*_free` functions. See the generated
[`include/ryu_sdk.h`](https://github.com/amajorai/ryu-sdk/blob/main/crates/sdk/ffi/include/ryu_sdk.h)
when writing a non-Go consumer.

## Testing boundary

The binding examples use local fixtures and do not require provider credentials. Core and Gateway
remain separate processes with their own configuration; a binding call cannot create a node or
replace Core's permissions, routing, approvals, or audit policy. The CI matrix
for these projects is defined in `.github/workflows/sdk-bindings.yml`.
