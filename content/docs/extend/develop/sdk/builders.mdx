## Builders and manifest schemas

To declare a `manifest.json` in code, the SDK exports a fluent `PluginBuilder` plus per-kind
builders (`agent()`, `workflow()`, `tool()`, `skill()`) and their builder classes
(`AgentBuilder`, `WorkflowBuilder`, `ToolBuilder`, `SkillBuilder`) from `.`.

```typescript
const manifest = new PluginBuilder()
  .id("com.example.my-plugin")
  .name("My Plugin")
  .version("1.0.0")
  .runnable(agent().id("agent-main").name("Main Agent").build())
  .grant("mcp:web_search")
  .build();
```

The Zod schemas and helpers behind the builders are also exported:

| Export | Purpose |
|---|---|
| `PluginManifestSchema` | full `manifest.json` schema (also at `./manifest`) |
| `RunnableKindSchema` | enum of the six packable kinds (`agent`, `workflow`, `tool`, `skill`, `companion`, `policy`) |
| `RunnableMetaSchema` | per-runnable metadata block |
| `CompanionSurfaceSchema` | optional Companion surface declaration |
| `coreManifestJsonSchema` | the manifest as a plain JSON Schema |
| `validateManifestStrict(manifestJson)` | validates a manifest string with Core's rules and returns the normalized JSON, or throws |
| `validatePluginId(id)` | checks Core's reverse-domain plugin-id rules, or throws |

`RunnableKindSchema` lists the kinds `ryu pack` accepts (`packages/sdk/src/manifest.ts`). Core
validates all eight `RunnableKind` variants. `coreManifestJsonSchema`, `validateManifestStrict`, and
`validatePluginId` call the `@ryuhq/sdk-native` addon. The manifest schema itself is documented on
[Plugin manifests](/docs/extend/develop/extensions/plugin-json-manifest).

## MCP bridge

The SDK can expose your Runnables as MCP tools and call other MCP servers
(`packages/sdk/src/mcp/`). The wire format is JSON-RPC 2.0 over newline-delimited stdio.
`MCP_PROTOCOL_VERSION` is `2026-07-28`. The client probes with `server/discover`, then falls back
to the legacy `initialize` handshake at `MCP_LEGACY_PROTOCOL_VERSION` (`2024-11-05`).

`McpServer` is a stdio JSON-RPC server. `register()` advertises a local executable as a tool.
`passthrough()` forwards `tools/list` and `tools/call` to an upstream MCP stdio server (for example
Ghost) and re-advertises its tools verbatim. If the upstream is down, the server still serves its
local tools.

```typescript
const server = new McpServer()
  .register({ name: "greet", run: () => Promise.resolve("Hello!") })
  .passthrough({ command: { command: "ghost" }, label: "ghost" });

await server.serve();   // reads stdin, writes stdout until EOF
```

The stateless client functions spawn a server, complete the handshake, make one call, and tear the
process down:

```typescript
function listTools(cmd: McpStdioCommand): Promise<McpTool[]>;
function callTool(cmd: McpStdioCommand, tool: string, args: unknown): Promise<unknown>;
```

`callTool` returns the full `tools/call` result object (`{ content: [{ type, text }], isError? }`).
Read `.content[0].text` for the plain output, or call `unwrapContent` to decode the first text block
(it parses the text as JSON when it can).

<Callout type="info">
  The SDK MCP server and client implement no tool approval or policy. Approval stays in the chat
  layer and policy stays in the Gateway. See
  [Core vs Gateway](/docs/start-here/architecture/core-vs-gateway).
</Callout>

## definePlugin

`definePlugin` assembles a complete `manifest.json` from typed options
(`packages/sdk/src/runnable/turn-hook.ts`). The `./plugin` subpath exports a different
`definePlugin` for runtime plugin modules (`packages/sdk/src/plugin/ryu-plugin.ts`).

```typescript
function definePlugin(options: DefinePluginOptions): PluginManifest;
```

| Option | Type | Purpose |
|---|---|---|
| `id` | `string` | Reverse-domain plugin id (e.g., `"com.example.my-plugin"`) |
| `name` | `string` | Display name |
| `version` | `string` | Semver version |
| `grants` | `string[]` | Permission grants the plugin needs |
| `tools` | `ToolRunnable[]` | Tools to include (auto-adds `tool:execute` grant) |
| `turnHooks` | `TurnHookContribution[]` | Turn hooks to include |
| `hookEvents` | `HookEventContribution[]` | App events the plugin emits; each `id` is namespaced to the plugin `id` |
| `lspServers` | `Record<string, object>` | Language servers, keyed by server name, passed verbatim |
| `composerControls` | `Record<string, unknown>[]` | Chat composer toggles |
| `settingsTabs` | `Record<string, unknown>[]` | Settings UI tabs |
| `slashCommands` | `SlashCommandContribution[]` | Custom `/` commands |
| `activationEvents` | `string[]` | Wake events (default `["*"]`) |
| `requires` | `DefineAppRequires` | Required plugins (enabled first), capability edges, and implied grants |
| `targets` | `Surface[]` | Target surfaces (empty means every surface) |

`inlineToolRunnable()` converts each `ToolRunnable` into a `kind:"tool"` runnable with
`backend: "inline_js"` config for Core's sandbox. Older manifests declare `backend: "inline_deno"`.
Core still loads them as `inline_js` and logs a deprecation warning, so new manifests use
`inline_js`.

```typescript
import { definePlugin, defineTool } from "@ryuhq/sdk";

const searchTool = defineTool({
  id: "web-search",
  name: "Web Search",
  schema: {
    type: "object",
    properties: { query: { type: "string", description: "Search query" } },
    required: ["query"],
  },
  run: async ({ query }) => {
    const result = await fetch(`https://api.example.com/search?q=${encodeURIComponent(query)}`);
    return result.json();
  },
});

export default definePlugin({
  id: "com.example.search",
  name: "Search Plugin",
  version: "1.0.0",
  grants: ["tool:execute"],
  tools: [searchTool],
});
```

## defineApp

`defineApp` assembles a manifest for a widget app: a plugin whose tool results render as
interactive widgets in chat (`packages/sdk/src/runnable/app.ts`).

```typescript
function defineApp(options: DefineAppOptions): PluginManifest;
```

| Option | Type | Purpose |
|---|---|---|
| `id` | `string` | Plugin id |
| `slug` | `string` | URL-safe slug for widget templates |
| `title` | `string` | Display title |
| `version` | `string` | Semver version |
| `uiEntry` | `string` | Source entry for widget UI |
| `tools` | `AppToolSpec[]` | Render + companion tools |
| `tools[].runnable` | `ToolRunnable` | Optional executable body, packed as Core `inline_js` |
| `grants` | `string[]` | Permission grants |
| `displayMode` | `string` | `"inline"`, `"fullscreen"`, or `"pip"` |
| `server` | `string` | MCP server namespace for tool ids (default `slug`) |
| `mime` | `string` | Widget MIME dialect (default `text/html+skybridge`) |
| `slashCommands` | `SlashCommandContribution[]` | Custom `/` commands |
| `activationEvents` | `string[]` | Wake events (default `["*"]`) |
| `requires` | `DefineAppRequires` | Required plugins, capability edges, and implied grants |
| `targets` | `Surface[]` | Target surfaces (empty means every surface) |

A render tool (`accessible` unset or false) gets a `contributes.widgets[]` entry that binds its id
to `ui://widget/<slug>.html`. A companion tool (`accessible: true`) is a call target for a mounted
widget. It gets `widget_accessible: true` and no widget template.

When a tool carries `runnable: defineTool(...)`, its body is embedded in the same manifest as an
`inline_js` backend and `tool:execute` is added automatically. The body runs in Core's
deny-by-default sandbox; use the injected `host` capabilities for Gateway-routed model work.

```typescript
import { defineApp } from "@ryuhq/sdk";

export default defineApp({
  id: "com.example.chart",
  slug: "chart",
  title: "Chart Widget",
  version: "1.0.0",
  uiEntry: "src/widget.html",
  tools: [
    { name: "render_chart", description: "Render a chart from data" },
    { name: "chart_data", description: "Get chart data", accessible: true },
  ],
});
```

## defineFunctionHook

`defineFunctionHook` opts a hook into Core's middleware chain and emits `"mode": "middleware"`.
The third argument is a `next(ctx)` continuation. The continuation is sandbox-mediated and reaches
only lower-priority middleware hooks, so a plugin never receives another plugin's host
capabilities or code.

```typescript
function defineFunctionHook(options: DefineFunctionHookOptions): TurnHookContribution;
```

```typescript
import { defineFunctionHook, definePlugin } from "@ryuhq/sdk";

export default definePlugin({
  id: "com.example.redact",
  name: "Redact Tool Results",
  version: "1.0.0",
  turnHooks: [
    defineFunctionHook({
      id: "redact.http",
      on: "tool_result",
      match: { tools: ["http*"] },
      run: async (ctx, _host, next) => {
        const result = await next(ctx);
        if (result.kind !== "transform") return result;
        return {
          kind: "transform",
          output: { ...(result.output as Record<string, unknown>), secret: "[redacted]" },
        };
      },
    }),
  ],
});
```

Use `defineTurnHook` for independent directives. Use `defineFunctionHook` when a hook needs to
short-circuit, rewrite the context passed downstream, or inspect and wrap a downstream result.
In a hand-authored manifest, omit `mode` for directive behavior, or set `"mode": "middleware"` for
the same behavior as `defineFunctionHook`.

## defineTurnHook

`defineTurnHook` creates a turn hook. By default it runs after each assistant turn
(`packages/sdk/src/runnable/turn-hook.ts`). The `run` function is serialized into the sandbox
`code` string, so it must be self-contained and cannot capture outer variables.

```typescript
function defineTurnHook(options: DefineTurnHookOptions): TurnHookContribution;
```

| Option | Type | Purpose |
|---|---|---|
| `id` | `string` | Hook id |
| `on` | `string` | Phase (default: `"post_assistant_turn"`) |
| `priority` | `number` | Higher-priority hooks run first |
| `match` | `HookMatch` | Optional Rust-evaluated pre-gate |
| `run` | `HookRun` | The hook function |

The hook function receives `ctx` (turn context) and `host` (capability bridge):

```typescript
import { definePlugin, defineTurnHook } from "@ryuhq/sdk";

export default definePlugin({
  id: "com.example.double-check",
  name: "Double Check",
  version: "1.0.0",
  grants: ["hook:side-model"],
  turnHooks: [
    defineTurnHook({
      id: "dc.review",
      run: async (ctx, host) => {
        if (!ctx.flags["com.example.double-check"]) {
          return { kind: "none" };
        }
        const last = ctx.transcript.at(-1);
        const review = await host.sideModel({
          prompt: last?.content ?? "",
          model_pref_key: "double-check-model",
        });
        return { kind: "note", text: review };
      },
    }),
  ],
});
```
