---
title: "SDK libraries and bindings"
description: "Choose the Ryu library for your application, or the authoring SDK for building plugins and apps."
---

Most developers should start with a library, not a generated binding. A library calls a running
Ryu Core node with normal types from your language. The authoring SDK is for creating things that
Ryu installs or runs. The lower-level bindings are for embedding the shared Rust kernel itself.

## Choose your path

| You are building... | Use | What it does |
|---|---|---|
| A Ryu plugin, app, tool, workflow, or skill | [`@ryuhq/sdk`](/docs/extend/develop/sdk) | Author and package Ryu extensions in TypeScript |
| A TypeScript or React Native app with embedded chat | [`@ryuhq/client`](/docs/extend/develop/sdk/client) | List agents, stream chat, read conversations, and search Spaces |
| A TypeScript or React Native app that manages Core | [`@ryuhq/core-client`](/docs/extend/develop/sdk/core-client) | Use typed agents, models, plugins, skills, MCP, Spaces, workflows, and Gateway calls |
| A Java app that calls Core | [Java library](/docs/extend/develop/sdk/java) | Use `com.ryu:ryu-client` with Java 17 and Maven |
| A Rust app that embeds the kernel | [Rust SDK](/docs/extend/develop/sdk/rust) | Use manifest, egress, model, and embedding primitives directly |
| A Python, Swift, Kotlin, C#, C, or Go app that embeds the kernel | [Language bindings](/docs/extend/develop/sdk/language-bindings) | Use the generated or C-ABI kernel surface |

## The short version

### Calling an existing Ryu agent

Use `@ryuhq/client`:

```bash
npm install @ryuhq/client
```

```typescript
import { createRyuClient } from "@ryuhq/client";

const client = createRyuClient({
  baseUrl: "http://127.0.0.1:7980",
  token: process.env.RYU_TOKEN,
});

const reply = await client.agents.run("pi", [
  { role: "user", content: "Hello from my app." },
]);
```

### Building a Ryu extension

Use `@ryuhq/sdk`:

```bash
npm install @ryuhq/sdk
npx create-ryu-app my-plugin
```

Then author `defineAgent`, `defineWorkflow`, `defineTool`, `defineSkill`, or `defineAction` and
pack the result with the `ryu` CLI. See [TypeScript SDK](/docs/extend/develop/sdk) for the full
authoring contract.

### Building a Java app

Use the Java library, not the generated UniFFI project:

```bash
cd bindings/java
mvn install
```

```xml
<dependency>
  <groupId>com.ryu</groupId>
  <artifactId>ryu-client</artifactId>
  <version>0.2.5</version>
</dependency>
```

```java
import com.ryu.sdk.RyuClient;
import java.util.List;

try (var ryu = new RyuClient("http://127.0.0.1:7980", System.getenv("RYU_TOKEN"))) {
  var reply = ryu.run(
      "pi",
      List.of(RyuClient.Message.user("Hello from Java.")));
}
```

See [Java library](/docs/extend/develop/sdk/java) for streaming and the complete typed surface.

### Building a React Native / Expo app

React Native does not need a separate Rust binding for Core access. Use the same TypeScript
libraries as a web app. For Expo streaming, inject `expo/fetch`:

```tsx
import { fetch as expoFetch } from "expo/fetch";
import { createRyuClient, type RyuFetch } from "@ryuhq/client";

const client = createRyuClient({
  baseUrl: "http://192.168.1.10:7980",
  token: nodeToken,
  fetch: expoFetch as RyuFetch,
});
```

Use `@ryuhq/core-client` for the full Core API. Keep node and control-plane tokens in secure
storage, such as `expo-secure-store`; never bundle a provider API key.

## What the generated bindings are

The generated bindings under the SDK hub wrap the shared `ryu-sdk` Rust kernel. They expose
manifest validation, Gateway egress checks, model calls, and embeddings. They do not replace the
Core client and they do not create a hosted node.

| Binding | Use it when... |
|---|---|
| `ryu-sdk` | Your Rust application needs the kernel directly |
| `ryu-sdk-ffi` | Your C or Go application needs the C ABI |
| `ryu-sdk-uniffi` | Your Python, Swift, Kotlin, or C# application needs the kernel surface |
| `@ryuhq/sdk-native` | You are using `@ryuhq/sdk`; it is its Node-API implementation detail |

Generated source files are created by each target's build and should not be hand-edited. For
the API contracts behind them, see [Language bindings](/docs/extend/develop/sdk/language-bindings)
and [Rust SDK](/docs/extend/develop/sdk/rust).

## Verify a hub checkout

These commands are for contributors changing the SDK hub itself:

```bash
bun install --frozen-lockfile --ignore-scripts
bun run build:native
bun run test:packages
cargo test --workspace --locked --all-targets
mvn --batch-mode test -f bindings/java/pom.xml

# Optional target-language smoke tests.
bash bindings/python/test.sh
bash bindings/swift/test.sh
bash bindings/java/test.sh
```
