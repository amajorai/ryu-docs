Ryu's SDK source is published together in the [`amajorai/ryu-sdk`](https://github.com/amajorai/ryu-sdk)
public hub. It is a generated satellite of the Ryu monorepo, in the same family as the
[`amajorai/ryu-docs`](https://github.com/amajorai/ryu-docs) documentation repository.

The monorepo remains the canonical source. The hub is the public contribution and build surface:
it carries the SDK packages, the shared Rust kernel, foreign-language bindings, runnable examples,
contract fixtures, tests, and registry workflows. A later sync can rewrite generated files and the
public `main` branch; pull requests are ported into the canonical source before they are published
again.

## Package map

| Job | Public package or crate |
|---|---|
| Author agents, workflows, tools, skills, Actions, and plugins | `@ryuhq/sdk` |
| Embed agent chat, sessions, and Spaces | `@ryuhq/client` |
| Operate a Core node through typed domains | `@ryuhq/core-client` |
| Share protocol and wire helpers | `@ryuhq/protocol` |
| Scaffold a project | `create-ryu-app` |
| Rust kernel and shared validation | `ryu-sdk` |
| C and Go FFI | `ryu-sdk-ffi` |
| Python, Swift, Kotlin, and C# | `ryu-sdk-uniffi` |
| Node-API native layer | `@ryuhq/sdk-native` |

Use [SDK Reference](/docs/extend/develop/sdk) for the API contracts and [Language bindings](/docs/extend/develop/sdk/language-bindings)
for generated foreign surfaces. The [Core API reference](/docs/extend/develop/api-reference) remains
the source for HTTP operation details.

## Repository layout

```text
packages/sdk/                 TypeScript authoring SDK
packages/client/              lightweight Core chat client
packages/core-client/         typed Core/Gateway domain client
packages/create-ryu-app/      project scaffolder
crates/core/kernel-contracts/ shared manifest and host contracts
crates/sdk/{core,ffi,napi,uniffi}/ Rust kernel and adapters
bindings/{python,go,csharp,kotlin,swift}/ language projects
examples/                     small runnable integrations
```

The root workspace is generated for the public tree. It includes only SDK-facing dependencies, so
the hub can be installed and tested without checking out the private application surfaces.

## Local verification

```bash
bun install --frozen-lockfile --ignore-scripts
bun run build:native
bun run build
bun run check-types
bun run test:packages
cargo fmt --all --check
cargo test --workspace --locked --all-targets
```

The foreign-language projects each have a committed example, test project, and `test.sh` entry
point. Those commands generate ignored binding files from the Rust surface and then execute the
language-specific tests; see the [binding guide](/docs/extend/develop/sdk/language-bindings).

```bash
bash bindings/python/test.sh
bash bindings/go/test.sh
bash bindings/csharp/test.sh
bash bindings/kotlin/test.sh
bash bindings/swift/test.sh
```

## Boundaries

The Rust kernel owns shared manifest validation and Gateway egress enforcement. TypeScript and
foreign bindings call that kernel; they do not accept provider credentials or reimplement the
policy. The hub does not contain first-party application code or deployment configuration.

Fumadocs owns the narrative public documentation. The hub README links here for API and
integration guidance, while this page links to the hub for source, examples, and contributor
workflow.
