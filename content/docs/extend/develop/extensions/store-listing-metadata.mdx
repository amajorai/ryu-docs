title: "Add Store Listing Metadata"
description: "Declare the Marketplace and Library presentation fields in manifest.json, deprecate a listing, and allow or block remixes."
---

A plugin or app's `manifest.json` also owns the safe, user-facing fields shown by the Marketplace
and Library. None of them grants a runtime permission.

| Field | Use |
|---|---|
| `tagline`, `author`, `homepage`, `repository`, `license`, `category` | Listing identity and links. |
| `privacyPolicyUrl`, `termsOfServiceUrl` | Policy links. |
| `tags` | The curated `string[]` used by the Store's tag filter. |
| `keywords` | The broader search vocabulary. |
| `icon` / `iconUrl`, `iconBackground`, `iconDither` | Tile art. First-party listings declare `iconDither` alongside their icon, for example `{ "from": 240, "to": "transparent", "direction": "down" }`. The shared tile uses it in light and dark appearances. |
| `banner` | Listing banner, for example a `gradient` or `animated-gradient` style (see below). |
| `screenshots` | Listing screenshots, as declared URLs. |
| `examplePrompts` | Sample prompts for the listing. |
| `external` | `true` marks a provider whose runtime lives outside the local Ryu process. It is a provenance label, not permission. The remote endpoint still needs an explicit `mcp_servers` entry and Gateway grants. |

```json
{
  "id": "@example/research-assistant",
  "name": "Research Assistant",
  "version": "1.0.0",
  "description": "Drafts a literature review from a folder of PDFs.",
  "tagline": "Turn a reading pile into a cited outline",
  "author": { "name": "Example Labs", "url": "https://example.com" },
  "homepage": "https://example.com/research-assistant",
  "repository": "https://github.com/example/research-assistant",
  "privacyPolicyUrl": "https://example.com/privacy",
  "termsOfServiceUrl": "https://example.com/terms",
  "license": "MIT",
  "keywords": ["research", "writing"],
  "tags": ["research", "writing", "citations"],
  "screenshots": ["https://cdn.example.com/research-assistant.png"],
  "banner": { "style": "gradient", "colors": ["#1d4ed8", "#7c3aed"] },
  "examplePrompts": ["Compare these papers and group their methods."],
  "runnables": [],
  "permission_grants": []
}
```

For `banner.style: "animated-gradient"`, the `banner.gradient.shape` input accepts
`checks`, `stripes`, and `edge`, ignoring case and surrounding spaces. Unknown shape
names use the chosen preset's shape. Numeric gradient overrides are normalized by
the same resolver for the live shader and its static fallback.

## Compatible GitHub descriptors

Ryu also reads compatible GitHub descriptors at `.codex-plugin/plugin.json` and
`.claude-plugin/plugin.json`. Codex-style nested `interface` fields such as `displayName`,
`shortDescription`, `longDescription`, `websiteURL`, `composerIcon`, `logo`, `screenshots`, and
`defaultPrompt` map to the same presentation contract.

This is GitHub discovery metadata. The server hydrates and scrubs it for cards and detail views.
It never imports executable code, permission grants, MCP endpoints, or install artifacts from an
unsigned descriptor. A compatible descriptor does not replace a Ryu `manifest.json` when you want
to install and run the plugin.

## Listing art

Screenshots and banners are declared URLs, so the GitHub repository (or another HTTPS asset host)
is the source of truth for listing art. Ryu does not need a new server-side image upload for a new
listing.

Existing hosted marketplace media remains a compatibility fallback for older records. The legacy
upload endpoint and database columns are still present for older publisher clients, but
manifest-declared presentation wins whenever it is available.

## Swappable layer summary

`provides` is also summarized as a non-executable **swappable layer** on cards and detail views.
Declare the capability and its canonical verbs there; the binding and adapter code remain in the
native signed manifest.

## Deprecate a listing

Set `deprecated` when a plugin should no longer be chosen for new setups. The listing stays in the
Store and keeps installing, enabling, and running for anyone who already has it. Ryu shows a
**Deprecated** badge on its card (in the Store and in Installed) and a notice on its detail page
before the install action.

`deprecated` accepts three shapes:

| Value | Meaning |
| --- | --- |
| `true` | Deprecated, with a generic notice. |
| `"Use @example/research-assistant-2 instead."` | Deprecated, with your message. |
| `{ "message": "…", "replacement": "@example/research-assistant-2" }` | Your message, plus the id of the listing that supersedes this one. |

`false` or leaving the field out means the listing is current. The message is trimmed and capped at
280 characters. The replacement id is shown as written; Ryu does not install or migrate to it
automatically.

```json
{
  "id": "@example/research-assistant",
  "name": "Research Assistant",
  "version": "1.4.0",
  "deprecated": {
    "message": "Research Assistant 2 adds citation export and replaces this plugin.",
    "replacement": "@example/research-assistant-2"
  },
  "runnables": [],
  "permission_grants": []
}
```

Deprecation ships with a version like any other manifest change. A third-party marketplace index
can also set the same `deprecated` field on an entry in its `marketplace.json`; that takes effect on
each client's next catalog fetch, without a new plugin release.

## Allow or block remixes

Others can remix your plugin or app unless you set `"allowRemix": false`. Leaving the field out
means remixes are allowed, so first-party and existing listings are all remixable. A remix of your
listing credits it with `remixedFrom`; see
[Remixing listings](/docs/extend/develop/extensions/marketplace-listings#remixing-listings).

```json
{
  "id": "@example/research-assistant",
  "name": "Research Assistant",
  "version": "1.4.0",
  "allowRemix": false,
  "runnables": [],
  "permission_grants": []
}
```
