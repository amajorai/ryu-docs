title: UI Conformance Scorecard
description: Reference for the source UI scorecard and Marketplace preflight that grade app and plugin UI against the Ryu App UI contract and shared design system

The UI scorecard is a read-only source check that grades app and plugin UI against the
[Ryu UI Kit](/docs/extend/develop/extensions/ui-kit) contract. In the first-party Ryu source tree,
run it before you package an app or plugin:

```bash
bun run check:ui-scorecard
bun run check:ui-scorecard -- --artifact @ryu/mail --json
```

<Callout type="warn">
  `check:ui-scorecard` is not included in the public `amajorai/ryu` repository. For a package
  published from its own repository, Marketplace publishing runs the same source checks as a
  [preflight](#marketplace-preflight) instead.
</Callout>

## What it checks

The check combines two read-only audits:

- the Ryu App UI contract: `RyuAppShell`, root marking, shared App UI CSS, host navigation,
  shared primitive reuse, and working-surface chrome;
- the shared `@shadcn/lint` rules: component restyling, raw colors, arbitrary values, inline
  styles, static class values, and unknown classes.

The source evidence is compared against the [Ryu UI Kit](/docs/extend/develop/extensions/ui-kit)
contract:

- Companion entrypoints use `RyuAppShell`, the root marker, and `@ryu/ui/app-ui.css`.
- Generic controls use `@ryu/ui` or `@ryu/blocks` instead of local button, field, dialog, or shell copies.
- Surfaces use semantic color tokens, shared typography and radius roles, and the host theme.
- Interactive UI shows accessible names and explicit loading, empty, error, disabled, or unavailable states.
- Local motion has a reduced-motion path, and primary navigation remains manifest-owned.

Domain-specific canvases, graphs, media, and editors remain valid specialized renderers. Their
surrounding chrome is still reviewed against the shared primitives.

## Output

| Flag | Output |
|---|---|
| (none) | A human-readable scorecard grouped by manifest id |
| `--artifact <id>` | The report for one app or plugin |
| `--json` | The complete report, with `schemaVersion`, `rulesetVersion`, artifact counts, scores, file locations, rule ids, and remediation messages, for CI or a publishing workflow |
| `--verbose` | The individual findings in the human output |

## Marketplace preflight

The scorecard is a source check. It reads the app or plugin checkout and does not execute package
code or sidecars. Marketplace publishing runs a package-aware preflight against the pinned source
tree, and it applies the source design-system checks when it detects custom UI.

- Manifest-declared surfaces that Ryu renders itself, such as settings tabs and composer controls,
  receive the host-renderer profile.
- Packages with no UI receive a passing not-applicable check and use their own artifact profile.
- If a catalog source provides no UI source evidence, the Marketplace Health scorecard reports the
  design checks as unavailable and excludes them from the numeric grade. A missing snapshot never
  counts as compliance.

Every supported kind must earn Grade A before it enters the Ryu review queue.

## Runtime Doctor

The installed-package check is a separate command:

```bash
ryu-cli plugin doctor <id>
```

Runtime Doctor validates the manifest, lifecycle state, grants, dependencies, and package eval
metadata that Core loaded. It does not run a JavaScript linter against a bundled UI document.

Existing packages may start with findings while they migrate to the shared contract. Use the
per-artifact report to reduce the baseline, then make the scorecard a release gate for new or
updated surfaces.
