---
title: "Bundle a Skill with a Plugin or App"
description: "Ship Agent Skills inside a plugin or app package so Ryu installs, activates, and removes them with the extension's lifecycle."
---

A Skill is a `SKILL.md` instruction pack. A plugin or app can carry Skills in its package so they
install and activate with the extension. This page covers that packaging. To write the `SKILL.md`
itself, see [Authoring a Skill](/docs/extend/skills/authoring). For how Core discovers, activates,
and injects Skills, see [Skills catalog](/docs/core/skills-catalog).

## Bundle a Skill with a plugin or app

The standalone Skills catalog and a manifest-bundled Skill use the same folder convention. A
plugin/app manifest can declare a `skill` Runnable whose `config.skill_id` identifies the skill,
then carry the body beside the manifest:

```text
my-extension/
├── manifest.json
├── skills/
│   └── research/
│       ├── SKILL.md
│       └── examples/       # optional resources
└── plugin.json             # generated Agent Plugins interop
```

On enable, Ryu copies plugin-owned skill directories into the canonical Skills home, activates them,
and records ownership so disable deactivates without deleting the files. Uninstall removes only
directories owned by that plugin; a user's same-named Skill is never clobbered. The skill directory
is a package-tree artifact, so include `skills/<slug>/` in the portable package rather than assuming
it will appear inside a single JSON `plugin.bundle.json`.

This is separate from `plugin.json`. The Agent Plugins schema discovers Skills from the folder, while
Ryu's native `manifest.json` declares the Runnable reference and still owns the install/enable/grant
lifecycle. See [Extension schemas & folder layouts](/docs/extend/develop/extensions/extension-folder-layouts#what-can-be-bundled).

## Bundle resource files

Anything else in the `<slug>/` directory ships with the Skill: example inputs, reference data, or
templates the body points to. The catalog's `SkillDetail.files` lists every file in the package
(`SKILL.md` plus your assets). Installs from a remote source are path-traversal guarded, so a bundled
file can never write outside its own Skill directory.

## Installed is not active

Enabling the extension activates the Skills it owns. A Skill installed any other way follows the
normal activation rules, and an agent's skill allowlist still applies. See
[Publishing and Loading](/docs/extend/skills/publishing#installed-versus-active) and
[Skills catalog](/docs/core/skills-catalog).
