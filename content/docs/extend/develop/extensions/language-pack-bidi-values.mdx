Translated sentences often carry values that are written left to right: a file path, a model
name, an `@handle`, or a `#channel`. Inside an Arabic sentence, the punctuation at the edge of such
a value can move to the wrong side, so `@alice` reads as `alice@` and `./agents` as `agents/.`.
Ryu prevents this when it formats a message. You do not need to add direction marks to your
translations. For the pack format itself, see
[Language packs](/docs/extend/develop/extensions/language-packs).

## What Ryu does for right-to-left languages

When the interface language is written right to left (Arabic, Hebrew, Persian, Urdu, Pashto, or
Dhivehi), Ryu sets each inserted text value apart from the sentence around it with invisible
Unicode isolation marks (FSI U+2068 before the value, PDI U+2069 after it). The value keeps its own
order and the sentence keeps its own.

- A value written only in left-to-right letters, such as `Release v2.4`, `./agents`, or
  `gpt-5`, is isolated.
- An `@` or `#` written just before a placeholder, as in `@{handle}` or `#{channel}`, moves
  inside the isolated value, so it stays attached to the name.
- Numbers, dates, plural and select output, and values that already contain right-to-left
  text are not changed.
- Bare links and email addresses are not changed, so chat apps and mail clients still detect
  them as links.
- Left-to-right languages, including English and German, render exactly as before.

The same rule applies to messages Core renders outside the app, such as mobile push
notifications, chat bot alerts, and inbox entries. A push notification body in a right-to-left
language also starts with an invisible right-to-left mark (U+200F). The phone then lays the body
out right to left, even when it begins with a Latin name.

## Writing translations

- Keep each placeholder where the sentence needs it, and keep any `@` or `#` sigil next to it
  (`إرسال إلى @{name}`). Ryu moves the sigil inside the isolated value for you.
- Do not type your own direction marks around placeholders. Ryu adds them, and values that are
  already isolated are not wrapped a second time.
- Text copied from the interface can contain these invisible marks. Code that compares a
  translated string or uses it as a key should compare the source message ID instead.
