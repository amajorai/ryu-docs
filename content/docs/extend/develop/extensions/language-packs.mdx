For the outer archive, folder, and GitHub transport contract, see [Portable packages](/docs/extend/develop/extensions/portable-packages).

Ryu language packs are data-only overlays for the shared interface catalog. One pack can be used by
the Ryu website, desktop app, Island, mobile app, browser extension, and sandboxed apps/plugins.
Packs can be normal locale translations, regional variants, or playful voices such as **English
(chronically online)**.

The runtime always keeps English as a fallback. A pack never ships JavaScript, permissions,
credentials, account data, or a plugin sidecar, and selecting one does not require an app update or
restart.

Authentication errors have a separate server boundary. Ryu registers Better Auth's i18n plugin
with its built-in locale dictionaries, so standard auth error codes follow the `locale` cookie when
present, then the request's `Accept-Language` header, and finally English. Auth responses retain
the original message for diagnostics. This layer is intentionally independent from community UI
packs: an `en-x-ryu-online` voice changes product copy, while security-sensitive auth errors use
reviewed Better Auth translations and fall back to English when no reviewed locale is available.
See the [Better Auth i18n plugin documentation](https://better-auth.com/docs/plugins/i18n) for the
server plugin's detection and error-response contract.

## The language-pack file

Put a `language-pack.json` file beside the package envelope:

```text
my-language-pack/
├── ryu.package.json
└── language-pack.json
```

The artifact is a partial catalog. Only the messages you want to change need to be present:

```json title="language-pack.json"
{
  "schemaVersion": 1,
  "id": "community/ryu-online",
  "name": "English (chronically online)",
  "version": "1.0.0",
  "locale": "en-x-ryu-online",
  "baseLocale": "en",
  "direction": "ltr",
  "messages": {
    "common.install": "Yeet it in",
    "common.marketplace": "The Bazaar",
    "language.title": "Language & vibes",
    "nav.marketplace": "The Bazaar",
    "sample.greeting": "Welcome to Ryu, {name}. The vibes are immaculate."
  }
}
```

`locale` and `baseLocale` use BCP-47 tags. Use `direction: "rtl"` for Arabic, Hebrew, Persian,
Urdu, or another right-to-left pack; Ryu updates the document direction with the selected pack.
Message IDs are stable API. Keep placeholders unchanged, including the names inside `{name}` or
`{count, plural, ...}`. The validator rejects malformed identity, invalid locale/direction,
control characters, oversized messages, placeholder changes, and artifacts larger than 4 MiB of
UTF-8 JSON. Missing messages fall back to the base catalog, then English.

## Package it for sharing

The outer envelope marks the artifact as a data-only language pack:

```json title="ryu.package.json"
{
  "schemaVersion": 1,
  "id": "community/ryu-online",
  "name": "English (chronically online)",
  "version": "1.0.0",
  "kind": "language_pack",
  "artifacts": ["language-pack.json"],
  "targets": ["desktop", "web", "mobile", "extension", "island"],
  "scopes": ["desktop"],
  "requires": {},
  "capabilities": [],
  "security": {
    "containsSecrets": false,
    "permissions": [],
    "privateContent": false,
    "redacted": false
  }
}
```

Validate and create the portable archive with the same package commands used by every other
Marketplace kind:

```bash
ryu package validate ./my-language-pack
ryu package pack ./my-language-pack ./ryu-online-1.0.0.ryupack
ryu package inspect ./ryu-online-1.0.0.ryupack
ryu package export ./my-language-pack ./ryu-online-export.ryupack
```

`export` applies the normal redaction rules. A language pack should already be publishable because
its only artifact is public text, but the same checks protect a package if extra files are added.
The archive can be imported into another node or attached to a GitHub Release.

Desktop and mobile expose this directly in **Settings → Language → Language packs**:
choose **Import** to send a local `.ryupack` through Core's data-only import validator, or
**Export** to share the currently selected pack. A successful import is activated immediately;
the same node-scoped pack then appears on the webapp, mobile, extension, and Island surfaces.

## Publish it in Marketplace

Open Marketplace → **Sell** on the website or desktop app and submit the repository or package URL
through **Publish from GitHub**. Ryu validates the artifact, checks that the immutable Release
asset matches the repository tree, signs the package descriptor, and sends the listing through the
normal moderation flow. A free pack can be loaded by the website; paid packs use the normal Ryu
install handoff.

For a standalone language-pack repository, add the `ryu-language-pack` GitHub topic. For a
collection repository, add `ryu-marketplace` and place the package under a folder containing its
own `ryu.package.json`. The deterministic Release asset is named from the package id and version
and must end in `.ryupack`.

Marketplace cards show the locale, base language, text direction, and translated-string count when
the listing includes the language-pack metadata. The same listing is available at
`/marketplace/language-packs` and in the desktop Marketplace Browse kind.

## Use a pack

On the website, choose a free pack's **Use in browser** action or use the language selector in the
header. On desktop, open **Settings → General → Language** (or the existing **Appearance → Language
& vibe** entry), or choose **Language Packs** from Marketplace Browse. The General selector starts
at **Auto detect** and can be fixed to English or an installed pack. On mobile, use Marketplace → **Languages** to install a free pack, then
choose it in Settings; the browser extension exposes the same choice in its Appearance settings,
and Island exposes it in the compact chat header. Installed packs are node-scoped, can be enabled
or disabled without a restart, and remain data-only at runtime. The UI falls back to English for
strings a community pack has not translated.

The selected website pack is remembered locally in the browser. Desktop stores its lifecycle state
on the selected Core node; the desktop selection is kept in the local app profile and only takes
effect on another node when that same pack is available there.

Translation is explicit: a pack changes text that a first-party surface or app/plugin sends through
`t`/`I18nText` or the host primitive. It does not heuristically rewrite arbitrary literal strings;
surface owners migrate new copy by giving it a stable ID and an English fallback.

## Build an app or plugin with the primitive

First-party React surfaces use the shared provider and hook:

```tsx
import { useI18n } from "@ryu/i18n/react";

export function Welcome() {
  const { t, locale, direction } = useI18n();
  return (
    <p dir={direction} lang={locale}>
      {t("my-app.welcome", { name: "Ada" }, "Welcome, {name}.")}
    </p>
  );
}
```

The `defaultMessage` is required at the sandbox boundary so an app remains readable even when a
community pack does not include its namespaced IDs. Sandboxed apps and plugins use the same
capability-gated host primitive:

```ts
const snapshot = await window.ryu.i18n.get();
const label = await window.ryu.i18n.translate({
  id: "my-app.refresh",
  defaultMessage: "Refresh",
});
const subscription = window.ryu.i18n.subscribe({
  onChange(next) {
    document.documentElement.lang = next.locale;
    document.documentElement.dir = next.direction;
  },
});
```

The plugin SDK exposes the same API as `context.plugin.host.i18n`. It is intentionally read-only:
apps/plugins can translate their own IDs and react to a pack change, but cannot install packs,
change another app's copy, access the full catalog, or receive credentials. The primitive is
available through the desktop, webapp, mobile WebView, browser-extension sandbox, Island, and
widget host paths.

Shared Ryu UI primitives localize direct literal children for user-facing controls such as
buttons, labels, headings, menus, select options, dialogs, empty states, and settings rows using
deterministic `literal.<slug>.<hash>` IDs. Data-bearing content such as entity names, tool output,
and status badges stays literal by default because a generic component cannot safely distinguish it
from a label. Use `<I18nText>` or an explicit `t(...)` call for child text that is intended to
localize. String attributes owned by a primitive—such as `aria-label`, `title`, and
`placeholder`—use the shared localization hook where supported. App and plugin authors should
prefer explicit namespaced IDs such as `my-app.refresh`, because they are easier to review and
remain stable when wording changes.

## Review and maintain community packs

Treat a language pack like any other community-published content: review its repository, release
history, and translations before enabling it. A pack cannot execute code, but misleading text can
still make an interface confusing. Keep the stable message IDs, bump the package version when
changing translations, and publish a new immutable Release for each update.

When Ryu adds new interface messages, older packs continue to work because the missing IDs fall
back to English. Pack authors can update later to cover the new catalog. Keep interpolated values
and plural/select branches semantically equivalent to the source message.
