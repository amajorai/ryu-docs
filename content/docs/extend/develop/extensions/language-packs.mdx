Ryu language packs are data-only overlays for the shared interface catalog. One pack can be used by
the Ryu website, Desktop, Island, the mobile app, the browser extension, and sandboxed apps and
plugins. Packs can be normal locale translations, regional variants, or playful voices such as
**English (chronically online)**. For the outer archive, folder, and GitHub transport contract, see
[Portable packages](/docs/extend/develop/extensions/portable-packages).

Ryu ships first-party starter packs for **Español**, **Français**, **Deutsch**,
**Português (Brasil)**, **日本語**, **简体中文**, **Italiano**, **한국어**, **हिन्दी**, **Русский**, and
**العربية**. They cover the shared interface catalog and are available offline in the website
selector and in the desktop app's language settings; the same catalog is available to mobile,
extension, and Island surfaces. Arabic uses the right-to-left layout direction. English remains
the default source catalog, and missing text in an older or community pack falls back to English.

These official languages also translate the rest of the first-party interface: Desktop, the
website and cloud dashboard, the browser-hosted app, Island, the mobile app, the browser extension,
and Companion apps opened from a Ryu host. On the web, Desktop, Island, and extension pages, the
selected language's interface text downloads the first time you choose it, so other languages add
nothing to what you load. The mobile app and the extension's in-page overlays include their own
translated text. Text added in a newer release can briefly appear in English until the next
translation update ships.

The terminal CLI follows your system language, like other command-line tools: it reads
`RYU_LOCALE` first, then `LC_ALL`, `LC_MESSAGES`, and `LANG` (for example `de_DE.UTF-8`). Set
`RYU_LOCALE=en` to keep it in English. Machine-readable output, such as `--json`, stays in English.

Emails from Ryu use the language you last chose on the website or in Desktop while signed in. Until
you choose one, emails sent during an action you take (such as a sign-in code or password reset)
use your browser's language, and other emails are sent in English.

The runtime always keeps English as a fallback. A pack never ships JavaScript, permissions,
credentials, account data, or a plugin sidecar, and selecting one does not require an app update or
restart.

The website also starts from the browser's locale when no language choice is stored, while an
explicit selection always wins. Regional tags such as `es-MX` and `pt-PT` resolve to the closest
reviewed starter pack when one is available.

In Desktop and the browser-hosted app, windows sharing the same local storage receive changes to
the language mode and selected pack. Clearing local settings in another window returns the mode to
automatic detection. If the host refuses a settings write, your new language choice still applies
in the current session, including a pack you switch to from **Auto detect** or choose in
Marketplace. Choose it again after storage becomes available to save it for future launches. A
language change saved in another window replaces a choice that this window could not save.

Installed-pack changes are reloaded from the active node, so a refresh cannot enable a pack that
Core has disabled. If you switch nodes or sign-in identity, or choose another language while an
import or Marketplace language installation is pending, its later reply does not replace your
current choice. An import already accepted by its original
node can remain installed there; changing the current selection does not undo that remote write.

Authentication errors have a separate server boundary. Ryu registers Better Auth's i18n plugin
with its built-in locale dictionaries, so standard auth error codes follow the `locale` cookie when
present, then the request's `Accept-Language` header, and finally English. Auth responses retain
the original message for diagnostics. This layer is independent from community UI packs. An
`en-x-ryu-online` voice changes product copy, while security-sensitive auth errors use
reviewed Better Auth translations and fall back to English when no reviewed locale is available.
See the [Better Auth i18n plugin documentation](https://better-auth.com/docs/plugins/i18n) for the
server plugin's detection and error-response contract.

## The language-pack file

Put a `language-pack.json` file beside the package envelope:

```text
my-language-pack/
├── ryu.package.json
└── language-pack.json
```

The artifact is a partial catalog. Only the messages you want to change need to be present:

```json title="language-pack.json"
{
  "schemaVersion": 1,
  "id": "community/ryu-online",
  "name": "English (chronically online)",
  "version": "1.0.0",
  "locale": "en-x-ryu-online",
  "baseLocale": "en",
  "direction": "ltr",
  "messages": {
    "common.install": "Yeet it in",
    "common.marketplace": "The Bazaar",
    "language.title": "Language & vibes",
    "nav.marketplace": "The Bazaar",
    "sample.greeting": "Welcome to Ryu, {name}. The vibes are immaculate."
  }
}
```

`locale` and `baseLocale` use BCP-47 tags. Use `direction: "rtl"` for Arabic, Hebrew, Persian,
Urdu, or another right-to-left pack; Ryu updates the document direction with the selected pack.
Message IDs are stable API. Keep placeholders unchanged, including the names inside `{name}` or
`{count, plural, ...}`. The validator rejects malformed identity, invalid locale/direction,
control characters, oversized messages, placeholder changes, and artifacts larger than 4 MiB of
UTF-8 JSON. Missing messages fall back to the base catalog, then English.

## Package it for sharing

The outer envelope marks the artifact as a data-only language pack:

```json title="ryu.package.json"
{
  "schemaVersion": 1,
  "id": "community/ryu-online",
  "name": "English (chronically online)",
  "version": "1.0.0",
  "kind": "language_pack",
  "artifacts": ["language-pack.json"],
  "targets": ["desktop", "web", "mobile", "extension", "island"],
  "scopes": ["desktop"],
  "requires": {},
  "capabilities": [],
  "security": {
    "containsSecrets": false,
    "permissions": [],
    "privateContent": false,
    "redacted": false
  }
}
```

Validate and create the portable archive with the same package commands used by every other
Marketplace kind:

```bash
ryu-cli package validate ./my-language-pack
ryu-cli package pack ./my-language-pack ./ryu-online-1.0.0.ryupack
ryu-cli package inspect ./ryu-online-1.0.0.ryupack
ryu-cli package export ./my-language-pack ./ryu-online-export.ryupack
```

`export` applies the normal redaction rules. A language pack should already be publishable because
its only artifact is public text, but the same checks protect a package if extra files are added.
The archive can be imported into another node or attached to a GitHub Release.

Desktop exposes this in **Settings → General → Language**, under **Available language packs**.
Mobile exposes it in **Settings → Language packs**. In either place, choose **Import** to send a
local `.ryupack` through Core's data-only import validator, or **Export** to share the currently
selected pack. Desktop activates an imported pack after Core
acknowledges the import and the refreshed installed catalog includes it. If importing or enabling
a pack fails, Settings shows the error and keeps your current selection; retry the same file or
choose the pack again after the node is available. After a successful import, the same
node-scoped pack appears on the webapp, mobile, extension, and Island surfaces.

## Publish it in Marketplace

Open Marketplace → **Sell** on the website or desktop app and submit the repository or package URL
through **Publish from GitHub**. Ryu validates the artifact, checks that the immutable Release
asset matches the repository tree, signs the package descriptor, and sends the listing through the
normal moderation flow. A free pack can be loaded by the website; paid packs use the normal Ryu
install handoff.

For a standalone language-pack repository, add the `ryu-language-pack` GitHub topic. For a
collection repository, add `ryu-marketplace` and place the package under a folder containing its
own `ryu.package.json`. The deterministic Release asset is named from the package id and version
and must end in `.ryupack`.

Marketplace cards show the locale, base language, text direction, and translated-string count when
the listing includes the language-pack metadata. The same listing is available at
`/marketplace/language-packs` and in the desktop Marketplace Browse kind.

## Use a pack

On the website, choose a free pack's **Use in browser** action or use the language selector in the
header. The website selector applies the pack immediately and updates the document language for
assistive technology and browser formatting.

On desktop, open **Settings → General → Language** (or the existing **Appearance → Language & vibe**
entry), or choose **Language Packs** from Marketplace Browse. The General selector starts at **Auto
detect** and can be fixed to English or an installed pack.

Choosing a pack from Desktop Marketplace installs and enables it on the selected node, then fixes
your language choice after the refreshed catalog acknowledges the enabled pack. The choice is saved
in your local profile for later launches when local settings storage is available.

On mobile, use Marketplace → **Languages** to install a free pack, then choose it in Settings. The
browser extension exposes the same choice in its Appearance settings, and Island exposes it in the
compact chat header. Island follows the language you choose in Desktop: Desktop saves its choice
(auto-detect or a fixed pack) on the selected node, and Island reads it from there. A choice made in
Island's header stays in effect until you change the language in Desktop again.

Installed packs are node-scoped, can be enabled or disabled without a restart, and remain data-only at
runtime. The UI falls back to English for strings a community pack has not translated.

## Localize the public Fumadocs site

The public documentation site uses Fumadocs' native i18n routing in addition to Ryu's shared product
language-pack runtime. The current docs locales are `en`, `es`, `fr`, `de`, `pt-br`, `ja`, `zh-cn`,
`it`, `ko`, `hi`, `ru`, and `ar`. English keeps the existing canonical URLs; translated routes use
the locale prefix, for example `/es/docs/0.4.0/start-here`.

The site uses the [Fumadocs internationalization configuration](https://www.fumadocs.dev/docs/internationalization)
and the [Next.js routing pattern](https://www.fumadocs.dev/docs/internationalization/next). A translated
page is added beside its English source with the locale suffix, such as
`start-here/index.es.mdx`; a translated navigation file uses the same convention, such as
`start-here/meta.es.json`. The `dot` parser keeps the URL slug stable across languages.

Translations can land progressively. When a page or navigation file is not yet translated, the
Fumadocs loader serves the English source at the active locale URL. This keeps every locale's page
tree, previous/next navigation, search index, Markdown projection, OpenAPI reference, and metadata
usable while individual pages are reviewed. Search is filtered to the active locale, and the language
selector preserves the current page when switching languages.

Fumadocs UI labels use the same locale list and include translated language-switcher, search, theme,
pagination, page-action, and table-of-contents labels. The Arabic route also carries right-to-left
document and portal direction.

The desktop welcome and device sign-in flow uses the same catalog, including the welcome actions,
approval state, retry state, and local Core download/setup dialog.

The selected website pack is remembered locally in the browser. Desktop stores its lifecycle state
on the selected Core node; the desktop selection is kept in the local app profile and only takes
effect on another node when that same pack is available there.

Named translation is explicit: a pack changes text that a first-party surface or app/plugin sends
through `t`/`I18nText` or the host primitive. For legacy first-party UI that still contains a raw
DOM literal, the shared provider offers that text to the same deterministic literal-ID resolver;
code blocks, editable content, and unknown dynamic content are left alone. Native `Text` elements
use the equivalent build-time boundary. Surface owners should still migrate new copy to a stable
namespaced ID and English fallback because that is easier to review and supports interpolation.

The DOM fallback processes changed regions and reuses translations for unchanged text.
Changing the selected pack or replacing its catalog content refreshes those translations, even when
the pack's ID and version stay the same.
Text inside explicit opt-out or editable regions remains outside this fallback.

Shared web and desktop controls also receive the pack's direction through Base UI's
`DirectionProvider`. Portalled menus, selects, comboboxes, popovers, dialogs, tooltips, and editor
overlays keep their `dir` attribute, spacing, directional icons, and animations aligned with the
active language. The logical `start`/`end` utility approach follows the
[shadcn/ui RTL guide](https://ui.shadcn.com/docs/rtl).

## Build an app or plugin with the primitive

First-party React surfaces use the shared provider and hook:

```tsx
import { useI18n } from "@ryu/i18n/react";

export function Welcome() {
  const { t, locale, direction } = useI18n();
  return (
    <p dir={direction} lang={locale}>
      {t("my-app.welcome", { name: "Ada" }, "Welcome, {name}.")}
    </p>
  );
}
```

A host using `I18nProvider` can change its optional `selectionKey` when it needs to re-read
`initialLocale` and `initialPackId`, including a selection stored by another window. This refreshes
the translation runtime while preserving mounted child components, unsent input, and keyboard focus.
Omitting `selectionKey` keeps the existing initialization behavior.

The provider compares each `packs` array it receives with the catalog it last applied. A new array
with the same content, such as an unchanged reload of the installed catalog, is not republished,
so consumers do not re-render and the page is not retranslated. Any change in content is
republished, including changed messages, enabled state, or pack order, even when a pack keeps
its id and version. While no pack is selected and the host leaves `initialPackId` unset, an
unchanged array still re-reads the saved pack id. A choice that became readable since the
provider started, for example after storage that refused reads recovers, is then applied and
published once. With `initialPackId` set to `null`, the saved id is not read.

The `defaultMessage` is required at the sandbox boundary so an app remains readable even when a
community pack does not include its namespaced IDs. Sandboxed apps and plugins use the same
capability-gated host primitive:

```ts
const snapshot = await window.ryu.i18n.get();
const label = await window.ryu.i18n.translate({
  id: "my-app.refresh",
  defaultMessage: "Refresh",
});
const subscription = window.ryu.i18n.subscribe({
  onChange(next) {
    document.documentElement.lang = next.locale;
    document.documentElement.dir = next.direction;
  },
});
```

An active language subscription follows later language choices and installed-pack changes while
the panel stays open. Call `subscription.dispose()` when your app no longer needs updates;
closing the panel also ends its subscriptions.

The plugin SDK exposes the same API as `context.plugin.host.i18n`. It is read-only. Apps and
plugins can translate their own IDs and react to a pack change, but cannot install packs,
change another app's copy, access the full catalog, or receive credentials. The primitive is
available through the desktop, webapp, mobile WebView, browser-extension sandbox, Island, and
widget host paths.

The browser extension's content-script overlays (the selection action, in-page Copilot launcher,
and AI-site prompt toolbar) run outside the React extension page. They use the extension worker's
read-only translation request, which loads the same built-in/installed pack and caches the result;
page selections, Copilot answers, prompt records, and other user content are marked literal and are
not rewritten.

Shared Ryu UI primitives localize direct literal children for user-facing controls such as
buttons, labels, headings, menus, select options, dialogs, empty states, and settings rows using
deterministic `literal.<slug>.<hash>` IDs. Data-bearing content such as entity names, tool output,
and status badges stays literal by default because a generic component cannot safely distinguish it
from a label. Use `<I18nText>` or an explicit `t(...)` call for child text that is intended to
localize. String attributes owned by a primitive, such as `aria-label`, `title`, and
`placeholder`, use the shared localization hook where supported. App and plugin authors should
prefer explicit namespaced IDs such as `my-app.refresh`, because they are easier to review and
remain stable when wording changes.

Companion apps get the same boundary from `RyuAppShell`. It mounts the shared provider and
direction context, mirrors the host-selected pack when one exists, auto-detects the browser locale
otherwise, and routes both the fixed toolbar/list/form/empty slots and legacy DOM attributes through
the shared resolver. A Companion should still use those slots for shell copy and keep domain values,
records, and host-provided content literal.

Automatic DOM localization resolves known catalog literals. Unknown prose remains unchanged;
it is never interpreted as an ICU message. For legacy UI copy supplied by a Companion's host
pack, opt the trusted UI subtree in with `data-ryu-i18n="on"`. Keep user records, assistant
responses, and other externally supplied content outside that subtree, or mark them with
`data-ryu-i18n="off"`. An opt-out takes precedence over an ancestor's opt-in.

ICU formatting supports nested select and plural messages within bounded limits: 32,000
characters, 32 brace levels, and 1,024 expressions or option bodies. Messages above a limit
are displayed literally rather than partially formatted.

## Review and maintain community packs

Treat a language pack like any other community-published content: review its repository, release
history, and translations before enabling it. A pack cannot execute code, but misleading text can
still make an interface confusing. Keep the stable message IDs, bump the package version when
changing translations, and publish a new immutable Release for each update.

When Ryu adds new interface messages, older packs continue to work because the missing IDs fall
back to English. Pack authors can update later to cover the new catalog. Keep interpolated values
and plural/select branches semantically equivalent to the source message.
