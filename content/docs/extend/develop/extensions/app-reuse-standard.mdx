---
title: App reuse standard
description: Build app-specific workflows on Ryu's existing layouts, controls, and runtime infrastructure.
---

A Ryu app supplies domain behavior. Ryu supplies the shared controls, layout vocabulary,
host navigation, theme, capability boundary, and runtime infrastructure. Importing a
stylesheet or wrapping a custom component framework in `RyuAppShell` is not sufficient.

This standard applies to new apps and changes to existing apps. Use it alongside the
[Ryu UI Kit](/docs/extend/develop/extensions/ui-kit) and
[platform consistency contract](/docs/start-here/architecture/platform-consistency).

## Reuse before implementation

Before creating a control or service, find its existing owner and inspect a working
consumer. Prefer a direct import. An adapter may translate app-specific data or events,
but must not reimplement the primitive's appearance, keyboard behavior, or state machine.

| Need | Reuse | The app supplies |
| --- | --- | --- |
| Page layout | `@ryu/blocks/companion/app-ui`: shell, toolbar, main, section, list, detail, form, empty, actions | Domain content and appropriate standard, editor, or canvas mode |
| Controls and overlays | `@ryu/ui/components/*` or the Companion controls exports | Labels, values, callbacks, validation, and named variants |
| Theme | Ryu App UI stylesheet and `@ryu/app-host/companion-theme` | Live theme subscription and root marking |
| App navigation | Manifest sidebar and other contribution surfaces | Declared entries and selected domain resource |
| Background queries | `@ryu/ui/hooks/use-query` | Query keys, granted bridge calls, and optional polling intervals; the shared hook ignores superseded responses |
| Host calls and events | Existing app-host bridges and capability contracts | A narrow domain adapter and subscription cleanup |
| Execution and lifecycle | Core orchestration and the existing sidecar runtime | App-specific backend or sidecar behavior |
| Authorization and policy | Gateway and server-owned permission checks | Capability declarations and visible denied/unavailable states |
| Persistence | Existing grant-gated storage or an app-owned sidecar store | Domain schema, validation, and migrations |

Feature-detect optional host capabilities. Do not add an app-specific Core or Gateway
transport, hard-coded service address, credential store, theme manager, or RPC protocol
when a generic extension seam already carries the operation.

## Compose the layout

Mount through `RyuAppShell` once at the entrypoint. Use `RyuAppToolbar` for a working
title and actions, `RyuAppMain` for page content, and the matching section, form, list,
detail, or empty-state role inside it. Declare app navigation in the manifest so hosted
and standalone app windows use the same navigation owner.

A canvas, timeline, graph, media editor, or domain inspector can keep its specialized
renderer. Its surrounding buttons, menus, dialogs, fields, and statuses still use Ryu.
Do not recreate an app sidebar or generic modal under the name of a domain component.

Use semantic tokens and the shared typography, density, focus, and motion behavior.
Avoid local variant tables, copied utility strings, and CSS that overrides the geometry
of an imported primitive. App CSS should describe the domain visualization or arrangement.

## Bundle the primitives

A sandboxed Companion can bundle Ryu components into its own document. It does not
import a live React tree from its parent. Keep the existing single-file build and CSP
contract; sandboxing is not a reason to replace shared controls with hand-written HTML.

```css
@import "tailwindcss";
@import "@ryu/ui/app-ui.css";
@source "./";
```

The App UI stylesheet registers shared control sources for Tailwind. Keep the app's own
source registration as well. Verify the emitted document: a valid JavaScript import does
not prove that the control's CSS was included. Dialog portals must inherit the same theme
inside the Companion document, including at narrow widths.

Use `NativeSelect` or `Select` for choices, `Checkbox` or `RadioGroup` for selection,
and `Tabs` with `TabsList` and `TabsTrigger` for keyboard-accessible panel switching.
Use `DropdownMenu` for action menus so Escape, focus movement, and dismissal stay shared.

Use `Dialog` or `AlertDialog` with their named title, description, content, and action
parts. Do not use browser `confirm`, `prompt`, or `alert`, clickable backdrop buttons
containing other controls, or a `role="dialog"` div with a local focus implementation.

## Preserve runtime ownership

Use the host bridge for granted platform capabilities and the generic extension proxy
for app-owned services. The app owns its domain data; it does not become the authority
for authentication, billing, model policy, or another app's resources.

App-local preview storage is permitted only in an explicitly labelled no-host preview.
A live storage or service failure must remain unavailable or show an error; it must not
fall back to demo data or claim that an operation succeeded. Keep credentials behind
the existing server or secret-store boundary. Never copy a live save into browser preview
storage. If loading host state fails, show the failure and prevent automatic saves of an
empty replacement until the state has been loaded successfully.

## When something is missing

If the behavior is domain-specific, implement it in the app using the shared controls.
If multiple consumers need a generic capability, extend its existing shared owner.
Record the missing behavior, why current exports cannot express it, and the verification
needed. Do not create another toolkit or copy a component as a shortcut.

A dependency-free static distribution may use the documented contract-compatible adapter
from the UI kit. This is a packaging exception, not permission for each app to maintain
its own controls or design tokens. Verify the adapter against the same contract.

## Acceptance checks

- Check shared imports, manifest navigation, bridge ownership, and removal of obsolete copies.
- Run the app contract check, affected package tests, typecheck, and single-file build.
- Exercise loading, empty, denied, unavailable, failure, and successful states that the flow supports.
- Inspect light and dark themes, narrow layouts, focus entry and restoration, keyboard navigation,
  Escape/cancel, and disabled actions in the rendered Companion.
- Inspect and retain a product screenshot or recording. Identify test harness evidence separately
  from a real host or provider round-trip.
- Update the relevant public documentation when behavior or the authoring contract changes.

Static checks catch known forms of duplicated controls and modal shells. They do not prove
that every abstraction reuses its canonical owner; review that decision explicitly.
