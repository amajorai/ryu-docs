[GitHub topic discovery](/docs/develop/extensions/github-topic-discovery) turns a public repo into
one listing. A **community marketplace** is the collection form of the same idea: one public repo
tagged `ryu-marketplace` hosts a `marketplace.json`, and every entry in its `plugins` array becomes
a listing under your marketplace's own heading. No account, no submission, no review — the topic is
the whole entry.

Because nobody reviews it, a community marketplace is **not an install path** in itself: its
entries are browse-only, exactly like a topic-discovered plugin, and installing one is a separate,
explicit act against the plugin's own repository. Read the [trust section](#trust-listing-is-not-an-install) before you publish this way.

<Callout type="info">
  The `ryu-marketplace` topic is what makes a repo **auto-discoverable**. Consumers don't need it:
  the desktop Store's **Plugins** / **Skills** **Add marketplace** also accepts a `owner/repo`, a git
  URL on any host (GitLab, Bitbucket, self-hosted), or a local path pointing at the same
  `marketplace.json`.
</Callout>

## 1. Add the topic

Push your marketplace to a **public** GitHub repository and tag it `ryu-marketplace` (**Settings**
on the repo page, or the gear next to **About**). That single topic is what Ryu's discovery queries;
you do not push anything to Ryu, and Ryu holds no record of you.

If the same repo also carries `ryu-app` / `ryu-plugin`, the marketplace classification wins — it is
a collection, so it renders its `marketplace.json` entries rather than appearing once as a bare
single-plugin listing.

## 2. Add `marketplace.json`

Ryu looks for it at these paths, first hit wins:

1. `.ryu-plugin/marketplace.json` — canonical, use this one
2. `.agents/plugins/marketplace.json`
3. `.claude-plugin/marketplace.json`
4. `.cursor-plugin/marketplace.json`

Each object in the `plugins` array becomes one listing:

```json
{
  "name": "my-bazaar",
  "displayName": "My Bazaar",
  "plugins": [
    {
      "name": "thing-tool",
      "displayName": "Thing Tool",
      "description": "Does the thing.",
      "version": "1.2.0",
      "source": "you/thing-tool",
      "icon": "lucide:brain",
      "hasCompanion": false
    },
    {
      "name": "canvas",
      "displayName": "Canvas",
      "source": { "repo": "you/canvas" },
      "hasCompanion": true
    }
  ]
}
```

Field notes:

- **`source`** is where each plugin actually lives: a bare `owner/repo` slug, a git URL, or the
  Claude-style source object (`{ "repo": "owner/repo" }` / `{ "url": "…" }`). It drives the
  link-out and the install handoff — an entry's repo is its own repo, never the marketplace's.
- **`hasCompanion: true`** classifies the entry as an **app** (it claims a UI destination);
  anything else is a plugin. This is the per-entry app/plugin split, since a marketplace repo can
  collect both kinds.
- **`displayName`** is the pretty card title; **`name`** is the kebab-case identity (and the
  stable part of the listing's catalog id, so it must be unique within the marketplace). Optional
  card fields: `description`, `version`, `tagline`, `category`, `icon` (a glyph id), `iconUrl`,
  `homepage`.
- The marketplace's own **`name` / `displayName`** becomes the heading under which all of its
  entries render.

A marketplace whose `marketplace.json` is missing or declares no readable entries still renders —
as a single listing of the repo itself, the same way a topic-discovered repo would.

## 3. How it renders

Community marketplaces live in the Store's **Community** area, inside the Apps and Plugins tabs.
Entries are grouped under a big **"Community Marketplaces"** heading with one smaller
**sub-heading per marketplace** and its entries in a grid underneath. Standalone topic-discovered
repos keep their own trailing "From the community" shelf. One "Not reviewed by Ryu" notice covers
the whole community area.

The rest matches topic discovery exactly:

- Cards sort by stars; search matches on entry name, description, and the marketplace repo's topics.
- Every card carries the **Community** / **Descriptor** badges, and the action is **Details**, not
  Install — the detail panel links out to the plugin's own repository.
- Your entry's catalog id is `ghmp:<owner>/<repo>:<entry>`, namespaced so it can never collide
  with, or masquerade as, an installed plugin id.
- Opening a listing surfaces the marketplace attribution ("Marketplace: your name") in the detail
  metadata.

## When it shows up

Discovery is cached for **6 hours** per install, and the topic query returns the top 100 repos by
star count. A new marketplace is not instant, and a zero-star repo in a crowded topic may not
surface until it picks up stars. When GitHub is unreachable or rate-limited, clients keep serving
the last good list with a staleness note rather than blanking the section.

## Trust: listing is not an install

<Callout type="warn">
  **A community marketplace is discovered automatically from the public `ryu-marketplace` topic.
  Anyone can tag a repo. Its entries are published by third parties and are NOT reviewed by Ryu —
  no moderation, no signature, no vetting of any kind. Install at your own discretion.**
</Callout>

Being discovered means exactly one thing: a public repo carries the topic. It is not a
recommendation or evidence that anyone ran the code.

- A marketplace entry carries **no installable manifest** in the catalog; install-by-id skips it
  fail-closed. Tagging a repo cannot make code run on anyone's machine.
- To install, a user takes a separate, explicit action — **Install from URL** against the plugin's
  `source` repo — which is a per-repo decision, not a trust grant to the catalog.
- Write the plugin's own README as the thing that earns the install. If you want review and
  signing instead, publish each plugin to the [Marketplace](/docs/develop/extensions/marketplace).

## Reference

| Surface | Where | Notes |
|---|---|---|
| Topic | `ryu-marketplace` | Discovery topic for a collection; wins over `ryu-app`/`ryu-plugin` on the same repo |
| Marketplace manifest | `.ryu-plugin/marketplace.json`, then `.agents/plugins/`, `.claude-plugin/`, `.cursor-plugin/` | Root, first hit wins |
| Entry `source` | `owner/repo`, git URL, or `{ repo }` / `{ url }` object | The plugin's own repo; drives the link-out / install handoff |
| Catalog id | `ghmp:<owner>/<repo>:<entry>` | Namespaced; never collides with an installed plugin id |
| Trust triple | `origin: "community"`, `reviewed: false`, `descriptor_only: true` | Drives the Community Marketplaces section, the notice, and the Details-not-Install CTA |
| Cache TTL | 6 hours | Stale-serves the last good list when GitHub is unreachable |
