Ryu apps use a shared UI kit. The app chooses its data and domain workflow; the kit sets the visual
layout and controls. Components are source code in the repository, themed by semantic tokens.

Ryu App UI `v1` is the current stable contract version. Every source Companion app must mount
through `RyuAppShell`. Importing the stylesheet alone does not meet the contract.

Follow the [App reuse standard](/docs/extend/develop/extensions/app-reuse-standard)
for the required reuse decisions, packaging checks, and acceptance evidence.

## Source of truth

Each package owns one part of the kit:

- `@ryu/ui` owns controls, fields, dialogs, menus, badges, status, loading, and theme tokens.
- `@ryu/ui/components/connection-status` owns the shared non-blocking connection toast and compact
  status dot; hosts supply the `checking`, `node-unreachable`, `offline`, or `online` phase from
  their platform signal.
- `@ryu/blocks/companion/app-ui` owns the fixed app roles: shell, toolbar, list, detail, form,
  empty state, and actions.
- `@ryu/app-host` owns the host seam: live theme subscription, root marking, and generic bridges.
- Desktop owns navigation chrome. Apps contribute `sidebar_sections`; the host represents each
  enabled app with one Apps-shelf tile in both the normal shell and standalone Ryu App windows.
- A satellite owns its domain state and bridge adapter. It does not copy or fork the visual system.

The one packaging exception is a dependency-free static app that does not bundle the shared
packages. It may carry a small contract-compatible v1 adapter, but it must use the same semantic
tokens and manifest-owned navigation. It cannot create a second visual language.

## Other shared packages

Beyond `@ryu/ui`, `@ryu/blocks`, and `@ryu/app-host`, apps reuse `@ryu/settings` for settings
forms and `@ryu/command` and `@ryu/hotkeys` for command and keyboard navigation.

## State ownership

The kit covers UI, not data. Ryu does not centralize every app's domain tables in a
shared SQL schema. A plugin Action can use grant-gated `storage:kv`; an app with relational data
owns its SQL database in its sidecar and exposes a narrow Action or route through the extension
proxy. This keeps one app from becoming the authority for another app's data.

## Mount a new app

For a new app, use the existing package seams directly and keep the app's adapters local:

```tsx
import { RyuAppShell } from "@ryu/blocks/companion/app-ui";
import { Button } from "@ryu/ui/components/button";

export function App() {
  return (
    <RyuAppShell>
      <Button>Save</Button>
    </RyuAppShell>
  );
}
```

Runtime and app-owned data stay behind their existing authority boundaries.

## Fixed roles

Use the smallest role that expresses the surface:

| Role | Primitive |
| --- | --- |
| Root surface | `RyuAppShell` |
| Title and actions | `RyuAppToolbar` |
| Page grouping | `RyuAppMain`, `RyuAppSection` |
| Collections | `RyuAppList`, `RyuAppListSection`, `RyuAppListItem` |
| Selected content | `RyuAppDetail` |
| Data entry | `RyuAppForm`, `RyuAppField` |
| No data / recovery | `RyuAppEmpty`, `RyuAppActions` |

Domain-specific editors, graphs, canvases, and media surfaces may keep their specialized renderer,
but their chrome and generic controls still use the Ryu kit. This keeps a canvas app recognizable as
Ryu without pretending a graph node is a generic list row. A left navigation rail is not domain art:
move it into the app manifest so Ryu can render it consistently in both hosted and standalone modes.

## App contract

```css
@import "tailwindcss";
@import "@ryu/ui/app-ui.css";
```

```tsx
import { markCompanionAppRoot } from "@ryu/app-host/companion-theme";
import { RyuAppShell } from "@ryu/blocks/companion/app-ui";

markCompanionAppRoot(document.getElementById("ryu-plugin-root"));

export function App() {
  return <RyuAppShell>{/* domain content */}</RyuAppShell>;
}
```

The repository contract check covers every first-party Companion entrypoint. It verifies the root
marker, the shared stylesheet, the `@ryu/blocks` dependency, and the `RyuAppShell` composition.
Primary navigation is still owned by Desktop: app-specific sections belong in manifest sidebar
contributions, while editor, canvas, and inspector rails remain domain content inside the shell.

The source check does not replace rendered checks. Inspect light and dark themes, focus, narrow
widths, empty, error, and loading states, and reduced motion.
