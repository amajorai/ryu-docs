          Server-Sent Events. Each event is framed `event: traffic` with an
          `id:` line holding

          the request id and a `data:` line holding one `TrafficEvent`. A new
          subscriber first

          receives a bounded tail of recent events, then live ones; a comment
          line every 15

          seconds keeps the connection open. One request can produce more than
          one event (a

          guardrail verdict, then its completion or failure), so deduplicate on
          `seq`, never on

          `request_id`.


          Requires the master key, or a loopback peer when auth is disabled. The
          master key

          sees every organization and may narrow the stream with `org`. Any
          other caller bound

          to an organization only ever receives that organization's events and
          is refused

          another one's. Events carry no prompt or response text, no full key
          and no end-user

          hash.
