      - content: >-
          Irreversibly delete every item in one category. Returns `{ removed: N
          }` with

          the number of top-level items deleted. Monitors and meetings are
          cleared by

          looping the existing per-item delete so their side effects
          (scheduler-job

          teardown, SSE) fire; the rest use the store's transactional
          `clear_all`.


          `category` is whatever `GET /api/data/counts` offered — a kernel id,
          or one an

          enabled app declared in its manifest. An app-owned category is refused
          unless

          that app is still enabled, so the authorization matches what the list
          offered

          rather than trusting the client to have filtered.
