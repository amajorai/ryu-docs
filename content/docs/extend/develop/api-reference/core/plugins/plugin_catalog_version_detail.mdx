          Reads the repo at that tag, so the README and the declared

          licence/description/engines/surfaces/permissions are genuinely
          historical. It

          deliberately does NOT include repository health — stars, open issues,
          archived,

          last-updated are current-state facts GitHub reports as of now and
          cannot be

          reconstructed for a past tag. Returning them next to historical fields
          would

          produce a card that looks like "the state at that version" while half
          of it

          silently describes today.


          404 when the tag has no readable manifest, which is normal for tags
          predating

          the listing being packaged — a client should render "not available for
          this

          version", not an error.
