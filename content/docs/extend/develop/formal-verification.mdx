Ryu's default formal verification lane is a small, pinned Lean project for
properties that are easier to state as mathematics than as an end-to-end test.
It covers the semantic core of deterministic reasoning, goal/proof
continuation transitions, and Blueprint dependency graphs. Ryu also supports
Bend projects that keep their laws in `LAWS.bend` and proofs in `PROOF.bend`.

This is a developer and CI verification record. It complements, rather than
replaces, [Automated Reasoning](/docs/apps/reasoning), [Goals](/docs/core/goals),
[Proof of Work](/docs/plugins/proof), live Checks runs, `/proof` workspace
inspection, and `/receipt` visual evidence.

<Callout type="warn">
  The Lean project (`formal/`) and its gate (`tools/verify-lean.mjs`) are part of the Ryu monorepo.
  They are not included in the public `amajorai/ryu` repository, so the commands on this page need a
  monorepo checkout.
</Callout>

## Reference project

The formal project lives under `formal/lean` and is pinned by
`formal/lean/lean-toolchain` to Lean 4.33.1. It has no Mathlib dependency, which keeps the trust and installation surface small.

The checked entrypoint imports the reference models and reports the axiom
dependencies for every declared theorem:

- `Ryu.Formal.Reasoning.entails_iff_no_counterexample` proves the meaning of a
  valid claim: no policy-and-premise model makes the claim false.
- `Ryu.Formal.Goals.continue_requires_active_budget` proves that a continuation
  requires an active goal below its turn cap.
- `Ryu.Formal.Goals.paused_cannot_continue` and
  `Ryu.Formal.Goals.achieved_cannot_continue` prove that paused and achieved
  states have no continuation transition.
- `Ryu.Formal.Graph.no_cycle_of_rank_decrease` proves the reusable graph contract
  used by Blueprint: dependencies with strictly decreasing layers cannot form a
  non-empty cycle.

The shared boolean conformance fixture at
`apps-store/reasoning/backend/fixtures/conformance.json` is projected into Lean
and also loaded by the production Rust reasoning test. It covers the four
runtime verdict classes: `valid`, `invalid`, `satisfiable`, and `impossible`.

Blueprint's
`apps-store/blueprint/backend/fixtures/conformance.json` is projected by
`tools/generate-lean-blueprint-conformance.mjs` and loaded by the production
Blueprint graph test. Its valid diamond and longest-path cases prove that the
recorded layout layers move every dependency strictly downward; its Rust cases
also pin cycle, dangling-dependency, and duplicate-id rejection.

The production Rust and TypeScript implementations remain the runtime owners.
The Lean model is not automatically a proof that those binaries implement the
model; that stronger claim requires conformance fixtures or a bound runtime
snapshot.

## Run the gate

From a Ryu monorepo checkout:

```bash
node tools/verify-lean.mjs
```

The command builds the project, checks the declared theorem reports, parses the
axioms Lean reports, and exits non-zero for a compiler error, missing toolchain,
timeout, theorem-list drift, or an axiom outside `formal/verification.json`'s
allowlist. Set `RYU_LAKE_BIN` when `lake` is not on `PATH`.

The gate checks every projection listed in `formal/verification.json`. Run the
corresponding generator after editing a shared fixture, for example
`node tools/generate-lean-blueprint-conformance.mjs` for Blueprint.

The Lean command prints one JSON certificate with `status` set to `proved`,
`failed`, `unavailable`, or `timed_out`. It includes `claimHash`, `sourceHash`,
the exact Lean toolchain/version, theorem names, axiom dependencies, and bounded
diagnostics. Pass `--snapshot <file>` to bind the certificate to an evidence
snapshot through `snapshotHash`.

## Bend projects

For a Bend project, run the Ryu wrapper from a Ryu monorepo checkout and point it at the
project directory:

```bash
node tools/verify-bend.mjs --project path/to/bend-project
```

The project must contain sibling `LAWS.bend` and `PROOF.bend` files. The wrapper
runs `bend PROOF.bend --verdict` and accepts the result only when Bend exits
successfully and prints `ALL PROOFS CHECK`. Install Bend and make `bend`
available on `PATH`. The certificate uses `system: "bend"`, lists the law names,
records Bend's version when the executable reports it, and hashes the project's
`.bend` sources. Pass `--snapshot <file>` to include a `snapshotHash`. A missing
version string is recorded as `unknown`; it does not turn a failed check into a
passing one.

Bend's [`--verdict` mode](https://github.com/bendlang/bend) rechecks proofs with
the project's Lean-proved kernel. When a workspace has both the Ryu Lean lane
and a Bend project, run both and keep their certificates separate. Lean remains
the default for Ryu's reference model.

To check a Lean or Bend source as one step of a workflow, without a separate gate, use a
[`code` step](/docs/core/workflow-code-and-scripts#code-steps-lean-bend-and-baml) in `check` mode.
It runs Lean or `bend --check-only` in your sandbox and fails the step on an error, a `sorry`, or a
law Bend cannot prove. It does not produce this page's `formal-proof` certificate.

## Evidence boundary

`evidenceLevel: "formal-model"` means the theorem or law was checked against the
recorded formal source. It does not imply that a deployed service, browser
surface, provider response, or screenshot has been verified. Keep those records
in their existing evidence lanes and combine them by hash when a goal requires
both a model invariant and observed product behavior. The built-in `/proof`
verifier runs this gate when a workspace goal is relevant and records the
certificate in its independent verifier report; it still requires separate live
or visual evidence for those claims.
