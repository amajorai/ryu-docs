Agent Inboxes (Ryu Mail) is Ryu Cloud's hosted email service for agents, built on AWS SES. An agent
(or a user) gets a real, hosted inbox at `<local>@<domain>`: a unique address that stores every
email it receives and can send email over an API. It is Ryu's own take on the hosted
email-agent category, built in-house.

<Callout type="info">
  Naming: the user-facing feature is **Agent Inboxes / Ryu Mail**, Ryu's own product.
  "AgentMail" is a third-party product with a similar shape; Agent Inboxes is built and
  hosted by Ryu, not a resale or dependency.
</Callout>

This page describes the hosted control-plane service. The self-hosted
`ryu-mail` process is a separate deployment with a local SQLite store, its own
API bearer, and per-inbox HMAC inbound verification. See [Standalone Ryu Mail](/docs/standalone/mail)
for that contract; its `/api/mail/*` request shape and ownership are not the
same as this hosted API.

## Where it lives

Inboxes, ownership, and send quotas are "what is allowed, measured, or paid for", so per the
Core-vs-Gateway placement rule this is **control plane**, not Core. The pieces:

| Piece | Path |
|---|---|
| Service package (SES send, S3 store, MIME parse, SNS verify) | `packages/mail/` (`@ryu/mail`) |
| REST API (`/api/mail/*`) | `packages/api/src/routers/mail.ts` |
| Plan quotas (single source of truth) | `packages/auth/src/lib/plans.ts` (`emailQuotaForPlan`) |
| Full setup + caveats | AWS SES, S3, and SNS settings for your deployment |

## The service package

`packages/mail/` (`@ryu/mail`) holds the building blocks, each lazy so importing the package never
touches AWS or throws on a missing env var:

- **Send.** `packages/mail/src/ses.ts` builds an SESv2 client lazily on the first send and exposes
  `sendEmail`. It throws `MailNotConfiguredError` when invoked without a configured domain, and
  rethrows SES errors verbatim so the caller can map them to a failed message plus an HTTP status.
- **MIME normalizer.** `packages/mail/src/parse.ts` turns raw RFC822 MIME into the stored message
  shape via postal-mime. `normalizeParsedEmail` is pure (no I/O), so it is unit-tested against a
  hand-built object; `parseRawMime` wraps the parser for the real inbound path. It groups replies by
  thread using the first reference, then the in-reply-to, then the message's own id.
- **Inbound (SNS) verification.** `packages/mail/src/inbound.ts` is the only publicly reachable
  surface, so it is fail-closed. `verifySnsSignature` cryptographically verifies each SNS message
  against its signing certificate, and the cert URL host is allow-listed to AWS SNS endpoints
  (`sns.<region>.amazonaws.com`), https-only. `confirmSubscription` auto-confirms a subscription
  only after the signature verifies and only when the `SubscribeURL` is likewise an allow-listed
  host. `extractSesInbound` reads the raw MIME from the inline SNS `content` when small, otherwise
  from the S3 object the receipt rule wrote.

## API

All endpoints live under `/api/mail` in `packages/api/src/routers/mail.ts`. Auth is either a Better
Auth **session** (the signed-in user plus their active org) or an `x-gateway-key` header (org-scoped,
the programmatic agent path). One `resolveScope` resolver handles both. When mail is not configured
every endpoint returns **503**, so it never crashes boot.

| Method and path | Purpose |
|---|---|
| `GET /mail/status` | `{ configured, domain }`, no auth |
| `GET /mail/inboxes` | List the caller's inboxes |
| `POST /mail/inboxes` | Create `{ name, localPart?, description?, webhookUrl?, clientId?, metadata?, podId?, domainId? }`, plan-gated |
| `GET /mail/inboxes/:id` | A single inbox |
| `PATCH /mail/inboxes/:id` | Rename, toggle, or set the webhook |
| `DELETE /mail/inboxes/:id` | Delete the inbox and its messages |
| `GET /mail/inboxes/:id/messages` | List/search messages, `?direction=`, `?labels=`, `?q=`, and `?limit=` |
| `GET/PATCH/DELETE /mail/inboxes/:id/messages/:messageId` | Read, label/mark, or remove one message |
| `GET /mail/messages/:id` | One message, scoped through its inbox |
| `POST /mail/inboxes/:id/messages/:messageId/reply` | Threaded reply |
| `POST /mail/inboxes/:id/messages/:messageId/reply-all` | Threaded reply to all visible recipients |
| `POST /mail/inboxes/:id/messages/:messageId/forward` | Forward a message |
| `GET /mail/inboxes/:id/threads` | List/search conversation threads |
| `GET/POST/PATCH/DELETE /mail/inboxes/:id/drafts...` | Save, schedule, update, delete, or send drafts |
| `POST /mail/inboxes/:id/send` | Send `{ to, cc?, bcc?, subject, text?, html?, replyTo?, attachments?, headers?, labels?, references?, inReplyTo?, trackOpens?, clientId? }`, plan + quota gated |
| `GET/POST/PATCH/DELETE /mail/webhooks...` | Signed event webhooks, custom header names, and delivery records |
| `GET /mail/events` | Replay durable received/sent/delivery/open events |
| `GET/POST/DELETE /mail/lists...` | Manage `send`, `receive`, or `reply` allow/block entries for inboxes, pods, organizations, or users |
| `GET/POST/PATCH/DELETE /mail/pods...` | Group inbox and webhook scope |
| `GET/POST/PATCH/DELETE /mail/domains...` | Track custom-domain verification and DNS records |
| `POST /mail/inbound` | Public AWS SNS webhook for SES inbound |

The `x-gateway-key` path is what makes this an agent service: an agent presents its org's gateway key
and drives inbox CRUD, listing, and sending with no interactive session.

## Plan gating

Quotas are decided by the shared plan catalog. Inbox creation gates on a live entitlement; sending
atomically reserves a durable monthly slot for the organization or personal account before the
provider call. A provider failure releases the slot, while an accepted send remains counted even if
its history row needs reconciliation.

| Plan | Inboxes | Sends per month |
|---|---|---|
| Free | 1 | 50 |
| Teams | Unlimited, subject to storage | 100,000 |
| Enterprise | Contracted | Contracted |
| Desktop license | off | off |

To change a number, edit one row in `packages/auth/src/lib/plans.ts`. The pricing page strings are
marketing copy; these are the enforced limits.

Inbound SES delivery ids are unique per inbox, so retries are storage-idempotent. The optional legacy
inbox webhook is dispatched after storage with SSRF checks and time bounds; the managed webhook
resource delivers a signed event envelope with bounded retries. Both are best-effort and cannot
delay the public inbound acknowledgement. `Idempotency-Key` makes sends, replies, forwards, and
draft sends safe to retry; reusing a key with different request data returns `409`.

The public TypeScript client exposes the same developer surface as
`client.mail.send`, `client.mail.listThreads`, `client.mail.createDraft`,
`client.mail.createWebhook`, and the list/domain/pod methods. Hosted callers use
the existing organization gateway key; self-host callers use the standalone Mail
bearer and the same path spelling.

## Configuration

Every mail env var is optional. With no `RYU_MAIL_DOMAIN` set the feature is off and every endpoint
returns 503. Before enabling inbound mail, verify the SES domain, inbound MX record, S3 bucket, and
SNS topic subscription in your AWS account.

```
RYU_MAIL_DOMAIN=mail.yourdomain.com   # the only var required to turn it on
AWS_SES_REGION=us-east-1              # falls back to STORAGE_REGION, then us-east-1
AWS_ACCESS_KEY_ID=...                 # falls back to STORAGE_ACCESS_KEY_ID, then the ambient chain
AWS_SECRET_ACCESS_KEY=...             # falls back to STORAGE_SECRET_ACCESS_KEY
RYU_MAIL_S3_BUCKET=ryu-mail-inbound   # raw MIME + attachments
RYU_MAIL_INBOUND_SECRET=...           # required if RYU_MAIL_SNS_TOPIC_ARN is not set
RYU_MAIL_SNS_TOPIC_ARN=...            # expected SES/SNS topic ARN; preferred webhook binding
```

## Operational notes

Inbound mail needs an SES-verified domain, an inbound MX record, an S3 bucket for raw messages, and
an SNS topic subscription. Configure the expected `RYU_MAIL_SNS_TOPIC_ARN`; if the deployment
cannot provide it, `RYU_MAIL_INBOUND_SECRET` becomes mandatory. The signed message is accepted only
when its topic matches the configured ARN or the shared secret matches. Keep all AWS credentials
and the inbound secret in your secret store. Test sending and receiving in a non-production inbox
before you enable the feature for users.
