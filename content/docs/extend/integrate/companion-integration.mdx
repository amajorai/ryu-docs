A companion is an in-desktop overlay panel declared by a plugin. It renders inside the desktop app
and can interact with the chat, memory, tools, and Gateway.

## The companion surface

Declare a companion in `manifest.json`:

```json
{
  "id": "com.example.my-plugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "runnables": [],
  "companion": {
    "label": "My Panel",
    "icon": "sparkles",
    "shortcut": "ctrl+shift+m"
  }
}
```

| Field | Required | Description |
|---|---|---|
| `label` | yes | Display name in the sidebar |
| `icon` | no | Lucide icon name |
| `shortcut` | no | Keyboard shortcut to toggle the panel |

## How it connects

The companion panel is rendered by the desktop shell. It communicates with Core through the
same HTTP API every other surface uses:

- **Chat** — `POST /api/chat/stream` for conversations
- **Memory** — `GET /api/memory/recall` for long-term context
- **Tools** — `GET /api/tools/search` for tool discovery
- **Spaces** — `POST /api/spaces/:id/search` for RAG

All calls are Gateway-governed.

## Background process bridge

Companion apps that need to show or stop long-running work can use the shared background-process
bridge. Add the `background:control` grant to the plugin's approved permissions, then call the
host-provided API:

```json
{
  "permission_grants": ["background:control"]
}
```

```typescript
const processes = await window.ryu.background.list({ running_only: true });

const process = processes[0];
if (process) {
  console.log(process.command, process.cwd, process.elapsed_ms);
  await window.ryu.background.stop({ process_id: process.process_id });
}
```

The list and stop calls are scoped to the verified caller. On an organization-bound node, an
anonymous bridge call is refused and a signed-in caller can see or control only processes registered
under that user; a process id from another user cannot be substituted. `background.stop` queues a
request for the process owner and returns immediately. The owner is responsible for performing its
safe cleanup and publishing the finished snapshot, so callers should list again rather than assuming
the process has already exited. The desktop pinned summary uses the same bridge and registry.

## Ephemeral toast feedback

Apps, frontend plugins, and inline widgets can show short feedback in the desktop shell. Request the
`ui:toast` grant, then use the host API under `window.ryu.ui.toast`:

```json
{
  "permission_grants": ["ui:toast"]
}
```

```typescript
const toastId = await window.ryu.ui.toast.show({
  title: "Publishing workflow",
  description: "Uploading the latest version",
  variant: "loading",
  duration: 60_000
});

await window.ryu.ui.toast.update({
  id: toastId,
  title: "Workflow published",
  description: "",
  variant: "success",
  duration: 4_000
});

await window.ryu.ui.toast.dismiss({ id: toastId });
```

`show` returns an opaque id. An app can use that id only to update or dismiss its own toast. There is
no global clear method. `update` requires the id and at least one changed field. Passing an empty
description clears the previous description.

The supported variants are `default`, `success`, `info`, `warning`, `error`, and `loading`. Titles
can contain up to 120 characters, descriptions up to 500 characters, and an explicit duration must
be between 1 and 60 seconds. Frontend plugin activation code can call the same methods through
`context.plugin.host.ui.toast`.

A toast is temporary feedback for the screen the user is looking at. It does not create an Inbox
entry, a native system notification, or a durable record. Use the app's notification or approval
flow when the message must survive dismissal, a restart, or the user leaving the current screen.

## Desktop extension host

For richer integration, the SDK exposes a desktop extension host API
(`packages/sdk/src/plugin/ryu-plugin.ts`):

```typescript
import type { RyuPlugin } from "@ryuhq/sdk/plugin";

export function activate(context: RyuPlugin): void {
  // Register commands
  context.registerCommand("my-action", () => { /* ... */ });
  
  // Register a panel
  context.registerPanel("My Panel", MyPanelComponent);
  
  // Access host services
  const agents = await context.host.listAgents();
  await context.host.gateway.chat(messages);
  await context.host.spaces.ingestDocument(spaceId, doc);
}
```

<Callout type="warn">
  The desktop extension host is **partly live**. The manifest carries `contributes` blocks and
  activation events, and the activation runtime wakes plugins on `onStartup`. But the full
  in-process plugin API (registering commands, panels, routes) is still being built. See
  [Plugin Runtime](/docs/extend/develop/extensions/plugin-runtime) for the current state.
</Callout>
