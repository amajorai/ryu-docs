Ryu Node Protocol v0 (RNP v0) is the continuity layer between Ryu surfaces and Core nodes. Its first contract moves a bounded, user-approved chat snapshot from one node to another. It uses the existing authenticated Core API rather than adding a new transport.

RNP does not replace the protocols around it:

| Contract | Job |
|---|---|
| RHP | Physical device audio, display, and control frames |
| ACP | A node-local agent process session |
| MCP | Tool discovery and calls |
| `ryu://` | User-facing navigation and handoff links |
| RNP | Logical conversation continuity between configured nodes |

## Continue a chat on another node

Open a saved chat, choose **Continue on another node**, select a node you already configured, and review the exact visible messages that will move. Ryu exports the preview with the source node's credential, freezes that bundle, then imports the same reviewed data with the destination node's credential. A lost response can be retried without creating a new bundle. Ryu binds the chat tab to the destination only after the import succeeds.

The default snapshot contains up to the latest 50 visible user and assistant messages. You can add a short context note and optionally suggest the same agent. Ryu saves the note as a visible user message. It never becomes a hidden system instruction, and the transfer never sends a chat turn automatically.

RNP v0 deliberately leaves these behind:

- node credentials, structured authentication data, and access-control fields;
- files and attachments;
- filesystem, branch, and worktree paths;
- structured tool calls, tool results, and provider provenance;
- run state and node-local ACP session IDs.

The next message starts or resumes an execution session on the destination node from the imported transcript.

## HTTP contract

```text
POST /api/rnp/v0/conversations/:id/export
POST /api/rnp/v0/conversations/:id/resume
```

Export requires read access to the source conversation and includes only its selected visible branch. Resume creates a private conversation for the verified caller or requires write access when that conversation already exists on the destination. Stable conversation, message, bundle, and context IDs make retries of the frozen review idempotent and let optional cloud sync converge on the same data later.

The TypeScript contract is available from `@ryuhq/protocol/continuity`. The encoded bundle is capped at 2 MiB, with at most 200 messages and 16 text context items. Implementations reject unsupported versions and oversized data instead of guessing or truncating silently.

## Handoff links

```text
ryu://handoff/<conversation-id>?source=<node-url>&v=0
```

A handoff link is a locator, not the transcript. It carries only the conversation ID, protocol version, and a credential-free HTTPS source-node URL (HTTP is accepted only for loopback Core). The receiver must match that URL to a node already configured on the device and show the exported transcript review. Unknown nodes fail closed. Extra fields, tokens, prompts, context, query-bearing node URLs, and embedded credentials are rejected.

## Cloud sync is optional

Cloud conversation sync can make the referenced conversation available before the handoff starts. RNP may treat the last included message ID as a readiness checkpoint and skip duplicate inserts. Sync is an optimization, not a requirement: the explicit export and resume flow still works when cloud sync is off.
