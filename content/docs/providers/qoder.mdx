title: Qoder Provider
description: "How to connect Qoder Global or Qoder CN as a text-only provider through the official regional CLI and a personal access token, and what the provider rejects."
---

Qoder Global and Qoder CN are separate direct providers. Ryu invokes the official
regional CLI for a single text turn; it does not treat `qoder.com` or `qoder.cn` as
OpenAI inference endpoints and does not use OAuth for these providers.

## Connect an account

1. Install the official regional CLI on the machine running the selected Core.
   Use the [Global installation guide](https://docs.qoder.com/cli/installation)
   or [CN installation guide](https://docs.qoder.cn/en/cli/installation).
2. Create a personal access token in the regional account's integrations page:
   [Global](https://qoder.com/account/integrations) or
   [CN](https://qoder.cn/account/integrations).
3. Choose **Qoder Global** or **Qoder CN** in the provider settings, save the PAT,
   discover that account's models, then select and activate a returned model.

Ryu stores the PAT in its sealed account vault. The selected token is passed only
to the corresponding CLI process. It is not written into Pi's `auth.json` or
`models.json`, copied into the parent environment, or sent as an OpenAI API key.
Global and CN tokens cannot substitute for one another.

The official authentication variables are `QODER_PERSONAL_ACCESS_TOKEN` for Global
and `QODERCN_PERSONAL_ACCESS_TOKEN` for CN. Ryu supplies its selected sealed PAT
explicitly instead of falling back to an unrelated saved CLI login. See the
[Global authentication contract](https://docs.qoder.com/cli/authentication) and
[CN authentication contract](https://docs.qoder.cn/en/cli/authentication).

## Models and supported input

Model discovery uses the installed CLI's `--list-models` result for the selected
account. Availability depends on the regional account and its entitlement; Ryu
does not invent a static model list. Changing the selected PAT invalidates the
credential-bound discovery cache.

This provider accepts text and preserves reasoning output when the CLI emits it.
Image input and tool declarations are rejected. Native CLI tools and MCP servers
are disabled, settings sources are disabled, and no CLI conversation is persisted.
Use an agent configuration without tools for this direct provider.

The normalized streaming response is emitted after the CLI's terminal result has
been validated. It does not promise token-by-token latency from the vendor.

## Credits and regional setup

Qoder's native credit-limit result becomes an **insufficient quota** response for
the selected account. Qoder does not expose a verified public quota API, so Ryu
does not advertise quota observations or quota-aware account rotation for it.

Qoder CLI's custom-model wizard is separate from connecting Qoder as a Ryu
provider. Ryu does not overwrite undocumented Qoder settings to redirect its CLI
to Gateway. Configure vendor-supported custom models through Qoder's own
[`/model` workflow](https://docs.qoder.com/cli/custom-models).

See [provider accounts](/docs/providers/byok) for account setup and
[provider routing](/docs/providers/routing) for transports.
