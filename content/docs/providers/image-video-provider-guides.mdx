This page covers setup and limits for each direct image and video provider. For the provider matrix,
request routes, and Topaz video enhancement, see [Image and Video](/docs/providers/image-and-video).

## Recraft

The direct `recraft` provider uses Recraft's JSON image-generation API. Add its
API token in **Gateway → API keys → Provider keys**, or configure
`[providers.recraft]` with `api_key`, optional `api_keys`, and an optional
`base_url` (default `https://external.api.recraft.ai/v1`). Environment-based
configuration accepts `RECRAFT_API_KEY`, `RECRAFT_API_KEYS`, and
`RECRAFT_BASE_URL`.

Use a `recraftv` model ID such as `recraftv4_1` with `/v1/images/generations`.
The model catalog reports the documented V2, V3, V4, and V4.1 generation
variants as image models. Chat, embeddings, video, editing and raw multipart
results are not advertised by this adapter. The Gateway supports `url` and
`b64_json` results, with a total JSON response limit of 64 MiB. Native style,
size, seed, and image-format fields are forwarded in the JSON body; model-specific
constraints are enforced by Recraft. Local validation requires a nonempty prompt,
checks its model-specific length, and limits `n` to 1–6.

Accounts support names, enable/disable controls, priority and rotation after
quota or credit rejection. Assigned outbound proxy pools are supported. A lost
or invalid successful generation response is not replayed through another
account or provider. Save returned assets promptly if you need durable storage.
See Recraft's [endpoint reference](https://www.recraft.ai/docs/api-reference/endpoints)
and [model limits](https://www.recraft.ai/docs/api-reference/appendix).

## Stability AI

The direct `stability` provider translates `/v1/images/generations` JSON into
Stability's native multipart API. Supported generation IDs are
`stable-image-ultra`, `stable-image-core`, `sd3.5-large`, `sd3.5-large-turbo`,
`sd3.5-medium`, and `sd3.5-flash`. Add keys in **Gateway → API keys**, or configure
`[providers.stability]` with `api_key` and optional `api_keys`. The default
`base_url` is `https://api.stability.ai/v2beta`. Environment configuration accepts
`STABILITY_API_KEY`, `STABILITY_API_KEYS`, and `STABILITY_BASE_URL`.

This adapter handles one text-to-image generation per request (`n: 1`). It
returns `b64_json`, with a 32 MiB image response limit. The default output is PNG;
`output_format` also accepts JPEG or WebP. Use Stability's `aspect_ratio`,
`negative_prompt`, and `seed` options. Gateway sizes `1024x1024`, `1536x1024` and
`1024x1536` map to `1:1`, `3:2` and `2:3`; these select aspect ratios rather than
promising exact output dimensions. SD3.5 supports `cfg_scale`; Core and SD3.5
support `style_preset`. Conflicting sizes/ratios and unsupported inputs are
rejected before submission. Editing, hosted URL results, audio and video are not
advertised by this generation adapter.

Named accounts and assigned proxy pools are supported. Quota or credit rejection
can select another eligible account before acceptance. Invalid or lost successful
image responses stop replay. Use one API key for each provider account, following
Stability's [API reference](https://platform.stability.ai/docs/api-reference).

## Black Forest Labs

The direct `bfl` adapter submits FLUX image tasks and polls the returned task URL
inline. It also exposes queued `flux-3-video` text-to-video jobs. Add keys in
**Gateway → API keys**, or set `[providers.bfl]` with `api_key`, optional `api_keys`,
and `base_url` (default `https://api.bfl.ai/v1`). Environment configuration accepts
`BFL_API_KEY`, `BFL_API_KEYS`, and `BFL_BASE_URL`. Inline image polling defaults to
500 ms with a 180-second limit; operator settings `poll_interval_ms` and
`poll_timeout_secs` adjust that wait.

Configured model discovery reports the documented FLUX.2 and legacy image
endpoints. Generate one asset per request. Image output uses `url`;
`b64_json` and local asset rehosting are not implemented. Signed delivery URLs
expire, so download assets promptly; browser CORS access to BFL delivery URLs is
not guaranteed. Native model options are forwarded, while `size` maps to width
and height. Model-specific resolution limits remain upstream constraints.

Submission rejection for quota or credits can select another account. After
acceptance, queued polling retains its original account and actual selected HTTP client.
Video references include an opaque credential fingerprint, preserving account
identity after key reordering. Poll URLs are
restricted to the configured origin or trusted HTTPS BFL API hosts, with the
returned task ID checked. Invalid accepted responses, poll failures and inline
timeouts stop generation replay. Gateway API clients do not follow redirects
implicitly; configure the final upstream URL.

The video operation defaults to `t2v`; other video modes, edit tools, webhooks,
and audio-only operations are not advertised by this adapter. See BFL's
[generation guide](https://docs.bfl.ai/quick_start/generating_images) and
[FLUX 3 API](https://docs.bfl.ai/api-reference/utility/generate-a-video-with-flux-3).

<Callout type="warn">
  Live model, asset-delivery, and video output validation require a BFL test key. Test with your
  own key before you depend on this adapter.
</Callout>

## MiniMax images

MiniMax connects directly to its native image-generation API. Configure one or
more provider keys under **Gateway → API keys → Provider keys (BYOK) → MiniMax**. Each
account can have a name, an enabled state and a priority. Assigned proxy pools
also apply. These upstream keys are separate from Gateway client keys.

Use model **image-01** with the OpenAI-compatible image-generation endpoint.
The adapter supports `n` from 1 to 9, a nonempty prompt up to 1500 characters,
`response_format: url` or `b64_json`, and `size: WIDTHxHEIGHT` with both dimensions
from 512 to 2048 in multiples of 8. Native `aspect_ratio`, `seed` and
`prompt_optimizer` options are supported. Choose size, native dimensions or an
aspect ratio without combining them. URL outputs expire after 24 hours.

MiniMax returns native error codes even with HTTP 200. Definitive quota and
insufficient-balance errors can try another eligible account. Accepted or
ambiguous failures, invalid output and moderation stop automatic replay.
Successful responses are normalized to OpenAI image objects and bounded to
64 MiB. This adapter supports text-to-image; other MiniMax services require their
own operation-specific adapters.

For headless configuration use `[providers.minimax]` with `api_key`, optional
`api_keys` and optional `base_url` (default `https://api.minimax.io/v1`). Environment
alternatives are `MINIMAX_API_KEY`, `MINIMAX_API_KEYS` and `MINIMAX_BASE_URL`.
See the [MiniMax image API](https://platform.minimax.io/docs/api-reference/image-generation-t2i)
for supported native options and account requirements.

## Runway videos

Connect Runway directly under **Gateway → API keys → Provider keys (BYOK) → Runway**.
Multiple accounts support names, enabled states, priorities and assigned proxy
pools. These credentials are separate from Gateway client keys.

Use `gen4.5` for text-to-video or image-to-video and `gen4_turbo` for
image-to-video. Requests use `prompt` (or native `promptText`), a native `ratio`
(or `size` such as `1280x720`), and `duration` in seconds. Gen-4.5 requires a
duration from 2 to 10; Gen-4 Turbo accepts the same range when supplied.
Prompts are limited to 1000 UTF-16 code units. Submit one video per request.

`promptImage` selects image-to-video. It accepts an HTTPS image URL, an existing
Runway upload URI, or a JPEG/PNG/WebP base64 data URI up to 5 MiB. A single native
first-frame image object is also supported. Text-only Gen-4.5 accepts `1280:720`
and `720:1280`; image mode additionally accepts `1104:832`, `832:1104`, `960:960`
and `1584:672`. Native options are forwarded to Runway for model-specific checks.

The video endpoint returns a queued job. Poll the returned Gateway job ID for
status and output URLs. Live account metadata changes preserve accepted jobs,
including when an account is disabled. Credential changes restart
Gateway and discard its in-memory job handles; retrieve pending results before
adding, replacing or removing credentials. An assigned proxy remains bound to
the job while Gateway is running.
Quota and credit rejection can try another eligible account before acceptance.
Ambiguous submission or polling failures never start another generation.
Output URLs expire within 24–48 hours; retrieve the job again for fresh URLs.

Headless configuration uses `[providers.runway]` with `api_key`, optional
`api_keys` and `base_url` (default `https://api.dev.runwayml.com/v1`). Environment
alternatives are `RUNWAY_API_KEY`, `RUNWAY_API_KEYS` and
`RUNWAY_BASE_URL`. The adapter sends API version `2024-11-06`.
See [Runway's API reference](https://docs.dev.runwayml.com/api/) for native options.
