BYOK means the request uses a credential you or your organization controls. It does not mean the
provider skips Ryu's Gateway policy, and it does not make a local model a cloud provider.

## Account paths

| Account path | Examples | Stored or enforced by |
|---|---|---|
| Gateway provider credential | OpenAI, Anthropic, OpenRouter, Fal, Replicate, Modal, or a custom endpoint | Gateway configuration and credential boundary |
| GenAI adapter credential | Gemini, Groq, xAI, DeepSeek, Cohere, and other configured native adapters | GenAI provider's adapter-key map |
| Agent provider account | Pi or ACP subscription/provider accounts | Core's provider account store and agent runtime |
| Local runtime | Ollama, Docker Model Runner, Mesh LLM, or another local OpenAI-compatible service | The local node or adopted runtime |
| Ryu-managed route | Managed OpenRouter or a credit-isolated provider slot | Managed control plane and Gateway policy |

The same vendor can appear in more than one row. An OpenAI BYOK slot and an OpenAI credit-isolated
slot use the same protocol but must remain separate for billing and credential custody.

## Personal versus shared use

Provider accounts and Gateway providers answer different scope questions:

- a personal account is used by the selected user or agent runtime;
- a Gateway provider can serve multiple governed callers on a node or fleet;
- a managed provider can use a platform-owned credential while still recording the calling identity;
- a local provider has no cloud credential but can still be restricted by node and Gateway policy.

Do not infer that selecting an account changes every other agent. Account switching is explicit and
the provider/model selection remains a separate setting.

## Usage and billing

Usage dimensions remain separate:

- provider-native subscription usage belongs to the provider account;
- Ryu wallet or credit usage belongs to the managed or credit-isolated route;
- local inference has node resource cost but no upstream provider bill;
- media and tool calls can carry a provider-reported cost or a clearly labeled estimate.

The provider ID used for a request is the attribution boundary. A managed OpenRouter request and a
BYOK OpenRouter request must not be reported as the same account just because they share a vendor.

## Safe setup

1. Add the credential through the Gateway or agent runtime's account surface.
2. Select the provider and model for the intended agent, modality, or Toolkit layer.
3. Confirm the provider is configured and available.
4. Send a bounded test request and inspect the provider/request attribution.
5. Remove or rotate the credential in its owning store when it is no longer needed.

Secrets are write-only or redacted in read projections. They should not be copied into model IDs,
public manifests, documents, or chat prompts.
