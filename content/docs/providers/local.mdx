Local providers keep inference on the node or adopt a local OpenAI-compatible service. Core owns
the local lifecycle where it owns the process: install, model cache, start/stop, health, and
hardware fit. Adopted services remain owned by their own runtime.

## Local chat and vision runtimes

The platform column is the node check Core runs before it installs, starts, or switches to an
engine. The node, not the client driving it, answers that check, so a remote Desktop sees the
requirement of the Core node it targets. An engine the node cannot run stays listed with a
sentence that says what it needs.

| Runtime | Engine ID | Model format | Platform | Ownership |
|---|---|---|---|---|
| llama.cpp | `llamacpp` | GGUF | Every platform | Core-managed; the default local Chat runtime |
| Ollama | `ollama` | Ollama model namespace | Every platform | Adopted or Core-started service |
| vLLM | `vllm` | Safetensors | Linux x86_64 or arm64, ideally with an NVIDIA GPU | Core-managed Python server |
| SGLang | `sglang` | Safetensors | Linux x86_64 or arm64, ideally with an NVIDIA GPU | Core-managed Python server |
| MLX | `mlx` | MLX | Apple Silicon Mac | Core-managed; text Chat |
| MLX-VLM | `mlx-vlm` | MLX | Apple Silicon Mac | Core-managed; vision and omni Chat |
| mlx-serve | `mlx-serve` | MLX | Apple Silicon Mac on macOS 26.2 or newer | Core-managed native server |
| oMLX | `omlx` | MLX | Apple Silicon Mac | Adopted multi-model server |
| Apple Intelligence | `apfel` | OS-provided model | Apple Silicon Mac on macOS 26 or newer, with Apple Intelligence on | On-device Chat through apfel |
| Docker Model Runner | `docker-model-runner` | Docker/Hugging Face model IDs | Where Docker Model Runner runs | Adopted; Docker owns the models |
| Mesh LLM | `mesh-llm` | Mesh LLM's configured models | Where Mesh LLM runs | Adopted or started; distributed Chat |
| Lemonade Server | `lemonade` | Lemonade's model store | Where Lemonade runs | Adopted; Lemonade owns models and backends |
| Magnitude | `magnitude` | Magnitude's model store | Where Magnitude runs | Adopted; Magnitude owns models and tuning |
| llama-swap | `llama-swap` | Backends from its YAML config | Where llama-swap runs | Adopted; llama-swap owns model swapping |
| FreeToken | `freetoken` | FreeToken's model store | Linux or Windows on x86_64 | Adopted; NVIDIA-focused |

Only one local Chat engine is active at a time. The resident model can be swapped. Selection checks the
model format: an incompatible model is shown with the reason it needs another engine and is not
selected.

## Supporting local tiers

| Tier | Provider or engine | Role |
|---|---|---|
| Embedding | llama.cpp embedding server | Vectors for Spaces, memory, and semantic routing |
| Reranking | llama.cpp reranker | Re-score retrieved candidates |
| Classification | Dedicated local classifier tier | Inspection and smart-routing decisions |
| Voice Recognition | whisper.cpp or optional Parakeet | Audio to raw transcript. The prebuilt whisper.cpp server is Windows-only; on macOS and Linux place your own `whisper-server` build or use Parakeet |
| Speech Processing | S1-mini by Superwhisper | Optional transcript cleanup |
| Audio | Ryu Audio or OuteTTS | Text to speech |
| Voice runtime | audio.cpp (optional, separate process) | Speech to text and text to speech on macOS, Linux x86_64, or Windows x64 |
| Image and video | stable-diffusion.cpp | Local generative media. Prebuilt servers exist for Windows x64, Linux x86_64, and Apple Silicon |

These supporting tiers can run alongside the active Chat runtime. The embedding tier is not a
second Chat choice, and the speech cleanup tier is not a general model picker entry.

## Local model formats

| Format | Local engines |
|---|---|
| GGUF | llama.cpp, Ollama, Docker Model Runner |
| Safetensors | vLLM, SGLang |
| MLX | MLX, MLX-VLM, mlx-serve, oMLX |

The node's detected RAM, VRAM, platform, and engine availability determine the fit result. A model
catalog entry is not a promise that the same model will fit on every node.

## Process ownership

Ryu's local provider path can point at a Core-managed process, a local service you already run, or a
custom OpenAI-compatible endpoint on a controlled network.

- Core owns filesystem and process state for the engines it manages.
- Gateway owns policy and cloud egress.
- An adopted runtime owns its model store and service lifecycle.

Some filesystem-backed OpenAI-compatible runtimes, including llama.cpp, report the loaded model's
absolute file path as the model id. Gateway preserves that id for the provider request and routes
path-shaped ids back to the local provider, so the model shown by live discovery remains callable.
