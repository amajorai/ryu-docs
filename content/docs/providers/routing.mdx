Provider selection is a routing decision, not a hardcoded vendor switch. The requested model,
modality slot, node defaults, and configured fallback policy all participate in the result.

## Model routing precedence

For a normal Gateway request, the route resolves through:

1. An exact model-map entry
2. The longest matching model prefix
3. A built-in prefix rule
4. The configured default provider

Common built-in prefixes include:

| Model form | Provider path |
|---|---|
| `gpt-`, `o1`, `o3`, `o4` | OpenAI |
| `claude-` | Anthropic |
| `gemini-` | Google GenAI |
| `openrouter/` | OpenRouter |
| `modal/` | Modal |
| Local model families such as `llama`, `mistral`, `gemma`, `phi`, `qwen`, and `deepseek` | Local runtime |
| `zeroclaw`, `openclaw` | Core agent provider |

An explicit model map can remap a name to another provider. Use stable model IDs and do not rely on
an array position or a mutable display label.

## Modality slots

Chat, image, TTS, STT, and video can have separate provider/model mappings. A chat provider is not
automatically used for image or speech, and a per-agent slot can override the node's modality map.

| Modality | Example provider choices |
|---|---|
| Chat | OpenAI, Anthropic, GenAI, OpenRouter, local, Modal, Vertex, Bedrock, Cloudflare |
| Image | OpenAI, OpenRouter, Fal, Replicate, stable-diffusion.cpp |
| Embeddings | OpenAI, OpenRouter, local, custom OpenAI-compatible endpoints |
| TTS | OpenAI, Fal, Replicate, local Ryu Audio, OuteTTS |
| STT | OpenAI or compatible Gateway endpoints, local whisper.cpp, optional Parakeet |
| Video | Fal, Replicate, stable-diffusion.cpp |

## Fallback and health

Fallback chains try another configured provider when the primary provider is unavailable, rate
limited, or otherwise eligible for demotion. The response keeps a degraded signal when the request
did not use its preferred provider. A provider being present in configuration does not mean it is
healthy; credentials, upstream model support, and local process state are checked separately.

## Inspect the current state

Use the live Gateway and Core surfaces to answer different questions:

- provider health tells you whether the registered backend responds;
- model discovery tells you what the provider reports;
- modality discovery tells you the configured provider/model slots;
- capability discovery tells you which Toolkit and document providers are enabled, available, or bound;
- a provider round-trip proves only the exact request that was sent.
