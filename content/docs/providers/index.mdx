Providers are the backends that answer a capability request. Ryu keeps four concepts separate:

| Concept | Meaning |
|---|---|
| Capability | What the request needs: chat, embeddings, speech, media, document parsing, or a Toolkit layer |
| Provider | Who answers the request: OpenAI, OpenRouter, a local runtime, a parser, or a plugin provider |
| Engine | The runtime that serves local model weights, such as llama.cpp or MLX |
| Model | The model or weights selected inside a provider or engine |

Use this root to find the complete provider surface. A provider listed here is a supported contract
or integration path; it is not necessarily enabled on every node. Cloud providers need their own
credentials, local engines need a compatible machine or an already-running service, and optional
apps need to be installed and enabled.

## Provider families

| Family | Examples | Credential or runtime boundary |
|---|---|---|
| Cloud and managed | OpenAI, Anthropic, Google GenAI, OpenRouter, Modal, Cloudflare Workers AI, AWS Bedrock, Vertex AI, Fal, Replicate | Credentials and egress are owned by the Gateway or managed control plane |
| Local | llama.cpp, Ollama, vLLM, SGLang, MLX, MLX-VLM, oMLX, Docker Model Runner, Apple Intelligence, Mesh LLM | The node owns the process, model cache, health, and hardware fit |
| Custom | OpenAI-compatible endpoints, native GenAI adapters, plugin-declared providers | The adapter declares its contract; Ryu does not infer capability from a display name |
| BYOK | Your OpenAI, Anthropic, OpenRouter, media, or custom endpoint credentials | Keys stay in the provider account or Gateway credential boundary and are not model metadata |

## Read availability correctly

The provider picker and API expose more than one state:

- **Supported** means Ryu has a provider, engine, or capability contract for that path.
- **Configured** means the node has the required credential or endpoint settings.
- **Installed** means a local app, engine, or model is present on the node.
- **Available** means the configured or installed dependency is healthy now.
- **Bound** means the provider is the current selection for the capability.

These states are intentionally not collapsed. An OpenRouter model can be supported but absent from
the live model discovery response; a document parser can be installed but report that its optional
OCR dependency is missing; and a local model can fit poorly even when its engine is installed.

## The complete inventory

### Gateway provider IDs

The Gateway's provider registry currently covers these request paths:

| Provider | Stable ID | Main capabilities |
|---|---|---|
| OpenAI | `openai` | Chat, embeddings, images, STT, TTS |
| Anthropic | `anthropic` | Chat through the Anthropic Messages protocol |
| Google GenAI | `genai` | Native chat adapters such as Gemini, Groq, xAI, DeepSeek, and Cohere |
| OpenRouter | `openrouter` | Chat, embeddings, and image generation through a dynamic upstream catalog |
| Modal | `modal` | OpenAI-compatible chat against a serverless GPU endpoint |
| Local | `local` | Chat, embeddings, and reranking against a node-local OpenAI-compatible runtime |
| Core | `core` | Core-hosted agent completions over loopback |
| Cloudflare Workers AI | `cloudflare` | OpenAI-compatible cloud model endpoint |
| AWS Bedrock | `bedrock` | Anthropic-Messages-compatible cloud model endpoint |
| Google Vertex AI | `vertex` | OpenAI-compatible Vertex chat endpoint |
| Replicate | `replicate` | Image, TTS, and asynchronous video predictions |
| Fal AI | `fal` | Image, TTS, and asynchronous video queue jobs |

The `classify` slot is a separate local classifier tier. `openai-credits` is a billing-isolated
OpenAI slot, not a second user-facing OpenAI protocol. `managed-openrouter` and `gateway` describe
managed delivery modes rather than additional upstream model APIs.

### Node-local provider and Toolkit inventory

| Layer | Supported options |
|---|---|
| Local chat and vision | llama.cpp, Ollama, vLLM, SGLang, MLX, MLX-VLM, oMLX, Docker Model Runner, Apple Intelligence, Mesh LLM |
| Local embeddings and ranking | llama.cpp embedding tier, llama.cpp reranker, local OpenAI-compatible endpoints |
| Voice Recognition | whisper.cpp, optional Parakeet |
| Speech Processing | S1-mini by Superwhisper through the local llama.cpp speech tier |
| Audio | Ryu Audio with Kokoro, KittenTTS, or Pocket TTS; OuteTTS |
| Local image and video | stable-diffusion.cpp |
| Document extraction | AnyDoc, MarkItDown, Docling, MinerU, Unstructured |
| Toolkits | Exa, Tavily, Brave, Firecrawl, Serper, Spider, SpiderCloud, memory providers, browser providers, and computer-control providers |
