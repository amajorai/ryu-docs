OpenRouter is one Gateway provider with a dynamic upstream model catalog. It is useful when the
model choice should remain within one OpenAI-compatible route while OpenRouter selects or exposes
the upstream model family.

## Model IDs

Ryu routes the following model-ID forms to the OpenRouter provider:

| Form | Meaning |
|---|---|
| `openrouter/auto` | OpenRouter chooses an upstream model for the request |
| `openrouter/pareto-code` | OpenRouter's coding-oriented router chooses a model |
| `openrouter/<provider>/<model>` | A specific OpenRouter catalog model, using the model slug returned by discovery |

The catalog is live. Do not copy a temporary model list into an agent definition when discovery or
the OpenRouter catalog can provide the current ID. Ryu also keeps the two router entries above in
the built-in model surface so they can be selected without enumerating every upstream model.

## Supported Ryu operations

| Operation | Support |
|---|---|
| Chat completions | Yes, streaming and non-streaming |
| Embeddings | Yes, when the selected OpenRouter model supports the endpoint |
| Reranking | Yes, when the selected OpenRouter model supports the endpoint |
| Image generation | Yes, through the provider's image adapter |
| STT | Not a generic OpenRouter provider operation in Ryu's Gateway contract |
| TTS | Not a generic OpenRouter provider operation in Ryu's Gateway contract |
| Video generation | Not a generic OpenRouter provider operation in Ryu's Gateway contract |

Use the [Speech](/docs/providers/speech) or [Image and video](/docs/providers/image-and-video)
pages when you need a provider with the corresponding media operation.

## Ryu-managed versus BYOK OpenRouter

| Path | Credential owner | Policy behavior |
|---|---|---|
| Ryu-managed OpenRouter | Ryu's managed delivery boundary | The deployment can enforce provider privacy, usage accounting, and credit policy |
| BYOK OpenRouter | Your OpenRouter account | Your account and key fund the request; Ryu still applies the local Gateway policy path |
| Custom OpenRouter-compatible endpoint | The endpoint owner | Ryu uses the configured base URL and only the operations that endpoint implements |

Ryu can inject server-side OpenRouter options such as provider data-collection posture, zero-data-
retention requirements, sorting preference, response healing, and usage accounting for managed
routes. A BYOK request retains its own routing intent unless the configured deployment policy says
otherwise.

## Routing

The `openrouter/` prefix is resolved before the Gateway default provider. This means a specific
OpenRouter model remains on the OpenRouter path even when the node's default provider is local or
OpenAI. Fallback and budget policy still run before the upstream request.

See [Routing](/docs/gateway/routing), [Chat and models](/docs/providers/chat-and-models), and
[BYOK and provider accounts](/docs/providers/byok).
