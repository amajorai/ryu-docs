Use this page to set up providers on a node from the desktop app. Where credentials are stored is
on [BYOK and Provider Accounts](/docs/providers/byok).

## Set up a chat provider

In Desktop, **Gateway → AI providers** opens the node's provider command center. Expand a chat
provider to:

- save or check a BYOK key;
- discover models, then choose a model and thinking level;
- enable models;
- set that provider's egress to direct or through Gateway.

**Use this provider** saves the active Core agent provider and model.

## Sign in to a subscription provider

Subscription providers open their sign-in flow instead of asking for an API key.

- Authorization links and device-code verification open in your system browser. If that handoff
  fails, the dialog shows an error and lets you try the browser button again.
- The dialog shows provider and Core errors inline. Use **Cancel** to stop an attempt, and reopen
  **Login** to retry.

Saved provider accounts can be selected for the current Ryu session. Setting one as the shared
Gateway account requires the `gateway.configure` permission, and the action is disabled on managed
Ryu Cloud nodes.

Per-provider sign-in steps are on [Chat and Models](/docs/providers/chat-and-models#oauth-accounts-in-the-managed-pi-engine)
and [ChatGPT Plan on Self-Hosted Core](/docs/providers/chatgpt-plan).

## Enable or hide models

In **Gateway → AI providers**, use each model's switch to control its availability, or use the
all-model switch for the currently listed models. An all-model change saves each choice in order,
waiting for its acknowledgement before sending the next. The model controls remain disabled while
that change is pending.

If a request fails, the remaining changes stop and the error reports how many model settings were
saved. Earlier acknowledged choices stay saved, and there is no rollback of the whole group. Review
the individual switches and retry the remaining choices. Reloading reads the saved settings from
the node.

## Review media providers

The **Other capabilities** section is a read-only summary of the providers serving image, speech,
audio, and video requests.

- **Edit capability routing** opens the single routing editor.
- **Manage media keys** opens Gateway keys.
- The Replicate and Fal rows show **Key set** or **No key**. The presence of that key activates the
  media provider, so these rows have no second enable switch.

## Edit Gateway keys

Gateway keys remain under **Gateway → API keys**.

- The BYOK credential value is saved and is not shown again. A failed save keeps the entered value
  available to retry. Storage details are on
  [Chat and Models](/docs/providers/chat-and-models#how-provider-key-saves-are-stored).
- Editing Gateway keys requires the node's `gateway.configure` permission.
- Managed Ryu Cloud nodes show read-only provider-key state because their credentials are held
  server-side.
