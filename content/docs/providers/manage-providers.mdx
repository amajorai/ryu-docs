Use this page to set up providers on a node from the desktop app. Where credentials are stored is
on [BYOK and Provider Accounts](/docs/providers/byok).

## Set up a chat provider

In Desktop, **Gateway → AI providers** opens the node's provider command center. Expand a chat
provider to save or check a BYOK key, discover models, choose a model and thinking level, enable
models, or set that provider's egress to direct or through Gateway. **Use this provider** saves the
active Core agent provider and model.

## Sign in to a subscription provider

Subscription providers open their sign-in flow instead of asking for an API key. During sign-in, the
dialog shows provider and Core errors inline. Use **Cancel** to stop an attempt, and reopen
**Login** to retry. Authorization links and device-code
verification open in your system browser. If that handoff fails, the dialog shows an error and lets
you try the browser button again. Saved provider accounts can be selected for the current Ryu
session. Setting one as the shared Gateway account requires the
`gateway.configure` permission, and the action is disabled on managed Ryu Cloud nodes.

Per-provider sign-in steps are on [Chat and Models](/docs/providers/chat-and-models#oauth-accounts-in-the-managed-pi-engine)
and [ChatGPT Plan on Self-Hosted Core](/docs/providers/chatgpt-plan).

## Enable or hide models

In **Gateway → AI providers**, use each model's switch to control its availability, or use the
all-model switch for the currently listed models. An all-model change saves each choice in order,
waiting for its acknowledgement before sending the next. The model controls remain disabled while
that change is pending.

If a request fails, the remaining changes stop and the error reports how many model settings were
saved. Earlier acknowledged choices stay saved. Review the individual switches and retry the
remaining choices; these updates do not provide a rollback of the whole group. Reloading reads the
saved settings from the node.

## Review media providers

The **Other capabilities** section reports the providers serving image, speech, audio, and video
requests. It is a read-only summary: **Edit capability routing** opens the single routing editor,
and **Manage media keys** opens Gateway keys. The Replicate and Fal rows show **Key set** or **No
key** because the presence of that key activates the media provider; they do not have a second
enable switch.

## Edit Gateway keys

Gateway keys remain under **Gateway → API keys**. The BYOK credential value is saved to the OS
credential store and is not shown again; a failed save keeps the entered value available to retry.
Editing Gateway keys requires the node's `gateway.configure` permission. Managed Ryu Cloud nodes
show read-only provider-key state because their credentials are held server-side.
