This page lists the providers Ryu supports and the states it reports for them. A provider listed
here is a supported contract or integration path, not necessarily enabled on every node:

- cloud providers need their own credentials;
- local engines need a compatible machine or an already-running service;
- optional apps need to be installed and enabled.

## Provider families

| Family | Examples | Credential or runtime boundary |
|---|---|---|
| Cloud and managed | OpenAI, Anthropic, Google GenAI, OpenRouter, Modal, Cloudflare Workers AI, AWS Bedrock, Vertex AI, Fal, Replicate | Credentials and egress are owned by the Gateway or managed control plane |
| Local | llama.cpp, Ollama, vLLM, SGLang, MLX, MLX-VLM, mlx-serve, oMLX, Docker Model Runner, Apple Intelligence, Mesh LLM, Lemonade Server, Magnitude, llama-swap, FreeToken | The node owns the process, model cache, health, and hardware fit |
| Custom | OpenAI-compatible endpoints, native GenAI adapters, plugin-declared providers | The adapter declares its contract; Ryu does not infer capability from a display name |
| BYOK | Your OpenAI, Anthropic, OpenRouter, media, or custom endpoint credentials | Keys stay in the provider account or Gateway credential boundary and are not model metadata |
| Subscription | Native ChatGPT, Codex-backed ChatGPT, ChatGPT Web, Claude Pro/Max, GitHub Copilot, Kimi Code, and Kiro provider accounts | Core's sealed provider-account vault, signed-in Browser boundary, and the provider's own subscription limits |

## Gateway provider IDs

Every cloud and managed provider ID, with the operations each supports, is in the
[cloud provider matrix](/docs/providers/cloud#cloud-provider-matrix). The registry also has two
node-side IDs:

| Provider | Stable ID | Main capabilities |
|---|---|---|
| Local | `local` | Chat, embeddings, and reranking against a node-local OpenAI-compatible runtime |
| Core | `core` | Core-hosted agent completions over loopback |

Other IDs are not separate upstream model APIs:

- `classify` is a separate local classifier tier.
- `openai-credits`, `managed-openrouter`, and `gateway` are billing or managed delivery
  boundaries; see [Managed delivery](/docs/providers/cloud#managed-delivery).

Per-modality detail lives on [Speech](/docs/providers/speech) (for example Deepgram and
ElevenLabs) and [Image and video](/docs/providers/image-and-video) (BFL Flux, Stability AI,
Recraft, MiniMax, Runway ML, and Topaz Labs).

## Read availability

The provider picker and API expose more than one state:

- **Supported** means Ryu has a provider, engine, or capability contract for that path.
- **Configured** means the node has the required credential or endpoint settings.
- **Installed** means a local app, engine, or model is present on the node.
- **Available** means the configured or installed dependency is healthy now.
- **Bound** means the provider is the current selection for the capability.

These states are reported separately. For example:

- an OpenRouter model can be supported but absent from the live model discovery response;
- a document parser can be installed but report that its optional OCR dependency is missing;
- a local model can fit poorly even when its engine is installed.
