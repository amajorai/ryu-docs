Image and video are independent from the resident Chat runtime. They can use a local media engine,
an OpenAI-compatible image provider, or a cloud provider with its own queue and model catalog.

## Provider matrix

| Provider path | Image | Video | Request behavior |
|---|---:|---:|---|
| OpenAI | Yes | No generic Gateway video implementation | OpenAI-compatible image generation |
| OpenRouter | Yes | No generic Gateway video implementation | Image generation through the OpenRouter model/provider route |
| Fal AI | Yes | Yes | Image can complete inline; video is submitted to a queue and polled |
| Replicate | Yes | Yes | Predictions can complete inline for image/TTS; video uses create → poll |
| stable-diffusion.cpp | Yes | Yes | Local Core sidecar; image and video models are separate model kinds |
| Custom OpenAI-compatible endpoint | If its image route is implemented | Provider-specific | Use a configured endpoint only for the operations it documents |

Model support is upstream-defined. A provider being listed here does not mean every model in its
catalog supports both image and video, or that the output is available immediately.

## Local media

The `sdcpp` engine wraps stable-diffusion.cpp for local text-to-image and text/image-to-video. It
runs alongside Chat and uses the node's hardware and model cache. The engine keeps the full
stable-diffusion.cpp request surface available instead of reducing it to a fixed Ryu-only schema.

Use the local path when the model and hardware fit the node and you want generation to stay on the
machine. Use a cloud provider when the selected model or GPU runtime is not local, subject to the
Gateway's policy and provider credentials.

## Cloud media jobs

Cloud video is job-based because generation can take minutes:

1. Submit a request to the video generation route.
2. Receive a job identifier and initial status.
3. Poll the job until it succeeds or fails.
4. Read the normalized media output and provider-specific raw result when available.

The Gateway keeps the provider reference and maps provider status into one job vocabulary. A
provider rate limit or queue failure remains visible; it is not turned into a false completed job.

## Public request surfaces

| Operation | Endpoint |
|---|---|
| Image generation | `POST /v1/images/generations` |
| Submit video generation | `POST /v1/videos/generations` |
| Poll video generation | `GET /v1/videos/generations/{id}` |
| Local image generation | Core image route |
| Local video generation | Core video route |

Per-agent image and video slots can override the node's modality mapping. The provider and model
remain subject to the Gateway's normal authentication, routing, budget, and audit path.
