## Highlights

### Public desktop and Island installers

Desktop and Island installers are now built on the public repository's runners and attached to releases, so a release no longer ships without those surfaces. Previously both assets had to build in the private repo, where GitHub Actions cannot run.

Island is packaged with electron-vite and electron-builder, with --publish never so the upload step owns the release.

### Terminal client and rolling channels

The TUI is now the terminal client that ships on every channel, distributed under the ryu-cli asset name so install.sh, install.ps1, and Core's updater keep fetching the same string. The deprecated Rust CLI has been dropped from releases.

Each backend satellite now has canary and nightly jobs that build a three-OS binary with a SHA-256 checksum, alongside its release job. UI-tier satellites remain release-only, so a rolling channel never churns an empty release. The workflow files were pushed across 24 repos.

### Install instructions and TUI binary

Generated release and beta notes now open with an Install block: the desktop app first, then the one-line headless install for developers and self-hosters. Emojis are gone from all section headings.

The TUI is shipped as a compiled standalone executable, produced by bun build --compile rather than the cargo matrix. Because @opentui/core resolves a platform-specific native package, the binary must be built natively on each OS, so the workflow runs three OS jobs instead of cross-compiling. The older ryu-cli binary is still built during the transition so existing install scripts continue to work.
