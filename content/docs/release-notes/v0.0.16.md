## Highlights

### Reactive routing policy engine

Operators can now configure a reactive routing policy that applies threshold and auto-retry behaviour to model selection, instead of having to rely on static routing choices. The policy is exposed through the routing API and in the desktop app's AutoRetrySection and AgentModelsSettings panels.

The engine ships in the core routing policy module with a dedicated test suite, so threshold and auto-retry decisions are covered by automated tests rather than ad hoc wiring. The desktop surfaces expose these controls alongside the existing gateway settings.

Affected packages: `ryu-core`, `Desktop app`

### Pi capability extensions

Users can now enable three additional Pi capability extensions — `ryu-plan`, `ryu-shell`, and `ryu-subagent` — alongside the existing `ryu-mcp`, closing the previously documented gaps around plan mode, subagent execution, and todo handling.

The extensions ship as core assets under the Pi extensions directory and are loaded through the plugin seed path, so they are available through the same Pi configuration surface as `ryu-mcp`. The seed rows and Pi configuration wiring were updated to make the three extensions discoverable.

Affected packages: `ryu-core`

### Versioned documentation URLs

Readers can now open documentation at versioned URLs such as `/docs/<version>/...` instead of an unversioned path, so bookmarks stay pinned to a specific release. The version is controlled by a single `DOCS_VERSION` constant in the fumadocs source.

Release automation now bumps that constant in the three fumadocs sites, the bare `/docs` redirect target, and the README version statement whenever the release version changes. That keeps the mirrored `amajorai/ryu-docs` satellite from continuing to serve the previous release's URL space.

Affected packages: `Documentation site (docs.ryuhq.com)`

### Gateway prompt caching

Operators using Anthropic or OpenRouter through the gateway can now take advantage of prompt caching for chat traffic that reuses prompt context. A shared prompt cache module implements the behaviour and is wired into both provider clients.

Because the support is implemented in the provider clients themselves, gateway chat traffic using those providers can pick it up without application-level changes. The Anthropic and OpenRouter clients each wire the cache into their request handling.

Affected packages: [`ryu-gw-providers`](https://crates.io/crates/ryu-gw-providers/0.0.16)
