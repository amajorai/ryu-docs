## Highlights

### Node discovery across profiles

Users can now discover and connect to nodes running under a different profile than their client, so a stable desktop app can find a canary node on the same machine without typing a URL by hand. Node discovery sweeps every profile port — release, dev, canary, nightly, and beta — instead of only the port the client happens to be on.

Each discovered node carries the profile it was found on, derived from the port it answers on, and the desktop Node Selector now names nodes with their profile instead of the host alone. That prevents a machine running several profiles from collapsing every node into one name, and results are deduplicated when the same Core answers on both 127.0.0.1 and the LAN address.

The webapp remains limited to localhost because browsers have no raw sockets, and its per-port failures are silent by design. On a machine running a single profile, four of the five probes always fail there.

Affected packages: `ryu-cli`, `Desktop app`, `Web app (app.ryuhq.com)`

### Profile-scoped deep clean

Users can now deep-clean any profile's node data from the desktop app's Danger Zone, not just the profile currently running. The clean can be scoped to configuration only, to data while keeping downloaded binaries and models, or to everything.

Deep clean now restarts the local Core and clears the client onboarding flags afterward, mirroring the Reset node flow, so the app is not left talking to a dead Core. The master key is never removed at any depth, because it is node identity and there is no rekey path.

Shared roots such as ~/.shadow and ~/.ghost are not profile-suffixed, so the confirm dialog is built from the actual selection: it names the profile and lists exactly what that scope will remove. The chosen profile is passed explicitly to the child process rather than picked up from the environment, so cleaning canary from a release app does not resolve release by accident.

Affected packages: `ryu-core`, `Desktop app`

### Marketplace engine floors

Marketplace listings now declare a minimum Ryu version, and the published index carries it. Every app and plugin manifest now declares `engines.ryu: >=0.1.0`, so compatibility with a given install is explicit instead of defaulting to a first-release floor or nothing.

The index previously dropped the entire engines block, which made even a correct floor invisible to anyone browsing the marketplace. The generator now keeps the `ryu` key when publishing, and Core enforces that floor at manifest load, so installing a listing whose minimum you do not meet can no longer produce a plugin that silently never loads.

Listings that declared no floor remain distinguishable from those declaring an empty one: an absent key stays absent rather than turning into `{}`. The floor is verified rather than asserted — all 93 Core manifest tests pass with it, which would be impossible if the requirement were unsatisfiable.
