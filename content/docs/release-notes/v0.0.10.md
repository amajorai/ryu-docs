## Breaking changes

### Manifest rename to manifest.json

The canonical manifest file name for plugins, apps, and SDK templates changed from plugin.json to manifest.json; 103 manifests across the store plugins, store apps, and Core fixtures were renamed. Loading remains backward-compatible: the loader and the Core and SDK crates accept manifest.json, plugin.json, and ryu.json in that order, so existing installed plugins under ~/.ryu/plugins and already-published third-party releases continue to work.

Authors publishing new plugins or apps should now ship manifest.json, because it is the first name probed by the loader, the marketplace generator, and the GitHub-topic discovery source, and it is what the SDK writes. Tooling and CI that generate or reference plugin.json paths should be updated to the new canonical name even though older names still load.

## Highlights

### Docs site satellite repository

Operators can now publish the documentation site as its own standalone satellite repository, amajorai/ryu-docs, instead of shipping it as a subtree of the public hub mirror. The flattened tree carries its own package.json, tsconfig, biome.json, and committed OpenAPI specs, so it installs and builds with no workspace dependencies.

The mirror tooling gains a docs mode, included in the all target, that pushes fumadocs flattened to the satellite root and creates the repository on first run. Pull requests raised against the satellite are remapped back under fumadocs/ by port-pr.sh, matching the existing predict satellite flow, and fumadocs was dropped from mirror-public.sh and its trigger.

The standalone build was verified end to end with bun install, generate:docs, fumadocs-mdx, and next build.
