Released 2026-07-24 · [GitHub release](https://github.com/amajorai/ryu/releases/tag/v0.0.9)

## Highlights

### Self-contained declarative plugins

Plugin authors can now declare the MCP servers and bundled skills a plugin owns directly in its own plugin.json, and installing or enabling the plugin registers those resources in the live registry. The Core no longer hardcodes the affected plugins, so a plugin's surface is defined by its manifest rather than compiled-in Rust.

Installing a plugin with an mcp_servers declaration registers those servers on enable and deregisters them on uninstall or disable, and bundled skills are installed and removed with the plugin. Advisor and shadow are now declarative HTTP tools, ghost and agentbrowser register their MCP servers from their fixtures, and headroom declares its own sidecar.

The marketplace generator derives catalog metadata from each plugin's own manifest, removing the hand-edited mirror pattern and letting a plugin be published and installed as a self-contained unit.

Affected packages:

- `ryu-core`
- [`ryu-kernel-contracts`](https://crates.io/crates/ryu-kernel-contracts/0.0.9)
- [`@ryuhq/sdk`](https://www.npmjs.com/package/@ryuhq/sdk/v/0.0.9)
- `plugin: advisor`
- `plugin: agentbrowser`
- `plugin: ghost`
- `plugin: headroom`
- `plugin: shadow`

### Hetzner provisioning end to end

Operators can now provision managed cloud nodes on Hetzner for real, end to end, instead of receiving a fake simulated row that could not be connected to. In production the provisioning task fails closed unless live configuration is present, so a non-live deployment cannot silently fabricate a node.

GET /nodes now mints a per-request JWT for each node, and the desktop app refreshes that token on a 10-minute timer and on window focus, so a provisioned node stays connectable beyond the old startup-only hydration. Provisioned servers are linked to their gateway credential row, and the destroy path is equally unarmed outside a live environment.

Affected packages: `Desktop app`, `@ryu/api`, `@ryu/db`, `@ryu/env`

### iOS and Android simulator control

Users can drive iOS Simulators and Android Emulators from the desktop client through a workspace app. The com.ryu.simulator app exposes a grant-gated simulator.control capability and provides a dependency-free Bun sidecar that wraps simctl and adb behind a loopback bearer-gated HTTP server.

Android gets full tap, swipe, and text input via adb input, while iOS supports view, install, launch, deeplink, and screenshot operations. Availability is determined at runtime by probing for Xcode or the Android SDK, so the app only appears where it can actually work.

Affected packages:

- [`@ryu/simulator`](https://github.com/amajorai/ryu-simulator/releases/tag/v0.0.9)

### Reference inline-widget plugin

Plugin developers now have a complete, working template for building third-party inline widgets: a zero-dependency stdio MCP server plus a sandboxed widget page that talks to the app-host bridge. The sample-widget plugin is opt-in and never seeds enabled or spawns a node until installed.

A fumadocs guide walks through the manifest shape, the widget bridge, and display modes, and is linked from the navigation. The same fixture is registered byte-identically in Core, with a unit test asserting load, grant, server, and widget bindings.

Affected packages:

- `ryu-core`
- `Documentation site (docs.ryuhq.com)`
- `plugin: sample-widget`

- Moved every apps-store app manifest from ui/ to the folder root so each app is a self-contained satellite, and removed the inert TypeScript bundles residue from the marketplace package. (`e25e94a`)
