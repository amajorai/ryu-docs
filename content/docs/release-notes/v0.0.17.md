## Highlights

### Scoped plugin ids and app events

Plugin ids are now scoped, so first-party plugins are addressed as @ryu/meetings rather than com.ryu.meetings. Plugin authors can also declare and emit app events, which Core fans out to every subscribed hook and workflow.

Legacy ids are rewritten to canonical form at manifest parse, and store schema v4 rekeys lifecycle records and plugin KV onto the scoped ids, so existing installs keep their grants. Event ids are namespaced to the owning plugin and only that plugin may emit them, making authorization a matter of ownership rather than a grant.

Desktop and Island now share one composer ACP section implementation in blocks. The marketplace reserved-namespace check was also fixed so community listings cannot claim @ryu/* first-party ids.

### Dispatch-only satellite release workflows

Maintainers can now dispatch release workflows for the ghost, shadow, and raycast satellites and receive packaged artifacts. Previously those satellites shipped source only, and their binaries were never published as release assets.

The generated workflows are dispatch-only, so a satellite can never fork the single release train. ghost and shadow build on all three platforms and archive the binary at the archive root with a sibling SHA-256 file; raycast gets a source tarball because it builds no binary.

The in-app download path still resolves against the hub release, so these archives do not yet flow to the app.
