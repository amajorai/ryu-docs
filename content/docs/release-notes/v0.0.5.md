## Highlights

### Shared marketplace and app lifecycle

The Models, Skills, Plugins and Apps catalogs and the store/marketplace money layer render from shared @ryu/marketplace implementations on desktop and ryuhq.com, so one edit updates both surfaces. Web visitors see the same model listings, fit estimates, skill listings, badges and detail views as desktop users. Desktop injects Core-node apps hook, install layer, DesktopMarketplaceHost with Better-Auth bearer tokens and Tauri openExternal; web injects a federated adapter with install set to null and WebMarketplaceHost with session cookie and window.location. On web, install, enable, source, active and fine-tune/authoring touchpoints collapse into Open-in-Ryu.

Users can enable or disable Core features as apps and install, enable, disable, update, or uninstall apps and plugins across desktop, mobile, TUI, CLI, and core API. Extracted apps are default-on, so existing installs keep behavior; when an app is off, gated routes return 503 app_disabled through AppGate, while Agents, the public workflow webhook, and hardware device channel remain ungated. Uninstall is refused while an enabled plugin depends on the target, and built-in/default-on plugins are protected. The ryu binary runs one-shot subcommands such as ryu list, add, enable, and chat, while bare ryu or ryu tui opens the interactive TUI; CLI includes catalog, install, enable, disable, uninstall, chat, node, help, and version, and TUI reaches /teams, /inbox, and /downloads parity.

### Sidecars, sandboxed plugins, and companion apps

Desktop fetches all ten converted app sidecar binaries into ~/.ryu/bin on startup, so teams, research, clips, finetune, quests, healing, meetings, recipes, dashboards and monitors can spawn in production; Gateway is the one required sidecar that fails loudly, while installs are detached, non-fatal, and skip resolved entries. Plugins and sandboxed companion apps run under a unified permission and contract system; one PermissionSet governs filesystem, child process, network, and tool access across wasmtime, Deno, and Docker.

Desktop Learning, Calendar, Mail, Activity, Quests, and Webhooks now run as sandboxed companions through the contribution registry, preserving manifests, seeds, grants, layouts, and states. Workflows and monitors also ship as sandboxed companions with parity for node editing, CRUD, runs, triggers, snapshots, alerts, and polling. Mobile and web can mount plugin UIs: mobile adds a WebView extension host, Apps drawer, and /plugin/[id] routes; web adds /apps and /apps/[id] through @ryu/app-host with a session-gated proxy. The default Pi agent can call Ryu tools through a Pi extension, and tool results synthesize into Apps-SDK widgets governed by contributes.widgets[] and the widget:render grant, with CSP connect-src 'none' and SSRF-guarded /api/widgets/asset proxy.

### Agent tools, composable primitives, and typed realtime

Plugins can call typed composable primitives on the agent context: ctx.rag, ctx.memory, ctx.realtime, ctx.durable, ctx.engines, ctx.tts, ctx.stt, and ctx.image. defineAgent accepts composable slots that lower to requires.capabilities plus persona and model RunnableMeta.config; .toManifest() emits a valid plugin manifest.

Applications on ryu-realtime can now broadcast and target named events instead of raw frames: broadcast_event fans a named event to every subscriber in a room, while send_event delivers one to a single connection without other connections or raw broadcast subscribers seeing it. Long-term memory, spaces, retrieval, predictive typing, monitors, hardware, tool execution, and durable execution now run through standalone ryu-memory, ryu-spaces, ryu-rag, ryu-predict, ryu-monitors, ryu-hardware, ryu-tool-exec, and ryu-durable crates, while ryu-tool-registry and ryu-model-catalog provide descriptor types, argument-schema parsing, search/describe bodies, and the Hugging Face model catalog with device-fit verdict.

### Gateway firewall, routing, and modular crates

Routing config can name any provider id, and pre-processing stages are data-ordered rather than hardcoded, so governance, inspector, inline-input, and policy blocks can be reordered or disabled. Operators can select per-stage backends for budget, cache, semantic_cache, audit, evals, circuit_breaker, and rate_limit; capability bindings resolve providers via GET and PUT /api/capabilities/bindings.

Gateway budget and evals now ship as self-contained crates with enforcement and runner capabilities, swappable backends, and config types. Mesh and webhook ingress ship as standalone library crates, preserving mesh's in-process default and gating plus webhook ingress's fail-closed HMAC re-verification, dedup, replay window, and registry helpers. Per-agent usage metering ships from ryu-usage with Claude Code and Codex OAuth readers and normalized snapshot types, while encryption-at-rest ships as a standalone Apache-2.0 crate with AEAD envelope and a master-key custody ladder. Mail can run as its own process Core spawns and proxies to, fault-isolating the endpoint; cargo features can exclude Mail, shrink a release build by about 1.49 percent, and compile out research, clips, and recipes under --no-default-features while healing is cfg-gated.
