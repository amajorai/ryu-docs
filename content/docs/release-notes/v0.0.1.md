## Highlights

### Chat, agents, and workflows

Desktop conversations are searchable and pull relevant history into model context automatically. Desktop chat can generate and display client-only images and speak assistant replies aloud. A conversation can hold several agents; users add or remove participants, type @ to pick an agent, and see a labeled prefix above each reply. On mobile, chat history persists on Core and a Conversations drawer resumes prior chats.

The Desktop app provides an agent manager to create, edit, and delete agents with a name, system prompt, and bound engine; chat routing resolves that bound engine before dispatch. After an ACP run, desktop shows a per-file summary and unified diff, and a reviewed run can be applied to commit and merge or Open PR. The Delegation page lets users add delegate rows, set caps, submit a fan-out, and watch live progress. Saved workflows fire on Manual, Schedule, Composio or Webhook triggers, and Workflow Agent nodes invoke the selected agent.

### Store, apps, skills, local models, memory, and SDK

The desktop app now has a single Store page with sections for Apps, Models, Skills, Agents, Engines and Services. Users can browse and install from the marketplace catalog across the browser extension, Island, mobile app, and CLI. Users can add custom catalog sources, including Hugging Face, ModelScope, SkillsSh and a Claude marketplace.json source, and browse or install MCP servers from the official registry, Smithery, and a curated Ryu-hosted index. Skills install from six source forms and hot-reload without restarting; MCP installs are written disabled.

The desktop Apps page opens chat with an app’s primary agent selected. Skills authored in the skill format are executable Runnables, and Ryu ships a flagship recommended agent named ryu; a new install can serve chat from a local model via llama.cpp and a Gemma GGUF started by llama-server. Spaces support BFS graph traversal, and Core supports two-tier conversation memory with recent turns and opt-in long-term recall. Publishing to Ryu Marketplace uses authenticated POST, moderation, gateway grant validation, ed25519 signing, and install-time signature verification; @ryu/client is a TypeScript SDK, and @ryu/sdk names extension units plugins and exports defineAgent, defineWorkflow, defineTool, and defineSkill.

### Gateway routing, tool search, safety, and safe memory

Model routing uses prefix rules with an ordered fallback chain, and replies include x-request-id and x-provider headers. When a request carries a tool signal, the gateway injects one tool_search meta-tool instead of forwarding a full list; requests without it stream directly. Core’s protected tool search and describe routes are backed by a catalog across MCP servers, built-ins, Composio, and plugin tools, with Composio searchable but not listed.

From the Gateway page, users set a default provider, add model-to-provider mappings, order the fallback chain, and store OpenAI, Anthropic, and OpenRouter keys in the OS credential store. Gateway routes image generation, text-to-speech, and speech-to-text alongside chat through the same firewall, budget, and audit pipeline. Guardrails policy supports block, warn-and-continue, or sanitize, with PII/secret redaction enabled by default; per-user and per-agent token budgets enforce notify, downgrade, restrict, or stop. Shadow queues meeting summarization, consolidates episodic memory into semantic facts, and uses a SafetyGate to block destructive and financial tool calls before they run, capture undo snapshots, and reuse successful procedure templates.

### Organization, identity, security, and cross-surface experience

Signed-in users can create and switch organizations from the web header, invite members by email with a role, update roles, and see pending invitations. Teams and bound projects are created from an organization hierarchy page, and Better Auth’s organization plugin is the source of truth for org, team, and member records with invitations sent through a new email template. A policy editor lets operators inspect and change policy layers, resolve effective cascaded policy for a selected scope, and see admin-locked fields. Layers can be created or updated at org, team, project, or user scope, with org-level edits gated to admins.

Across desktop, website, mobile, and browser extension, users get full Ryu chat with streaming, agent selection, conversation history, markdown, tool-call cards, and shared color themes. Sign-in uses browser-based OAuth PKCE on desktop and OAuth 2.0 authorization code flow with PKCE across surfaces, with consent review and authorized-app management; users can change email/password, set up two-factor authentication, and manage active sessions. Email sending and subscription contacts now run on Resend instead of Plunk, with rewritten branded templates, rate limiting, and subscription handling. Notion-backed website pages gain a table of contents with active heading detection, Shiki syntax highlighting, more block types, and @tanstack/react-query caching across blog, changelog, help, dashboard, and success views.
