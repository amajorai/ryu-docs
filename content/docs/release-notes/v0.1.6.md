## Highlights

### Island chat renders the full transcript

Island chat now renders the full transcript the desktop app produces, instead of a plain-text role-and-content list. Users of the island surface can see tool rows, MCP widgets, generated images, reasoning and citations exactly where they appear in the desktop conversation.

The island implements the AI SDK ChatTransport over the existing core:streamPart IPC, so Core's raw stream parts arrive as real UIMessage[] values with full parts. The desktop MessageList renders them at a new compact density tuned for the island's narrow panel.

Affected packages: `Island`, `@ryu/blocks`

### MCP widgets in the island transcript

The island transcript can now mount MCP widgets, rendered by the same widget renderer the desktop app uses. Widget parts that the hand-rolled island transcript used to drop now appear inline.

The renderer moved into @ryu/blocks so both surfaces share one implementation. The island's host routes the governed widget round-trips — call, follow-up and state — over plugins.coreHttp, so the sandboxed frame never receives a Core token. Island widgets start at a 220px default box instead of the desktop's 360px, so a compact transcript is not swallowed before the widget reports its own height.

Affected packages: `Desktop app`, `Island`, `@ryu/blocks`

### Animated OTP slots for code entry

Every short code field now uses the animated OTP slot input: web 2FA and email sign-in codes, 2FA setup, device activation, and the desktop and extension 2FA dialogs. The field animates each slot on entry, with a gliding caret, an error shake and a success check draw.

The component keeps an alphanumeric mode for device-activation codes and groups slots so an 8-character code reads as XXXX-XXXX. Backup codes remain on a plain field because they are hyphenated and variable-width.

Affected packages: `Desktop app`, `Browser extension`, `Documentation site (docs.ryuhq.com)`, `storyboard`, `Website (ryuhq.com)`, `@ryu/blocks`, `@ryu/ui`

### MCP servers register when binaries land

Enabling a plugin that ships an MCP server no longer leaves that server dark until the next boot. The registration is attempted again the moment the plugin's managed binary resolves, so a fresh enable brings the servers up immediately.

The notifier fires on all resolution paths and re-runs the existing registration logic, which still applies the tier and approved mcp:server gate before registering anything. It skips the work when a declared server name is already present, so the re-probe stays cheap.

Affected packages: `ryu-core`
