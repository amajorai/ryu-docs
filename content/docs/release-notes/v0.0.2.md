## Highlights

### Gateway routing, policy, and billing

Agents can route through ryu-gateway instead of being pinned to a model, with model-prefix routing, fallbacks, caching, circuit breaking, skills injection, rate limits, token budgets, audit logging, evals, metrics, and a Composio tool-call loop. The gateway exposes streaming and non-streaming /v1/chat/completions, /v1/models, and /health, and translates Anthropic requests and SSE streams. A reusable channel layer turns Telegram, Discord, and WhatsApp messages into gateway requests and delivers replies back to the originating chat. Teams can define evaluators once and reuse them as inline gateway guardrails or offline evals, with a policy firewall in the pipeline.

Accounts can top up credits automatically, and operators can run a hosted gateway where bearer tokens resolve to an organization, budget, and policy. Billing resolves the caller's active organization, and subscriptions grant the plan's monthly included credit pool that scales by seat count and stops on cancel or downgrade. Org admins can export, diff, apply, inspect, and roll back control-plane policy, with policy distributed down org, team, project, and user levels and local gateways enforcing model allowlisting and inbound guardrails. Gateway operators set per-user and per-agent token budgets with notify, downgrade, restrict, or stop actions.

### Desktop chat, voice, recall, and worktree runs

Desktop opens to a home dashboard and Library where agents appear as lanyard badge cards, and users can add dashboard widgets by chatting with the dashboard builder. Desktop chat can generate images, render PNGs inline, speak replies with WAVs, and hold spoken conversations end to end, with Kokoro 82M as default text-to-speech. Users can search past conversations, and every turn auto-recalls semantically related chat messages and memory chunks with an auto-recall toggle. The island morphs between idle, context, suggestion, and expanded states, surfacing proactive suggestion chips with Accept, Snooze, and Dismiss.

Conversations can hold multiple agents with participant chips, @mention autocomplete, and replies prefixed with the handling agent's bold label; runs continue when navigating away and desktop notifies on completion. Desktop users can run worktree-isolated agents that produce a reviewable diff, then apply it as commit-and-merge or open a pull request through gh. Desktop also adds Tools/MCP visibility, per-agent allowlists, test calls, tool approvals, delegation controls, and a Gateway status view. Core provides session and optional long-term memory, named Spaces with retrieval, named agents, persisted chat history, resumable DAG workflows, cron scheduling, and sub-agent delegation caps.

### Workflow automation, plugins, and agent authoring

Saved workflows can fire on a schedule, on a Composio event, or manually, with TriggerPanel configuring interval presets or custom cron, Composio toolkit and trigger pickers, Run-now, and a placeholder webhook URL. Nodes read and write named state, templates resolve at run time, and managed-tier users receive Composio webhooks through RyuRelay without opening inbound ports. Agents and callers can search a single catalog covering MCP servers, built-ins, Composio, and plugin tools, and run JavaScript that fans out across many tools. Operators can install, enable, and disable turn-hook plugins that run code on each chat turn.

The plugin host runs plugin-authored JavaScript in a deny-by-default sandbox with capability-gated host APIs, returns none, note, or continue directives, and fails open; outside developers can build from @ryuhq/sdk using typed factories. Developers can define agents, workflows, tools, and skills in TypeScript with defineAgent, defineWorkflow, defineTool, and defineSkill; conversations record inspectable tool-span timelines for run-trace queries. Operators can opt into Docker or WSL2 sandboxed commands, run untrusted code in a default-deny WebAssembly WASI sandbox, cap tool executions in a rolling window, and see every execution in the audit log.

### Marketplace, mobile, AIoT, and refreshed clients

Users can browse and install skills, MCP servers, plugins, and models from the browser extension, island, native app, and CLI through a federated Ryu Marketplace catalog. The unified Store presents Apps, Models, Skills, Agents, Engines, and Services, replacing separate Models and Skills entries, with lifecycle UI and admin-gated publisher approval. Catalog sources can be added and selected per kind for models, skills, MCP servers, and plugins. The mobile app now uses one consistent header across drawer screens and a native data layer for agents, teams, spaces, meetings, workflows, and schedules.

Ryu ships an AIoT hardware platform with ESP32-S3 thin clients for desk, watch, and necklace form factors; they speak RHP to Core's hardware API and WebSocket adapter, and the mobile app can act as a BLE relay to list, pair, and provision nearby devices. Users can sign in through OAuth 2.0 authorization code flow with PKCE, completing browser-based sign-in that returns to a localhost or ryu://auth/callback deep link, with profile and settings listing authorized applications and a sessions tab for devices and sessions. Desktop gets a rebuilt chat and shell with color themes that apply without restart, the website adds installable app iconography and reworked auth pages, and the browser extension ships chat with streaming, agent selector, and OAuth login.
