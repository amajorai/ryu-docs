## Highlights

### Plugin-declared language servers

Plugins can now declare language servers in their manifest and the Pi agent will spawn them, bringing code intelligence to agent sessions. A Claude Code .lsp.json entry is wire-compatible, so it can be pasted unchanged into a Ryu plugin manifest.

Core resolves enabled manifests with Claude's arbitration rules: invalid servers are skipped without claiming their file extensions, non-stdio transports are gated separately, and first-registration-wins is made deterministic by sorting on plugin id. The ryu-lsp extension appends diagnostics to edit and write tool results and adds definition, references, hover and diagnostics tools, on a bounded wait so a slow server never stalls a turn.

The SDK manifest schema mirrors the lsp_servers field, so declarations survive ryu pack instead of being stripped at publish time.

Affected packages: `ryu-core`, `Documentation site (docs.ryuhq.com)`, [`ryu-kernel-contracts`](https://crates.io/crates/ryu-kernel-contracts/0.0.14), [`@ryuhq/sdk`](https://www.npmjs.com/package/@ryuhq/sdk/v/0.0.14)

### Pluggable document parsing

Ryu can now parse documents through a hot-swappable document.parse capability instead of a single built-in converter. MarkItDown remains the default engine, with Docling, MinerU and Unstructured available as installable satellite parsers.

Each parser ships as a self-contained sidecar with its own jobs, formats and limits, so swapping the active engine does not change how tools call it. Parsed output can be mirrored into the retrieval database for later search.

The desktop app now has a Document Parsing settings panel for picking the active engine. The choice is enforced on the Core side, so every tool request sees the same parser.

Affected packages:

- [`@ryu/docling`](https://github.com/amajorai/ryu-docling/releases/tag/v0.0.14)
- [`@ryu/markitdown`](https://github.com/amajorai/ryu-markitdown/releases/tag/v0.0.14)
- [`@ryu/mineru`](https://github.com/amajorai/ryu-mineru/releases/tag/v0.0.14)
- [`@ryu/unstructured`](https://github.com/amajorai/ryu-unstructured/releases/tag/v0.0.14)
- `ryu-core`
- `Desktop app`

### Marketplace catalog installs

The marketplace storefront now supports per-tab catalog sources, a detail reviews panel and a web install dialog that builds a one-line install command. Visitors can install an app from the website instead of manually assembling the command.

The CLI, desktop app and mobile deep-link handling all recognise the new install links, so an install started on the web can be carried through to the running client. Catalog sources can be switched per tab rather than being a single global selection.

Affected packages: `@ryu/marketplace`, `ryu-core`, `ryu-cli`, `Desktop app`, `Website (ryuhq.com)`, `Mobile app`, [`@ryuhq/protocol`](https://www.npmjs.com/package/@ryuhq/protocol/v/0.0.14)

### Encryption settings

Desktop users can now turn on encryption from a dedicated Encryption Settings panel. The setting is backed by Core server endpoints rather than a manual config file edit, and the desktop client keeps the encryption configuration in sync with the Core service.

Affected packages: `ryu-core`, `Desktop app`
