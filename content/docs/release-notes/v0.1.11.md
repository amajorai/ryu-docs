## Highlights

### Cross-machine settings sync

Sign in on a second machine and your desktop settings are already there: appearance, layout, tab behaviour, chat display and keyboard shortcuts arrive without reconfiguring anything. Sync defaults to off, so nothing leaves the device until you enable it in the settings dialog.

Only an explicit allowlist of keys travels, and the sync covers well over a hundred storage keys while session tokens, vault credentials and provider API keys are never candidates. Each key syncs independently with its own timestamp, so a window-size change on one machine no longer reverts a theme change made on another.

Keyboard shortcuts are stored under a per-OS key, since Mac and Windows chords are not interchangeable. A 60-second debounce groups a run of adjustments into one upload, a window-close flush covers anything still pending, and a conflict policy lets you choose ask, always-download or always-upload.

Affected packages: `Desktop app`, `@ryu/api`, `@ryu/db`

### Merged per-agent chat view

Clicking an agent in the sidebar now opens a single merged view: every earlier thread with that agent rendered above the live one as one continuous scroll, each block headed by its thread title. The live thread is still the ordinary useChat conversation, so streaming, editing and branching behave exactly as before.

Older threads are read-only history loaded above it, with nothing merged or migrated server-side. A picker in the composer chooses which thread a send joins, defaulting to the most recent, with New thread to start a fresh one.

Prepended messages carry a merged conversation id that edit, branch, regenerate, select-version and feedback refuse, so a click on foreign history cannot write into the live conversation. The view is capped at five older threads of forty messages each so a busy agent cannot stall the tab, and context usage and transcript copy keep reading the live thread only.

Affected packages: `Desktop app`

### Agent-to-agent messaging

Agents on a node can now message each other through the @ryu/agent-comms plugin (Switchboard). It adds four tools — agents__directory, agents__send, agents__ask and agents__thread — so asking the research agent what it found is a real message to a real agent.

The tools ship as ordinary registry tools rather than a private runtime feature, so the flagship agent via ryu_call_tool, an ACP agent via the in-process bridge and the gateway tool loop all get them. Send queues a message delivered at the start of the recipient's next turn; ask runs the recipient synchronously with the pair's own history, and nothing wakes an idle agent.

Senders are resolved from the dispatch path, not from tool arguments, so an agent cannot post as another. Hop limits, busy markers on both ends of an ask, and a refusal to address yourself bound what agents can spend of each other's budget.

Affected packages:

- `ryu-core`
- `Documentation site (docs.ryuhq.com)`
- [`ryu-tool-exec`](https://crates.io/crates/ryu-tool-exec/0.1.11)
- `plugin: agent-comms`

### Row-level settings search

The search box in both settings dialogs now finds individual settings rows instead of tabs. Typing 'dark' points straight at the row that toggles dark theme, wherever it sits, rather than listing the tabs that merely resemble the query.

A result from the other dialog says so on its row and switches dialogs when clicked, so one query reaches client-scoped and node-scoped settings alike. Clicking a result navigates to the section, scrolls to the row and flashes it.

The index is tested against the settings sources and fails on any label that no longer exists, since nothing in the type system ties an entry to the JSX that renders it. Coverage is row-level for the App dialog and most Gateway panes, group-level for bespoke panes, and absent for manifest-contributed plugin tabs.

Affected packages: `Desktop app`, `@ryu/blocks`
