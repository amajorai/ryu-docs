## Highlights

### Desktop, mobile, terminal, composer, patch diff, and agent UX

In the desktop app, project folders are the primary workspace structure, with project settings and workspace store handling folder-first metadata for multi-folder projects, and end-to-end proof harnesses covering them. The pull-requests app understands stacks, the sidecar resolves and validates stacks over the GitHub client and types, the UI derives stack-aware task state, and the desktop app surfaces pull request CI status with a dedicated pull request summary panel and pinned summary sidebar.

The mobile app follows the same drawer-based navigation as the desktop app, with drawer routes for agents, channels, credits, delegation, gateway, hardware, plugins, store, timeline and space documents, shared list-screen and screen-header components, a shared mobile surface definition, and a mobile parity end-to-end proof harness. Desktop settings include a top-level reset for keyboard shortcuts in the Keyboard shortcuts tab, covered by an end-to-end proof spec and documented in the desktop user guide.

### Auth, billing, waitlist, and usage

The platform sends authentication emails for application invites, account deletion confirmations, email verification one-time codes, password reset codes, stale account notices, and admin stale-account notices. Templates live in @ryu/email behind an auth template registry, stale account detection is in @ryu/auth, and the @ryu/api waitlist router gained access-code coverage.

Operators can issue and redeem waitlist access codes, with an admin waitlist page on the website and redemption through the waitlist view. The waitlist has an upgrade tab rendered by a new waitlist-queue component in @ryu/ui on desktop and website. Waitlist visitors can complete daily quests and see a leaderboard with battle-pass style progress, backed by quest and waitlist API routes, auth quest rules, a database quest model, and shared UI.

### Marketplace, plugins, skills, apps, catalogs, operations, and installer progress

Marketplace manifests can include presentation metadata defined in ryu-kernel-contracts and @ryuhq/sdk. The ryu-core catalog pipeline reads it, @ryu/api federation and marketplace routers pass it through to @ryu/marketplace, and the website storefront and desktop app render richer listings. App and plugin manifests under apps-store and the plugin marketplace were updated, including twenty first-party apps and cloudflare-browser-run.

Built-in skill packs now include unlazy and diagram design, registered in the core skills catalog and system skills and surfaced through the @ryu/api catalog router, desktop skills surface, and end-to-end proof harnesses. Ego Browser is available as a provider plugin shipped as a store entry and registered in the core builtin plugin list and plugin manifest.

### Managed channel install links, simplified downloads, and GitHub Action

Managed channel install links let an operator provision a channel without walking through the full manual configuration flow. Desktop channel components in @ryu/blocks and the shared agent UI module handle the links, with a desktop end-to-end harness and spec, updated gateway channels page and cloud deployment guide, and a proof image.

The Ryu website download flow is simplified to a single clear action. The @ryu/blocks download components were refactored, including dropdown content, menu and asset helpers, and the website download page, engine pages, sitemap and llms.txt were updated.

Affected packages:

- `@ryu/blocks`
