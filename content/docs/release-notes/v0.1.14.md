## Highlights

### OpenAPI-derived agent tools

Store app agents can now call routes that previously had no tool. Ryu Core derives an LLM tool from each operation in a sidecar's OpenAPI document, then exposes only the operations the app manifest declares.

Backends across the store were updated to serve complete OpenAPI documents with named request schemas, so derived tools carry real arguments instead of opaque JSON.

Affected packages:

- [`@ryu/clips`](https://github.com/amajorai/ryu-clips/releases/tag/v0.1.14)
- [`@ryu/crm`](https://github.com/amajorai/ryu-crm/releases/tag/v0.1.14)

### Blueprint, drafts, and rlm tools

Blueprint, drafts, and rlm now contribute callable tools to agents. Each sidecar serves a hand-written OpenAPI document at its root, and Core derives tools from the routes the manifest declares.

The documents name concrete request types instead of untyped JSON values, so derived tools have visible arguments. A test in each crate checks every manifest route against the document, so a missing annotation can no longer silently drop a tool.

Affected packages:

- [`@ryu/blueprint`](https://github.com/amajorai/ryu-blueprint/releases/tag/v0.1.14)
- [`@ryu/drafts`](https://github.com/amajorai/ryu-drafts/releases/tag/v0.1.14)
- [`@ryu/rlm`](https://github.com/amajorai/ryu-rlm/releases/tag/v0.1.14)

### Browser and simulator agent tools

Browser and simulator sidecars now serve /openapi.json, letting Core derive tools from their routes. Simulator gains its full agent surface — 14 operations covering install, launch, open URLs, and input — because it previously shipped no runnables.

Simulator's incorrect HTTP mount was dropped, so proxied calls reach the routes the document describes. Browser documents only / and /health, keeping its existing hand-written chromium runnables as the agent surface.

Affected packages:

- [`@ryu/browser`](https://github.com/amajorai/ryu-browser/releases/tag/v0.1.14)
- [`@ryu/simulator`](https://github.com/amajorai/ryu-simulator/releases/tag/v0.1.14)

### Usage statements and admin audit

Desktop and web users can now see a usage statement alongside the credit balance. The statement breaks down what each charge was for, including model, provider, token counts, and duration, instead of showing only a running balance.

Organizations get a member-readable usage page, and administrators get a cross-org audit page. Both share one table component, with amounts shown to four decimals, null durations as an em dash, and the sign carried by a plus or minus as well as color.

Affected packages: `Desktop app`, `Website (ryuhq.com)`, `@ryu/blocks`
