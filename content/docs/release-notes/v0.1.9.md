## Highlights

### Step-up verification for sensitive actions

Operators can now require users to confirm their identity again before sensitive operations such as opening the key vault, managing gateway keys, editing org members, administering affiliates and announcements, granting support access, or activating a device. The challenge appears on the web, in the desktop and mobile apps, and in the CLI, so the same gate applies regardless of surface.

A new shared @ryu/step-up package backs the feature with a step-up router, a better-auth plugin, a persisted challenge model, and an OTP email. Each sensitive operation can demand its own challenge, and the persisted model means the outcome is durable rather than held only in memory.

Affected packages: `ryu-cli`, `Desktop app`, `Mobile app`, `Website (ryuhq.com)`, `@ryu/api`, `@ryu/auth`, `@ryu/blocks`, `@ryu/db`, and 2 more — see the changelog below.

### Two-surface hero workflow loop

Visitors to ryuhq.com now see the landing hero act out a real Ryu workflow instead of a static chat mockup. The Island surfaces a follow-up after a call ends, a pointer accepts it, the job hands off to the desktop app, and four tool calls — local transcript read, Gmail draft, CRM note, Slack post — resolve one at a time in a live transcript.

The loop is built from the same DesktopShell and AgentChat components the product uses, fed genuine AI-SDK v5 tool parts, so the tool rows are the app's own renderers. The script is a beat list where every visual derives from the current beat index, which keeps the animation drift-free; the island shapes are shared with the persistent site island, and the demo island is suppressed only while the hero is on screen.

Typing in the composer still takes over the demo, and the loop pauses off-screen and respects prefers-reduced-motion.

Affected packages: `@ryu/blocks`
