## Highlights

### Remote access and permission levels

Core now mints a 256-bit node token on first boot, so it can start without an operator-provisioned credential, and surfaces that cannot read the token file authenticate through a device-code pairing flow. Operators can grant resources at specific permission levels, so browser.view and browser.control are distinct grants rather than a single blanket allowance.

The desktop app exposes Node Access, Node Permissions, and Resource Permissions settings, and the webapp, TUI, MCP, and Island targets resolve the new node-token and pairing clients.

### App-contributed Pi agent extensions

Apps can now declare pi_extensions in their manifests, and a reconciler projects the enabled set onto Pi's extension directory, adding and removing files as apps are enabled or revoked. The first user is the plan-continue plugin, which nudges the model while plan mode is on and the plan is not finished.

Plan mode continuation is no longer kernel behaviour; it is a plugin bounded by three consecutive auto-continues, a no-progress exit when the last two replies are identical, and the server's existing MAX_CONTINUE_TURNS backstop. The pi namespace is now reserved in gateway governance, so a Community plugin cannot self-approve the pi:extension capability.

Affected packages:

- `plugin: pi-shell`

### App-declared quotas and MCP bridge

Tier quotas are no longer a fixed table in core auth: kernel-level quotas stay in code, while app quotas such as maxMonitors and meetingRetentionDays are declared in the owning app's manifest. Every existing limit value round-trips unchanged, and PlanLimitField is now derived from the quota registries.

Developer Mode can arm a loopback MCP bridge so an agent can drive a stable release build. Arming is single-shot, the bridge state is reconciled app-wide rather than from the settings tab, and the bridge section appears whenever the socket is live, noting that it accepts uncredentialed local connections.

Affected packages:

- [`@ryu/meetings`](https://github.com/amajorai/ryu-meetings/releases/tag/v0.1.2)
- [`@ryu/monitors`](https://github.com/amajorai/ryu-monitors/releases/tag/v0.1.2)
- `ryu-core`
- `Desktop app`
- `Website (ryuhq.com)`
- `@ryu/auth`

### Live timing on tool calls

Every tool call in the chat UI now carries an elapsed badge that ticks while the call runs and freezes on the final time. The timing hangs off the shared tool row, so mcp, generic, search, thinking, subagent, and grouped rows all get it from one place.

Duration formatting tapers precision as the number grows, so a 420ms call and a 1m 23s call both stay readable. Rows that mount already complete never start a clock, so historical conversations show no invented timing.

Affected packages: `@ryu/blocks`
