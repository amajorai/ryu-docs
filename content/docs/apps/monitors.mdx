Website monitors: price, stock, keyword, content, and uptime watches with cross-device notification fan-out.

### Hook events

- **Monitor alert raised** - A scheduled (or run-now) check tripped its alert condition and the alert was stored. Fires once per transition, not once per check: a site that stays down, or a keyword that stays present, does not re-raise. `kind` says which transition it was - `uptime_down` / `uptime_up` / `keyword` / `content_change` / `price` / `stock` - so a recovery is this same event with `kind: "uptime_up"`.
- **Monitor check failed** - A check could not complete - the fetch failed, the crawler was unavailable, or the price/region regex matched nothing - so the site was never actually evaluated. The watch is broken, not the watched page. Unlike an alert this is NOT transition-gated: a monitor that keeps failing emits this on EVERY run until it is fixed. Uptime checks never emit it, because for them a failed fetch is the signal (`uptime_down`) rather than an error.
