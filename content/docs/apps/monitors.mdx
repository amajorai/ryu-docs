## What it does

Monitors watch websites for price, stock, keyword, content, and uptime changes, then fan out notifications across devices.

URL screening and guarded fetching come from Ryu's shared egress primitive: DNS/IP
pinning, redirect re-screening, response limits, and scheme checks are enforced by
the shared runtime seam while the app owns only monitor-specific extraction rules.
Notifications can target a webhook, Telegram, Expo push, or an email recipient
sent through the node's configured SMTP transport.

companion keeps its space for editing, running, and inspecting one monitor.

### Hook events

- **Monitor alert raised** - A scheduled (or run-now) check tripped its alert condition and the alert was stored. Fires once per transition, not once per check: a site that stays down, or a keyword that stays present, does not re-raise. `kind` says which transition it was - `uptime_down` / `uptime_up` / `keyword` / `content_change` / `price` / `stock` - so a recovery is this same event with `kind: "uptime_up"`.
- **Monitor check failed** - A check could not complete because the fetch failed, the crawler was unavailable, or the price/region pattern matched nothing. The site was not evaluated. This event is not transition-gated, so a monitor that keeps failing emits it on every run until it is fixed. Uptime checks do not emit it because a failed fetch is their signal (`uptime_down`), not an error.
