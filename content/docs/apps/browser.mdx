## What it does

Ryu Browser is a local Chromium session that both the user and the agent can
see. The desktop Browser panel follows a real embedded tab, while the
browser.control capability gives the agent structured access to that same
session: tabs, screenshots, accessibility snapshots, DOM context, visual
annotations, and computer-use input.

The important boundary is shared state: an agent reading browser.context sees
the embedded tab the user is looking at, not a separate external browser. A
snapshot, annotation, click, key press, or navigation is applied to the same
tab id shown in the Browser panel.

### Alternative provider: Ego Browser

[Ego Browser](/docs/plugins/ego-browser) is an optional `browser.control`
provider backed by [Ego lite](https://github.com/citrolabs/ego-lite). Install Ego
lite separately, ensure its `ego-browser` command is available to Ryu, then
install and enable the plugin from Marketplace. Select **Ego Browser** in the
node's Layers or capability-provider settings to route the same stable
`browser.*` tools through Ego's conversation-scoped Spaces.

The provider covers the canonical navigation, snapshot, screenshot, and input
verbs and keeps the choice reversible: select **Agent Browser** again when you want Ryu's MCP-backed
provider. Ego lite currently supports macOS; its browser login state remains in
Ego rather than being copied into Ryu.

Navigation is limited to web-safe destinations: `http:` and `https:` URLs, plus the exact
`about:blank` starting page. Script, data, file, and other custom schemes are rejected by the
sidecar before a tab is opened or moved.

### Hosted provider: Cloudflare Browser Run

[Cloudflare Browser Run](https://developers.cloudflare.com/browser-run/) is an optional external
`browser.control` provider. Its Marketplace entry is marked **External** and **Browser toolkit**
because the headless Chrome session runs on Cloudflare's network rather than on the Ryu machine.
Enable it from the plugin store, then choose Cloudflare Browser Run in the Layers picker.

Its canonical adapters provide URL-scoped navigation, snapshots, and screenshots. The native
Cloudflare MCP surface also offers HTML, Markdown, PDF, JSON, links, crawl, and browser-session
operations. The remote server uses OAuth, and the external provider does not copy local browser
cookies into the hosted session.

### Core browser app

A real-Chromium browser (Electron) Ryu runs as a local sidecar and exposes the
grant-gated browser.control capability. Core spawns the sidecar lazily and
idle-stops it; the desktop Browser panel and agents reach it through the same
ext-proxy.

### Browser shell

The same local Chromium session is available as a normal browser window. Its
shell provides tabs, a URL/search field, back/forward/reload, find-in-page, zoom,
device emulation, page screenshots, and a downloads popover. The browser menu
also opens browsing history, downloads, clear-browsing-data controls, and browser
settings.

Browser settings include link destinations, annotation screenshot policy, history
and download management, a save-location prompt, site permissions, and explicit
camera, microphone, geolocation, notification, and clipboard-read decisions.
Site-specific overrides are stored locally and can be removed. Agent browser
control is a separate setting enforced by the sidecar; turning it off blocks the
protected control surface even when a session token is available.

Passwords and autofill remain a deliberate privacy boundary: the browser can
open the credential-manager surface and import cookies from a user-selected
export, but raw saved passwords are not returned to Core or agents. Full CDP is
off by default; enabling it is marked elevated risk in Developer mode and takes
effect after the browser restarts.

## Embedded browser context and annotations

### Context

browser.context returns a live context bundle for a tab:

- page URL and title;
- viewport size and scroll position;
- a fresh accessibility snapshot with stable refs;
- the tab's saved annotations; and
- an optional PNG screenshot.

Pass CSS-pixel selections to resolve what the user pointed at. Each selected
target can include its tag, role, accessible name, text preview, attributes,
CSS selector, XPath, bounding rectangle, safe computed styles, React component
hint, and the matching accessibility ref. This makes a visual request
actionable without exposing arbitrary JavaScript evaluation to the canonical
agent surface.

### Annotation mode

In the desktop Browser panel, choose **Annotate** or press **Cmd/Ctrl+Shift+D**.
The current frame freezes so the marked pixels and the live DOM context stay in
agreement. Then:

1. Click an element to attach a point annotation, or drag to mark an area.
2. Hold **Shift** while selecting to add multiple elements to one note.
3. Write a specific request, optionally dictate it with the microphone, and
   open **Adjust styling** for safe feedback such as font size, weight, color,
   letter spacing, padding, or margin.
4. Choose **Add note**. The note remains attached to the tab and includes the
   captured target metadata.
5. Choose **Ask Ryu to address notes** to send the live browser context and
   saved annotations to the assistant.

Annotations are data, not an instruction to execute code. They can be listed
through browser.context, removed individually, or cleared for the tab. A
navigation clears stale element refs and the UI resumes the live frame after
annotation mode ends.

## What it exposes

### Tools

### `chromium.list_tabs` - List Browser Tabs

List the tabs currently open in the local Chromium browser sidecar. Returns `&#123;tabs:[&#123;id,url,title&#125;]&#125;`; the `id` is what every other browser tool takes. When the sidecar is not running the tool reports itself unavailable.

Backend: HTTP · Method: GET

_No parameters_ (empty schema).
### `chromium.open_tab` - Open Browser Tab

Open a NEW tab in the local Chromium browser at `url` and return `&#123;tab:&#123;id,url,title&#125;&#125;`. Use the returned `id` with the other browser tools. To move an EXISTING tab, use chromium.navigate_tab instead.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `url` | string | yes | URL to load in the new tab (the sidecar defaults to about:blank when omitted). |

### `chromium.tab_detail` - Browser Tab Detail

Fetch one tab's current `&#123;tab:&#123;id,url,title&#125;&#125;` by tab id. 404s once the tab has been closed.

Backend: HTTP · Method: GET

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | Tab id, as returned by chromium.list_tabs or chromium.open_tab. |

### `chromium.navigate_tab` - Navigate Browser Tab

Navigate an EXISTING tab to `url` and return `&#123;tab:&#123;id,url,title&#125;&#125;`. Requires a tab id from chromium.list_tabs or chromium.open_tab; 404s once the tab has been closed.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | Tab id to navigate. |
| `url` | string | yes | URL to load in that tab. |

### `chromium.screenshot_tab` - Screenshot Browser Tab

Capture a PNG screenshot of one tab. Returns `&#123;image,encoding:"base64",mime:"image/png"&#125;`. Requires a tab id from chromium.list_tabs or chromium.open_tab.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | Tab id to capture. |

### `chromium.tab_title` - Browser Tab Title

Read one tab's current document title as `&#123;title&#125;`. Cheaper than a screenshot for confirming a navigation landed.

Backend: HTTP · Method: GET

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | Tab id whose title to read. |

### `chromium.snapshot_tab` - Snapshot Browser Tab

Read one tab's accessibility tree. Returns `&#123;tab,snapshot_id,elements:[&#123;ref,role,name,value,depth,props&#125;],truncated&#125;`, where each `ref` (`@e1`, `@e2`, …) is the handle chromium.click and chromium.type take. Refs are minted fresh by every snapshot and are dropped when the tab navigates, so snapshot again after any action that changes the page. Content inside cross-origin iframes is not included.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | Tab id to snapshot, as returned by chromium.list_tabs or chromium.open_tab. |

### `chromium.click` - Click Browser Element

Click the element a chromium.snapshot_tab `ref` names, using a real mouse event at the element's centre. Returns `&#123;ok,tab,x,y&#125;`. A ref the current snapshot does not know, or whose element is hidden or gone, is a 400 telling you to snapshot again - it never falls back to another element.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `ref` | string | yes | Element reference from a prior chromium.snapshot_tab, e.g. "@e3". |
| `tab_id` | string | no | Tab to act on. Omit for the tab the browser is currently showing (a snapshot focuses the tab it reads). |

### `chromium.type` - Type Into Browser Element

Focus the element a chromium.snapshot_tab `ref` names and insert `text` at its caret, optionally pressing Enter. Text is APPENDED by default - set `replace` to overwrite a field that already has a value. A `ref` that is focusable but cannot accept text (a link, a read-only or disabled input, a checkbox) is a 400 rather than a silent no-op. Returns `&#123;ok,tab&#125;`.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `ref` | string | yes | Element reference from a prior chromium.snapshot_tab, e.g. "@e3". |
| `text` | string | yes | Text to insert at the element's caret. |
| `replace` | boolean | no | Overwrite the field's current value instead of appending to it. Use `replace` with an empty `text` to clear a field. |
| `submit` | boolean | no | Press Enter after typing (a real key event, so form/search handlers fire). |
| `tab_id` | string | no | Tab to act on. Omit for the tab the browser is currently showing. |

### `chromium.scroll` - Scroll Browser Tab

Scroll a tab's viewport with a real wheel event dispatched at its centre. `amount` is a distance in CSS pixels; omitted it travels 80% of the viewport. Returns `&#123;ok,tab,x,y&#125;`. Snapshot again afterwards - scrolling changes what is laid out.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `direction` | string (one of: up, down, left, right) | yes | Direction to scroll the page in. |
| `amount` | integer | no | Scroll distance in CSS pixels. Defaults to 80% of the viewport. |
| `tab_id` | string | no | Tab to act on. Omit for the tab the browser is currently showing. |

### `chromium.close_tab` - Close Browser Tab

Close one tab and return `&#123;ok:true&#125;`. 404s when the tab is already gone.

Backend: HTTP · Method: DELETE

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | Tab id to close. |

#### Context and annotation tools

### `chromium.context` - Get Browser Context

Return the live page, viewport, accessibility snapshot, saved annotations, and
optionally a screenshot. Pass `selections` as CSS-pixel rectangles to retrieve
structured DOM context for pointed elements. Set `include_screenshot` to `false`
for a text-only refresh.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | Tab id. |
| `selections` | array of rectangles | no | Up to eight `{x,y,width,height}` CSS-pixel selections. A zero-size rectangle resolves the element at a point. |
| `include_screenshot` | boolean | no | Include a PNG screenshot; defaults to true. |

### `chromium.annotate` - Annotate Browser Tab

Save a visual note to a tab. Use `kind: "element"` for one pointed element,
`"elements"` for a relationship between multiple targets, or `"area"` for a
drawn region. The sidecar captures target metadata when the note is created.

Backend: HTTP · Method: POST

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | Tab id. |
| `kind` | enum | yes | `area`, `element`, or `elements`. |
| `rect` | object | yes | CSS-pixel `{x,y,width,height}` note rectangle. |
| `selections` | array | no | Up to eight target rectangles. |
| `comment` | string | yes | Specific change request. |
| `style` | object | no | Safe style feedback such as `font_size`, `color`, `letter_spacing`, `padding`, or `margin`. |

### `chromium.clear_annotations` - Clear Browser Annotations

Delete every saved annotation for a tab.

Backend: HTTP · Method: DELETE

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | Tab id. |

#### Computer-use input tools

Element refs are preferred when the accessibility snapshot provides one.
Coordinate tools cover canvas, custom controls, hover states, drag gestures,
and other visual interactions that do not expose a useful semantic ref.

### `chromium.hover` - Hover Browser Element

Move the real pointer over a snapshot ref without clicking it.

### `chromium.click_at` - Click Browser Coordinate

Click a viewport CSS coordinate. Supports `left`, `middle`, or `right` button
and a bounded click count.

### `chromium.key` - Press Browser Keys

Send a key or chord to the focused page, such as `Enter`, `Escape`, or
`Control+L`.

### `chromium.drag` - Drag in Browser

Drag from one viewport CSS coordinate to another. This is intended for sliders,
canvas controls, drawing surfaces, and area-selection interactions.

| Level | Description | Implies |
|---|---|---|
| **Can view** | Read the browser's open tabs, titles, screenshots, accessibility snapshots, DOM context, and saved annotations. |  |

## UI it contributes

### Dock panels

- **Browser** (placement: both)

The Browser dock continuously refreshes the selected tab's viewport as a live frame
stream. **Annotate** freezes that frame, overlays numbered notes, resolves the
pointed DOM targets, and exposes comment, voice, multi-select, and styling controls.
The live-media card follows the selected tab and provides **Open PiP** for a native
always-on-top Tauri window or **Expand** for a fullscreen morphing lightbox. The
same lightbox transition is shared with user image attachments and marketplace
screenshots.

## Browser extension runtime

The browser extension reuses the desktop application interfaces for its main dashboard and chat, while keeping browser-owned surfaces such as New Tab, Ask Ryu, page saving, screenshots, downloads, and the in-page copilot.

Every extension model picker includes a `Browser` provider. Its selection is remembered independently for each agent and surface. Curated Transformers.js defaults and validated Hugging Face model IDs run in the extension worker/offscreen context using WebGPU when available and WASM otherwise. Transformers.js uses the browser Cache API for reuse; inference does not call Core.

Action-capable browser models receive a typed registry grounded in an indexed DOM/accessibility state. The Safe default requires one-time approval for page changes, navigation, external effects, downloads, uploads, clipboard access, and page saving. The registry does not expose arbitrary JavaScript evaluation, cookies, hidden credentials, or extension storage. Core/local/cloud turns can opt into the same tools through a per-turn browser-context consent switch; Core pauses on a server-issued nonce until the extension validates policy, executes the action, and returns a sanitized result.

Normal browser-local turns can link a bounded transcript and source metadata back to Core without sending the full page body, DOM index, screenshot, or raw tool result. Ghost Chat never creates that link.
