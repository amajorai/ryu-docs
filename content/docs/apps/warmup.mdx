## What it does

Warmup starts your subscriptions' rolling usage windows on your own schedule, so a window is already open when you sit down to work. At the times of day you choose (05:00, 10:00, 15:00, and 20:00 by default), it sends a one-word ping on the cheapest model to each subscription agent and to every saved account of each subscription provider (Claude Pro/Max, ChatGPT).

## Saved accounts and usage

Ryu decides which subscription providers offer a per-account schedule. A provider is listed when Ryu can ping one of its saved accounts at a time, which today means Claude Pro/Max and ChatGPT.

Each saved login shows its own usage windows, including per-model limits. Per-account usage covers Claude Pro/Max, ChatGPT, OpenAI Codex, and GitHub Copilot. ChatGPT Plan, Kiro, Kimi, Radius, Ant Ling, and CLI logins report no per-account usage. A login that needs a new sign-in is still listed, marked as expired, and is never read or pinged until you sign in again.

Saved accounts belong to the node owner. Only the owner, or an owner or admin of the node's organization, sees them in Warmup and can schedule pings on them, because a ping spends that login's quota.

## How pings run

Pings are ordinary scheduled jobs that Core runs, and Core checks every change the app makes. A change needs the app's approved `warmup:crud` grant and your own permission to view and edit agents on the node. The app only lists, replaces, or runs jobs that it created, never one created by you, Core, or another app. When you save new times, Core checks the whole plan first, so a bad time or zone leaves your existing pings unchanged. An app with its own background service can use the same four operations (`warmup.detect`, `warmup.list`, `warmup.apply`, and `warmup.runNow`), scoped to its own jobs. A background service has no signed-in user, so Core allows those calls only on a single-operator node that is not bound to an organization or managed.

## Permissions

**Grants:** `warmup:crud`, `core:list_agents`

| Level | Description | Implies |
|---|---|---|
| **Can view** | See which subscription agents and provider accounts are warmed, on what schedule, and when each was last pinged. |  |
| **Can ping now** | Trigger a warmup ping immediately, which opens a usage window on that agent's or account's subscription. | `warmup.view` |
| **Can configure** | Change which agents and provider accounts are warmed and at what times, which decides how much subscription quota is spent unattended. | `warmup.run` |
