## What it does

Warmup starts subscription agents' rolling usage windows on a schedule you choose. It sends a one-word ping to each agent on its cheapest model at the configured times, 05:00, 10:00, 15:00, and 20:00 by default, so a window is open when you start work.

## Permissions

**Grants:** `warmup:crud`, `core:list_agents`

Warmup keeps schedule and usage data on its `warmup:crud` domain bridge. It reads
the shared runtime catalog so its model control uses the same Ryu picker as other
apps, but it intentionally projects only a subscription lane that matches the
agent's advertised models. A scheduled Warmup target stores an agent plus model,
not a Gateway provider id, so showing BYOK or Ryu-managed lanes here would be
misleading; those provider-bearing choices belong to model-generating apps. The
agent's own subscription transport remains the execution authority. The catalog
contains metadata only; no provider key or subscription token enters the app.

| Level | Description | Implies |
|---|---|---|
| **Can view** | See which subscription agents are warmed, on what schedule, and when each was last pinged. |  |
| **Can ping now** | Trigger a warmup ping immediately, which opens a usage window on that agent's subscription. | `warmup.view` |
| **Can configure** | Change which agents are warmed and at what times, which decides how much subscription quota is spent unattended. | `warmup.run` |
