---
title: "Preview and live data"
description: "How Ryu companion previews differ from node-owned work."
tags: ["Apps"]
---

This guide connects the [Apps catalog](/docs/apps), [app manifest lifecycle](/docs/core/app-manifest-lifecycle), [Plugins vs Apps](/docs/extend/develop/extensions/plugins-vs-apps), and [Marketplace](/docs/extend/develop/extensions/marketplace) so a preview can be evaluated alongside the runtime and install contracts that make a connected app real.

A companion bundle opened directly in a browser does not have the Ryu host bridge.
It cannot read a node, a Space, a sidecar, or a provider. A bundle may show a
small, deterministic preview so its layout and controls can be inspected, but
that preview is not customer data and is never evidence of a live operation.

When a companion is opened by Ryu, its live branch uses the capability bridge
declared by its manifest. A live storage or sidecar failure produces an empty,
unavailable, or error state; it must not replace node-owned data with preview
records. The app's visible mode marker is the first clue, while the host logs
and persisted state are the authority for an end-to-end result.

| Companion | Standalone browser state | Connected state |
|---|---|---|
| Autopilot | Preview node | Node-owned strategy and runs |
| Clips | Bundled editor preview | Core and Shadow capture/ingest |
| Help Center | Demo mode with local sample records | Ryu Space documents |
| Invoices | Preview data | Node-owned invoice records |
| Outreach | Preview workspace; sends are recorded locally | Node-owned campaign and delivery state |
| People | Preview data | Node-owned people records |
| Projects | Preview data | Node and Space-backed projects |
| Slides | Preview data | Node-owned gallery in host storage |
| Studio | Browser preview | Node-owned content queue in host storage |
| Token Table | Demo table with simulated tokens | Local sidecar table with simulated tokens |

The **Preview data**, **Demo mode**, **Browser preview**, **Node-owned**, and
**simulated tokens** labels are deliberate. They prevent a screenshot, a sample
count, or a local button state from being mistaken for a provider charge, an
external message, a published post, or a completed node workload.
