title: "Preview and Live Data"
description: "How a Ryu app's standalone browser preview differs from the live, node-owned data it shows inside Ryu."
tags: ["Apps"]
---

This page explains how to tell a Ryu app's sample preview apart from real data,
for anyone who tests, screenshots, or reviews an app. A Companion UI bundle
opened directly in a browser does not have the Ryu host bridge, so it cannot
read a node, a Space, a sidecar, or a provider. The bundle may show a small,
deterministic preview so you can inspect its layout and controls. That preview
is not customer data and is never evidence of a live operation.

When Ryu opens a Companion UI, its live branch uses the capability bridge
declared by its manifest. A live storage or sidecar failure produces an empty,
unavailable, or error state. It does not replace node-owned data with preview
records. The app's visible mode label is the first clue. The host logs and
persisted state are the authority for an end-to-end result.

## Mode labels by app

| App | Standalone browser state | Connected state |
|---|---|---|
| Autopilot | Preview node | Node-owned strategy and runs |
| Clips | Preview workspace | Core and Shadow capture/ingest |
| Help Center | Demo mode with local sample records | Ryu Space documents |
| Invoices | Preview data | Node-owned invoice records |
| Outreach | Preview; sends stay in the preview | Node-owned campaign and delivery state |
| People | Preview data | Node-owned people records |
| Projects | Preview data | Node and Space-backed projects |
| Slides | Preview data | Node-owned gallery in host storage |
| Studio | Browser preview | Node-owned content queue in host storage |
| Token Table | Demo table with simulated tokens | Local sidecar table with simulated tokens |

The mode labels (**Preview data**, **Demo mode**, **Browser preview**, and
**simulated tokens**) prevent a screenshot, a sample count, or a local button
state from being mistaken for a provider charge, an external message, a
published post, or a completed node workload.
