## Human approval gates

Add a `Notify user` step when a workflow needs people to review before it continues.
The editor can load the organization directory, let you select multiple people, and set the
rule to first approval, everyone, a minimum count, or a minimum percentage. Percentage rules
round up (50% of 3 people requires 2 approvals). Core verifies selected IDs against the bound
organization before delivery; recipients approve from their Ryu inbox, and a direct run
resume cannot bypass the gate.

## Read-only dry runs

Open a saved workflow's Run panel and enable **Dry run** to preview its graph without changing
workflow state or delivering anything. Pure steps and explicitly read-only MCP tools are evaluated;
steps that could write, send, call a model, change the desktop, or wait for approval are marked
skipped with a reason. The result is transient, is not added to run history, and cannot be resumed.

The editor lays out the normal flow left to right and uses direct side-to-side connectors between
adjacent nodes, so the graph does not add decorative turns to otherwise straight connections.

## Permissions

**Grants:** `workflows:crud`, `workflows:runstate`, `workflows:catalogs`, `ghost:record`, `core:list_agents`, `app:realtime`, `ui:toast`, `ui:declarative-http`

| Level | Description | Implies |
|---|---|---|
| **Can view** | See workflows and their run history, without changing or starting anything. |  |
| **Can run** | Start a workflow and watch it execute. Implies viewing. | `workflow.view` |
| **Can edit** | Create and change workflows, including their triggers and steps. Implies running. | `workflow.run` |
| **Can delete** | Permanently remove a workflow and its run history. Implies editing. | `workflow.edit` |
