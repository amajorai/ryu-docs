## What it does

Agent Inboxes - email as a service for agents. Runs the out-of-process ryu-mail sidecar; Core proxies /api/mail/* to it. Its sandboxed companion is a per-node mail client (list inboxes, read messages, compose/send, create an inbox) driving /api/mail/* via the mail:crud bridge capability.

## Permissions

**Grants:** `mail:crud`, `ui:toast`

| Level | Description | Implies |
|---|---|---|
| **Can read** | List agent inboxes and read the messages in them. |  |
| **Can send** | Compose and send mail from an agent inbox, which leaves this node and reaches real recipients. Grant this level separately from read access. |  |
| **Can manage inboxes** | Create and remove agent inboxes, which decides what addresses agents can be reached at. Grant send access separately. |  |

### Hook events

- **Email received** - An inbound message was accepted and stored. Fires once per accepted POST to the inbound webhook, after the per-inbox HMAC verified and the row was written - so a forwarder that retries the same message fires this again. The payload is metadata only; fetch the body with GET /api/mail/messages/:id.
- **Email sent** - An outbound message was handed to the SMTP transport and recorded against the sending inbox. Fires once per successful send; a send that the transport rejects fires nothing. Hand-off is not delivery - providerMessageId is the relay's id, and a later bounce is not visible here.
