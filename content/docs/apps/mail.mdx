## What it does

Agent Inboxes provides email as a service for agents. The out-of-process `ryu-mail` sidecar owns the mail surface, and Core proxies `/api/mail/*` to it. Its sandboxed companion is a per-node mail client for listing inboxes, reading messages, composing and sending mail, and creating inboxes through the `mail:crud` bridge capability.

Outbound mail uses Ryu's node-owned SMTP transport. Configure the relay once in
Ryu Settings; headless nodes use the same node-level configuration. The Mail
sidecar calls the generic Core email capability and never carries a second SMTP
password or transport cache.

## What it exposes

### Companion surfaces

- **Mail** (html)

The desktop sidebar renders the app's **Inboxes** section from the live inbox feed.
Selecting an inbox opens `/mail/<id>` with that inbox focused; the companion then
uses its content area for messages, reading, composing, and inbox management.

Inbound delivery and inbox deletion share one transactional store boundary. A
delivery that races with deletion is rejected rather than recreating a deleted
message, attachment rows are foreign-keyed to their parent rows, and content-
addressed blob cleanup is retried from a durable queue on the next sidecar start
if the filesystem is temporarily unavailable.

## Permissions

**Grants:** `mail:crud`

| Level | Description | Implies |
|---|---|---|
| **Can read** | List agent inboxes and read the messages in them. |  |
| **Can send** | Compose and send mail from an agent inbox, which leaves this node and reaches real recipients. | `mail.read` |
| **Can manage inboxes** | Create and remove agent inboxes, which decides what addresses agents can be reached at. | `mail.send` |

## UI it contributes

### Hook events

- **Email received** - An inbound message was accepted and stored. Fires once per accepted POST to the inbound webhook after the per-inbox HMAC verifies and the row is written. A forwarder retry therefore emits again. The payload contains metadata only; fetch the body with `GET /api/mail/messages/:id`.
- **Email sent** - An outbound message was handed to the SMTP transport and recorded against the sending inbox. Fires once per successful send; a rejected send emits nothing. This confirms handoff, not delivery. `providerMessageId` is the relay's id, and a later bounce is not visible here.
