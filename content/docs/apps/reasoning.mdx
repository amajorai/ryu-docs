## What it does

Check an answer against a written policy with a solver instead of a second opinion. Point it at a document - an HR handbook, a refund policy, an underwriting rule sheet - and it drafts a formal model of it: typed variables and rules you can read and edit in plain language. From then on, a question and an answer are translated into logic and decided by a decision procedure built from scratch here (finite-domain enumeration over booleans and enums, Fourier–Motzkin elimination over linear rational arithmetic, branch-and-bound for integers). The result is not a score: `valid` means the policy PROVES the answer, `invalid` means it CONTRADICTS it and comes with a concrete counterexample, `satisfiable` means the policy simply does not settle it, and `impossible` means the policy contradicts itself - the case a naive checker silently reports as approval. Every finding names the minimal set of rules that decided it, the facts the answer quietly assumed, and what would have had to be different, all read back out of the solver rather than written by a model. Exact rational arithmetic throughout, so a rule about 0.1 + 0.2 does not fail on floating point. Model calls happen only at the two language edges; the verdict is reproducible offline from the formulas.

### MCP server

MCP (Model Context Protocol) is a standard way for an AI host to find and call tools. An MCP server provides those tools.

- **`reasoning`** - Automated reasoning checks as tools: `solve` decides claims written in the policy language with no model call at all, `check` does the same for prose, `policies` lists the vocabulary a policy declares, and `analyze` reports whether a policy's own rules are consistent. `solve` is the one to reach for inside a workflow - it is deterministic, so a branch gated on it always takes the same path for the same inputs.

### Hook events

- **An answer contradicted the policy** - A check finished with at least one `invalid` finding: the policy does not merely fail to support the answer, it proves the answer wrong, and a counterexample exists. Fires once per check, not once per finding. A check that came back `satisfiable` (the policy does not settle it) or `impossible` (the policy contradicts itself) does NOT fire this - those are gaps in the policy, not errors in the answer, and routing them to the same place trains people to ignore it.
