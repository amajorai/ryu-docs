## What it does

Groups: named collections of agents you can address as one. Governance shell over the agent-group store (agent-id membership only); no documents, no external dependencies. Runs the out-of-process group sidecar.

### Hook events

- **Group created** - A new group was persisted, from the desktop, the API, or Core's own agent-builder. Fires exactly once per group, on the insert that mints its id - a failed create does not fire. The payload is the group record as the group API returns it, so a brand-new group may already carry members (they can be supplied at create time) and its coordination defaults to `broadcast`.
- **Group changed** - A group's configuration changed - renamed, re-described, its coordination strategy or lead agent swapped, or an agent added to / removed from its roster. Fires for BOTH the full patch and the incremental member endpoints the desktop's drag-an-agent-into-a-group gesture uses, so "when an agent joins a group" never misses a path. Both member endpoints are idempotent, and a re-add of an existing member (or a remove of one who was never on the group) changes nothing and does not fire. The payload is the group AFTER the change, not a diff; compare `members` against your own last-seen copy to see who moved.
- **Group deleted** - A group was removed. Fires only when a row was actually deleted, so deleting an id that does not exist is silent. The payload is the group as it stood immediately BEFORE the delete - captured then because nothing can look it up afterwards - which is what lets a consumer clean up per-group or per-member state it was holding.
