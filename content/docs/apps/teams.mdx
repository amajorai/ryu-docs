## What it does

Teams: named groups of agents you can address as one. Governance shell over the in-crate teams store (agent-id membership only); no documents, no external dependencies. Runs the out-of-process ryu-teams sidecar; Core proxies /api/teams/* to it.

## UI it contributes

### Hook events

- **Team created** - A new team was persisted, from the desktop, the API, or Core's own agent-builder. Fires exactly once per team, on the insert that mints its id - a failed create does not fire. The payload is the team record as `GET /api/teams/&#123;id&#125;` returns it, so a brand-new team may already carry members (they can be supplied at create time) and its `coordination` defaults to `broadcast`.
- **Team changed** - A team's configuration changed - renamed, re-described, its coordination strategy or lead agent swapped, or an agent added to / removed from its roster. Fires for BOTH the full patch (`PATCH /api/teams/&#123;id&#125;`) and the incremental member endpoints the desktop's drag-an-agent-into-a-team gesture uses, so "when an agent joins a team" never misses a path. Both member endpoints are idempotent, and a re-add of an existing member (or a remove of one who was never on the team) changes nothing and does not fire. The payload is the team AFTER the change, not a diff; compare `members` against your own last-seen copy to see who moved.
- **Team deleted** - A team was removed. Fires only when a row was actually deleted, so deleting an id that does not exist is silent. The payload is the team as it stood immediately BEFORE the delete - captured then because nothing can look it up afterwards - which is what lets a consumer clean up per-team or per-member state it was holding.
