## What it does

Answer questions about a corpus far larger than any model's context window without putting it in a prompt. Your documents remain a variable. A root model plans over an outline of chunk ids, sources, line spans, and headings. It reaches text through bounded operators: `grep` locates candidates, `map` reads selected chunks in parallel, and `recurse` gives a sub-question its own plan over a subset. The root model sees the folded findings instead of the full corpus.

Every root query owns one model-call allowance and one deadline. Map leaves and nested recursive runs spend from those same limits, so recursion cannot multiply the caller's budget. A run that exhausts a limit reports `budget_exhausted` instead of presenting a shortened answer as complete.

Capability callers can require evidence. An evidence policy can set a minimum citation count, require one or more successful recursive reads, and restrict citations to an allowed source prefix. RLM accepts a final answer only when its citations point to chunks that an operator actually observed and the policy is satisfied. The result includes an input digest and evidence summary, allowing Research to bind a recommendation to the exact campaign history it submitted.

## What it exposes

### Companion surfaces

- **Deep Read** (html)

Deep Read uses Ryu's shared form controls, cards, badges, tables, alerts, and
semantic theme tokens. It follows the active desktop theme across context loading,
exact corpus search, cited answers, cost summaries, and expandable recursive
traces.

Deep Read's **Contexts** picker is rendered by the desktop host sidebar. A selected
context opens `/rlm/<id>` in the companion; loading a new context remains an in-app
action, but the primary context switcher is shared with the rest of the desktop.

The HTTP companion and the stdio MCP server resolve the same profile-aware
`RYU_DIR` (including the relocation pointer fallback). Dev, canary, nightly, and
beta sessions therefore never read the release context database by accident.

### Capabilities

- **rlm.query** - capability `rlm.query`
  - Grant: `rlm:query`

### MCP server

- **`rlm`** - Read more than fits in your context. `ask` takes paths and a question and returns an answer with `path:line` citations without adding the files to the conversation. `load` builds a reusable context, `query` asks follow-up questions against one, and `grep` and `peek` search and read it without a model call.

## Permissions

**Grants:** `rlm:query`, `hook:side-model`, `hook:run-agent`, `mcp:rlm`

| Level | Description | Implies |
|---|---|---|
| **Can view** | See the contexts loaded on this node, their outlines, and the traces of past runs. |  |
| **Can edit** | Load and delete contexts, and run queries against them. Loading a context reads files from disk and running a query spends model calls, so this is the level that costs something. | `rlm.view` |

## UI it contributes

### chat widget templates

- **Recursive Language Model widget** - Open Recursive Language Model data in a host-rendered chat widget.

### Composer controls

- **Deep read the corpus** - After each answer, ask the same question of the selected context and append what the documents actually say, with citations. Use it when the answer should come from your files rather than from the model. (type: toggle)

### Settings tabs

- **Recursive Language Model** (fields: Context to read (text), Planner model (model_picker), Reader model (model_picker))

### Turn hooks

- **rlm.deep-read** (on: `post_assistant_turn`)

### Hook events

- **A corpus-grounded answer was produced** - A deep read finished and returned an answer from the loaded context with at least one citation. Fires once per read, not once per citation. A read that could not run because no context or reader was available, or because the budget ended before reading, does not fire this event.
