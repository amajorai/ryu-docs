## What it does

Run durable autoresearch campaigns with one-shot proposals, direction-aware winners, bounded budgets, policy-based stopping, and automatic recursive analysis for oversized history.

## Who can see a campaign

Each campaign belongs to the person whose conversation or request created it.
On a personal node that is the node's owner, who sees every campaign. On a node
shared by an organization, a person (and their agents) sees and drives only the
campaigns they created: listing returns only their own, and another person's
campaign, workspace files, attempts and analyses behave as if they do not exist.
Campaigns created before this ownership existed stay visible only to the node
owner. If Ryu cannot tell who is calling on a shared node (for example, a
background job with no signed-in person behind it), Research refuses the call.

## How a run is approved and isolated

Every `research.run` call names a `workspace_tree`, a token for the exact
workspace contents it will execute. `research.write_file`,
`research.init_workspace` and `research.get_campaign` return the current token.
Ryu always asks you to approve a run, and the approval covers that token. If the
workspace changes after the token was issued, for example because a file was
rewritten while the approval was pending, the run is refused and its proposal is
kept, so you can review and approve the new contents. While an attempt runs, other
writes to the same workspace are refused until it finishes.

Each attempt executes a private copy of the approved contents inside an
operating-system sandbox. The experiment can read the language runtime and
system libraries. It can write only to its own temporary run directory and to a
private runtime directory that belongs to its campaign. That directory is the
experiment's home directory and holds its package caches, tools and downloaded
Python versions. Nothing outside the sandbox runs code from it. The experiment
cannot read Ryu's data directory (where node credentials and keys live), the
Research engine's credentials or campaign database, or your home directory. It
cannot write to shared package caches or tool folders such as `~/.cache/uv` or
`~/.local/share/uv`, which other Ryu components run code from.

It cannot open local (Unix domain) sockets, so the desktop session bus, keyring and other local
services are out of reach. Network access is off unless the experiment kind
needs it. The bundled `nanochat` experiment has network access so it can
download its dependencies and corpus. Its first attempt in a campaign downloads
them into that campaign's private cache, and later attempts reuse it. Network
access only allows outgoing connections. An experiment can never listen on a
port or accept connections, so it cannot pose as a local Ryu service. It also
cannot detach a process from its attempt: when the attempt ends, every process
it started is stopped. Experiment code that starts a new session or process
group (for example `setsid`) gets a permission error.

<Callout type="warn">
Experiments run on Linux only. The sandbox is required and needs Landlock
(kernel 5.13 or newer, with Landlock enabled, which is the default on current
major distributions) and seccomp on x86_64 or arm64. On macOS, on other
platforms, or when the sandbox cannot be set up, Research refuses to start the
attempt and keeps the proposal. It never runs agent-written code without the
sandbox.
</Callout>

## Data at rest

Research encrypts campaign content on disk with a key only this app receives from Ryu: campaign goals, attempt hypotheses, descriptions and run logs, proposals and analyses, and each campaign's history and results ledger files. Campaign names, scores, statuses, and times stay unencrypted so lists and winner selection keep working. Experiment workspaces, including their code and version history, are not encrypted because experiments run that code directly. Campaigns saved by an earlier version are encrypted the first time the updated app starts. If the app is updated before Ryu itself, new campaign content stays unencrypted until Ryu delivers its key, and the app reports that it is waiting for a Ryu update.

Ryu gives the key to the Research app itself, not to the Research tools agents call. When an agent starts Research before the app has run, the agent's campaign content is written unencrypted and is encrypted the next time the app opens; once the data is encrypted, the agent tools work only while the Research app is running, and otherwise ask you to open it. Research never restarts its engine while an experiment is running.
