## What it does

Deep research: multi-step web research runs backed by the autoresearch sidecar, with sources, findings, and RAG-searchable reports. Declares the out-of-process ryu-research sidecar (a thin Rust proxy that forwards /api/research/* to the Python autoresearch engine on :8087); Core reaches it via the generic ext-proxy loader.

## What it exposes

### MCP server

- **`research`** - Research - the autoresearch experiment loop over MCP (8 tools: list_experiments, init_workspace, read_file, write_file, run, keep, reset, ledger). Launched via `ryu-research mcp`, the same binary this app's sidecar entry declares; Core resolves the bare command out of its managed bin dir once that binary has landed. The tools drive the Python autoresearch engine on :8087, which installs separately - a call made before it is running returns `available: false` rather than failing the turn.

## UI it contributes

### Hook events

- **Research workspace created** - A fresh git-versioned workspace was initialised for an experiment kind and its initial commit made, so the autoresearch loop (read -> edit -> run -> keep/reset) can begin against it. Fires once per POST /api/research/workspace, whether the desktop or an agent asked for it. It says a workspace EXISTS, not that anything has been run in it - the attempts themselves go through the research__* MCP tools inside Core and are not visible here. `mutable_files` is the set of files a researcher is allowed to edit; the researcher instructions (program_md) are deliberately left out of the payload because they are a document, not a signal.
