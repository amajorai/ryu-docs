## What it does

AnyDoc is a `document.parse` provider backed by Firecrawl's MIT-licensed Rust
library. It converts Word, PowerPoint, Excel, OpenDocument, RTF, EPUB, CSV, and
text-based PDF files into GitHub-Flavored Markdown. Format detection uses the
document bytes when possible, with the filename or an explicit format for CSV
and other signature-less input.

The local service has no model download, native toolchain, OCR, or URL fetch. A
scanned or image-only PDF returns `needs_ocr`; choose a parser with OCR for that
corpus. The same `ryu-anydoc` process can run as a Core-managed sidecar or as a
separate API service.

## Document parser

AnyDoc is selectable as the `document.parse` backend. Core uses its
submit-and-poll routes so large files do not hold one request open:

```text
POST /api/ext/@ryu/anydoc/parse
GET  /api/ext/@ryu/anydoc/capability
GET  /api/ext/@ryu/anydoc/jobs/{job_id}
```

The provider accepts either a Core-confined blob path plus the original
filename, or inline bytes. Path inputs are resolved and checked against the
configured AnyDoc roots before reading.

## Standalone API

The same binary exposes `POST /v1/extract` with a tenant-scoped bearer API key.
Send raw bytes with `Content-Type` and `X-Filename`:

```sh
curl -fsS https://extract.example.com/v1/extract \
  -H "Authorization: Bearer ${RYU_ANYDOC_API_TOKEN}" \
  -H 'Content-Type: application/pdf' \
  -H 'X-Filename: report.pdf' \
  --data-binary @report.pdf
```

The JSON response contains `markdown`, the detected `format`, the AnyDoc
library version, an input SHA-256, warnings, and `truncated`. Smaller clients
may send `{ "contentBase64": "...", "filename": "report.docx" }` as JSON;
the standalone API does not accept filesystem paths.
Configure `RYU_ANYDOC_API_TOKEN` for one tenant or
`RYU_ANYDOC_API_TOKENS` for a JSON tenant-to-key map. TLS, edge rate limiting,
and billing remain deployment concerns; the service enforces API-key
authentication, tenant key separation, input/output limits, and conversion
errors.

## Errors and limits

The API uses stable error codes, including `needs_ocr`, `unsupported_format`,
`encrypted_document`, `resource_limit`, and `input_too_large`. Results are
bounded at 200 MiB input and 8 MiB output by default; output clipping is
reported with `truncated: true`.
