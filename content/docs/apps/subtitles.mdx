## What it does

Choose a video on this machine, transcribe it locally, translate the transcript, and write a timed `.srt` or `.vtt` file beside the source. Both model calls stay on the device: local Whisper handles transcription and the local Gateway model handles translation. Long jobs run through a queue, so a feature film can process while you do something else.

Cancelling or deleting a running job is terminal: late transcription or translation work cannot
resurrect its cues, status, or in-app output. A completed job commits its downloadable file before
the optional copy beside the source video is written, so a cancellation never leaves a new output
behind.

## UI it contributes

### Data categories

- **Delete all subtitle jobs**

### Hook events

- **Subtitle job queued** - A video was accepted and is waiting for the worker. Fires once per job before decoding starts. The transcript does not exist yet, so subscribe to `job.completed` when you need the cues.
- **Subtitles ready** - A subtitle file was written. `output_path` names the copy beside the source video and is absent when that write failed or the node setting is off; a downloadable copy still exists. The cues are not in the payload; read them from `GET /api/subtitles/jobs/&#123;id&#125;/cues`.
- **Subtitle job failed** - A job stopped before producing a file, and `error` explains why, such as an unsupported codec, a moved file, or an unavailable transcription engine. A job with some untranslated lines still completes and does not fire this event; compare `translated_count` with `cue_count`.
