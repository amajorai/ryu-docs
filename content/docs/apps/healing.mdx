## What it does

Self-healing diagnoses failed runs with a Gateway side model and sends proposed fixes to the approvals inbox. A person reviews each fix before it applies.

The per-source attempt cap is durable and fail-closed. If its state is corrupt or cannot be written
atomically, Self-Healing refuses to diagnose or auto-apply another fix instead of resetting the cap.

## UI it contributes

### Hook events

- **Fix diagnosed** - The side model diagnosed a failed run and resolved a fix. Fires once per heal attempt before the fix is acted on, whether `auto_apply` is true and the run will retry automatically or false and the fix goes to the approvals inbox. It does not fire when healing is off, the attempt is suppressed by the cap or cooldown, or the model returns nothing. `corrected_prompt` is `null` for a workflow, which retries from scratch instead of using a rewritten instruction.
- **Auto-fix gave up** - Self-healing reached its per-source attempt cap. No further fix is diagnosed or proposed for that run, and a terminal review item is queued. Fires at most once per source; later failures are dropped as already given up. Use this event for escalation.
