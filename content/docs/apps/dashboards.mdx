## What it does

Dashboards: composable widget boards that assemble live views over monitors, meetings, quests, and other Core surfaces via soft HTTP loopback. Declares the out-of-process ryu-dashboards sidecar (kind:local) that owns the store + refresh loop + /api/dashboards/* surface, served to the desktop through the generic ext-proxy public_mount. Started eagerly (not lazy) so the kernel hardware device-dashboard renderer + nudge loop can reach it at boot / on a device poll before any desktop has opened Home. The dashboard_builder MCP runnable + the hardware render seam reach it over loopback via dashboards_client.

### Hook events

- **Dashboard widget broke** - A widget's data source stopped resolving - the endpoint errored, the agent refused, the monitor or workflow it reads is gone. Fires on the TRANSITION into failure, which includes a brand-new widget whose very first resolve fails; a widget that then STAYS broken re-tries every interval but does not re-fire, so this is safe to hang an alert on. `source_type` is the wire tag of the resolver that broke (`core_endpoint` / `monitor` / `workflow` / `composio` / `http` / `agent`). Note that expensive sources are only refreshed while someone is watching the dashboard, so their failures surface when the board is opened rather than in the background.
- **Dashboard widget recovered** - A widget that had been failing resolved cleanly again - the counterpart transition to `widget.failed`, so an escalation raised on that one can be cleared by this one. Fires only on the crossing back to healthy; a widget that was never failing does not emit it on every refresh.
