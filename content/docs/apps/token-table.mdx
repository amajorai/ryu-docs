## What it does

Token Table is a six-seat Texas Hold'em table for friendly, cosmetic play. Players use a simulated token balance to join a room, post blinds, bet, fold, and see the hand resolve together in real time.

The balance is deliberately fictional. Token Table never changes model quotas, billing, credits, or the node's actual token accounting. It is a playful multiplayer surface on top of Ryu's room, presence, and event primitives.

## What it exposes

### Companion surface

- **Token Table** (html)

### Table views

- **Lobby** - join the shared room, see active seats, and choose a cosmetic buy-in.
- **Table** - six-max Hold'em with private cards, community cards, pot, blinds, street, and action controls.
- **History** - review the latest actions and the current simulated balance for the room.

## Multiplayer model

The sidecar is authoritative for seats, hands, card dealing, legal actions, settlement, and the simulated ledger. Ryu Core carries the room connection and presence channel; the companion receives table snapshots and only renders its own private cards while sending actions through the host bridge. Reconnecting clients receive the latest room snapshot.

## Permissions

**Grants:** `app:http`, `app:realtime`

The app can call only its own sidecar surface and join the room owned by the current node. It does not receive a node token and does not open network connections from the sandboxed companion.

## Cosmetic token disclosure

Token Table's “tokens” are an in-game score. They are not transferable, redeemable, purchasable, or usable for model inference. Any node usage that inspired the concept is intentionally not read, spent, or mutated by the game.

## Engine requirement

Requires Ryu >=0.1.0 and the generic realtime room primitive.
