## What it does

A cosmetic six-max no-limit Texas Hold'em table played with simulated tokens, run by a local sidecar. It never touches billing, quotas, wallets, or real money.

## Private cards

Table snapshots and shared realtime updates omit unrevealed opponents' hole cards.
Joining assigns a server-issued player identity and a private viewer capability; a
claimed player ID alone cannot read another player's cards or submit their actions.
The Companion retains its viewer capability for the current browser session so a
reload or reconnect can resume the same seat. It never includes that capability or
private cards in shared table publications.

Older tables with seats created before viewer identities are kept as public
history. Opening one selects a fresh table with the same settings so play can
continue without reclaiming another player's identity or deleting the old hand.
All clients opening the same older table use one shared replacement and its new
realtime room. The Companion remembers it during the browser session. Read-only
viewers can still inspect the older table's public history. Fresh hands
use a cryptographically random shuffle; earlier hands were not private snapshots.

At showdown, participating players' cards may be revealed. Folded cards and hands
won without a showdown remain private to their owner. Tokens remain cosmetic and
have no monetary, quota, or billing value.

For API clients, joining returns `playerId`, `viewerToken`, and a recipient-visible
`snapshot`. Keep the capability private and include `viewerToken` in mutation
bodies. The table's `view` operation accepts it in a POST body to retrieve private
cards; ordinary GET snapshots and shared events contain public information.
