Sites is Ryu's workspace for turning a prompt, local project, or Help Center
into a versioned, shareable web experience.

## One edge, many Sites

Published Sites receive a stable Ryu URL such as
`https://acme.sites.ryu.app`. Ryu uses one wildcard edge hostname and routes
requests by the validated `Host` header. A Site does not create a DNS record or
public tunnel of its own, so DNS records are not the Site-count limit.

Wildcard routing is not an unlimited-hosting promise: build minutes, storage,
egress, visitors, published Sites, connectors, and custom domains remain
explicit plan resources. The dashboard shows those limits before publishing.

## Domains

You can use the managed Ryu hostname immediately. For a customer-owned domain,
Sites shows the exact DNS verification record and only marks the domain live
after DNS and TLS are both ready. A delegated wildcard under a customer domain
can cover many Site subdomains with one DNS record; individual custom domains
are tracked separately because each one needs ownership and certificate
validation.

Raw IP addresses are reserved for local previews and diagnostics. Production
Sites use HTTPS hostnames so identity, certificates, and origin migration stay
stable.

## Public edge modes

- **Managed Ryu Edge:** Ryu provides the public edge and route leases.
- **BYO frp:** a self-hosted `frps` relay carries one node connector and many
  Site routes; the operator owns the relay, DNS, TLS, and egress.
- **BYO Cloudflare Tunnel:** one named, tunnel-scoped connector can carry many
  Site routes. Account-wide Cloudflare certificates are never required.

Quick Tunnels are suitable for previews only. Ryu does not represent them as
unlimited production hosting.

## Help Center widget

A published Help Center Site can generate a copy-paste widget snippet for any
website. The widget opens with Ryu's floating assistant language and provides
Ask, Help, and Contact destinations. It can search published articles, show
source links, collect a contact request, and hand off to a human without
exposing operator tickets, private notes, Space ids, or node credentials.

The generated snippet contains only the public Site origin and public Site key.
It never contains a connector token or Cloudflare credential.

## Current boundary

Sites publishes immutable deployments and keeps source, deployment, domain, and
connector state separate. The first release does not run arbitrary server-side
code, promise unlimited traffic, or publish a private node automatically.
