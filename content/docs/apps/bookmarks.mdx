## What it does

Bookmarks adds browser saving and import to Ryu Spaces for links you want to
remember, not just links you want to keep in a toolbar. It stores each bookmark
as an app-owned document in a dedicated Ryu Space, infers a small collection of
tags, and sends the document through Core's existing Space retrieval index.

Search by an idea such as “that article about typography systems” instead of
remembering the page title. Search is still Core-owned: Space visibility,
tenancy, indexing, and retrieval are enforced by the node rather than by the
companion frame.

## Imports and saving

- **Browser import:** the Ryu extension can read the browser's existing bookmark
  tree and import it into the same Bookmarks Space. Re-running the import skips
  URLs already in the library as well as duplicates in the current browser tree.
- **Save from a page:** the extension registers the app's “Save page to
  Bookmarks” context-menu contribution. The label and action belong to the
  Bookmarks app, while the extension supplies the current page context.

The extension asks for browser-bookmark access only when you choose Import. It
does not request that permission during extension installation. Save and Import
controls appear only while the optional Bookmarks app is installed and enabled;
availability is checked before Ryu creates a Bookmarks Space.

### Organize bookmarks into folders

Bookmarks groups saved links into explicit browser folders, inferred topics, or **Unsorted** when no
folder or topic applies. Open a folder to preview its saved links. Each preview keeps the existing
open, edit, favorite, and delete actions, so you can manage a bookmark without leaving its
collection.

## What it exposes

### Browser contribution

- **Save page to Bookmarks** (anchor: `browser-page`): adds the active page to
  the app-owned Space from the extension context menu.
- **Import browser bookmarks:** copies the browser tree after a user-approved
  optional permission, preserving folder paths and skipping duplicate URLs.

Bookmarks currently ships as an extension integration rather than a desktop
Companion. This keeps the built-in package honest: installing it never produces
an empty or unmountable interface. A future Companion release must carry its
packed `ui_code` in the satellite package before desktop support can be marked
full.
