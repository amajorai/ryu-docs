## What it does

Places keeps one map of places you want to visit and places you've been, and
plans trips day by day. Search real places or drop a pin, import places from a
TikTok, Instagram, YouTube, or blog link (or a Google Maps export), then plan
trips with AI-drafted days, optimized routes, bookings, split costs, and a
checklist. Places never books anything; bookings are records of what you
already booked. Records stay on your Ryu node.

What leaves the node:

- **Search text** (and the map center, to rank nearby results) goes to a
  [Photon](https://github.com/komoot/photon) geocoder over OpenStreetMap data.
  By default that is komoot's public instance at `photon.komoot.io`. A node
  can point Places at its own Photon server with `RYU_PLACES_GEOCODER_URL`, or
  turn search off with `RYU_PLACES_GEOCODER_URL=off` and drop pins by hand.
- **Imported place names and addresses** go to the same geocoder to find
  their coordinates: the names and addresses of Google Maps export rows that
  have no coordinates, and the place names (with any city) picked out of
  imported links, captions, and messages.
- **Imported links** are read from their public pages, and the page text, or
  the caption or message you paste, is sent to Ryu's configured model to pick
  out places. If that model is a cloud provider, the text goes to that
  provider.
- **AI trip drafts** send your request, the trip's name, destination, dates,
  planned stops, and saved place names to the same model. Each new stop the
  model proposes is then looked up in the geocoder by name together with the
  trip's destination.
- **Map tiles** load from OpenFreeMap.

## Sharing

Sharing follows your organization. Everyone in your organization uses one map
and one set of trips, and each person keeps their own want-to-go or been mark
on a place, with a visit date, a rating, and a note. Without an organization,
the map is just yours.

## Places Guide agent

The Places Guide agent can search places, save them to the map, import places
from a link, and plan trips with stops, bookings, costs, and checklists.

Agent access is off until you turn it on. Open **Members and your profile** in
the Places app and turn on **Places Guide agent access**. The agent then works
on that one map, and only one map on a Ryu node can use it at a time. When a
node serves an organization, only the organization's map can use the agent;
a personal map on that node cannot.

The agent works as **Places Guide**, not as you or any other member, so the
places and trip changes it makes are shown as made by Places Guide. It sees
each member's want-to-go and been marks with their dates and ratings, but not
the notes on those marks. It cannot set or clear anyone's mark; do that in the
Places app. It can delete only places it saved itself. When it records a cost,
it has to say who paid.

## Data at rest

Places encrypts the text of every shared map with a key only this app receives from Ryu: place names, addresses, links and notes, each member's personal notes, member and list names, the activity feed, and trips with their stops, bookings (including confirmation numbers), expenses and checklists. Each map is encrypted separately. Coordinates, categories, dates, amounts and ratings stay readable so the map, routes and budgets keep working; a copy of the data folder still shows where saved places are. Data saved by an earlier version is encrypted when the updated app starts. If the app is updated before Ryu itself, it keeps working unencrypted until Ryu delivers its key, and its health status says it is waiting for a Ryu update. The Places Guide agent tools reach encrypted maps through the running app.

### MCP server

MCP (Model Context Protocol) is a standard way for an AI host to find and call tools. An MCP server provides those tools.

- **`places`** - Places Guide tools for searching real places, importing them from shared links and captions, saving them to the one shared map that turned on agent access, and planning trips: AI-drafted days, day-by-day stops, route optimization, bookings, shared expenses with balances, and checklists.
