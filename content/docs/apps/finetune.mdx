## What it does

The fine-tuning studio launches LoRA/QLoRA jobs on this node's GPU or a remote Ryu Cloud GPU node. It tracks jobs durably, merges the trained adapter to GGUF, and registers the result as a swappable local model.

## How a run works

1. Open Fine-tuning from a model's catalog detail. The selected base model is carried into the
   form automatically; you can also enter any supported Hugging Face model ID yourself.
2. Choose chat, Alpaca, or text data, then start a local CUDA run or enter a configured remote GPU
   node. The app shows the capability check before enabling local training.
3. Follow the job in History while progress arrives over a live stream. Job records survive a
   worker restart, and trained adapters retain their base-model provenance.
4. Merge a completed adapter to GGUF. The result is registered as an installed model and can be
   selected as the active local model; the catalog labels it as a fine-tuned variant.

Local training requires a supported NVIDIA CUDA GPU. A remote run requires a reachable, configured
GPU node; those infrastructure credentials are not supplied by the app.

## UI it contributes

### Hook events

- **Fine-tune started** - Fires when a fine-tune job is accepted and a job id exists. The id can come from the local Unsloth worker at `POST /api/finetune/start` or from a remote GPU node. A GPU-gate refusal or a job the worker never accepted does not fire. Training has not started yet; the adapter arrives with `job.succeeded`. `target` identifies where the job runs. A remote dispatch also raises `job.started` on the remote node's own record, so two Cores produce two job ids for the same distributed run.
- **Fine-tune succeeded** - Fires once when training finishes and the adapter is added to the adapter catalog. `adapter_name` is the catalog stem and the value accepted by `POST /api/finetune/merge`. This crate has no background poller, so the event fires when Ryu next reads the job state, not when the worker finishes. A remote job is refreshed only by a detail fetch; the list refreshes local jobs only.
- **Fine-tune failed** - Fires once when a job ends in failure, such as an out-of-memory error, unusable dataset, or worker crash. A cancelled job does not fire this event because cancellation is recorded as `cancelled`. It follows the same read timing as `job.succeeded`, and remote jobs emit only after a detail fetch. `error` contains the worker's message when available, otherwise `null`.
