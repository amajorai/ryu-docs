## What it does

A LoRA/QLoRA training studio: launch fine-tune jobs on this node's GPU or a remote Ryu Cloud GPU node, track them durably, merge the trained adapter to GGUF, and register the result as a swappable local model.

### Hook events

- **Fine-tune started** - Fires when a fine-tune job has actually been accepted and a job id exists - either the local Unsloth worker returned one from POST /api/finetune/start, or a remote GPU node did. A start the GPU gate refused (no CUDA device on this node) or one the worker never accepted does not fire. Nothing is trained yet: the adapter arrives with `job.succeeded`. `target` says where it runs; dispatching to a remote node also starts the job on that node, so that node raises its own `job.started` against its own record - two Cores, two job ids, not a duplicate.
- **Fine-tune succeeded** - Fires once, when a job finishes training and the adapter it produced has been added to the adapter catalog. `adapter_name` is the stem it is filed under, which is exactly what POST /api/finetune/merge takes as `adapter_name` - so "when a fine-tune finishes, merge it into a GGUF" needs nothing else from the payload. TIMING: this crate has no background poller, so the event fires when Ryu next READS the job's state (a job list or a job detail fetch), not the instant the worker finished. A remote job is refreshed only by a detail fetch - the list refreshes local jobs only - so a remote job's completion is announced when someone opens it.
- **Fine-tune failed** - Fires once, when a job ends in failure - the training run itself broke (out of VRAM, an unusable dataset, a worker crash), so no adapter exists. Cancelling a job does NOT fire this: a cancel is user-initiated and recorded as `cancelled`, and the person who asked for it already has the answer. Same timing as `job.succeeded` - it fires on the next read of the job's state, and for a remote job only on a detail fetch. `error` is the worker's own message when it gave one, otherwise null.
