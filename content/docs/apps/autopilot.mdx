## What it does

Autopilot is a positioning-first launch companion. It starts with one question:
what is the one job this product should earn first? It then carries that choice
through the market position, differentiation, value proposition, narrow first
ICP, proof test, outreach motion, and copy.

The default Expense Tracker example is an illustrative working hypothesis, not
validated market evidence. Replace it with the product being shipped, run a
strategy pass, and review the outputs with customers before treating them as
validated.

## The launch chain

| Stage | Output |
|---|---|
| **One job** | The first outcome the product owns, plus an explicit boundary for what it will not do yet. |
| **Position** | Category, alternatives, market opening, differentiation, value proposition, and one-line positioning statement. |
| **First ICP** | A reachable audience, buying trigger, likely buyer, deliberate exclusions, and a proof test. |
| **Outreach + copy** | A proof-oriented first conversation, landing-page headline, subhead, and call to action derived from the same strategy. |

Autopilot is upstream of execution tools. It is not another CRM, outbound
sequencer, marketing suite, or generic copy generator. Its working hypothesis
is that a small product team needs a coherent decision before those tools can
create useful motion.

## Market position

The adjacent market is split across tools that execute different parts of the
job: [Clay](https://www.clay.com/) focuses on go-to-market research,
enrichment, and personalized outreach; [HubSpot](https://www.hubspot.com/products)
coordinates CRM and marketing execution; [Wynter](https://wynter.com/) tests
messaging and ICP understanding; and [Jasper](https://www.jasper.ai/platform)
keeps audience and brand context in marketing content workflows.

Autopilot is intended to sit before those categories: choose one job, state why
the product deserves a place in the market, narrow the first buyer, and only
then hand off to outreach or copy. This is a positioning hypothesis to validate
through customer conversations and paid tests, not a claim of established
category leadership.

### Permissions

**Grants:** `hook:run-agent`, `storage:kv`, `core:list_agents`,
`shell:integrate`, `ui:toast`

| Level | Description | Implies |
|---|---|---|
| **Can view** | See the one-job strategy, market position, ICP, activation pack, and guardrails. |  |
| **Can edit** | Edit the strategy draft, selected agent lane, and Autopilot guardrails. | `autopilot.view` |
| **Can run** | Run a bounded positioning-first strategy pass through the selected Ryu agent. The agent still follows each enabled tool's own grants and approval gates. | `autopilot.edit` |

## Runtime boundary

Autopilot delegates the strategy pass to the selected Ryu agent. The Companion
does not hold provider credentials, call a provider directly, or bypass another
app's permissions. Preparing outreach and copy changes the local strategy
record; an external send remains inside the destination app's approval or
review flow.

When opened without a host bridge, the Companion uses a demo node. Demo runs
change only preview state and never contact an external service.
