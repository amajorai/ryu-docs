## What it does

The WhatsApp app opens channel setup as a normal workspace tab. It uses Ryu's existing Gateway
channel system, so messages share the same agent or team sessions, history, tools, routing, access
policies, and memory as desktop chats.

Choose one of two transports:

- **WhatsApp Business (Cloud API)** uses Meta's official Cloud API and webhook credentials.
- **WhatsApp Personal** connects a self-hosted OpenWA session and is not an official WhatsApp
  integration.

Credentials belong to each channel record. Multiple WhatsApp numbers can therefore use different
agents, teams, policies, webhook secrets, and sessions without a global credential.

WhatsApp delivery fees are separate from model metering. The current Meta Cloud API adapter receives
message identifiers rather than a billable fee, so Ryu does not guess a Meta, Twilio, or Sent charge
from a successful send. When a future delivery adapter supplies an explicit provider cost, the
Gateway's provider-level billing policy can pass that raw cost through without platform markup.

## What it contributes

- A **WhatsApp** workspace/sidebar entry that opens the native channel editor.
- No sidecar, new transport, or duplicate credential store. Gateway remains authoritative for both
  WhatsApp adapters.

For credentials, webhooks, access policies, attachments, reactions, voice behavior, and deployment
details, see [Channels](/docs/gateway/channels).
