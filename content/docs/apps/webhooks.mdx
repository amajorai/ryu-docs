## What it does

Webhooks lists inbound endpoint registrations, their resolved public URLs, secret configuration, last-delivery times, and ingress backend status.

## Protecting an endpoint

Composio setup is automatic. Before Ryu creates a trigger instance, it creates
or updates the project's webhook subscription with the node's current public URL,
selects the V3 payload format, and enables trigger-message events without removing
other event types already selected for the project. The signing secret returned
by Composio is stored encrypted at rest.

Every Composio delivery must include its webhook ID, timestamp, and signature.
Core verifies the HMAC over the ID, timestamp, and exact raw body, and rejects
deliveries outside the five-minute replay window. V3 trigger identity is read
from the event's `metadata`, while older flat payloads remain supported.

The managed Ryu relay forwards the raw body and all signed headers to Core for
verification. Its URL token selects the destination node; it is not treated as
proof that a delivery is authentic.

Workflow webhooks use their own per-workflow signing secrets. In the Webhooks
app, choose **Generate** for a fresh server-generated workflow secret or enter a
custom value of at least 16 characters and choose **Save**. Configure the same
value in that workflow's external sender.

Secret values are fetched only through an explicit protected request; the endpoint
registry contains only whether a secret exists. The editor is blurred by default
and reveals the normal text field on hover or focus. An operator-managed
  Composio secret override must match the project subscription before Ryu creates
  a trigger. On a mismatch, Ryu saves the provider's current value securely and
  asks the operator to remove the stale override before retrying.

Secret access is also enforced by Core, independently of the Webhooks app's host capability. A
workflow secret requires `workflow.view` and that workflow's resource ACL to read, and
`workflow.edit` plus the same ACL to rotate. The node-wide Composio secret requires the
`gateway.configure` administrative permission for both operations because it authenticates every
Composio delivery on the node.

## Permissions

**Grants:** `webhooks:crud`

| Level | Description | Implies |
|---|---|---|
| **Can view** | See registered inbound endpoints, their public URLs, signing-secret status, and when each last received a delivery. |  |
| **Can manage** | Configure and rotate inbound signing secrets, which decides which outside systems may trigger work here. | `webhooks.view` |

## Engine requirement

Requires Ryu >=0.1.0.
