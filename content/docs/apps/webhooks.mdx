## What it does

Inbound webhook endpoint registry: resolved public URLs, signing-secret configuration, last-delivery times, and the ingress backend status.

## Using the registry

Copy a resolved ingress URL or endpoint URL with its copy button, then paste it into the sending service. An endpoint without a reachable public URL stays marked as unavailable and has no copy action. The app never substitutes a localhost address.

The registry and the ingress status are read from Core with the app's approved `webhooks:crud` grant. An app with its own background service can read the same two lists, and still never receives a signing secret from them.

### Signing secrets

Signing secrets are read and changed one endpoint at a time. Every read or write needs both:

- the app's approved `webhooks:crud` grant;
- your own permission: edit permission on that workflow, or Gateway configure permission for the Composio endpoint.

The grant alone never reveals a secret, and an app's background service cannot read secrets at all.

| Endpoint | What you can do |
|---|---|
| Workflow | Save a custom secret (Core accepts 16 to 512 characters), generate a server-side replacement, or copy the current value. |
| Composio | Nothing here. Composio signing secrets are managed when the trigger is saved and cannot be edited from this registry. |
