## What it does

Inbound webhook endpoint registry: resolved public URLs, secret configuration,
last-delivery times, and the ingress backend status.

## Protecting an endpoint

Each registered Composio or workflow webhook can be protected with a signing
secret. In the Webhooks app, choose **Generate** for a fresh server-generated
secret or enter a custom value of at least 16 characters and choose **Save**.
Core stores app-managed Composio secrets encrypted at rest and verifies signed
deliveries before accepting them. Workflow webhook secrets are saved with the
workflow and are also verified at ingress.

Use the same secret in the external sender's signing-secret configuration; the
button configures Ryu's verifier, not the external provider.

Secret values are fetched only through an explicit protected request; the endpoint
registry contains only whether a secret exists. The editor is blurred by default
and reveals the normal text field on hover or focus. If `COMPOSIO_WEBHOOK_SECRET`
is set in the environment, that operator-managed value takes precedence and must
be cleared before the app can replace it.

Secret access is also enforced by Core, independently of the Webhooks app's host capability. A
workflow secret requires `workflow.view` and that workflow's resource ACL to read, and
`workflow.edit` plus the same ACL to rotate. The node-wide Composio secret requires the
`gateway.configure` administrative permission for both operations because it authenticates every
Composio delivery on the node.

## Permissions

**Grants:** `webhooks:crud`

| Level | Description | Implies |
|---|---|---|
| **Can view** | See registered inbound endpoints, their public URLs, signing-secret status, and when each last received a delivery. |  |
| **Can manage** | Configure and rotate inbound signing secrets, which decides which outside systems may trigger work here. | `webhooks.view` |

## Engine requirement

Requires Ryu >=0.1.0.
