## What it does

Pull Requests is a GitHub work inbox inside Ryu. Its **Pull requests** tab searches
across repositories, switches between work you authored and work waiting for your
review, and shows the description, changed files, patch, checks, reviews, and
comments in one split view.

You can comment, approve, request changes, mark a draft ready, and merge with a
merge commit, squash, or rebase strategy. Every action runs through the GitHub CLI
installed on the node. Ryu does not ask for or store a separate GitHub token.

## Issues

The **Issues** tab uses the same GitHub sign-in and locally installed GitHub CLI. It
supports issue search, the **All**, **Assigned**, and **Authored** views, and open or
closed filters. Select an issue to see its description, labels, assignees, and
discussion, then comment, close, reopen, or open it on GitHub.

## Stacked pull requests

The app understands [GitHub stacked pull requests](https://docs.github.com/en/pull-requests/get-started/about-stacked-prs).
When a pull request belongs to a stack, the detail view shows the ordered layers
from the stack's trunk to the selected pull request. Select another layer to review
it, or use the stack actions to create a stack, add pull requests, or unstack it.

Stack actions follow GitHub's ordering: the first pull request is the trunk and each
later pull request is based on the previous layer. The merge menu can merge the
stack through the selected layer, queue the stack, or merge the selected layer
directly. GitHub processes stack merges asynchronously; Ryu keeps the pending state
visible and polls GitHub for the result. Stacks must be supported by the repository
and signed-in GitHub account because the feature uses GitHub's public-preview Stacks
API.

## Tasks and linked issues

Pull-request descriptions with Markdown task-list items are rendered in a read-only
**Tasks** section, including completion progress. GitHub sub-issues are rendered in a
separate **Subtasks** section with their open/closed progress, and issue references
that the pull request closes appear as linked issues in the same summary. Use GitHub
to edit the description, check off tasks, or change issue relationships; Ryu does not
mutate those fields.

When enabled, the app also powers the Git context surfaces in desktop: the pinned
Environment summary and chat-sidebar hover cards resolve the pull request for the
local branch and reuse the app's check rollup. Open, draft, closed, and merged requests
use the same GitHub-colored status icons across the app and desktop; open is green, draft
is gray, closed is red, and merged is purple. A branch with an existing open or draft PR
shows its GitHub-linked title instead of a second create action, while a closed or merged
request does not prevent a later open PR. If checks fail, the
Environment row's **Fix** action stages a bounded `.txt` report in the current chat;
it does not rerun workflows or change files automatically. When GitHub reports merge
conflicts, the summary adds a red **Merge conflicts** row with its own **Fix** action;
that action stages branch and merge-state metadata in a bounded `.txt` report for the
next chat turn, without copying repository contents. The same summary includes the PR's
comment count and links back to the discussion. Every operation uses the local
authenticated `gh` CLI; the desktop does not call GitHub's web API directly.

## Set up

Install [GitHub CLI](https://cli.github.com/), then install and enable **Pull
Requests** from the Ryu app store. If GitHub CLI is not signed in, choose **Sign in
with GitHub** in the app. Ryu shows a one-time code, opens GitHub's device
verification page in your browser, and waits for you to authorize it.

GitHub CLI owns the login and local credential storage. You can also sign in from a
terminal if the browser flow cannot be completed in the app:

```bash
gh auth login
```

## Provider support

GitHub is supported today. The app keeps provider commands behind its sidecar
boundary so GitLab can be added later without a Core or Gateway integration, but
GitLab and Bitbucket are not currently available.

## Permissions

**Grants:** `app:http`, `shell:integrate`

The HTTP grant lets this companion call only its own sidecar and only routes declared
in its manifest. The shell grant keeps the companion theme in sync with Ryu.

## Engine requirement

Requires Ryu >=0.1.0.
