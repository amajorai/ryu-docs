## What it does

A unified GitHub code review workspace for Ryu. Browse pull requests across repositories, inspect summaries and changes, see reviewers and CI status beside the selected pull request, and submit reviews through the locally authenticated GitHub CLI. GitHub issues remain available from the app's Issues contribution.

The inbox can search pull requests or open a pasted GitHub pull request link. The review view keeps the summary, diff, checks, discussion, and merge actions together.

To ask about the selected pull request, open the desktop's **Ask Ryu** assistant, the same assistant you use everywhere else in Ryu. Code Review does not have a separate chat panel.

For stacked pull requests, each layer shows its title, target and source branches, and status together. Select another layer to inspect it before choosing a stack merge action.

### Assistant context

While a pull request is open, the assistant shows it as two context chips. Remove a chip to leave it out.

- a summary with the description, changed file list, review and check status, and reviewer names;
- the diff.

The assistant also offers review starter prompts such as **Review this PR for bugs and risks**. Nothing is sent to a model until you ask the assistant something.

<Callout type="info">
The assistant is told not to post GitHub feedback, push, or merge unless you ask. Any tool it calls follows your tool permission settings, which may run some read-only tools without asking. Check its suggestions against the source and CI results before acting.
</Callout>

Each pull request gets its own conversation:

- Selecting another pull request replaces the context and starts a separate thread.
- Going back to an earlier pull request resumes its thread, even after you close the assistant.
- The assistant keeps your most recent app conversations (about a dozen, each trimmed to its latest turns) until the app restarts. Older ones start fresh.
- A diff that finishes loading for the previous selection is not attached to the new one.

If the app's assistant permission is turned off, Code Review works normally and the assistant simply has no pull request context.

### Sign-in and merges

During GitHub device sign-in, the app checks the authorization status while its view is
visible. Returning to the view refreshes the status, and a successful sign-in refreshes the work
inbox once. If the Companion cannot write to the clipboard, it selects the one-time code in a field
so you can copy it yourself.

Queued stack merges keep their completion notice visible while the inbox refreshes.

### Other desktop features that use this connection

The desktop app also uses this app's GitHub connection for:

- chat pull-request status icons;
- the optional **Gateway settings → Developer → Git → Watch and fix pull requests** automations (see
  [Git workspace controls](/docs/surfaces/desktop/user-guide/git-workspace-controls)).

Both read a pull request's state, recent comments and reviews, and open inline review
threads in one GitHub request. The request includes each author's repository association so
automations can ignore bots and outside commenters.

## Permissions

**Grants:** `app:http`, `shell:integrate`, `assistant:context`

| Level | Description | Implies |
|---|---|---|
| **Can view** | Use your local GitHub CLI login to list pull requests and issues and read their summaries and discussion. |  |
| **Can review** | Post comments and reviews, mark drafts ready, manage stacked pull requests, merge pull requests, and comment on or close issues using your local GitHub CLI credentials. | `pull-requests.view` |
| **Can ask for AI review** | Share the selected pull request's description, changed file list, review and check status, reviewer names, and diff with the Ask Ryu assistant as removable context. Nothing reaches a model until you ask the assistant a question. | `pull-requests.view` |
