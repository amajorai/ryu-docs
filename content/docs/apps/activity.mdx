## Observability workflow

The Activity Companion includes an **Observability** view for agents. It is the
local-first observe-to-evaluate loop: live audit rollups, searchable model and
tool events, correlated run traces, quality evaluation, bounded security probes,
and trace-to-Quality-test capture.

1. Open **Observability** and inspect request, error, latency, quality, token, and
   spend rollups. Choose a one-hour, 24-hour, seven-day, or all-available window;
   the view refreshes every 15 seconds and supports manual refresh.
   The status badge stays at **Checking** until the first audit response, reports
   **Live** only for an explicit reachable response, and reports **Unavailable**
   for a rejected, malformed, or unreachable audit request.
2. Search or filter events, then select one to inspect its correlated run trace.
   Raw prompts and responses stay in the conversation; tool inputs are represented
   by fingerprints in the trace view.
3. Run **Quality evaluation** to replay the shared dataset, or run **Security
   sweep** to probe prompt injection, jailbreak, PII leakage, tool misuse, toxic
   output, injection variants, and bias/fairness handling.
4. Add a selected correlated trace to **Quality tests**. Ryu creates a baseline
   suite when needed, versions the capture, and deduplicates retries.
5. Use **Online scoring** on the selected trace to score a completed output
   without replaying its provider request. **Prune local audit** applies the
   configured retention policy.

Quality evaluation and security probes use the configured model and the normal
Gateway policy, budget, and audit path. The security campaign owns a fixed set of
probes and never executes a real tool from a probe.

For side-by-side prompts and models, assertions, custom evaluators, imports,
exports, and human review, continue with the [Agents guide](/docs/surfaces/desktop/user-guide/agents).

## Permissions

**Grants:** `activity:read`, `activity:run`, `shell:integrate`

| Level | Description | Implies |
|---|---|---|
| **Can view** | See the node's activity feed: every monitor alert, finished run, approval, meeting, and note. |  |
| **Can run checks** | Run bounded security probes, score completed outputs, capture traces as quality tests, and apply local audit retention. |  |
