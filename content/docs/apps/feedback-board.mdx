## What it does

A public feedback board and private Ryu product workspace: collect requests, votes, and comments, turn demand into a roadmap, and use configurable Ryu workflows to prepare or build what users ask for.

## Review moderated submissions

When **Moderate public submissions** is enabled, visitors receive confirmation
that their request was sent for review. Request and comment submission responses
include `pendingReview` so clients can distinguish content waiting for review.
Pending requests remain private until a workspace member opens them in **Requests**
and chooses **Approve and publish** or **Reject submission**. Pending comments
appear on their request detail with **Approve comment** and **Reject comment**
actions; pending and rejected content does not appear on the public board.

If a public request cannot be saved, the dialog keeps the entered values and
shows a dismissible error so the visitor can retry without starting over.
API errors include a request ID in the response body and `x-request-id` header
to help correlate support reports.

## Public votes

Each visitor's first vote sets a signed, HttpOnly voter cookie that the board
issues itself. Votes are counted once per request for that cookie; a voter id
chosen by the client is ignored, so voting again from the same browser does not
raise the count. A visitor who clears the cookie is issued a new one, so the board
limits new voter cookies per client: five each hour and twenty each day for
one connection (one IPv4 address or IPv6 /64 network, or one signed-in account),
plus an overall limit for the whole board. One visitor using up their own limit
does not stop other visitors from voting, and the limits are kept across restarts.
When a limit is reached, the vote returns `429` with the `rate_limited` error code
and nothing is counted; the visitor can retry later. Visitors who already have a
voter cookie are never affected.

Ryu tells visitors apart by the address their connection comes from. Visitors who
reach the board through a tunnel, or through a reverse proxy on the same machine or
on a private network, all arrive from that proxy's address, so Ryu cannot tell
them apart. They share only the overall limit of sixty new voter cookies a minute
and six hundred an hour. A reverse proxy or CDN on a public address looks like a
single visitor to Ryu, so everyone behind it shares one per-connection limit. A vote
count is a signal of demand from distinct browsers, not a count of verified people.

## Public board branding

On the Free baseline, the public board carries a small [Powered by Ryu badge](/docs/billing/powered-by-ryu). Paid subscription plans remove it.

## Data at rest

Feedback Board encrypts the email address a visitor leaves with a request, with a key only this app receives from Ryu; only the board's admin views show it. Commenter email addresses are not stored. Request titles, descriptions and author names are public board content and are not encrypted. Emails saved by an earlier version are encrypted when the updated app starts. If the app is updated before Ryu itself, it keeps working unencrypted until Ryu delivers its key, and its health status says it is waiting for a Ryu update.
