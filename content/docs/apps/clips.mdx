## What it does

Clips captures and browses screen and timeline clips. It runs the out-of-process `ryu-clips` sidecar and uses Core as a proxy to `/api/clips/*`. The sidecar depends on the Shadow capture app for recordings and reads `RYU_SHADOW_URL` itself. URL/yt-dlp ingest and automatic filing into the Clips Space use Core's kernel machinery; the standalone sidecar degrades cleanly without it.

## UI it contributes

### Hook events

- **Clip recording started** - Fires when `POST /api/clips/start` begins a Shadow capture and a clip id exists. A refused start, or a start that never reached Shadow and returned `&#123; available: false &#125;`, emits nothing. The clip has no video or duration yet; those arrive with `clip.ready`.
- **Clip ready** - Fires once a finished clip bundle exists after `POST /api/clips/&#123;id&#125;/stop` stops a recording or `POST /api/clips/ingest` imports a watched URL or local video. `source` identifies the path. Fires once per clip alongside automatic filing into the Clips Space, even when filing fails. `framesEndpoint` is the Core-served frame path, and the MP4 is at `/api/clips/&#123;id&#125;/file`.

When a clip is ready, the desktop also inlines its first captured frame into the shared live-media dock. That evidence frame can be opened with the small-to-large morphing lightbox or kept visible in the native always-on-top PiP window alongside the Browser and Virtual Desktop streams. The secondary window never receives the node bearer token.
