## Presentation slots

Use `appearance="marketplace-guide"` on `DialogContent` for the scrolling guide surface and its overlay. Set `purpose="marketplace-guide"` on `DialogHeader`, and `typography="marketplace-guide"` on `DialogTitle` and `DialogDescription`. These options belong to the named slots, not `Dialog` root. For the visual header, `AnnouncementVisual` accepts `appearance="marketplace-guide"`; omitting it preserves the ordinary announcement visual.

On `DialogContent`, choose a named surface appearance for its complete popup frame: `license-browser`, `package-install`, `marketplace-detail`, `project-settings`, `conversation-share`, `quick-preview`, `git-history`, or `agent-editor`. The focused `worktree-handoff`, `workspace-required`, `workflow-fork`, `continue-on-node`, and `auto-routing` surfaces keep their respective form spacing and width limits. `gateway-settings` retains the existing settings frame; `deferred-settings` keeps the simpler loading frame.

`appearance="announcement"` pairs the scrolling announcement frame with its dark blurred overlay. `media-lightbox` pairs the black media surface with its overlay stack, while `image-editor` supplies the fullscreen editor frame and `sketch` supplies the sketch window frame. Continue to set `mobileFullPage`, `showCloseButton`, native focus props, children, and open state for the calling flow; these appearances do not replace those native controls. Omitting `appearance` preserves the ordinary popup.

Choose a `DialogHeader` purpose to match a sectioned surface: `license-browser`, `package-install`, `project-settings`, `records-panel`, or `agent-editor`. Use `cloud-settings` or `quick-preview` to leave room for the closing control, and `workflow-fork` for the fork form. Keep outer width, position, and open state at the calling site; omitting `purpose` retains the ordinary header.

On `DialogFooter`, `purpose="panel-actions"` adds the separated panel action frame; `cloud-actions` and `agent-editor` match those settings surfaces. Choose `package-actions` for package actions with a small top inset, or `package-list-actions` for horizontally flush package-list actions, or `announcement-actions` for spaced announcement actions. The default footer keeps its ordinary spacing and responsive action order.

Set `layout="inline"` on `DialogTitle` for an inline icon and title. Its `typography` options include `wrapped-label` for a wrapping name, `code` for a secret or code name, `explanation` for a roomier explanation heading, `conversation-share` for a share heading with room for the closing control, and `compact-preview` for a smaller preview heading. Labels, children, actions, and external layout remain owned by the caller.

Set `spacing="flush"` on `DialogContent` to remove the popup padding when its children supply their own insets, such as an edge-to-edge detail layout. It combines with the named appearances; omitting it keeps the ordinary popup padding.

## Import

```tsx
import { Dialog, DialogClose, DialogContent, DialogDescription, DialogFooter, DialogHeader, DialogOverlay, DialogPortal, DialogTitle, DialogTrigger } from "@ryu/ui/components/dialog";
```

The module exports `Dialog, DialogClose, DialogContent, DialogDescription, DialogFooter, DialogHeader, DialogOverlay, DialogPortal, DialogTitle, DialogTrigger`, so you can compose the primitive with its related parts.

## Usage

```tsx
import { Dialog } from "@ryu/ui/components/dialog";

export function Example() {
  return (
    <Dialog>Dialog content</Dialog>
  );
}
```

Add the props required by your workflow and compose the named exports as needed. TypeScript provides the complete prop and event contract at the import site.
