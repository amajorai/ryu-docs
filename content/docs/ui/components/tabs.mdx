## Scrollable tab strips

Set `manageLayout={false}` to keep every tab in a single horizontally scrollable strip. When the strip overflows, left and right arrow controls appear at its edges, with the edge fade showing which direction still has content. An arrow fades out and becomes disabled when the strip reaches that edge.

The arrows page through roughly 80% of the visible strip. Selecting or focusing an offscreen tab scrolls it into view without moving the surrounding page, and scrolling respects reduced-motion preferences.

## Presentation slots

Set `layout="catalog-sections"` or `layout="listing-detail"` on `TabsList` for wrapping catalog tabs. Use `density="catalog"` on `TabsTrigger` and `inset="listing-detail"` on `TabsContent`. Keep these named-slot choices separate from `Tabs` root state and orientation.

## Root, label, and content purposes

On `Tabs`, use `inset="agent-activity"`, `"store-sections"`, or `"library-sections"` for the corresponding root inset. Use `spacing="generous"` for a wider gap between the tab list and content. Existing root spacing, selection, and orientation remain independent choices.

On `TabsTrigger`, use `typography="pricing-plan"` for the larger pricing plan label or `"pricing-audience"` for the audience label. Use `labelCase="capitalize"` for capitalized labels, `spacing="store-section"` for compact icon-label spacing, or `tone="muted"` for muted label text. Existing list variants and active-state treatment continue to apply.

On `TabsContent`, choose `spacing="comfortable"`, `"relaxed"`, or `"generous"` for vertical content spacing, or `inset="agent-activity"` for the activity panel inset. Use `layout="install-instructions"` for a stacked installation body or `"sticky-showcase"` for the showcase body arrangement, and `appearance="layout-proof"` for a rounded, bordered, muted panel. Keep panel content, list management, and interaction at the calling site; caller classes follow these slot defaults.
