`ryu-cli` is the Bun and [OpenTUI](https://github.com/sst/opentui) React terminal client for
Ryu Core. It follows the Desktop information architecture where a terminal can do the same task.
It reaches the active Core node over HTTP and SSE (Server-Sent Events). It holds no model and runs
no inference of its own.

The client opens on the active node selected for the CLI (`ryu-cli node use`, or `Ctrl+N` inside
the workspace, which saves the choice for the next launch). `--node <name|url>` or `RYU_CORE_URL`
overrides it for one launch.

<Callout type="info">
  Desktop parity means capability parity where a terminal can complete the same task. Native
  Dock and window management, Tauri permission prompts, voice capture, and rich visual editors
  remain Desktop-owned. See [Desktop parity](/docs/surfaces/cli/parity) for the tested mapping.
</Callout>

## Launch it

Run the installed terminal client with no arguments:

```sh
ryu-cli
```

From a source checkout, use `bun run --filter cli dev`. Official binaries update themselves in the
background; see [Automatic CLI updates](/docs/surfaces/cli/getting-started#automatic-cli-updates).

### CLI state directory

For a separate CLI state directory, set `RYU_CLI_CONFIG_DIR` to an absolute directory path before you launch `ryu-cli`. It stores `nodes.json`, `cli-product-mode.json`, `prompt-history.json`, `cli-memory.json`, and `cli-layout.json` directly in that directory. This changes only these CLI state files; Core data and account authentication keep their own configuration. When this variable is unset, `nodes.json` lives in the data folder's `state/` directory and the other files in `state/cli/` (the data folder honors `RYU_DIR`). An empty or relative path is rejected.

### Reduced motion

Launch with `NO_MOTION=1 ryu-cli` to keep terminal spinners static. Spinner timers also stop under
`CI=true`.

## Terminal equivalents

The terminal client keeps shared Core behavior. It replaces pointer-heavy or OS-specific
interactions with keyboard commands and compact projections.

| Capability | Terminal behavior |
|---|---|
| HTTP/SSE client | Connect to a running Core node; models and tools execute through Core |
| Workspace navigation | Use `Ctrl+K`, tabs, panes, and node switching without a mouse |
| App contributions | Render portable list, table, and data-table views, or show an explicit unavailable state |
| Native effects | Consume Core notifications and status; it does not claim phone haptics, Live Activities, Dynamic Island, or browser permissions |

The terminal client does not duplicate Desktop-only UI. Use [Desktop parity](/docs/surfaces/cli/parity)
to see which features have a terminal equivalent and which stay in the desktop app.

### Guided setup

The Setup wizard separates Dependencies, Providers, Tools, and Agents. Use `Left`/`Right` or
`Tab`/`Shift+Tab` to change steps; each catalog list shows items for the selected category. Press
`Enter` to install the selected item. If an install fails, the wizard keeps the error visible; press
`r` to reload the catalog, then retry. The refreshed list shows the installed state after success.

When you switch nodes or refresh Apps, the launcher hides contributed app actions until the selected node returns its enabled app catalog. If that catalog is unavailable, built-in terminal shortcuts stay available. Press **r** to retry; only Apps admitted by the current node return to the launcher.

The launcher uses the active node selected with the CLI's node controls, so the terminal and
Desktop operate on the same conversations, agents, apps, and tools.


## The shell

The client is a tabbed workspace shell. Its Ctrl-modified bindings own the workspace:

| Key | Action |
|---|---|
| `Ctrl+K` | Open the fuzzy command palette (the Cmd+K analog) |
| `Ctrl+N` | Switch the active node (not in Bot mode) |
| `Ctrl+T` | Open a new chat tab |
| `Ctrl+Shift+T` | Restore the last-closed tab |
| `Ctrl+W` | Close the focused pane's active tab |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | Next / previous tab in the focused pane |
| `Alt+1` … `Alt+9` | Jump to tab 1–9 of the focused pane |
| `Ctrl+Alt+S` | Split Center into two panes, or join them again |
| `Alt+Arrow` | Focus the nearest visible pane in that direction |
| `Ctrl+Shift+→` / `Ctrl+Shift+↓` | Move the focused tab to the **Right** or **Bottom** pane |
| `Ctrl+Shift+↑` | Move the focused tab back to **Center** |
| `Ctrl+B` / `Alt+B` | Show or hide the sidebar |
| `F6` / `Alt+0` | Move keyboard focus into the sidebar |
| `Ctrl+Shift+M` | Choose Bot, Agent, or OS mode |
| `F1` / `Ctrl+?` / `?` | Open the keyboard shortcuts overlay (`?` only outside text fields) |
| `Ctrl+C` | Copy the selection, stop or clear the chat, or arm quit (see below) |
| `Ctrl+C` twice | Quit |

Alt shortcuts work whether the terminal sends Alt as Option or as an Esc (Meta) prefix. In macOS
terminals, set Option to send Meta. `Alt+B` exists for tmux and Herdr, which use `Ctrl+B` as their
prefix.

The terminal client uses the same pane layout as Desktop: the sidebar on the left, **Center** with its
split panes, and **Right** and **Bottom** panes that appear when they hold a tab. While **Right**
or **Bottom** has keyboard focus, the status bar names it and shortens the node URL rather than the
pane name. The command palette offers the same moves by name, plus **Show** or **Hide** for Right
and Bottom (a hidden pane keeps its tabs), **Split Center**, and **Reset layout**. Center is never
left empty: moving or closing its last tab opens a new chat there.

Tab placement, splits, and pane visibility are saved in `workbench-layout.json` in the Ryu data
directory (`RYU_DIR` when set, otherwise the profile's `~/.ryu` directory) and restored on the next
launch. If the file cannot be saved, the client shows one message and keeps working; a damaged file is
ignored and the default layout is used.

The shell keeps navigation, tabs, content, and key hints on the same canvas. Spacing and muted
labels group controls, and list/detail screens use a single vertical rule between columns instead
of separate framed panels. Split workspaces use one divider between panes, and it resizes with the
terminal. The Right and Bottom panes are set off by one divider each.

### Keyboard shortcuts overlay

`F1` opens a searchable **Keyboard shortcuts** overlay. `Ctrl+?` (or `Ctrl+/`), a bare `?` when no
text field has focus, the palette entry **Keyboard shortcuts**, and a bare `/help` in chat open it
too. It lists the navigation keys, then the chat keys, then every slash command. Type to filter by
key, label, or group; `↑`/`↓` and `PgUp`/`PgDn` scroll; `F1` or `Esc` closes it. In Bot mode it
hides `Ctrl+N`, `Ctrl+A`, `/agent`, `/group`, `/model`, and `/reasoning`.

### Quitting with Ctrl+C

`Ctrl+C` acts in this order:

1. If text is highlighted with the mouse, it copies the selection.
2. Otherwise, in a focused chat, it stops a reply that is still streaming, or clears an unsent draft.
3. Otherwise it shows **Press Ctrl+C again to quit**. A second `Ctrl+C` within 2 seconds quits;
   any other key cancels.

Choosing **Quit** in the command palette quits immediately. On the waitlist and sign-in screens, a
single `Ctrl+C` quits.

### Command palette

The command palette is the main navigation surface. A narrow sidebar cannot hold every tab, so
the palette fuzzy-jumps to any tab and to global actions. Switching nodes is one of those actions and
is driven with the arrow keys and Enter.

With an empty query, the palette groups entries into **Suggested** (up to three commands you ran
this session), **Navigation**, **Actions**, and **Plugins**. Typing ranks matches: exact, then
prefix, then word prefix, then substring, then letters in order. Spaces are ignored, so `gotohome`
or `nwcht` find their commands. Some entries also match aliases; for example, `channels` finds
**Open Gateway** and `credits` finds **Open Settings**. Actions show their shortcut on the right,
and the palette includes **Split Center** (**Join Center panes** while split), **Close tab**,
**Reopen closed tab**, the layout moves above, **Toggle sidebar**,
and **Keyboard shortcuts**. Hover selects a row, a click runs it, and clicking outside closes the
palette. The footer reads `↑↓ select · Enter run · Esc close` with the result count.

### Overlays

Settings, Gateway, the mode and node pickers, the command palette, the keyboard shortcuts overlay,
and the chat pickers and panels (`/help`, `/sessions`, `/btw`, `/theme`, the `/delete`
confirmation, and plugin notes) open as a centred panel over a dimmed backdrop. Opening one does not
move the transcript or composer. Click the backdrop or press `Esc` to close it. In a split, chat
overlays stay inside their own pane. A panel taller than the terminal scrolls with the mouse wheel
or with `↑`/`↓`, `j`/`k`, and `PgUp`/`PgDn`; pickers keep the selected row in view.

### Tabs and sidebar

The tab strip is one row that never wraps. Each tab shows as `n:title`, where `n` is its `Alt+n`
index, and long titles end in `…`. Pinned tabs show `*` after the index. The active tab is
highlighted and has a `×` close button. When tabs do not fit, `‹ +N` and `+M ›` show how many are
hidden; click a marker to reveal the nearest hidden tab. Click a tab to focus it, and middle-click
it or click its `×` to close it. In a split, a pane with few tabs gives its spare width to the other
pane.

`Ctrl+B` or `Alt+B` shows and hides the sidebar. Until you choose, the sidebar hides automatically
when the terminal is narrower than 100 columns. A hidden sidebar leaves a thin strip on the left
edge; click it to show the sidebar. Your choice is saved in `cli-layout.json` with the other CLI
state files, so it persists across launches.

`F6` or `Alt+0` moves keyboard focus into the sidebar, showing it briefly if it was hidden. Inside
it, `↑`/`↓` or `j`/`k` move, `Enter` opens a row and returns focus to the content, `Enter` on a
section header folds it, `←`/`→` fold and unfold a section, and `Esc` or `F6` return focus.
Clicking in the pane also returns focus.

Empty sidebar sections start collapsed to their header row (for example `▸ MEETINGS 0 +`) and
expand when items arrive. Click a header to fold or unfold it. Rows highlight under the pointer and
open when you release the mouse button; pressing a row and dragging off it cancels the click. On
short terminals, the section list is cut off and scrolls with the mouse wheel, while the footer
(Account, Inbox, Downloads, and settings) stays visible.

### Status bar and notifications

The status bar is one row that fits the terminal width. When space runs out, it drops whole hints
by priority: `^K palette`, `^C×2 quit`, and `F1 keys` stay; the focused view's hints come next;
then new tab, close, node, mode, and sidebar. A long node URL is shortened in the middle with `…`.
While a chat reply streams, the bar leads with a spinner, `esc interrupt`, and the elapsed seconds.
While an overlay such as Settings is open, the bar shows that overlay's hints.

Notifications float in the top-right corner over the panes. Up to three show at once, newest first,
and the rest collapse into `+N more`. Each has a bar coloured by severity. Repeats of the same
message merge into one notification with a `×N` count. Click a notification to dismiss it.
Information and success messages stay for 3 seconds, loading for 4, warnings for 6, and errors
for 8.

### Selecting and copying

Drag with the mouse to select text, for example in the transcript. When you release, the selection
is copied to the system clipboard through the terminal (OSC 52) and **Copied to clipboard**
appears. A plain click copies nothing, and the highlight stays until your next click or key press.
A click while text is highlighted only clears the highlight. Terminals without OSC 52 support, and
tmux without `set -g set-clipboard on`, show **Clipboard unavailable in this terminal (OSC 52)**
instead. Some terminals silently ignore clipboard writes, so the confirmation can appear even when
nothing was copied.

## When Core is not running

If the active node cannot be reached, Home shows **Core isn't running at host:port** (or **isn't
reachable** for a remote node) in place of its System card. Press `s` to start a local Core when
this terminal can start one, `^N` to switch node (not in Bot mode), or `r` to retry. Ryu also
retries automatically after 3, 5, and 8 seconds, then every 10 seconds, and shows a countdown. An
empty chat shows a compact version of the same message and points to Home for starting Core.

### Local node identity check

For a local node reached over plain `http://` (such as `http://127.0.0.1:<port>`) with a saved node
token, `ryu` first proves that the process on that address and port is your Core. It sends a
one-time challenge that only a holder of the token can answer, and never sends the token during the
check. The check repeats before every request that carries the token, including a reconnecting
stream, and the token goes only over the connection that passed it. `localhost` is tried as
`127.0.0.1` and then `::1`.

If another program holds the port, or an older Core cannot answer, the node shows as not running,
the CLI does not start a second Core, and commands stop with a message that the process could not
prove it is your Ryu Core. Stop the program using the port, or update Ryu Core. A local
plain-`http://` node with no saved token gets no credential at all (no token, sign-in identity, or
vault token; `ryu secrets` machine commands stop with an error, see
[machine access](/docs/security/secret-vault-engines)). Remote nodes over `https://` rely on TLS
instead.

The check also fails, and `ryu` sends nothing, in two legitimate setups:

- The saved token is a paired-device or delegated token rather than that Core's node token. Use
  the node token for a local address, or reach the node over `https://`.
- The address is a port forward that does not reach Core on the same loopback address and port,
  such as `docker -p` or an `ssh -L` forward to another port. Forward to the same address and port
  (for example `ssh -L 7980:127.0.0.1:7980`), or use `https://`.

### Account service address

Account features (Settings → Account, Profile, Sessions, Authorized apps, managed nodes, and the
waitlist check) talk to the Ryu account service named by `RYU_AUTH_URL`. When it is unset, the CLI
uses the hosted service at `https://api.ryuhq.com`. Under the `dev` profile (`RYU_PROFILE=dev`) the
fallback is `http://localhost:3000` instead. That is a local port any program can claim, so `ryu`
sends that fallback neither your account session nor your sign-in identity. To use a local account
service, set `RYU_AUTH_URL` to its address explicitly.

### Error messages

Error screens use plain language: an unreachable node is named, an unexpected response names the
first field that failed, an expired sign-in asks you to sign in again from Settings → Account, and a
permission error says you lack access. **Press r to retry** appears only where `r` reloads.
