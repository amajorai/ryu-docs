`ryu-cli` is the Bun and OpenTUI terminal client for Ryu Core. It uses the same node and account as
the other Ryu clients.

## Install and run

Follow the [Getting Started guide](/docs/start-here/getting-started) to install Ryu and start Core.
Then open an interactive terminal and run:

```sh
ryu-cli
```

From a source checkout, run `bun run --filter cli dev`. Set `RYU_CORE_URL` when you want to connect
to a different Core node, and set `RYU_CORE_TOKEN` if that node requires a token.

## Log in

Run `ryu-cli login` to start Core's device-login flow. The CLI prints a device code and verification
URL. After sign-in, account-backed workspace commands use the same approval state as Desktop.

## Start a chat

The Chat surface opens by default. Type a message and press Enter. Core saves the conversation, so
you can resume it from Desktop or another client connected to the same node. Press `Ctrl+A` to pick
an agent, or `Ctrl+K` to open the command palette.

## If you are on the waitlist

The Ryu account service decides which nodes need waitlist approval for a signed-in account. A queued
account sees a waitlist message on a gated node; press `r` to retry after approval. One-shot
commands follow the same rule.

## If two-factor setup is required

Ryu accounts need a passkey or an authenticator app. When the signed-in account has neither, the
workspace shows **Set up two-factor authentication** instead: press `Enter` to open the website's
setup page, then `r` to check again once it is done. A one-shot command that Ryu refuses for this
reason prints the setup page address and exits with status 1; with `--json`, the error carries the
code `mfa_enrollment_required` and a `setupUrl` field. See
[Required second factor](/docs/security/authentication-account#required-second-factor).

## Automatic CLI updates

Official `ryu-cli` binaries check their release channel in the background when **Automatic updates**
is on in Settings → Updates. The CLI verifies the downloaded release against its published SHA-256
file and makes it active for the next launch; it never closes a session to install an update. Source
and development runs skip binary self-updates. See [Ryu updates](/docs/core/updates) for how other
surfaces update.

`ryu-cli update` checks the selected Core node's release status. That check is separate from updating
the local `ryu-cli` executable.

## Essential keys

| Key | Action |
|---|---|
| `Enter` | Send the message |
| `Shift+Enter`, `Alt+Enter`, or `Ctrl+J` | Insert a newline |
| `Esc` | Stop a streaming reply |
| `Ctrl+K` | Open the command palette |
| `Ctrl+N` | Switch the active node |
| `Ctrl+T` | Open a new chat tab |
| `Ctrl+Shift+M` | Choose Bot, Agent, or OS mode |
| `F1` | Show every keyboard shortcut and slash command |
| `Ctrl+C` twice | Quit and restore the terminal |

The full key map is in [The shell](/docs/surfaces/cli/tui#the-shell) and
[Chat](/docs/surfaces/cli/tui-chat#chat).
