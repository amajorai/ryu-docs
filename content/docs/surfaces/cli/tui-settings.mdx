This page covers the settings overlay and workspace views of the [terminal workspace](/docs/surfaces/cli/tui).

## Settings

Settings opens as an overlay. Use `Up`/`Down` or `j`/`k` to move between panels, and `Esc` to close
it. In Profile, Account, and Sessions, `Up`/`Down` switch accounts while `j`/`k` keep moving between
panels. **Connections** and **Integrations** open the Services view.

### Startup realm

Settings → General lets you choose **Last used**, **Bot**, **Agent**, or **OS** for the next
launch. Changing this preference keeps your current workspace open. If the CLI cannot save it, the
previous choice stays selected and an error appears. Restore access to your CLI state directory,
then select the realm again.

### Account and security

Settings → Account offers `w` to set or change a password, `u` to request an email change, `v` to
request verification mail, and `c` to cancel a pending email change. Password and email changes use
the account service's identity-verification methods. Use Left/Right to choose an offered method;
`Ctrl+S` requests a mailbox code or magic link when offered. For a magic link, paste its token or
the complete verification URL from your mailbox.

Enter submits and Tab cancels a security editor. `t` turns two-factor authentication on or off;
after you add the displayed URI to your authenticator, enter its code. Save the displayed backup
codes privately; `b` regenerates them while two-factor is on. Email changes stay pending until both
addresses confirm them.

If the account service has no active session, account details are unavailable. Sign in again and
reopen Settings to reload them. In the Account tab, `l` starts the same browser sign-in
flow as `ryu-cli login`, and `a` adds another account. If you deny the code, it expires, or the flow
is replaced or cancelled, the Account tab says so, and the account that was already active stays
signed in.

### Profile and authorized apps

Settings → Profile uses `e` to edit the display name and `p` to edit personal context. Within
personal context, Tab moves between fields, Enter saves, and the Cancel control discards changes.
Personal context is part of the system prompt for every thread, so saving a changed value first asks
you to confirm the one-time prompt-cache reset: `y` applies it and `n` keeps the saved value. `a`
uploads a JPEG, PNG, or WebP photo from a local file path (up to 5 MB); Enter uploads and Tab
cancels. `d` removes the photo after `y` confirmation; `n` cancels.

Settings → Authorized Apps shows granted scopes. Use Up/Down to select an application, `x` to
request revocation, `y` to confirm, `n` to cancel, and `r` to reload.

Account, profile, and application changes report completion only after the service confirms the
result. A failed action keeps its error visible so you can retry. After you switch accounts or sign
out, the terminal withdraws the previous account's app views and commands while it refreshes
identity. A failed account change keeps the current account active.

### Memory settings and library

In Settings → Memory, `m` opens the summarizer model, effort, and consent controls, and `l` opens
the memory library. Core verifies access and sensitive-topic consent. Cross-session chat consent is
saved in the CLI profile and applies to later turns.

In the library, use Up/Down to select an entry, `/` to search, `a` to add, `e` to edit, and `r` to
reload or retry. `x` opens deletion confirmation; `y` confirms and `n` cancels. `l` returns to
Memory settings.

An entry editor has content and metadata JSON fields. Tab switches fields, Enter saves, and
`Ctrl+B` cancels without writing. Metadata supports scope, scope ID, category, importance, tags, and
when-to-use guidance. Saves and deletions are confirmed through fresh Core reads.

The library loads up to 500 visible memories. CLI cross-session consent is host-local and
separate from Desktop.

### Privacy settings

Settings → Privacy shows each consent and support-access control. Up/Down selects a row and its
explanation, Enter changes a choice, and `r` reloads or retries. Use `e` to edit the OTLP endpoint
and Left/Right to choose a support-access duration before you grant access.

Analytics, community statistics, and crash reports are on by default; diagnostics export is off
until you opt in. Changes are confirmed through fresh Core reads, and the support-access expiry is
saved before access is turned on. See [Privacy and Telemetry](/docs/surfaces/desktop/transparency) for what
each setting sends.

### Preference keys

The Privacy and Memory panels read and write these Core preferences through
`GET/PUT /api/preferences/:key`.

| Panel | Preference keys |
|---|---|
| Privacy | `product-analytics-enabled`, `community-stats-enabled`, `profile-activity-enabled`, `crash-reports-enabled`, `diagnostics-export-enabled`, `diagnostics-otlp-endpoint`, `support-access-local-enabled`, `support-access-local-expiry` |
| Memory | `auto-recall-enabled`, `auto-recall-top-k`, `context.max-tokens`, `context.max-output-tokens`, `context.auto-compact`, `skills-disclosure`, `tools.active_ranker`, `context.compact-model`, `context.compact-effort` |

Sensitive-topic consent uses `/api/memory/settings` instead.

### Gateway safety settings

Agent → Gateway → Guardrails edits the node firewall's enabled
state, inbound/outbound scanning, detection logging, PII/secret redaction, policy, and command
approval. Use Up/Down to select a row, Enter to change it, j/k to switch Gateway sections, and r to
reload. Writes require verified access to Agent and are confirmed by a fresh read. Failed saves
retain the same intended change for retry.

Gateway → Advanced safety edits the complete served node firewall, organization and agent
overlay maps, including inspectors, patterns, locks, alerts and evaluator bindings. Inspectors
require an explicit model ID. Select a section with Up/Down, press e to edit its JSON, Enter to
review the full replacement, then y to save or n to return. Omitted overlay IDs are removed;
concurrent changes require reloading. The custom evaluator catalog is read separately and
saving its complete array requires confirmation of a Gateway restart and catalog readback.
Claude, Codex and per-agent egress preferences use the canonical node preferences; changes
apply when the agent next starts. Agents that bypass interception remain direct. Unsupported
or denied sections cannot be edited, and server permissions remain authoritative.

### Read-only panels

**Features**, **Meetings**, **Tasks**, **Storage**, and **Danger Zone** show the node's current
data read-only. Press `r` to reload a read-only panel or retry a failed read. Storage relocation and
destructive data actions stay in Desktop. Billing, Teams, and Credits are managed from your Ryu
account.

## Workspace views

Open views through the command palette, the sidebar, and app contributions. Views use the same Core
contracts as the other clients rather than terminal-only backends.

- **Lists** such as Setup steps, Library, Inbox, Downloads, Store tabs, and plugin list and table
  views fill the available height. Long titles end in `…`, and an `N/M` position line appears when
  not every row fits.
- **Conversation lists** show Core's epoch-millisecond timestamps as UTC calendar dates. A
  timestamp that cannot be displayed leaves the date blank.
- **Services** shows running state, installed services, and installation progress together, and
  refreshes while open.
- **Store** refreshes its sidecar catalog while an installation is in progress.
- **Workflows** shows a run's status. Escape clears the displayed result; it does not cancel the run
  in Core. Switching nodes clears the previous node's workflow selection.

### Confirmations

Destructive and bulk actions ask first: Store → Plugins `D` (uninstall) and `C` (also disable or
uninstall dependents), Store → Apps `D` (uninstall), and Services `A` (start all), `Z` (stop all),
and `D` (uninstall). The confirmation explains what will happen, lists any dependent plugins, and
selects **Cancel** by default. Press `y` to confirm, `n` or `Esc` to cancel, `Enter` to run the
selected button, and `Tab`, `←`/`→`, or `h`/`l` to switch buttons. Nothing is sent until you
confirm. Services `d` installs without a confirmation.
