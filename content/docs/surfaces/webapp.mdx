The browser app is Ryu in a web browser at [ryuhq.com](https://ryuhq.com). It is for people who
want Ryu without installing the desktop app, or who manage their account and organizations on the
web. It reuses the shared Desktop shell, so chats, agents, and Marketplace contributions look the
same, but it has no native windows, tray, file launchers, or app updater.

<Callout type="warn">
The hosted workspace requires a Ryu account that has cleared the waitlist for managed Ryu Cloud
access. There is no anonymous trial while waitlist access is active. Choose **Get Started** to sign
in.
</Callout>

## Sign in and get access

An approved account also needs a passkey or an authenticator app. Until it has one, the browser app
shows **Set up two-factor authentication**, which opens the website's setup page, with **Check
again**. The workspace opens once the factor is in place. See
[Required second factor](/docs/security/authentication-account#required-second-factor).

### Waitlist and invite passes

While you wait for access, enter a six-character code from Ryu or an early member on the waitlist
screen. When the code is accepted, the browser opens Ryu.

A member invite pass unlocks one account and expires at the weekly reset. The sender's invite pass
card changes to **Used** after the recipient redeems it. The Overview refreshes pass status while it
is open.

Invite links load their current status in your browser. A loading message appears while the
pass is checked; if the check is unavailable, refresh the page to retry. Checking a pass does
not redeem it.

### Connect to your own node

Direct `/connect` and the widget's **Local node** option authenticate to Core with that node's
own token, not a Ryu account session, so they stay separate from the signed-in waitlist gate.
Connecting to an existing node does not grant access to the hosted workspace.

## Choose where the work runs

- **Device path.** Direct `/connect` uses the node's own credentials. A signed-in client that opens
  a local Core follows the waitlist rules the Ryu account service sets for that node.
- **Cloud path.** Hosted access is subject to the account's waitlist approval and any plan or usage
  limits.
- **Phone or tablet.** Ryu continues with the hosted browser experience, because mobile browsers
  cannot install and manage a device runtime.

The browser never displays the session bearer. It stores the account session in its local auth vault
and uses it only for authenticated requests. Signing out removes the browser session.

## Explore apps before setup

The public **Apps** page at `/apps` shows curated app previews before sign-in or connecting a
computer. These previews describe the apps and do not execute work. After approved sign-in,
the page lists apps enabled on your node; when no node is connected, the previews remain available
above the connection actions. Opening an actual app at `/apps/[id]` still requires approved access,
node permissions, and any applicable paid services.

## What the browser app adds

The browser app owns browser navigation and browser-safe actions. It can prefer a reachable local
Core or continue with Ryu Cloud. It cannot load native modules or run the mobile `llama.rn` path.

| Capability | Browser behavior |
|---|---|
| Account access | Hosted managed access uses normal account sign-in followed by the server-authoritative waitlist gate and a required second factor |
| Local setup | Direct `/connect` uses the node's credentials; signed-in node access follows the server-selected waitlist scope |
| Cloud access | Use the hosted browser experience after approval |
| Browser actions | Use browser navigation, **Open in new tab**, reload, copy, fullscreen, and external links |
| Opened apps | Can call their own app routes, or another app's with its reviewed grant, when the node is bound to an organization you belong to; see [app requests in the web app](/docs/extend/develop/extensions/desktop-companion-capabilities#in-the-web-app) |
| Native boundaries | Hide Desktop windows, tray settings, native updater, local launchers, and OS-only controls |

Browser surfaces do not show Desktop-only actions such as **Open in new window**, launch-at-login
and tray settings, the native app updater, local editor or file-manager launchers, native
backup/restore controls, or the always-on-top media window. Right-click keeps the browser's normal
context menu instead of the Desktop app menu.

The Webapp, its phone-sized layout, and the browser extension dashboard align their top navigation
to the browser viewport. They do not reserve the macOS traffic-light gutter or the Windows/Linux
caption-button gutter used by Ryu's native Desktop window.

For browser-local model execution and in-page tools, use the [Browser extension](/docs/browser-extension).

## Signed-in workspace

After sign-in, the Web app opens at the workspace overview with a two-row portal header. The first
row places the account controls before the active organization with a `/` separator and omits the
separate Ryu mark. Inbox and Download remain aligned on the right; interaction sounds are in the
account menu. The second row holds the primary
workspace routes in one place: **Overview**, **Apps**, **Servers**, and **Marketplace**. In an
organization view, that row changes to the organization tabs with a **Console** back link.

The overview keeps a simple count row for servers, organizations, and teams, followed by a getting-
started checklist, a desktop-app card, an Explore card, and plan actions. Certifications remain
available from the overview's Explore card and the public Academy navigation.

The signed-in **Inbox** separates all updates into **Invitations**, **Marketing**, and
**Transactional** categories. Open an item’s action or invitation list link, mark one item read, or
mark all items in the current category read. Read state persists to the account. **Refresh inbox**
reloads the selected view. If the inbox is unavailable, the page shows an error and keeps the
caught-up message hidden until the next successful read.

In **Chat**, the first available agent is selected automatically. Choose another agent or clear the
selection; message composition stays disabled while no agent is available. **Enter** sends a
message, **Shift+Enter** adds a line, and the **Double-check** switch controls the extra review turn.
Conversation history rows work with keyboard selection, and each row’s actions menu can delete that
conversation.

A chat can also include a **Space**: choose one before messaging, or use **Clear selection** to leave
it unattached. If the spaces list cannot be loaded, select **Retry loading spaces** to fetch it again.

Code blocks in chat have a **Copy code** action. If the browser denies clipboard access, the
message stays visible and you can try again; a successful copy clears the error. On phones,
**Open sidebar** shows conversation history. Selecting a conversation closes the sidebar, or
you can dismiss it by tapping the backdrop.


**Settings** on the web uses the desktop app's Settings layout: a sidebar with a search box and
grouped sections (Profile, Stats, Account; Preferences; Security), and links to the active
organization's settings and billing. Each section has its own address (for example
`/settings?tab=sessions`), and search finds individual settings such as **Passkeys** or
**Two-factor authentication**.

## Notifications

The web app can show browser notifications when an agent replies, needs approval, or finishes a run,
with the sending agent's avatar as the notification icon. Onboarding asks for permission from a
button, and **Settings → Privacy → Device permissions → Notifications** turns them on or off for
this browser. The web app installs a small service worker that only shows notifications and
handles their clicks; it does not cache pages or intercept requests. Notifications therefore keep
working after you close the tab, and work in phone browsers too: Chrome on Android asks for
permission directly, and on iPhone and iPad you first add Ryu to the Home Screen (**Share → Add to
Home Screen**) and open it from there. For background alerts on a phone when Ryu isn't open, use the
[Ryu mobile app](/docs/mobile/native-surfaces).

## Interaction sounds

The browser app gives selected controls a quiet, synthesized sound cue for navigation, buttons, and
toggles. Cues are generated locally with the Web Audio API: no audio
files are downloaded and no sound data leaves the browser. Playback starts only after a user
interaction. In the signed-in workspace, open the account menu and toggle **Interaction sounds**;
the public-site footer keeps its speaker button. The choice is kept in the browser on the current
device.

## Marketplace on the web

Marketplace search remains available beside the toolbar, and the toolbar wraps on
narrow screens. Use the global search to find listings across catalogs, or open
the search control inside a catalog to narrow that catalog alone. If a federated
catalog is temporarily unavailable, change or clear the search to try again.

**Open in Ryu** and bundle **Install** actions hand the selected destination to
the installed Ryu app. The browser does not complete a native
installation. A paid listing opens Ryu's checkout page after sign-in; a failed
checkout request can be retried. Returning without purchasing leaves the listing
available to buy and does not create an owned license.

The web Marketplace exposes public publisher organizations in its **Marketplaces** tab. A signed-in
visitor can choose **Follow** on a publisher or a listing’s publisher row, then use the persistent
**Following** filter beside the search field in every Marketplace tab. The filter is reflected in the
URL as `?following=1`, so a filtered catalog can be bookmarked or shared. **Open in Ryu** still
hands installation to Ryu; the web app does not claim that a node install completed.
