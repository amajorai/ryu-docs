---
title: "Browser app"
description: "Use Ryu in a browser without creating an account, with an optional local Core runtime for computers."
---

The browser app is the lowest-friction way to try Ryu. Choose **Try Ryu without an account** and
Ryu creates an anonymous session for that browser. No email, password, or desktop app download is
required.

## Choose where the work runs

- **Browser path.** Continue as a guest and use the hosted browser experience. This removes
  account setup, but it does not make hosted model usage free.
- **Computer path.** On a computer, choose **Download Ryu Core for this computer** to get the
  standalone Core binary. It is the real local runtime, not a demo node and not the desktop app.
  Download it from [the Core download page](https://ryuhq.com/download/core), run it locally, and
  connect it from the browser app's node selector. Core remains authenticated by default; the
  browser never reads or displays the node token.
- **Phone or tablet.** The browser path remains available, but the local Core download is not
  offered because a browser cannot install and manage a computer runtime on iOS or Android.

The browser never displays the session bearer. It stores the session in its local auth vault and
uses it only for authenticated requests. Signing out removes the anonymous session; a later
account sign-in uses the normal Better Auth flow.

## Browser extension

The browser-specific extension prompt is intentionally not shown until the extension's public
release is available. Once it is released, the browser app can offer the matching store link for
the visitor's browser.

## App-like navigation

Ryu's browser app uses app-style navigation for public pages. Links stay in the current browser
session, reusable route UI can arrive before the click, and pages with live data show a matching
loading shell while that data streams in. This keeps navigation responsive without moving the
page's server-rendered content into the browser.

The experience applies to the blog, help center, changelog, marketplace, and other content
surfaces. Cached route UI can be reused across visits, while request-specific data still loads for
the destination. Search, filters, sign-in, and downloads keep their existing behavior.
