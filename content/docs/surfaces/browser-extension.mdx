The browser extension brings Ryu into the browser's toolbar, new-tab page, and active pages. It
shares the familiar chat and agent controls with the other Ryu clients, then adds browser-local
inference and permissioned browser tools.

## What the extension adds

The extension owns browser entry points and browser-only runtime behavior:

| Capability | Browser extension behavior |
|---|---|
| Browser-local inference | Run text generation with Transformers.js inside the extension runtime, using WebGPU first and WASM as the fallback |
| Browser model storage | Cache model files in the browser with the Cache API; browser-local turns do not call Core for inference |
| In-page copilot | Read a bounded page context and offer typed actions through a consent-gated browser tool registry |
| Browser entry points | Use the popup, dashboard, New Tab, Ask Ryu, in-page copilot, page saving, tabs, screenshots, downloads, and the `ryu` omnibox keyword |
| Shared Ryu work | Connect to Core or Cloud for normal turns, agents, conversations, services, and settings |

The extension never exposes arbitrary JavaScript evaluation, cookies, hidden credentials, or
extension storage to browser tools. Page changes, navigation, downloads, uploads, clipboard access,
and page saving require the matching approval.

## Browser-local models

Choose the **Browser** provider in an extension model picker. The selection is remembered per agent
and browser entry point. Curated models and compatible Hugging Face model IDs load through
Transformers.js in the extension worker or offscreen runtime.

WebGPU is preferred when the browser supports it. The runtime falls back to WebAssembly (WASM) when
WebGPU cannot load the model. The model remains in the browser cache, and the extension reports
preparation progress before it starts a local turn.

Browser-local inference is separate from the mobile `llama.rn` path and from Core-hosted inference.
The extension can send a bounded transcript and source metadata back to Core when you choose to link
the local turn, but it does not upload the full page body, DOM index, screenshot, or raw tool result.

The public website uses the same reviewed browser model contract in its **Ask Ryu** widget. A visitor
can explicitly download the small ONNX model and ask documentation questions in the tab without an
account. The widget also exposes a separate **My local node** mode: after the visitor enters a node
address and token, the browser calls that node directly and sends non-persistent chat turns through
Core's normal stream. The browser-local path never silently upgrades to the node path, and the node
token never goes through the Ryu control plane.

## Browser tools and permissions

Browser tools use the active tab's indexed DOM and accessibility state. Action-capable models can
request typed operations, but the extension checks the operation, the page context, and the current
grant before it changes a page or causes an external effect.

The host feature-detects browser notifications and other browser capabilities. It does not pretend
to provide mobile haptics, Live Activities, or Dynamic Island. See [Native bridges](/docs/extend/develop/extensions/native-bridges)
for the shared host contract.
