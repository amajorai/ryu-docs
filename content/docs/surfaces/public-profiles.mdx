---
title: Public Profiles and Agents
description: How public Ryu profiles work, what they show, and how to publish a limited public agent and embed it on another site.
---

A public profile is a page at `https://ryuhq.com/u/<username>` that shows your bio, links, a
project showcase, and the activity sections you choose. You manage it from the
[browser app](/docs/surfaces/webapp) or Desktop. You can hide individual sections or make the whole
profile private.

## Profile contents

The profile shows the owner's display name, joined month, level, headline usage totals, and
privacy-safe verification signals. A compact activity card shows a year of Ryu request activity in
a Sunday-to-Saturday contribution grid, with hover details for individual days. The card is built
from Ryu usage data, not a linked GitHub account. Usage totals include requests through a hosted
Gateway and the daily totals that desktop devices with a local Gateway send with their profile
activity signal. Days without a recorded request stay empty.

Open **Settings → Profile → Public profile** to add a short bio, up to eight HTTPS links, and up to
twelve showcase items with an optional HTTPS cover image. The profile can show or hide activity,
usage totals, model usage, plugin usage, showcase, and public agents independently. Public profile
reads include only the enabled sections. Spend, points, session counts, email addresses, and
private agent configuration are not part of the public projection. A private profile is removed
from the public route, including its activity and annual Wrapped projection.

## Share a public profile

**Share profile** on a public profile opens a card with your name, handle, and joined month. If
usage totals are public, the card also shows your current streak, lifetime tokens, requests, agent
hours, and longest streak. Copy or download the card as an image, save it as a video or GIF, or post
the profile link to X or LinkedIn. **Copy link** copies the profile URL. A shared profile link shows
a preview image built from the same public sections; a private profile has no preview image with
its details.

### Streaks

A profile's **Current streak** is the number of consecutive UTC days with any Ryu activity on that
account, and **Longest streak** is the best run so far. A streak day is any UTC day on which you used
Ryu, including agent runs, even ones started by a schedule, a workflow, or a channel, and Ryu Cloud
managed agents. The built-in [Patrol](/docs/surfaces/desktop/user-guide/agents#patrol-watches-your-setup) health and security bot does not count, so a streak means you (or an
agent working for you) used Ryu, not only that Ryu was running. If a whole UTC day passes with no
activity, the current streak resets to zero; the longest streak is kept. The activity marker from
Desktop adds nothing to token or request totals by itself.

When the device's Gateway does not report
usage to Ryu Cloud, the same signal carries that device's daily usage totals, which count toward
your profile totals and heatmap but never earn points. A day with only that activity earns no
points, including no streak bonus. In your own Stats
**Daily activity** heatmap, such a day shows at the lightest shade rather than empty. See
[Transparency](/docs/surfaces/desktop/transparency) to turn that signal off.

## Profile banner

Choose a Marketplace wallpaper in desktop **Settings → Profile → Profile banner** to add a shared
banner on the active node. Devices connected to that node share the choice, and its public profile
copy stays in sync so visitors can see it at `/u/<username>`. The selection is also added to this
device's Wallpaper Library. Clearing the selection removes the public banner.

If the public profile update fails after the node saves your banner, the node choice stays active
and **Retry public profile sync** retries the account copy. Pending saves stay with the account and
node where they started. Switching accounts or nodes does not publish that choice under the new
account or replace the new node's preview.

Your annual Wrapped card follows the same choices. If you hide **Usage stats**, the card leaves out token totals, agent hours, streaks, and XP. If you hide **Models**, it leaves out your top model. Your points balance is never shown on a public profile or Wrapped card.

## Publish an agent

Open **Settings → Profile → Public agents**. Create a draft, choose its runtime, then publish it. A public agent appears only while the account profile is public, the profile's **Agents** section is enabled, and the agent status is published. Paused and suspended agents are not listed.

You can publish:

- **Visitor browser model.** The owner explicitly consents to sharing the prompt. The visitor's browser runs it locally; the public prompt is visible in the agent detail response.
- **Owner-sponsored model.** Ryu runs turns on a low-cost hosted model through the Ryu Gateway, which screens each turn with Ryu's platform safety floor. The owner sets a monthly run cap. This cap counts admitted requests, not dollars.
- **Ryu Core agent.** The owner supplies an HTTPS A2A endpoint and a principal bound to one published agent. The server stores the bearer token encrypted and never returns it to visitors. Each turn narrows the principal's tool grant to the profile's selected capabilities, the Core agent's own allowlist, and tools marked read-only by Core. Mutating tools stay off, and an agent on Ryu's managed engine also runs without that engine's own shell and file tools. Tool-enabled runs require a healthy Gateway-backed Core route.

Visitors do not need a Ryu account to open a public agent. Browser-local turns stay in that browser. Hosted turns send the current turn and bounded transcript context to the hosted model. Core-backed turns are processed by the owner's Core node and follow that node's task-retention policy.

## Budgets and abuse controls

Hosted and Core-backed agents have an owner-selected monthly request cap and a per-network rolling rate limit. A request whose network address cannot be verified is refused rather than sharing one limit with other visitors. Successful admission is idempotent, so retrying the same turn does not start a second run. A failed upstream call still uses an admitted run. These controls limit run volume; they do not set a currency budget. Gateway budgets and firewall rules remain the spend and egress controls for Gateway-backed Core tools.

Ryu rejects selected high-confidence credential-theft, impersonation, and malware instructions at publish time. Visitors can report spam, scams, impersonation, malware, unsafe content, or other issues. Reports accept a category only, not arbitrary prompt text. This screening is not a guarantee that every harmful agent will be detected. Owners can pause an agent at any time.

Visitor-local, hosted, and Core-backed replies are replaced when high-confidence checks detect requests for passwords, verification codes, payment details, wallet keys, or recovery phrases. A hosted turn the Gateway's safety screen refuses returns a short refusal without the screen's reasons.

Read-only does not mean public: an allowed tool can still return private files, account data, or memory. Only grant sources intended for anonymous visitors.

## Embed an agent

Select a published agent in **Settings → Profile → Public agents** and copy its iframe snippet. The hosted embed uses `https://ryuhq.com/embed/agents/<username>/<slug>`, runs without the surrounding Ryu site navigation, and keeps the frame sandboxed. Do not remove the sandbox attributes when adapting the snippet.

The shareable profile URL is `/u/<username>`. Username subdomains such as `username.ryuhq.com` are not enabled.
