The public website is the part of [ryuhq.com](https://ryuhq.com) that works without a Ryu account.
For the signed-in workspace, see [Browser App](/docs/surfaces/webapp).

## Explore apps before setup

The public **Apps** page at `/apps` shows curated app previews before sign-in or connecting a
computer. These previews describe the apps and do not execute work. After approved sign-in,
the page lists apps enabled on your node; when no node is connected, the previews remain available
above the connection actions. Opening an actual app at `/apps/[id]` still requires approved access,
node permissions, and any applicable paid services.

The public homepage also shows an illustrative sample workspace on desktop and mobile before
its download and setup actions. Sample content is not a generated result and uses no credits.

The interactive preview uses the same Bot-mode reading as the desktop app: **Agents** are the
primary sidebar section, each agent row shows its latest message, and its direct threads appear
inline underneath. Group and fallback chats remain available below the roster without a separate
Sessions tab.
Switching use cases morphs the running preview into the selected workflow at its current phase.

## Landing page and navigation

The public landing page has **Download** and **Set up Ryu for me** actions. Its product previews
are samples. They do not show live account state or deploy a server. Compute and Share previews
show early-access selection boundaries, not completed leases or published capacity. Blog,
Changelog, and Help open directly into their filters, search, and entries. The
[pricing page](https://ryuhq.com/pricing) has plan cards and a monthly or yearly billing selector.

The [Challenges page](https://ryuhq.com/challenges) lists published challenges, hackathons, and
events from the Ryu service. A signed-in member can register with their account, submit a project,
and review their own entry status. Administrators review submissions and can award Ryu Points from
the control plane; the browser does not invent participation, submissions, or awards locally.

On desktop, Products and Resources share one hover-activated surface. Challenges is grouped under
Resources, while Marketplace remains a direct top-level link.

On phone-sized public pages, the bottom navigation mirrors the desktop header: **Products** and **Resources** on the left,
a raised **Download** button in the center, and **Marketplace** and **Account** on the right. The
logo at the top of the page goes home, and **Enterprise** stays in the top bar. **Products** and
**Resources** open focus-managed sheets and close on Escape, the close button, the backdrop, or
destination selection. **Marketplace** and **Download** expose current-page state to assistive
technology. Signed-out visitors see **Sign in** in the **Account** slot; signed-in users see their
avatar, which opens the same menu for profile, invitations, settings, plan actions, theme, account
switching, and sign-out. In the signed-in workspace, account controls stay in the portal header
beside the separate organization switcher.

Ryu's browser app uses app-style navigation for public pages. Links stay in the current browser
session, route UI can be prefetched before the click, and pages with live data show a loading shell
while that data streams in. Page content stays server-rendered.

The experience applies to the blog, help center, changelog, marketplace, and other content
surfaces. Cached route UI can be reused across visits, while request-specific data still loads for
the destination. Search, filters, sign-in, and downloads keep their existing behavior.

## Get the other Ryu apps

The signed-in account menu, on the website and in the browser app, has a **Get Ryu apps** submenu.
It links to the [download page](https://ryuhq.com/download) sections for the desktop app and the
browser extension. The mobile app is listed only when it can be installed from an app store.

## Help Center

The web Help Center groups published articles by category. Selecting a category
shows its articles. Reloading a category page keeps that selection. Choose **All Articles** to return to the full
list, then open an article to read its guide.

On a narrow screen, scroll the category strip horizontally to reach more
categories.

Use **Back to Help** on a category page to return to the full list. On wider
screens, an article can also show related articles from its category; select a
related title to open that guide.

## Recover from an unexpected website error

If a website page shows **Something went wrong**, choose **Try again** to fetch
fresh page data and render the page again. A temporary data or rendering failure
can recover without navigating away from the page.

If the error affects the whole website shell, **Try again** reloads the document
so the shell and page can initialize again. If the error persists, return to the
page later or share the details with support.

## Enterprise page and theme

The public Enterprise page is available from the website header on desktop and mobile. It describes organization identity, execution permissions, Gateway governance, and audit controls, with links to their documentation. **Talk to sales** opens an addressed email inquiry; it does not create an account or send an email automatically.

The website theme control switches between light and dark appearance and remembers your selection.

## Ask Ryu on the public site

The public site and these docs include an **Ask Ryu** widget as a small, working example of a
visitor-facing AI surface. Choose its runtime from the settings button in the widget's header:

- **Browser** downloads the reviewed `SmolLM2 135M` ONNX artifact once, caches it in the
  browser, and runs the answer with Transformers.js using WebGPU or WASM. No account is required,
  and the question stays in the tab.
- **Ryu guest** sends the question, without page context, through the site to Ryu's hosted
  Gateway, which screens it for safety and applies guest limits. No API key is required, and the
  site picks the model.
- **Local node** connects directly to a running Ryu Core server after you provide its address and
  server token. The browser sends the question to that server's `/api/chat/stream` endpoint; the Ryu
  website does not proxy or store the token, and visitor turns use `persist: false`.

Choose **Local node** in the widget and fill in the connection form that appears in its composer,
or open the dedicated [`/connect` route](https://ryuhq.com/connect). Loopback addresses are the default. A LAN or remote
address requires an explicit trust confirmation, and Core must allow the site's origin through its
CORS configuration. This is a browser bridge, not a silent account registration or a replacement
for Core's server authentication.

The widget grounds public answers against a small, auditable documentation index and links to the
source page. It is separate from the authenticated browser app. A visitor can try the local model
without creating a cloud session, then choose a running server to use Ryu's configured agent and
Gateway policy.
