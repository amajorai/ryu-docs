---
title: Audio, Voice Recognition, and Speech Processing Engines
description: Reference for the engines that recognize speech, clean up transcripts, and generate spoken replies, with their settings and fallbacks.
---

Voice Recognition turns audio into text. Speech Processing optionally cleans up that transcript.
Audio engines generate spoken replies. These engines run alongside the active Chat engine, not
instead of it.

## Engines

| Engine | Capability |
|---|---|
| `whispercpp` | Local Voice Recognition using whisper.cpp. The prebuilt server is Windows-only; on macOS and Linux, place your own `whisper-server` build in the engine folder or use Parakeet. |
| `parakeet` | In-process local Voice Recognition using Parakeet. |
| `audiocpp` | Local Voice Recognition and speech generation through audio.cpp. macOS, Linux x86_64, or Windows x64. |
| `outetts` | Built-in local speech generation using OuteTTS. |
| `ryutts` | Ryu Audio, a registry of local speech-generation engines and voices. |
| `gateway` | Speech Recognition routed through the configured Gateway provider. |
| `s1-mini` | Local Speech Processing that cleans up recognized text. |

Open **Library → Engines** to configure a Voice Recognition or Audio runtime from its card.
**Store → Engines** offers the same controls next to installation. The connected node determines
which engines are available.

## Voice Recognition

**Settings → Voice Recognition** and **Read back responses** save to the node selected for that tab.
When you switch nodes or credentials, Ryu loads that node's saved preferences before you can edit
them. If loading fails, use **Retry**. Ryu does not write defaults over the saved configuration. A
refused save keeps the previous selection and offers **Retry** for the same change. A save already
sent to the previous node can finish there, but it does not change the newly selected node's
controls.

The whisper.cpp detail page exposes language, translation, temperature, best-of, beam size, prompt,
context controls, extra multipart fields, thread count, and additional server flags. These settings
are shared by transcription callers that select whisper.cpp.

The audio.cpp detail page exposes language, temperature, prompt, additional request fields, plus its
backend, device, thread count, and maximum loaded models. The current adapter sends language,
temperature, prompt, and additional fields; other Whisper-specific typed options remain saved but
are not sent. Runtime hardware settings take effect when the audio.cpp service restarts.

Transcription requests go to `POST /api/voice/transcribe`. The request is a multipart form with the
audio bytes in a `file` field, and the response contains the transcribed `text`. The `engine` query
parameter selects the voice engine. Without it, Core uses the in-process Parakeet engine.
Parakeet accepts PCM integer WAVs (8/16/24/32-bit), 32-bit float WAVs, any sample rate, and any
channel count. Core downmixes and linearly resamples those inputs to the model's required 16 kHz
mono PCM before inference. Input and normalized WAV output are each limited to 32 MiB, and
recordings must be no longer than two hours. Inputs that would exceed the normalized sample budget
are rejected before resampling. The desktop recorder emits the normalized format.

<Callout type="warn">
  Ryu saves profiles for Parakeet and Gateway Speech Recognition, but their Core adapters do not use
  those custom request options yet. The engine pages label this limit beside the controls, and the
  default behavior stays in effect.
</Callout>

## Speech Processing

S1-mini by Superwhisper is Ryu's local transcript-cleanup engine. Open the llama.cpp engine detail
page and choose **Speech Processing defaults** to configure its engine, style, structure, and
context. These node-wide preferences are shared with the Speech Processing layer on the
**Voice & sandbox** page of the expanded node selector and with Dictation settings. They are
separate from Chat sampling.

Keep the full name **S1-mini by Superwhisper** when referring to the model and retain its
[upstream license](https://huggingface.co/superwhisper/s1-mini-GGUF/blob/main/LICENSE).

Dictation can run Speech Processing after Voice Recognition. See the
[Dictation guide](/docs/apps/dictation) for its transcript-cleanup setting.

## Audio

Open **Library → Engines → Ryu Audio**, **Store → Engines → Ryu Audio**, or **Settings → Audio** to
choose the default speech-generation engine and voice and play a test. All three share the same
desktop preferences. The engine list
reflects the built-in OuteTTS path, audio.cpp, and the local Ryu Audio registry when available.

Model installation and runtime start failures appear beside the Audio controls. If a model
inventory refresh fails, previously confirmed models stay visible, and **Retry** reloads the
inventory without repeating an installation. Runtime status is **Unknown** when the node cannot
confirm it. Start, stop, restart, and uninstall controls wait for a successful status refresh. The
Store's **Running** badge also waits for confirmed status. Switching nodes or credentials loads the
newly selected node's state.

Generation options are saved separately for each selected speech engine:

| Engine | Settings Ryu sends |
|---|---|
| Ryu Audio engines | Voice, speed, supported language, and reference audio for engines that advertise cloning. |
| audio.cpp | Voice, speed, language, and a reference sample when the runtime supports it. Hardware settings are on its engine detail page. |
| Gateway | Voice and speed when supported by the provider. The provider controls language. |
| OuteTTS | Uses its bundled model voice; speed, language, and cloning overrides are not supported by this adapter. |

If the node's default Ryu Audio engine or the cloud engine is unreachable or fails to render,
read-aloud falls back to OuteTTS so speech still plays. Read-aloud that names a different engine,
uses a voice sample, or sets a studio control reports the error instead, because OuteTTS would
not honor that request. Voice mode falls back to OuteTTS for whichever engine it uses, so a live
call does not go silent mid-sentence. In both cases, an engine id that Ryu Audio does not recognize
returns a `tts_engine_unknown` error instead of a fallback.

Speaking speed is a multiplier from `0.25` to `4`. Ryu ignores a saved value outside that range. A
reference audio path points to a voice sample managed by the connected node.

Ryu Audio supports multiple registered engines and voices. Install or start the relevant runtime
from **Store → Engines**, then choose its speech engine in the Audio settings. Language and voice
choices come from the selected engine. A cloning-capable engine can use a reference WAV managed by
the connected node.

OuteTTS runs locally through the built-in runtime. audio.cpp and the Ryu Audio backends expose
additional local generation engines; cloning support depends on the selected engine. See the
[OuteTTS project](https://github.com/edwko/OuteTTS),
[audio.cpp project](https://github.com/0xShug0/audio.cpp), and
[Ryu Voice app](/docs/apps/voice) for engine and model details.
