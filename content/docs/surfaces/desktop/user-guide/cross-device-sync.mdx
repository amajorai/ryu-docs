title: "Cross-Device Sync"
description: "How to sync chats and editable Spaces documents between nodes through your account, what stays local, and how Settings Sync moves desktop preferences between machines"
---

Cross-device sync mirrors chats and editable Spaces documents through an authenticated account
service so another configured node can read them. This is server-backed sync, not automatic
transfer between nearby devices over Bluetooth.

<Callout type="warn">
  Cross-device sync is **off by default**. Turn it on separately on each node. A node operator can
  override the choice, so an off switch alone does not prove sync is disabled on that node.
</Callout>

## Enable sync for a node

1. Sign in on the node. A signed-out node pauses syncing even if its switch is on.
2. Open the node selector, choose **Gateway settings**, then open **Connect → Connections**.
3. In **Cross-device sync**, turn on **Sync my chats and Spaces across devices**.
4. Configure the other node for the same account and service.
5. Check that a small test conversation or document arrives before you depend on sync.

The choice takes effect without restarting Core. If saving fails, the switch returns to its previous
saved value and shows an error. Retry after the node connection is back.

The switch belongs to the active node, not to the account, so changing accounts does not create a
separate sync preference. Switching nodes or accounts reads that connection's current setting. A
save already sent to the previous connection can still finish on its node, but it does not change
the switch or show an error for the new connection. A delayed read does not replace a newer saved
choice.

## What syncs

The mirror includes:

- chats and their messages;
- editable Spaces pages, databases, whiteboards, and app-owned documents;
- stable Space and document identities, so links point to the same page on each node.

Messages merge by their stable identity. When two nodes change the same document independently,
the most recent edit wins. The account service encrypts stored content at rest.

After a successful upload, unchanged conversations are skipped on later checks. A change to message
text, including a reply saved while it streams, makes the conversation eligible for upload again.
Failed uploads are retried. Switching the server or signed-in account starts a fresh mirror check.

## Edited chats and versions

Editing or regenerating a message keeps each version of the chat. Sync records which message each
synced message replies to, so new messages from another node join the version you have selected
when they continue it. If this node already has newer messages after the point where the other node
continued, the synced messages appear as another version of that message. Your selected version
stays in place, and the version arrows switch between them. Messages from a chat that was never
edited, or from a node running an earlier Ryu release, are added after your selected version.

## What stays on the node

Binary file attachments, downloaded models, engine binaries, long-term memory, and local app setup
do not sync. Credentials, installed runtimes, and tool permissions also need their own setup on each
node, so a synced chat does not make two nodes identical execution environments. Use the
[full-data zip](/docs/surfaces/desktop/user-guide/data-and-storage#back-up-by-exporting-an-encrypted-zip) to
move everything, and see [Chat with a local model](/docs/learn/cookbook/chat-with-a-local-model)
for local inference setup.

Keep sync off when your work requires local-only content, and check the effective node
configuration with its operator.

To browse the chats stored on each of your computers without syncing them, use the **All
computers** sidebar mode in [Sidebar and chat controls](/docs/surfaces/desktop/user-guide/chat-sidebar-controls#see-chats-from-every-computer).

<Callout type="info">
Cross-device sync and live collaboration solve different problems. The mirror moves durable data
between nodes. When two clients open the same node, realtime rooms deliver chat updates, presence,
shared app changes, and document edits immediately.
</Callout>

## Desktop settings sync

**Settings → Settings Sync** syncs supported desktop preferences between machines signed in to the
same Ryu account. It is separate from the node data mirror above.

- It is off until you turn on **Sync My Settings Across Machines**.
- Local changes upload about 60 seconds after you stop editing. Choose **Sync now** to send them
  sooner.
- **What Gets Synced** lists the portable preferences. Node and Gateway configuration, API keys,
  workspace folders, and device-specific selections stay on their machine.
- When the same setting changes on two machines, **Ask me every time** lets you choose the local or
  cloud value, and both values stay on their machines until you decide. **Always keep this
  machine's copy** uploads the local value with a newer timestamp. Set the default in
  **Conflict Handling**.
- **Delete cloud copy** asks you to confirm, then removes the account's remote copy. Settings on
  this machine do not change.

The status row shows when sync is up to date, running, offline, or waiting for a conflict decision.
**Up to date** and the success message for **Sync now** appear only after every pending change is
accepted. A setting you edit while an earlier upload is finishing stays pending until its newer
value is accepted. When local storage is available, pending settings survive closing and reopening
Desktop.

Sync stays incomplete, and your saved values stay in place, in these cases:

| Case | What to do |
|---|---|
| Core cannot save downloaded keyboard shortcuts | Use **Sync now** after the connection recovers |
| Local storage is full or unavailable (status **Sync incomplete**) | Free local storage space, then use **Sync now** |
| A saved custom theme collection is larger than 128 KiB | Reduce the collection, then use **Sync now** |

Turning settings sync off stops a cloud response that is still arriving from changing local
settings or starting an upload. If you change the selected Core node while a sync is pending, use
**Sync now** to download shortcuts to the new node.

### Switch accounts

Synced settings belong to the account that made them.

- When you switch accounts, Desktop sets the previous account's settings and pending changes aside
  and loads the new account's settings. Pending changes upload only after you switch back to the
  account that made them. They are never saved in another account's cloud copy.
- Every other open Desktop window reloads to show the new account's settings. A change made in a
  window before it reloads is discarded, so make it again after the reload.
- **Delete cloud copy** removes the copy of the account that was active when you opened the
  confirmation. If the active account changes before you confirm, nothing is deleted.
- If Desktop cannot yet confirm which account a new sign-in belongs to (for example, while
  offline), settings sync pauses. Nothing uploads or downloads until the account is confirmed, and
  settings you change during the pause are discarded when that account's settings load.
- Signing an account out removes the settings Desktop kept for it. The next account that signs in
  does not adopt settings changed after the sign-out.

### Keyboard shortcuts

The Core node keeps one set of shortcuts for everyone who signs in on it. Switching accounts does
not change the shortcuts in effect until the new account's synced shortcuts download.

- Sync uploads only the shortcuts you change yourself. Each edit adds just the changed shortcuts to
  your account's synced set, even when the node shows shortcuts another account set.
- A shortcut edit belongs to the account that was signed in when you made it.
- Shortcut edits made while sync is off upload when you turn it on.
- Shortcuts already on the node that you have not changed (for example, ones set by another app
  connected to the node) are not uploaded. Change one once to add it to your synced set.

### After upgrading from an earlier Desktop

Earlier versions did not keep settings per account.

- The settings on screen stay with the account that is signed in. Changes the earlier version had
  not uploaded are not uploaded, because it could not tell which account made them.
- Desktop does not upload the shortcut copy it kept earlier, because it may include another
  account's shortcuts. Your next shortcut edit is added after Desktop reads your synced set from the
  cloud.
- If more than one account was signed in at the upgrade, sidebar sections, saved split layouts, and
  custom themes are not kept for any account. Each account downloads its own cloud copy of them.
