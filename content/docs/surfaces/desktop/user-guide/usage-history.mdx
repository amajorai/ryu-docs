---
title: Usage History
description: Import retained token metadata from coding tools and provider reports, including history from before you installed Ryu.
---

Open **Settings → Usage**, then **Usage history**, to review saved usage from before and after you
installed Ryu. The page shows tokens, an estimated API-equivalent cost, cache savings, daily usage by
source, models, and session counts where session identities are available.

<Callout type="info">
  An API estimate is the value of recorded tokens at model API rates. It is not your subscription
  bill. Source-reported costs appear separately, and a tool may report its own estimate rather than
  a charge.
</Callout>

## Import local history

1. Under **Import on this node**, select the sources you want to read.
2. Choose **Import history**. Ryu reads saved usage metadata on the connected node.
3. Review the imported, duplicate, skipped, and error counts. If the scan reaches its batch limit,
   choose **Continue import**. After correcting an inaccessible or malformed source, choose
   **Retry failed files**.

Local imports run in the background on the connected node. Closing **Usage** leaves the import
running, and starting the same selection again reconnects to it. If the node restarts or an import
fails, repeat that selection to resume from saved checkpoints.

You can repeat an import. Unchanged files are skipped, recorded events are deduplicated, and changed
records can update existing entries. Importing on a remote node reads that node's history, not your
laptop's.

| Local source | Retained history |
| --- | --- |
| Codex | Session and archived-session token events |
| Claude Code | Assistant usage in project and transcript files |
| OpenCode | SQLite history and legacy JSON messages |
| Gemini CLI | Saved chat usage counters |
| Pi and Oh My Pi | Assistant usage in agent session files |
| Senpi | Retained agent session usage |
| Qwen CLI | Assistant usage in project histories |
| Kimi CLI | Retained session usage |
| Amp | Saved usage-ledger events |
| Goose | Saved session token aggregates; daily attribution can use the session timestamp |
| OpenClaw | Retained agent session usage |
| Grok Build | Completed-turn events with saved token categories and event timestamps; total-only legacy events are skipped |
| Droid | Saved session token aggregates, dated by the last retained assistant event; daily totals do not reconstruct individual turns |
| Zed | Saved first-party hosted thread token aggregates, dated by the thread update time; imported and external ACP threads are excluded |
| Antigravity | Retained token metadata in an existing Tokscale sync cache; Ryu does not perform the upstream sync |
| Cline, Roo Code and Kilo | Usage counters in saved editor task histories |
| Copilot CLI | Retained telemetry usage records where token counters were exported |
| Ryu saved sessions | Completed ACP usage parts already retained in Ryu chats |

If a tool uses a different location, use **Custom location or provider metadata export**, select its
format, and provide an absolute path on the connected node. A directory or file must contain a
supported history format. Ryu does not infer tokens from conversation text.

Antigravity requires an existing metadata cache created by Tokscale. Undated records are skipped,
and cache-creation tokens remain unknown because that export does not measure them.

### Track future ACP usage

Enable **Track future ACP usage** to record supported completed-turn usage going forward. This
setting is opt-in and does not recreate records that were never saved. ACP context-window meters
describe current context occupancy and are not added as historical token consumption.

### How overlapping records stay separate

Saved Ryu sessions can contribute completed-turn counters retained before you enabled future
tracking. Their importer reads usage metadata without decrypting message bodies. A saved turn with a
native session binding retains that identity. Shared source and event IDs deduplicate repeated
records. A native session ID alone does not prove that an imported file contains every live turn.
Saved turns without usage counters stay absent from token totals.

When native history exists for a session but its turn IDs cannot be matched to Ryu's live turns,
**Unreconciled live usage** retains those live counters separately. Their session identity remains
known. Only their overlap is unresolved. This includes newer live turns because a partial file
cannot prove its coverage. Session history excludes this subtotal. Do not add the two views together
without resolving the event identities.

When a provider account identity was captured, Ryu retains it with the turn and keeps records from
different known accounts separate. Native CLI files often lack an account identity, and Ryu leaves
it unknown. Such a file may overlap a live turn with a known account in the same native session, so
that uncertainty also stays in Unreconciled live usage. Matching token counts or timestamps does not
prove that two records are the same turn.

Older Ryu usage without a retained native session identity appears in **Unattributed usage**. These
measured counters may overlap with a tool's native history, so they stay out of **Session history**.
A known Ryu conversation can retain its identity, but a turn ID alone does not become a session
count.

Some Codex cumulative snapshots include counters from before the retained per-turn history. Ryu also
keeps these in **Unattributed usage**. Their dates describe when the snapshot was observed, not when
its tokens were consumed, and the model can be unknown. Do not add this view to session totals
without resolving the missing provenance.

## Keep accounting scopes separate

Choose **Session history**, **Account reports**, **Organization reports**, **Unattributed usage**,
or **Unreconciled live usage**. Each view has its own totals. Account and organization reports can
overlap with local sessions, so Ryu does not add them to session history automatically. Unattributed
counters remain separate because their original session or consumption details were not retained.
Unreconciled live counters retain their known session identity but remain separate because their
overlap with native history is unresolved.

Use **All time**, **30 days**, or **7 days** and the source filter to narrow the view. Daily charts
and model breakdowns use the selected scope and sources. In **Daily usage by source**, choose **By
source** or **All sources**. With **Forecast** on, each line continues as a dashed 14-day projection
from its recent trend. **All sources** also shows an 80% range. Days without records count as zero
usage. Today is projected rather than fitted because it is still in progress. **Unattributed usage**
is never forecast because its dates record when a snapshot was observed. Organization cost reports
contain monetary buckets and may have no tokens or sessions. A request count is not a session count.

## Import provider reports

Use **Custom location or provider metadata export** for a saved report. Provide a stable **Account
alias** for provider exports. Reuse the same alias when importing more pages or a refreshed export
from that account. Use a different alias for a different account or organization. The alias
separates identities. It is not a credential.

| Report format | Imported metadata |
| --- | --- |
| OpenAI organization usage JSON | Time buckets, model dimensions, input/output/cache tokens and request counts |
| OpenAI organization costs JSON | USD cost buckets without invented token counts |
| Anthropic organization usage JSON | Ordinary input, cache reads/creation, output and time buckets |
| Anthropic organization costs JSON | Reported USD cost buckets |
| Claude Code analytics JSON | Daily model tokens and provider-estimated costs |
| Cursor account JSON or CSV | Saved usage events, available token categories and source-reported amounts |
| Usage metadata JSON or JSONL | Explicit normalized counters and stable event/session IDs from an ACP tool, provider, or server |

Cursor's Admin API JSON uses `chargedCents` for reported charges. Events marked
`isChargeable: false` remain subscription allocations and do not enter the billed total. Dashboard CSV `Cost` stays
source-reported, and an explicit `Cost to you` is treated separately. `Included` or a missing amount
does not become a guessed invoice. Sign in through Cursor and export your usage, or use an
authorized team Admin API report. Local Cursor conversation files alone do not establish complete
account usage. See [Cursor's official Admin API
documentation](https://cursor.com/docs/account/teams/admin-api).

For organization reports, use credentials authorized for the provider's reporting API. An ordinary
inference key or personal subscription login may not have that permission. OpenAI API organization
reports are distinct from personal ChatGPT subscription usage. Anthropic's Admin API is unavailable
for individual accounts. Its Claude Code analytics costs are estimates, and Enterprise has a
separate reporting API. See [Anthropic reporting
access](https://platform.claude.com/docs/en/manage-claude/usage-cost-api) and [Claude Code
analytics](https://platform.claude.com/docs/en/manage-claude/claude-code-analytics-api).

To import a report directly from a provider API:

1. Under **Authorized provider reports**, choose **Connect a usage report**.
2. Select the **Provider report** and enter an authorized organization or Cursor admin API key.
3. Provide an **Account alias**, and set **Start date UTC** and **End date UTC**.
4. Choose **Import provider report**. If more pages are available, re-enter the key and choose
   **Import next page** until the report is complete.

Credentials are transient and are not stored in the history ledger.

The direct API controls support OpenAI organization usage/costs, Anthropic organization usage/costs,
and Cursor team usage. Other supported formats, including Claude Code analytics, can be imported
from a saved export.

## Understand missing fields

Ryu keeps unavailable counters unknown. A missing cache count is different from a reported zero.
Reasoning and cached-output counters can be subsets of output, so they do not automatically add
extra tokens. Cache savings are estimated using available cache-read and ordinary-input rates.

OpenCode saves text output and reasoning separately. Ryu adds those categories once to its inclusive
output total while retaining the reasoning breakdown, following [OpenCode's usage
accounting](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/session.ts).

Totals and breakdowns mark a counter **Unknown** when no records supply it and **Partial** when only
some do. This applies to input, output, cache reads, cache creation, cached output, and reasoning.
An explicit zero remains a known value.

Unknown model prices leave records unpriced. The displayed estimate can therefore cover only part of
the imported usage. Source-reported charges can include discounts, fees, or other adjustments that
token pricing cannot reproduce.

Deleted sessions, disabled logging, unavailable account permissions, unsupported formats, and
provider retention limits can leave gaps. Signing into a subscription does not guarantee that the
provider offers a historical token API. Server billing aggregates cannot recreate individual
sessions that were never recorded.

## Privacy

Local imports read existing histories without changing the source files. Ryu saves selected usage
metadata and provenance, not raw conversations or credentials. It skips symbolic links and limits
file sizes and scan batches. Malformed or oversized JSONL frames produce warning counts, and valid
usage records in the same file can still be imported. Inaccessible files appear in the import result
so you can fix the source and retry.

See [Transparency](/docs/surfaces/desktop/transparency) for Ryu's data and consent controls.

## Normalized metadata format

For server logs and other providers, prepare a metadata-only export before importing. Include stable
identities, timestamps, model and provider IDs, and actual usage counters. Do not upload
conversations to calculate historical tokens, and do not paste browser session cookies into import
controls.

The normalized export accepts one JSON object per line, an array, or a JSON object with a `records`
array. Use `eventId`, `sessionId`, and an RFC 3339 `timestamp`. Optional fields include
`providerId`, `modelId`, `scope`, `inputTokens`, `outputTokens`, `cacheReadTokens`,
`cacheWriteTokens`, `cachedOutputTokens`, `reasoningTokens`, `reportedCostUsd`, `costKind`,
`bucketSeconds`, and `requestCount`. Input excludes cache categories, and reasoning is a subset of
output. Supply a native `sourceId` only when preserving that source's original event identity.
Source identifiers use up to 128 letters, digits, periods, underscores, colons, or hyphens, so a new
tool can provide metadata without a built-in scanner. Repeated exports match an existing recorded
event. Extra conversation or credential fields are discarded.

`costKind` can be `unknown`, `sourceEstimate`, `apiEquivalent`, `billed`, or `subscription`. Only
use `billed` for an authentic provider charges report. An estimate attached to a subscription
session remains an estimate. Legacy `estimated` and `source-reported` kinds are also accepted.
