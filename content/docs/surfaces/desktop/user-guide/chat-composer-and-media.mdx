## Jump around with the TOC rail

A Notion-style table-of-contents rail runs down the left gutter of the message list, one marker per
user message. Hover the rail to reveal each message's text, click to scroll that turn into view; the
active turn's marker is highlighted. The same rail is available in compact chat surfaces; when the
surface is too narrow, it collapses into a compact message count. Click that count to open the full
message list in a bounded, scrollable popover and jump straight to any turn.

## Use the same chat primitives everywhere

The main desktop chat, the floating **Ask Ryu** assistant, the island mini chat, and side-chat panels
share the same transcript and composer primitives. That means tool rows, including agent-emitted JSON
UIs, use the same renderer, while `@` mention tokens and the searchable composer directory keep the
same behavior as the surface changes. Compact surfaces use tighter spacing but retain the preview rail
through its collapsed popover form.

The floating **Ask Ryu** panel is quieter than the full Chat page: it starts with a
single-line composer, a small **New chat** header, and up to four recent chats. Agent/model settings
remain available from the header, and **Open in full screen** hands the same conversation to a normal
chat tab. The Island mini chat follows the same compact shape; attachments stay behind **+**, while
voice and the command palette remain available through their global shortcuts.

Ask Ryu sends your selected page context with your question. Your visible question keeps your own
words, and the context chips show which page is included. Remove a chip to leave that context out.
For external agents, model, permission-mode, and thinking choices use the same saved session
settings as the main chat composer and are sent with your next Ask Ryu or builder request.

The global **Search everything** command palette also searches published Marketplace listings. Pick a
result to open the Marketplace Browse section with that listing selected, or keep using the palette
for chats, pages, captured context, and commands.
Chat-message and page searches follow the selected node and its credentials. Switching either
refreshes those results and ignores responses from the previous connection. Compose opens a fresh
chat with your message; pending image attachments from a closed draft or previous connection are
not added to a later draft.

The `/btw` side-question service has no tools and does not add its exchange to the
main transcript. Its presentation and follow-up composer still use the shared chat primitives, so the
surface stays familiar without changing the side-question safety boundary.

## Queue messages while a reply streams

You can keep typing and sending while a reply is still streaming. Extra messages stack in a **queue**
above the composer and drain automatically, one per turn, when the run finishes.

Each queued item has send-now and remove actions, plus inline editing and **Send all**. A list-end icon
and count identify the waiting queue above the composer. Attachments are saved with the queued message
and shown as thumbnails, so adding or removing an attachment in the composer later does not change
what that queued turn will send.

Drag the cards to reorder them, or focus a card and press **Alt + Up** or **Alt + Down** for keyboard
reordering. Choose the automatic drain order (oldest-first, latest-first, or send-all-combined) in
**Settings → General → Chats**.

A queue belongs to the chat tab and conversation it was typed in. Switching to another tab keeps it:
the queued messages wait in their own tab and still drain into their own conversation, one per
finished reply, even while you are looking at a different chat. Starting a new thread in that tab, or
opening a different conversation in it, clears its queue.

The primary composer action becomes **Send** whenever there is text or a staged attachment, including
during a reply. It shows **Stop** only when the composer has no text or attachments and a reply is
running. When the composer has no text or attachments and is idle, a Desktop chat shows the phone
**Start voice call** control in that slot, and it turns into **Send** as soon as there is text or an
attachment. A chat that does not offer voice calls shows a disabled, icon-only upward-arrow **Send**
button instead.

The message box grows with your draft up to a maximum height, then scrolls. It fits its text again
whenever its width changes: when you resize or split the pane, and when you return to a chat tab
that was in the background or was restored when the app reopened.

## Follow the current turn above the composer

While an agent works, two floating status chips sit side by side above the composer: one shows the
current `TodoWrite` progress, and the other shows the files changed in the latest user turn,
including total lines added and removed. The step chip is shown as **Step 2 of 3** and opens the
agent's tracked todo list, including completed, active, and pending items; it is not a separate
plan-progress list. The files chip includes edits from the turn while it is still in progress and
opens the per-file change breakdown. The chips reset for each new user turn, so they never mix
older edits into the current run.

## Keep plans in the pinned summary

When an agent creates a plan, the pinned summary adds a **Plans** section. It accepts ACP and Pi
plan signals, including `TodoWrite`, Pi's `PlanWrite`, and the compatible `update_plan` shape.
Each completed snapshot is saved as a markdown document in the node's built-in **Artifacts**
Space, so earlier plan versions remain available instead of only the latest checklist.

Saved plan links belong to the selected node and account. Switching either reloads the
saved plan state for the current account.

Open the pinned summary, expand **Plans**, and select a plan to open its saved artifact in the
workspace artifact viewer. The row shows whether the snapshot is still being saved, was saved
successfully, or could not be persisted.

## Tune how much tool detail you see

Agent tool calls can render compactly or in full. **Settings → Appearance → Chat** has a
**Detail level** slider with four steps. **None** hides tool calls and file edits, though failed
steps still show. **Compact** keeps each call collapsed to a row, **Minimal** opens file diffs, and
**Detailed** expands diffs, command output, and code blocks and lists every call individually.
The individual toggles it drives sit under **Advanced detail** for fine control. When those toggles
no longer match a step, the slider reads **Custom**, and screen readers announce **Custom** as well.

With **Group tool uses** enabled, consecutive compact actions appear in one activity disclosure.
The row streams while tools are running, then collapses to a summary such as "Ran 4 tools"; open it
to inspect each action in chronological order. Rich results such as file diffs, expanded command
output, questions, app widgets, and failures remain standalone so their controls and detail stay
available.

Activity rows use an icon that matches the operation so a long run is easier to scan: a book for
file reads, a pencil for writes and edits, a globe for web search, a terminal for commands, and a
wrench for other tool calls. The icon is visual shorthand; the operation label remains visible for
accessibility and precision.

## Follow-up suggestions and unsent messages in tabs

After a reply finishes, suggested next prompts appear as chips under the transcript. They belong to
the chat tab and conversation they were made for. Switching to another chat or opening a new chat tab
keeps them, and a reply that finishes while you are looking at another tab gets suggestions for its
own conversation. Choosing another thread in that tab's thread picker clears them.

The thumbs you gave replies also stay with their own chat tab while you look at other chats.

**Review** on a turn's edited files opens the **Changes** view on **Files from this turn**. In the
standard tab layouts that is a tab of the window's Right pane and it belongs to the project, not to a
chat: it stays on those files while you look at other chats or a new chat tab, and when you choose
another thread in the tab. Select **Review** again to focus the same tab. In the scrolling and
**Infinite canvas** layouts each chat keeps its own right dock, so the pane stays with its chat while
you look at others, and choosing another thread in that tab closes it.

When the composer cannot send because the Gateway the chat's agent needs is unreachable, a message
you submit, such as a suggestion chip, stays in the transcript unsent instead of disappearing. It
stays there when you switch to another chat or a new chat tab, and starting a new thread in that tab
clears it. A new chat tab is labeled **New chat**, not after the chat you opened it from.

## Open and preview links in messages

Links in both your messages and agent replies show a preview when you hover or focus them. Website
previews include the page title, description, and Open Graph image when the site provides them.
Clicking a website link opens it in an installed app that declares support for web links, such as
Browser; without one, Ryu uses your system browser. Preview requests block local and private network
addresses.

Agents can reference a workspace file as `@src/components/App.tsx`. For paths containing spaces,
use `@<docs/project notes.md>`. These mentions use the same complete file-type icon set as the Files
tree, preview the first few lines with a soft scroll fade, and open the file in a workspace editor
tab. Ryu only resolves files inside the conversation's active workspace folder.

## Attach a Clip as context

**Clips** are screen recordings for agent context. Record your screen (with audio) or paste a video URL,
and Ryu turns it into a frame-plus-transcript context bundle you can attach to a chat message so the
agent can watch what happened. You can also attach the last
few minutes of ambient activity without a discrete recording. Finished clips are filed into a
default **Clips** Space.

The docked workspace assistant shows recording controls when the Clips app is enabled. Choose the
primary screen, a display, or a window, then toggle microphone and system audio before starting.
Controls stay disabled while a recording action is pending. Pause freezes the elapsed timer. If
starting, pausing, resuming, or stopping fails, the error stays visible and you can retry. A failed
stop keeps the current recording available. If capture sources cannot load, close and reopen the
source picker to retry. The source picker follows your active node, so switching nodes clears the
previous source list.

Stopped and saved recordings attach their context and available frames to the next message. While
an attachment is preparing, choosing the same recording again does not duplicate it; choosing a
different recording queues it. If a saved recording cannot load, use **Retry attachment**. Missing
frames do not discard the context: the attached summary states how many images were available, or
that the recording contains context without images.

<Callout type="warn">
  Screen and audio capture require the appropriate operating-system permissions on the computer
  running your active node. If capture is unavailable, check that the Clips app is enabled and that
  capture permissions are granted, then retry.
</Callout>

## Image generation

Image generation runs on a local engine you install from the Store. The default is Qwen Image 2.1
through stable-diffusion.cpp (`POST /api/images/generate`), and the engine ships install, start,
and stop lifecycle in the Store's **Engines → Image** group. The Qwen weights are licensed for
non-commercial use unless you obtain a separate commercial license.

Image results appear inline in the assistant turn; failed generations can be retried in place.

For image processing, open an attached or generated image's **Annotate** action. The editor can find
subjects, highlight a detected subject to select it, erase a selected subject or brush area, remove
the background, draw markup, and place numbered comments. **Resize** opens AI canvas expansion: choose
an aspect ratio and let the image model generate the new edges instead of stretching pixels. **Add to
chat** attaches the edited PNG to the composer; **Download PNG** saves a copy.

Segmentation and background removal use separate browser-local model engines. Their model IDs can be
changed from **Models** in the editor. The first use downloads each selected model and stores it in
the browser cache; image pixels remain in the browser during these processing steps.

AI Resize defaults to **On this device**, using Ryu's local stable-diffusion.cpp image model. Setup
downloads the engine and default model on supported platforms, then reuses the local weights. Install
and select alternate diffusion models from **Store → Models**. The resize panel also offers
**Gateway model** for the image route configured in Gateway; that sends the source image to the
provider and may incur charges. Each aspect preset shows its ratio and output dimensions for the
selected engine.

Closing the editor or opening another image cancels the pending resize. A late result cannot replace
the new image. If generation fails, the current image stays intact so you can retry. **Add to chat**
exports and attaches the edited PNG once, even if you activate it again while export is pending.
After attachment, the viewer and editor close and keyboard focus returns to the conversation; page
scrolling is available again.

**Add blank padding** remains available as a separate non-generative option. See
[Image and video providers](/docs/providers/image-and-video) for model requirements and local/cloud
data handling.

## Review sources and subagents

Attachments sent with user messages also appear under **Pinned summary → Sources → Chat attachments**,
alongside the web, connector, and local-file sources the agent used. The list keeps the original
filename and media type so the context supplied to the conversation remains visible. Calls through
qualified MCP servers and app tools are included as named source groups, and integration actions such
as Composio appear with the operation they ran and its identifying input.

Local media objects are available on personal nodes only until per-object tenancy is enabled on
managed nodes. Uploaded SVG files are served as non-executable downloads, and stored media is not
publicly cacheable.

The pinned summary and the full **Sources** workspace tab use the same live inventory, so these entries
stay aligned across both views. The pinned summary keeps every source group visible and caps the
concrete items inside each group at five rows, so an MCP, app, or integration cannot be hidden by the
order in which it was used.

Open **Sources** or **Subagents** from the workspace tabs for the complete live list. Subagents are
named after the concrete task they own, with active work grouped above completed work. The first four
active tasks stay visible before a **Show more** control, live rows show elapsed working time, and
completed rows show when they finished. Selecting a task opens its transcript inside the same
**Subagents** tab; use the back button to return to the roster.

## Viewing images

Images that arrive in chat (a picture you attached to a message, or one staged in the composer)
open in a fullscreen **lightbox** when you click the thumbnail. The viewer morphs open from the
thumbnail, supports zoom and pan, and shows the image title above a `− / percentage / +` zoom
control at the bottom. **Download** and **Close** stay in the top-right corner. It shows a gallery
when more than one image is present: arrow keys, chevron buttons, and dot navigation move between
images, and **Esc** or clicking the overlay closes it. Assistant-generated images stay inline and
offer their own **Annotate** action to open the editor.

The same viewer is reused for marketplace listing screenshot galleries. See
[Marketplace](/docs/surfaces/desktop/user-guide/marketplace).

## Audio

Install a voice engine such as OuteTTS from the Store to use speech synthesis through
`POST /api/voice/speak`.

<Callout type="info">
  To hear a message, right-click it and choose **Speak**. Playback uses the voice engine selected
  in your desktop speech settings. Available voice engines are documented under
  [Voice Engines](/docs/surfaces/desktop/engines/voice-engines).
</Callout>

## Ask Ryu permission responses

When Ask Ryu asks you to allow or deny a tool, the choices stay disabled while your response is
being sent. The prompt closes after the node accepts the response. If sending fails, the prompt
stays visible with an error so you can try the same choice again.
