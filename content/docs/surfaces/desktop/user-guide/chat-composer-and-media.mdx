## Jump around with the TOC rail

A Notion-style table-of-contents rail runs down the left gutter of the message list, one marker per
user message. Hover the rail to reveal each message's text, click to scroll that turn into view; the
active turn's marker is highlighted. The same rail is available in compact chat surfaces; when the
surface is too narrow, it collapses into a compact message count. Click that count to open the full
message list in a bounded, scrollable popover and jump straight to any turn.

## Use the same chat primitives everywhere

The main desktop chat, the floating **Ask Ryu** assistant, the island mini chat, and side-chat panels
share the same transcript and composer primitives. That means tool rows—including agent-emitted JSON
UIs—use the same renderer, while `@` mention tokens and the searchable composer directory keep the
same behavior as the surface changes. Compact surfaces use tighter spacing but retain the preview rail
through its collapsed popover form.

The floating **Ask Ryu** panel is intentionally quieter than the full Chat page: it starts with a
single-line composer, a small **New chat** header, and up to four recent chats. Agent/model settings
remain available from the header, and **Open in full screen** hands the same conversation to a normal
chat tab. The Island mini chat follows the same compact shape; attachments stay behind **+**, while
voice and the command palette remain available through their global shortcuts.

The global **Search everything** command palette also searches published Marketplace listings. Pick a
result to open the Marketplace Browse section with that listing selected, or keep using the palette
for chats, pages, captured context, and commands.

The `/btw` side-question service intentionally remains no-tools and does not add its exchange to the
main transcript. Its presentation and follow-up composer still use the shared chat primitives, so the
surface stays familiar without changing the side-question safety boundary.

## Queue messages while a reply streams

You can keep typing and sending while a reply is still streaming: extra messages stack in a
**queue** above the composer and drain automatically, one per turn, when the run finishes
(`packages/blocks/src/desktop/agent-elements/queue/`). Each queued item has send-now and remove
actions, plus inline editing and **Send all**. A list-end icon and count identify the waiting queue
above the composer. Attachments are saved with the queued message and
shown as thumbnails, so adding or removing an attachment in the composer later does not change what
that queued turn will send. Drag the cards to reorder them, or focus a card and press **Alt + Up** or
**Alt + Down** for keyboard reordering. Choose the automatic drain order (oldest-first,
latest-first, or send-all-combined) in **Settings -> General -> Chats**. The primary composer action
becomes **Send** whenever there is text or a staged attachment, including during a reply; it shows
**Stop** only when the composer has no text or attachments and a reply is running. When the composer
has no text or attachments and is idle, it stays the icon-only **Play** control; the phone icon is an
explicit surface-level opt-in rather than the default send action.

## Follow the current turn above the composer

While an agent works, two floating status chips sit side by side above the composer: one shows the
current `TodoWrite` progress, and the other shows the files changed in the latest user turn,
including total lines added and removed. The step chip is shown as **Step 2 of 3** and opens the
agent's tracked todo list, including completed, active, and pending items; it is not a separate
plan-progress list. The files chip includes edits from the turn while it is still in progress and
opens the per-file change breakdown. The chips reset for each new user turn, so they never mix
older edits into the current run.

## Keep plans in the pinned summary

When an agent creates a plan, the pinned summary adds a **Plans** section. It accepts ACP and Pi
plan signals, including `TodoWrite`, Pi's `PlanWrite`, and the compatible `update_plan` shape.
Each completed snapshot is saved as a markdown document in the node's built-in **Artifacts**
Space, so earlier plan versions remain available instead of only the latest checklist.

Open the pinned summary, expand **Plans**, and select a plan to open its saved artifact in the
workspace artifact viewer. The row shows whether the snapshot is still being saved, was saved
successfully, or could not be persisted.

## Tune how much tool detail you see

Agent tool calls can render compactly or in full. **Settings -> Appearance -> Chat** has a
**Tool detail** knob with three presets - Compact, Minimal, and Detailed - a monotonic ramp from
grouped-and-collapsed to fully expanded (`apps/desktop/src/components/settings/AppearanceTab.tsx`).
The individual toggles it drives sit under the **Advanced settings** section for fine control.

With **Group tool uses** enabled, consecutive compact actions appear in one activity disclosure.
The row streams while tools are running, then collapses to a summary such as "Ran 4 tools"; open it
to inspect each action in chronological order. Rich results such as file diffs, expanded command
output, questions, app widgets, and failures remain standalone so their controls and detail stay
available.

Activity rows use an icon that matches the operation so a long run is easier to scan: a book for
file reads, a pencil for writes and edits, a globe for web search, a terminal for commands, and a
wrench for other tool calls. The icon is visual shorthand; the operation label remains visible for
accessibility and precision.

## The composer picker

### Prompt suggestions

When the composer is empty, a plugin or chat surface can show a ghost prompt. Press
**Tab** to accept it, or use **Arrow Down/Up** to open and move through the suggestion
list; **Enter** or a click fills the highlighted prompt. Typing hides the list. The
shared bridge lets hosts provide suggestions from a fast side agent using recent chat
and project context instead of a hardcoded list.

The **+**, `@`, and `/` entry points share one sectioned, searchable menu that opens above the
composer. After opening **+**, keep typing in the composer to filter the list; choosing a result
replaces that search text with its tag. Enabled apps and plugins appear automatically from their
installed manifests, alongside files, chats, and composer actions, without a separate registration
step.

### Pin frequent composer items

Every row in the **+** menu can be pinned, including apps, skills, plugins, and built-in actions.
Hover a row and select its pin button to move it into the **Pinned** section at the top. Pins are
stored on this device and stay available across composer surfaces; select the pin again to remove
one. Search still filters the pinned section, so clearing the search shows the complete pinned list.

The composer's agent and model picker is one grouped dropdown with a search box and three sections
(`packages/blocks/src/desktop/agent-elements/input-bar.tsx`):

In **Ryu Work**, the same dropdown is agent-only; the model selector is not shown anywhere in the
composer or nested provider/ACP picker. The selected agent remains the user's choice while model
routing stays automatic. Ryu Work's hidden permission choice is limited to the agent's own advertised
options; it never invents a bypass/full-access mode.

Ryu Work mode also removes the project-folder picker from a new-chat composer. A normal conversation can
start without a folder; a message that clearly asks Ryu to edit or run local project files opens a
contextual project chooser and resumes that message after selection. Once a chat has a project, its
Pinned summary Environment row shows that chat's project name without allowing the row to retarget it.
Ryu Work keeps the Environment section and the number of changed files visible, while hiding
insertion and deletion line-count chips.

- **Ryu Portal** - the flagship `ryu` agent, with its live model and reasoning-effort pickers when active.
- **Providers** - your configured Pi providers; an unconfigured one links straight to credential setup.
- **External Agents** - installed ACP agents, each probed lazily for its model and permission options when you drill in; agents you have not added yet show an Install button.

Connected subscription providers in the **Providers** section show the same user-configured usage
meters as subscription ACP agents. The rings or bars follow the Usage meter settings, including
remaining-versus-used mode, 5h/7d windows, and reset details; managed Ryu pool rows continue to show
their separate grant balance.

Hover a model row to open a compact insight preview. Rounded meters compare speed, cost,
intelligence, and context on a five-point scale; available rate and token details appear beneath
the meters.

## Target a turn with `@` mentions

The composer's `@` menu routes a turn before you send it:

- **`@agent`** directs the message at a specific conversation participant.
- **`@group`** fans the message out to a group's members under its coordination strategy (see [Groups](/docs/surfaces/desktop/user-guide/teams)).
- **`@workflow`** runs the message through a workflow: the text becomes the workflow's input, its nodes stream back as a live checklist, and the output is the reply. Only workflows that accept a chat input (a root `input` node) appear — see [Run a workflow from chat](/docs/core/workflows#run-a-workflow-from-chat).
- **`@app`**, **`@plugin`**, and **`@skill`** add an installed capability as a reference in the prompt.
- **App list items**, **Space pages**, and **personality profiles** are also available from the same
  `@` directory. App list items come from the app's existing sidebar/Library source, so the row
  opens the same destination in chat that it opens from those surfaces. A personality profile opens
  the Agents page, where you assign it to an agent.
- **`@integration`** references an active connected integration, such as a Composio GitHub or Slack account. Integrations appear only when the active node has Composio access configured through BYOK or its managed subscription/proxy; unconfigured nodes show none.

Picking an agent, team, or workflow also sets the turn target from the mention itself; chats, Space
pages, personality profiles, app list items, spaces, skills, apps, plugins, integrations, MCP servers,
folders, and composer plugins are plain reference tokens.

## Open and preview links in messages

Links in both your messages and agent replies show a preview when you hover or focus them. Website
previews include the page title, description, and Open Graph image when the site provides them.
Clicking a website link opens it in an installed app that declares support for web links, such as
Browser; without one, Ryu uses your system browser. Preview requests block local and private network
addresses.

Agents can reference a workspace file as `@src/components/App.tsx`. For paths containing spaces,
use `@<docs/project notes.md>`. These mentions use the same complete file-type icon set as the Files
tree, preview the first few lines with a soft scroll fade, and open the file in a workspace editor
tab. Ryu only resolves files inside the conversation's active workspace folder.

## Attach a Clip as context

**Clips** are screen recordings for agent context. Record your screen (with audio) or paste a video URL,
and Ryu turns it into a frame-plus-transcript context bundle you can attach to a chat message so the
agent can watch what happened (`apps/desktop/src/components/clips/`). You can also attach the last
few minutes of ambient activity without a discrete recording. Finished clips are filed into a
default **Clips** Space.

<Callout type="warn">
  Recording sources (display and window enumeration) are cross-platform, and the full
  desktop-to-Core-to-Shadow live path is not yet fully runtime-verified. Frame extraction and local
  ingest are proven; treat live capture as early.
</Callout>

## Image generation

Image generation runs on a local engine you install from the Store. The backend is live
(stable-diffusion.cpp via `POST /api/images/generate`), and the engine ships install, start, and
stop lifecycle in the Store's **Engines → Image** group.

<Callout type="warn">
  There is no "generate an image" action in the chat composer yet. Image generation is reachable
  through its backend and the engine lifecycle, but it is not surfaced as a chat composer feature
  today (this is a known gap in `CLAUDE.md` §4). To install the image engine, see
  [Voice Engines](/docs/surfaces/desktop/engines/voice-engines) and the Store's Engines section.
</Callout>

## Viewing images

Images that arrive in chat — a picture you attached to a message, or one staged in the composer —
open in a fullscreen **lightbox** when you click the thumbnail. The viewer morphs open from the
thumbnail, supports zoom and pan, and shows the image title above a `− / percentage / +` zoom
control at the bottom. **Download** and **Close** stay in the top-right corner. It shows a gallery
when more than one image is present: arrow keys, chevron buttons, and dot navigation move between
images, and **Esc** or clicking the overlay closes it. Assistant-generated images are not clickable;
only user-attached and composer attachments open the viewer.

Attachments sent with user messages also appear under **Pinned summary → Sources → Chat
attachments**, alongside the web, connector, and local-file sources the agent used. The list keeps
the original filename and media type so the context supplied to the conversation remains visible. Calls
through qualified MCP servers and app tools are included as named source groups as well, and
integration actions such as Composio appear with the operation they ran and its identifying input.
The pinned summary and the full **Sources** workspace tab use the same live inventory, so these
entries stay aligned across both views. The pinned summary keeps every source group visible and caps
the concrete items inside each group at five rows, so an MCP, app, or integration cannot be hidden by
the order in which it was used. Open **Sources** or
**Subagents** from the workspace tabs for the complete live list. Subagents are named after the
concrete task they own, with active work grouped above completed work. The first four active tasks
stay visible before a **Show more** control, live rows show elapsed working time, and completed rows
show when they finished. Selecting a task opens its transcript inside the same **Subagents** tab;
use the back button to return to the roster.

The lightbox is gated by the `enableImagePreview` preference (default on). The same viewer is reused
for marketplace listing screenshot galleries. See
[Marketplace](/docs/surfaces/desktop/user-guide/marketplace).

## Audio

Audio has a working backend (the OuteTTS engine, swappable, via `POST /api/voice/speak`)
and the engine installs from the Store.

<Callout type="warn">
  There is no "play this reply" action on assistant messages in the desktop chat UI yet. Audio
  playback is wired in surfaces like the Island companion, but not on chat messages (a known gap in
  `CLAUDE.md` §4). The voice engines you can swap in are documented under
  [Voice Engines](/docs/surfaces/desktop/engines/voice-engines).
</Callout>
