bundles, and templates, with free and paid listings. Free browse and install is covered in

In the desktop Marketplace **Browse** and card-based catalog tabs, use the view switcher to choose

## One-click bundles

The **Bundles** tab groups existing Marketplace items into one install plan. **Software Factory**
combines Ryu's project, planning, checks, review, research, proof, security, design, and code-quality
tools. **Social Media Marketing** combines content, social, research, media, brand, and growth tools.
**Outreach** combines contacts, CRM, calendar, agent communication, and clear-writing tools.

Industry packs make the same idea easier to discover by job function:

| Pack | What it brings together |
| --- | --- |
| **Legal** | Documents, research, correspondence, meetings, deadlines, and invoices for legal operations. AI output is a starting point for qualified legal review, not legal advice. |
| **Marketing** | Audience research, positioning, content, social publishing, campaign media, brand presence, and growth strategy. |
| **Sales** | CRM, contacts, outreach, calendar, email, meetings, account research, and follow-up context. |
| **Engineering** | Planning, implementation, checks, pull requests, security, code quality, debugging, and proof. |

These are curated compositions of existing Marketplace items, so each member keeps its own
permissions, lifecycle, and update path.

The broader role catalog also includes connector- and skill-rich packs for finance, support, people
operations, operations, education, data, enterprise search, product management, real estate,
e-commerce, security and IT, and small business. These packs can include Ryu apps, Marketplace
plugins, MCP servers, Agent Skills, and Agent Templates in one reviewable install plan.

The catalog also includes topic bundles based on the public [UI Skills catalog](https://www.ui-skills.com/skills),
including [Craft](https://www.ui-skills.com/skills/craft), [Taste](https://www.ui-skills.com/skills/taste),
Accessibility, Motion, Systems, Visual, Frontend, Testing, Typography, Color, 3D, and framework-specific
collections. The source skill ids remain visible in each bundle, and the live category index is documented
by [UI Skills Topics](https://www.ui-skills.com/skills/topics).

Installing a bundle coordinates the existing kind-specific installers in order. Apps, plugins, skills,
agents, workflows, and MCP servers keep their normal signature, permission, and lifecycle checks. A
bundle never auto-enables a package or hides a partial failure: required and optional failures are shown
after the run so you can retry or review permissions.

Marketplace cards and detail views also show **Community usage**: anonymous aggregate downloads, runs,
and instance counts. The signal contains no account, hostname, prompt, or content, and follows the
community-stats preference. A missing value is shown as zero. Usage counts do not mean Ryu reviewed
the package.

## GitHub-backed packages

Ryu handles billing and packaging on top of the publisher's GitHub repository. A seller submits a
repository or package-folder URL. GitHub stays the source of package files and immutable Releases.
Ryu stores the repository binding, package identity, offer, Stripe IDs, optional license, reviews,
and moderation state. New listings do not require a central `marketplace.json` index.

Standalone repositories are discovered through the `ryu-app` and `ryu-plugin` topics. A repository
tagged `ryu-marketplace` is treated as a collection and Ryu scans its folders for `ryu.package.json`.
The release asset is a deterministic `.ryupack`; Ryu validates its manifest and digest, checks the
Gateway signature, and serves the asset through its own download proxy.

Buyers never connect GitHub or install a GitHub App. For a private release, Ryu uses the seller's
GitHub App installation and a short-lived installation token only while validating or streaming the
release. The token and upstream GitHub URL never reach the buyer or desktop.

An installed package remains available on the node regardless of its listed price or whether the
buyer has completed the optional checkout. A direct license and any legacy publisher-pool plan
describe commerce; they do not replace signature, digest, dependency, permission, or node-lifecycle
checks.

Marketplace installs are package operations, not full-node restores. For a local folder, archive, or
GitHub package that you want to inspect, import, export, or move between machines, see
[Portable packages](/docs/extend/develop/extensions/portable-packages). For chat history, sessions,
memory, and the rest of a node's state, use [Data Folder & Storage](/docs/surfaces/desktop/user-guide/data-and-storage).

## Ask Ryu what's available

You don't have to browse to find something. Ask Ryu in chat, for example "Are there any templates
for invoicing?" or "Is there an app that reads my calendar?". Ryu searches the public Marketplace
and answers with the matching listings, their kind, and their price, or tells you nothing matched.

"Template" covers **Agent Templates**, **Stack Templates**, and **Workflows**. Any other question
searches everything in the Marketplace: apps, plugins, skills, MCP servers, models, knowledge
packs, themes, language packs, Spaces, profiles, output styles, and bundles. Ryu matches the
important words of your question against each listing's name, description, author, category,
keywords, tags, and example prompts. Searching never installs anything. Ryu asks for your approval
before it installs a listing you choose.

## Agent Templates

The free **Agent Templates** catalog includes customized, ready-to-install agent definitions:

- **Animator**
- **Brand Presence**
- **Codex Quota Reset Watch**
- **Design Director**
- **Expense Tracker**
- **Expiry Date Tracker**
- **Family Planner** (listed only when the Family hub rollout is on for your account)
- **Growth Psychology Strategist**
- **Marketing Studio**
- **Security Guard**
- **Subscription Reset Watch**

The catalog is separate from **Agents**, which contains ACP runtimes such as Claude Code, Codex, and
Cursor.

- **Design Director** covers product UI/UX, responsive systems, accessibility, interaction design,
  motion, and programmable explainers.
- **Animator** turns technical ideas and data into storyboarded Manim, HyperFrames, or Remotion
  videos.
- **Growth Psychology Strategist** helps with offers, pricing, sales copy, objections, and measurable
  experiments using mechanisms such as anchoring and framing while keeping proof, scarcity, and pricing
  claims truthful and avoiding deceptive dark patterns.
- **Codex Quota Reset Watch** watches [Tibo's reset announcements](https://x.com/thsottiaux)
  through read-only Composio Twitter actions about every 30 minutes, selects a suitable low-cost
  monitoring model during setup, and backs off to confirmed reset times. Seven editable presets
  live in the existing **Quests** todo list.

  If direct Composio actions are unavailable, it can use an authorized `composio_connect` read-only
  search tool or the Marketplace X MCP (`com.x/mcp`).
  It never publishes or changes an X account.

  Its optional public forecast source is [Codex Resets](https://codex-resets.com/).
  Forecasts are advisory and do not verify an account reset or available reset credit.

  After you bind a Codex worker and project and authorize the queue, it coordinates useful work
  before confirmed resets, including overnight. Account verification needs connected tools;
  banked-reset redemption requires separate authorization and an available redemption tool.
  Installation alone does not enable work or redemption.
- **Subscription Reset Watch** watches the current account-aware usage windows exposed by Ryu
  for Codex, Claude Code, Copilot, Grok, and GLM. Its 30-minute routine is quiet when unchanged,
  and its explicit reset action checks a live upcoming reset before looking for a real,
  idempotent, separately authorized provider action. It never guesses a redemption endpoint or
  treats a public forecast as account evidence.

Agent Templates can carry several schedules, each with its own instructions. Installing one creates
the corresponding independent background jobs on your node. See [Scheduler](/docs/core/scheduler) for
the schedule model and the built-in template behaviors.

## Browse creators

The **Creators** tab lists every organization with a live public listing. Each card shows the
creator's name, handle, publisher mark, bio, and how many listings, followers, and reviews they
have. Search by name, handle, or bio, and sort by **Most followed**, **Most listings**, **Top
rated**, **Newest**, or **Name**.

Open a creator to see their profile: bio, website and social links, when they started publishing,
their totals (including combined downloads), and every live public listing, which you can filter
by kind. On the web, a profile has its own shareable link, and the publisher line under a
listing opens it. The desktop Store shows the same tab; opening a listing from a profile takes you
to its Browse entry.

To edit your own organization's profile, open **Sell** and fill in **Creator profile**. You need
permission to publish Marketplace listings for the organization. The bio is limited to 280
characters, the website must be an `https` URL, and GitHub and X accept a username with or without
`@`. The profile appears on the Creators tab once the organization has a live public listing.

If a save is refused or the service is unavailable, the editor keeps your entries so you can
correct the problem and choose **Save profile** again. **Reload profile** replaces your draft with
the organization's saved profile. Profile fields are locked while a save is pending.

The save is bound to the organization whose profile you loaded. If you switch organizations while
editing, the server rejects the save, so reload the profile before you edit for the new
organization.

## Listing pages and search

On the web Marketplace, licenses, seller status, membership reports, and reports on your listings
follow the selected account and organization. Returning from checkout or onboarding refreshes them.
Switching accounts or organizations loads that scope separately, and signing out clears it from the
current view.

Reports on your listings show the item, the reason, and the reporter's details text,
but not who filed them. A reporter's name, email, and account stay with Ryu's trust and
safety team, so a seller can fix a reported problem without identifying the reporter.

Listing pages on the web follow the desktop listing preview's layout: a header with the icon, name,
and **Open in Ryu** (**Install** for a bundle, **Get** for a listing from an external catalog), a row
of key facts such as rating, price, version, downloads, and runs, and an **Information** panel beside
the description and reviews. On a phone the header's actions move onto their own line below the
listing name. A description too long for the header is also shown in full under **About**, unless
the listing has a README, which **About** shows instead. The web page does not show the desktop's
anonymous instance count. Per-kind pages on the web show the same listing rows as the desktop Store,
including each listing's like count; liking a listing on the web requires signing in.

The web Marketplace keeps its search field available when a section adds many filters. Search and
filter controls wrap onto separate rows when needed, so you can still search the whole catalog while
browsing a specific kind.

Marketplace search results arrive in pages. In the desktop Store, the **From the Marketplace** strip
shows the first page and a **Load more** button while more matches remain. When the Ryu Marketplace
is the selected source in the Models or MCP catalog, scrolling loads the next page.

Package cards keep the package name, publisher verification, and like control together. Release-stage
and capability badges wrap onto a separate row. A package image that fails to load falls back to the
icon tile.

## Remix a listing

An app or plugin published from GitHub shows **Remix** on its detail page, which opens a fork of its
source repository. Adding an agent or workflow template already gives you your own editable copy.
To publish your changes as a new listing that credits the original, follow
[Remixing listings](/docs/extend/develop/extensions/marketplace-listings#remixing-listings). A listing whose
author turned remixing off shows **Remixing: Not allowed by the author** and has no Remix action.

## Wallpaper catalogue

The wallpaper catalogue is available from the desktop **Wallpaper** tab and can also be opened
while choosing a Space cover, agent banner, or account profile banner. The default list includes all
258 PatternCraft CSS wallpapers and both Remocn shader backgrounds. Each entry renders through a
built-in CSS or shader adapter; the saved choice contains only its stable catalogue id, adapter id,
and bounded parameters. Choosing a banner wallpaper also adds it to this device's Wallpaper Library.
Space and agent choices are node-shared. A user profile banner is stored on the account and appears
on its public profile.
