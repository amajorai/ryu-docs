## Choose a model

Ryu can use a cloud model or a model on your computer. Normal chats use the cloud model when one is
set. Otherwise, they use the local model. Change these choices in the Gateway **Defaults** dialog.
The same agent and model picker appears during setup and in Settings. Agents from other tools keep
their own model, effort, and permission settings.

## Start with Ryu in everyday language

After first setup, Ryu opens a new conversation and says hello as your main assistant. The greeting is
an assistant message, so no message from you is added. A ready cloud model answers right away. When
a local model is still being installed or started, Ryu waits and continues when it is ready.

You can describe the result you want in ordinary words. Ryu can look at the files, notes, conversations,
apps, connections, and routines already available, then make a short checklist when setup needs more
than one step. It explains what needs adding or connecting and asks before it installs something, changes
access, sends a message, or saves a recurring routine.

The first message uses the same composer as the start page. After you choose **Send**, the composer
moves to the bottom of the conversation and the transcript appears. This animation follows
**Settings → Appearance → Interface → Enable animations** and your operating system's reduced-motion
preference.

## Resume chats after Ryu restarts

If Ryu stops while agents are working (a crash, a forced quit, a restart, or a power
loss), it resumes those chats the next time it starts. You do not
need to open the app or the chat: once the node is ready again, each chat that was
mid-turn runs its last message again and the new reply appears in the same chat.
This also covers background worker threads that were running when Ryu stopped.

- The resumed turn reuses the message already saved in the chat, so no duplicate
  prompt is added. The agent is told the previous attempt was cut off, so it checks
  what was already done before repeating any action.
- Each interrupted turn is resumed at most twice. If the resumed turn stops Ryu
  again, it is left as **Interrupted** for you instead of restarting in a loop.
  Sending a new message starts a fresh allowance.
- Only chats that were working when Ryu stopped are resumed. Chats you stopped
  yourself, chats stopped by [Kill Switch](/docs/plugins/kill-switch), finished
  chats, and chats whose turn started more than 7 days before the restart are left
  alone.
- On a node shared with a team, chats that belong to a team member are not
  resumed automatically, because the restarted turn would not run with that
  member's identity and permissions. They stay **Interrupted** until the member
  retries them.
- Nothing is resumed in Safe Mode, while Kill Switch is pausing execution, or while
  the node's automations are paused.

To turn this off, open **Settings → General → Chats** and switch off **Resume
interrupted chats**. The setting belongs to the node, so it also applies when no
desktop is connected.

## Pick up chats after Wi-Fi or LAN returns

The optional [Reconnect Retry](/docs/plugins/reconnect-retry) plugin retries chats that stopped
because the connection dropped. When the
selected node or network goes away, it remembers conversations that were actively
running. When both are reachable again, Ryu first reconnects to any turn that kept
running; only a turn that became **failed** or **interrupted** is retried, and each
conversation gets one bounded attempt.

The retry reuses the user message already saved in the conversation, so it does not
append a duplicate prompt. Core checks the conversation's access and run permission
before accepting it, and unrelated old failures are not retried. If you do not enable
the plugin, a lost stream still gets the normal live-turn resume behavior, but a
terminal failure remains available for a manual retry.

## Give an agent a role and a name

When you create or edit an agent, you can add any short title, for example **CTO**, **Researcher**,
or **Travel planner**. Ryu shows that title as a badge beside the agent name in chat, the sidebar,
and the agent picker. New agents start with a common English first name; use the refresh button to
pick another one, or use the magic button after describing what the agent should do to ask the local
agent for a contextual name. You can edit the suggested name.

## See when a reply is being written

While Ryu is generating a response, the transcript shows a speech-bubble typing indicator with
three animated dots. It stays visible through the thinking, tool-work, and first-token stages of a
live reply.

If you scroll up while a reply arrives, the chat keeps the latest incoming messages unread instead
of pulling you away from what you are reading. A theme-colored divider marks where those messages
begin, and the bottom affordance shows the count beside its arrow or live dots. The count clears
when the divider enters view or when you return to the latest message; updates to one streamed reply
still count as one message.

## Presence in shared chats

Shared chats show who is here or typing. Missing or blank names appear as **Someone**.

## Reply to any message

Hover a user message, an agent reply, or a message from another person in a shared chat and choose
**Reply to message** from its action icons. Ryu opens the same quote composer used for text
selections, carrying the whole message into the pending quote above the composer. You can add your
response before sending, or dismiss the quote and keep the draft.

When the reply points back into a chain of three or more turns, the composer shows a **Long reply
chain** infobar with **Create thread**. That action forks the conversation at the replied-to message,
copies the earlier history and chat context into a new tab, keeps the same agent and selected model,
and carries the quote and unsent draft with it. The original conversation is unchanged. The new
thread has the full preceding context, not only the reply chain.

## Right-click a message

Right-click a message (or long-press it on a touch screen) to open its quick menu. When reactions are
enabled, a row of quick emoji sits at the top; pick one to react, pick a highlighted one to remove
your reaction, or choose **+** for the full emoji picker. Below the row are the message's actions:
**Reply**, **Copy text**, **Copy selection** when you have highlighted part of the message, and,
where they apply, **Edit message**, **Regenerate reply**, **Fork chat from here**, and **Speak**.
Actions that enabled apps add to a message also appear at the end of the menu. The hover toolbar
keeps the same actions for mouse users. The menu is unavailable while a reply is still streaming or
while you are editing the message.

## Rename a chat without losing the thread

Manual chat renames and titles supplied automatically by an enabled chat-title feature use the
same desktop transition. The new title appears one character at a time while the previous title
fades from left to right underneath it. The transition follows your animation setting and the
operating system's reduced-motion preference.

## Manage a chat from the Library

Open **Library → Chats** and right-click a chat card to open its context menu. From there you can
open the conversation in the current or a new tab, copy its transcript, mark it read or unread, pin
or archive it, add or remove it from Favorites, rename it, or delete it. Enabled apps may add their
own conversation actions to the same menu.

If Core cannot save a rename, the dialog shows the error and keeps your draft. The previous title
stays visible until the save succeeds, so you can retry without retyping.

Deletion asks for a slide-to-confirm gesture. Cancel leaves the conversation untouched. If Core
rejects the deletion, the confirmation shows the error, the chat stays in the Library, and the slide
resets for another try. Ryu-owned system Spaces also appear in the Library, but their Delete action
is disabled because Ryu maintains them.
