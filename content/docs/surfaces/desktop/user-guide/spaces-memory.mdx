Use a **Space** as a project folder for documents, notes, databases, and whiteboards. Ryu can search
its content and use relevant results when an agent answers a question. Each Space belongs to a node
and can be private or shared with that node's organization.

For facts Ryu remembers across conversations, see
[Long-Term Memory](/docs/surfaces/desktop/user-guide/memory). For retrieval details, see
[Spaces & RAG](/docs/core/spaces-rag).

<TryInRyu page="spaces" />

## Browse Spaces as project folders

The desktop Spaces Library shows each Space as a project folder. Open a folder to preview its
top-level pages and databases. Select a page to open its Markdown editor, or select a database to
open its database editor. If the document list cannot load, the folder offers **Try again**.

The page editor's compact toolbar holds undo, redo, bold, italic, and AI commands. Expand the
toolbar to see the other editing tools in a two-row grid.

## Create a Space and add documents

A Space stores documents so Ryu can find them by meaning and by keyword. To build one:

1. Open the **Spaces** page in the desktop app.
2. Create a Space, give it a name, and choose **Private** or **Team** visibility. New Spaces
   default to **Private**.
3. Add documents or start a blank **page** and write notes directly in the editor. Ryu indexes
   saved content so agents can find it by meaning as well as by keyword.

## Import files and connected-app data

Open a Space and choose the **Import** tab to convert existing content into editable Space
documents. This is different from attaching a raw file for search. An import creates pages and
databases that you can open, edit, and search like documents created in Ryu.

- **Documents become pages.** Ryu accepts text, Markdown, HTML, Word (`.docx`), PDF, EPUB, and
  OPML files. You can choose several files in one pass.
- **Spreadsheets become databases.** CSV, TSV, DSV, Excel (`.xls` and `.xlsx`), and OpenDocument
  (`.ods`) files create typed database columns and rows. CSV-style headers are de-duplicated, and
  Ryu recognizes number, checkbox, URL, short-text, and long-text columns.
- **ZIP archives can contain both.** Ryu imports each supported file inside a ZIP and records all
  resulting pages and databases together. Nested ZIP files and unsafe archive paths are rejected.

The built-in text reader handles text-based formats. PDF, Word, Excel, EPUB, and OpenDocument
need an enabled document parser that supports them. If an import reports that no parser is
available, enable a compatible parser in **Tools & Connections**.

| Limit | Value |
|---|---|
| Uploaded file | 32 MB each (also applies to CSV, TSV, and DSV files inside a ZIP) |
| Expanded ZIP content | 256 MB |
| Database import | 25,000 data rows and 200 columns (the summary still counts every nonempty source row) |
| File storage per owner | 512 MiB or 10,000 files |
| File storage per node | 4 GiB |

Deleting a file frees its quota. An upload or replacement that would pass a limit is rejected
before anything is saved. An oversized file stays in the upload queue with its size error. Remove
it and choose a smaller file. A transfer that failed for another reason offers **Retry**.

Every file and connected-app import appears under **Previous imports** with its status, source,
time, size or item count, errors, and links to every created document. This history stays with the
Space. If Ryu closes during an import, the history marks it as failed.

The **Third-party imports** card reads from accounts connected through **Store → Connections**.
Choose a connected app and one of its read-only actions, then choose whether the result should
become a page, a database, or be selected from the returned data.

## Choose Vector or Graph retrieval

Each Space has a retrieval picker in its detail view:

- **Vector / Quick search** finds content with a meaning similar to your query. It is the default.
- **Graph / Connected search** follows terms that appear together across related content. The links
  show co-occurrence, not facts inferred by an AI model.

Changing to Graph starts a background rebuild and shows its progress. The current mode stays
active until the new graph is ready. You can cancel before the rebuild finishes without changing the
mode. Switching back to Vector removes the term graph but keeps existing embeddings. If a large
document cannot be indexed in Graph mode, split it into smaller documents or switch back to Vector.

## Share a Space as Markdown

Use **Export package** in a Space to download a portable <code>.ryupack</code> archive. Pages are
Markdown files, and each database includes a schema file and one file per row. The files stay
readable and editable outside Ryu.

The package contains source pages, database structure, row values, and frontmatter only. It does
not contain embedding vectors, vector indexes, provider credentials, chat history, or binary files.
When you import it on another node, Ryu creates a new **private** Space. Re-index the Space there
before using it for retrieval. Sharing the imported Space with a team is a separate action on that
node.

You can also import a portable package from the Space's **Share this Space** card. An imported
package is a content snapshot. Disabling or uninstalling its Marketplace package removes the
imported Space, and exporting the Space again creates a new source snapshot.

## Open files in workspace tabs

Uploaded files and agent-created artifacts open beside chats, pages, databases, and Browser tabs.
Ryu chooses the built-in surface from the stored file type:

| File | Workspace support |
|---|---|
| PDF | Page navigation and zoom in a read-only viewer |
| DOCX | Rich-text Word document editor |
| XLSX / XLSM | Multi-sheet spreadsheet editor with formulas and typed cells |
| PPTX / PPTM | Slide previews plus editable text boxes |

Office files use an explicit **Save** button. Saving replaces the file in its Space, keeps the same
document identity and access rules, and refreshes its searchable content. **Download** always exports
the latest saved revision. Legacy `.doc`, `.xls`, and `.ppt` files remain downloadable but are not
presented as editable Office Open XML documents.

## Share a Space with your team

Spaces are private by default, but a shared node can keep personal and team knowledge side by
side. Use the visibility control in the Space's sidebar menu to switch between:

- **Private** - only the Space owner can list, open, search, or retrieve its content.
- **Team** - members of the organization that owns the node can use the Space.

Pages, databases, whiteboards, and uploaded documents inherit the visibility of their parent
Space by default. Changing a Space back to **Private** at once removes those inherited pages from
the team's lists and retrieval results. You do not need to move or re-index them.

A visibility indicator appears beside each Space in the sidebar and in the Space picker.

You can also drag a Space row between the **Private** and **Team** groups. Ryu asks you to confirm
before it changes the scope. Only organization admins and owners can move a Team Space back to
Private. Other members see **Make private (admins only)** disabled.

## Edit Space documents

Open any document to edit it in Ryu's page editor. Saving refreshes its searchable content so
agents can use the latest text. Delete individual documents from the Space when they are no longer
needed.

Saving a Word document opened from a Space, or choosing **Export as Word** in a
rich-text editor's export menu, writes a portrait `.docx` with default margins.
Code blocks keep their syntax colors, bold and italic tokens, and a monospaced
font. Column layouts become borderless tables that keep each column's width.
Table of contents entries link to their headings and indent by heading level.
Callouts are exported as tables, and equations as their LaTeX source text.

<Callout type="info">
  When a meeting is finalized, Ryu saves its notes and transcript as a Markdown document in a
  "Meetings" Space. You can open and edit it like any other Space document. See
  [Meeting notes](/docs/core/meeting-notes).
</Callout>

## Beyond pages: databases, whiteboards, and a wiki graph

A Space also holds databases, whiteboards, and linked pages. All of them feed the same retrieval,
so an agent can ground its answers in them.

### Databases

A database is a typed data grid. Columns can hold text, numbers, checkboxes, dates, links,
single- or multi-select values, and formulas. Open a row as its own page, or view the same data
as a **table**, **board**, **gallery**, or **list**. Changing views changes how the rows are displayed, not the
underlying data. Database content is searchable alongside Space pages.

Double-click a saved view's name above the database to rename it inline. Press **Enter** to commit
the new name or **Esc** to cancel; read-only databases keep the view names unchanged.

Use **Add column**, or a column header's **Edit property** action, to set its name, type, and
select options. Read-only databases disable column creation and hide **Edit property**. Changing a
column's type clears that column's existing row values; renaming it or editing its options keeps
the values under the same column ID.

A **Formula** column calculates its value from other columns in the same row, for example
`{Price} * {Quantity}`. Refer to a column by its name in braces. Formulas support `+ - * / ^`,
`&` to join text, comparisons (`= <> < > <= >=`), `TRUE` and `FALSE`, and the functions `IF`,
`AND`, `OR`, `NOT`, `SUM`, `AVERAGE`, `MIN`, `MAX`, `ROUND`, `ABS`, `CONCAT`, `LEN`, `UPPER`,
`LOWER`, `TRIM`, `CONTAINS`, `ISBLANK`, `TODAY`, and `DAYS(end, start)`. The editor checks the
formula as you type, and you can insert a column reference by selecting its name. Errors show in the
cell as `#DIV/0!`, `#VALUE!`, `#REF!` (unknown column), `#NAME?` (unknown function or unbraced
name), `#CYCLE!`, or `#ERROR!` (syntax). Formula cells are read-only. Results are calculated from
the stored inputs rather than saved, and appear in every view, on row pages, and in **SQL query**
results.

Renaming a column updates the formulas that refer to it by name. Text is treated as a number only
when it is written in plain decimal form (such as `12`, `-3.5`, or `1e3`). `TODAY()` returns the
current date in UTC, so the table and SQL queries agree on the date. A formula can be up to 1,024
tokens long with up to 64 levels of nesting, and text results are limited to 32,767 characters.
Longer formulas show `#ERROR!`, and longer text results show `#VALUE!`. Text stored in a regular
column that looks like an error code, such as `#REF!`, is treated as ordinary text.

Add **Conditional formatting** rules in the property editor to highlight cells in the table view.
Each rule compares the cell with a value (is, is not, contains, greater or less than, or empty) and
picks a highlight color; the first matching rule applies. Numbers compare numerically, dates
compare as `YYYY-MM-DD`, select values compare by option name, and text matching ignores case.

Select **Open row** in the grid to edit that row's properties and page body. Saved views stay the
same when you update row properties. If a row save is rejected, the page keeps your values and
offers **Retry save**. Read-only rows lock both their properties and body.

#### Spreadsheet shortcuts in the table view

The table view supports common spreadsheet editing gestures. On macOS, use **Cmd** where this list
says **Ctrl**.

- **Fill handle.** Select a cell or range and drag the small square at its bottom-right corner to
  fill neighboring cells. Numbers and dates continue their pattern (`10, 20` → `30, 40`), text
  ending in a number counts up (`Item 1` → `Item 2`), weekday and month names advance, and other
  values repeat. A single date steps one day; a single number copies. Filling across columns only
  writes into columns of the same type.
- **Double-click the fill handle** to fill down as far as the data in the neighboring column runs.
  When neither neighbor has data below, it fills the empty cells under the selection.
- **Ctrl+D** fills the top row of the selection down through the rest of it, and **Ctrl+R** fills
  the first column right. With a single row or column selected, they copy from the cell above or
  to the left.
- **Ctrl+Enter** while editing a cell writes the value into every selected cell of the same type.
- **Ctrl+V** pastes tab-separated cells, such as a range copied from a spreadsheet, starting at the
  focused cell. Values that don't fit a column's type are skipped. A paste that runs past the last
  row offers to add the missing rows. Right-click and choose **Paste transposed** to swap the
  clipboard's rows and columns.
- Right-click a selection and choose **Insert row above**, **Insert row below**, or
  **Duplicate rows**. One row is inserted for each selected row.
- **Ctrl+Z** undoes cell edits, pastes, clears, fills, and inserted, duplicated, or deleted rows;
  **Ctrl+Y** or **Ctrl+Shift+Z** redoes them. Undoing a deletion restores the row in its place,
  including its page body link. Rows added with **Add row** or **Shift+Enter** can be undone too.
- **Ctrl+Arrow** jumps to the edge of the current block of filled cells, or to the next filled cell
  across blanks. **Ctrl+Shift+Arrow** extends the selection the same way.
- **Shift+Space** selects the whole rows of the selection, and **Ctrl+Space** selects whole columns.
- **Ctrl+;** enters today's date in a date or text cell.
- **Double-click a column's border**, or choose **Auto-fit width** in its header menu, to size the
  column to its header and contents.
- Open a column header's menu and choose **Filter** to show or hide rows by value, as with Excel's
  AutoFilter. Each distinct value is listed with its row count, and blanks are listed last. A
  filtered column shows a filter icon in its header; choose **Clear filter** to show all rows
  again. Filters apply to the open table and are not saved with the view.
- The status bar under the table shows the row count, including how many rows a filter hides.
  Select two or more cells to see their **Count**, and for numbers their **Average**, **Min**,
  **Max**, and **Sum**.

Choose **SQL query** in the database editor to inspect or summarize rows with read-only queries.
Edit records in the regular table editor. A query has a 500 ms budget shared by loading, formula
evaluation, and SQL. Computed formula cells have a 16 MiB total budget. A query that exceeds a
budget fails with an error and does not change the saved database.

### Whiteboards

A whiteboard is an editable Excalidraw canvas. You can start from a blank board or ask Ryu to draft a
diagram from a prompt. Text on the canvas can be found alongside other Space content.

### Wiki links, backlinks, and a graph

Pages can link to each other with `[[wikilinks]]` and `@mentions`. The editor shows backlinks, and
the knowledge graph helps you explore connected pages. Linked pages can also add context when an
agent searches a Space.

To open the graph, click **Graph** in a page's editor toolbar for that Space's graph, or search
**Knowledge graph** in the command palette for the graph across every Space. Click a node to open its
page. A dashed node is a link to a page that does not exist yet. Clicking it creates the page first.

<Callout type="info">
  The page-link graph and Graph search show different connections. For how retrieval works, see
  [Spaces & RAG](/docs/core/spaces-rag).
</Callout>

## Attach a Space to an agent

Attach a Space from the agent's **Agent** edit page. The agent then retrieves relevant passages
from that Space and grounds its answers in them. To manage agents, see
[Agents](/docs/surfaces/desktop/user-guide/agents).

<Callout type="info">
  Open **Gateway settings → Apps → Spaces → Editor & Embeddings** to set the
  model id, optional embedding endpoint, and optional dimensions. Dimensions must be a positive
  whole number. **Change & reindex** changes the model and re-embeds existing documents. **Reindex
  stale** reruns the active model over stale chunks. The API is `GET|POST /api/embeddings/model`. See
  [Spaces & RAG](/docs/core/spaces-rag).
</Callout>

## Switch nodes

Each node has its own Spaces library. When you switch nodes, the library shows that node's Spaces.
If a recent change does not appear, refresh the library.

## Space covers

Open a Space and choose **Choose cover** to browse the Marketplace wallpaper catalogue. The
selection is added to this device's Wallpaper Library, and the cover choice is saved as a preference
on the active node. Other devices connected to that node show the same Space cover. **Remove cover**
returns the Space to its plain header.
