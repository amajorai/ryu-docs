## Attach your own items

**Attached sign-ins**, on the agent editor's **Advanced** tab, lets the agent's browser sign in to
sites with items from your vault. The agent fills them into the page and never sees the values.

1. List the items, one per line, as `folder/key`, optionally followed by the site the item fills
   on, for example `logins/github https://github.com`. Without a site, the item's first URL is
   used. Pick the environment if the items aren't in the default one.
2. For each item, check its **Login URL**: the page the site's sign-in form posts to. It is
   prefilled from the URL you wrote when that names a page. In a session Box the password is sent
   only to this address. Leave **Allow Box fill without a login URL** off unless you accept its
   warning: with it, the agent can capture the password by sending it to another page on the
   site.
3. Choose how long the agent may use them: 1, 4, or 24 hours.
4. Choose **Attach items**.

You need read access to every item, without an approval step, because a fill hands the value to
the agent's browser. Cards can't be attached, and an agent can hold one set of attached items at a
time. The first browser session that fills from the set keeps it: closing that session, or a
browser restart, ends the agent's use of it. Choose **Revoke attached items** to end it sooner.
The [Browser](/docs/apps/browser) guide explains how the agent fills them.

## Account login URLs

**Account login URLs**, below **Attached sign-ins** on the same tab, lists the agent's own website accounts. Enter each account's
login URLs, one `https` address per line on the account's site, and choose **Save login URLs**.
In a session Box the agent's password for that account is sent only to these addresses, and an
account without any is not filled there. Each change is recorded in the vault audit log.
