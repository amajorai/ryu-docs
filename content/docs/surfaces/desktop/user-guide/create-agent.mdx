Create a custom agent from the **Agents** page. For what agents are and the built-in ones, see
[Agents](/docs/surfaces/desktop/user-guide/agents).

## Create a new agent

1. On the Agents page, click **+** to create a new agent.
2. Under **How should this agent work?**, choose one of three options. You can change this later in
   the agent's settings.
   - **Acts as you**: works on your behalf with the accounts you've connected. This is the default.
     It can't connect new accounts itself. It asks you with a card in the chat, and you finish the
     sign-in.
   - **Its own identity**: gets its own accounts and logins, and never touches yours. Models Ryu
     routes for it run on Ryu credits, your organization's Ryu Cloud model use, or a local model,
     not on your provider keys. The default **Ryu** engine runs it on Ryu's built-in engine under
     its own identity. Engines that use
     your own sign-in (such as Claude Code, Codex with your ChatGPT sign-in, or Gemini CLI), and
     engines Ryu can't route through its Gateway, don't start for it; see
     [Choose which accounts an agent can use](/docs/surfaces/desktop/user-guide/agent-account-access#choose-which-accounts-an-agent-can-use).
     It also can't use MCP servers or app tools that need an API key or secret you saved, or
     control your desktop with Ghost or read what Shadow captured. You can
     [connect apps for it](/docs/surfaces/desktop/user-guide/agent-account-access#connect-apps-for-an-agent)
     after you save it.
   - **Both**: has its own accounts, and can also use the ones of yours you allow.
3. Give it a **name**.
4. Write its instructions in the setup composer. It accepts Markdown, and the expand button
   opens the full Plate editor with formatting, blocks, links, and other writing controls.
5. Use the agent and provider/model picker at the bottom of that composer to choose the model and
   provider that run it.
   The same setup composer is used for both a new agent and an existing agent, and the choice is
   saved with that agent.

Before you create the agent, you can turn on channel setup for **Telegram**, **Discord**, and
**WhatsApp**. The first selected setup opens automatically with the new agent already selected.
Telegram can use Ryu's managed bot flow. Discord and WhatsApp still ask for the credentials their
platforms require. If you select more than one, finish the first setup and add the others from
**Channels**. On shorter windows, the dialog scrolls so **Create agent** and **Advanced setup**
stay reachable.

If you close the dialog before creating the agent, the name, title, instructions, and other details
you entered are kept. The next time you open it, it starts again at **How should this agent work?**
with **Acts as you** selected, so check that choice before you continue.

Before the agent is created, Ryu checks that the engine you picked will start with the choice you
made in step 2. If it won't, the dialog shows why, with the same message the agent's first chat
would show, and **Create agent** stays unavailable until you pick an engine that starts. **Use Ryu
instead** switches the agent to the **Ryu** engine; it isn't offered when the agent is **Both**
with no limit on a computer without the account sandbox, because Ryu can't run it there either.
**Limit to selected accounts** then creates the agent limited, and you choose its accounts in the
editor after it's created. On a computer without the
[account sandbox](/docs/surfaces/desktop/user-guide/agent-account-sandbox), the first step also says that an agent with its own identity or limited accounts
can run only on Ryu there.

When a custom agent on the **Ryu** engine has its own identity or
limited model providers, a line under the engine picker says that it runs on Ryu's built-in engine
while its accounts are limited. If such an agent would start on Ryu's local model and that model
isn't downloaded, the dialog warns that the agent has no model it can use; you can still create it,
but its chats fail until you download the local model, pick a default model it can use, or allow a
model provider.

Which engines start depends on that choice and on the agent's account access:

| Agent | Engines that start |
| --- | --- |
| **Acts as you**, no limit | Every engine. |
| **Both**, no limit | Every engine, in the account sandbox. On a computer without the sandbox, none, **Ryu** included. |
| **Acts as you** or **Both** with **Limit to selected accounts** on | **Ryu**, engines that send their model calls through Ryu's Gateway, and Claude Code, Codex with your ChatGPT sign-in, Gemini CLI or Kiro when that engine's provider is selected. In the account sandbox. |
| **Its own identity** | **Ryu** and engines that send their model calls through Ryu's Gateway. In the account sandbox. |

[Choose which accounts an agent can use](/docs/surfaces/desktop/user-guide/agent-account-access#choose-which-accounts-an-agent-can-use)
has the full rules.

A new agent starts with access to all of the accounts its choice allows. To limit it to specific
accounts, use **Account access** on the **Connections** tab of the agent's editor; see
[Choose which accounts an agent can use](/docs/surfaces/desktop/user-guide/agent-account-access#choose-which-accounts-an-agent-can-use).
**Connections** is an advanced tab. The **Bot** editor, which has no **Connections** tab,
shows **Account access** under **Identity** on the **Tools & knowledge** tab instead. The same panel
has the agent's **Treg**
switch, which applies to the Treg calls apps make for the agent, including calls they make later for
work the agent set up, and its **Model providers**, which limit the provider keys and sign-ins its models may
run on.

When an update to an app asks for a wider identity choice for one of its agents, Ryu keeps the
choice you have and the agent's editor shows the request under the identity choice. **Accept**
selects the requested choice, and saving the agent applies it. **Keep current** dismisses the
request and leaves your choice as it is.

After you create the agent, Ryu opens a new chat with it. The agent introduces itself and asks what
you want to do first. You can keep the full editor open in another tab when you use **Advanced
setup**.

### Editor layout

The agent editor opens with a short profile row (picture, name, and a one-line description) and
three essential tabs:

- **Behavior**: instructions with the model picker, personality and tone, and rules.
- **Tools & knowledge**: **Identity** (whether it acts as you, has its own identity, or both),
  lifecycle and safety, the tools and skills it may use, and the Spaces it may read and whether it
  may remember new things.
- **Triggers**: when it runs on its own. An event trigger watches one of your connected accounts
  or, for an agent with **Its own identity** or **Both**, one of the apps connected to the agent
  itself. A trigger whose account the agent's **Identity** or account access no longer allows is
  marked **Paused: account not allowed**.

The Ryu agent and Jay Jr. run on Ryu's own engine, which has its own shell and file tools that are
not in the tools list. The Ryu agent keeps them in your own chats; its tools list controls only which
Ryu tools it can call. Jay Jr. keeps them only while it may use every tool. Once its tools are limited
to specific tools, as they are by default, it can use only those tools and its shell and file tools
are off.

An agent whose account access is limited, or that is set to **Its own identity** or **Both**,
runs in a sandbox, in trusted folders too. The sandbox hides Ryu's data, your credential stores, and
on macOS your Keychain. See [Agent Account Sandbox](/docs/surfaces/desktop/user-guide/agent-account-sandbox)
for what it hides and what happens on a computer without it.

The editor runs the same check as the new-agent dialog. When the agent's engine won't start with
its **Identity** and **Account access**, the **Identity** section and the **Account access** panel
show why, and a custom agent's editor offers **Use Ryu instead**. The **Identity** section also
shows the warning about an agent with no model it can use. While a custom agent on the
**Ryu** engine runs on Ryu's built-in engine, its saved **Agent launch** settings are set aside;
they apply again when the limit is off.

An agent that stands in for a remote A2A peer (added from **Settings → A2A**) runs on the peer's own
node, with the accounts set up there. Ryu reaches it with the credential you saved for the peer and
hands it none of your accounts on this computer, so its **Identity** section shows **Runs on another
node** instead of the three choices, and it has no **Account access** panel. Only an agent that acts as you
with no account limit can hand work to a remote peer.

In **Bot**, the editor shows only these tabs. When you have access to Agent,
**Advanced settings in the Agent workspace** switches to the full editor. In **Agent** and **OS**,
the advanced tabs follow the essential tabs after a divider: **Connections**, **Integrations**,
**Health**, **Activity**, **Prompt Studio**, **Versions**, and **Advanced**. **Advanced** holds the
profile card (banner, badge, and display name), model capabilities, orchestration, and engine
defaults. **Connections** holds **Account access**, where you choose which of your accounts and
the agent's own accounts it may use, and its channels. Settings search is available alongside the
advanced tabs.

The editor in Agent and **Advanced setup** include a **Health** tab. Its scorecard updates while you
edit and checks the agent's name, instructions, selected runtime and model, lifecycle, access
scope, memory writes, external connections, and background triggers. Failed checks identify setup
contradictions that need fixing before the agent can run. Warnings call out optional or broad
access to review. The scorecard is read-only and does not replace Core or Gateway
authorization, and it does not claim that the model has been live-tested.

The small **New agent** dialog shows only the required starting choices. It does not show the full
scorecard; use **Advanced setup** or open the agent's editor after creation
when you want the detailed health review.

Choose **Audit with agent** in Health to send the current editor snapshot, including
unsaved instructions and configuration, to your default chat agent with the bundled
`ryu-health-audit` skill. A reviewer override is available in **Gateway → Guardrails →
Health audit agent**. The normal agent runtime, permissions, and approvals apply.

The result includes an advisory score, confidence, evidence, prioritized recommendations,
and limitations, separate from the static grade. The audit does not save editor changes
or authorize applying recommendations. Editing the snapshot clears its previous assessment.
Use **Open audit conversation** to inspect the transcript or continue an incomplete review.
