The **Payments** app supports the [Machine Payments Protocol (MPP)](https://mpp.dev). It can find
compatible services, show the exact charge, and ask for approval before it pays. Current support is
Tempo testnet and pathUSD. It does not send mainnet funds.

The companion follows your active Ryu theme, including the same colors, controls, focus states, and
reduced-motion preference as the rest of the desktop app. Payments are off until you install the
app and create its wallet.

## Set up the wallet and policy

1. Install **Payments** from the Store and open its companion.
2. Create the wallet. The signing key is generated locally and stored through the operating system's secure-storage facility.
3. Fund the wallet with testnet pathUSD.
4. Add the HTTPS origins you trust, then set a maximum charge, daily cap, and approval threshold.

The app compares the exact integer amount in every challenge against the policy again immediately before signing. A redirect cannot leave the original origin, and a prepared approval token can be used only once.

## Pay an HTTP endpoint

Choose **HTTP**, enter the method and allowlisted endpoint URL, then select **Review payment**. Ryu first sends the request without a credential. If the service returns an MPP `402 Payment Required` challenge, the approval dialog shows:

- the exact pathUSD amount and the remaining daily budget;
- recipient, origin, network, purpose, and challenge fingerprint;
- the challenge expiry.

Approving signs that exact captured challenge and retries with `Authorization: Payment`. If any material part of the challenge changes, Ryu stops and asks for a new review. A successful response must include a protocol receipt before the reservation is committed.

## Pay an MCP tool

Choose **MCP**, enter the remote Streamable HTTP server URL and tool name, then review the charge in the same dialog. Ryu recognizes both standard MPP forms:

- JSON-RPC error `-32042` with `data.httpStatus: 402` and `data.challenges`;
- a tool result carrying `org.paymentauth/payment-required` metadata.

After approval, Ryu retries the tool call with `org.paymentauth/credential` metadata and requires `org.paymentauth/receipt` on success. An ordinary MCP call never silently turns into a payment.

## Automation and approvals

Auto-pay is optional. It applies only when the charge is below the approval threshold and every other guardrail passes. Calls to the financial `mpp.pay` tool remain visible as risky actions in Ryu's tool approval system.

For agent workflows, use `mpp.payment_prepare` for HTTP or `mpp.mcp_payment_prepare` for MCP. Review the returned payment summary, then pass its one-time `approvalToken` to `mpp.pay`.

## Receipts and private data

The Receipts tab stores safe settlement projections: amount, network, recipient, origin, timestamp, method, and reference. It does not store payment credentials, signing proofs, private keys, request bodies, or response bodies.

Wallet keys never enter chat or app state. The sidecar accepts only a small request-header allowlist, blocks private and local network targets, applies the same check to IPv4 addresses embedded in IPv6, pins the resolved public address for each request, limits request and response sizes, and rejects cross-origin redirects.
