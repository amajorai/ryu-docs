title: "Groups"
description: "Address several agents as one unit with a coordination strategy."
---

A **group** lets several agents work on one turn. Ryu sends your message to each member and combines
their replies into one answer. Use a group when you want several agents to work together.

## Create a group

Groups live in their own **Groups** section in the sidebar.

1. Open **Groups** from the sidebar.
2. Select **New group** in the Groups Companion and give it a name.
3. Pick the **coordination strategy** (see below).
4. Add members from the Companion's agent picker. For router or debate/synthesis, choose a lead
   agent as well.

The sidebar stays a quick live roster. Creation and membership changes happen in the Companion,
so the same management flow works from any shell that can host the app.

At the top of Group settings, **Group at a glance** shows a roundtable view of the roster. Each
seat shows a member's name and engine, the lead is highlighted, and the center shows the group's
coordination strategy. Larger rosters keep the full ordered list in **Members** below while the
table summarizes the first six seats; an empty group shows an open table ready for agents.

## Talk to a group

There are two ways to direct a turn to a group:

- **Composer target picker** - Click the agent picker in the composer and select a group from the
  list. Groups appear alongside agents; selecting one sets it as the persistent target for the
  conversation. The selection is stored as a `team:` prefix on the id and sent as `team_id` on the
  request. `team_id` takes precedence over `agent_id`, so the whole turn fans out to the group.
- **`@mention`** - Type `@groupname` in the composer for a one-off group mention within a
  conversation where you are otherwise talking to a single agent.

Every member's reply is folded into one streamed answer, each block prefixed with the member's
name so you can see who said what. The user turn is persisted once, and the combined reply is
attributed to the group.

## Coordination strategies

Four strategies are built in:

- **Broadcast** - every member answers the turn independently. No member sees another's reply.
  This is the default.
- **Round-robin** - each member answers in order, seeing the prior members' replies folded into
  its prompt.
- **Debate / synthesis** - members answer independently (round one), then the lead agent reads
  all replies and produces one merged answer.
- **Router** - the lead agent classifies the turn and routes it to a single best-suited member.

For `debate-synthesis` and `router`, the lead is the agent in the `lead_agent_id` field; it
falls back to the first member when unset.

<Callout type="info">
  Council chat (`@mention` of individual agents in one thread) and groups are related but distinct:
  council chat targets agents one at a time, while a group is a named unit with a fixed roster and a
  strategy.
</Callout>

## Expose a group via a channel bot

A group can be the route target for a channel bot (Telegram, Slack, WhatsApp, Discord) configured
in **Gateway settings**. When a channel is bound to a group, each inbound message is dispatched by
Core through `run_team_reply_text` - the non-streaming sibling of the in-app path that fans out to
the group's members under the same coordination strategy and returns one combined, attributed reply.

The **Routes to** picker in the Gateway channels dialog lists agents and groups. Selecting a group
  stores it with a `team:` sentinel and persists it as `teamId` on the channel config. Each sender
gets a persistent conversation in Core's `conversations.db`, so history, memory, and tools all
apply just as they do in the desktop.

See [Channel Bots](/docs/gateway/channels) for full setup instructions.
