Inspect one agent's activity and turn completed work into evaluation cases you can review. Core owns
local traces and suite state. The Gateway is the source for measured cost, provider usage, and
policy. For related workflows, see the [Agents guide](/docs/surfaces/desktop/user-guide/agents),
[Gateway evals and audit](/docs/gateway/evals), and
[chat session controls](/docs/surfaces/desktop/user-guide/chat-session-controls).

## Observability

### Inspect an agent's activity

The agent's Activity area has an **Observability** view. It refreshes the Gateway audit data while
you work and gives you a trace explorer. Search by model, provider, request, session, or error.
Narrow to failures, slow calls, model calls, or tool calls. Select an event to see its latency,
token usage, cost, quality score, and correlated Core spans. The summary comes from the server-owned
audit rows, so the desktop does not compute billing or policy on its own.

### What a trace stores

Core spans show the ordered model and tool timeline and a fingerprint for tool input. The local
trace database does not store raw tool arguments. The conversation remains the place to
read the full prompt and response, while the Gateway audit is the place to read measured tokens,
latency, quality, and cost. Direct Gateway events without a Core session link stay visible and show
that no local span timeline is available.

## Evals

### Capture work into a quality suite

Use **Add to Quality tests** on a correlated trace to capture its last user/assistant pair in the
agent's versioned Prompt Studio suite. If the agent has no suite yet, Ryu creates a baseline suite.
Repeating the action for the same run does not add a duplicate. Then switch to **Quality tests** in
the same Activity area to compare prompt and model variants and add deterministic, model-graded,
code, or human review. Node data is not exported by default.

### Run quality and security checks

The same view includes **Quality evaluation** and **Security sweep** actions. Quality evaluation
replays the shared built-in dataset through the configured Gateway model. Security sweep runs a
server-owned, fixed set of Promptfoo-style probes for prompt injection, jailbreaks, PII leakage,
tool misuse, and toxic output, scored by the existing evaluator catalog. It reports which probes
were protected and which need attention; it never executes a tool from a probe. These actions use
the configured provider and therefore consume the normal Gateway budget and audit path.

### Run agent-scoped cases

The edit page has an **Evals** view scoped to the agent you are editing. Running an eval scores cases on latency,
token efficiency, policy pass, and an optional substring match. With no custom dataset, the Gateway
uses its built-in case set.

The view uses the Gateway's eval and audit API. A run posts to `POST /api/gateway/evals/run`, and
run history reads the Gateway audit.

### Author prompt tests

A **Prompt Studio** view on the same page lets you edit the agent's system prompt, fill
`{{variables}}`, preview a rendered prompt, author test cases, run an LLM judge, compare prompt
variants and models, and inspect per-case assertion results.
Preview sends the variable-substituted draft in a chat request to the selected agent and displays
the streamed response; each time you reopen the preview it starts a new conversation.

### Manage prompts in the prompt library

**Prompt library** in the Prompt Studio header opens the node's prompt registry: named prompts with
numbered versions and labels. Versions never change once saved. A label such as `production` or
`staging` points at one version, and moving it is how you promote or roll back a prompt.

- **Save as prompt** stores the editor text as a new prompt (version 1).
- **Commit** stores the editor text as the next version of the selected prompt, with an optional
  commit message. For a chat prompt, the text replaces its system and developer messages and the
  other messages and placeholders are kept. If someone else committed a newer version since you
  opened the prompt, the commit is refused and the newer version is loaded so you can review it
  and commit again.
- **Point label at** moves a label (for example `production`) to the selected version. `latest`
  always means the newest version and cannot be moved.
- **Compare** shows a line diff between two versions, plus the variables and model settings that
  changed.
- **Use in this agent** replaces the agent's system prompt with the selected version. For a chat
  prompt, its system and developer messages are used.

When the node is signed in to an organization, the library also lists the organization's prompts
and keeps a copy on the node, so they still resolve while the node is offline. Organization
prompts are read-only on the node; **Sync organization prompts** refreshes the copy. A prompt
saved on the node keeps its name if the organization later adds a prompt with the same name.

Agents built with the TypeScript SDK can load the same prompts by name and label; see
[Prompts](/docs/extend/develop/sdk/prompts).

### Import and edit datasets

The suite editor imports Promptfoo YAML, JSON, JSONL, and CSV, plus text, Markdown, and
Jinja-style prompt files. It exports the same dataset formats. Import and export preserve typed
variables, metadata, providers, chat messages, default tests, assertion thresholds, weights, and
transforms, nested assertion sets, and run concurrency, timeout, repeat, cache, and tags. They also
preserve provider-output fixtures, custom sandboxed JS and Python evaluators, and model-graded
rubrics.

Dataset rows can be duplicated, reordered, and edited without leaving the suite. Configs may
reference selected companion prompt/dataset files with `file://`; Ryu resolves and copies those
contents into the suite, and shows an import summary before replacing the current draft.

Dynamic functions are retained as configuration but are not executed implicitly in the renderer.
Promptfoo's `targets` provider alias and `evaluateOptions` runtime settings are imported, normalized,
and emitted back in their canonical Promptfoo forms.

Structured exports retain custom text-variant IDs and names, and result metadata facets accept
`key=value` queries such as `team=support`. Imported rows inherit `defaultTest`; set
`defaultTest: false` (or `skipDefaultTest: true`) on a row that should stand alone.

### Understand evaluator support

The evaluator catalog includes the common deterministic, structured-output, moderation, refusal,
model-graded, and code/webhook assertion shapes. Unsupported runtime adapters are reported as
failures, not passes. `not: true` negates a supported assertion's verdict
and score, while an unavailable runtime is shown as skipped (`executed: false`).

### Save versions and reopen runs

Suites are Core-owned resources scoped to the agent. Saving creates immutable suite versions;
restoring a version is undoable and ACL-checked. Completed runs are durable, can be reopened from
run history, and expose per-result human pass/fail review, numeric score, comment, and highlight
state. Runs can be renamed, duplicated, compared, re-run, or deleted with a confirmation step.

### Review case results

The result matrix supports text/regex/facet search, pass/fail/error/difference/highlight filters,
score/pass-rate/distribution charts, full prompt/output inspection with text/Markdown/JSON rendering,
copy actions, failed-only exports, DPO preference JSONL, and human-eval YAML. Matrix state is
deep-linkable in the URL so a saved review view can be reopened after a reload.
Prompt snapshots use the same Core-owned server history, with diff and undoable restore, rather
than browser-only storage. The source history is backed by immutable local Git commits under
`~/.ryu/files/source-history/agents/`; the older SQLite prompt snapshot table remains a migration fallback.

### Review runs in annotation queues

The **Annotation queues** section of an agent's Evals view collects runs for human review. Create a
queue with a rubric, an optional label set (for example `correct, off-topic, rude`), and a top
score; scores run from 1 to that value. Add runs by id, then choose **Review next item**: Ryu
claims the next unreviewed item for you (another reviewer never receives the same item), shows the
prompt and response next to the rubric, and records your score, labels, and comment. **Skip** marks
an item as reviewed without a verdict.

When enough items are reviewed, choose a Prompt Studio suite and **Export reviewed**. Each
completed item becomes a suite case whose expected output is the reviewed response, with your score,
labels, and comment kept in the case metadata; set a minimum score to export only the answers you
approved. Re-exporting skips items already in the suite, and each export that adds cases saves a new
suite version.

Queues follow the agent's permissions: viewing a queue needs view access to the agent, and adding
items, reviewing, and exporting need edit access. Adding a run also checks that you can read that
conversation and that it belongs to the same agent. An item holds a copy of that exchange, encrypted
on disk, and you only see items whose conversation you can read, so view access to the agent alone
does not expose another user's private chat. Deleting the conversation deletes its items, and
deleting the agent deletes its queues. An item that someone else is reviewing, or whose review
someone else recorded, cannot be submitted over by another reviewer.

The same queues are available over Core's API under `/api/annotation-queues` (create, list, update,
and delete queues; add runs, single assistant messages, or external traces with their captured
input and output; claim the next item; submit; assign or release; export to a suite) and through
`@ryuhq/core-client/annotation-queues`.

## Versions

### Version agent definitions

The agent editor's **Versions** tab uses that same history for complete agent-definition checkpoints.
Every successful agent save is checkpointed automatically, and **Save version** creates an explicit
checkpoint for a regression baseline. Each entry identifies the agent name and SemVer, offers a
bounded source diff, and can be restored. Ryu records the current definition as **Before restore**
first, so a rollback can itself be rolled back. Lifecycle transition rules and the locked-agent
guard still apply during restore.

### Know what a checkpoint contains

An agent configuration version includes the Core-owned card: identity, lifecycle and safety posture,
runtime/model slots, tools, skills, memory and policy references, persona, and instructions. It does
not include chat transcripts, credentials, provider secrets, run state, schedules, plugin-owned
preferences, or capability-detection overrides. After restoring a checkpoint, run **Quality tests**
to compare the behavior of that definition against the saved regression suite. API clients can use
`GET/POST /api/agents/:id/versions`, `GET /api/agents/:id/versions/:version_id`, and
`POST /api/agents/:id/versions/:version_id/restore` for the same flow.

Agent configuration saves are checkpointed as JSON alongside the Markdown prompt snapshots, while
credentials, run state, and provider data are never committed.

<Callout type="info">
  Prompt Studio targets Promptfoo's local authoring and evaluation contract. Provider calls still
  flow through Ryu Gateway, Core owns persistence and ACLs, and executable JavaScript/Python/Ruby
  or webhook assertions remain sandbox/runtime adapters; imported config is retained and the UI
  reports when an adapter is unavailable. Promptfoo-hosted sharing, cloud red-team campaigns, and
  hosted account billing are outside a local-first Ryu node.
</Callout>
