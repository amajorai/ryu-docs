---
title: "Onboarding"
description: "Set up a Ryu node for personal or team work and finish your desktop preferences"
---

Ryu keeps two onboarding decisions separate so setup follows the thing you are configuring:

- **Node onboarding** applies to the server you are connected to. It records whether that node is
  for **Personal use** or **Team or company use**, and it controls which context Ryu builds next.
- **Desktop onboarding** applies only to this installed desktop. It covers appearance, window
  behavior, privacy choices, and other device-local preferences.

## Choose the node's context

The first node setup step asks how you will use the node.

### Personal use

Personal setup lets you add a short note about yourself. It stays with the personal node and is
not turned into shared company knowledge.

### Team or company use

Team setup lets a node administrator add a short company starting point: the team, products,
customers, policies, or working style that should shape the next step. Ryu can then use approved,
read-only connections and imported work to draft shared company knowledge for the organization.
The draft is reviewable; onboarding never edits an external account or silently changes an agent.

Only a node administrator with the `gateway.configure` permission can save or reset team setup.
Personal-node setup is stricter: only that node's owner can save or reset it. The server enforces
both boundaries, including when a member uses a different desktop.

## What runs next

After the node context is saved, onboarding continues with the node's agent/model defaults,
connections, optional thread imports, and the appropriate private profile or shared company
knowledge draft. The profile build uses the context selected for this node and keeps memory scopes
separate: personal setup writes user-scoped context, while team setup writes organization-scoped
company knowledge.

Sensitive memory remains a separate, default-off consent choice. See [Spaces & Memory](/docs/surfaces/desktop/user-guide/spaces-memory)
for memory scope, recall, and sensitive-topic controls.

## Reset node onboarding

To run node setup again, open the node selector, choose **Gateway settings**, then open
**This device -> Onboarding** and choose **Reset onboarding**. This resets only the node's onboarding
state; it does not delete chats, Spaces, memories, themes, or other data. The next launch (or a
reload) asks for the node context again.

The node state is available to authenticated clients through:

```text
GET    /api/onboarding/state
PUT    /api/onboarding/state
DELETE /api/onboarding/state
```

Desktop onboarding can be restarted independently from **App settings -> General -> Setup**.
Resetting desktop onboarding does not reset the node's personal/team choice.
