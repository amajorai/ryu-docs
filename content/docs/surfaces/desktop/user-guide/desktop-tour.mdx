This page shows where things are in the Ryu desktop app and what each area does. It is part of the
[Desktop User Guide](/docs/surfaces/desktop/user-guide).

## Layout

The desktop is organized into three parts:

- **Sidebar** (left) - your entry points and chat history. It holds **New chat**, **Search chats**, quick links to **Agents**, **Models**, and **Skills**, and the running list of your past conversations.
- **Main area** (center) - the active page, usually the chat view, but it switches to whatever page you open.
- **Tabs** (top) - pages open as tabs so you can keep several surfaces open at once and switch between them.

### Infinite canvas and the empty workspace

Choose **Infinite canvas** from the tab layout menu to keep open pages on a movable
canvas. Select a tab header to focus it, drag a pane to arrange it, and resize the
selected pane. **Fit all** brings every open pane into view; **New chat tab** opens
a separate chat. Canvas positions and the viewport are saved locally when you leave
the canvas. Switching back in the same window restores the arrangement. Restoring a
session after restarting recreates the tabs, so their pane positions begin again;
the saved canvas viewport remains available.

When links open in the current tab, choosing another chat from the sidebar replaces
that pane's conversation. In **Horizontal tabs**, **Scrollable tabs**, and
**Infinite canvas** alike, the pane reloads with the selected chat's history, and
your next message goes to that chat.

Closing every tab shows the launchpad composer. Write a prompt or stage attachments
there and send to open a fresh chat with those inputs. Agent and model choices use
the same composer controls as chat. The launchpad currently shows the greeting,
composer, and any live activity; recent lists and quick-action sections are hidden.

## Navigation

Press **Ctrl+K** (or **Cmd+K**) to open the command palette and jump to any surface. The full set of pages includes:

- **Chat** - talk to your agents.
- **Agents** - browse, create, and configure agents.
- **Services** - run background helpers for agents.
- **Engines** - choose how Ryu runs an agent.
- **Models** - find and install models that run on your computer.
- **Compute** - choose a bounded CPU or GPU workcell from the exchange.
- **Share** - configure how an idle node or approved agent could be offered.
- **Skills** - add instructions that teach an agent how to do a task.
- **Spaces** - keep notes and files an agent can search.
- **Tools** - give agents access to services and actions. Developers may see MCP servers here.
- **Workflows** - run several steps in order.
- **Calendar** - scheduled events and time-based context.
- **Timeline** - chronological activity view.
- **Monitors** - background watchers and alert conditions.
- **Tasks** - auto-detected todo list (Quests); tracks items from your conversations.
- **Approvals** - requests that need your sign-off before they can run.
- **Meetings** - meeting notes and audio capture.

Use the back and forward buttons in the top-left navigation cluster to walk through
recently opened tab views. The same navigation is available with **Alt+Left** and
**Alt+Right**, or with a mouse's dedicated back and forward buttons.

The palette also shows filter tabs directly under the search field. **All** keeps the
global actions and navigation together; the other tabs narrow results to the matching
sidebar section, such as Chats, Spaces, Workflows, Skills, or Tools. App-contributed
sidebar sections receive their own tab automatically when the app is enabled, so an
installed app does not need a separate command-palette registration.

On Desktop, press **Ctrl+.** (or **Cmd+.** on macOS) to open Settings, or **Ctrl+,** (or **Cmd+,**) to open Gateway settings. To customize shortcuts, open **Settings → Keyboard Shortcuts**. Global dictation and Agent Ask changes wait for the selected node to save before you can edit again. If a save fails, the previous shortcut stays selected and an error appears; record the shortcut again to retry. Switching nodes or changing node credentials clears the old node’s shortcut controls while the new values load.

Both Settings and Gateway settings have a search box at the top of their sidebar. Results are grouped by the section that holds each setting. A group marked **Node** (in Settings) or **App** (in Gateway settings) lives in the other dialog: choosing one of its results closes the current dialog before opening the other. Choosing a result clears the search and opens the section. Each dialog also opens the page inside that section that holds the setting, including when you arrive from the other dialog. The setting is then scrolled into view and briefly highlighted, also when its section is already open. A setting behind a switch that is off, such as the daily reset behind **Developer Mode**, opens its section without a highlight. Settings that need the desktop app do not appear in search on other surfaces.

Plugin and app shortcut changes stay scoped to the selected node. Failed saves and resets keep the saved shortcut; record it again or retry Reset. If initial saved shortcut data cannot be read, editing is disabled until **Retry plugin shortcuts** succeeds. Switching nodes retires pending edits from the previous node.

Plugin shortcuts recorded with cross-platform modifiers also work through the Island shortcut bridge. Clearing a shortcut removes its binding; resetting restores the enabled app's default. Shortcuts reserved by the operating system or another action may remain unavailable.

In **Apps**, a refused enable or disable restores the previous state. Switching nodes keeps errors scoped to the current node; a delayed failure from another node does not replace them. Retry after resolving the error.

In-app shortcut persistence is best-effort: an unsuccessful storage write can still change the shortcut for the current session, but reloading restores the last saved binding. Use the large filter field at the top of that tab to narrow actions by name, category, description, or key binding; the shortcut list scrolls independently below the filter. Select **Reset all to defaults** beside the filter to restore every in-app shortcut in one step.

On macOS, **Settings → Keyboard Shortcuts → Quick Capture** keeps text you select in any app. Turn on **Keep The Selection With A Double-Tap Of Shift**, select text, and tap Shift twice to add it to your Quests board with the app and page it came from. **Which Shift** limits the gesture to the left or right Shift key. Input Monitoring is required for the gesture. Accessibility is optional: without it, captures still record which app they came from but not the window title or page URL, and a fresh grant takes effect after Ryu restarts. Each permission row has a **Grant** button, and returning to Ryu refreshes their status. Captures need the Quests app, which you enable from the Store. If a capture fails, the reason appears under **Last Capture Failed**.

At the bottom of **Settings → General**, **Open source licenses** opens a read-only list of the third-party notices for dependencies that may be bundled with Ryu Desktop. The list includes the JavaScript packages and native Rust crates used by the desktop build, along with the license or notice text published by each dependency when available. Platform-specific dependency notices cover macOS, Windows, and Linux, even when the list is generated on another operating system.

The notices load when you open the reader. If loading fails, choose **Try again** to request them again. Once loaded, reopening the reader in the same Settings view reuses the complete notices.

## Choose a computer

The sidebar computer selector lists **Computers**. **Your computer** is the local
computer running Ryu Desktop. Remote computers keep their configured names, and
Ryu-managed computers are labeled **Cloud Computers**. Select a computer to choose
where Ryu runs the conversation. These labels appear in both the sidebar list and
the compact dropdown. **Auto-select computer** prefers a reachable remote computer
and uses **Your computer** when none is reachable. Leave it off to always use your
default computer. **Add computer** connects another computer.

The compact dropdown also shows the Core, Gateway, and Shadow services. Select its expand button, or
**Engines, voice, toolkits…**, to open the full computer view, which works like a settings app: select a
row to open its page, and **Back** to return. Engines, voice, sandboxes, toolkits, connected devices, and
hardware each have their own page there. On the **Toolkits** page, **VPN** selects the network backend,
including Tailscale and Headscale; backend names keep their own labels.

### Project selection when you switch computers

Workspace changes update your current selection after their settings are saved. If a save fails, Ryu attempts to restore the previous settings. If that recovery also fails, the error reports incomplete recovery. Retry once storage is writable.

Choosing another project, clearing the selection, or switching nodes while a folder check is pending cancels that older selection. Its later response will not select the old path or close the project picker.

A pending create or clone may finish on its original node after you switch nodes. It keeps your current project selection, and a retry runs on the newly selected node. Closing and reopening resets pending dialog state.

## General preferences

When startup selection is enabled, choose a signed-in account and then a node
before opening the workspace. **Back** preserves your choices. Each **Use as
default** switch controls its own saved startup preference; turn it off to keep
choosing that account or node on later launches. Startup defaults are saved after
the selected node is accepted. If saving fails, the chooser remains open so you
can retry. Account, node, and default controls stay locked while their operation
is pending. **Add account** opens browser authorization and lets you retry a
failed sign-in while retaining your existing accounts.

**Settings → General** keeps the Desktop defaults that shape a new workspace:

- **Projectless task folder** defaults to **Ryu/Projects** inside the OS-provided Documents folder and can be changed in Settings. Ryu creates the folder if needed. New chats without an explicitly selected project use it as their local working directory; existing conversations and selected projects keep their own folders.
- **Default file open destination** chooses the OS file manager or an installed editor for the workspace file tree's Open action.
- **Language** defaults to **Auto detect** and can be fixed to English or an installed language pack. In **Settings → Appearance → Language & vibe**, choose **Import** to add a `.ryupack`, or **Export** beside a pack to save a portable copy. Selecting an installed pack that is disabled on this node enables it. Changes apply immediately, and the Language & vibe page stays open in the new language. From the keyboard, Tab moves through **Import**, the language picker, each pack's **Export**, and **Marketplace** in that order, and Shift+Tab moves back. Enter or Space activates **Import**, **Export**, and **Marketplace**. On the language picker, Up Arrow or Down Arrow opens the list at the current choice, the arrow keys move between languages, and Enter applies the highlighted one.
- **Show in menu bar** keeps Ryu available from the macOS menu bar (or the system tray on other desktop platforms) when the main window is closed.
- **Use hardware acceleration** is on by default and lets Ryu draw its window with the graphics card. Turn it off on Windows or Linux if you see blank windows, flickering, or other rendering glitches; the change applies after Ryu restarts, and the row offers **Restart now**. macOS always uses GPU rendering, so the switch is unavailable there.
- **Bottom panel** controls whether the bottom-panel button appears in the chat header.
- **Default terminal location** chooses whether terminal shortcuts and project environment actions open the terminal in the Bottom or Right pane.
- **Prevent sleep while running** keeps the local computer awake while an ACP agent is active; the display may still turn off.

These preferences are local to the Desktop client except for sleep prevention, which is also reflected in the active node's Gateway ACP policy. The native sleep inhibitor is active only while a local ACP agent is running.

The account control in the sidebar footer opens the user menu. Choose the current
account at the top of that menu to open the account submenu, where you can switch
accounts, add another account, sign out an individual account, or **Log out of all
accounts**.
Choose **Invite a friend** in the same menu to open the web referral page.
Choose **Get Ryu apps** to open the download page for the browser extension; the submenu also
lists the mobile app when it can be installed from an app store.

### Scroll horizontal rows with the mouse wheel

When the pointer is over a row that scrolls horizontally but has no vertical
overflow, roll the mouse wheel up or down to move the row left or right. Trackpad
swipes that already include horizontal movement continue to work normally. Areas
that also scroll vertically keep their usual behavior, and when a horizontal row
reaches an edge, the surrounding page can continue scrolling.

  Some controls open in dialogs instead of pages. **Gateway** controls model choice, safety,
  budgets, channels, and identities. **Memory** and **Credits** are tabs inside Settings.
</Callout>

## Notifications and announcements

Inbox items and announcement banners can share one compact notification stack in the
sidebar footer, similar to the notification trays on iOS, iPadOS, and macOS. Open
**Settings → Appearance → Interface → Notification layout** and move the slider to
choose the display:

- **Split** keeps the announcement stack above the account footer and the Inbox in
  its own tray.
- **Grouped** puts both in one tray while keeping separate Approvals, Notifications,
  and Announcements sections.
- **Unified** blends approvals, tasks, app notifications, and announcements into one
  expandable stack. The full Inbox remains available from the tray footer for detail.

The setting updates the sidebar immediately and is included in Appearance reset and
settings sync.

Outside the app, Ryu raises system notifications for agent replies, approval requests,
quests, monitor alerts, and credit alerts. A notification from an agent uses that agent's
name and avatar, whether it is an uploaded image, an emoji, an icon, or a DiceBear avatar.
An agent without a custom avatar shows its engine's logo; animated avatars show the agent's
initial in its colour. Clicking a run notification opens that conversation. Turn system
notifications on or off for this device in **Settings → Privacy → Device permissions →
Notifications**. Alerts follow the selected node and its current credentials, and never open
a permission prompt. Switching nodes does not replay alerts from the previous connection.

The Inbox page and its sidebar notification popover also share notification filter
pills. **All** shows every notification, **Unread** keeps only live rows that still
need attention, and **Archived** shows rows you have put away. Additional pills are
created for each notification level (such as **Info**, **Success**, **Warning**, or
**Error**), so you can scan one kind of alert without changing the underlying feed.
Archiving marks a row read; use **Restore to inbox** from **Archived** or **All** to
bring it back.

Approval and task decisions show a pending indicator while the request is in flight.
If a decision fails, its row stays available so you can retry it.

When the sidebar count increases, the notification bell gives a short ring and the
count rolls to its new value. The bell stays quiet when notifications are read or
archived, and the animation follows the system's reduced-motion preference.

Click an announcement banner to open its detail dialog, where any images and animated scenes for
that announcement load. The newest unread announcement opens there automatically when the
announcement surface first loads; opening it marks it read.
