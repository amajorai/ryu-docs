Long-term memory carries durable facts and preferences across conversations. A Space is different:
it is a collection of content you organize and attach to agents. See the
[Spaces guide](/docs/surfaces/desktop/user-guide/spaces-memory) to create and manage project
content.

| Use | Long-term memory | Space |
|---|---|---|
| Holds | Durable details and preferences | Documents, notes, databases, and whiteboards |
| Used for | Personalizing future conversations | Grounding an agent in selected project content |
| Managed from | **Gateway settings → Plugins → Memory** and **Library → Memory** | The Spaces library |

## How memory works

Ryu captures memory as you chat, so you do not curate it by hand. The store is encrypted at rest on
your machine.

Before each reply, Core can add relevant snippets from long-term memory and past conversations as
background context. [Auto-recall](/docs/surfaces/desktop/user-guide/search-and-recall#auto-recall)
explains what it adds and how to turn it off. See [Memory](/docs/core/memory) for the internals.

Saved notes reach the model most important first, each labelled with its category, the date it was
saved, and where it came from, plus its "when to use" guidance, for example
`[preference · 2026-03-14 · conversation]`. The model is told that notes can be out of date, and to
check any that matter and correct one that proves wrong. The **Recall budget** setting caps how many
notes and how much text a turn can use; see
[Recalled notes](/docs/core/memory#recalled-notes).

```mermaid
flowchart LR
  Chat["Your conversations"] --> Capture["Memory capture"]
  Capture --> Store["Encrypted memory store"]
  Store --> Recall["Auto-recall"]
  Recall --> Reply["Context for the next reply"]
  Store <-->|"Manual export and import"| Git["Git-backed memory folder"]
```

## Memory settings

Open **Gateway settings → Plugins → Memory** in the desktop app:

- **Long-term memory** is on for fresh installs, so onboarding can build a starting profile. If you
  turned it off before, it stays off. You can turn it off at any time.
- The onboarding profile job follows the node's Personal or Team choice. Personal setup writes a
  draft profile to your own memory. Team setup writes shared company knowledge to the selected
  organization memory after you consent. Review these facts as drafts.
- **Auto-recall** turns per-turn recall on or off. See
  [Auto-recall](/docs/surfaces/desktop/user-guide/search-and-recall#turn-it-on-or-off).
- **Recall budget** (Low, Balanced, or High) sets how many saved notes, and how much of their
  text, a turn can add.
- **Minimum relevance** (Off, Low, Medium, or High) skips automatically recalled memories that
  match your message only loosely. Off, the default, always adds the closest ones.
- **Write frequency** sets when new memories are saved. **Each turn** (the default) saves what you
  send in each saved chat. **Reviewed** saves no raw messages: Dream reads your saved chats and
  proposes facts that you accept or reject in **Library → Memory → Dream**. Reviewed needs
  **Remember chats** on and Dream running, either with **Automatic review** or **Run Dream now**;
  otherwise nothing new is saved. **Never** keeps memory read-only: saved facts are still
  recalled.

  Dream does not suggest a fact again after you reject it, and automatic review waits for new
  chat messages before it runs again. Dream also suggests updates to memories you already have:
  when a chat contradicts a saved memory, or two memories say the same thing, the suggestion shows
  the current text as **Before** and the change as **Proposed**. Accepting it replaces the old
  memory, which is no longer recalled.

  Dream can also suggest retiring a memory, shown as **Retire this memory** with its current
  text. It does this when a chat shows the memory no longer holds, or for an event memory older
  than 90 days that no chat has used in the last 90 days. **Archive memory** stops Ryu from
  recalling it without deleting it, and a retirement you reject or undo is not suggested again,
  however long ago that was.

  Changes you accepted in the last week appear under **Recently accepted** in the Dream view;
  **Undo** puts memory back the way it was, so a replaced or archived memory is recalled again and
  the accepted text no longer is. Undo is refused when a later change builds on the one you
  picked; undo the later one first. A change already undone elsewhere, for example in another
  window, drops out of the list. If a proposal was already accepted or rejected elsewhere, or the
  memory it would change was deleted or edited since, Accept and Reject say so and the list
  reloads.
- **Remember chats** lets Ryu index your conversations so Dream can review them and you can
  search past chats. It is off by default. Turn it on or off with the **Remember chats** switch in
  **Library → Memory → Dream**, below **Automatic review**. If you press **Run Dream now** while it
  is off, Dream asks you to turn it on and offers **Turn on Remember chats**; nothing changes until
  you press it. Turning it off clears the chat index; your conversations stay saved.
- **Automatic review** in **Library → Memory → Dream** lets Dream prepare suggestions on its own.
  While it is on, **Quiet hours start** and **Quiet hours end** set when it must not start, in the
  node's local time (10 PM to 8 AM by default). Choose the same hour for both to let it run at any
  time. Reflect's quiet hours also hold it back. On a node shared with your organization, automatic
  review never runs, because Dream cannot tell whose chats to review without you there, so the
  switch is off and disabled and says why. Use **Run Dream now** instead.
- **Search memory and Spaces** runs a ranked similarity search, the same retrieval the desktop
  uses to surface context.
- **Graph** shows visible memory facts and their connected topics, people, categories, agents, and
  scope levels. It is separate from a Space's document-link graph.
- **Include sensitive topics in memory** is off by default and set per user. See
  [Auto-recall](/docs/surfaces/desktop/user-guide/search-and-recall#turn-it-on-or-off) for what it
  covers.
- **Add to memory** saves a durable, encrypted memory.

A failed search or add keeps your query or draft so you can retry. A failed settings save returns
the control to its previous value.

## Manage saved memories

Open **Library → Memory** to curate saved records. The page header holds **New memory** and a
**⋯** menu; the **Library**, **Graph**, **Dream**, and **Reflect** views sit below it.

- **Search** matches the memory text, its usage guidance, and its tags. **Filters** beside the search
  combines the scope, category, and tag filters.
- The list shows the memories Ryu recalls. Turn on **History** beside the search to also show
  memories that are kept but no longer recalled, each labelled **Replaced** (by an accepted
  update), **Archived** (retired by Dream), or **Undone** (an accepted change you undid). History
  rows can be deleted but not edited, and the Git source exports only recalled memories.
- Each row shows the memory, its usage guidance, and one line with its scope, category, importance,
  and tags. A **Sensitive topic** label marks special-category facts.
- **New memory** and **Edit** set the memory text, scope (including a project id), category,
  importance, when to use it, and tags. Hover a row and open its **⋯** menu for **Edit memory** and
  **Delete memory**.
- **Delete** asks you to confirm before it removes a memory. Deleting it also turns down any Dream
  proposal still waiting to change or archive that memory.
- A new memory records where it came from: a chat (with the conversation and message it was
  captured from), a thumbs-up or thumbs-down on an answer (with the conversation and the rated
  answer), an import, Dream, or something you added yourself. The profile drafted during
  onboarding is recorded as coming from its onboarding profile chat, with the reply it was drafted
  from.

If a save or delete fails, the draft or row stays so you can try again.

Clients that talk to Core use these routes. The `/api/memory` routes are available while the
Memory plugin is enabled, and `/api/retrieval/search` while the pre-installed RAG app is enabled.
`GET /api/memory` lists active memories; add `include_history=true` to list every lifecycle, or
`lifecycle=superseded`, `archived`, or `retracted` to list one.

```text
POST /api/retrieval/search
GET|POST /api/memory
GET|PUT|DELETE /api/memory/{id}
GET|PUT /api/memory/settings
GET /api/memory/graph
```

## Track memory in a local Git repository

Open the **⋯** menu in the **Library → Memory** header and choose **Git source** to bind memory to
a local repository you choose. Once a folder is bound, a one-line status under the views shows it;
select it to reopen the Git source. Ryu writes a `memory/` folder with one Markdown file per memory and an `index.md`. YAML
frontmatter holds the scope, category, importance, tags, and stable memory id, so the files open in
Obsidian and show as normal Git diffs.

- Export and import run only when you start them.
- Ryu never writes encrypted database rows, conversation provenance, provider credentials, or
  vectors to the repository.
- The Git source shows the current branch and changed-file count. It can initialize a repository and
  commit the Markdown files.
- Import reads only the `memory/` folder. A file missing from the folder does not delete that
  memory from Ryu.

<Callout type="warn">
  The repository holds your memories as plain text. Treat it as sensitive and review changes
  before you commit or push.
</Callout>

<Callout type="warn">
  Long-term memory remains personal to the signed-in caller. A shared Space is different: its
  documents are filtered by the Space's visibility, and auto-recall uses the current caller's
  permissions.

  A shared conversation does not give one teammate access to another teammate's private memory or
  private Space. The "Connected" presence panel answers who is on a node, not who may see every
  resource. See [Node & presence](/docs/core/node-and-presence).
</Callout>
