---
title: Bot Flows
description: Build a chat bot from a template, publish or embed it, and hand conversations to Workflows.
---

Bot Flows is available in the desktop Apps shelf after you install it from the Store. Its workspace holds your bots and the conversations they collect on the active Ryu node.

## Create a bot

Select **New bot** and pick a template: support triage, lead capture, NPS survey, appointment request, product quiz, bug report, onboarding, contact form, or AI FAQ. Each card shows what the flow does and how many blocks it has. Choose **Blank** to start with a single welcome message.

Each bot has five tabs: **Flow**, **Theme & settings**, **Knowledge**, **Share**, and **Results**.

## Edit the flow

The **Flow** tab is a canvas of groups. Each group lists its blocks, which run from top to bottom. Drag from a block, a choice item, or a condition branch to another group to connect them. Select a block to edit it in the inspector.

Use **Add block** to insert:

- **Bubbles**: text, image, video, or an embedded page. Text can include variables such as `{{name}}` and basic **bold**, *italic*, and link formatting.
- **Inputs**: text, number, email, phone, URL, date, rating, or choice. Set **Save to** to keep the answer in a variable, and optionally a retry message for answers that are not valid.
- **Logic**: set variable, condition, A/B test, jump, wait, or redirect.
- **Integrations**: AI reply, HTTP request, or handoff.

Manage variables from the canvas toolbar. Renaming a variable also updates every `{{name}}` reference to it in the bot. Mark a variable as **hidden** to let the bot's link or embed fill it, for example `utm_source`. Problems such as an edge with no target, an input with nothing to save to, or an unknown variable in a template are flagged on the block.

To draft a whole flow, describe the bot and select **Generate flow from description**. The app replaces the canvas only when the generated flow is valid. Otherwise it shows an error and leaves your flow unchanged.

Deleting a group asks for confirmation. Jump blocks in other groups that point to it are removed too, and the confirmation says how many.

Select **Save draft** to keep edits. If the bot was changed in another window since you opened it, saving tells you so instead of overwriting the other changes. If the link name is already used by another bot, saving says so and offers **Change the public link**. A draft can be up to 1 MiB; when it is larger, the app says so and disables saving and publishing until you shorten it.

Edits you make while a save is in progress are kept. If you select **All bots** with unsaved flow or knowledge edits, choose **Save and leave**, **Discard changes**, or **Cancel**.

## Preview

Open **Preview** to chat with the current draft exactly as visitors will see it. Preview conversations are not published, and they never trigger workflows.

## Theme and settings

Set the bot's display name, avatar, accent color, appearance (light, dark, or automatic), and typing delay. Settings also include the message shown for an answer that is not valid, the message shown while the bot is unpublished, and the AI reply budgets.

## Knowledge and AI replies

The **Knowledge** tab is a list of articles, each with a title and body. A bot can have up to 50 articles of up to 20,000 characters each. Select **Save knowledge** to keep your changes. Unsaved article edits stay when you switch tabs, and the tab shows a dot until you save. AI reply blocks that use knowledge include the best-matching articles in their prompt. Knowledge is stored with the bot so anonymous visitors can use it.

AI replies use the model configured on your Ryu node, and you pay for them. Visitors cannot change the model or the instructions. By default a conversation gets up to 5 AI replies and a bot gets up to 200 per day. Change these limits in settings. When a limit is reached, the bot shows a fallback message and continues.

## Publish and share

Select **Publish** to make the draft you see live. If the bot was changed elsewhere since you opened it, Publish asks you to reload first. Later edits stay in the draft until you publish again, and visitors who are mid-conversation finish on the version they started. **Unpublish** closes the bot and keeps its results.

The **Share** tab shows the bot's link and copyable embed snippets for three modes:

- **Standard** shows the chat inside an element on your page.
- **Popup** opens the chat in a dialog.
- **Bubble** adds a floating chat button.

A bubble embed looks like this, with your node's address and the bot's link name:

```html
<script src="https://your-node.example.com/bots/support/embed.js"></script>
<script>
  RyuBotFlows.init({ slug: "support", mode: "bubble", hidden: { utm_source: "pricing" } });
</script>
```

On the **Share** tab, add each site that embeds the bot under **Allowed websites**, for example `https://www.example.com`, then save and publish. Other sites cannot frame the bot. Visitors need network access to your Ryu node.

## Hand off to Workflows

Bot Flows does not send email or create tickets itself. Instead it emits two events that a workflow can use as a trigger:

- **Bot conversation completed** fires once when a visitor reaches the end of a published bot.
- **Bot handoff requested** fires each time a Handoff block runs. It carries the handoff topic, a summary, the variables, and the transcript.

In Workflows, select the pinned **Trigger** node, choose an app event, and pick one of these events. Steps can read the payload, for example `{{trigger.topic}}` or `{{trigger.variables.email}}`. Use a condition on the topic to route support, sales, and bug handoffs to different steps.

## Review results

Open **Results** to see views, starts, completions, and where visitors stop. A bot keeps up to 5,000 conversations in which the visitor answered at least once. Conversations nobody answered are removed after about a day. Select a row to read its answers, transcript, any handoff, and any failed HTTP requests. **Export CSV** downloads every result for the bot.

Deleting a bot permanently removes its results and knowledge from this node.
