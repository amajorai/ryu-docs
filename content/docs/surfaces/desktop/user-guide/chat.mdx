## Keep the workspace open during a connection loss

The Desktop window stays mounted when your connection changes. A small status toast at the top of the
window tells you which connection needs attention:

- **Connecting to …** means Ryu is checking the selected node.
- **Node offline** means the selected local, self-hosted, or managed node is not answering. Ryu keeps
  reconnecting and provides a **Retry** action.
- **Offline mode** means the device reports no network connection. Ryu waits for connectivity before
  retrying live work.
- **Connection restored** briefly confirms that the node answered again. Ryu refreshes the affected
  data sources, and an enabled Reconnect Retry plugin can resume eligible interrupted chats.

Already-rendered tabs and local drafts stay on screen while a node is unavailable. Live features that
need the node, such as sending a new message or changing shared data, wait until that node is reachable;
this status surface does not promise full offline editing or an offline copy of every page.

## Close Ryu without stopping local work

By default, closing the Desktop window means **Stay in tray on close**: the window hides and the local
Core process continues, so active agent turns and background work keep running. Use **Quit** from the
tray menu when you want to stop Ryu completely. If **Stay in tray on close** is off, closing is a real
quit; when local chat or workflow runs are active, Ryu asks for confirmation before stopping them.
