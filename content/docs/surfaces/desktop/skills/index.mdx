The Skills catalog opens on one view across public [skills.sh](https://skills.sh), vendor GitHub
taps, [browse.sh](https://browse.sh), [ClawHub](https://clawhub.ai), [LobeHub](https://lobehub.com),
Ryu Marketplace, and custom Claude marketplaces. Like the model catalog, all the logic lives in Core
(`apps/core/src/skills_catalog/`), so clients are pure UI over the same endpoints.

## What an Agent Skill is

A skill is a reusable capability described by a `SKILL.md` file (a YAML front-matter block with a
name and description, plus a markdown body). Installed skills load into Core's skill registry from
`~/.ryu/skills/`, where agents can use them.

## Browse

```
GET /api/skills/catalog
```

Search the directory with a `query` and a `limit`, or omit the query to get a featured default. The
featured view runs a handful of seed searches (agent, react, next, typescript, python, security,
database, testing), merges and de-duplicates the results, and sorts by install count. Pass
`installed_only=true` to list what is on disk.

Use `source=<id>` to narrow to one registry, or `source=all` (the desktop default) to build a
best-effort merged catalog. Each result from the merged view carries its producing registry so the
detail and install requests can stay on the same source. The source picker includes `skills.sh`,
the vendor/community GitHub taps, browse.sh, ClawHub, LobeHub, Ryu Marketplace, and any custom
Claude `marketplace.json` source you add.

Core uses the same anonymous endpoints the official skills.sh CLI uses. The token-gated `/api/v1`
endpoints are deliberately not used.

## Bundled skill packs

Ryu also ships a curated set of built-in repository packs. Their `SKILL.md` files are fetched from
the upstream repository during system sync, so Ryu does not redistribute the upstream bodies. The
pack shelf includes [`wshobson/agents`](https://www.skills.sh/wshobson/agents), a broad collection
of engineering, product, security, testing, and operations skills, and
[`cathrynlavery/diagram-design`](https://www.skills.sh/cathrynlavery/diagram-design), an editorial
diagram skill with 27 visual types plus branded HTML/SVG/PNG, Mermaid, and draw.io workflows.
It also includes [`Leonxlnx/unlazy`](https://github.com/Leonxlnx/unlazy), an anti-laziness execution
skill whose root package includes gate files, runnable checks, Depth Tree planning, and proof-based
completion. Ryu fetches the whole upstream repository for this root-level skill, so its references,
scripts, and templates remain available after installation.
Bundled skills are installed into the shared skills directory, while the activation set still
controls which skills are injected into an agent.

```
GET /api/skills/packs
GET /api/skills/packs/detail?id=owner%2Frepo
POST /api/skills/packs/install
```

The built-in pack list is managed by Ryu and cannot be removed. You can install additional packs
from the Skills page or add a custom pack through the same API.

## Detail

```
GET /api/skills/catalog/detail?id=owner%2Frepo%2Fslug&source=<id>
```

The detail view downloads the skill package, finds `SKILL.md`, splits its YAML front-matter from the
body, and returns the description, the README body, and the full file list.

The detail view also shows a **Health** scorecard. It uses skill-specific checks
for source trust, published audits, maintenance, documentation, and package
integrity. On a node-backed desktop, **Scan with agent** sends a bounded,
read-only evidence snapshot to the agent selected in **Gateway → Guardrails →
Catalog scanner**. The deterministic score and the agent narrative are shown
separately; the narrative cannot change the score.

## Install

```
POST /api/skills/catalog/install
```

Installing downloads or materializes the source's `SKILL.md`, writes it into the universal skills
directory, hot-reloads the skill registry so the skill is usable immediately with no restart, and records provenance in
`~/.ryu/skills-catalog-installed.json`. Any sibling docs are written alongside so references are not
lost.

To list every installed skill and its enabled state, use `GET /api/skills`.

## Author your own skill in-app

You do not have to install from the catalog - you can write a `SKILL.md` from scratch in the desktop
and edit it later, with the same PlateJS editor Spaces pages use. Open the Skills page and choose
**New skill** (from the filter panel or the empty state), or **Edit** an installed skill from its
detail header (`apps/desktop/src/pages/SkillEditorPage.tsx`).

The editor gives you the front-matter as form fields - name, description, allowed tools, and an
**Always on** switch - plus the Plate body for the instructions. Core owns the write and stores each
file at `~/.claude/skills/<id>/SKILL.md` through these routes.

```
POST /api/skills          # create a new skill
PUT  /api/skills/:id      # update (autosaved)
GET  /api/skills/:id/source
```

Editing an existing skill autosaves on a short debounce. Creating a new one is explicit: name it,
press **Create skill**, and the tab moves to that skill's edit route. Saving patches only the
editor-managed front-matter keys and preserves any others, so the catalog's own enabled state (which
the activate toggle owns, not this editor) is never clobbered.

## Version history

Every skill you edit in-app carries server-backed version history - the same **snapshot / diff /
restore** control that pages and workflows use. Versions store the raw `SKILL.md` string, so a
restore is lossless and the diff includes front-matter changes as well as body edits.

```
GET  /api/skills/:id/versions
POST /api/skills/:id/versions            # snapshot
GET  /api/skills/:id/versions/:version_id
POST /api/skills/:id/versions/:version_id/restore
```

Open **Version history** in the editor header to name a snapshot, compare any version against the
current source, or restore one. A restore auto-snapshots the current state first, so you can always
step back.

<Callout type="info">
  Version history is stored as immutable Git checkpoints under
  `~/.ryu/source-history/skills/<id>/SKILL.md`, separate from the shared skills directory. The old
  `~/.ryu/skill-versions/` JSON snapshots remain readable as a migration fallback, but new saves are
  not capped or pruned by the app. It applies to skills you author or edit in-app, not to catalog
  packages themselves.
</Callout>

<Callout type="info">
  Skills here are the catalog-installed `SKILL.md` capabilities loaded by Core. They are distinct from
  the Gateway's skill-injection feature, which prepends prompt snippets to system messages at the
  Gateway. See [The Gateway](/docs/gateway).
</Callout>

## View installed Skills in the Library

Installed Skills can appear in the desktop Library as visual, book-like objects. The Skills catalog
remains the place to browse, install, enable, disable, and edit Skills. Use the Library shelf for a
visual overview, then open the catalog when you need to manage a Skill.

The Library's **Relations** view adds a visual map of the installed set. Switch from the bookshelf
with the view toggle to see three groups:

- **Agents → Skills** shows which enabled Skills each agent can receive. An empty agent allowlist
  means all enabled Skills; an explicit no-capabilities setting shows no access.
- **Skills → Tools** shows the tools a Skill declares in its front matter. These edges describe the
  Skill's declared tool needs, not a grant that bypasses the normal tool and Gateway checks.
- Skill nodes can show your existing observed usage count from Stats. Usage is account-level and
  is kept visually separate from configuration relationships; it is not an assignment count.

Disabled installed Skills remain visible so you can see what is present without implying that an
agent can currently receive them. Selecting a node opens its direct relationships, and the Library
search filters the graph. The view does not infer Skill-to-Skill dependencies from free-form
instructions or from two Skills appearing in the same usage period.
