---
title: Video Studio product guide
description: Build video timelines, review scenes, edit captions, and export finished films.
---

Video Studio is a separate editing workspace. Use [Clips](/docs/apps/clips) to
capture recordings, then import your footage into Video Studio alongside music,
voice recordings, and still images.

Agents can import media through `POST /api/video-studio/assets/import` using one
local absolute file path, HTTPS URL, or bounded base64 payload. The sidecar
probes the source, copies it into app-owned storage, and returns its validated
metadata before timeline placement. URL imports reject local/private hosts and
follow only a small number of validated HTTPS redirects.
Agents can inspect one asset with `GET /api/video-studio/assets/{id}/inspect`;
the response combines source metadata, saved transcript, completed analysis, and
the generated thumbnail unless `thumbnail=0` is requested.

Visual library items expose **2× upscale** and **4× upscale** actions. Video
Studio creates a new app-owned derivative with a local Lanczos resize, preserves
the source asset and folder, caps the long edge at 3840 pixels, and keeps video
audio when present. Agents can request the same operation with
`POST /api/video-studio/assets/{id}/upscale` using `factor` (`2` or `4`) and an
optional `name`.

The Plan tab includes an append-only **Decision log** for consequential
production choices. Record the category, subject, chosen path, and rationale
before a provider, model, render runtime, or creative direction is used. Agents
can read the log with `GET /api/video-studio/projects/{id}/decisions` and append
an entry with the current `revision` through the matching `POST` route.

Plan also exposes **Pipeline checkpoints** for research, proposal, script, scene
plan, assets, edit, and compose. Start and complete stages in order; agents can
read them with `GET /api/video-studio/projects/{id}/stages` and transition them
with the revision-checked `POST` route.

Use **Inspect color** on an image or video library item to measure a source
frame's normalized luma, chroma, saturation, hue, and black/white clipping. The
same read is available to agents at `GET
/api/video-studio/assets/{id}/scopes?time=...`; it measures the raw source and
does not alter the asset or timeline.

## Build your edit

Create a project and choose **Import media** for a local file, or paste an HTTPS
footage URL into **Import media URL** and choose **Import URL**. Imported media
is probed and copied to your Ryu node before it appears in the library. Add items
from the library to the timeline, then select a clip to edit
its source in/out points, timeline start, track, speed, volume, framing, rotation,
opacity, color, and fades. Higher-numbered tracks appear above lower-numbered tracks. Drag a clip to move
it in time or between tracks; movement snaps to the project frame rate. With a
clip focused, Alt+Left/Right nudges it by one frame.
With a clip selected, Alt+[ trims its start to the playhead and Alt+] trims its
end to the playhead. These shortcuts honor locked tracks and the same frame and
source bounds as pointer trimming.

Visual clips also expose bounded crop edges (top, right, bottom, and left).
Crop is applied in the preview and encoded render before framing and layout.
The **Edge shape** controls add rounded corners and bounded alpha feathering to
the selected visual clip. Rounding is a percentage of the clip's short edge;
softness is an encoded pixel radius. Both values stay with the clip when its
settings are copied and are applied in the preview and final render.
The same inspector supports bounded exposure, temperature, tint, and vibrance
grade values; these settings are preserved by agent clip-property edits and
encoded through the local render graph.
The effect stack supports blur, grayscale, sepia, sharpen, and vignette entries
with the same bounded preview/render ordering. Vignette darkens the frame edges
in both the editor and encoded output.

Use **Animation** in the clip inspector to add scale, position, rotation, and
volume keyframes at the playhead. Values interpolate linearly between keyframes and
appear in the rendered export. Splitting a clip preserves its animation.

Choose an **Entry transition** in the clip inspector to slide a visual clip left,
right, up, or down, crossfade it, or use a bounded zoom in/out. Set its duration
in timeline seconds. Place the entering clip above overlapping footage to reveal
it over the previous shot. Transitions combine with framing, position keyframes,
opacity, and fades. They move the visual layer; audio mixing remains controlled
by volume and fades. Splitting during a transition preserves its progress. A clip
that ends before the transition finishes cuts the motion short.

Move the playhead inside a clip and choose **Split at playhead** to make two
independently editable segments. Duplicate and delete clips, or use Undo and
Redo while editing. Choose **Save changes** to persist the project. Concurrent
edits use revision checks: if another editor or agent saved a newer revision,
reload that project before saving your changes.

Agents can inspect the bounded saved revisions with
`GET /api/video-studio/projects/{id}/history`, then restore one as a new current
revision with `POST` to the same path using `revision` and `historyRevision`.
For a one-step agent rollback, `POST /api/video-studio/projects/{id}/undo` uses
the newest saved revision by default; pass `historyRevision` when the target
must be explicit.

Choose **Duplicate project** to create an independent alternate cut at revision
zero. The copy keeps the same app-owned media and editable timeline state while
its future saves and export choices remain separate. Agents can create the same
version with `POST /api/video-studio/projects/{id}/duplicate`, optionally passing
a new `title`.

Agents can also address Ryu projects as timeline workspaces: `GET
/api/video-studio/timelines` lists stable ids, duration, canvas, fps, and revision;
`POST /api/video-studio/timelines` creates an empty workspace or duplicates one
with `from` and `title`; and `GET /api/video-studio/timelines/{id}` reads the
workspace before using the revisioned project edit routes.

The Media library's **Nested sequences** section renders another timeline as an
app-owned sequence clip. Add that clip to the current timeline like any other
video; **Refresh sequence** re-renders it after source edits. Agents can create
one with `POST /api/video-studio/projects/{id}/sequence`, then refresh it with
`POST /api/video-studio/assets/{id}/refresh-sequence`. Cycles are rejected.

Keyboard shortcuts include Space for playback, J for reverse playback, K to
pause, L to play forward, Home/End to jump to the beginning or end, S to split,
D to duplicate, Delete to remove
the selected clip, arrow keys to step by one frame (Shift for one second), and
Alt+Left/Right to nudge the selected clip by one frame. Press `[` or `]` to move
to the previous or next saved marker. Command/Ctrl+S and
Command/Ctrl+Z save and undo; Shift+Command/Ctrl+Z redoes. Shortcuts leave text
fields and dialogs alone.

Alt+[ trims the selected clip's start to the playhead; Alt+] trims its end. The
same locked-track, frame-rate, and source-bound checks used by pointer trimming
apply to these keyboard edits.

Press `I` to mark the range start at the playhead and `O` to mark its end. The
shortcuts leave fields and dialogs alone; after reviewing the selected range,
choose **Ripple delete range** to apply it.

Drag a timeline clip body to move it between tracks or in time. Drag its left or
right edge to trim the source range directly; the trim snaps to the project
frame rate, respects playback speed and source bounds, and removes animation
keyframes that now fall outside the shortened clip. When a saved marker is within
the snap window, moving or trimming an edge also snaps to that marker.

Shift-click timeline clips to build a multi-selection, then choose **Delete
N clips** to remove the group in one undoable edit. Linked audio/video partners
are removed with their selected member, and a locked member blocks the batch
until its track is unlocked.

Each timeline track has a saved name plus **Mute**, **Solo**, and **Lock** controls.
Mute removes that track's audio from preview and export; Solo isolates one or more
selected tracks while leaving their visual layers visible. Lock prevents clip
selection, movement, trimming, and inspector edits on that track until it is
unlocked. Agents can update the same settings through
`POST /api/video-studio/projects/{id}/tracks` with the current `revision`, `track`,
and any `name`, `muted`, `solo`, or `locked` fields. Agent `track` values are
zero-based from 0 through 15.

Use the **↑** and **↓** controls in each timeline header to reorder the visible
tracks. The lane, clips, and saved mute/solo/lock/name settings move together;
empty lanes stay available while a cut is being assembled. Agents can send the
bottom-to-top permutation to `POST
/api/video-studio/projects/{id}/tracks/reorder` as `order` with the current
`revision`.

Select an overlapping audio or visual clip and choose **Link overlapping
audio/video** to keep the pair together while moving or deleting it. Linked
groups support J-cuts and L-cuts without losing the relationship; choose
**Unlink audio/video** before editing the two sides independently. Agents can
use `POST /api/video-studio/projects/{id}/links` with `action: "link"` or
`"unlink"` and the current revision.

Open **Layouts** to place selected visual clips into a deterministic composition:
**Side by side**, **Stacked**, **2 × 2 grid**, **3 × 3 grid**, **4 × 4 grid**, or
**Picture in picture**. **Single frame** centers one clip. Selection order
determines slot order. Applying a layout replaces the selected clips' position
and scale keyframes; other clip properties remain intact. Agents can apply the
same preset through `POST /api/video-studio/projects/{id}/layout` with the
current `revision`, `layout`, and ordered `segmentIds`.

Open **Sync** to align audio-bearing clips from a camera, recorder, or external
microphone. Choose a reference clip and one or more targets, then use **Audio
correlation** after completing source analysis on both assets. Video Studio
searches their measured local audio envelopes, reports a confidence score, and
moves the targets on frame boundaries; if the match is weak, use **Manual
offset** with a signed number of seconds. The reference and target tracks must
be unlocked. Agents can request the same revisioned edit through
`POST /api/video-studio/projects/{id}/sync`; it returns each target's measured
lag, confidence, applied frame offset, and any group shift needed to keep clips
at or after timeline zero. Choose **Embedded timecode** when the imported media
contains SMPTE start timecode; Video Studio reads the source frame rate and
supports regular and drop-frame `HH:MM:SS:FF` values.

Open **Multicam** to create a named session from two or more video angles and a
mic or camera-audio source. The app writes ordinary angle clips plus a dedicated
program-audio layer, then **Switch camera over range** replaces only the selected
full-frame range; **Ungroup session** removes the session metadata and leaves the
clips in place. Agents can read groups with
`GET /api/video-studio/projects/{id}/multicam` and create, switch, or ungroup
with the same revisioned `POST` route. This local session model keeps angle
switches explicit. Imported media retains valid embedded SMPTE start timecode
and source frame rate metadata when present, so the Sync panel can align a
multicam source by timecode; it falls back to audio correlation or a manual
offset when the metadata is absent.

For a larger cut, set **Range start** and **Range end** in the timeline's **Range
edit** row and choose **Ripple delete range**. The selected interval is removed,
later clips shift left on every track, captions and timed layers keep their relative
timing, and markers inside the cut are removed. Crossing clips retain their source
trim and animation continuity in the pieces that remain; use Undo if the range needs
adjustment.

Choose **Insert at playhead** with a selected clip to splice a copy into its track.
The inserted source range is placed at the playhead, crossing clips are split when
needed, and later clips, captions, titles, graphics, avatars, meshes, and markers
shift right by the inserted duration. The edit is one undoable revision. Agents can
call `POST /api/video-studio/projects/{id}/insert` with a target `track`, insertion
time `at`, and ordered source entries to make the same ripple insert.

Agents can also use the direct timeline operations. `POST /api/video-studio/projects/{id}/add`
places source ranges without rippling; `POST /api/video-studio/projects/{id}/move`
frame-quantizes a clip to a new track and start; `POST /api/video-studio/projects/{id}/split`
preserves source timing at a chosen timeline time; and `POST /api/video-studio/projects/{id}/remove`
deletes one or more unlocked clips. Every operation requires the current project
`revision`.

Before an agent edit, `GET /api/video-studio/projects/{id}/timeline` returns
the saved frame rate, canvas, total frames, stable `trackId` values, clip source
ranges, gaps, markers, and current revision. Use those IDs and ranges as the
inputs to the mutation routes.
`GET /api/video-studio/projects/{id}/transcript` maps saved source cues through
clip trims, playback speed, and timeline positions; pass `track` to scope it.
Use `POST /api/video-studio/projects/{id}/remove-words` with timeline-second
ranges from that read to cut filler or unwanted speech and ripple later media
left in one revision-checked edit.

`GET /api/video-studio/search?q=...` returns matching source-transcript ranges
from current app-owned indexes. Use the returned `assetId`, `start`, and `end`
with the direct timeline routes; semantic Spaces search remains available when
the host provides it.

Use `POST /api/video-studio/projects/{id}/keyframes` to replace one clip's
clip-relative x, y, scale, rotation, opacity, or volume keyframe track. Passing an empty
`keyframes` array clears that property while leaving the other animation tracks
and clip treatment intact.

Choose **Capture frame** in the toolbar to render the current composited playhead
frame into a full-resolution PNG asset in the media library. Captured frames include
timeline transforms, effects, titles, captions, and other local layers; they can be
reviewed, placed back on the timeline, or used as a generation reference. Agents
can request the same app-owned still through
`POST /api/video-studio/projects/{id}/capture-frame` with the saved `revision` and
timeline `time`.
For non-mutating visual inspection, use
`GET /api/video-studio/projects/{id}/inspect-frame?time=...`; it returns a
composited PNG without adding an asset to the library.

Project settings also include **Download FCPXML** and **Download Premiere XML**.
These exports preserve the saved frame rate, canvas, clip timing, source trims,
track lanes, and app-owned media references for Final Cut/Resolve or Premiere
handoff. The sidecar returns the same original XML through
`GET /api/video-studio/projects/{id}/interchange?format=fcpxml` or
`format=xmeml`; the output uses `ryu://video-studio/assets/{id}` references so
media stays on the node and can be relinked during an authorized handoff.

Agents can update the same project settings without sending a full project body
through `POST /api/video-studio/projects/{id}/settings`. Send the current
`revision` plus `width` and `height` together, an `aspectRatio` such as `9:16`
or `2.4:1`, a `quality` preset (`720p`, `1080p`, `2K`, or `4K`), `fps`, an
`exportCodec` (`h264`, `h265`, or `prores`), or `exportPreset`. Aspect ratios
preserve the current short edge and quality presets preserve the selected ratio
within the bounded canvas. Explicit dimensions cannot be combined with
`aspectRatio` or `quality`; the operation returns the next saved revision and
rejects stale or incomplete updates. Video exports support H.264/MP4,
H.265/HEVC, and ProRes 422/MOV encodings.

Choose a **Visual style** in Project settings to apply a saved canvas playbook:
**Clean professional**, **Flat motion**, **Minimalist diagram**, or
**Cinematic**. The selected profile controls the local canvas color in the
preview and encoded output and is revisioned with the project. New vector layers
use the profile accent by default. Agents can set
`styleProfile` through the same settings operation.

Agents can make granular clip edits without replacing the project body. Use
`POST /api/video-studio/projects/{id}/clip-properties` for the same bounded
inspector fields used by the Companion, `copy-clip-settings` to copy treatment
and compatible keyframes to several targets, or `swap-clip-media` to replace a
source while keeping its timeline slot. Each operation checks the current
revision, honors locked tracks, and validates the resulting source range.

For a visual clip, choose **Visual effect** in the clip inspector. **Soft blur**,
**Grayscale**, and **Sepia** use the same bounded effect choice in the preview and
the rendered MP4; **Original look** leaves the source color and detail unchanged.
The **Effect stack** adds bounded blur, grayscale, sepia, sharpen, and vignette
passes for a reusable treatment that is also available through the effects route.
When one stack pass is selected, **Amount (%)** controls its bounded strength.
Selecting another pass appends it to the stack; each pass has its own amount and
remove control, so treatments stay editable instead of becoming a baked filter.

Agents can make the same edit through `POST /api/video-studio/projects/{id}/ripple-delete`
with the current project `revision`, `start`, and `end`; the sidecar applies the same
validation and keeps the saved revision conflict check.

Use the **Marker label** and **Marker color** fields beside the timeline and
choose **Add marker** to save a labeled, color-coded cue at the playhead. Marker
labels appear on the ruler and in the timeline marker list; choose one to jump
back to its time or remove it from the list. Markers are part of the revisioned
project and do not change the rendered duration. Agents can create, update, or
delete the same cues through `POST /api/video-studio/projects/{id}/markers`.
Agent-created range markers retain their duration, review status (`open`,
`review`, or `resolved`), and comment through ripple edits and project history.

Projects can contain up to 200 timeline segments and run for up to two hours.
Individual imported files can be up to 2 GB. Media is uploaded in chunks.
Use **Preview** for an image or **Preview frame** for a video to inspect its source
thumbnail before adding it to the timeline. Close the preview to return to the
library. Timeline edits and exports use the original media.

Expand **Organize** on any library asset to rename it or move it into a relative
folder such as `B-roll/Sunset`. The folder is saved with the asset and appears in
the library. **Delete media** removes the app-owned file and thumbnail and removes
its clips from saved projects after checking any supplied project revisions; use
it only after reviewing the affected timelines.
Agents can perform the same rename, move, or delete through
`POST /api/video-studio/assets/{id}/organize`.
Use the **Media folder** filter beside search to browse one folder or return to all
library assets.

## Turn audio into waveform video

Select an audio clip and set **Audio visualization** to **Waveform**. The video
uses the source audio samples, with configurable color and height. It can be
layered over footage and combined with titles and captions for podcast or voice
clips. Framing, opacity, fades, and keyframes apply to the waveform layer.

For a music or effects layer, set **Duck under voice** to lower that layer while
other audible timeline layers speak. Export uses FFmpeg sidechain compression
with a short attack and release; leave **Keep full mix** selected when the layer
should stay at its authored level.

For any audio clip, choose **Audio processing** in the clip inspector. **Normalize
loudness** applies a bounded EBU-style loudness pass, while **Voice enhance** uses
high/low-pass filtering, denoise, and compression for spoken tracks. The preview
graph and node export use the same mode; **Original audio** leaves the source
unchanged.
**Noise reduction** applies a bounded high/low-pass and spectral denoise graph
for steady background noise while preserving the original source asset.

The preview loads bounded audio windows, and exports render the waveform on the
node. Playback uses a monotonic clock and Web Audio gain so volume automation and
fades can be previewed, including gains above the browser element's normal range.
Waveform previews follow the clip's source trim, playback speed, and output frame
rate. Slowed and sped-up windows use the same audio time-stretching path as export;
normal-speed audio bypasses time stretching. Newly requested windows show a loading
state until their matching audio is ready.

## Analyze source footage

Choose **Analyze source** on an imported video or audio file to calculate its
scene changes and audio envelope. Analysis runs on your node and can be canceled.
The results persist with the media library; interrupted jobs are marked failed
after a restart.

For video, each detected source range can be added to the timeline as an editable
clip. Scene detection measures visual changes, so review the suggested boundaries
before using them as editorial cuts. The waveform displays measured audio levels,
normalized for visibility. Completed analysis also identifies separated, pronounced
loudness peaks. Choose **Add loudness markers** to turn those measured source times
into color-coded timeline markers for beat, emphasis, or review notes. These cues
are loudness measurements, not beat or tempo detection.

When the envelope contains recurring onsets, analysis also offers **Add estimated
beat markers**. These are local timing estimates derived from the same RMS bins;
they are review cues and do not promise a detected tempo or musical beat grid.
Agents can read the same estimate through `GET /api/video-studio/assets/{id}/beats`
after source analysis completes.

Audio sources with a measurable signal also report bounded silent ranges. Choose
**Remove detected silence** to ripple-delete those ranges from every matching audio
clip on the timeline; later visual and timed layers move with the edit. Review the
cut before saving because silence removal changes the program duration.

## Study a reference video

Open **Reference** and choose an imported video that has completed source
analysis. **Build reference profile** saves measured pacing for the project:
duration, dimensions, shot count, average shot length, audio presence, caption
coverage, and a sampled opening-frame style profile with luma, saturation, hue,
and clipping review.

The generated brief describes the observed rhythm and sampled visual treatment
so you can adapt the structure to an original production. It does not copy the source
media, transcript, or creative text. Edit the brief if needed, then choose
**Copy brief to Plan** to continue with a reviewed storyboard brief.
It also includes a bounded planning estimate for image, video, and narration
work; this estimate is planning context and does not replace Gateway receipts.
The profile also offers three editable structural concepts: preserve the
observed rhythm, slow the reveal, or lead with a faster hook. Each concept has
an original direction and target duration; choosing **Use concept in Plan**
copies that direction into the project brief for further review.

## Transcribe and localize

In **Transcript**, choose a source video or audio file. **Transcribe with Ryu**
uses the node's configured speech-recognition service and saves progress in
20-second source windows. Engine segment timestamps are retained when available;
text-only results use window timing. Neither mode claims word alignment that the
engine did not supply. You can stop after the current window and resume from the
last saved offset.

When the speech engine supplies word timestamps, Video Studio saves them alongside
the segment transcript. **Apply word captions** creates individually timed words
on the timeline, accounting for each clip's source trim and playback speed. The
button stays unavailable when the engine did not provide word alignment. Review
the timing before export; alignment quality depends on the speech engine.
Standalone punctuation is attached to the preceding word using its measured end.
Use **Transcribe again** to replace an older source transcript with fresh engine
results. This resets its saved transcription progress; existing timeline captions
stay unchanged until you apply the new transcript.

**Apply highlighted captions** groups measured words into short readable lines
and highlights the word being spoken. The full line remains visible between
words. Change a line's highlight color in **Captions**. Editing its text or timing,
or translating it, removes the old word alignment; reapply measured captions to
restore highlighting. MP4 exports retain highlighting, while SRT and WebVTT
downloads contain the line text and timing.

You can also import a source SRT or WebVTT file. **Apply to timeline captions**
maps its cues onto every use of that source, accounting for source trims and
playback speed. Reapplying replaces previously derived captions for that source;
other captions are kept.
Agents can make bounded caption edits without replacing the project body through
`POST /api/video-studio/projects/{id}/captions`. Use `append`, `replace`, or
`remove`, pass the current `revision`, and set `trackId` to `null` for source
captions or an existing localization track ID.

Agents can make the same bounded changes to titles and lower thirds through
`POST /api/video-studio/projects/{id}/titles`. Use `append` or `replace` with
complete title objects, or `update`/`remove` with a `titleId` and the current
revision.
Use `POST /api/video-studio/projects/{id}/color` to apply a partial grade, copy
a source clip's grade, or reset selected visual clips without replacing the
project body.
Use `POST /api/video-studio/projects/{id}/effects` to replace the bounded visual
effect stack on one or more clips with the same preview/render contract.

In **Captions**, select a target language and choose **Translate with Ryu**.
Translation uses the node's configured language model. Caption IDs and timing
are preserved in a durable language track, and malformed or incomplete responses
leave the original captions intact. The **Caption track** selector lets you
switch between the source captions and every saved translation. Playback,
preview, burned-in ASS captions, subtitle downloads, dubbing, and timeline
inspection all use the selected track. If the captions change while translation
runs, the newer edit is kept. Review translated text before exporting.
Translation quality depends on the selected language model. Review grammar and
specialized terms as well as timing; preserving caption IDs does not establish
that a translation is accurate.

Use **Dub this caption track** after reviewing the captions to create a spoken
audio track through Ryu's configured narration engine. Choose an optional
language code, voice, and speaking rate. The original caption timings stay
unchanged; the saved WAV is added to the timeline for review and can be trimmed,
ducked, or paired with a visual scene. Long tracks must be split before dubbing.

## Find footage by meaning

In **Find footage**, choose a completed source transcript and a Space name, then
choose **Index transcript**. This explicitly copies transcript ranges into that
Space; video and audio files stay in Video Studio. The Space's access settings
apply to the copied text, and Ryu Core performs indexing and semantic search.

Describe a moment in **Search footage**, review the matching transcript ranges,
and choose **Add source range** to add one to the timeline. Newly saved documents
may take time to become searchable. Results are checked against the current source
transcript and the accessible Space document before being shown.

After changing a source transcript, index it again. Interrupted indexing resumes
from saved progress. **Rebuild index** creates a fresh projection; documents edited
outside Video Studio are preserved rather than overwritten or deleted. Search
requires a Ryu host with Spaces access and does not fall back to cached results
when access is denied.

## Find open media

Open **Stock** to search the allowlisted Archive.org, Wikimedia Commons, NASA
Images and Video, Openverse images and audio, node-configured Unsplash images, or
node-configured Pexels, Pixabay, and Coverr catalogs by topic. A result includes
its source page, attribution, rights text, format, and size before anything is
downloaded. **Import to library** accepts only the stable catalog identifier; the
node resolves a supported image or video file, applies a 512 MB limit, probes it,
and stores it as app-owned media with the source provenance attached. Pexels and
Pixabay searches require node API access; without it, Stock reports an unavailable
provider.

Unsplash is available when the node has `RYU_VIDEO_STUDIO_UNSPLASH_ACCESS_KEY`.
The key stays on the node and the picker reports Unsplash as unavailable until
it is configured. Coverr is also available when the node has
`RYU_VIDEO_STUDIO_COVERR_API_KEY`; its signed download host and attribution /
commercial-use guidance stay attached to the imported asset. The credential stays
on the node. NASA media is generally public domain in the United States, but review
item metadata for credited third-party material.

The app never accepts an arbitrary URL from the browser. Review the recorded rights
and attribution before publishing a production. Openverse audio keeps the successful
search metadata in the node for the immediate import, so a temporary detail-endpoint
failure does not discard a result that has already been reviewed.

## Titles

Use **Titles** to add title cards or lower thirds. Edit the text, position, color,
size, timing, fades, and entry animation. Fade and slide-up, slide-down, slide-left,
and slide-right entrances use the same fade-in timing in the preview and rendered
MP4. Titles appear in both surfaces and can extend the timeline or create a
title-only video.

## Vector graphics

Open **Vector graphics** to add rectangle, ellipse, triangle, and line layers
above the timeline. Set a shape's timing, position, size, opacity, fill, stroke,
stroke width, and slide entrance. Shapes preview in the editor and render through
the same saved timeline as footage, titles, captions, and audio. Ellipses and
triangles use deterministic local raster slices, so no external renderer or
provider is required.

## Avatars

Open **Avatars** to add a procedural 2.5D character layer. Set its timing,
position, size, depth, skin, outfit, and accent colors, then choose a neutral,
wave, or point pose. Idle bob and slide entrances use the same saved timing in
the preview and FFmpeg export. The character is composed from bounded local
shape layers, so it can be edited and rendered without a provider or external
asset. These avatars are a local 2.5D rig: choose a limb, head, or mouth
asset.

These avatars are a local 2.5D rig: choose a limb, head, or mouth property, set
its value, and choose **Add rig keyframe at playhead**. Rig values
interpolate between saved keyframes and use the same pose timing in the preview
and rendered export. Add a **Rotation limit** or **Translation limit** for the
selected joint and axis to keep keyed local poses inside a bounded range. The
same limits clamp the evaluated pose in preview and export; saving a second
limit for the same joint and axis replaces the previous one.

## 3D stage

Open **3D stage** to add local depth blocks. Set the stage camera's offsets,
zoom, orbit, and tilt, then set each block's center offsets, depth position,
width, height, extrusion, timing, and color. Float and orbit motions update the
projected camera position in the preview and export. Each block renders with
front, top, and side faces through the local FFmpeg graph,
so the result is an editable, deterministic 3D composition primitive without
an external renderer. Add camera path keyframes for x, y, zoom, orbit, or tilt at
explicit timeline times; the same linear interpolation drives preview and export.

Enter a **World direction** and choose **Generate local world** to replace the
stage with a bounded local world layout: terrain, water, mountains, structures,
a landmark, and a saved 12-second camera path. The result is ordinary editable
stage blocks and camera keyframes, so you can adjust or remove every part after
generation. The direction and generated world are saved with the project; no
external renderer or provider is required. This is a deterministic local
composition primitive, not a claim of unrestricted 3D asset generation.

Open **Meshes** to import bounded Wavefront OBJ or glTF/GLB geometry. Video
Studio keeps validated triangle vertices and faces in the project, applies glTF
node transforms, projects the result through the saved stage camera, and
rasterizes the same geometry into the local export. Rotation, scale, position,
timing, and color remain editable.

Add mesh keyframes for position or Euler
rotation to animate a short stage motion; the same interpolation is used in
preview and export. The first bounded glTF rotation and translation animation
channels are projected into mesh rotation and position keyframes. Embedded
buffers and embedded PNG base-color textures are accepted.

Static glTF skins
expose bounded joint pose, parent controls, and rig keyframes. Bounded linear
glTF skin animations are baked into validated vertex poses for preview and
export; external buffers, image URLs, and other unsupported animation channels
remain outside this importer. Imported skins can still receive the same local
joint rotation and translation limits in the Meshes panel.

## Captions and scene review

Import an SRT or WebVTT file from **Captions**, or add timed captions manually.
Edit the words and their start/end times on the selected caption track, then
download the selected subtitle file or include that track in your rendered
video. Source and translated tracks share the same bounded cue contract; ripple
edits and asset cleanup keep every saved track aligned with the timeline.

Use **Plan** to write a brief and organize storyboard scenes. Select a take for
each scene and approve it when ready. When scene approval is required, export
waits until every scene has selected media and approval. Changing a scene's
script, prompt, title, or selected takes reopens its review. Approval uses a
separate **Can approve scenes** permission and a revision check. Saving a project
cannot grant scene approval. When approval is required, every timeline asset must
belong to an approved scene. Each unapproved scene also has an **In review** or
**Changes requested** status and a bounded review note for the next edit pass;
the scene contact sheet shows the status, selected take, technical score, and a
short note preview. Approved notes remain read-only until the scene is reopened.

## Assemble a storyboard

For each scene, choose a take, its source in point, and a duration. Choose
**Assemble storyboard** to replace the timeline with those scenes in order and
add timed scene titles. Source ranges are bounded by the selected file's duration.
Each scene can pair one visual take with narration or music layers. Audio layers
have independent source in points; changing the visual trim keeps those audio
positions. **Fit scene to this audio** uses the selected layer's remaining duration.
If a video take is too short, choose a longer take or a still image before fitting.

**Mute visual audio** silences the video's original sound while retaining added
audio. Changing these settings reopens scene approval. Assembly creates separate
timeline tracks, where you can continue mixing and editing.

Existing captions are cleared so their old timing is not applied to the new edit.
Undo restores the previous edit, and saved revisions remain in project history.
When scene approval is required, every scene must be approved before assembly.

## Production readiness

The **Production readiness** card in **Plan** mirrors the app's saved delivery
gates. It reports the brief, scene plan, scene assets, creative approval,
timeline, and current delivery review separately. Direct timeline edits can skip
storyboard stages; projects with scenes or required approval keep those gates
explicit. **Export gate ready** means the current project can be rendered;
**Delivery ready** appears only after the current saved revision has a passing
post-render review. Agents can read the same snapshot from the project's
`readiness` operation, so the editor and tool calls share one source of truth.

The **Production activity** ledger beside the readiness card shows the brief,
storyboard, takes, approval, and assembly stages alongside saved project
revisions, generation outcomes, and export reviews in newest-first order. It is
an app-owned run history; provider spend and settlement remain Gateway-owned.

The **Production preflight** card combines the same gates with pipeline stage
progress, pending or interrupted generation requests, logged decisions, and
budget admission. Agents can read the bounded snapshot from
`GET /api/video-studio/projects/{id}/preflight` before starting the next
production step.

When scenes have visual takes, the **Scene contact sheet** loads bounded
app-owned thumbnails and shows each scene's approval state before assembly.
It also shows a bounded technical take score based on the saved resolution,
duration, and audio metadata. This is a review aid, not a claim about creative
quality or provider output; required-approval projects keep low-quality takes
blocked until you choose a better take.
When a timeline contains only still images without authored motion controls,
readiness adds an optional **Motion quality** advisory so you can review the
delivery promise before publishing.

## Production recipes

Open **Recipes** to compose imported media or a local template into an editable
timeline:

- **Animated explainer** starts without footage and creates a 12-second local
  composition of vector cards and a title. Add optional audio to fit the
  composition to that source; the result remains ordinary editable project
  layers.
- **Footage montage** sequences selected images and videos in selection order,
  bounds each shot by its source duration, and adds short fades. An optional audio
  source replaces the clips' original sound.
- **Cinematic montage** uses the same editable source order but crossfades every
  later shot with a bounded timeline-second transition, making a trailer-style
  cut without baking the result into a single file.
- **Narrated slideshow** distributes selected images across the full narration
  duration and adds alternating slow zooms.
- **Waveform video** uses the complete audio source, a measured waveform, and an
  optional background image.
- **Clip factory** accepts one video, cuts it into bounded clips of the selected
  length, and adds a marker at each generated boundary. Audio remains optional.
- **Multicam cut** alternates two to four synchronized video sources by the
  selected camera-cut length. It places the selected program audio (or the first
  camera's audio) on a separate track, mutes scratch-camera audio, and adds a
  marker for each camera change.

Choose landscape, vertical, or square output and an optional title. **Apply recipe**
replaces and saves the timeline, titles, and captions. Undo restores the previous
edit; saved versions remain in project history. Required scene approvals also
apply to recipe media. Review the result and choose **Export video** to render it.
Animated explainer uses only local composition; the other recipes use imported
media and do not invoke a paid generation provider.

## Export

Project settings include landscape, vertical, square, and 4K dimensions, plus
24, 25, 30, or 60 frames per second. Choose an **Export preset**: **Master**
keeps the default fast high-quality encode, **Review** favors a smaller file for
approval, and **Social** uses a balanced encode. **Export video** saves pending
changes and renders the saved timeline to H.264 MP4 with AAC audio when audio is
present.

Exports run on the node. FFmpeg and ffprobe must be installed there; caption
burn-in requires an FFmpeg build with the subtitles filter. Missing dependencies
or unsupported media produce a visible error. Rendering does not silently fall
back to downloading the original footage.

The export history shows running, completed, failed, or canceled jobs. Completed
exports include checked dimensions, frame rate, duration, audio presence, and file size. Each export identifies the saved project version it renders.
Choose **Download MP4** to retrieve the finished file. An interrupted render is
marked failed after a restart and can be started again. When a failed or canceled
job belongs to the current saved revision, **Retry export** starts it again from
Export history; older revisions are left available for inspection while **Export
video** renders the current edit.

Completed exports also include a delivery review. Video Studio samples four
rendered frames for visible luma, checks the encoded dimensions, frame rate,
duration, file size, and expected audio stream, and records each result beside
the export. An all-black render or a missing expected audio stream fails the
delivery gate and is not presented as a completed export. Warnings and passed
checks remain expandable in **Export history** so an agent or editor can review
the evidence before downloading.
ProRes 422 MOV output keeps its 10-bit pixel format; the review sampler converts
only its temporary luma sample to 8-bit before applying the same content gate.

**Download production package** writes a validated `ryu.video-studio.package.v1`
JSON bundle containing the editable project, referenced asset metadata, and
provenance credits. Media bytes remain on the node; the package is a handoff
manifest rather than a second media store. **Import production package** creates
a new project after validating that the referenced media is available locally.

## Credits and provenance

Open **Credits** to review source attribution and rights for media used by the
current project. The report includes the provider, stable source identifier,
source page, attribution, and rights text saved with each imported asset.
**Download credits** writes a Markdown document suitable for a production
handoff. Generated media and local graphics do not receive invented source
credits; provider billing remains in Gateway-owned records.

## Agent access

Video Studio exposes its project, media, and render operations through Ryu's
existing tool discovery. Agents and the editor work on the same saved project
and revision. The app requests permission to run its local media sidecar. Viewing and editing
are separate app permissions; editing also
allows importing media and starting or canceling renders.

## Generate media and draft scenes

The **Generate** panel uses Ryu's configured image, video, and narration services.
Describe a scene or provide the narrator's script, then generate and review the
result in your media library. Provider and model overrides are optional; leaving
the provider empty uses the node's local diffusion engine for images and video.

The Media panel also includes **Local soundtrack**. Choose a duration, tempo,
and mood to create a bounded offline score as an app-owned WAV asset. It is
deterministic node-local audio and does not claim a cloud provider receipt.

In **Plan**, set a project production cap and planning estimates for image, video,
and narration requests. Video Studio checks the cap before admitting a new
generation, including pending and unsettled requests. A configured cap gates
requests made through this app and its agent API; it cannot override another
client's Gateway spend. Exact Gateway receipts replace planning estimates when
the trusted provider row is available.

Local generation requires a compatible model installed on that node. Unsupported
explicit provider names return an error rather than silently using another engine.
Cloud providers may charge for generation.
The app never substitutes a sample asset when a model fails.

Local video generation uses the node's native queued diffusion job and waits for
the completed container before importing it. The returned WebM or MP4 keeps its
measured frame rate and dimensions; a failed, canceled, or timed-out job is
shown as an error and is never recorded as a saved asset. GPU-capable Wan/LTX
models are recommended because CPU video generation can take several minutes.

**Generation history** records the request before generation starts and retains
its prompt, requested settings, project version, and saved media. Expand an entry
to review its details. Requests whose outcome was not saved remain marked for
review, including after a node restart. They are never automatically retried.
Each request also records the execution route and rationale you selected before
starting it. These values are requested production context; Core and Gateway
remain authoritative for the resolved provider, enforcement, and any charge.
Check the provider before starting another request: a timeout or failed import
can occur after the provider has already completed or charged for the work.
The history does not infer actual provider costs or which fallback model ran.

For narration, you can set an engine-specific voice, a language code, and a
speaking rate from 0.5× to 2×. Empty voice and language fields use the speech
engine's defaults. Available voices and languages depend on the engine configured
on the node. Generate the narration, review it in the media library, then select
it as the audio source for a narrated slideshow or waveform recipe.

In **Plan**, write a brief and choose **Draft scenes with Ryu** to produce editable
scene directions and scripts. Drafting scenes does not generate their media or
approve them. Review the plan before producing its takes.
The **Research sources** card keeps HTTPS citations with the project. Add a title,
URL, and note; each source records its retrieval time and can be removed later.
These are editorial citations, not a claim that Video Studio verified the source
or performed live web research.
Each scene has separate **Spoken script** and **Visual direction** fields. Editing
either reopens its approval. You can continue editing while scenes are drafted.
If the brief changes while a model is drafting, the
late result is rejected and your current edit is kept.

## Gateway budget snapshot

Generation history can show a read-only snapshot from the node's Gateway when the
Core bridge is available. It reports node-wide tracked users, agents, sessions,
and the accounting unit; it does not attribute spend to a project or invent a
provider receipt. If the Gateway is unavailable, the panel says so and the
editor remains usable.

The Plan budget panel separately shows the project's configured cap, exact
receipt-backed spend, reserved estimates for requests still running, and
unsettled estimates for completed or interrupted requests without a matching
Gateway row. A zero cap leaves admission uncapped. Planning estimates are local
admission values; Gateway remains authoritative for provider billing and policy.

When Gateway audit records are available, **Gateway audit** also shows recent
redacted provider/model rows and the actual cost field returned by Gateway.
Cloud image and video requests carry the saved generation ID and project ID
through the trusted Core-to-Gateway forwarder. When Gateway returns a row with
that exact request ID, Generation history shows the resolved provider and actual
cost beside the matching project request. A missing row stays unavailable; the
app never joins records by timestamp, prompt, or an inferred provider. Other
Gateway records remain node-wide and are not attached to a project.

The execution route and decision note saved with a generation request are the
user's requested context. Core and Gateway remain authoritative for provider
resolution, admission, enforcement, and any charge. A visible budget snapshot
does not create a spending cap, and the app does not infer a cost from a
generation that lacks an authoritative Gateway result.
