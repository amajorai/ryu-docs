## What it does

Security Guidance checks each answer for risky code patterns and has a second model review the code before you ship it. It is off until you turn on the **Security review** toggle in the composer, or run `/security` for a one-off review of the last answer. You choose the reviewer model in the plugin's settings.

## How review results are reported

The reviewer treats the answer as data. Comments or other text in the code that claim it is safe or already reviewed are not evidence, so they cannot exclude a line from the review.

When the reviewer cannot be reached, returns nothing, refuses, or stops before finishing, the note says **LLM security review did not complete** and that this is not a clean result. Pattern warnings are still shown. No note appears only when nothing matched and the reviewer replied that the code looks secure.

The note follows your app language: pattern warnings and status sentences are translated, and the reviewer is asked to write its findings in that language. Code names in a warning, such as `yaml.safe_load()`, stay as written.
