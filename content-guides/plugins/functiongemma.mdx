`@ryu/functiongemma` downloads the pinned 270M [Google FunctionGemma](https://huggingface.co/google/functiongemma-270m-it)
checkpoint into a private plugin runtime (about 575 MB for the model and tokenizer,
plus the CPU inference dependencies). Inference runs on the node that runs Core, and the
sidecar supports Python 3.11 through 3.14 there.

The Hugging Face repository is gated, so set up access before you enable the plugin:

1. Accept Google's Gemma terms on Hugging Face.
2. Save a Hugging Face token in the **Hugging Face** card under **Integrations** in the Gateway
   settings. Open them from the node selector.
3. Install and enable the plugin from
   [Marketplace](/docs/surfaces/desktop/user-guide/marketplace), and review its requested
   permissions.
4. Select **FunctionGemma · 270M** under **Settings → Plugins → Shadow → Computer use → Local
   model plugin**. Text entry still uses Shadow's configured text model.

Ryu uses the token only for Hugging Face metadata and file downloads. It does not accept the
license on your behalf or pass the token to the plugin sidecar.

<Callout type="warn">
  FunctionGemma is an experimental base checkpoint, not a Shadow-specific fine-tune. It can choose
  only the supplied operation and target ids, and Shadow validates the decision and rechecks the
  live target before sending input. For reliability-critical tasks, prefer a planner validated for
  your workflow.
</Callout>

See [Shadow Computer Use](/docs/plugins/shadow) and
[Bundle Hugging Face models in a plugin](/docs/extend/develop/extensions/local-model-plugins).
