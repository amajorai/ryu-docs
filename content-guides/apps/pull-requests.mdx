A unified GitHub code review workspace for Ryu. Browse pull requests across repositories, inspect summaries and changes, see reviewers and CI status beside the selected pull request, and submit reviews through the locally authenticated GitHub CLI. GitHub issues remain available from the app's Issues contribution.

The inbox can search pull requests or open a pasted GitHub pull request link. The review view keeps the summary, diff, checks, discussion, and merge actions together. To ask about the selected pull request, open the desktop's **Ask Ryu** assistant, the same assistant you use everywhere else in Ryu. Code Review does not have a separate chat panel.

For stacked pull requests, each layer shows its title, target and source branches, and status together. Select another layer to inspect it before choosing a stack merge action.

While a pull request is open, the assistant shows it as context chips: a summary (description, changed file list, review and check status, reviewer names) and the diff. Remove a chip to leave it out. The assistant also offers review starter prompts such as **Review this PR for bugs and risks**. Nothing is sent to a model until you ask the assistant something. It is told not to post GitHub feedback, push, or merge unless you ask; any tool it calls follows your tool permission settings, which may run some read-only tools without asking. Check its suggestions against the source and CI results before acting.

Each pull request gets its own conversation: selecting another one replaces the context and starts a separate thread, and going back to an earlier pull request resumes its thread, even after you close the assistant. The assistant keeps your most recent app conversations (about a dozen, each trimmed to its latest turns) until the app restarts; older ones start fresh. A diff that finishes loading for the previous selection is not attached to the new one. If the app's assistant permission is turned off, Code Review works normally and the assistant simply has no pull request context.

During GitHub device sign-in, the app checks the authorization status while its view is
visible. Returning to the view refreshes the status, and a successful sign-in refreshes the work
inbox once. If the Companion cannot write to the clipboard, it selects the one-time code in a field
so you can copy it yourself.

Queued stack merges keep their completion notice visible while the inbox refreshes.

The desktop app also uses this app's GitHub connection for chat pull-request status icons and the
optional **Gateway settings → Developer → Git → Watch and fix pull requests** automations (see
[Git workspace controls](/docs/surfaces/desktop/user-guide/git-workspace-controls)). Those read a pull request's
state, recent comments and reviews, and open inline review threads in one GitHub request, including
each author's repository association so automations can ignore bots and outside commenters.
