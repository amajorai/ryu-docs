## What it does

Create contact, feedback, and blank forms, publish a respondent link, and read or export the answers. Forms is a Ryu app and stores its forms and responses on the Ryu node running the app.

## Build a form

Start with a blank form or a contact or feedback template. The editor is a document page: edit the title, description, question prompts, helper text, and choice labels in place while the answer controls remain visible. Type a question and press **Enter** to add a short-answer block, type **/** to open the question block picker, or use the **+** control beside the question line. Change each question's type or required state from its inline controls, and move questions with the arrows. Expand **Confirmation screen** below the submit button to edit the post-submit message.

Save changes to update the form. Saving changes to a published form updates the respondent page at its existing link.

If creating a form fails validation or the Forms service is unavailable, the create dialog stays open and shows the error so you can correct the values or retry. The form and its responses remain stored on the active Ryu node.

## Publish and share

Publishing makes the form available to anyone who can reach its link. The app uses the reachable web origins reported by the active Ryu node. If the node has no reachable web origin, Forms shows a path that can be combined with the node's address.

A published form accepts responses without requiring respondents to sign in. Unpublishing makes the respondent page unavailable while preserving existing responses.

On the Free baseline, the respondent page carries a small [Powered by Ryu badge](/docs/billing/powered-by-ryu). Paid subscription plans remove it.

The current Forms app uses the Ryu node's generic app route. It does not provision a domain or managed public edge. Respondents need network access to that node and its published route.

## Responses and export

The Responses view shows the latest answers, with older pages available as needed. **Export CSV** downloads the form's responses, including the question titles and submission times. Spreadsheet formula prefixes are escaped in exported cells.

Forms and answers are stored with the app data on the active Ryu node. The app does not forward submissions to another service or send email notifications.

## Data at rest

Forms encrypts each response's answers on disk with a key only this app receives from Ryu, so respondents' names, email addresses, and free-text answers are not readable from the app's database file. Form definitions, response times, and counts stay unencrypted so the editor, paging, and limits keep working; exports decrypt the answers. Responses saved by an earlier version are encrypted the first time the updated app starts. If the app is updated before Ryu itself, new responses stay unencrypted until Ryu delivers its key, and the app's status reports that it is waiting for a Ryu update. A Forms service run without Ryu creates its own key file in its data folder; keep that file with the data.

## Local runtime limits

| Resource | Limit |
| --- | ---: |
| Forms per node | 100 |
| Questions per form | 40 |
| Responses per form | 1,000 |
| Responses across the node | 2,000 |
| Responses per form per minute | 30 |

The current app does not include conditional logic, file uploads, payments, or external response destinations.
