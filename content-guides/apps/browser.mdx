## What it does

Browser is a real Chromium browser (Electron) that Ryu agents and the desktop share. It provides the grant-gated `browser.control` capability. On a local node, agents can share one embedded session with you. On a managed cloud node, each Bot gets a hidden tab lane with its own persistent Chromium profile (see [Agent profiles](#agent-profiles)). Core routes the desktop Browser panel and agent tools through its authenticated ext-proxy.

## Appearance bridge

The desktop Browser panel sends the current Desktop appearance to the browser chrome through the authenticated sidecar bridge. The shell follows the selected light or dark palette, contrast colors, interface and heading fonts, locale, and display time zone as they change. History labels use that display time zone and locale. Appearance tokens are never injected into websites opened in browser tabs.

## Activity center

The browser toolbar includes an Activity center. It shows active and recently active
audio/video playback, microphone and camera capture, screen capture, and browser control
sessions started by Ryu. Selecting an activity for a visible tab brings that tab forward.
Activity records are ephemeral browser-chrome state. They are not written to browsing history
or sent to an agent, and a closed or navigated tab clears its activity.

Media capture is reported after a page receives a real `getUserMedia` or `getDisplayMedia`
stream. A permission prompt by itself does not appear as active capture. Audio/video playback
comes from Chromium's media lifecycle events, so a tab with several media elements stays active
until the page has no playing element left.

Camera, microphone, and screen indicators stay active until the captured tracks actually end,
including cloned tracks, capture in additional frames, and same-page or unsuccessful navigation.
A page cannot clear these indicators by sending an activity message or dispatching a synthetic
track event. Once capture stops, the activity briefly appears under **Recently active**.

## Browser window

The tab strip lets you select, open, and close tabs. The navigation controls go back, forward,
or reload the selected tab; the address field accepts a URL or search. The Browser menu also
contains Find in page, zoom, the device toolbar, screenshot capture, cookie import, History,
Downloads, and Browser settings.

History lists visited page titles, URLs, and visit times. Choose **Open** to bring that saved
page into a visible browser tab, or choose **Clear history** to remove the list. Use the page's
back control to return to the browser while keeping the active tab.

The toolbar's **Downloads** button shows recent download status and offers a shortcut to the
download folder. Open the Downloads page from that popover or the Browser menu to review the
download list, open the folder, or clear its history.

### Desktop Browser dock

The Desktop dock opens a URL in the sidecar, refreshes its tab list, and lets you select or close
a tab. Choose **Annotate** to freeze the current preview, then click an element or drag an area.
Hold **Shift** while clicking to add more targets. Describe the change, and optionally open
**Adjust styling** before choosing **Add note**. Saved notes appear as overlays and in the tab's note list; remove one note or choose **Clear notes** to
remove all notes. **Cancel draft** discards an unsaved selection, comment, and style adjustments.
Press **⌘⇧D** on macOS or **Ctrl+Shift+D** on other platforms to toggle annotation mode. Notes
remain with the open tab and are cleared when that tab navigates or closes.

If saving a note fails, the dock keeps the selection and comment so you can choose **Add note**
again. After the save succeeds, the error clears and the note appears in the preview. **Ask Ryu to
address notes** opens the assistant with the current page and its saved annotations queued as
context. The assistant request includes the latest saved notes and their style adjustments; while
Ryu prepares that context, the button stays disabled to prevent duplicate requests. Failed note
deletions and clears keep the saved notes visible so you can retry. If preparing assistant context
fails, the notes remain saved and you can choose **Ask Ryu to address notes** again.

When your browser supports speech recognition, **Dictate annotation** appends recognized words to
the current comment. Choose **Stop voice annotation** to finish dictating, then review the comment
before saving it. You can always type the comment directly.

## Chromium extensions

Open **Browser settings → Extensions → Load unpacked** to add a local Chrome or Chromium
extension folder. Ryu loads the extension into the visible browser session with local file access
disabled and remembers the folder for the next browser launch. Remove an extension from the same
list to unload it and forget its path.

Electron accepts unpacked extension folders, not `.crx` packages, and does not implement every
Chrome extension API. Only load extensions you trust. Extension code stays in the browser
profile and is not exposed through Ryu's browser-control tools.

## Agent profiles

On a managed cloud node, each agent browses in its own Chromium profile. Cookies, logins, and site storage from one
agent's session are never available to another agent or to your own browser tabs, so each
agent signs in to sites separately, and an agent stays signed in to a site across browser
restarts until it signs out or the site ends the session.

Each agent also keeps its own browsing history, saved site permissions, and downloads folder.
Pages an agent visits are not added to your History or to another agent's. An agent's profile
never prompts for site permissions: camera, microphone, location, notification, and clipboard
requests are blocked unless that agent's own profile has the permission saved, and the
permissions you save in your browser never apply to an agent. Files an agent downloads are saved
in that agent's own folder, not your download location. Your own browser's history, site
permissions, and download settings are unchanged.

### Upgrading from earlier versions

Before Browser 0.1.17, every agent on a managed cloud node shared one profile. Updating signs
agents out of the sites they had signed in to there: Browser clears that shared profile's cookies
and site storage once, and each agent signs in again in its own profile.

Before Browser 0.1.18, agents on a managed cloud node also shared one browsing history,
site-permission list, and download list. Those entries can't be traced to a single agent, so
updating deletes them once and each agent starts with an empty history and download list. Files
already saved in the old shared downloads folder stay where they are.

## Agent accounts

Agents can sign up for and log into websites with their own accounts instead of yours. The
account's password, and any two-factor secret, live in the Ryu vault; the agent never sees,
types, or is told them.

1. **Sign up.** The agent calls `chromium.create_account` with the site and the username or
   email it will register with. Ryu generates a strong password and stores it. The agent then
   fills the sign-up form with `chromium.fill_credential`, naming the account and the form
   field (`username`, `email`, or `password`); Ryu types the value straight into the page.
2. **Two-factor setup.** When the site shows an authenticator setup page, the agent calls
   `chromium.capture_totp` on the QR code or the text setup key (sites usually reveal it behind
   a "can't scan?" link). Ryu reads the secret from the page and stores it.
3. **Log in.** The agent finds the account with `chromium.list_accounts`, fills the username,
   email, and password with `chromium.fill_credential`, and fills the current six-digit code
   with field `totp` when the site asks for it.

Ryu only fills an account into an HTTPS page on the account's own host (subdomains do not
match, since they can serve other people's content). It fills only the page's top-level document,
never an embedded frame, and types a password only into a password field. Each agent sees and fills only the accounts it
created. Listing accounts returns names and addresses, never passwords or two-factor secrets.
Reading a QR code needs Chromium's built-in barcode detection, which is not available on every
platform; the text setup key works everywhere.
