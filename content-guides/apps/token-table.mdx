## Private cards

Table snapshots and shared realtime updates omit unrevealed opponents' hole cards.

- Joining assigns a server-issued player identity and a private viewer capability.
  A claimed player ID alone cannot read another player's cards or submit their
  actions.
- The Companion keeps its viewer capability for the current browser session, so a
  reload or reconnect can resume the same seat. It never includes that capability
  or private cards in shared table publications.
- At showdown, participating players' cards may be revealed. Folded cards and
  hands won without a showdown stay private to their owner.
- Fresh hands use a cryptographically random shuffle.

Tokens are cosmetic and have no monetary, quota, or billing value.

### Older tables

Tables with seats created before viewer identities are kept as public history.
Earlier hands were not private snapshots.

- Opening an older table selects a fresh table with the same settings. Play
  continues without reclaiming another player's identity or deleting the old hand.
- All clients opening the same older table use one shared replacement and its new
  realtime room. The Companion remembers it during the browser session.
- Read-only viewers can still inspect the older table's public history.

### For API clients

Joining returns `playerId`, `viewerToken`, and a recipient-visible `snapshot`.

- Keep the `viewerToken` capability private, and include it in mutation bodies.
- The table's `view` operation accepts `viewerToken` in a POST body and returns
  private cards.
- Ordinary GET snapshots and shared events contain only public information.
