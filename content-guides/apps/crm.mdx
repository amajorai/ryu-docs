### Editing records and schemas

On a record page, a failed field save keeps the attempted value in the editor, and a failed activity save keeps its composer draft. You can retry without re-entering the edit.

If a field update succeeds but the timeline refresh fails, Harbor keeps the saved value visible and reports the refresh error. Opening a related record switches the panel to that record's object schema.

In the table:

- Changing the search returns to the first page and clears the previous selection.
- Sorting queries the full object on the server.
- Inline edits merge only the changed field. A rejected edit restores the previous value, and a successful retry clears its error.
- Bulk deletion keeps failed records selected and shows the rejection so you can retry without reselecting them.
- A rejected **New record** action shows its error while keeping the table available. Repeated clicks are ignored while a creation request is pending.
- Global search clears previous results as the query changes. If search is unavailable, the current query still narrows the table.

Currency edits require a complete decimal amount and save integer cents. Invalid amounts and ratings outside the field range stay in the editor without changing the record. Press Escape to discard a draft.

Open **Edit schema** to create objects, configure fields, or change their order. Failed schema writes keep the form draft available for retry.

- System fields cannot be deleted.
- Existing field types stay fixed.
- Standard objects have no delete action.
- After deleting a custom object, Harbor returns to an existing object when one remains.

## Data at rest

Harbor encrypts these with a key only this app receives from Ryu:

- records' names and field values;
- timeline notes and change history;
- list entry values;
- import files and previews. An uploaded import file is deleted once the import is applied.

Object and field definitions, record links, timestamps, and task assignees and due dates stay unencrypted so views, boards, and reminders keep working.

Search uses keyed fingerprints of words rather than the words themselves, which still shows which records share a word. Search has these limits:

- search matches whole words only, so a word matches once you have typed all of it;
- partial-word and phrase search are not available;
- one-letter words and very common words are not searched.

Data saved by an earlier version is encrypted the first time the updated app starts. If the app is updated before Ryu itself, it keeps working unencrypted until Ryu delivers its key. Its health status says it is waiting for a Ryu update.
