## Review moderated submissions

When **Moderate public submissions** is enabled, visitors receive confirmation
that their request was sent for review. Request and comment submission responses
include `pendingReview` so clients can distinguish content waiting for review.

| Pending item | Where to review | Actions |
| --- | --- | --- |
| Request | **Requests** | **Approve and publish**, **Reject submission** |
| Comment | Its request detail | **Approve comment**, **Reject comment** |

Pending requests remain private until a workspace member approves them. Pending and rejected content does
not appear on the public board.

If a public request cannot be saved, the dialog keeps the entered values and
shows a dismissible error so the visitor can retry without starting over.
API errors include a request ID in the response body and `x-request-id` header
to help correlate support reports.

## Public votes

Each visitor's first vote sets a signed, HttpOnly voter cookie that the board
issues itself. Votes are counted once per request for that cookie. A voter id
chosen by the client is ignored, so voting again from the same browser does not
raise the count.

### New voter cookie limits

A visitor who clears the cookie is issued a new one, so the board limits how many
new voter cookies it issues:

| Scope | Limit |
| --- | --- |
| One connection (one IPv4 address or IPv6 /64 network, or one signed-in account) | 5 an hour and 20 a day |
| The whole board | 60 a minute and 600 an hour |

- One visitor using up their own limit does not stop other visitors from voting.
- The limits are kept across restarts.
- When a limit is reached, the vote returns `429` with the `rate_limited` error code
  and nothing is counted. The visitor can retry later.
- Visitors who already have a voter cookie are never affected.

### How Ryu tells visitors apart

Ryu tells visitors apart by the address their connection comes from:

- Visitors who arrive through a tunnel, or through a reverse proxy on the same machine
  or a private network, all share that proxy's address. Ryu cannot tell them apart,
  so they share only the board-wide limit.
- A reverse proxy or CDN on a public address looks like a single visitor, so everyone
  behind it shares one per-connection limit.

A vote count is a signal of demand from distinct browsers, not a count of verified people.

## Public board branding

On the Free baseline, the public board carries a small [Powered by Ryu badge](/docs/billing/powered-by-ryu). Paid subscription plans remove it.

## Data at rest

Feedback Board encrypts the email address a visitor leaves with a request, with a key only this app receives from Ryu. Only the board's admin views show it. Commenter email addresses are not stored. Request titles, descriptions and author names are public board content and are not encrypted.

Emails saved by an earlier version are encrypted when the updated app starts. If the app is updated before Ryu itself, it keeps working unencrypted until Ryu delivers its key. Its health status says it is waiting for a Ryu update.
