#### Verification verdicts

Automated Reasoning is the default provider of the [verification layer](/docs/core/swappable-layers#verification-layer).
`verify.claim` checks a claim against one saved policy, named by `scope` (a policy id from
`verify.scopes`). With no `scope`, the only policy is used; with several, the call returns
`unverifiable` with the ids to choose from instead of guessing.

Each part of the claim gets a canonical verdict. The solver's own result is kept as
`provider_verdict`.

| Solver result | `verify.claim` verdict |
|---|---|
| `valid` | `proved` |
| `invalid` | `refuted`, with the counterexample |
| `satisfiable` | `undecided` |
| `impossible` | `inconsistent` |
| `no_translations`, `translation_ambiguous`, `too_complex`, or a tool error | `unverifiable` |

The overall verdict is folded from those parts. One refuted part refutes the whole claim. The claim
is `proved` only when every part was translated and proved and nothing was left out. When the parts
that were checked are all proved but something was left out (a sentence the policy's variables
cannot express, or a fact or rule that could not be used), the overall verdict is `unverifiable`
with a `reason`, and `notes` lists what was skipped.

Translating prose into logic uses the model set as **Extraction model** in Settings → Automated
Reasoning. Core runs that completion on the app's behalf under the `hook:side-model` grant, for the
companion and for the MCP server's `check` tool alike, so the app holds no provider key of its own.
`solve` never calls a model.
