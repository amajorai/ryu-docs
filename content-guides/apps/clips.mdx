A local-first video capture and ingest surface with a bundled editor preview. The out-of-process ryu-clips sidecar owns Core→Shadow recording and local-file ingest; transcript-led analysis and vertical rendering are not connected yet. Inside Ryu, the Companion starts from an empty project: add a video, or open a clip the node already has. Analyzing a file path on the node (in Movies, Downloads, or Desktop) fills the editor with that clip's duration and the moments the node detected; no sample moments are mixed in. A file you open from your computer plays in the Companion but is not uploaded. When the node is unavailable, Clips says so instead of showing sample data. Opened outside Ryu, it shows a bundled sample project labeled **Preview only**.

The node does not yet return transcripts or stream clip playback into the Companion, and URL downloads are unavailable on the standalone node service. The source field offers local paths when the node lacks URL ingestion; entering a link does not start analysis. Automatic Space filing is also unavailable on that service: finished clips remain in Clips, and successful analysis reports this limitation instead of claiming that a Space copy was saved. Source export reports a browser download request and cannot confirm that the browser saved the file.

Local video previews start at the beginning of the selected file. The overview scrubber follows the visible timeline window around your selected clip; dragging it seeks within that window, including when the source video is longer. Use Tab to focus the scrubber and the arrow keys to seek within that window. When playback is outside the visible window, its marker stays at the nearest edge while the time display shows the actual playback time. Undo and Redo remain disabled because the preview does not yet have edit history.

When the embedded host blocks browser fullscreen, the video expands inside the Companion instead. Use **Close** or press **Escape** to return; playback and the selected clip range are preserved.

## Quick attach

Quick attach stages your recent Clips activity in a chat with a keyboard gesture. Enable
**Clips quick attach** under **Settings → Keyboard Shortcuts** and choose where the captured
activity goes. **Automatic** uses the selected chat when a chat tab is active,
otherwise it opens a new chat. **Current chat** always uses the selected chat and reports an error
if no chat is active. **New chat** always opens a new chat. Press Command twice on macOS or Alt
twice on Windows from any app to stage the last three minutes of Clips activity as image
attachments, a visible summary, and available text from Shadow's accessibility/OCR context.
Ryu never sends the chat automatically. The shortcut stays off until you enable it.

On macOS, the double-Command gesture needs Input Monitoring permission. Returning to Ryu after
changing system permissions refreshes the shortcut permission status. Restart Ryu if it still
cannot listen.

The **Attach recent activity to a chat** switch enables the gesture; **Clips destination** chooses
where its attachments will be staged. Changing the destination does not enable the gesture or
send a message. The controls pause while a choice saves. If saving fails, the previous choice
remains selected and you can try again.

Quick attach uses the active node's recent activity. Switching nodes retires the previous shortcut
handler, including when it finishes connecting after the switch.

## Recording access

Recording uses the active node's Shadow capture devices. Screen capture must be enabled and
unpaused in Shadow. On macOS, grant Screen Recording to the responsible Ryu application and
restart it. Review local device permissions under **Settings → Privacy → Device permissions**.
A remote node requires its own grants and devices.

Clips checks screen capture before reporting that recording started. Slow screen capture preserves
the recording duration when the video is encoded, so it does not shorten the requested audio. A
requested microphone or
system-audio source must also start successfully; an unavailable source reports an error instead
of silently producing a recording without that source. Enabling voice input in onboarding only
checks the desktop microphone path and does not prove that a remote node can record audio.

<Callout type="warn">
Windows native recording does not use macOS-style Screen Recording toggles. Linux native screen
recording requires X11. Wayland portal capture is not supported by this recorder.
</Callout>
