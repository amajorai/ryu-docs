A local-first video capture and ingest surface with a bundled editor preview. The out-of-process ryu-clips sidecar owns Core→Shadow recording and local-file ingest. Transcript-led analysis and vertical rendering are not connected yet.

Inside Ryu, the Companion starts from an empty project: add a video, or open a clip the node already has.

- Analyzing a file path on the node (in Movies, Downloads, or Desktop) fills the editor with that clip's duration and the moments the node detected. No sample moments are mixed in.
- A file you open from your computer plays in the Companion but is not uploaded.
- When the node is unavailable, Clips says so instead of showing sample data.
- Opened outside Ryu, Clips shows a bundled sample project labeled **Preview only**.

<Callout type="warn">
The node does not yet return transcripts or stream clip playback into the Companion. On the standalone node service:

- URL downloads are unavailable. When the node lacks URL ingestion, the source field offers local paths, and entering a link does not start analysis.
- Automatic Space filing is unavailable. Finished clips remain in Clips, and successful analysis reports this limitation instead of claiming that a Space copy was saved.

Source export reports a browser download request and cannot confirm that the browser saved the file.
</Callout>

Local video previews start at the beginning of the selected file. The overview scrubber follows the visible timeline window around your selected clip:

- Dragging the scrubber seeks within that window, including when the source video is longer.
- Press Tab to focus the scrubber, then use the arrow keys to seek within the window.
- When playback is outside the visible window, its marker stays at the nearest edge while the time display shows the actual playback time.

Undo and Redo remain disabled because the preview does not yet have edit history.

When the embedded host blocks browser fullscreen, the video expands inside the Companion instead. Use **Close** or press **Escape** to return. Playback and the selected clip range are preserved.

## Quick attach

Quick attach stages your recent Clips activity in a chat with a keyboard gesture. The
shortcut stays off until you enable it, and Ryu never sends the chat automatically.

1. Open **Settings → Keyboard Shortcuts → Clips quick attach**.
2. Turn on **Attach recent activity to a chat** to enable the gesture.
3. Choose a **Clips destination**:

   | Destination | Where attachments go |
   | --- | --- |
   | **Automatic** | The selected chat when a chat tab is active, otherwise a new chat. |
   | **Current chat** | Always the selected chat. Reports an error if no chat is active. |
   | **New chat** | Always a new chat. |

4. From any app, press Command twice on macOS or Alt twice on Windows. Ryu stages the last
   three minutes of Clips activity as image attachments, a visible summary, and available
   text from Shadow's accessibility/OCR context.

Changing the destination does not enable the gesture or send a message. The controls pause
while a choice saves. If saving fails, the previous choice remains selected and you can try
again.

On macOS, the double-Command gesture needs Input Monitoring permission. Returning to Ryu after
changing system permissions refreshes the shortcut permission status. Restart Ryu if it still
cannot listen.

Quick attach uses the active node's recent activity. Switching nodes retires the previous shortcut
handler, including when it finishes connecting after the switch.

## Recording access

Recording uses the active node's Shadow capture devices. Screen capture must be enabled and
unpaused in Shadow. On macOS, grant Screen Recording to the responsible Ryu application and
restart it. Review local device permissions under **Settings → Privacy → Device permissions**.
A remote node requires its own grants and devices.

Clips checks screen capture before reporting that recording started:

- Slow screen capture preserves the recording duration when the video is encoded, so it does
  not shorten the requested audio.
- A requested microphone or system-audio source must also start successfully. An unavailable
  source reports an error instead of silently producing a recording without that source.

Enabling voice input in onboarding only checks the desktop microphone path. It does not prove
that a remote node can record audio.

<Callout type="warn">
Windows native recording does not use macOS-style Screen Recording toggles. Linux native screen
recording requires X11. Wayland portal capture is not supported by this recorder.
</Callout>
