The scheduled-runs calendar: every agent and workflow scheduled job projected onto Month, Week, Day, and Agenda views. Past runs come from recorded history; cron and interval schedules project only future runs from the current time through the visible period. The New automation dialog schedules an agent.

## Using Calendar

Use **Month**, **Week**, **Day**, or **Agenda** in the bottom toolbar to change the view. **Previous**, **Today**, and **Next** move the visible period.

Select a date or a scheduled run to open that day’s details. Past runs show their recorded outcome, and workflow runs use the workflow’s name when it is available.

Calendar hides Core’s internal maintenance schedules by default. When the active node has those jobs, turn on **Show system jobs** to include them. **Refresh** reloads the schedule list from the active node.

## Calendar on an agent's profile

Calendar also adds a **Calendar** tab to the agent profile. To open the profile from a chat with one
agent, choose the agent's **profile and activity** button in the title bar.

The tab shows only that agent's past and upcoming scheduled runs and opens on **Agenda**. **New
automation** starts with that agent selected. If you disable Calendar, the tab disappears from every
agent profile.

The tab reads dates and times in your display time zone, not your computer’s:

- each run sits under the date that zone’s clock shows;
- run times use a 24-hour clock in that zone;
- **Today** is that zone’s date;
- changing the zone moves runs to their new days.

<Callout type="info">
Calendar’s own page does not use the display time zone yet. It still files runs under your
computer’s dates and marks your computer’s today.
</Callout>

## Create an agent routine

Choose **New automation** and select an agent, then pick a schedule:

| Schedule | How the time is set |
| --- | --- |
| **Every minute**, **Every hour** | Fixed interval, no clock time |
| **Daily**, **Weekdays**, **Weekends**, **Weekly** | Clock time entered in UTC |
| **Custom cron** | Cron expression interpreted in UTC |

You can require an Inbox approval for each scheduled run.

To choose whether the routine starts a new transcript or reuses a persistent chat, use **Triggers → Routines** on the agent’s edit page.

While the routine is being created, the dialog controls are disabled. If creation is refused, the dialog keeps your selected agent, schedule, and approval choice so you can review and retry.

After the node acknowledges the routine, the dialog closes and Calendar reloads schedules and workflow names from the active node. If that reload fails, choose **Try again** to reload them. Do not submit the creation again.

### How Calendar saves routines

Saving a Calendar schedule creates the agent’s durable routine. Saving again for the same agent updates that routine instead of creating a duplicate. For the routine’s transcript destination, full editing, or removal, use **Triggers → Routines** on the agent’s edit page (see [Automations](/docs/learn/academy/operator/automations)).

- Renaming the agent does not create a second Calendar routine.
- Concurrent saves use the same saved routine ID and retain its execution history.
- A Calendar save preserves an existing transcript destination unless a caller
  explicitly clears or changes it.
- If several older generated schedules could be the routine, creation stops for
  review instead of choosing one to overwrite.

If another surface changes or deletes the routine while a save is being
validated, reload before retrying. A fresh creation after deletion gets a
new routine ID.
